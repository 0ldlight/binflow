# API 参考

BinFlow 的 API 分为四个面：

1. **制品内容路径**（无 `/api` 前缀）：`/binflow/<repoKey>/<path>`——上传、下载、删除制品，各协议客户端走这里。
2. **管理面 API**（`/binflow/api/*`）：仓库 CRUD、用户/组/权限、审计、GC、Token、搜索、系统信息。BinFlow 自有端点以 `/api/v1` 前缀标记。
3. **Docker Registry 平面**（`/v2/*`）——根级独立路由，见 [Docker 接入](/integrations/docker)。
4. **Webhook 事件面**（`/binflow/event/api/v1/*`）——见 [Webhooks](/admin/webhooks)。

认证与错误格式见本页后半；各域行为细节见对应指南。

## 通用制品域

| 方法 | 路径 | 语义 |
|---|---|---|
| PUT | `/binflow/{repoKey}/{path}` | 上传文件（body 为内容），checksum 头支持；**matrix 参数（`;k=v` 尾随成对序列剥离为部署属性）**——非成对 `;` 维持文件名字面 |
| PUT | `/binflow/{repoKey}/{path}/` | 创建目录（尾斜杠） |
| PUT | `/binflow/{repoKey}/{path}.sha1\|.md5\|.sha256` | 上传校验和旁车文件 |
| GET | `/binflow/{repoKey}/{path}` | 下载文件（Range / If-None-Match / ETag） |
| HEAD | `/binflow/{repoKey}/{path}` | 文件元信息（响应头同 GET 无 body） |
| DELETE | `/binflow/{repoKey}/{path}` | 删除文件或目录树 |
| GET | `/binflow/api/storage/{repoKey}/{path}` | 取 FileInfo / FolderInfo JSON |
| GET | `…?properties=K1,K2*` | 取属性（key 过滤 + 尾 `*` 通配；无命中 = 200 `{"properties":{}}`——自有裁定，非 404；node 不存在 = 404） |
| PUT | `…?properties=k=v1,v2[&recursive=1]` | 写属性——**merge 语义**：同名键值集整体替换、异名键保留；node 须存在（404） |
| DELETE | `…?properties=k1,k2[&recursive=1]` | 删属性（幂等；`properties=*` 全删） |
| GET | `…?stats` | 取下载统计 |
| GET | `…?lastModified` | 取目录最新修改时间 |
| GET | `…?permissions` | 取有效权限视图（admin only，仅 local 仓；virtual/remote → 400） |
| GET | `/binflow/api/storage/{repoKey}?list` | 流式文件清单（仅认证用户） |

属性语义全解见 [属性系统](/search/properties)。

## 搜索域

| 方法 | 路径 | 参数 | 语义 |
|---|---|---|---|
| GET | `/binflow/api/search/artifact` | `name=`（必填，大小写不敏感子串）、`repos=a,b` | 按名称子串搜索（权限过滤） |
| GET | `/binflow/api/search/checksum` | `sha1=/md5=/sha256=`（至少一）、`repos=` | 按 checksum 精确搜索 |
| POST | `/binflow/api/search/aql` | body = AQL 文本（`text/plain`）；`?compact=true`；`?query=` 空体回退 | **AQL 查询**（items 域子集，见 [AQL 指南](/search/aql)） |
| GET | `/binflow/api/search/gavc` | `g=/a=/v=/c=`（至少一）、`repos=` | Maven 坐标检索（布局路径形态匹配） |
| GET | `/binflow/api/search/prop` | `props=k[=v]` 或任意 `?k=v`（`repos` 保留） | 按属性检索（键无值 = 键存在性） |
| GET | `/binflow/api/search/pattern` | `pattern=<repo-glob>:<path-glob>` | 按路径模式检索（`*`/`?` SQL 语义，跨段） |
| GET | `/binflow/api/search/props\|users\|artifactory\|badge` | — | **404** 有意不做（`prop` 是官方单数拼写，复数 404） |

搜索结果 envelope `{"results":[FileInfo…]}`（含 `uri`/`downloadUri`）、按调用者权限过滤、未命中一律 200 `results:[]`、上限 1,000 行 + `X-Binflow-Search-Truncated` 截断头。

## uploads 域（MPU；数据端点仅纯 S3 后端）

| 方法 | 路径 | 语义 |
|---|---|---|
| POST | `/binflow/api/v1/uploads/create?repoKey=&repoPath=&partSizeMB=` | 开会话（QueryParam 非 JSON；**200 `{"token": ...}`**） |
| GET | `/binflow/api/v1/uploads/config` | 能力探测：**200 `{"supported": bool}`**（S3 栈 true / filestore false——探测端点不回 501） |
| POST | `/binflow/api/v1/uploads/urlPart?partNumber=N` | 第 n 片上传 URL（Bearer 会话 token；URL 自带 `?token=` 能力） |
| PUT | `/binflow/api/v1/uploads/part/{id}/{n}?token=` | 传片（可乱序到达；服务端中继进 S3 multipart） |
| POST | `/binflow/api/v1/uploads/status` | 异步进度：`{status, error, progress, checksumToken}`；status ∈ PARTS/PROCESSING/FINISHED/NON_RETRYABLE_ERROR |
| POST | `/binflow/api/v1/uploads/complete?sha1=` | 提交组装（sha1 40 hex 必填）→ **202 受理**异步 |
| POST | `/binflow/api/v1/uploads/abort` | 弃置会话 → 204 |

流程：create 拿 token → urlPart/PUT 分片 → `complete?sha1=` 202 → 轮询 status 至 FINISHED 拿 `checksumToken` → 客户端凭它做零传输 `X-Checksum-Deploy` PUT 落节点。会话跨重启存活。filestore/双写实例的数据端点恒 **501 纯文本**（非 404）。

## 三种认证方式

### Basic 认证

curl、CI 脚本、客户端凭据配置（settings.xml、`.pypirc`、npm `_auth`）。REST 层要求凭据始终在请求中——**不存在「先访问后挑战」**（一次性失败直接 401）：

```bash
curl -su admin:<口令> $BASE/binflow/api/system/ping
```

口令哈希为 **argon2id**（memory-hard），高并发场景请用 Token。

### Token 认证（Bearer）

高 QPS、CI/CD、无浏览器场景。Token 校验不触发 argon2 计算：

```bash
TOKEN=$(curl -su admin:$ADMIN_PW -X POST $BASE/binflow/api/security/token \
  -d 'grant_type=client_credentials&username=ci-bot' | jq -r '.access_token')
# 200: {"access_token":"<64hex>","token_id":"<id>","expires_in":2592000,"scope":"api:*"}
curl -s -H "Authorization: Bearer $TOKEN" $BASE/binflow/api/v1/storage/stats
curl -su admin:$ADMIN_PW -X POST $BASE/binflow/api/security/token/revoke \
  -d "token_id=<token_id>"
```

| 属性 | 值 |
|---|---|
| token 形态 | 64 位 hex（256-bit）；默认 TTL 2592000 秒（30 天），`auth__token_default_ttl_hours` 可调 |
| 签发 | admin 为任意用户；非 admin 限本人；可选 step-up 二次认证（见 [Token 指南](/admin/tokens)） |
| 吊销 | admin only；docker token 同表——吊销对 docker token 即时生效 |

### 会话 Cookie（浏览器端）

服务端签发 `binflow_session`（HttpOnly; Path=/binflow; SameSite=Lax）；TTL 默认 24 小时，**活跃不能续期**（绝对 TTL 封顶）：

```bash
curl -s -c jar.txt -X POST $BASE/binflow/api/v1/session \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"<口令>"}'    # 200 {"username":"admin","admin":true}
curl -s -b jar.txt $BASE/binflow/api/v1/session    # whoami
```

**CSRF 防护**：会话 cookie 认证的非 GET/HEAD 写请求携带非同源 `Origin` 头 → **403**；Basic/Token 免疫。

## 请求/响应头参考

### 请求头

| 头 | 场景 | 说明 |
|---|---|---|
| `Authorization: Basic / Bearer` | 全部管理面 + 内容路径 | 认证 |
| `X-Checksum-Sha1/-Sha256/-Md5` · `X-Checksum` | PUT 上传 | 客户端声明校验和 |
| `X-Checksum-Deploy: true` | PUT 上传 | checksum-only 部署（不传 body） |
| `Expect: 100-continue` | PUT 上传 | 去重加速：先查 blob 是否存在 |
| `X-Explode-Archive[: true]` / `X-Explode-Archive-Atomic` | PUT 上传 | 解包部署 |

### 响应头

| 头 | 场景 | 说明 |
|---|---|---|
| `X-Checksum-Sha1/-Sha256/-Md5` | GET 下载 | 服务端实测校验和（有值才发） |
| `ETag: <sha1>` | GET 下载 | 不包围引号；条件请求 `If-None-Match` |
| `Last-Modified` / `Accept-Ranges: bytes` | GET 下载 | RFC1123 / Range 支持 |
| `X-Artifactory-Filename` | GET 下载 | URL-encoded 文件名 |
| `Location` | PUT 成功 | 新资源 URL |
| `X-Binflow-License-Required: <addon>` | 门控写拒绝 | license 门控标记 |
| `X-Binflow-Cache` / `X-Binflow-Resolved-From` / `X-Binflow-Upstream-Error` | remote/virtual 读 | 缓存状态 / 解析成员 / 上游故障 |
| `X-Binflow-Search-Truncated: true` | 搜索截断 | 结果超 1,000 行 |

## 审计日志查询参数

`GET /binflow/api/v1/audit`：

| 参数 | 说明 |
|---|---|
| `repo` / `actor` / `action` | 等值过滤（action 词表见[治理](/admin/governance)） |
| `since` / `until` | RFC3339；闭开区间 `[since, until)` |
| `limit` | 默认 100，上限 1000（超限 400） |
| `cursor` | 游标分页（`nextCursor` 回传）；结果按时间倒序 |

## GC 触发参数

`POST /binflow/api/v1/system/gc`（admin only）：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `apply` | bool | false | false=dry-run；true=实际执行 |
| `graceHours` | number | 配置值（默认 24） | 宽限期；0=无宽限；负值或 >876000 → 400 |

响应：dry-run `{"candidateCount":5,"candidateBytes":204800,"deletedCount":0}`；apply 的 `deletedCount` 为实际删除数。
