# Docker 运行

BinFlow 提供两个镜像变体，均以非 root 用户运行、多架构（linux/amd64 + linux/arm64）：

| 变体 | 镜像标签 | 特点 |
|---|---|---|
| **alpine**（默认） | `binflow:v1.0.0-alpine` | 基于 alpine:3.24，含 shell + wget（HEALTHCHECK）+ ca-certificates + tzdata |
| **distroless** | `binflow:v1.0.0-distroless` | 基于 distroless/static-debian13:nonroot，**无 shell**，最小攻击面，Go 探针二进制做 HEALTHCHECK |

## 前置要求

- Docker >= 24.0
- 拉取镜像：`docker pull ghcr.io/lzwzzy/binflow:v1.0.0-alpine`（或 `-distroless`）

## 快速启动

```bash
docker run -d \
  --name binflow \
  -p 127.0.0.1:8080:8080 \
  -e BINFLOW_ADMIN_PASSWORD=change-me \
  -v binflow-data:/var/lib/binflow \
  ghcr.io/lzwzzy/binflow:v1.0.0-alpine
```

| 参数 | 说明 |
|---|---|
| `-p 127.0.0.1:8080:8080` | 绑定 loopback——BinFlow 仅 HTTP，绑定到非 loopback 前请确保在可信网络内（或前置 TLS 反代） |
| `-e BINFLOW_ADMIN_PASSWORD` | 管理员初始密码（**必填**，env-only，永不进入 YAML） |
| `-v binflow-data:/var/lib/binflow` | 持久化数据卷（blobs + SQLite + sessions） |

distroless 变体同参数换标签即可——无 shell，无法 `docker exec` 调试，HEALTHCHECK 由内置探针 `/usr/local/bin/healthcheck-probe` 完成。

## 验证

```bash
docker ps --filter name=binflow      # STATUS 显示 "(healthy)"
curl -s http://127.0.0.1:8080/readyz  # ok
docker logs -f binflow
```

## 自定义配置与资源限制

配置项均经环境变量传入（全大写、点改下划线、双下划线分隔层级）：

```bash
docker run -d --name binflow \
  -p 127.0.0.1:8080:8080 \
  -e BINFLOW_ADMIN_PASSWORD=my-secret \
  -e BINFLOW_SECURITY_ANONYMOUS_ACCESS=false \
  -e BINFLOW_LOGGING__LEVEL=debug \
  -e BINFLOW_AUTH__TOKEN_DEFAULT_TTL_HOURS=168 \
  --cpus 2 --memory 1g \
  -v binflow-data:/var/lib/binflow \
  ghcr.io/lzwzzy/binflow:v1.0.0-alpine
```

## 从源码构建镜像

```bash
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -f deploy/release/Dockerfile.alpine \
  -t binflow:v1.0.0-alpine \
  --build-arg BINFLOW_VER=v1.0.0 \
  --build-arg BINFLOW_REVISION=$(git rev-parse --short HEAD) \
  .
```

构建上下文必须是仓库根目录（distroless 换 `Dockerfile.distroless`）。

## 卸载

```bash
docker stop binflow
docker rm binflow
docker volume rm binflow-data   # 删除数据卷（谨慎）
```
