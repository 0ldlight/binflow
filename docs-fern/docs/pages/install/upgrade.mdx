# 升级

BinFlow 使用 [semver](https://semver.org/)：**MAJOR** = 不兼容变更、**MINOR** = 兼容功能新增、**PATCH** = 兼容缺陷修复（预发布标签如 `v1.0.0-rc.1`）。

升级策略一句话：**同 MAJOR 用二进制/镜像替换 + 启动时自动迁移；跨 MAJOR 用 export/import**。

## 各部署方式的升级命令

### 二进制 / systemd

```bash
# 1. 备份（建议）
binflow-server export -c binflow.yaml --output /backup/bf-pre-upgrade

# 2. 下载新版本并校验（见单二进制安装篇）
# 3. 停机 → 替换二进制 → 启动 → 验证
sudo systemctl stop binflow
sudo cp binflow-server /usr/local/bin/binflow-server
sudo systemctl start binflow
curl -s http://127.0.0.1:8080/readyz    # ok
```

### Docker / compose

```bash
docker pull ghcr.io/lzwzzy/binflow:v1.0.1-alpine
docker compose -f deploy/compose/docker-compose.yml up -d --build
curl -s http://127.0.0.1:8080/readyz
```

### Helm

```bash
helm upgrade binflow ./charts/binflow \
  --set image.tag=v1.0.1-alpine \
  --set admin.password=$(kubectl get secret binflow-secret -o jsonpath="{.data.BINFLOW_ADMIN_PASSWORD}" | base64 -d)
kubectl rollout status deployment/binflow
```

### 原生 K8s

```bash
# 编辑 kustomization.yaml / deployment.yaml 中 image tag
kubectl apply -k deploy/k8s/ && kubectl rollout status deployment/binflow
```

## 元数据自动迁移

服务端启动时自动执行元数据迁移（幂等可重入；执行失败则进程退出不启动服务；日志可见 `applied migration NN`）。迁移文件按编号顺序执行，全部向后兼容（仅加表、加列、加索引、回填数据）：

| 编号 | 说明 |
|---|---|
| 001 | 初始 schema：repositories、blobs、nodes、users、tokens、permission targets、audit 等 |
| 002 | Docker 域：docker_manifests、docker_tags、docker_refs |
| 003 | Remote 域扩展：TTL/私网放行字段、缓存过期索引、blobs sha1 索引 |
| 004 | 控制台/治理域：users email、groups、user_groups、web_sessions、repo_usage |
| 005 | 配额回填（nodes SUM → repo_usage） |
| 006 | user_groups(username) 索引 |
| 007 | 文件夹行回填（目录级节点物化） |

当前仅 SQLite 驱动支持（Postgres 目录为占位）。

## 跨大版本：export/import

元数据格式不兼容时（MAJOR 升级），export/import 是**唯一**迁移路径：

```bash
binflow-server export -c old-binflow.yaml --output /backup/bf-v1-data
sudo systemctl stop binflow
rm -rf /var/lib/binflow/data && mkdir -p /var/lib/binflow/data
binflow-server import -c new-binflow.yaml --input /backup/bf-v1-data --verify full
sudo systemctl start binflow
```

直接替换二进制靠自动迁移只适用于同 MAJOR 的 MINOR/PATCH 升级。

## 回滚与建议流程

```bash
sudo systemctl stop binflow
sudo cp /usr/local/bin/binflow-server.bak /usr/local/bin/binflow-server
sudo systemctl start binflow
```

注意：若新版本执行了不可逆迁移，回滚旧版本可能启动失败——生产升级前务必 export 备份。

建议流程：阅读 Release Notes → export 备份 → staging 先行 → 停机窗口（MINOR/PATCH 秒级；MAJOR 与数据量正相关）→ `/readyz` 200 + 制品 PUT/GET 烟测 → 保留旧二进制与备份作回滚预案。
