# NuGet 接入（v3 / v2）

BinFlow 同时提供 **v3 主面**（service index / flatcontainer / registration / search / publish——`dotnet` 与现代客户端走这里）与 **v2 全路由面**（OData 18 端点——nuget.exe 2.x 与老工具链走这里）。`dotnet` 工作流只需一个 `nuget.config`。

> nuget 包型为 **pro 档**能力——建仓/推送需 pro 及以上 license；未解锁时既有包仍可还原。

## URL 形态

| 平面 | 地址 |
|---|---|
| v3 service index | `$BASE/binflow/api/nuget/v3/<repoKey>/index.json` |
| v2（OData）base | `$BASE/binflow/api/nuget/v2/<repoKey>`（GET 根 = service document；PUT 根 = v2 直推） |

v3 index 自述全部资源端点（含 `registration-semver2` 行）——客户端只认 index 里的 `@id`，无需手拼其余 URL。

## 接入步骤

### 1. 创建仓库

```bash
curl -su admin:$ADMIN_PW -X PUT $BASE/binflow/api/repositories/nuget-local \
  -H 'Content-Type: application/json' \
  -d '{"rclass":"local","packageType":"nuget"}' -o /dev/null -w '%{http_code}\n'    # 200
curl -su admin:$ADMIN_PW -X PUT $BASE/binflow/api/repositories/nuget-remote \
  -H 'Content-Type: application/json' \
  -d '{"rclass":"remote","packageType":"nuget","url":"https://api.nuget.org/v3/index.json"}' \
  -o /dev/null -w '%{http_code}\n'    # 200
curl -su admin:$ADMIN_PW -X PUT $BASE/binflow/api/repositories/nuget-virt \
  -H 'Content-Type: application/json' \
  -d '{"rclass":"virtual","packageType":"nuget","members":["nuget-local","nuget-remote"]}' \
  -o /dev/null -w '%{http_code}\n'    # 200
```

### 2. 写 nuget.config（源映射 + 凭据）

放解决方案根目录（与 `.sln` 同级）：

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <clear />                                    <!-- 断开 nuget.org 缺省源：解析全走 BinFlow -->
    <add key="binflow"
         value="http://localhost:8080/binflow/api/nuget/v3/nuget-virt/index.json" />
  </packageSources>
  <packageSourceCredentials>
    <binflow>
      <add key="Username" value="admin" />
      <add key="ClearTextPassword" value="<你的管理员口令>" />
    </binflow>
  </packageSourceCredentials>
</configuration>
```

- 凭据是 Basic（push/restore 自动携带）；只读场景若匿名读开启可省 `packageSourceCredentials`。
- `ClearTextPassword` 为明文——CI 上建议用环境变量扩展或用户级加密配置。

### 3. 推送、还原与上游包

```bash
dotnet pack -c Release
dotnet nuget push bin/Release/Acme.Lib.1.0.0.nupkg --source binflow
# 已推送包。（201 + Location；包上限 512MiB；服务端生成 .nuspec 与 .nupkg.sha512 sidecar）

cd ../Consumer
dotnet add package Acme.Lib --source binflow       # 无版本号走 search 面解析最新
dotnet add package Newtonsoft.Json --version 13.0.2 --source binflow   # 上游包经 remote 缓存
dotnet restore && dotnet run
```

remote 拉取的 registration 文档由 BinFlow 重写为本仓地址；`packageHash`（SHA-512）随包校验。上游临时故障时已缓存的 registration 与包照常服务；第二次 restore 起零上游流量。

## 重复推送臂（v2/v3 两面同语义、字节盲）

| 形态 | 响应 |
|---|---|
| 同 id/version 已存在，当前用户无 `delete` 权限（同字节或异字节） | v3：**409** `A package with the provided ID and version already exists`；v2：**409** `Package already exist: <deployPath>` |
| 同 id/version 已存在，有 `delete` 权限 | 覆盖 → **201** |
| 新包 | **201** |
| remote 仓 | v2：400 `This operation can only be performed on local repositories.`；v3：405 |
| virtual 未配 `defaultDeploymentRepo` | 400（v2）/ 路由拒绝（v3） |

客户端提示：`dotnet nuget push --skip-duplicate` 只跳过 409——CI 对同一版本重复推包时用它避免流水线红灯。

## v3 行为速查

| 端点（相对 v3 仓面） | 行为 |
|---|---|
| `<id>/index.json` | 版本清单（local=事实生成 / remote=透传 / virtual=成员并集）；id 键**小写折叠**（`Acme.Lib` → `acme.lib`），展示名保留原大小写 |
| `<id>/<ver>/<id>.<ver>.nupkg` | 包文件下载；同名 `.nupkg.sha512`/`.nuspec` 可直取；与 v2 `Download` 面缓存互通 |
| `SearchQueryService`（`q`/`take`/`skip`/`prerelease`/`semVerLevel`） | local = 存储事实；remote = **上游实时代理**；virtual = 两源合并 |
| registration / `registration-semver2` | `semVerLevel=2.0.0` 的结果与链接指到 semver2 基 |
| 版本归一化 | 补零到三段、prerelease/build 小写（`1.0` → `1.0.0` 寻址） |
| DELETE（包或版本） | **硬删**版本目录，无 listed/unlisted 位 |

remote search 代理要点：上游 service index 缓存 → 定位 `SearchQueryService` @id → 带 `q/skip/take/prerelease/semVerLevel` 直连上游（不落盘）→ 结果 URL 改写为本仓 v3 基。上游不可达 → 贡献空（200 `totalHits:0`，不 5xx）；**搜索出站不带上游凭据**——带凭据源（如 Azure Artifacts）搜索回落空集，包下载/还原不受影响。

## v2 全路由面（老客户端）

base = `$BASE/binflow/api/nuget/v2/<repoKey>`，OData Atom feed：

| 端点（相对 base） | 行为 |
|---|---|
| `GET /`（service document）/ `GET /$metadata` | workspace 形状 / EDMX（含 Search/GetUpdates FunctionImport） |
| `GET /Search()` ± `/$count` | 行管线与 Packages 共享；**空集 → 404**（OData 语义） |
| `GET /FindPackagesById()?id='<小写id>'` ± `/$count` | **缺 id 参数 → 404**（非 400）；未知 id → 200 空 feed |
| `GET /Packages()` | 全 feed；`(Id='',Version='')` 单条目未命中 404；`()/$count` 计数 |
| `GET /GetUpdates()/?…` | **服务端过滤**（严格大于基准版本、预发布默认滤、`versionConstraints='[a,b)'` 范围） |
| `POST /$batch` | 202 + `multipart/mixed`；不支持形态整批 400 `Unsupported batch entry.` |
| `GET /Download/{id}/{version}` | 包文件下载（v3 缓存互通） |
| `DELETE /{id}/{version}` | 200 `Successfully removed '<path>'` / 404 / 无删权限 403 |
| `PUT /`（multipart，字段名 `package`） | 201 `Successfully published NuPkg to: <path>`；**落点差异**：BinFlow 落 canonical flatcontainer 三件套（非仓根扁平布局） |

**semVerLevel 过滤语义**：SemVer2-only = 点分预发布标识（≥2 个点分段，如 `alpha.1`）或含 build metadata；`3.0.0-alpha` 等 v1 形预发布在默认档可见。

## 符号服务器边界

BinFlow **不提供符号服务器**：`.pdb` 的 SYMSRV 路径与 `.snupkg` 端点未实现（404）。`.nupkg` 内嵌文件（含随包打入的 pdb）随包原样存取不受影响。

## 常见报错对照

| 症状 | 原因 | 处置 |
|---|---|---|
| 建仓 400 `package type 'nuget' is not available ...` | community 档 | 装 pro/enterprise license |
| push 403 + `X-Binflow-License-Required: nuget` | license 写门；restore/读不受影响 | 重装 license |
| push 401 | 匿名写被拒 | 补 `packageSourceCredentials` |
| push 400（id/version 校验） | nuspec 与寻址形态不一致 / 包损坏 / nuspec 超 4MiB | 重新 `dotnet pack` |
| push 409 | 同 id/version 已存在且无 `delete` 权限（**字节盲**） | 升版本；先 DELETE；授 delete 覆盖；CI 用 `--skip-duplicate` |
| `dotnet add package` 搜索为空（200 `totalHits:0`） | 上游不可达或带凭据源搜索回落空集 | 检查上游；带 `--version` 走版本清单（不依赖搜索） |
| 版本寻址 404 | 未做归一化（用 `1.0` 寻址存储为 `1.0.0`） | 用三段版本 |
| v2 `Search()` 空集 404 / `FindPackagesById()` 缺 id 404 | OData 语义 | 核对 id 拼写（小写）；单包探测用 `FindPackagesById()?id=` |
