# Token 与二次认证（step-up）

Token 的日常使用（签发/吊销/高 QPS 场景）见 [API 参考 · 认证](/api-reference)；本篇讲**从控制台会话铸造 Token 的二次认证门（step-up）**。

## step-up 解决什么问题

web session cookie 本身就是完整的 bearer 证明。若浏览器 session 被盗（XSS / 离机未登出），攻击者可立即用该 cookie 铸一枚**最长 365 天**的 API Token——把小时级的劫持窗口升级为季度级持久化立足点。

step-up 在 `POST /api/security/token` 上加一道**第二因子门**：session cookie 可用 ≠ 可铸 Token，铸造还需重验口令（本地/LDAP）或 IdP 新鲜重认证（OIDC）。**默认关闭**——不开开关，一切行为不变。

## 开关键

| 键 | 类型 | 默认 | 校验 |
|---|---|---|---|
| `auth.token_step_up` | bool | **false** | 不配置 = 全部行为不变（含既有脚本） |
| `auth.token_step_up_grant_ttl_seconds` | int | 300 | 域 **[60, 3600] 闭区间**，越界**无条件拒启动**（开关 off 也拒） |

```yaml
auth:
  token_step_up: true
  token_step_up_grant_ttl_seconds: 300
```

环境变量双拼写等价：`BINFLOW_AUTH_TOKEN_STEP_UP=true` 或 `BINFLOW_AUTH__TOKEN_STEP_UP`（TTL 键同形）。

## 作用域：谁触发、谁豁免

触发条件 = **web session cookie 认证** × **非 admin 角色** × **开关开启**，三者同时成立。

| 认证臂 | 触发？ | 说明 |
|---|---|---|
| web session（本地 / LDAP 用户） | **是** | body 携 `step_up_password`（本地 argon2 / LDAP bind 重验，与登录同源） |
| web session（OIDC 用户） | **是** | body 携 `step_up_grant`（见下文） |
| web session（**admin** 角色） | 否 | admin session 免——首因子已是全权 |
| Basic / Bearer / docker `/v2/token` | 否 | CI/脚本主路径完全不受影响 |
| 匿名 | 否 | 路由 401 挑战在 step-up 之前 |

两点边界：**readonly_admin 不豁免**（豁免的是 admin 角色）——其 session 自铸同样要过 step-up；门位在 TTL 护栏**之前**——step-up 通过后护栏照常生效（如非 admin 请求 `expires_in` > 365d 仍 401）。

## 本地与 LDAP 腿：step_up_password

```bash
export BASE=http://localhost:8080

# 1) 登录取 session cookie
curl -s -c cj-dev1.txt -X POST $BASE/binflow/api/v1/session \
  -H 'Content-Type: application/json' \
  -d '{"username":"dev1","password":"<dev1口令>"}' -o /dev/null -w '%{http_code}\n'   # 200

# 2) 无凭据铸 → 401 step_up_required
curl -s -b cj-dev1.txt -X POST $BASE/binflow/api/security/token \
  -d 'grant_type=client_credentials' -w '\nHTTP %{http_code}\n'
# {"error":"step_up_required","error_description":"step-up authentication required to mint a token"}

# 3) 对口令 → 200（错口令 → 401 step_up_invalid）
curl -s -b cj-dev1.txt -X POST $BASE/binflow/api/security/token \
  -d 'grant_type=client_credentials&step_up_password=<dev1口令>'
# {"access_token":"<64hex>","token_type":"Bearer","expires_in":2592000,"scope":"api:*"}
```

LDAP 腿同形：同一字段走 LDAP bind 重验。目录停机与口令错误对外同形态 401 `step_up_invalid`（不区分原因）。

## OIDC 腿：prompt=login 重认证换 mint grant

OIDC 用户没有本地口令——第二因子是 **IdP 新鲜重认证**：

1. `GET /api/v1/oidc/login?purpose=step_up` → 302 到 IdP，强制 `prompt=login`（IdP 必须重新问凭据，不吃 SSO 会话）；
2. 用户在 IdP 重新提交口令；
3. callback 不建新 session（重认证主体必须与当前 session 同人），签发 **mint grant** → 302 `/binflow/ui/#step_up_grant=<64hex>`（URL fragment 承载，不进服务端与代理日志）；
4. 携 grant 铸造：`POST /api/security/token` body `grant_type=client_credentials&step_up_grant=<grant>`（同一 session cookie）。

grant 契约：opaque 64 位 hex（服务端只存 sha256）；绑定 `{username, session_id}`；**单次消费**（复用/错绑定/过期一律烧掉）；TTL 默认 300s；台账在进程内存——**服务重启丢失**（用户重走 re-auth）。

**SSO 用户的三条现实路径**：控制台 Set Me Up 自动分腿（推荐，见[控制台](/admin/console)）；脚本驱动 re-auth 流（cookie jar + IdP 表单 POST + 立即铸造，可 headless 自动化）；admin 代铸（`grant_type=client_credentials&username=<目标>`，admin 臂免 step-up）。

> 错腿凭据按「所欠凭据缺失」判：OIDC 用户交 `step_up_password` → 401 `step_up_required` 而非 `step_up_invalid`——不借此泄露「该用户的腿是什么」。

## 401 step_up_invalid 的全部场景

| 成因 | 说明 |
|---|---|
| 口令失验 / grant 不存在 | 本地 argon2 / LDAP bind 不过、grant 拼错 |
| **grant 已被消费** | 单次性——同一 grant 第二次铸造即烧 |
| grant 过期 | 超出 TTL 窗口 |
| 服务重启 | grant 台账在进程内存，重启即空 |

## 审计

step-up 路径铸造的 `token.issue` 事件 detail 增两个维度（仅 step-up 路径出现，豁免臂不写）：`step_up: true` + `step_up_method`（闭集两值：`password`（本地与 LDAP）/ `oidc_reauth`）。

## 常见报错对照

| 症状 | 原因 | 处置 |
|---|---|---|
| 401 `step_up_required` | 所欠凭据缺失；**或交了错腿的凭据** | 按腿补字段；OIDC 用户先走 re-auth 流 |
| 401 `step_up_invalid` | 口令失验 / grant 过期 / **grant 复用** / 服务重启 | 见四成因表；grant 一次性 |
| 401 `invalid_request` + `... expires in larger than 0 and smaller than 31536000 seconds ...` | **不是 step-up 报错**——TTL 护栏拒了 `expires_in`（>365d 帽） | 调低 `expires_in` |
| 403 `administrator privileges required` | 非 admin 为**他人**铸（step-up 之后才判） | 仅限本人；为他人铸走 admin |
| 启动失败 `... must be within [60, 3600] seconds` | TTL 越界（开关 off 也拒） | 取值落回区间 |
| CI 里 Basic 铸 Token 突然 401 `step_up_*` | 不可能由 step-up 引起（Basic 臂豁免） | 核对口令本身 |
