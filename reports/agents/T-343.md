- **folderDownloadConfig 六默认**（§2.1 逐字）：enabled=false / enabledForAnonymous=false / maxDownloadSizeMb=1024 / maxFiles=5000 / maxConcurrentRequests=10 / enabledEmptyDirectories=false。落在 service 字段 + `repo.ConfigureFolderDownload(svc, cfg)`（AttachReplicator 式装配缝）；**热更新未实现**（BinFlow 无热加载配置面——重启/预服务生效，登记分歧）。
- **执行序照 §2.2 模板逐条**：匿名门 401（先于 archiveType 解析，测试固化）→ archiveType 必填枚举 400 → 仓资格（missing 404 `is not a repository.`；非 local 404 `only available for local (or cache) repositories`；BinFlow 无 cache rclass，remote/virtual 同判）→ 路径资格（缺失 404 / 是文件 400，逐字）→ 读权限 403（逐字）→ 总开关 403（逐字）→ 预统计（文件数/总字节数，MB 两位小数逐字）→ 并发槽 400（逐字；chan 信号量，body Close 释放）→ **流式打包不落盘**（io.Pipe + goroutine，zip=Deflate / tar / tar.gz|tgz=gzip）。
- `includeChecksumFiles=true`：从 blobs 台账**生成** `.sha1/.md5/.sha256` 伴随条目（BinFlow 无边文件——ADR-0006；登记为本条目的 BinFlow 语义）。

- 例外未实现（登记）：`jfrog-support-bundle` 豁免（BinFlow 无此仓）、Xray 403（无 Xray）。

### 2. `archive!/` 成员读取 —— `GET /binflow/{repo}/{archive}!/{entry}`（内容面）
- **dispatchContent 顶层拦截**（先于 adapter 分发——`!/` 寻址是跨协议形态，不归任何包型），**解码后**按**首个 `!/`** 切分；成员路径内再遇 `!/` 递归下钻（嵌套归档：中间层有界缓冲 256MiB——BinFlow 自有上限，登记——外层始终流式）。
- **strictArchiveDotSlash 默认 true 由构造满足**：本路由从不折叠点段（router.go 包注释的既定立场），成员名逐字匹配——`./strict.txt` 只匹配 `./strict.txt`，折叠形 404（测试固化）。
- **成员 checksum 后缀**：`…!<entry>.sha1|.md5|.sha256` → 按需流式计算返回裸 hex（无尾换行，登记）；与真实名为 `x.sha1` 的成员不可区分（规格中置信，登记）。
- 解析**骑 s.Get（归档路径）**：读权限（401 匿名/403 认证）、remote 拉取、virtual 成员路由、DOWNLOAD 审计行全部继承；**V-6 负向断言成立**：BinFlow 无 `archiveBrowsingEnabled` 类开关，成员读取仅受归档路径读权限约束（代码注释+测试钉住）。
- 读扩展集 = zip 家族（zip/jar/war/ear/nupkg/conda/apk，同容器格式）+ tar 家族（tar/tar.gz/tgz）；**bz2/xz/7z 不支持**（V-4 开放，Go 标准库无 reader；白名单外答 §4.1 同款 400，登记分歧）。
- 404 逐字：`Unable to find zip resource: '<entry>' using full URI '<uri>'` / `Failed to get zip resource: '<path>'`；非 GET → 405 `Allow: GET`（规格只列 GET，登记）。

### 3. explode —— `PUT /binflow/{repo}/{path}` + `X-Explode-Archive[: true|-Atomic: true]`
- **M10 E-25 断言反转**：router 在 RBAC 写门与包型门之后、adapter 之前拦截两个触发头——经完整服务的 PUT 现在接受并解包；generic/maven 适配器内部的 400 死臂未动（area 纪律，经 router 已不可达；裸挂载测试仍钉住旧行为，见遗留②）。头值非 true/false 拼写 → 显式 400（不半选分支，登记）。
- **白名单 = PRD 四类闭集**（zip,tar,tar.gz,tgz）；白名单外/无扩展名 → §4.1 逐字 400；PUT 路径尾斜杠 → 逐字 `Explode archive deployment failed, Missing file name.`。
- 执行：临时文件 `to_extract_*` 落盘 → 单遍流式解包（zip 走中央目录惰性开、tar/tar.gz 边扫边部署）→ **逐条目经 svc.Put 落库**（权限对/配额/审计/复制钩子全链随行）→ **归档文件本身不落库**（测试断言 404）。
- 排除项：首段 `.jfrog` 系统文件、文件名含 `maven-metadata.xml`（静默跳过 debug）；**zip-slip 防御**（`../`、绝对、空段条目 → 整单 400，BinFlow 安全新增，登记）。
- 权限：目标父目录 w 预检 → §4.2 逐字 403 `User is not authorized to deploy to specified repo path.`；匿名 401；remote 目标吃写面 RE-05 405（登记）。
- 失败映射：IO/流 → 404 逐字 `Explode archive deployment failed. View log for more details.`；坏归档 → 400（措辞 BinFlow 自拟，规格未载，登记）；**非原子模式 accumulate-then-answer**（条目失败记录后继续，首个错误定响应码，部分落地保留——statusHolder 姿态）；**Atomic = 全有或全无**（补偿式回滚已落地条目——Put 无跨调用事务，登记）。
- **V-1 定案：201 + 空体**。规格优先级裁决：官方文档 201 > 反编译隐式 200（响应基类默认、未显式设置）；且与 BinFlow 自有 PUT 201 惯例一致。**无活体 Artifactory 可达**（环境无实例），按"文档优先"定案并在此留痕；成功响应另带 `X-Binflow-Exploded-Files: <n>` 计数头（BinFlow 新增）。
- threads 固定 1（规格默认；>1 双批并行不实现，登记）；60 分钟超时旋钮不实现（同步执行，登记）。
