# T-474 — helm classic PUT 在 read-only /tmp 下 500（spool 落盘位置错误）

状态：done（等收编；零 git 操作）
area：`internal/adapter/helm`（+ 共享原语 `internal/adapter/spool.go`，+ `cmd/binflow-server/main.go` 一行接线——见「交错与归一」）

## 1. 根因

`internal/adapter/helm/handler.go` 的 `spoolBody`（原 L489）用 `os.CreateTemp("", "binflow-helm-*.tgz")`
把 PUT 的 chart body spool 到 **OS 临时目录**。硬化部署（read-only rootfs，k8s 常态）下
`/tmp` 不可写，UAT 实测（52.79.109.153:8080，2026-09-04 21:0x）：

```
$ curl -su admin:password -T matrix-chart-1.0.99.tgz http://52.79.109.153:8080/binflow/uat-matrix-helm-local/matrix-chart-1.0.99.tgz
spool request body: open /tmp/binflow-helm-984094729.tgz: read-only file system   → HTTP 500
```

错误文案把内部路径原样泄给客户端（裸 `err` 直灌 writeText）。CI 十协议矩阵 helm 腿因此红
（GH run 33866554682 leg/helm）。

**对三疑点的判定**（部署二进制装配 / 路由链 / staging 卷）：事故错误文本本身就是证据——
`open /tmp/binflow-helm-*.tgz` 只能出自旧代码 `os.CreateTemp("")`，旧代码根本没有 staging 目录
概念；装配链与路由无涉。修复后 spool 根为 `filepath.Join(cfg.Storage.DataDir, "staging")`，
DataDir 由 config 校验强制非空（`ValidateDataDirFailures` 钉死），不存在「运行时 dir 空」路径。

## 2. 方案选型：为何 staging 卷而非配置 TMPDIR

- **TMPDIR 指到数据卷**（被否）：仍是 OS-temp 语义——依赖运维记得在每个部署里注入 env；
  容器里 TMPDIR 指向的卷与 blob 卷可以不同，跨卷 rename 失效、磁盘配额分裂；且不解决
  「TMPDIR 未设」的默认 /tmp 陷阱。
- **storage 会话复用**（被否）：`Engine.BeginSession` 的 `uploads/<id>/` 有 DB 行 + sweep
  生命周期，spool 文件无行会被 orphan 扫描误删（in-flight 竞态）；改走 Session→Commit→
  Open→Put 需要新的 Service SPI（PutLandedBlob 不带 Properties/expect），P1 热修不做 SPI 手术。
- **采用：存储同卷 staging 目录**（`<data_dir>/staging`，rpm 的 `DataDir/.rpmcache` 同族先例）：
  与 blob 落盘同卷（disk 模式 = blob 根；S3 模式 DataDir 仍持有 binflow.db，必然可写，否则起不来）；
  每次上传 MkdirAll 一次（卷后挂自愈；失败统一走 507 拒绝面，不引入启动期依赖）。

## 4. 交错与归一（conductor 披露的另一 agent 残留）

并行同票 agent 死前在本票文件上留下第二种设计，检测到的残留与处置：

1. `handler.go`：两个错误常量被改成 `%v` 格式串但**调用点未改**（会向客户端输出字面 `%v`）——半成品设计，按归一裁决重写（507 + 有界披露，见上）。
2. `Options.SpoolDir` 注释尾句引用 `adapter.StagingDir`——与归一后实现一致，保留。
3. `internal/adapter/spool.go`/`spool_test.go`：完整但无生产调用方的孤儿原语——**收编**为本实现的地基（helm 改走它，孤儿消除）。
4. `spool_test.go` 的 `TestStagingRefusalNamesTheAttemptedRoot` 期望 `StagingDir` 在「已存在但不可写」的根上失败——错误期望（`MkdirAll` 对已存在目录是成功的 no-op，mkdir 探测不了写位）；已改为诚实契约：已存在不可写根在 `StagingDir` 通过、在 `StageFile` 的 CreateTemp 拒绝；不可创建的根（父目录只读）在 `StagingDir` 拒绝。
5. 其「staging dir 已在 main.go:487 接线但 UAT 运行时 dir 空」线索：经查旧 main.go 无任何 staging 接线（`helm.Options{BaseURL}` 仅此而已），该线索不成立（§1 判定）。

**路径披露自查**（吸收裁决的取舍结论）：修复前的泄漏是**临时文件名 + os 错误**（零诊断价值的噪音）；归一后 body 只点名**尝试的 staging 根**（运维配置值、可行动的唯一事实），临时文件名与 os 错误细节留在服务端日志。非「零披露」而是「有界披露」。
