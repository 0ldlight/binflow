## 关键决策（PRD 层面）

1. **双入口用「授权模型 + 错误体」两轴讲清**，不是简单加一条端点：管理面 admin-only（T-15/D3 裁决的既成事实）与 docker login 必须放行普通用户是硬约束——把两者并列为设计而非债务，并给出 D04c 的对照断言（同用户两入口 200/403），QA 可直接验证语义边界。
2. **offline_token 从严拒绝**：规格对 Artifactory 行为只有低置信度走读（未见专门分支），接受一个无语义参数不如明确 400——避免实现者猜。
3. **service 固定值而非 host 推导**：规格 §5.1 的 service=host 是 Artifactory 部署形态耦合，反代场景下挑战/签发两侧会不一致；spec 对值本体无约束，固定 `"binflow"` + 可配置最稳。
4. **4MB 上限定案记为 PRD 决策**（规格无值），不伪装成「按规格」——校准表里来源列如实区分「规格高置信度 / 规格低置信度 + PRD 决策 / PRD 定案」。
5. Q1 定案后**对比表保留为决策记录**而非删除（审计可溯），并新增「落地影响」三条，其中 M1 E-26 的 `/v2/` 断言反转已在 §8 剧本第 1 步提示 qa 更新回归基线。
