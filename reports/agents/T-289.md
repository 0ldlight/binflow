## 1. 端点清单（六端点 + urlPart 契约的 PUT 目标）

全部挂 `/binflow/api/v1/uploads`，路由门 `routeAuth{required}` + handler 内目标仓路径 `w`（§15.4「required + 目标仓 w」——内容面归属，非 CapSystemWrite；会话 id 为不可猜测 capability，§5.3.1 契约 4 同源）：

| 端点 | 方法 | 语义 | 关键裁定 |
|---|---|---|---|
| `/create` | POST | `{repoKey,path,partSizeMB?,mimeType?}` → 201 会话 + URL 族 | partSizeMB=0 取引擎默认 16MiB；<5MiB **clamp 到 5MiB 并如实回显**（resolveS3PartSize 同表）；>5GiB 400 fail-fast |
| `/config` | POST | `{sessionId,partSizeMB}` 重定分片 | 仅零字节会话可改（有字节 409）；实现 = 换引擎会话、**REST id（capability）保持不变**——非 inert 字段，真实生效 |
| `/urlPart/{id}/{n}` | GET | 返回 part n 的 PUT 目标 URL + 期望起始 offset | **URL 是 BinFlow URL**（见裁定 A） |
| `/status/{id}`、`/status` | GET | 单会话 / **list 形态**（bare 数组，BinFlow 自有臂） | 进度 receivedBytes/partsReceived/state |
| `/complete/{id}` | POST | `{sha256(必填),sha1?,md5?}` → Commit 校验 + PutLandedBlob 建 node → 201 | 错 sha256 → **409**（repo-semantics §5 客户端校验和姿态）且会话消费；Commit 后建 node 失败 → 5xx「safe to retry」（docker writeBlobCreated B4 同款） |
| `/abort/{id}` | POST | 丢弃会话与 S3 multipart 状态 → 204 | 会话离开注册表：后续 status/再 abort 404（AC1「abort 后 status 404」） |
| `/part/{id}/{n}` | PUT | urlPart 的目标：分片字节流 | 严格顺序（n=parts+1 否则 409）；Content-Length 必填（缺 → 411）；超 partSize 400 预拒；短 part = 终结片（state→awaiting-complete，后续 part 409）；offset 权威源 = `Session.Offset()`（[M7] 规则） |

会话生命周期：`active → awaiting-complete → completed`；任意 Append/Commit 失败 → `failed`（可观察、abort 回收）。空闲 24h（storage.DefaultSessionTTL）后台 sweep 回收，TTL/48 频率（docker sessionRegistry B2 同款）。

**filestore 诚实 501（FR-90-AC3）**：`Deps.Uploads` 未接线（filestore / dual-write）时六端点 + part + bare status 全部 **501 + text/plain**，body 含 `not supported on this backend` 与 `S3` 字样——按 conductor 指令纯文本、非 404 伪装；路由认证门在前（匿名 401 先于能力答复）。

## 2. 设计裁定（自有，待 architect 复核）

- **A. part URL 是 BinFlow URL，非 S3 presigned**：§15.4 明令「复用 storage.Session/ResumeSession 既有面——零存储层改动」。字节经 BinFlow 中继进 `Session.Append`（服务端 PutObjectPart），客户端零 S3 凭据、bucket endpoint 不暴露、sha256/sha1/md5 链服务端计算——与所有既有上传路径同构。PRD 90.1 的「(presigned)」按行为模式对齐（capability-by-id）而非字面 presigned；若 PM 坚持字面 S3 presigned 直传，需新 ADR（破坏零存储改动 + 引 SSRF/凭据面）。
- **B. create 限 generic local 仓**：协议仓（docker/maven/npm/pypi/go/nuget）的 layout 归各自 adapter 管，MPU 直落任意 node 会写出 layout 之外；generic local 是 MPU 的全部地址空间（400 点名「protocol repositories take their own upload paths」）。
- **C. AC2（kill -9 续传）不可达且按契约不做**：§15.4「零存储层改动」+ §5.3.1 契约 5（S3 ResumeSession 恒 ErrSessionNotFound，TestS3ResumeSessionNotSupported 钉死）+ §11.31 明文登记 S3 REST 续传为 M8+ 债（路径：upload ID 落表 + ListParts 重建）。本票如实呈现：kill -9 后 status 404（探针断言该**钉死现状**并注明翻转条件），S3 侧残留由引擎启动 sweep（T-203 D-6）+ TTL 回收。**AC2 需付 §11.31 债方能兑现——留给 conductor/PM 决断**。
- **D. config 语义自定**：inv-4 L3 仅证端点名（`MultipartUploadResource.java` @Path 列表），行为模式一句「可断点续传、按 node 查状态」。BinFlow 取「零字节会话重定分片」（换引擎会话、保 REST id），真实生效非 inert。
- **E. dual-write（MigrationEngine）也 501**：其写路径 front 的是磁盘半边；MPU 直写 S3 会绕过 dual-write 的一致性——缺 seam 即语义，非缺口（cmd 接线注释已述）。

## 3. 实现

**storage seam（最小扩展，零内核改动）**：
- `internal/storage/api.go`：`MultipartUploads` 接口（`BeginMultipartSession(ctx, partSize)`）——能力发现型接口，返回的就是既有 `Session`；doc 注明 S3 实现 / disk 有意不实现 / ResumeSession 契约不动。

- `internal/httpapi/router.go`：8 条路由臂（create/config/status×2/urlPart/complete/abort/part），全部 `required:true` + handler 内 `w`。

## 5. 真实客户端验证（协议票硬性要求）

`scripts/m10-mpu-probe.sh`（MinIO `minio/minio:latest` 容器 127.0.0.1:29000 + bucket `binflow-mpu` + 两个 scratch binflow-server 实例）——**全链 GREEN**：

1. **filestore 501 矩阵**（8 臂：create/config/urlPart/status/{id}/status 裸/complete/abort/part）：全 501 text/plain，body 同时含 `not supported on this backend` 与 `S3`。
2. **curl 全链**：create（partSizeMB=2→clamp 回显 5242880）→ urlPart(2)（URL + offset 5MiB）→ PUT 3 片（5+5+1MiB）→ status 进度 5242880→10485760→11534336、短终结片后 state=awaiting-complete → bare status list 含活跃会话 → **错 sha256 complete 409 + status 404** → 正 sha256 complete 201（size 回显 11534336）→ GET 制品 **sha256 逐字节对账一致**。
3. **abort**：上传 1 片后 abort 204 → status 404 → 制品 404（blob 不可见）。
4. **kill -9 + 重启**（同 data dir + 同 bucket）：会话 status 404（§11.31 钉死姿态，断言含翻转条件注释）；已 complete 制品仍 200。
5. **docker push 大镜像**（T-103/104 dind 手法：`docker:dind --insecure-registry=host.docker.internal:<port>`，宿主 daemon 零改动）：20MiB layer（> 16MiB 默认分片 → 真实 multipart）push → rmi → pull 回环，digest `sha256:6676911d…` 双侧一致（既有能力回归）。
6. **bucket 侧对账**（mc）：`blobs/f2/f284…`=11MiB（MPU 制品）、`blobs/1d/1df0…`=20MiB（docker layer）、`blobs/66/6676911d…`=406B（manifest，与 push digest 同值）；**无任何 `sessions/` 残留对象**（abort 清理干净）。
