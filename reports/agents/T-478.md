## ⚠️ 前置项（用户操作，DNS/防火墙归用户）——显著位置

在把本票合入 main 之前（或之后任何时候，见下方时序说明）需要：

1. **DNS A 记录**：`uat.binflow.org → 52.79.109.153`
   - binflow.org 的权威 NS 是 `ns1/ns2.hosting.businessidentity.llc`（DoH 实测，
     SOA serial 2026090414）——去**购买域名的 hosting 控制台**（businessidentity.llc）
     加这条 A 记录。TTL 建议先用 300。
   - 实测（2026-09-06，Cloudflare DoH）：`uat.binflow.org` 当前 **NXDOMAIN**
     （记录不存在）。本机 dig 不可信（本地 TUN 代理返回 198.18.x fake-ip），
     验证一律走 DoH。
   - 域名想换（不用 uat.binflow.org）：设 CircleCI env `UAT_DOMAIN=<域名>` 即可，
     代码零改动。
2. **AWS 安全组**：放行 52.79.109.153 入站 **80 和 443**（TCP）。
   - 80 必须：Let's Encrypt HTTP-01 验证 + http→https 308 跳转面。
   - 从本机探测 80/443 结论不可靠（TUN 代理劫持，nc 假 OPEN、直连 curl 000），
     权威判定交给部署脚本的 https 探针（DNS 就绪后失败即 job 红，报错信息带
     journalctl/SG 排查指引）。
3. （可选回退保险）**时序**：CI 默认基地址已翻到 `https://uat.binflow.org`。
   若在 DNS/SG 就绪前有 main 合并，协议矩阵十腿会因解析失败变红——过渡期在
   CircleCI/GitHub 各设 `UAT_MATRIX_BASE=http://52.79.109.153:8080` 即回退，
   DNS 就绪后删掉该 env 恢复 https 默认。**推荐顺序：先加 DNS+SG → 跑一次
   deploy（脚本自动装 caddy/签证书，见下方 checklist）→ 确认 https 绿 → 再合本票。**
   反过来（先合票）也不破坏部署本身：uat-proxy.sh 在 DNS 未就绪时走 WARN 路径
   不挡部署，只有矩阵腿红。

## 方案裁定：反代终结 TLS（caddy）——否决进程内 TLS 与 nginx+certbot

**选定：Caddy 反代终结 TLS，BinFlow 保持 127.0.0.1:8080 plain HTTP，产品零改动。**

| 选项 | 裁定 | 理由 |
|---|---|---|
| **Caddy 反代**（选定） | ✅ | ACME 全自动（HTTP-01+TLS-ALPN-01，签发+续期+重试退避都在 daemon 内），零 certbot/零续期定时器/零首签鸡生蛋问题；配置 5 行；apt 官方源单包。 |
| nginx + certbot | 否决 | 产品已有 `deploy/nginx/ssl.conf.template`（T-168）证明反代姿态正确，但 certbot 需要首签 dance（nginx 引用证书文件前 cert 必须先存在）、续期 timer、renew hook——UAT 单用途主机上三个移动部件换 Caddy 一个。模板保留，供生产 nginx 形态继续用。 |
| Go 进程内 TLS | 否决 | **进程内根本没有 TLS 面**（实测 grep：internal/config 的 TLS 全是 LDAP 客户端侧 StartTLS/SkipTLSVerify，cmd/ 是 bf CLI 的客户端 TLS）。新做 = 动 internal/（area 纪律）+ 自写 ACME（autocert）+ 证书热载 + 二进制膨胀，全部是反代免费送的能力。 |

反代终结本就是产品既定姿态（T-168 模板头注释明说"SSL termination template"），
UAT 只是把这个姿态自动化。

```bash
#   预期：Answer 含 52.79.109.153

# 1) 触发部署（main 合并自动 / 或手动跑 deploy_uat job），看 job 输出：
#    "caddy already installed" 或安装日志（首跑）
#    "listeners: :80 and :443 held by caddy"
```

```diff
- 'export BINFLOW_BASE="${UAT_MATRIX_BASE:-http://52.79.109.153:8080}"' \
+ 'export BINFLOW_BASE="${UAT_MATRIX_BASE:-https://uat.binflow.org}"' \

# .github/workflows/protocol-matrix.yml (env block)
-  BINFLOW_BASE: ${{ vars.UAT_MATRIX_BASE || 'http://52.79.109.153:8080' }}
+  BINFLOW_BASE: ${{ vars.UAT_MATRIX_BASE || 'https://uat.binflow.org' }}

# 两 face 的 docker 腿（原样无条件写 insecure-registries）
+ if printf '%s' "$BASE" | grep -q '^https://'; then
+     echo "https UAT base — no insecure-registries needed (public CA chain)"
+     [ -f /etc/docker/daemon.json ] && (rm + restart docker)   # 清陈旧配置
+ else <原 insecure-registries 逻辑不变> fi
```

过渡兼容：`UAT_MATRIX_BASE`（CircleCI env / GitHub vars）设回
`http://52.79.109.153:8080` 即恢复旧行为——docker 腿自动回到 insecure-registries
分支，矩阵脚本本体无需任何改动（REG 推导 scheme 无关）。

## 设计要点留痕

- **proxy 步骤先于二进制换装**：apt/caddy 出问题时 job 在触碰standing实例之前红。
- **validate 先于 reload**：坏配置永远到不了 running daemon。
- **DNS 未就绪不挡部署**（WARN 路径）：proxy 层可先于 DNS 落地，caddy 对 ACME
  失败自动退避重试；DNS 生效后脚本首跑自动 restart 冲退避（有界 60s 自愈，防
  "首次 DNS 后部署"被长退避误杀——这是复盘时补的第三版探针）。
- **8080 直连面永久保留**：矩阵回退通道 + 部署探针/回滚通道，不因 TLS 层存在而收窄。
- **kill switch**：`UAT_DOMAIN=off`（或 none/空）整体停用 proxy 层步骤，回到纯 8080。
- **无新增 sudoers**：远程腿 `sudo bash -s` 与 uat-deploy.sh 同一授权面。
- **安全性注记**：GitHub workflow 改动经 env 变量取值（`$BINFLOW_BASE`），无
  inline interpolation——沿用该文件既有安全形态。
