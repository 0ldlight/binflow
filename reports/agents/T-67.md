## 做了什么

### AC① layout 解析 + deploy/resolve + checksum 三态（ME-01/02/03/09）

- **`layout.go`**：maven-2-default 六字段严格解析。判定顺序按规格 §1.2（高置信度）：先剥 checksum 后缀（`.sha1/.md5/.sha256/.sha512`）→ 再认 metadata 文件名（`maven-metadata.xml` 与 plugin 群变体 `metadata-maven-metadata.xml`）→ 再匹配 artifact 模板 `[orgPath]/[module]/[baseRev](-SNAPSHOT)/[module]-[baseRev](-[fileItegRev])(-[classifier]).[ext]`。unique snapshot 文件名正则 `yyyyMMdd.HHmmss-N`（日期时间点号按字面量匹配，代码注明）；目录层数 ≥3（groupId ≥1 段 + artifactId + version）；文件名必须以 `<module>-` + version 拼写开头（M20 两例 400 钉死）；classifier/扩展任意（PRD 原文）。不合规路径 400【C2 暂行，模型定案、码值暂行】。NFR-S18 穿越（`../`、`%2e%2e`、`%2E%2E%2F`、双斜杠）由共享 `adapter.Layout` 解码后判定，400（测试钉死）。
- **`handler.go`**：GET/HEAD 继承 M1 头集（`X-Checksum-Sha1/Md5/Sha256`、`ETag=<sha1>` 未引号、Last-Modified、Accept-Ranges、Content-Type；Range 206/416、If-None-Match/If-Modified-Since 304 —— `rangecond.go` 与 generic 同契约的逐字镜像，adapters 是叶子不共享私有helper，测试钉住不漂移）。旁车 GET 返回**服务端实测裸 hex**（无换行，`Content-Type: application/x-checksum`，允许尾换行上传、剥离后比较）；`.sha512` 认 layout 但 GET 404（三摘要模型外无诚实计算值）。`DELETE` → 204/重复 404（metadata 联动归 T-68）。`/.index/**` 任何方法 404 E-01（**先于** layout 400，ME-10 的状态码优先）。方法白名单外 405 + Allow。
- **`put.go`**：PUT 校验链按 repo-semantics §2 顺序：layout → 仓解析/类拒绝 → handleReleases/handleSnapshots（**409**，v1.1 勘误口径 ME-08；按 version 目录分类，timestamped 文件继承；**旁车继承主文件的版本类别**——被拒制品的旁车不得落盘；**metadata 文件豁免**——ME-06 要求客户端 metadata PUT 始终可接受）→ checksum 三态（ME-09）。
  - X-Checksum-* 头链：client-checksums（默认/未配置等价）不一致 → 409 received/actual（M1 C14 同文案）；`server-generated-checksums` → 剥离客户端声明、服务端计算接受、响应回显实测值。
  - 旁车链（rest-api §1.5 高置信度）：>1024B → 409 `"Suspicious checksum file, content length of N bytes is bigger than allowed."`；目标不存在 → 404 `Could not locate artifact...`；值不一致按仓策略二态（client-checksums 409 / server-generated 静默接受且**落盘以实测为准**——存储字节被改写为实测值，GET 侧恒回实测）；sha512 旁车无实测可比 → 接受登记。旁车 PUT 成功 = **201 无 body 带 Location**（rest-api §1.1 专用列）。
  - `snapshotVersionBehavior`：deployer（默认）/non-unique/unique 在 M3 传输面统一为「按上传名落盘」（unique 服务端改写 P2 不做，FR-16-AC12；规格「已 unique 名不改写」对合规客户端不可区分）——`config.go` 读值留缝。
  - 客户端 `maven-metadata.xml` PUT 走通用上传链接受 201（ME-06；T-68 前权威内容=已存 node）。小 body（≤1MB）缓冲后自带 sha256 传入服务层，使「同字节重发」命中幂等重传豁免（mvn 每次 deploy 都重发 artifact 级 metadata）。
  - `X-Checksum-Deploy` 显式 400（T-73 范围，防静默落空节点）；`X-Explode-Archive` 400（同 generic）。
- **remote/virtual 类拒绝**：remote PUT → **405 + Allow: GET**（RE-05）；virtual PUT → 405 + C5 定案文案 `No local repository was configured as local deployment repository for the (<key>) virtual repository.`（Q2）。实现走「透传 svc.Put + sentinel 映射」而非前置拦截——为 T-71 的服务端写路由留通道（配置后路由在 Service 内生效，adapter 只整形拒绝面）。remote 仓旁车 GET 在**任何引擎介入前** 404 `"Checksums are not downloadable."`（规格 §1.5 高置信度 / FR-20 第 2 步顺序；经 T-63 ClassReader 无 principal 缝，匿名可达，T-66 落地后依然先行）。

## 遗留 / 交接

1. **metadata/sidecar 覆盖检查豁免的写面缺口（SPI 变更请求，交 architect）**：repo-semantics §3 高置信度要求「旁车与 maven-metadata.xml 永不触发覆盖检查」，但 repo.Service 的三个 Put* 用例（Put/PutFromBlob/PutLandedBlob）都内联 `authorizeContentPut` 且无豁免标记（T-61 AC① 预期的「豁免标记」未随 T-64 落地）。本票以「小 body 缓冲 + 自传 sha256」覆盖了**同字节重发**（幂等重传豁免，mvn 常态路径）；**变更字段的 metadata/旁车重发**仍走覆盖链——对无 delete 权限的 principal 是 403（admin/写删用户不受影响，M 序列全用 admin）。T-68 的 metadata 计算器同样需要服务端写 metadata 的缝。建议 architect 在 Service SPI 面加一个豁免入口（如 `PutOptions{SkipOverwriteCheck}` 或 maven 专用用例），约 10 行。
2. **`PackageName` 对 metadata 的 module-level 启发式**：version 级 metadata 路径无法在不读内容时区分层级，现按「末目录=module」读法（注释已述）；T-72 聚合如需按 GAV 分组可结合目录形态精化。
3. **T-68 前的 metadata GET**：仅返回已存 node（客户端 PUT 过的）；服务端三级计算/删除联动/`-U` 全链归 T-68。M14/M15/M16b 由该票收口。
4. **cmd 三协议装配汇合点**：T-69/T-70 将编辑 `newAssembledServer` 同一函数，conductor 合并批次时注意三段装配的文本冲突。
5. 版本比较器为 clean-room 子集（注释声明规则表）；如 QA 对拍发现偏差，单文件单点修。
