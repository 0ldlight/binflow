## 4. 与规格/裁决的偏差登记

| # | 偏差 | 依据与处置 |
|---|---|---|
| D-1 | publish 200 体 = `{"warnings":{"invalid_categories":[],"invalid_badges":[],"other":[]}}`，**不含** 规格画的 `"errors":[]` 成员 | 真机矩阵实测（cargo 1.98）：errors 键**存在即失败**（即使空数组），cargo 报 "the remote server responded with an error: "（空 detail）；warnings-only/`{}`/空体均通过，201 失败。建议 reverse-engineer 随 R-1 修订 §2 该行 |
| D-2 | 解帧失败拆分：畸形帧/metadata（客户端输入）→ 400+信封；body 读 IO/落盘失败 → 500+信封 | AC 草案把两者并写 500；CG-2 的裁决本意是"统一 4xx/5xx、禁 200+errors"。畸形输入答 500 会把客户端错误伪装成服务端故障。两形态都在 CG-2 伞下 |
| D-3 | 重复版本一律 409（CG-3），未实现规格 §5.2 的"有 DELETE 权限→覆盖重传"臂 | 官方 crates.io MUST：同版本不得二次发布；CG-3 裁决即为此。覆盖臂与索引唯一性 must 冲突，不实现 |
| D-4 | 索引重写为**请求内同步**（零延迟），非后台异步 indexer | 官方允许 index 延迟（cargo 发布后轮询短窗口、未见仅告警）；零延迟是该允许的上界，L-r3 的立即轮询直接可见。后台化无收益只加面 |
| D-5 | bare 面 PUT 对 `index/**` 与 `.cargo/**` → 403（DB-3 姿态） | 手写索引行/侧车会破坏 cksum 对账闭环。其它路径 bare PUT 照常 201（外部导入入口，测试覆盖回填） |
| D-6 | search 的"不鉴权"按全局匿名读策略执行 | 规格 §8 BinFlow 决策（沿用全局匿名策略）。匿名开（默认）= 裸 serve（官方姿势）；匿名关 = 全实例读 401。适配器无法、也不应绕过中间件 |
| D-7 | remote/virtual cargo 仓 → 404 + 信封（文案注明 local-only、remote/virtual 随其票落） | 票面范围；RepoTypes=[local] 声明式诚实 |

## 5. 跨包改动显著登记（需 conductor 过目）

**`internal/auth/authenticator.go`：新增 bare-token Authorization 臂。**

- **事实链**：探针服务器（`Authorization` 头逐字回显）+ 真机 cargo 1.98 证明 sparse HTTP registry 的官方认证形态是 `Authorization: <token>`（**无 scheme**，crates.io 兼容形态）。BinFlow 原链：basicAuth 对无空格值直接报 "malformed Authorization header" → 呈现即拒绝 → 路由面 401——发生在任何 adapter 之前，cargo 的 publish/yank 全部无法认证（L-r3 首跑实录 401）。dotnet 不受影响（nuget.config 走 Basic），go 不需要认证，cargo 是第一个 bare-token 客户端。
- **改动**：`authenticate` 在 Bearer 臂后加 bare 臂（无空格的 Authorization 值 → `verifier.Verify`，垃圾值照旧拒绝、绝不降匿名）；`basicAuth` 的无-scheme 分支从"报错"改为"放行给后续臂"（带 scheme 的非 Basic 值行为不变，全量回归绿）。
- **越界判断**：派单禁改清单（web/、其它 adapter、httpapi router）不含 internal/auth；我的角色章程含"认证权限"域。仍按纪律显著登记：这是一处全局认证面加宽（所有端点开始接受 bare token 形态），虽是纯加法且语义安全，建议 conductor 以此为据补一条 ADR 或并入 K-3 的认证面登记。
- 测试：`internal/auth/auth_test.go` 表加两行（bare token 通过 / bare 垃圾拒绝）。

## 8. 评审修复轮（REQUEST_CHANGES → 待复审）

评审报告 `reports/agents/T-294-review.md`（B1 blocker + M1/M2 minor；auth 裸 token 臂与 D-1~D-7 七偏差复核全过）。三项修复：

### B1 — 索引整文件重写丢失更新竞争（blocker）

- **修复**：`internal/adapter/cargo/index.go` 新增 `rewriteMutexes`（按 `(repoKey, crate)` 键的引用计数互斥集——锁粒度=单个索引文件，不同 crate 不互串；mpuRegistry per-session 先例）。`rewriteIndex` 的 List→组装→Put 全临界区经 `withLock` 串行；调用方（publish/yank/unyank）**先落自己的状态变更再进锁**，故最后一个写者的快照必然完备——串行化是确定性修复，不是概率缓解。释放顺序 unlock→refs--（refs 计持有者+等待者，acquire 在阻塞前计数，键在最后一个等待者通过后出 map，无泄漏、无"同键第二把活锁"）。
- **并发回归测试（必补项，handler_test.go）**：
  - `TestConcurrentPublishIndexIntegrity`——3 轮 × 8 goroutine 并发 publish 同 crate 8 个不同版本；断言索引行数==8、无重复 vers、每行 cksum==该版本实测 sha256、无 yanked。
  - `TestConcurrentYankPublishMix`——并发 publish v3 + yank v1 + unyank v2 混合；确定性论证（状态变更先于进锁 → 末位写者见全量）：最终 3 行、v1 yanked=true、v2/v3 false、cksum 全对。
- **诚实记录**：锁禁用探针在本机未复现行丢失（10 轮 8×3 + 6 轮 24×2 并发 publish 全 0 触发——本机窗口 ~百微秒级；评审环境 1/15~1/60 触发是其负载画像）。修复的正确性依据是串行化本身 + 评审方的复现取证；回归测试作为不变量锁留存（若有人移除锁，重载 CI 上仍有几率咬住）。

### M1 — Authorization 无空格含 tab 值的姿态漂移

- **修复**：`internal/auth/authenticator.go` 的 `bareTokenHeader` 改三元返回（合法裸 token / 空或带空格的 scheme 形态→沿用原路 / 无空格但含 tab/CR 等→malformed），authenticate 的 bare 臂对 malformed 返回 `invalidf("auth: malformed Authorization header")`——回到 basicAuth 旧姿态（拒绝，绝不静默匿名）。带空格未知 scheme（`Digest xyz`→匿名）的既有钉死行为不变。
- **测试**：auth_test 表加两行——`foo\tbar` malformed 拒绝；`Bearer\t<tok>` malformed 拒绝。
