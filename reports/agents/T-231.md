# 工作日志 T-231 — internal/client 上传路径 percent-encode 修复（D-1）

- role: dev-go-core；日期：2026-08-23
- 票据：T-231 [P1] internal/client 上传路径 percent-encode 修复（T-228 发现的 D-1 缺陷）`area:internal/client + cmd/bf`（BOARD 只读）
- 缺陷输入：reports/agents/T-228-qa.md §7 D-1 —— `internal/client` uploadFile 构造 PUT URL 未对 path 逐段 percent-encode，路径含字面 `%`（`sym'bols$/percent%.txt`）时 `url.Parse` 报 `invalid URL escape "%.t"`，157/158 迁移即此因；reader 侧（internal/migrate/reader.go:317 escapePathSegments）已有同构实现。

## 1. 做了什么

**根因**：`internal/client/artifact.go` 各方法构造 URL 时只对 repo key 调 `pathEscape`，nodePath 以 `trimPrefix(nodePath, "/")` 裸拼进 URL。字面 `%` 令 `http.NewRequestWithContext` 内的 `url.Parse` 直接失败（D-1 现象）；`#`/`?` 不报错但被切进 fragment/query——上传落到**另一个节点**（更隐蔽的错址）。空格/UTF-8 靠 net/http `EscapedPath()` 的重转义兜底恰好存活（见 §4 变异观察）。

**修复**（单一转义契约，非双份逻辑）：

1. `internal/client/client.go`：在既有 `pathEscape` 原语之上提取导出函数 **`EscapePathSegments`**——逐段 `url.PathEscape`、分隔 `/` 不动、段内 `/` 编码为 `%2F`。与 reader 侧（migrate reader.go）逐字节同构：两侧都用 `url.PathEscape`，reader 读到的拼写 == writer 写出的拼写。**导出**的理由：internal/migrate 本就 import internal/client（单向），后续一票删 migrate 私有副本即可收敛（改 internal/migrate 超出本票 area，见 §6 遗留）。
2. `internal/client/artifact.go`：新增 `contentPlanePath` / `storagePlanePath` 两个构造点（repo key + 逐段转义 nodePath），**五个** nodePath 消费方法全部改走之：UploadArtifact（D-1 主修复点，即 uploadFile 的调用方）、DownloadArtifact、GetArtifactInfo、ListArtifacts、DeleteArtifact——同一 URL 族同一缺陷类，只修上传会留下"传得上取不回"的半修复。空 nodePath 的仓库根拼写 `"/binflow/{repo}/"` 与修复前逐字节一致（EscapePathSegments("") == ""）。
3. `cmd/bf/main.go`：上传成功打印的 `uri:` 行同样走 `EscapePathSegments`（repo 无 `/`，折叠为一次调用）——否则 `%` 路径打印出的 URI 对下一次 curl/浏览器跳转不可解析。
4. `cmd/bf/main_test.go`：fakeBackend 的 fakeCall 增记 `Raw`（r.URL.EscapedPath()）字段，既有断言（decoded Path）不受影响。

**调用方无双重转义风险**：migrate writer 传入的 `f.Path` 来自源 listing JSON 的字面名（reader 侧 `child.URI` 不做预转义）；cmd/bf 传操作员字面 `--path`。其余 client 构造点（repo key、username、token 固定路径）本就走 `pathEscape`/固定串，grep 全量核实无第三处缺口。

## 3. 5×2 回归矩阵

矩阵字符：`%`（D-1 复现 `sym'bols$/percent%.txt`，特殊字符同时落在**目录段**与文件名）、`#`、`?`、空格、UTF-8 中文（`中文/文件 名.txt`）。两形态：

**表驱动（Go，三层）**：
- 转义语义钉死：TestEscapePathSegments（`sym'bols$/percent%.txt` → `sym%27bols$/percent%25.txt`；注：`url.PathEscape` 转义 `'`→`%27`、保留 `$`——与 reader 侧同规则）。
- wire 形态：TestArtifactPathEscapingWireForm 5/5 绿——fake 按**解码路径**键控存储，错编码即 404（判别性而非仅断言）；每个动词的 EscapedPath 精确钉死；`?list` 腿证明转义路径不漏进 query。
- 真实栈：TestArtifactSpecialPathsRealStack 5/5 绿——生产 config→metadata→storage→repo.Service→generic adapter→httpapi 全链，服务端 adapter.Layout 入口统一解码回**字面节点名**（`?list` files[].URI == 字面名即解码契约证据）。
- CLI 形态：TestArtifactUploadEscapesSpecialPaths 5/5 绿（裸 `--path` 上传 + wire + uri 行）。
- bf-migrate 形态：writer 缝 `migrate.Writer.UploadArtifact → client.UploadArtifact` 为**同一函数**（internal/migrate/writer.go:88），由上述覆盖；`./internal/migrate` + `./cmd/bf-migrate` race 回归绿（§5）。

**scratch 实例实证（真实二进制 + curl）**：构建 binflow-server/bf（CGO=0）→ 临时 data dir + 随机端口起服 → 建仓 `t231-scratch`：

## 4. 变异验证

把 `contentPlanePath` 还原为旧式裸拼接（`"/binflow/" + repo + "/" + trimPrefix(...)`，即 D-1 原样）→ 跑矩阵：

```
--- FAIL: TestArtifactPathEscapingWireForm/literal_percent
    client_test.go:1010: UploadArtifact("sym'bols$/percent%.txt"): ... client: build upload request:
    parse "http://127.0.0.1:62390/binflow/esc-repo/sym'bols$/percent%.txt": invalid URL escape "%.t"
--- FAIL: literal_percent / fragment_marker / query_marker（两层测试同红）
```

`%` 腿复现 T-228 生产报错**原文**（`invalid URL escape "%.t"`）；`#`/`?` 腿以错址（fragment/query 切分）翻红。还原修复后全绿。
观察（如实记录）：空格/UTF-8 腿在变异下不红——net/http 对 RawPath 非法或缺失时由 `EscapedPath()` 兜底重转义这两类字符，故它们在旧代码"碰巧能用"；`%`/`#`/`?` 是结构性致命字符。矩阵对五字符仍全量钉死 wire 拼写。

## 6. 规格依据与遗留

- 规格依据：percent-编码本体以公开规范 RFC 3986 为准（clean-room 铁律：有公开规范的以官方文档为准）；wire 侧转义拼写以 reader 侧实现为同构基准——该拼写已在 T-228 真实 Artifactory 7.84.10 迁移中对 157 制品下载实证可用。docs/reverse/rest-api.md 对路径转义无专门章节（仅 `X-Artifactory-Filename` URL-encoded 一处旁证），置信度口径：高（公开规范 + 生产实证），无需低置信标注。
- 遗留①（收敛建议，需改 internal/migrate，超出本票 area）：migrate/reader.go 私有 `escapePathSegments` 可删并改调 `client.EscapePathSegments`（依赖方向已成立），彻底消除两份同构体；当前两侧语义由相同原语（url.PathEscape 逐段）+ 双侧测试钉死。
- 遗留②（观察，非缺陷）：`adapter.Layout` 对整条 EscapedPath 统一解码后切段，段内 `%2F` 解码回 `/` 会与真实分隔符合流——字面名含 `/` 的节点无法与嵌套路径区分。reader/writer 两侧输入恒为斜杠分隔的字面路径，不受影响；如未来需要支持文件名含 `/`，属服务端布局语义票。
- T-228 的 158 号制品（`t228-generic/sym'bols$/percent%.txt`）在本修复后即可迁移；真实源栈按 T-228 §8 保留，复验腿归 QA/conductor 安排（T-233 dep:T-231 已解锁）。
