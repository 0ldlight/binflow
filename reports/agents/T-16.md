## 做了什么

### 装配链（AC ①）

```
config.Load(-c / $BINFLOW_HOME/binflow.yaml / 纯 defaults+env)
  → newLogger(logging.level/format, stderr)
  → metadata.Open(自动迁移 + admin 种子, sqlite DSN = metadata.dsn 或 <data_dir>/binflow.db)
  → storage.OpenEngine(<data_dir>, SessionTTL)   ← 启动清扫过期 session（storage.Open 自带）
  → auth.NewFromStore(md, cfg.Security.AnonymousAccess)
  → audit.New(md, cfg.Audit.Enabled)
  → repo.New(st, md, authSvc, auditLog)
  → generic.New(svc, md.Blobs())
  → httpapi.New(Deps{…ReposSvc/Passwords/Tokens 三个 T-15 新缝…})
  → srv.Run(signal.NotifyContext(SIGINT, SIGTERM))
```

- **无全局单例**：全部构造函数注入；`stack` 结构体持有打开的协作者与其关闭顺序，`openStack`/`stack.close` 是唯一的一对开/合序列。
- **serve 与测试共用同一个装配形态**：`newAssembledServer(cfg, stack, logger)` 封装 `httpapi.Deps` 的组装（照抄 harness_test.go 98~112 行的形态，含 T-15 遗留①列出的三个新缝 ReposSvc/Passwords/Tokens——全部指向同一个 `auth.Service` 实例与 `repo.Service` 实例）。
- **关闭顺序（架构 §7.4）**：`httpapi.Run` 内部在 ctx 取消时先 `Shutdown(GracefulTimeout)`（默认 30s）→ `defer stack.close(logger)` 关 storage → 关 metadata → 退出码 0。`stack.close` 幂等且记录 opened 顺序。
- **`BINFLOW_HOME`（架构 §8 第四例外名）**：cmd 层实现——① 无 `-c` 且 `./binflow.yaml` 缺失时回落 `$BINFLOW_HOME/binflow.yaml`；② data_dir 为默认拼写 `./data` 时解析为 `$BINFLOW_HOME/data`。操作员显式路径（含 `BINFLOW_DATA_DIR`）优先于 HOME 推导（架构 §8 边界条款）。`-c` 显式指定但文件缺失 → fail-fast 报错，绝不静默回落 defaults。
- **无配置文件也可启动**（FR-6-AC5 裸二进制）：`applyEnvDefaults` 经由临时空文件走 `config.Load`，复用 config 包的 env 覆盖 + 校验管线，不导出其内部。
- **启动日志**：打印版本、revision、config 来源、监听地址、data_dir、driver；`httpapi.Run` 打 `binflow listening` + addr + version。

### gc subcommand（AC ②，ADR-0006）

- `binflow-server gc [--apply] [--grace-days N]`，默认 **dry-run** 打印可回收清单（每行一个 sha256）。
- **引用集回调**：`distinctNodeChecksums` 走 metadata 公共接口（Repos().List + Nodes().ListByPrefix 逐仓聚合去重）等价实现 `SELECT DISTINCT sha256 FROM nodes`，**不碰 FilterUnreferenced**（T-25 回写后它是对账路径，非 GC mark）。cmd 层不持 SQL 句柄，保持 area 纪律。
- grace 透传：默认取 `storage.gc_grace`，`--grace-days N` 覆盖（N>0）；负值 400 形态 CLI 报错。
- `--apply` 物理删除后同步清 blobs 台账行（"曾经存在"记录不残留幽灵行）；台账行缺失只记 WARN 不失败。
- gc 打开 storage 与 metadata 均为幂等操作（迁移跳过、种子只在 admin 缺失时），失败路径各自关闭。

### 启动检查（AC ②）

- **postgres 拒启（FR-3-AC10）**：`openStack` 第一道闸——`metadata.driver=postgres` → 日志 ERROR「Postgres support is not enabled」+ 退出码非 0（errors.Is 可判 `errPostgresDisabled`）。实测：退出码 1、**不创建任何文件**（data 目录为空）。
- **admin 缺省口令 WARN（ADR-0009）**：`warnDefaultAdminPassword` 用真实认证路径（argon2id verify）探测 `admin:password` 是否仍然有效——不是比对哈希（明文不可恢复，也不该）。命中打 WARN，文案给出两条修复路径（env 重启 / PUT 改密）。设了 `BINFLOW_ADMIN_PASSWORD`、或已改密 → 无 WARN（两者均有测试与 e2e 实证）。
- **启动清扫过期 session**：`storage.OpenEngine` 自带（T-9 交付），装配传入 `cfg.Storage.SessionTTL`，完成后打 `startup session sweep complete` 日志行。

### scripts/smoke.sh（AC ③）

裸二进制一键冒烟：`sh scripts/smoke.sh [binary]`。构建（bin 缺失时 `make build`）→ 临时数据目录 + 随机端口起 serve（`BINFLOW_ADMIN_PASSWORD` 显式注入，不用缺省口令跑冒烟）→ C01 ping（附冷启动计时 + NFR-P1 2s 门断言）→ C03 建仓断 200 → C07 上传断 201 + `checksums.sha256` 与本地 sha256 对账 → C08 下载断 200 + sha256 一致 → 匿名读 200（ADR-0009 默认开）→ SIGTERM 优雅停机断退出码 0 与 `binflow stopped` 日志行 → trap 清理进程与临时目录（EXIT/INT/TERM 三信号）。依赖仅 curl + python3（无 jq 依赖，跨 macOS/Linux）。

## 遗留问题 / 需上游确认

1. **`make run` 仍会占 :8080**：Makefile 的 run 目标裸跑 serve，端口冲突时错误信息是标准的 bind 报错——可接受，但 T-17 README 快速开始里建议示例用显式端口或说明。
2. **gc 不接受 `-c`**：gc 的配置解析与 serve 共用 `loadServeConfig("")`（默认查找路径 + env 覆盖），当前无 `-c` 旗标。若 QA（T-19）需要 `-c` 形态跑 gc，加一行旗标透传即可——本次按票面「grace 参数透传」最小面实现，不擅自扩 CLI 面。
3. **二次信号强退未构造出观察窗口**：优雅排空在毫秒级完成，连发信号观察到的是干净退出（见上）。若 review 认为需要专门的"停机卡死时第二信号强退"测试，需在 httpapi 层注入慢 handler 的进程级测试（跨 area，建议另开票）。
4. **`applyEnvDefaults` 经临时空文件复用 config.Load**：行为正确且复用校验管线，但语义上略绕；若 architect 后续给 config 包加 `LoadEnvOnly()` 一类入口，可替换为直调（一行改动，不阻塞）。
5. **冒烟脚本的 python3 依赖**：sha256/随机负载/端口/计时用 python3 标准库实现（避免 jq/macOS sha256sum 差异）。CI 与开发机均有 python3；若未来要求纯 shell，可换 `openssl dgst -sha256` + `$RANDOM` 端口探测（精度略降）。
