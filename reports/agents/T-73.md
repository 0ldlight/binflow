## 做了什么

### 特性语义（PRD M3 §6.4-1 定案）

`X-Checksum-Deploy: true` + 仅 `X-Checksum-Sha1`（无 Sha256）：按 sha1 命中 blobs 台账（`idx_blobs_sha1`）→ `PutFromBlob` 零传输 201；sha1 未命中 → 404（与 sha256 未命中同文案同码，C15b 不可区分姿态）；sha1/sha256 均缺 → 400（C15c 不变）；格式非法 → 404（C15d 不变）。maven 生态 sha1 主算法（mvn/wagon CI 场景）为驱动力；generic 与 maven 两平面同时启用（PRD 定案是通用能力，非 maven 专属）。

### ① internal/metadata（**area 外一处必要扩展，见「越界说明」**）

- `api.go`：`BlobStore` 增 `GetBySha1(ctx, sha1) (*Blob, error)`——sha1 键查 blobs 行（idx_blobs_sha1，T-62 留缝的消费者）。接口注释写明非唯一列语义（LIMIT 1 取首行；同 sha1 不同内容为密码学谬误，相同字节本就同 sha256 一行）与 ErrNotFound 契约。
- `substores.go`：实现（`WHERE sha1 = ? LIMIT 1`，索引背书）+ **空串短路**：folder-marker 行的 sha1 为空串，调用方漏了双空守卫时不得解析出 marker——空串直接 ErrNotFound。
- 纯增量：接口无既有实现者受影响（repo 的 hookBlob 为接口嵌入，编译期自满足）；M1 metadata 测试套零回归。

### ② internal/repo（查询面 + PutFromBlob 语义扩展）

- `service.go` PutFromBlob：sha256 缺、sha1 在场时，**先于权限对**经 `GetBySha1` 解析出 sha256（幂等重传探针与其后所有步骤键在解析后的 sha256 上）；未命中 → `ErrNodeNotFound`（C15b 404 语义）；双缺 → `ErrInvalidPath`（消息改「sha256 or sha1 is required」）。解析在 `resolveWriteRepo` 之后，虚拟写路由语义不变；台账行为 digest 真相源的 T-13 契约原样（sha1/md5 永远取自行、不取自声明）。
- `api.go`：PutFromBlob 接口文档同步（sha1-only 寻址、miss 与 sha256 miss 同形）。

### ③ internal/adapter/generic（checksum-deploy 面）

- `handler.go`：删除 sha1-only 的 404 拒绝分支（M1 时代 T-13 裁决「维持 404」，PRD v1.1 §6.4-1 已回写收编）——sha1 直接随 BlobRef 进 PutFromBlob 由服务层解析；400/404 分支与 C15 文案零变化。

### ④ internal/adapter/maven（checksum-deploy 面，替换 400 占位）

- `put.go`：`X-Checksum-Deploy` 从「not implemented」400 占位换成真实链路 `putChecksumDeploy`：
  - **检测在 gate 前、执行在 gate 后**——零字节也是该版本类型的 deploy，ME-08 的 handleSnapshots/handleReleases 409 照样绑定（测试证实 release 拒绝仓/snapshot 拒绝仓均 409）；
  - **仅 artifact 路径**：sidecar（旁车是注册数据、有自己的链路）与 maven-metadata.xml（再生簿记）路径 400 拒绝——不落地那些链路永远不会写的 node；
  - 头形状与 miss 文案照抄 generic 的 C15 家族（400 no checksum header / 404 malformed / 404 no content found）；
  - 落地后触发 `calc.afterArtifactDeploy`（FR-17 元数据计算照常喂数）并 `writeCreated`（响应 checksums 取台账，originalChecksums 反映客户端声明集）。
