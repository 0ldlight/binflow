## 1. 做了什么

  （落 `PermissionPrincipal.CanManage`）；unknown-action 400 文案同步扩为

  与 `?permissions` 视图的 m 字母同族）。
- 无 manage 位的既有 target 行为零变更（既有 C22/W19/W21 全套复跑绿佐证）。

### ② T-215 移交三挂钩（review-a 留证）
- **① m-holder 覆盖集臂**：target 编辑门 = `CapSecurityWrite ∨ 请求 target 的 repos ⊆ 调用者
  manage 覆盖集`，落在 handler（permissions.go `canManageAllRepos` + `errPermissionEditDenied`）。
  覆盖判定逐 repo 走 `CanManageRepo(p, repo, write=true)`——对 role=user 即 `Can(repo,"","m")`，
  与路由门同一决策点（§3.4a 不变量 2，无第二求值点）；readonly_admin 在 write 臂恒 false，
  只读不变量保持。**空集拒绝**（vacuous subset 不放行）。DELETE 臂：repo 集取自存量 target；
  非安全写者对未知名一律 403（存在性隐藏——permission 清单是 security:read 数据），admin 保留
  诚实 404。
- **② principals 视图 manage 字母**：见 ①（GET 回显）。

## 7. 返修轮（review 双 REQUEST_CHANGES → B1）

**B1（两位 reviewer 独立收敛，正确性视角对抗探针实证）**：POST 覆盖集臂只校验 body 的
repos，未并集存量 target 的 repos。实证链：carol（覆盖集 {app-local}）POST
`{"name":"t-ent","repos":["app-local"],...}` 指向存量 t-ent（repos=[other-local]）→ 201
整体替换 → dave 在 other-local 的既有 read 被吊销；同场景 DELETE 臂正确 403（它查存量）。
create-or-replace 语义下 ADR-0026 决策 3 的「target 的 repositories ⊆ 覆盖集」应读作
**存量 ∪ 新 body**。

**修复**（internal/httpapi/permissions.go，`handlePermissionCreate` 非写者臂）：
- `covered = canManageAllRepos(body.Repos)` 之后，`GetTarget(body.Name)` 命中存量时追加
  `canManageAllRepos(unmarshalStrings(existing.Repos))`——两子集分别通过 ≡ 并集 ⊆ 覆盖集
  （union 判定的无别名实现）；GetTarget 非 NotFound 错误 → 诚实 500。
- 附带收益：body 侧已拒绝（covered=false）时跳过 store 查询——无望调用者不再付出
  （也不再触及）按名探测。
- admin/security-writer 臂零变化（先过 `canManage(CapSecurityWrite)` 分支，不进新判定）。

**测试**（TestT217CoverageMatrix 尾段新增）：
- B1 腿：admin 建 t-ent（repos=[other-local]，dave:[read]）→ carol 同名替换

- 对照腿：t-in（存量 ⊆ 覆盖集）同形替换 → 201（并集判定不误伤 V07 形态）。
