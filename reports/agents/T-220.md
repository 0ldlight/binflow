## 2. N3 钉死（ctx 取消窄窗）

- **修复**：`internal/storage/session.go` Append 的落库写改为 `persistStateLocked(context.WithoutCancel(ctx))`。数据字节在 copy 到达 EOF 时已全部落盘，EOF 与 SetState 之间到达的取消（客户端发完最后一个字节即断连）不得让簿记失败毒化一个完整的会话；copy 期间的取消仍按原语义毒化（部分写使文件与摘要链发散）。
- **测试**：新增 `internal/storage/append_eof_cancel_test.go`：
  - `TestAppendEOFCancelDoesNotPoison`：`cancelAtEOFReader`（发完全部数据后在返回 io.EOF 的同一次调用里 cancel）+ `ctxAwareSessions`（包装 memUploadSessions，SetState 先查 ctx.Err()，模拟真实 sqlite/pg 驱动的 context 感知——mem 双打忽略 ctx 会掩盖回归）。断言：Append 返回 (全长, nil)、行状态 Received=全长、同会话随后 Commit 成功（毒化会话 Commit 应报 ErrSessionPoisoned）。
  - `TestAppendMidBodyCancelStillPoisons`：fail-closed 反向钉死——body 中途取消仍毒化（第二次 Append 报 ErrSessionPoisoned），防止 N3 修复被读成"取消永远无所谓"。
- **变异验证**（临时把 `context.WithoutCancel(ctx)` 还原为 `ctx`）：

```

    append_eof_cancel_test.go:78: Append with cancel-at-EOF reader: storage: append session
      6b9c38e4-…: persist session state: context canceled, want nil (EOF beat the cancellation)
```

还原修复后：`ok github.com/lzwzzy/binflow/internal/storage 2.100s`（-race）。红→绿闭环成立。
