## 关键决策摘要

1. **PRODUCT.md Non-goals 解禁**：OIDC/LDAP 在 PRODUCT.md 标注「第一版不做」，M6 起进入企业就绪期，正式解禁。SAML 归 M7+。

2. **S3 后端 - sessions 入 DB**：ADR-0006 决策 2 定 sessions 为磁盘状态。S3 后端无本地数据目录，sessions 必须入 DB（`upload_sessions` 表）。建议本地 filestore 也统一为 DB 会话，降低双路径维护成本——需用户确认（Q2）。

3. **S3 后端 - GC grace 基准**：ADR-0006 勘误定 grace 基准 = blob 文件 mtime。S3 后端下改为 S3 自定义元数据 `blob-created-at`（S3 LastModified 是上传时间非创建时间）。需 ADR-0019 补充。

4. **复制 - push 单向**：M6 仅 push 单向复制（源→目标），目标端 replica 仓库只读。pull 复制、多源拓扑、双向同步归 M7+。

5. **认证臂优先级**：Bearer Token > Session > Basic（本地→LDAP fallback）> 匿名。OIDC 仅参与 `/api/v1/oidc/*` 登录流，不参与常规请求认证。

6. **OIDC 与 LDAP 用户名冲突**：不允许冲突——`username` 全局唯一。第二个不同 source 的同名用户返回 409（Q5）。

7. **bf CLI 与 bf-migrate 两个新二进制**：随 binflow-server 同版发布（goreleaser 三二进制 + checksums），Docker 镜像不含 CLI 工具。

8. **条件腿处置**：AWS S3 验收（Q8）与迁移工具验收（Q9）为条件腿——MinIO 等价 + Docker 自建 Artifactory 可覆盖 P0/P2 验收；真实 AWS S3 / 企业版 Artifactory 需用户提供环境，未到位时归档降级。

### 目的

将 BinFlow 的单二进制发布矩阵（binflow-server）扩展为三二进制：

- `binflow-server`（现有，服务端）
- `bf`（新增，CLI 客户端）
- `bf-migrate`（新增，Artifactory 迁移工具）

### 变更文件

#### 新增文件

1. **`cmd/bf/main.go`** — bf CLI 客户端骨架，含 `--version` 输出（同源 ldflags 注入: `main.version` + `main.revision`）
2. **`cmd/bf/main_test.go`** — 覆盖 help 矩阵、--version 输出、未知命令错误
3. **`cmd/bf-migrate/main.go`** — bf-migrate 迁移工具骨架，含 `--version` 输出
4. **`cmd/bf-migrate/main_test.go`** — 覆盖 help 矩阵、--version 输出、未知命令错误

#### 修改文件

5. **`.goreleaser.yaml`** — `builds` 节新增 `bf` 和 `bf-migrate`（六平台 CGO_ENABLED=0 amd64/arm64 linux/darwin/windows，ldflags 与 binflow-server 一致）；`archives` 节通过 `ids` 将三个二进制打包进同一个归档
6. **`Makefile`**:
   - 新增 `BF` / `BF_MIGRATE` / `BINARIES` 变量
   - `build` 目标扩展为三次 `go build`（三个二进制）
   - `check-size` 重写：三个原始二进制各自对各自的预算检查（bf < 15MB, bf-migrate < 15MB, binflow-server < 40MB）+ 归档体积检查

### 面积纪律

- 未修改 `internal/` 任何文件
- `cmd/bf/` 和 `cmd/bf-migrate/` 是独立二进制，**不 import 任何 internal 包**（M6 后续 ticket 才实现功能）
