### 1.2 真实消费者 e2e（FR-115.7 / L08，AC2）

**web/e2e/m13/t366-receiver.mjs**（脚本接收器，node 标准库）：按路径分模式——`/ok` 200、`/flaky` 前 2 次 500 后 200（重试恢复腿）、`/fail500` 恒 500（死信腿）、`/hang` 挂 90s（超时注入腿）；`GET /__log` 回放**原始字节（latin1 往返无损）+ 头**——HMAC 腿对**线上字节逐字验签**。

**web/e2e/m13/t366-consumer.spec.ts**（自举 ephemeral **pro** 实例——共享 BASE 是 community 写动词全 403；license 注入式（m10-tier-matrix --license-dir 姿态：env `T366_LICENSE_FILE` 或 bin/bf+仓内开发签发钥自动铸造，材料不可得则诚实 skip）+ 32B 随机 BINFLOW_REMOTE_CREDENTIALS_KEY（secret 封存链）。八腿全绿：

| 腿 | 断言 |
|---|---|
| UI | 真控制台对话框建签名订阅（pro 实例上的 wh-* 锚全链） |
| PIPE | 制品 PUT 201 且 <2s（主路径零阻塞面）→ 接收器收到**七字段信封**（domain/event_type/data{repo_key,path,name,sha256,size}/subscription_key/jpd_origin/source=`binflow/binflow@<26 位 ULID>`/userContext={admin,false,internal}）+ **HMAC-SHA256 hex 对线上字节逐字验签**（openssl 兼容形态）+ sha256 与 PUT 字节对账；排障环携带成功记录（status 200/elapsed>0/retries=0，debug 订阅成功也录） |
| TEST | test 端点直发：ok/200/elapsed；**明文态** X-JFrog-Event-Auth = secret 本体（官方双态默认臂） |
| SSRF | **默认姿态拒绝回环目标**：ok=false + "target rejected… loopback"（§5.4/L09 负面腿钉住） |
| RETRY | 500,500→200：3 次到达、**两个间隔均 ≥9s（固定 10s 无退避曲线）**；环记录 retries_attempted 0,1,2 |
| DEAD | 恒 500：**5 次尝试（首试计入）**全部到达 + 环上 5 条记录 retries 0..4、errors 含 500 |
| HANG | 挂死接收器（超时注入）：ok=false、status_code=0、error 含 "send failed"、**elapsed ≥25s（30s 整尝试预算）** |
| DRAWER | 控制台抽屉呈现死信订阅的记录链（AC1×AC2 集成：行→抽屉→500 记录→载荷快照） |

## 4. 契约漂移 / 上游缺口（conductor 面）

1. **`webhook.allow_private_target` 旋钮在配置装载层不可达（高，阻塞接收器腿的常规形态）**：`internal/config/config.go` 的 env 键映射（`case "replication.allow_private_target", "webhook.allow_private_target"`）与 `api.go` 的 `WebhookConfig` 结构体**已落地**，但 `internal/config/load.go` **从未接线**——yaml 形态报 `field webhook not found in type config.raw`，env 形态报 `bool path "webhook.allow_private_target" not wired`（实测两条报错原文）。ADR-0041 决策 6 / T-362 §6.2 的旋钮因此是**死键**。修复 = conductor 在 load.go 补 raw 段 + applyBoolEnv 一臂 + raw→Config 映射（约 3 行级）；本票不改 internal/，消费者腿以本机全局 IPv6 接收器 + SSRF 默认拒绝负面腿的形态绕开（诚实且零放松），旋钮修复后可平移回 loopback 形态。
2. **投递记录（outbox 行 status/pending 水位）无 REST 面**：`Bus.Deliveries()` 在服务层存在但七端点族未暴露；AC1 的「最近投递记录」按派发口径落在**排障环 records 面**（troubleshooting——状态/耗时/重试计数三列齐）。pending→delivered 的**行级**状态流在环上不可见（环只记 attempt 结果）；FE 空态文案已如实标注「空列表 ≠ 无投递」。如需 outbox 行面（含 dead 行 Replay，T-364 §5-3 同留）另裁。
3. 次要：`error-retry` 锚在册但 ErrorCard 公共组件未渲染该 testid（本票 spec 按角色定位绕开，未动公共组件——如需对齐册，归 ErrorCard 所在票）。
