## 三、风险清单（R1~R12，供 conductor 转交）

- **R1**（PRD 回写，须赶在 T-37 派发前）：ADR-0010 定案 token 端点为 `/v2/token`（adapter 自有，realm 指向它），而 PRD DE-13/FR-11/D04b 仍写 realm=`/binflow/api/security/token`。票已按 ADR-0010 写死；PRD 需 +0.1 回写 Q1 定案与 realm 口径（D04b 命令的 URL 同步改），否则 T-37/T-43 照 PRD 原文执行会误判。另注意：M1 的 `POST /binflow/api/security/token` 是 admin-only（T-15/D3 裁决），`/v2/token` 是任意有效用户入口（docker login 语义）——两入口并存是设计而非矛盾，PRD 宜写明。
- **R2**（PRD 回写）：FR-9-AC7 写「DELETE by-tag → 202」，但规格 §8 高置信度指出官方 spec 禁止 by-tag、§10 建议栏 3 定按官方 405/400 拒绝；任务指令「实现取按官方实现栏为默认」——T-39 已按 405 `UNSUPPORTED` 写。PRD 需回写该 AC 并删 D 序列中对应的 by-tag 删除断言（若有）。
- **R3**（架构冲突，转 architect）：架构 §5.3 校验链① 是四种 mediaType 白名单（其余 415/400），PRD FR-9/DE-08 明确「Content-Type 透传不白名单，保证前瞻兼容」（Helm OCI 与未来类型依赖此）。T-39 已按 PRD 透传 + 结构性解析写（中间立场：不白名单但验结构）；需 architect 回写 §5.3 消歧——若裁回白名单，oras 的 helm config 类型等将 400，直接影响 FR-12。
- **R4**（PRD 回写）：PRD FR-10 写空仓 tags 返回 `"tags":null`（对齐 distribution 参考实现），规格 §6 指出官方建议 200 空数组、Artifactory 404 NO_TAGS_FOUND。null 与空数组两个官方容许形并存，T-40 已按 PRD 的 null 写死，仅记录不必改；风险在 QA 断言脚本需按 null 写（jq `.tags == null`）。
- **R5**（校准回写，PRD §6.5 四项）：manifest 4MB 上限、`offline_token` 拒绝、`service` 值（binflow）、catalog `last` 参数——T-37/T-39/T-40 已按暂定值实现并标注；PM 按规格回写后若有出入，改动面均为单行常量。
- **R6**（T-33 实现注意）：`Docker-Upload-UUID` 用纯 UUID（规格建议栏 6），不用 Artifactory 的 `<uuid>.patch`；Location 用相对路径——与 Artifactory 的 X-Forwarded-Host 绝对 URL 构造不同，五客户端均容忍相对 Location（docker/oras 实测为证，T-44 兜底）。
- **R7**（批次 2 面积边界）：T-37（adapter/docker token 子域）与 T-41（httpapi middleware）都可能触碰 `/v2` 请求的日志与错误路径；派发时主会话须在指令中划定文件级边界（T-41 仅动 middleware.go/accessLog，T-37 仅动 adapter/docker/），冲突则 T-41 顺延。
