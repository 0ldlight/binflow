## 做了什么

ADR-0025 决策 6 要求：管理员通过 REST 禁用用户后，该用户的现有 token / 会话 / 登录必须立即失效（guardrail-3）。审计确认 `internal/auth` 三条认证臂（token、session、login）都已按每请求重查 owner 行的 `Enabled` 标志（token.go:51、session.go:90、authenticator.go:316），因此只需要把 `enabled` 字段从 REST 正确落到存储即可。

实现分四层：

1. **HTTP 面（`internal/httpapi/security.go`）**
   - 给 `userCreateBody` / `userUpdateBody` 增加 `Enabled *bool`（指针以区分「缺省」与「显式 false」，沿用 `userUpdateBody` 既有指针 pattern）。
   - 创建路径：新增用户默认 `Enabled: true`（`body.Enabled == nil || *body.Enabled`）。
   - 替换路径（PUT）与部分更新路径（POST）：`if body.Enabled != nil { SetEnabled(...) }`；缺省则保持既有语义不变（回归不破坏）。

2. **接口（`internal/metadata/api.go`）**
   - `UserStore` 增加 `SetEnabled(ctx, username, enabled) error`，godoc 写明语义：禁用后立即失效现有 token/session（因为 Verify 每请求重查 owner 行）。未知用户返回 `ErrUserNotFound`。

3. **实现（`internal/metadata/substores_auth.go`）**
   - sqlite `userStore.SetEnabled`：单条 `UPDATE users SET enabled=?, updated_at=? WHERE username=?`，`RowsAffected==0` → `ErrUserNotFound`。

4. **机械补齐（`internal/adapter/docker/token_test.go`）**
   - 唯一完整实现 `metadata.UserStore` 的 fake（`fakeUsers`）补 `SetEnabled` stub；npm adapter 用的是窄接口 `UserDirectory`（只有 `Get`），无需改动。
