### ② GE-05 — quotaBytes enforcement（W26/W26b/W27）

- 配置面：`validateLocalConfig`（config.go）校验 quotaBytes 非负整数（0=不限默认）、类型错 400；httpapi `repoConfig` 增 `QuotaBytes *int64`（指针使显式 0 可存可回显），local 臂 `configJSON` 透传三字段（includesPattern/excludesPattern 字段早已在结构体上，本票真正转发）。
- 计量：`internal/metadata/substores_usage.go`（新）`UsageStore`：`PutNodeWithUsage`/`DeleteNodeWithUsage` 与 node 增删**同一事务**；delta 用标量子查询在**首条写语句内部**算（事务以写开——遵守 store.go 的「无读→写升级」红线；初版 SELECT-then-写在并发测试里立刻 SQLITE_BUSY，已修复并保留该教训注释）。`Get` 无行=0 不报错。putNode 全路径改走计量写；Delete 单文件/目录递归/DeleteManifest（含 heal 支路）改走计量删；pruneEmptyParents 删 folder 行（size 恒 0）保持普通删。
- **005_quota_usage_backfill.sql**（新迁移）：对既有库按 `SUM(nodes.size)` 回填 repo_usage（老库升级否则永远只见到增量）；幂等（schema_migrations + ON CONFLICT DO NOTHING）；文件体零 BEGIN/COMMIT，模板同 001~004。**不是 DDL 变更**——repo_usage 表 004/T-90 已建，005 只做一次性数据回填（conductor 问询的裁决依据）。
- 挂点：Put 流式臂在 `commitBlob` 之后（size 已知，落盘后判，超限**不写 node**、blob 留 GC）；PutFromBlob/PutLandedBlob 在 O(1) size probe 后、任何元数据写之前（秒传/mount/docker finalize 全受限，NFR-S23）；PutManifest **故意不挂配额**：docker 双 node 布局（blobs/<hex> + manifests/<hex>）下 manifest body 已在 adapter step-1 的 svc.Put 过门，再查一次等于要求天花板覆盖同一字节两遍（会把放得下的 push 拒掉——curl 实测发现后移除，见自测记录）。
- 413 = `StatusError`（message 含 `quota exceeded` + used/quota 双值；cause=`ErrQuotaExceeded`）→ generic/maven/npm/pypi 四 adapter **既有 verbatim 渲染**直接出 413，零改动；原子性：被拒路径不落 node/ledger/索引行。
- 幂等重传豁免（同内容同路径 delta=0 不 413）；overwrite delta = new-old（涨过顶拒、缩放行）；quotaBytes<=0 短路零 I/O。
- 观测：`quota.exceeded` 审计（detail 五元组 actor/repo/path/used/quota；动作常量在 repo 包本地定义——audit 词表是 T-93 area）+ WARN 结构化日志。

## 遗留 / 需上游确认

1. **docker 面 413 渲染缺口（跨 area）**：adapter/docker 的 `writeManifestPutError` 与 blob 注册失败支路无 StatusError-verbatim 臂（generic/maven/npm/pypi 均有），配额拒绝在 /v2 上出 **500 UNKNOWN**（message 含 quota 文案、零残留成立）。W26c 断言「服务端 413」→ 需在 adapter/docker 加一条渲染臂（约两处小改），与本票「五协议 adapter 麻零改动」的挂点契约相抵，故不越界代改——请 conductor 排给 adapter 侧或并入 T-103 前置。
2. **docker manifest 双计数**：两 node 布局使 manifest 计两次、usage 可显示超顶（enforcement 不受影响：每个上传在 blob 面都有界）。若 QA/FE 需要精确数，需在计量层对同 blob 同仓去重（引用计数化），登记为后续票。
3. **配额预检非预留**：同仓并发上传可在读-写间隙多进一个 racing write（SQLite 串行化写本身，不串行化该读）；顺序序列（AC 口径）精确。
4. **透传清空局限**：local config 透传链上，空字符串=「保持现状」，无法经 REST 显式清空 includes/excludes（与 checksumPolicyType 族同款既有约束）。
5. `quotaBytes`/patterns 仅挂 local config（remote/virtual 规范化会丢弃未知字段）；FE（T-99）表单按 local 仓呈现即可，virtual/remote 呈现为只读「—」的建议留给 T-99。
6. 并行批次共文件：router.go 与 T-93 的 audit case 同 switch 不同分支（已在磁盘共存编译通过）；harness_test.go 的 audit 接线是共享基建改动（生产对齐），若有并行票依赖「audit 为 nil」的行为请知会。

### B1（blocking）— 声明 checksum 的幂等重传在配额边界误拒 413

- 根因确认与评审一致：三处 `replaced` 计算的 `!idempotent && existing != nil` 条件把幂等重传的 replaced 置 0，预检 delta=全量，而同事务计量层真实 delta=0——预检与计量背离，「幂等豁免」方向写反。
- 修复（采 reviewer 建议方案一）：三处条件改为 `existing != nil`（service.go 流式臂 / PutFromBlob / PutLandedBlob）。幂等 ⇒ existing.Size == incoming（同 sha256 ⇒ 同字节 ⇒ 同尺寸）⇒ delta 0 ⇒ 复用 checkQuota 既有 `delta <= 0` 短路豁免，零额外 store 读；overwrite（异内容）行为不变（replaced=旧行尺寸，按差值计费）；全新路径 replaced=0 不变。
- 注释修正：governance.go checkQuota 的 replaced 语义描述整体重写（原注释恰好把方向说反）；三处调用点各加 review B1 由来的短注。
- **回归测试的证明力**：TestQuotaIdempotentRetransmitAtCeiling（新）在 quota=1600、used=1600 恰在顶的形态下跑三臂——① 带 `expect.Sha256` 的流式同内容重传；② PutFromBlob 同 blob 重宣告（X-Checksum-Deploy）；③ PutLandedBlob 同 digest 重 finalize（docker 重推形态）——全部放行、usage 不动、**零 quota.exceeded 审计噪声**（逐事件断言）；随后新 800B 路径仍真 413（三臂未松动真增长门）。用 round-trip 回退法验证了三臂各自有牙：分别还原单处为旧条件，臂 1 报出与评审复现一致的 `quota exceeded: used 1600 of 1600 bytes ... needs 800 more`，臂 2/3 同样红；恢复后全绿。
