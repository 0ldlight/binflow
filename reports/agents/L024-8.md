## 乙：D01-R08 — PATCH/DELETE `/api/metadata` + POST `/api/storage` 405

### Changes

1. **新面** `internal/httpapi/metadata_patch.go`：
   - `handleMetadataPatch`：§3.1 逐条——annotate 门先行（403 专属文案 `Request for '<repo>:<path>' is forbidden for user: '<u>', You must have annotate permission on this path`）→ body 存在性门（400 `props or stats fields required` 逐字）→ 值类型门（非串非数组 → 400 `Failed to set properties on <repo>:<path>: Failed to parse json object while performing patch properties request.` 逐字含句号，§3.1 item 13 的纯文案进 envelope）→ 目标门（非 local 仓〔含未知 key，单一 guard〕→ 400 `Repository '<repo>' is not a local repository`；item 不存在 → **400 非 404** `Item <repo>:<path> does not exist`）→ 执行（item 9 序：null 键先 Delete，再 Merge——store 的 same-key replace 即 item 2 的「删旧键原子写新值」）→ 204。
   - 值语义：串=单值集；数组=仅保留文本元素（item 7 非文本静默跳过）；null=删键（幂等 204）；空数组=写空集=store 的 delete+零 insert=键落空（规格未记，登记）。
   - `recursiveProperties`（item 8）：缺席按目标类型定（目录默认递归/文件非递归，§3 表尾注），显式 `0/1`；`atomicProperties` 不读取（item 8 登记的参照差异，对齐忽略）。
   - `{"stats":{…}}`（item 10，低置信「普通客户端不应触达」）：合法 JSON 对象过门、无可观测变更、204——**规格待验证**，活体定案前不实现 merge。
   - `handleMetadataDelete`：删全部属性（store 全键形式）、无属性 204 幂等、`recursive=` 同法；403 用族裸文案（item 11：详细文案专属 PATCH）。

## Risks

1. **DELETE 侧目标失败文案**（item 缺）：missing item / 非 local 仓在 DELETE 上复用 PATCH 的 `Failed to set properties on…` wrap——规格只记了「无属性→204」；共享 guard 是登记读法，差分候选。
2. **PATCH 403 的 repoPath 分隔符**：规格引 `'<repoPath>'` 未展开；取族内一致的冒号拼写（item 5/6/12 皆 `repo:path`），逐字待差分。
3. **stats 腿**：低置信（item 10 自记「未活体」）；本实现=合法对象过门 no-op 204，活体定案前不猜 merge 形态。
4. **空数组值** `{"k":[]}`：规格未记；落 store 的「delete+零 insert」=键落空（等价删键），登记。
5. **`!`-无斜杠 miss 文案**：L024-1 探针 repo 类型未记录——generic 面保持 §1.4 `Failed to find the requested resource`（BinFlow 既有高置信），maven 面=L020 `File not found.; Path:` 与 §3.3 同形；差分时以参照仓型分辨。
6. **/api/metadata 其它动词**（GET/PUT/POST）：规格未记，维持 E-26 404，不猜 405。
7. 隔离实例为 community 无证档：丙的 403+门头是 as-designed 证据，非 §3.3 行为臂的活体验证（该面在 pro-install 测试栈已逐字 pin）。
