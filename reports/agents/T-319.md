## 一、mini 规格（先落笔）

**`docs/design/gpg-keypair.md`**（新文件，约 180 行）。keypair 体系属**自设计 + Artifactory 行为对齐混合**，按派单裁定放 docs/design/（机制条款 ADR-0038 已裁；wire 面对齐 Artifactory），文件内 §0 显式分级出处：

- **L-A（Artifactory 行为，高置信）**：**官方 REST 文档实时取证**（docs.jfrog.com/administration/reference/*.md 的 OpenAPI 定义，2026-08-27 抓取，网络可达 jfrog.com）——9 端点族 + KeyPairInput/KeyPairSummary schema 逐字落规格：
  `POST/PUT/GET /api/security/keypair`、`GET/DELETE /api/security/keypair/{pairName}`、`POST /api/security/keypair/verify`（200 正文 `Key was verified.`）、`GET /api/security/keypair/public/repositories/{repoKey}`、`POST /api/v2/repositories/{repoName}/keyPairs`（text/plain body=钥名）、`DELETE …/keyPairs/{keyName}`。KeyPairSummary = {pairName, pairType, alias, publicKey} 四字段。
- **L-B（BinFlow 自设计，ADR-0038）**：双列 enc:v1 密封、删除引用护栏、生成默认、BinFlow 原生 generate 端点、能力门、签名 seam。
- **L-C（低置信）**：Artifactory UI 面 keygen 行为无公开 REST 证据——BinFlow 生成端点自设计，证据出现后按 Q8 翻转。

**Q8 锚定结论（§2.3）**：Artifactory 官方 REST 面**无 keygen 端点**（导入面 privateKey+publicKey 由调用方供给）→ ADR-0038 决策 6 的「暂行 RSA-4096」**无处翻转、转正**；生成端点落在 BinFlow 自有管理面 `POST /binflow/api/v1/admin/security/keypair/generate`（Artifactory 兼容面保持导入-only，wire 零分歧）。

**分歧登记 D-1~D-8**（§2.6）：D-1 门（Artifactory anonymous-read vs BinFlow CapSecurityRead——ADR 机制条款）；D-2 删除护栏（Artifactory 文档未载，ADR 为准）；D-3 回显 additive 四字段（createdAt/updatedAt/updatedBy/repositories）；D-4 生成端点自设计；D-5 verify 扩展（body 仅 pairName → 校验存量密封钥）；D-6 3.3 legacy GPG 三端点不实现；D-7 primary/secondary/promote 族不做（单关联槽 = primary 语义；轮换 = PUT 换钥 + 改关联 + 重签）；D-8 `X-GPG-PASSPHRASE` 头不收（口令随钥密封，rpm.md §4.2 的头形态不进 BinFlow 签名腿）。
