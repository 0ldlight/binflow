## 定案 A：健康可见性 — 维持 admin-only（规范向实现对齐）

`GET /api/v1/health` 路由门 `routeAuth{required, admin}`（router.go 注释明示 D2）**不放宽**。理由：

1. 健康端点暴露实例内部状态（storage/metadata/registry 子系统细节与失败原因），与 `/api/v1/storage/stats` 同属运维面数据——D2 已定「非 admin 不得得知实例体量」，健康放宽是在同一 stance 上开旁门。
2. BinFlow 安全立场一贯**存在性与内部状态不泄露**：登录失败不泄露用户存在性、`?permissions` 收 admin 门（T-97 review B2）、T-97 conductor 裁决明示「BinFlow 存在性不泄露立场」。健康是典型内部状态。
3. 需要健康信号的角色（运维/排障者）就是 admin 本身；部署侧探活有免认证的 `/healthz`/`/readyz`（router.go 注释原文「Deployers' liveness/readiness probes use the unauthenticated /healthz and /readyz instead」）——放宽没有真实受益者。
4. 非 admin 的实际工作（CI push/pull、浏览制品）不需要实例健康即可完成。

**后端票：无。** 前端姿态：仪表盘健康卡、设置页健康行对非 admin 隐藏（L3，§3.6.3）。

## 定案 B：仓库列表可见性 — 维持路由门 admin-only

service 层（`ListReposFiltered`）虽只要求 authenticated 并支持按 read 过滤，但路由门收紧是正确姿态，不放宽。理由：

1. 权限模型是 **path-keyed**（permission target 的 include/exclude pattern），没有 repo-keyed ACL。「列出调用者可读的 repo」需把全部 target 的 pattern 对全部 repo key 求值——语义不正交（`**` 授予的是「将来一切路径」而非「某仓的存在」）、无索引、无法判定为精确集合。
2. 列表即**存在性枚举**：非 admin 看到全量列表即得知其无权访问的仓库存在。router.go 注释本身引用 FR-5-AC8 / C22b 断言（「an authenticated non-admin would otherwise see every repository's configuration」）；「A filtered listing needs the M4 repository-ACL model」——M4 落地的是 path-keyed 完整模型（T-97），前置条件并未成立。
3. 非 admin 的**制品可达性已由内容面承担**：`GET /api/storage/{repo}/{path}`（authenticated + 路径 ACL）、`GET /api/search/artifact`（T-92：与内容面同一 `allow()` 路径、按调用者过滤、ACL 零泄漏）——管理面列表不是必需路径。T-100 树页走 `/api/storage` 族，不受本门影响（T-99 漂移①的判断正确）。
4. M4 控制台非 admin 主场景（按权限浏览/上传制品）不依赖仓库管理列表；管理动作（建/改/删仓）本就 admin。

**后端票：无（本轮）。** 若未来产品确需「非 admin 可见自己可读的仓库」，登记条件性票模板（**不派**，供 conductor 备查）：repo-keyed 读授权枚举模型 + `GET /api/repositories` 路由门放宽 + 按 ACL 过滤 + C22b 断言更新。届时前端零改版——403 消失列表自动出现（L2「放宽跟随=自动」）。

## 附带定案（矩阵核对浮出的第三处 §3.3 旧设想）

**Tokens 收回 admin-only**：`POST /api/security/token` 及 `/revoke` 均为 admin+OAuth 门（D3：M1/M4 无 scope 模型，非 admin 自签 `api:*` token 会携带完整主体权限，分支保持关闭——router.go 注释原文）。v1.0 §3.3「安全→Access Tokens（仅自己的 token）」作废；非 admin 的「安全」分组**整组隐藏**（v1.0 设想「分组只保留 Tokens 一项」不再成立）。

## N1 裁定（前端硬编码 admin 位收敛，一句话）

> **数据呈现（页面主数据面/卡片/行）一律 403 驱动，禁止 whoami admin 位硬编码——后端放宽端点门时 UI 自动跟随；whoami `admin` 位仅用于导航分组与写入口的预收敛，且必须与 403 收敛同向（admin 位收紧面 ⊆ 403 收紧面）。**

落点：仪表盘四卡已是 403 驱动（合规）；**存量偏离一处**——SettingsPage 健康行 `{admin && …}` 应改为与仪表盘健康卡相同的 403 驱动（一行前端修正，建议随 T-100~T-102 任一批次或 T-104 前顺手收口，并补 `settings-health` 锚）。AppShell NAV 安全/治理组 `adminOnly` 维持（属 L1 预收敛，合规）。

## 403 收敛主姿态（四层，console-ux §3.6.3 全文）

| 层 | 对象 | 姿态 | 放宽跟随 |
|---|---|---|---|
| L1 | 导航入口/分组 | 不渲染（whoami 位预收敛） | 需一次性前端微调 |
| L2 | 页面主数据面整体 403 | 单张无权限卡（壳保留 + 说明 + 搜索/直链引导），不留空白壳 | **自动** |
| L3 | 卡片/行级数据 | 隐藏该卡/行（非 admin 一排红卡是噪音） | **自动** |
| L4 | 动作按钮 | 不渲染（隐藏非置灰，P6 同款） | 随 L1 |

- 只读降级**不是** 403 姿态（能力收窄走 §3.4 矩阵 + 替代命令）。
- 401 ≠ 403（401 一律过期 toast + 重登，不进矩阵）。
- 操作中 403（上传/删除被拒）仍走行内错误并指向权限模型（§4.7 原文不动）。

## 端点 × 门矩阵（§3.6.2，核对自 router.go）

管理面 admin-only：`v1/health`、`v1/storage/stats`、`v1/audit`、`v1/system/gc`、`repositories` 全族（含列表）、`v1/permissions` 全族、`security/users` 全族、`security/groups` 全族、`security/token` + `/revoke`、`storage/{…}?permissions`。
authenticated：`v1/session` GET/DELETE、`v1/storage/usage/{key}`（use case 裁 admin 或 read 授权）、`security/password`。
门空/use case 自裁：`system/ping`、`system/version`（开放）、`storage/{repo}/{path}` item info（内容面语义）、`?list`（handler 自答 403）、`search/artifact` + `search/checksum`（结果按调用者 ACL 过滤）。
内容面：读=匿名可（开关开时）、写/删=authenticated+action ACL；`/v2/**` adapter 自持。全表含 console 消费面落 §3.6.2。
