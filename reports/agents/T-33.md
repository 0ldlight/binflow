## 实现

### 1. 路由：/v2 根级例外（ADR-0010 第 1/2 条）

`internal/httpapi/router.go` `dispatch()`：

- `/v2` 与 `/v2/**` 在**所有其他分支之前**判定（它根本不在 `/binflow` 下），命中后把请求**原样**（不剥前缀、不改 URL）连同 principal（经 `adapter.WithPrincipal` 同一 context 缝）交给 `s.adapters["docker"]`。同一 middleware 链（requestID → accessLog → recover → CORS → authenticate）自然覆盖——dispatch 本身就在链内。
- 无 docker adapter 挂载时（装配缺失）：`writeV2Unavailable` 输出 spec 体 404（UNSUPPORTED）+ api-version 头 + ERROR 日志，保持 /v2 平面响应契约不因装配降级而破。
- `/binflow/v2/**` **维持 E-26 信封 404**（第 2 条：不做双挂载），测试断言其响应**不带** `Docker-Distribution-Api-Version` 头（域隔离的可观测证据）。
- 认证缝（T-14 红线）：/v2 路由**不经过** `authorize()`（binflow 信封 401 会破坏 spec 体协议）；challenge 由 adapter 自持（它拥有 realm 构造），与内容路径「adapter 渲染协议错误」的既有风格一致。
- EscapedPath 纪律（T-14 教训）：dispatch 判定继续基于 `r.URL.EscapedPath()`，无 ServeMux、无 cleanPath；`TestV2TraversalDefenseRawTCP` 用 raw-TCP 证明 dot-segment 请求到 /v2 无 3xx 重定向（400/404 直答）。

### 2. name 解析（ADR-0010 第 3 条，NFR-S11）

`internal/adapter/docker/name.go` `parseV2Name()`：

- 全路径先 `url.PathUnescape` 再切分——%2e%2e 在**解码形**上被审判，逃不逃不出 dot-segment 防线（与 generic 层 FR-4-AC10 同构）。
- 首段 = repoKey，余段 = 镜像相对名；路由尾段（manifests/blobs/tags/referrers/uploads）在余段中**贪心定位**（至少留一个 image 段）：`/v2/team1/acme/app/manifests/x` → repoKey=team1、image=acme/app；`/v2/team1/manifests/manifests/latest` → image=manifests（镜像自己可以叫这个名字）。
- **安全检查先于形状分析**：dot-segment/空段防线在「是否有路由尾」判定**之前**执行——`/v2/team1/../etc/passwd` 恰好没有路由尾，若先判形状会把攻击探测答成无害 404，400 必须赢（实现中发现的真 bug，测试驱动修复）。
- 单段 name（`/v2/ubuntu`）→ 404（无 repo 切分；Artifactory 亦要求 repo 前缀，规格 §0 校准）。
- 错误分两形：dot-segment/坏编码/超长 → wrap `adapter.ErrBadRequestPath`（400）；单段/无路由尾 → `notANameError`（404）。

### 3. repo 门（ADR-0010 第 3 条 + NAME_UNKNOWN）

`internal/adapter/docker/handler.go` `serveNameRoute()`：

- repo 不存在、lookup 出错、`package_type != "docker"` 三者**同一** 404 `NAME_UNKNOWN`（spec 体，detail=null）——不让未认证调用者区分「仓不存在」与「仓不是 docker 型」。
- 匿名关闭时：name 路由在 repo 门**之前**先 challenge（401 + Bearer）——参考实现同序，且避免 404 泄露仓库存在性。
- `RepoLookup` 消费端接口（`Get(key) (RepoRow, error)`）+ `metadata.RepoStore` 适配器（not-found → nil,nil）+ 静态表 stub（测试）。

### 4. spec 错误信封 + api-version 头（AC②，DE-17/NFR-S10）

`internal/adapter/docker/errors.go`：`{"errors":[{code,message,detail}]}`，detail 无内容时序列化 `null`（规格 §1 表 2 形态）；`Docker-Distribution-Api-Version: registry/2.0` 全 /v2 响应（ping 200/401、method 405、name 404 全带）。/v2 域内**绝不**出现 E-01 信封（`TestV2ErrorEnvelopeIsolation` 以「无 "status" 字段」判别）。

### 5. ping 端点（AC①，DE-01/D04）

- 匿名开（默认）：GET/HEAD `/v2` 与 `/v2/` → 200 `{}`；其他方法 → 405 UNSUPPORTED（spec 体）。
- 匿名关：401 + `WWW-Authenticate: Bearer realm="<base>/v2/token",service="binflow"`（ADR-0010 第 4 条头形；PRD v1.0 的旧 realm 已被 PRD v1.1 回写，R1 结案）。已认证 principal 在关匿名实例上仍得 200。
- realm base：`server.base_url` 优先（尾斜杠归一），否则 X-Forwarded-Proto/-Host → 请求原生 Host，scheme 缺省 http。

### 6. 未定义路径与 referrers（AC②，DE-15/16，D24）

`/v2/foo/bar/baz/qux`、`/v2/<name>/referrers/<digest>`、`/v2/token`（本体归 T-37）→ 全部 spec 体 404。curl 实测 D24 两例。

### 7. health registry 字段（AC②，只增不破）

`internal/httpapi/system.go`：`healthResponse` 增 `Registry subsystemStatus`，`probeRegistry()` 按 adapters["docker"] 挂载与否报 ok/error；顶层 status 聚合含 registry。既有 storage/metadata 字段与测试零变化。

### 8. 装配

- `cmd/binflow-server/main.go` `newAssembledServer`：挂 `docker.New(svc, NewRepoLookup(md.Repos()), Options{AnonymousAccess, BaseURL})`，generic 之前（顺序无关：docker 只占 protocol 键）。
- `internal/httpapi/harness_test.go`：harness 同法挂 docker（Adapters 切片两项）。

### 关键裁定：RepoTypes 为空的缘由（架构 reviewer 请看）

`docker.Handler.RepoTypes()` 返回**空切片**。httpapi 的 adapters map 以 protocol 键 + 每个 repo class 键注册（`New()` 中后者覆盖前者）：若 docker 声明 `{"local"}`，`adapters["local"]` 会被 docker 覆盖 generic 的内容路径分发（M1 唯一 local 服务者）——已用最小程序实证 map 覆盖序。M2 的 docker 分发只需 protocol 键（/v2 路由 + 未来的 package_type="docker" 行分发同键）。当 T-35+ 需要 class 键分发时，map 需先演进为 per-package-type 命名空间（已在 `server.go` 与 `handler.go` 注释中写明该契约与归属）。注意 `adapter.Register()`（进程级注册表）对空 RepoTypes 会 panic——docker 走 Deps.Adapters 注入路径不受影响；若未来改走 Register 需先扩该契约。

`sessionRegistry` 已立在 Handler 构造中（T-38 填 UUID→Session+received 表；UUID 用纯 UUID、Location 相对路径——规格建议栏 6，非 Artifactory 的 `<uuid>.patch`）。
