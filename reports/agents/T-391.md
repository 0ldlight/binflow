## 1. 根因复算（AC1 判据链）

T-374 L2 在案缺陷复算确认：

- hover 行底 = MUI `TableRow hover`（`action.hover`）叠透明行——表格在
  `Container main` 上无 Paper 包裹，composite 落在 `--bf-bg` 上。
  探针实测 tr 背景字面量：**亮 `rgba(0,0,0,0.04)` × #f3f5f7 = #e9ebed**（与
  T-374 axe 实测逐字节吻合）；**暗 `rgba(255,255,255,0.08)` × #12161d = #25292f**
  （MUI 暗色 hover 是 8% 白——比直觉的 4% 重，实测纠正）。
- 修前对比度（axe-core 同式 WCAG 手算）：
  - 亮 `#0b6bcb` on `#e9ebed` = **4.42:1 < 4.5**（= T-374 报的 4.41，舍入位差）→ 缺陷
  - 暗 `#4aa3ff` on `#25292f` = 5.55:1（本就过线）

## 2. 修法定案（AC1「票内定案留痕；不引入新 token 优先」）

**定案：`.row-link:hover` 色改 `color-mix(in srgb, var(--bf-accent) 88%, var(--bf-text))`**
（web/src/styles/pages.css 一处；resting 态 / MUI 主题 / 其余承载面零改动）。

选型理由（三案对比）：

| 方案 | 判定 |
|---|---|
| A. hover 链接色向正文 token 压 12%（color-mix 两枚现货 token） | ✅ 取——一处修复、零新 token、assert-tokens 对 `color-mix(... var(--bf-*) ...)` 明示放行（脚本头注释即为此形态预留）；`.row-link` 是 8 页共用类，一处收口全表受益 |
| B. hover 行底换档（surface-2 ≈ 4.49:1 仍差 0.01；改 MUI action.hover 波及全部 hover 面） | 弃——要么仍不过线，要么修复面放大 |
| C. 调 `--bf-accent` 全局 token（MuiProvider 双源同步） | 弃——品牌主色全局面，远超票面 |

修后数字（axe-core 同式手算 + 浏览器 computed 采样复核）：

| 主题 | hover fg（color-mix 实算） | hover 行底 | 修前 → 修后 |
|---|---|---|---|
| 亮 | `rgb(13,98,184)` = #0d62b8 | #e9ebed | 4.42 → **5.08** ✅ |
| 暗 | `rgb(93,172,254)` = #5dacfe | #25292f | 5.55 → **6.12** ✅ |

非 hover 承载面安全边际（同色在 surface-1/surface-2/bg 上）：亮 6.08/5.16/5.56、
暗 6.85/6.22/7.60——双主题全部 ≥5.1（`.row-link` 也被树/搜索/配额等非 hover 行
引用，此矩阵是收口依据）。色相仍 accent 族（88% 配比），下划线 hover 语义不变。
