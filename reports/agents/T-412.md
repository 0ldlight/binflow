## 做了什么

FR-21-AC8（P2 挂账自 M3）兑现为 FR-136：virtual 仓的聚合浏览面打开——
`GET /api/storage/<virtual>/<path>` folder 面经既有路由即答 200 children =
成员并集（httpapi 零改动：handleStorageItem→storageNode→Get 的 folder 拼写臂
+ writeFolderInfo/serveRootFolder→List 的聚合臂，两张脸都在 service 层落地）。

### 实现三点

1. **List 的 virtual 臂**（service.go → virtual.go `listVirtual`）：按
   `virtualMemberOrder`（与 pull 解析同一个两桶序，单一顺序源）遍历成员，
   `ListByPrefix` 取各成员存储行，按 path 去重合并——**同名路径取序内第一
   成员的行**（= pull 该路径会服务的那个成员的行，「解析顺序与 pull 聚合
   同源」由同一次顺序计算保证，不引入第二解析通道）。合并结果按 path 重排
   保持接口的 path-ordered 契约。remote 成员只出缓存行（T-406 listing 面
   口径：浏览永不回源）。行保留成员 repo key（存储面真相；与 pull Get 返回
   成员 node、aql.md §7-2「结果行 = 实际存储仓」同姿态——httpapi 的
   FolderInfo envelope 仍渲染 virtual key）。
2. **Get 的 folder 拼写臂**（virtual.go `getVirtualFolder`）：尾斜杠探询在
   进 pull walk 之前由成员**存储行**作答——第一个持有 folder marker 的成员
   的行；无人持有 marker 但有严格子路径时**合成 display-only marker**
   （virtual key、FolderMarkerSHA、零副作用不落库——ADR-0013「virtual 扫描
   不污染成员」；明确不复制 remote 臂的读侧材料化专用分支，T-406b 教训）；
   全空 → ErrNodeNotFound。上游永不被探询（目录不是上游资源）。无斜杠拼写
   仍走 file 面（folder 行不是下载命中——TestVirtualFolderMembersKeepWalking
   语义零变化）。
3. **读门归位**（service.go List）：virtual 分支从「allow 之前 400 拒绝」改
   为「allow 之后聚合」——与 Get 同序（先门后类分派），越权者只见到门自身
   的回答（401/403），零成员行泄漏（FR-136.4「沿内容面 allow() 既有」）。
   loadLocalRepo 的「aggregate listing is deferred」陈旧文案改为真实语义
   （该 loader 服务 /v2 写面等 local-only 用例）。
