## 二、方法与关键裁决

1. **官方规范优先**：GOPROXY 是有公开规范的协议，端点/转义/404-410/逗号管道回退/.info 契约/.mod 合成义务/latest 候选序/私有模块配方全部以 go.dev/ref/mod 原文为基准（高置信度主体）；反编译只进 S1–S12 补充清单。
2. **clean-room**：零代码粘贴；正则锚点属于「常量表」（GoVersionUtilities 的版本形态正则）按允许范围引用；类名只出现在本日志与规格的「来源」标注，不出现在行为描述行文中。
3. **三处口径澄清**（防实现票踩坑）：
   - 票据文本 `$BASE/binflow/goproxy/<repo>/...` 的 `goproxy` 段不存在——PRD 87.1/AC 字面 `$BASE/binflow/<repoKey>/...` 为准（规格 §1 显式登记）。
   - `GONOSUMCHECK` 非真实 go 环境变量（票据文本讹传）——真实面 `GONOSUMDB`/`GOPRIVATE`/`GOSUMDB`；`-insecure` 是废弃 go get 旗标非 GOFLAGS 值，替代 `GOINSECURE`（§7.1 勘误）。
   - Artifactory 对 remote go 仓直连显式 400（assertRemoteRepoBlock）——BinFlow 按 PRD AC3 允许直连，分歧点显式登记不采纳（§6.2）。
4. **反编译关键发现**（均已转行为行为条目）：wire→存储为**解码形态**（`!x`→大写，`!!`→400），回源上游时重新转义；`.versionList`/`.latest`（无斜杠怪癖）内部缓存标记；`.info` 缺失时由 zip mtime 合成并回写；`.mod` 仅 `+incompatible` 触发合成；list 仅聚合 `.zip` 存在的版本、版本行带时间戳列（BinFlow 收紧为纯版本列，S7+S13）；HEAD .mod 未命中 410；virtual 文件类 first-found / list 并集 / latest 全局最优。
5. **加严面标注**：Artifactory 上传不做 .info/.mod 内容校验——BinFlow 按 PRD 87.3 加严（400），规格以 PRD 为准并注明差异来源（§5.2）。
