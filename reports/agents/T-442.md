## 1. 架构决策（票内核定留痕）

1. **三型枚举器全部落 `internal/remote`，adapter 包零改动**（area 内取舍，非义务）。理由：适配层 import remote（单向）；若在 adapter 实现解析、经 registry 注册回 remote，则 remote 包自测无法覆盖（import 环）。协议解析（index.yaml/Packages/repomd+primary 的**读侧**）与既有 adapter 的**写侧**渲染引擎正交，无重复——helm `parseIndex` 的 read-modify-write 文档引擎仍在 adapter，browse 只做 urls[0] 定向抽取。
2. **T-448 的消费缝**：`(*remote.Engine).BrowseRemote(ctx, permit, repoKey, folder) (*BrowseResult, error)` + `remote.BrowseSupported(packageType)`。repo service 接线时在 children/listVirtual 的 allow() 通过后调用，permit 传 `func(folder string) bool { return s.allow(ctx, p, repoKey, folder, ActionRead) }` ——**ACL 字面同源**（AC2 的实现方式）。返回值：Entries（display-only 合成行，Path 全路径无尾斜杠 + IsFolder）+ Degraded（远端层错误态文案；非空时 Entries 空、error nil——已缓存行由调用方继续出，不整树塌）。
3. **快照缓存 = metadata TTL 映射**（remote-browsing.md §1「按 Metadata Retrieval Cache Period 缓存」）：整树 path 集缓存在进程内，窗口 = `RemoteConfig.MetadataTTLSeconds`（DDL 默认 600s，0 → 600s）；签名含 URL+username（改配置即时失效）；`Forget` 清扫。不落 node/blob/cache-state 行——「metadata 缓存行」的官方语义以进程内快照承载，**display-only 合成行零落库**（§4-3）。
4. **assumed-offline 同一套**（§4-2「上游压力防护与既有 pull-through 同一套」）：browse 的 transport/5xx 故障 `markOffline`（窗口内再 browse → 零上游接触 + 错误态）；401/403 降级**不**开窗（与 fetcher 的 resource-unfound 族一致）；新鲜快照在窗内照常出（零上游接触，等价 fetcher step-4 本地副本姿态）。**Test 探测针则明确零状态**（AC3「认证探测零副作用」——探测故障绝不开窗、不写任何行；测试以「探测后下一次 Fetch 仍打上游」钉死）。
5. **wire 裁定（歧义⑥，conductor 预裁采纳 + 本票留痕）**：`POST /binflow/api/repositories/{key}/test`，**repositories 域新路由**（与 replication Test 分族——消费面（仓库表单）与语义（探上游而非推目标）不同）。门 = `repoManageGate{repo, write:true}`（与 PUT/POST 配置臂同款：draft body 可携带凭据，只读 manager 不得用存储凭据指向任意上游）；body 可选 `{url, username, password}`（T-422 TargetOverride 同构三分支：无 body=存储配置探测〔解封密钥〕/ 带密码=明文对、不咨询存储/ 仅改 URL 或 username=**匿名**探测——密封密钥绝不静默送往别的主机）。呈现 = T-422 同款 `{ok, status_code, message}`，ok:false 走 HTTP 400（auth.config.test 姿态）；audit 词 `repository.remote.test`（internal/audit 常量已登记）。**LC 登记**：建议 PM 在 milestone-16 契约矩阵补一行（LC-83 族关联；本文件即留痕）。
6. **探测为包级函数而非 Engine 方法**：引擎在 repo.New 内部组装（架构 §5.4——cmd 与 adapter 均不可见），REST 面只持有 metadata.Store；`remote.TestRepositoryUpstream(ctx, md, repoKey, ov)` 复用包内 `effectiveSocketTimeoutMs`/`NewClient` 姿态（同 SSRF 链/超时/凭据拼写），一次性 client（不入池、不残留）。`RemoteUpstream`（RemoteV2Plane）缝不可用——其门限 v2 族（docker/helmoci），排除 helm classic/deb/rpm。
7. **探测 pass 判据 = 2xx/3xx/404**（票内 C 层裁定，无官方锚）：registry 族上游（docker/helmoci）裸根 404 是设计行为，探测的问题是「可达 + 认证未被拒」而非内容；401/403 = 凭据被拒（FE 内联失败臂）；其余状态/传输故障 = Connection failed / transport 族（§9.2-C-8 形状移植）。**与 replication 探针的 200/302 严格判据的差异已在 probe.go 注释登记**。
8. **尺寸上限（remote-browsing.md R-d 的 C 层参数定案）**：索引文档走 client 既有 64 MiB 缓冲上限 + 解压上限 256 MiB（覆盖 Fedora/EPEL 级 raw primary.xml ~100-300MB 的下沿；.gz/.bz2/.xz 三种压缩按后缀解）+ 派生路径集上限 500,000（防 64MiB 恶意文档膨胀显示行）。

## 2. 三型枚举形态（batch-1 实际口径）

- **helm classic**：`GET index.yaml` 一文档全树；每 entry 的 urls[0] → path（相对拼写原样；绝对 URL 取 path 部、剥 query/fragment；`..`/`.` 段拒绝——索引项不得越出仓树）；index.yaml 本身作根文件行。chartsBaseUrl 分离（T-367）不影响树派生（取 url 的 path 分量）——**登记**：若上游 chart 与 index 不同基座，浏览行路径仍按 url path 归树。
- **deb**：suite 集 = 本仓 dists/ 下已缓存 node 行的首段（**Debian 无 suite 索引文档**——诚实发现源 = apt 客户端已拉过的 Release 行；纯 HTML 抓 dists/ 属规格明确不做的脆弱族）。每 suite `GET dists/<suite>/Release` → checksum 节（MD5Sum/SHA*/Checksums-*）枚举 dists/<suite>/ 文件行（含 by-hash 镜像，忠实上游树）；每索引目录**择一** Packages 变体（无压缩优先，次 .gz/.bz2/.xz）解压解析 Filename: 节 → pool/ 行。**batch-1 边界登记**：Sources 索引作为文件行枚举但其 stanza 的 pool 源码文件不派生；InRelease 不在 Release checksum 节内、不单独探测（树中缺席为已知小失真）；flat repo（根 Packages、无 dists/）无 suite 可发现 = 零远端行。
- **rpm**：`GET repodata/repomd.xml` → 每个 `<data>` 的 location href = repodata 文件行；`type="primary"` 文档解压 → `<package><location href>` = 包文件行（Packages/<arch>/… 树自然派生）。primary 缺失/不可读时树降级为 repomd 自身枚举的 repodata 行（不整塌）。
- 三型共同：unfound（404/410）= 健康但空，**不缓存**（上游长出第一个索引下次 browse 即现）；单文档故障的容差按型内策略（deb 丢 suite/丢单索引不降级整层）。
