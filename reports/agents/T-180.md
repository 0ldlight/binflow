## 做了什么（对照六条 AC）

### AC ① replications CRUD REST + 聚合 status 端点

`internal/httpapi/replication.go`（新文件）+ `server.go`（Deps 两字段）+ `router.go`（四条路由）：

| 端点 | 行为 |
|---|---|
| `GET /binflow/api/v1/replications` | 全量配置列表（bare JSON array，沿 `/api/v1/permissions` 惯例）；**不含 target_password / target_password_enc** |
| `POST /binflow/api/v1/replications` | 建配置；密码经 `Deps.ReplicationCipher`（ADR-0012 enc:v1）封存后落库，**永不回显**；201 + 配置行 |
| `DELETE /binflow/api/v1/replications/{name}` | 删配置（按名解析 id）；任务行随 009 FK 级联；204 / 未知名 404 |
| `GET /binflow/api/v1/replication/status` | T-159 面板载荷：targets（配置×ConfigStatus 拍平）+ events（跨配置合并 newest-first，默认 limit 50、`?limit=` 1..500） |

门禁：四条路由均 `routeAuth{required:true, admin:true}`；create/delete handler 内再查 admin
（写审计者不依赖路由细心，沿 handleSystemGC 先例）。未接线实例（Deps.Replication 为 nil）
四端点统一 **501**（T-159 裁定 6 的「实例未启用复制」降级）。错误体走 errors[] 信封
（沿 `/api/v1/storage/migration`、`/api/v1/system/gc` 治理族惯例）。

创建校验（table-driven 固化）：name 1..64 字符 `[A-Za-z0-9._-]` 且首字符字母数字
（保证 DELETE 单段可寻址、无 dot-segment 拼写）；source_repo 必须存在（预检查名出问题键，
沿 permissions 面先例）；target_url 必须绝对 http/https（镜像 engine.targetURL 的闸，坏配置
在 REST 时 400 优于任务事端 not-retryable）；数值字段非负；重复名 **409**；max_items_per_push
缺省 0 → 1000（009 DDL 默认，store INSERT 恒带列需 handler 归一）；enabled 缺省 true（`*bool`
区分缺省与显式 false）。无 master key + 带密码 → 400 点名 `BINFLOW_REMOTE_CREDENTIALS_KEY`
（绝不落明文，ADR-0012 同款 fail-fast）。

审计：`replication.config.create` / `replication.config.delete` 字符串字面量（沿 engine 的
`replication.push` 先例——M6 词汇未落 internal/audit，见遗留①）。

### AC ② cmd 复制引擎装配

`cmd/binflow-server/main.go`：

- **openStack** 末段新增：`openReplicationDB`（metadata 库上的**第二条连接池**，
  DSN 带 `foreign_keys(1)` + `busy_timeout(metadata.BusyTimeoutMs)`——009 级联与双池争用
  所需的两个 per-connection pragma；journal_mode 是库文件属性 metadata.Open 已设，store 无
  LIKE 查询，其余 pragma 留 metadata 内部）→ `replication.NewSQLiteStore` →
  `replicationCipher()`（`remote.LoadKey` 复用 BINFLOW_REMOTE_CREDENTIALS_KEY，与 remote 仓库
  凭据同钥同 scheme，ADR-0021 复用裁定）→ `replication.NewEngine(store, st, opts)`
  （blobs 就是 serve 写入的同一 storage 引擎；Logger/Cipher/Audit 注入）→
  `repo.AttachReplicator(svc, engine)`。错误路径逐层回收（replDB→st→md）。
- **runServe**：`stack.startReplication(ctx, logger)` 在 `srv.Run` 前启动 engine.Run
  （独立可取消 ctx + goroutine + sync.Once drain）。停机序：HTTP 排空 → `drainReplication()`
  （取消 → **等 Run 返回**（在途任务回退 pending）→ CloseIdleConnections → "replication
  engine drained" 日志）→ `stack.close`（st → replDB → md）。serve 失败路径同样 drain。
- **newAssembledServer**：`deps.Replication = stack.replStore`；
  `deps.ReplicationCipher = replicationCipherSeam(stack.replCipher)`（nil 指针→nil 接口，
  防 typed-nil 翻转 400 分支，沿 T-179 oidcLoginSeam 同款单点守卫）。

## T-159 契约对齐（差异清单）

**status 端点零差异**：targets[]/events[] 字段名、snake_case、int64 计数、'' 时间哨兵、
`[]` 非null、凭据不下发、ReplicationID 不重复、newest-first 合并、默认 50/`?limit=` 可调、
403/501/200+空 targets 三态——逐项按裁定实现并有断言钉死（见 t180 测试）。

**CRUD 面为新增面（T-159 时无消费方，遗留 1 提及的 UI 票此前端无需适配）**，形状供后续票对齐：
- list 为 bare array（沿 permissions 面）；create 201 回配置对象；delete 204；重复名 409。
- `enabled` 缺省 true（POST body 可显式 false）；`max_items_per_push` 缺省 1000。
- 密码字段 `target_password` 只写不读；status 面连 `target_username` 也不出（CRUD 面出——
  无密码时无敏感性，管理面惯例）。
