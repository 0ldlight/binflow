### 行为口径（对齐规格）

- 有钥（local deb，`keyPairName` 关联）：每次重算（debPUT 自动链 + `/binflow/api/deb/reindex`）写 InRelease（clearsign）+ Release.gpg（detached armor）。
- 无钥/钥不可开（ErrNoKeypair/ErrUnavailable）：跳过签名 + 清扫旧签名文件（DB-1；debian.md §4.2）；ErrUnavailable 记 WARN（配置态）。
- 其他签名执行错：浮出（同步 reindex 500 带上下文；异步链 ERROR 日志）。
- 轮换：换关联 → 重算 → 新签（测试断言旧钥验不过、新钥验过）。
- virtual：聚合面签名是 seam 驱动的——受管路径 virtual 不能带关联（repo 层按名拒绝 keyPairName），故实际姿态仍是登记的 404/unsigned；手工塞关联（非受管形态）时聚合用自己的钥签自己的字节（成员签名绝不复用——验签测试断言对成员 Release 必须失败）。
- D-8：不收 `X-GPG-PASSPHRASE` 头（口令随 keypair 行密封，签名时解封即弃）——debian.md §4.3 该头按 gpg-keypair.md D-8 裁定不实现。
- skipSnapshotPublish 等旁支：未涉（票面确认）。

6. `TestReleaseSigningGPGClientRoundTrip`（无 gpg 则 skip）: 线上 InRelease/Release.gpg 经本机 gpg `--import`/`--verify` 双形态往返。

## 真实 apt gpg 校验链（BINFLOW_DEB_E2E_APT=1，debian:bookworm 容器）

`TestClientE2EAptContainerSigned`（262s，PASS）——生成钥（真 Manager.Generate 面）→ 仓关联 → dpkg-deb 真 .deb → curl debPUT → 异步重算签名 → 容器内：

1. **阴性对照**：无 signed-by、无 trusted=yes 的裸 `deb` 行 → `apt-get update` 拒绝，输出 `NO_PUBKEY 839E1796BEDDC62A`（证明校验真开启，非静默信任）。
2. **正向**：公钥 `gpg --dearmor` 入 `/usr/share/keyrings/binflow.gpg`，`deb [signed-by=…]` → `apt-get update` 过（InRelease 验签）→ `apt-get install -y binflow-signed` → `Status: install ok installed` / `Version: 1.0-1` / 二进制输出 `binflow t321 signed`。

容器腿首跑发现并修掉一个真问题：armored `.asc` 直用 signed-by 时 apt 报 `Unknown error executing apt-key`，按 DebianRepository/UseThirdParty 姿态改走 dearmor（容器内装 gnupg 后 `gpg --dearmor`），即绿。
