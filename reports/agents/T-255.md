## 一、交付内容

### 1. W-1 关闭：在途持有集（mechanism B）— `hold.go`（新文件）

- `holdSet`：进程内 sha256 → `{count, refreshed}`；`acquire`/`release`/`held`，全 mutex 保护。
- **注册时机（ anchoring 不变量）**：`Session.Commit` 在**摘要校验后、rename/publish 之前** acquire（disk：fsync 前；S3：dedup StatObject 前、CopyObject 发布 blob key 前）。注册先于可见性 ⇒ GC 扫描若能看到 blob，则必然晚于 acquire ⇒ 删除前的 hold 门不可能错过它（这是 happens-before 论证的锚点，godoc 全文见 `engine.GCSweep`）。
- **释放语义**：成功 Commit **保留** hold（等 repo 五路径的 `ReleaseGCHold`，T-256 接线）；失败 Commit 由 deferred complement 立即释放；漏 release / 进程崩溃 ⇒ TTL 兜底。**refcount 而非 presence**：并发同内容上传（dedup 命中双方都 acquire）时，一方 release 不会剥掉另一方在途元数据事务的保护（`TestGCHoldRefcountSurvivesConcurrentDedup` 钉死）。
- TTL：`DefaultGCHoldTTL=600s`、`MinGCHoldTTL=60s`、显式零值取默认（grace 同款零值语义）；`Options.GCHoldTTL` / `S3EngineOptions.GCHoldTTL` 承接 `storage.gc_hold_ttl_seconds`（config 键 §8 已登记，cmd 装配归 T-256）。过期条目在 `held()` 惰性清除。
- S3 的 multipart 在途无需单独持有：在途分片位于 `sessions/` 前缀，GC sweep 从不扫描该前缀；唯一可见性事件是 Commit 内的 CopyObject，acquire 先于它（godoc 注明）。

### 2. W-2 关闭：删除前引用复核（mechanism A）— `gc.go`

- apply 模式下每个候选删除前过 `gcDeleteGate`：**hold 门 → Live 门 → unlink**。
- **门序是正确性不变量**（godoc + `TestGCHoldGatePrecedesLiveRecheck` 钉死）：
  上传方时间线 `H(acquire) < P(publish) < M(metadata commit) < R(release)`。
  - 若 `M ≤ T_Live`：忠实 Live 看到引用 → 跳过；
  - 若 `M > T_Live`：则 `R > M > T_Live > T_hold`，而 `H < P < scan < T_hold` ⇒ T_hold 时刻注册在场且未释放 → hold 门跳过。
  两种交错都安全；**倒序（Live 先于 hold 门）会重开窗口**——M 落在两门之间时 Live 太早看不见、hold 门又太晚（已被 R 清空）。单测用「Live 副作用执行 release」构造该交错证明现实现跳过。
- `GCMarker{ Mark() (map[string]struct{}, error); Live(sha) (bool, error) }`（api.go）：Live 契约 = 有界单点查询（metadata.IsReferenced 形态，T-256 接线）。legacy `ReferencedFunc` 适配器：Mark=fn()，Live=重跑 fn 取成员；**引擎识别 legacy 形态并以 apply 阶段一次惰性重快照（"mark 集重查"）替代逐候选 Live**，避免每删除一个 blob 重建一次引用集（`TestGCLegacyMarkerResnapshotSkipsLateReference` 钉两跳语义）。真 marker 则逐候选 Live 且不重快照（`markCalls==1` 断言）。
- Live 出错 ⇒ 保守跳过该候选不删、错误作为 sweep firstErr 上抛（disk 记 firstErr 继续；S3 沿该文件既有风格即时返回）。
- **dry-run 语义**：候选排除 held blob（不看 grace，ADR 决策 2）；不做 Live 复核（无破坏面，且保无并发时与 M4~M8 逐字节同源的口径——除 hold 排除本身）。
- 候选门（dry/apply 共同）：mark 命中 → hold 命中 → grace → 候选。apply 返回 deleted 列表（被门跳过者两个计数都不进——方向只会更保守，ADR 决策 5 登记）。

### 3. 三引擎实现

- disk（gc.go）/ S3（s3.go）：完整 `GCSweep` + hold 生命周期 + `ReleaseGCHold`（纯内存、不可失败、未知 sha/双重/过期后/Close 后均 no-op）。
- migration（migration.go）：`GCSweep` 按 bypass/dual-write/completed 委托（同一 marker 下传，Mark 可能被多次调用——契约已注明）；`ReleaseGCHold` 同时释放两侧（dual-write Commit 在两个引擎各注册一次）。
- **迁移清单旁路**：`diskList`/`s3Set`（后台迁移 diff 输入）改走 `gcList`（hold 门与 grace 全关）——迁移清单是盘点不是回收决策，held 的存量 blob 仍须被复制；否则无 repo 接线的直接存储消费者会让迁移漏拷（TestMigrationManyBlobs 38.9s -race 绿验证）。
- **legacy `GC` 面保留**：三引擎的 `GC(ctx, func()…, grace, apply)` 签名不动，内部包 `ReferencedFunc` 委托 `GCSweep` —— CLI/REST/既有测试零改动即获得 hold + 删除复核保护。

### 4. 与 ADR-0031 字面的两处偏离（均已定案并论证，请 architect 复核）

1. **`Engine.GC` 参数未就地升级为 GCMarker**。ADR 决策 3 要求参数升级（旧 func 形态适配器兼容）；但就地换签名会把编译涟漪打进 httpapi（`GarbageCollector` 窄接口 + system_gc 两处 + t114 mock）与 cmd main.go 两处——均在本票 area 之外且被派单明令不动（"不动 cmd"）。采用**加法**：`Engine` 新增 `GCSweep(GCMarker)` 与 `ReleaseGCHold`，`GC` 保留为 legacy 面。语义等价（legacy 委托同一实现，W-1/W-2 保护对两种调用面都生效）；T-256 重写调用方时可顺势收口 GC→GCSweep 并删 legacy 面（届时 ADR 字面达成）。
2. **派单括注「BeginSession/Resume 注册、Commit/finalize 释放」与 ADR/§14.2 的生命周期（Commit 注册 → repo release → TTL 兜底）不一致**，且 BeginSession 时刻 sha256 未知、无法注册。按派单自述「权威契约 = ADR-0031 + §14.2」采 ADR 生命周期；Commit 入口 acquire、失败 finalize 自动 release 涵盖了括注的合理部分。

## 三、故障场景覆盖（可靠性清单）

- **并发**：并发写同 blob（refcount + singleflight 既有）；上传×grace=0 apply 赛跑压力腿（-race ×5）；GC 与 upload 的锁序（refs-mu→holds-mu 无环，论证见 hold.go/gc.go 注释）。
- **中断**：Commit 后崩溃未 release ⇒ TTL 兜底回收（六例表驱动）；失败 Commit（rename EACCES 注入）自动释放不留 hostage。
- **校验失败**：digest mismatch 在 acquire 之前拒绝（不产生 hold）；Live 查询失败 ⇒ 保守跳过 + 错误上抛。
- **GC 误删**：W-1（hold 锚定 + 删除前 hold 复核）、W-2（apply 重快照 / 真 marker 单点 Live）双门；门序倒置由单测钉死。
- **残留微窗（如实登记）**：dedup 命中型 Commit（无新鲜 publish 锚定 acquire 早于扫描）与最后一门到 unlink 的物理间隙——与一切 check-then-unlink 文件序列同类的微秒级窗口，ADR 候选 C（停写）才能根除，已被否决。

2. T-256 的接线面（本票已备好）：repo 五路径 Commit 成功后 `ReleaseGCHold(sha)`（Put/PutFromBlob/PutLandedBlob/PutManifest/remote pull-through）；REST/CLI 调用面 GC→GCSweep 换真 marker（Mark=liveChecksumSet，Live=metadata.IsReferenced 单点，dev-go-core 侧助手）；`storage.gc_hold_ttl_seconds` → Options/S3EngineOptions.GCHoldTTL 装配；serve.lock（cmd）；届时可删 legacy GC 面达成 ADR 字面。
