## 四项落点

### C6+D44-1（P0，最重要）：ping 无条件 401 挑战

推翻 v1.0~v1.2 的「匿名开 → ping 200 `{}`」：
- **DE-01**：未认证一律 401+Bearer 挑战（无条件，不随 `anonymous_access` 变化）；已认证 → 200 `{}`；层级置信度标「spec + 真实世界行为（Docker Hub/GHCR/Harbor 同构，docker-registry.md §0/§5）」。
- **FR-11 探针弹**：写明根因（docker daemon/containers-image 为 ping-缓存型认证器：ping 200 → 判无需认证 → 后续 401 不再协商——T-44 实证 push 零凭据全断、错口令 login Succeeded）；**匿名拉取不受损路径**（挑战 → 无凭据 `/v2/token` → `anonymous_access=true` 照发 pull scope 匿名 token → 匿名 pull 照常，podman 挑战模式实证全通）；FR-11-AC4 随 ping 挑战化在默认配置下恢复有效。
- **FR-11-AC2/D04 命令**：断言反转（无凭据 → 401，anonymous_access 开/关均如此；带 Basic → 200 `{}`）；D04 补匿名 token 路径验证注释。
- 联动：场景 B（匿名读机制与 M1 generic 直读不同但语义一致）、Q2 暂行假设（开关管「匿名 token 是否发 pull scope」，ping 恒挑战）。

### C4+D44-3（P0，口径补明）：token POST 表单凭据

- FR-11 行为规格新增**凭据来源**段：① Basic 头；② POST OAuth 表单（`grant_type=password` 的 `username`/`password` 或 `client_id`/`client_secret` 对）与 Basic 同权（官方 token spec OAuth 流凭据在 form body——buildx/helm 用此形态，T-44 D44-3 实证其被忽略后签出匿名 token 致 Bearer 被拒）；两者皆缺才按匿名。
