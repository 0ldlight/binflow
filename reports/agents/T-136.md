### 架构决策

- **单副本硬约束**: `values.schema.json` 中 `replicaCount` 和 `hpa.maxReplicas` 均设 `maximum:1`，`--set replicaCount=2` 被 schema 拦截
- **口令分离**: admin password 经 Secret（secret.yaml），不进入 ConfigMap（ADR-0009）
- **Ingress 无 rewrite**: `/` 与 `/v2/` 均直通，无 rewrite 注解（ADR-0010）
- **enableServiceLinks: false**: 防止 K8s 注入的 service 环境变量（如 BINFLOW_SERVICE_HOST）被 BinFlow 配置解析器当作未知 BINFLOW_ 变量拒绝启动
- **镜像默认 distroless**: ghcr.io/lzwzzy/binflow tag 默认 `v1.0.0-distroless`

## 已修复的 Bug

### enableServiceLinks 缺失导致 Pod CrashLoopBackOff

**现象**: Pod 启动后立即退出，日志显示：
```
binflow-server: config: unknown BINFLOW_ environment variable(s) BINFLOW_PORT, BINFLOW_PORT_8080_TCP, ..., BINFLOW_SERVICE_HOST, BINFLOW_SERVICE_PORT
```

**原因**: Kubernetes 默认向 Pod 注入以 `{SERVICE_NAME}_SERVICE_HOST` 等命名的环境变量，BinFlow 的配置解析器将所有 `BINFLOW_` 前缀的 env var 视为配置项，未知变量会拒绝启动。

**修复**: 在 deployment template 的 pod spec 中添加 `enableServiceLinks: false`。

### arm64 镜像在 amd64 kind 节点上无法运行

**现象**: kind 节点是 amd64（Docker Desktop on macOS Rosetta），但本地构建的 binflow-test 镜像为 arm64 架构，导致 Pod 无法启动。

**修复**: 使用 `docker buildx build --platform linux/amd64` 重新构建镜像，再 `kind load docker-image` 加载到集群。
