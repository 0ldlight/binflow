## 一、做了什么

`internal/repo` 的 virtual 解析子域全部落地：

1. **两桶序解析（RE-07/08，C3）**：`virtualMemberOrder` 逐请求现算（零解析缓存）——优先桶（`priorityResolution=true` 成员，桶内声明序）→ 其余成员（桶内声明序）。优先标记读成员自身 config JSON（local 透传 blob / remote 规范形，同名字段一个探针通吃，坏值安全默认 false）。
2. **下载首命中即停 + `X-BinFlow-Resolved-From`**：local 成员查 node（folder 哨兵不算命中，聚合浏览 P2）；remote 成员走 T-66 引擎全链（FR-20 含缓存与 stale 语义——M50 上游包经 virtual 拉取落盘即依赖此）。命中体包 `resolvedFromReader`：实现 `ExtraHeaders() http.Header`（与 remote 的 hinted reader 同一结构化缝），**合并**底层 X-BinFlow-Cache / X-Binflow-Upstream-Error 后叠加 Resolved-From。
3. **R10 stale/miss 规则（FR-21-AC7）**：消费 `FetchResult.HasCopy`——成功必有副本（含过期副本 STALE 与 assumed-offline 期）即该成员结果、不跳桶；`*FetchError{Unfound}`（负缓存/无副本/offline 无缓存）才继续；**非 Unfound 成员故障（SSRF 400 / hardFail 502）原样透传**（「仅真 404 才继续」的严格读法——掩盖安全拒绝/硬失败配置为全仓 404 更危险）。HasCopy=false 的防御分支按 miss 继续并 WARN。
4. **探索性 miss 不落盘（ADR-0013）**：探测前 pre-read 成员负缓存行（fresh negative 记账），探测 Unfound 后 `DeleteCache` 撤掉**本次探测写入的**负缓存行；pre-existing fresh 行不删（guard 区分）。副作用上限：误删一行已过期行 = 零危害（下次 miss 重写）。
5. **写路由（M52/M53，C5）**：`resolveWriteRepo` 在三个 Put* 之前解 virtual → 无 `defaultDeploymentRepo` → **405 + Allow: GET + C5 定案文案逐字**；有则换址到目标 local 成员走**目标仓原生**权限对/覆盖检查/checksum 链/audit（node 实落成员，virtual GET 逐请求现算立即可见）。路由读取用**容忍式**探针（三别名并收、`{}` 裸行→无路由→405——T-67 harness 直种 `{}` 行的兼容，`parseVirtualConfig` 严格形留给建仓面）。目标仓消失（drift）→ 换址后重载得 ErrRepoNotFound（诚实 404）。
6. **virtual DELETE 恒 405**（BinFlow 有意不兼容，RE-08）：未配路由 → C5 文案；已配路由 → truthful 措辞 `Deletes are not propagated through the virtual repository '<key>'; ...`（对配了路由的仓说「未配置」是说谎）。
7. List 聚合维持拒绝（FR-21-AC8 P2 可延后），措辞更新；`loadLocalRepo`/`refuseNonLocalWrite`（virtual 臂改为安全网）/Get 分派注释全部去掉「lands with T-71」过渡语。

读权限门在 **virtual key** 上、先于任何成员接触（T-66 同姿势，测试断言零上游流量）。
