## 端到端时间线（全部实际执行，二进制 real server）

1. **弃置会话持久化**：POST→PATCH(512KiB)→弃置。sqlite 行在场（expires=+24h）；`uploads/<id>/data` 524288B 与源前半 `cmp` MATCH；无 `sessions/` 目录。
2. **AC4 真栈**：在线 export 38ms → 导出库 upload_sessions/web_sessions 均 0 行（表在、行清）；活库行不动。
3. **干净重启（SIGTERM）**：行+目录被清——`Engine.Close()` 对在册会话逐个 `cleanup()`（删行删目录）。**比对 f21fd74（T-209 前）同一函数逐字相同 → 既有引擎语义，非本票回归**；效果上干净停机不孤儿化会话行。
4. **崩溃重启（kill -9）**：新会话 POST→PATCH(512KiB)→kill -9→重启 → **行 + 部分数据幸存**（未过期行保护目录，sweep 不误杀）。
5. **过期 sweep**：停机后 sqlite 回填 `expires_at` 为过去 → 重启 → 行 count=0、`uploads/` 空（启动 sweep 删行删目录）。
6. **正常完成**：POST→PATCH（行在场 count=1）→PUT `?digest=sha256:670ae5f9…` 201 → 行 count=0、`uploads/` 空；GET blob 200，sha256 逐位一致（`cmp` MATCH），落盘 `blobs/67/670ae5f9…` 内容寻址正确。

## 观察（非阻塞，供 conductor 裁量）

- **O-1（语义边界）**：「重启可续传」实际覆盖**崩溃路径**（kill -9/断电，行+目录幸存，`ResumeSession` 可恢复）；**干净停机**（SIGTERM/compose restart）会经 `Engine.Close()` 清空在册会话——续传前提不存在。此为 T-209 之前的既有 Close 语义（f21fd74 同码），且避免了干净重启后的孤儿行；但「重启可续传」若对外措辞，建议文档限定为"异常中断后"。
- **O-2（接线缺口，M7 候选）**：docker HTTP 层会话注册表为进程内存（`sessionRegistry`），重启后旧 upload URL 一律 `404 BLOB_UPLOAD_UNKNOWN`——引擎级 `ResumeSession` 已具备且被单测钉死，但**无生产调用方**把 DB 行接回 HTTP 续传。票面 AC 措辞为"经 `ResumeSession` 续传"（引擎 API），判 PASS；wire 级续传如需，另开票。
