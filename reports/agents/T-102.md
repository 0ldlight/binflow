### 2. GC 页（`/governance/gc`，AC② W35）

- 概况卡 `gc-stats`：storage stats（blob/逻辑/物理/去重率，与仪表盘同源）；「上次运行」按 R4 兜底引导到审计页过滤 `gc.run`。
- 危险区：dry-run 默认姿态（ADR-0015 勘误①）；**apply 必须先看当前参数下的 dry-run**——grace 变更后结果标过期、apply 关回并提示重新试运行。
- apply 二次确认（P5）：type-to-confirm **输入 `YES`**（console-ux §4.11「输入仓库实例名或 YES 确认」的后一分支——产品无实例名概念，派单的「输入仓库名」对实例级 GC 无指称对象，取规范明示的字面量分支），走 T-99 沉淀的 `confirmDisabled` 缝；对话框列候选数/字节 + grace 窗口。
- graceHours 高级项（`<details>` 折叠）：留空 = 实例缺省；0 = 无宽限窗口（黄字说明）；0..876000 校验（与服务端 maxGCHours 同值）。
- 409 互斥呈现：专用红面板「维护操作互斥」+ 服务端 message 原样 mono（含 holder pid/op 诊断）。
- 结果面板：dry-run（候选数/字节 + grace 说明 + 「REST 回执仅聚合计数，逐项走 CLI」的诚实提示）/ apply（实际回收 vs 试运行预计，分歧时注明「写入方竞态的诚实分歧非错误」）/ **0 候选绿色空态 `gc-empty-ok`**（§5.3 好消息态）。

## 二、契约漂移（conductor 转 architect/PM 回写）

1. **`GET /api/v1/audit` 无 `path` 过滤参数**：派单描述「repo/path/actor/action/since/until 过滤」与实现不符——`audit.Filter` 只有 Repo/Actor/Action/Since/Until（substores_console.go `repo_key = ?` 等）。UI 的 path 过滤按 console-ux §6.3 兜底为**已加载集客户端子串**并显式提示边界（count 文案「路径过滤仅作用于已加载集」）。若要服务端 path 过滤需后端票。
2. **repo/actor/action 均为精确匹配**（非子串）：spec 线框「仓库 [全部▾]」暗示枚举；UI 以 datalist 建议 + 文案「精确」呈现。过滤语义建议回写 GE-01 注记。
3. **GC dry-run 回执无候选清单**：`gcResponse` 仅 `{candidateCount, candidateBytes, deletedCount}`——spec §4.11「候选 blob 列表（digest/大小/最后引用时间）」不可实现，结果面板呈现聚合计数 + 逐项核对走 CLI 的引导。REST 面加清单属后端增量票（P2 债务候选）。
4. **派单「apply 输入仓库名确认」**：GC 是实例级操作无仓库指称；按票面 AC②「输入实例名」+ spec §4.11「输入仓库实例名或 **YES** 确认」的 YES 分支实现（产品亦无实例名概念）。若 PM 想要更强确认令牌需先定义实例名。
