## 复审修复段（REQUEST_CHANGES → done）

conductor 复审提出三处必须修（全在本 area），均已修复并回归：

### 修复 1 — 备份瞬态净化未覆盖 upload_sessions（AC4）
`PurgeTransientFromSnapshot` 原先只删 `web_sessions`，新表 `upload_sessions` 会跟着
备份走，违反 AC4（会话为实例级运行时状态，不得进入备份；且 upload_sessions 行
失去 `uploads/<uuid>/data` 后是孤儿行）。改为对两张表逐一独立探测 + 删除：
- 语句改为**字面量**（`DELETE FROM web_sessions` / `DELETE FROM upload_sessions`，
  无 SQL 拼接），表名为固定白名单非调用方输入，满足 gosec G202；
- 每张表先 `sqlite_master` 探测，快照早于该表（pre-010 无 upload_sessions）时
  no-op，不使导出失败。
- 测试 `TestPurgeTransientFromSnapshotRemovesWebSessionsOnly` 更名
  `TestPurgeTransientFromSnapshotRemovesRuntimeSessionTables`；fixture 种入一条
  upload_session 行（字符串时间戳，`ExpiresAt = metadata.NeverExpires`），断言
  净化后 `upload_sessions` 计数为 0。

### 修复 2 — ResumeSession 持 e.mu 调 old.cleanup()（锁序反转 + 误删共享态）
`ResumeSession` 注册新会话时，旧实现持 `e.mu` 调 `old.cleanup()`：
- **ABBA 死锁**：`e.mu → old.mu` 与既有 `s.mu → e.mu`（finishLocked → forgetSession）
  锁序反转；
- **误删共享资源**：`cleanup()` 会 `os.RemoveAll(dir)` + 删 DB 行，而新会话与该 id
  共享同一 `uploads/<uuid>/` 目录与同一行——旧引用清理会摧毁正要返回的新会话。
改为：持 `e.mu` 仅替换注册表并取出旧引用，**释放锁后**调新增的 `old.detach()`
（关 fd + 标记 done，使后续 Append/Commit/Abort 全部 no-op；不删目录、不删行）。
`detach()` 注释明确「调用方不得持 e.mu」。

### 修复 3 — TestV2BlobSessionSweepResidue 断言 `dataDir/sessions` 存在（AC2）
该测试原断言旧 `sessions/` 目录存在且为空；本票已把会话目录迁移到 `uploads/`
并 DB 化，原断言必然 FAIL。重写为 DB 语义：先 `metadata.Open` 再 `storage.OpenEngine`
注入 `Sessions: md.UploadSessions()` 缝；POST+PATCH「弃置」上传后断言
`ListExpired(9999...)` 有 1 行（证明 DB 持久化缝真实生效，原测试从未证明会话
有任何持久化）；Close 后重开第二个 engine 断言 0 行、`uploads/` 目录空（无残留）。

### 非阻塞项处理
- **Append 每 chunk 一次 SetState DB UPDATE**：保留现状。理由——chunk 边界即网络
  读块（copyWithCtx 32KB），本地 SQLite 下每块一次 UPDATE 的可测开销 < 1%；且
  state 仅作观测簿记（ResumeSession 以文件大小为真、重哈希重建），不值得引入
  throttle 复杂度。若未来 postgres + 高并发 PATCH 暴露为热点，再降频为
  `received` 变更按时间窗口批量 flush。
- **字段名 deviation（id vs sha256）**：维持 `id`（uuid 主键），理由已在前文
  「遗留 1」说明——commit 前会话不绑定任何 blob，uuid 才是正确主键。
