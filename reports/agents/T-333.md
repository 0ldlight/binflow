## 2. 决策要点（ADR-0040 摘要）

**写 B + 队列 B + 读 C**，要点八条：

1. **断路器不做错误分类学**——「成功/不成功」二分是唯一稳定判据（MinIO/Ceph/R2 错误形态各异）；closed/open/half-open 三态进程内；窗内 BeginSession 走 disk-only 快路、Open/Stat 直读 disk（免 per-请求超时惩罚）；零新配置键（binstore.yaml schema 冻结，排空 worker 复用 `migration.concurrency`）。
2. **写路径三点降级**（Begin/Append/Commit 任一时刻 S3 臂失败 → 弃 S3 臂继续 disk-only；Commit = disk commit + 入队 + 成功）——**site-3 反删盘条款废止**；单缝在 MigrationEngine/migrationSession，MPU 与 remote pull-through 免费覆盖；**地板 = disk**（disk 写失败仍诚实 500）。
3. **读回退**：Open/Stat 回退条件从 NotFound 扩为任何 S3 错误；回退命中计数 + 首错 WARN。
4. **一致性窗口声明**：disk 恒为超集（迁移方向 disk→S3 且 disk 不自动删）→ 回退无洞、读己之写保持；S3 桶是引擎私有物，带外读旧集合不在契约内；分歧关闭点 = `storage.replay.drained`。
5. **队列 = `<data>/replay-queue/<sha256>.json`**（temp+rename 原子、per-sha 天然去重、**派生可重建**——丢队列可 StartMigration 重扫恢复）；退避 1s×2 上限 5min、attempts 进程内重启重置；**无死信删除**（16 轮全败 → permanent-failed 记账，条目保留）；不进版本兼容承诺。
6. **排空与对账**：关窗即排空；drain 完 → `diskList`×`s3Set` 存在性 diff → missing 重入队收敛环 ≤3 轮 → 仍缺 permanent WARN；migration status 端点形状逐字节不变。
7. **治理交互**：队列不是引用不是 hold（ADR-0031 语义零变化）；source-gone = drop 条目（GC 只回收无引用件，其 S3 副本本就不需要）；GC/Delete 维持诚实失败（fail-open 只覆盖数据面）；**completed + 队列非空 → 拒启 fail-fast**；bypass/completed 零新代码路径。
8. **可观测**：指标六枚（`binflow_storage_replay_queue_depth` / `replay_drained_total` / `replay_failed_total{outcome}` / `read_fallback_total` / `s3_window_open`）+ 审计两事件（`storage.replay.window{phase}` / `storage.replay.drained`，发射点在装配层 facet——cleanup.run 先例，engine 不 import audit）+ 启动水位 INFO 行。

## 3. 备选方案对比

| 维度 | 选 | 落选理由 |
|---|---|---|
| 写路径 | B 故障窗 fail-open（稳态双写不动） | A 全量异步化把稳态翻成最终一致（H13「上传后双侧均有」变 eventual），为容错重写正确性模型不成比例；FR-50 承诺语义是「S3 写失败不阻塞」非「永远异步」——B 兑现承诺而非字面顺序。C（PRD 勘误）用户已否 |
| 队列载体 | B 磁盘目录 per-sha 文件 | A 违反 AC2 重启幸存；C（元数据表）破分层——ADR-0006 勘误①「storage 不读 DB」既有立场 + SQLite 写热点 |
| 读回退判定 | C 任何错误皆回退 + 可观测 | B 分类学两端都可能错（权限错被吞 / 网络错被当致命）；disk 超集论证使 C 无正确性风险，代价由指标兜底 |

## 4. 风险（登记于 ADR「后果」+ 本报告）

1. **磁盘满显性化**：窗口期 disk 是唯一副本 + PUT 全量落 disk——容量规划风险从 S3 后移回本地（Artifactory cache-fs 同姿态）；磁盘满 = 诚实 500（地板）。
2. **读回退吞 S3 配置错**：权限错/桶名错期间读全走 disk 不断服但迁移停滞——可见性全押在 `read_fallback_total` 持续增长 + `s3_window_open=1` + 首错 WARN 上（可观测义务，非分类学）。
3. **队列持久性 = 同卷命运**：队列与数据同 disk 卷，盘坏同失——但队列为派生状态（可重扫重建），无独立暴露。
4. **GC/队列竞态**：source-gone drop 语义成立的前提 = GC 只回收无引用 blob；若未来引入「S3 侧必须有全量副本」不变量需回本 ADR 重评。
5. **单实例前提**：断路器/排空循环是进程内状态——§9 多副本本就禁止（ADR-0031 同款立场）。
6. **窗口期 GC 诚实失败**可能被误读为「M12 又引入一个 500」——文档须明示这是治理面有意姿态（管理面可重试）。
