## 路由核对差异登记（router.go ↔ 契约页 ↔ spec）

**A. 契约页与路由不一致——spec 采路由验证文法，描述内已标注：**
1. npm packument/publish 三行的 `-/` 前缀拼写（NE 表）与适配器文法不符：实测文法 = `GET/PUT /binflow/api/npm/{repoKey}/{pkg}`（internal/adapter/npm/route.go + 测试 `npm/npm-local/demo-pkg`）。
2. npm unpublish 的 `?rev=` 查询形态不符：路由文法 = `DELETE …/{pkg}/-rev/{rev}`（整包）与 `…/{pkg}/-/{file}.tgz/-rev/{rev}`（单版本）。
3. npm dist-tags 族（`/-/package/{name}/dist-tags[/tag]`）路由在册、契约页未列——spec 未收（协议数据面，待契约页补册后再生）。

**B. 路由在册、契约页未列——收录裁定：**

## 与派单的偏差（实测推翻，逐条有据）

1. **docs.yml api 形态**：派单给的 `api: {path: openapi/binflow.json}` 对象形态在 CLI 5.112.0/5.113.1 与平台均解析失败（`Invalid object at path $.navigation`）。官方 schema（fern-api/fern `fern/apis/docs-yml/definition/docs.yml`）+ docs-starter 实例证实：**api 是 tab `layout:` 内的字符串条目**，且 tab 须在 `tabs:` 声明。定稿形态：
   ```yaml
   tabs:
     API 参考: {display-name: API 参考, icon: square-terminal}
   navigation:
     - tab: API 参考
       layout:
         - api: openapi/binflow.json
           slug: binflow-api
           display-errors: true
   ```
2. **必须新增 `fern/generators.yml`** 注册 spec（`api: specs: [- openapi: openapi/binflow.json]`），否则 `Failed to load API Definition referenced in docs`（官方 docs-starter 同构）。
3. **生成器放 `tools/openapi-spec/`**：fern/ 内放 .py 会让 CLI 误判 fern 目录（`Detected empty API definiton`）。
4. `fern/pages/api-reference.mdx` 删除而非保留（防双源）；8 处跨链已改指。**注意**：docs/user/api-reference.md 主源不动（红线遵守），fern 镜像页退役属本票结构性变更——T-458/conductor 重发布时请知悉镜像不再一一对应。
5. tag-description-pages 为主干 schema 项但当前 CLI 不识别，未启用（避免解析失败）。
