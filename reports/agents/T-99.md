### 关键决策（reviewer 请重点看）

1. **编辑=全量替换的保全**：UpdateRepo 提供 config 即整体重写（local 为 caller-owned JSON）。编辑表单从 GET 回显**预填全部 transport 支持字段**再整体提交，避免「改 quota 丢 patterns」；transport 未覆盖的本地 config 字段见契约漂移 4。
2. **删除双段流**（AC② 的「UI 呈现 400 原因」落法）：确认（未勾 deleteContent）→ DELETE → 非空 400 → **同一对话框重开**：HTTP 400 原文（含 `holds N node(s)`）mono 呈现 + deleteContent 预勾选 + 重新输入 key → 确认删除。空仓第一次即成功。
3. **已用列逐仓拉 usage**：仓库量级小（管理面手工创建），行级独立到达对齐 §5.2；403（无 read 授权）与错误降级 `—` 不显 0（§4.3「remote stats 不可用显示 —」同款）。
4. **virtual 成员「优先解析」呈现为只读 badge**：priorityResolution 是成员仓自身 config 字段，在本表单勾选会隐式改另一个仓的配置（跨仓 PUT）——只读标记 + tooltip 指向成员自身设置页；写面留后续票（遗留 3）。
5. **data-testid 立标杆**（T-104 断言锚，清单见文末——T-98 遗留 5 的回写素材）。

## 契约漂移（与文档/规范不一致处，供 conductor 逼回写）

1. **`/api/repositories` 全面 admin-only**（router.go 路由门 `routeAuth{admin:true}`，E-04~E-08 全族）vs console-ux §3.3「非 admin 已登录 → 仓库（仅列出有 read 权限的 repo）」。repo.Service.ListReposFiltered 本身只要求 authenticated（可按 read 过滤），是 HTTP 路由门收的紧。前端按 403 无权限卡收敛（列表+详情），不伪造。需 architect/PM 裁决：放宽路由门（service 层已支持）或修 ux §3.3。**影响 T-100 树页同款判断**（树走 /api/storage children，那族是 authenticated+ACL，不受影响）。
2. **列表项无 node 计数与更新时间**（repoListItem 无字段）→ ux §4.3 线框「制品/缓存」「更新时间」两列未呈现（已用列以 usage 端点的字节数替代 local node 数）。需列表端点扩字段或接受降级。
3. **remote 更新无「保持凭据」形态**：UpdateRepo 全量替换，body 不带 password 即清除已存凭据（service.go 注释明示 "a body without a password clears it"）。表单以字段提示明示「留空保存=清除」；无 UI 侧解法（需后端 PATCH 或占位语义）。E2E 已覆盖「回显面无密码」。
4. **local config 全量替换 × transport 字段子集**：httpapi configJSON 的 local 臂只转发 {priorityResolution, handleReleases, handleSnapshots, snapshotVersionBehavior, checksumPolicyType, includesPattern, excludesPattern, quotaBytes}；经 curl 手工写入的其它本地字段（repoLayoutRef/blackedOut/maxUniqueSnapshots/archiveBrowsingEnabled）会在 FE 驱动的保存中丢弃。表单已保全 transport 全集；根治需 transport 扩字段或 config 原文回传。
5. docs/user/integrations/generic.md 未写篇（README 导航有目无文）→ generic 接入命令块取 M1 FR-4 契约形态（curl -T/-O + X-Checksum-Sha256），建议 tech-writer 补篇后 UI 同步对齐。
