### H24 OIDC 登录流 — PASS
```
GET /binflow/api/v1/oidc/login → 302
  → http://localhost:8181/realms/binflow/protocol/openid-connect/auth
    ?client_id=binflow-console&code_challenge=bbx4DSQ…&code_challenge_method=S256
    &redirect_uri=http%3A%2F%2Flocalhost%3A8180%2Fbinflow%2Fapi%2Fv1%2Foidc%2Fcallback
    &response_type=code&scope=openid+profile+email&state=beea5ccb…（64 hex=256bit）
  + Set-Cookie binflow_oidc_tx=<state>.<verifier>（HttpOnly, Path=/binflow/api/v1/oidc）
Keycloak 表单 POST（ssouser/ssopass-42）→ 302 callback?code=…&state=…
GET callback → 302 /binflow/ui/ + Set-Cookie binflow_session=…
GET /binflow/api/v1/session → {"username":"ssouser","admin":false,"source":"oidc"}
GET /binflow/ui/ → 200
```

### H28 groups_claim 同步 — FAIL（D4）
前置：建仓 oidc-sync-repo + 上传 + **本地建组 developers**（`POST /api/v1/permissions` 对不存在的组直接 400 "Unable to find group by name"——IdP 组不会物化）+ 组读权限。
```
ssouser session GET /binflow/oidc-sync-repo/h28/test.txt → 403   # ❌ session 臂丢组
  （id_token 实测 groups:["developers"]，Keycloak 侧确在组内）
Authorization: Bearer <id_token> 同路径 GET → 200                 # 仅 Bearer 臂带 claims
Keycloak 移出组 → 新 id_token groups 无 developers → Bearer GET → 403   # Bearer 臂随新 token 失效 ✅
```

代码定位：`authenticateOIDC` 把 claims.Groups 放进 Principal，但 session 臂（`authenticateSession`）从 DB 用户行重建 Principal，`fillGroups` 只并 DB `user_groups`——无任何代码把 claims 组写入库；且既有用户登录不刷新 `is_admin`（DB 权威、首登定死）。

### H35 TLS — 部分（D5/D6）
```
ldaps:// + 不信自签证书（host 实例）→ 401（证书拒绝 ✅）
ldaps:// + 系统 CA（alpine 容器内 linux 版 binflow, ldaps://host.docker.internal:6362）
  → 200 {"username":"jdoe","source":"ldap"}                     # ldaps 正腿 ✅
ldap:// + start_tls: true（无 CA）→ 200 登录成功                 # ❌ 假阳性：StartTLS 根本没做
```
代码定位：`auth.LDAPConfig.StartTLS` 声明后**全库无消费点**（`grep -rn "\.StartTLS(" internal/` 仅接口/包装定义，pool/Bind 均不调用）——连接保持明文，凭据裸奔。`skip_tls_verify` 键在 config 严格解码器下不存在（T-179 遗留自报），评估场景腿不可测。
排障记录（环境，非缺陷）：osixia 默认 `olcTLSVerifyClient: demand` 使 Go TLS 客户端一律 EOF（openssl/openldap-client 正常），改 `never` 后 ldaps 全通——组内如复验 ldaps 需先改此项。
