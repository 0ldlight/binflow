## 二、本次发现并修复的问题

1. **TestClientAbsURL 假断言（AC 关键缺口）**
   - 症状：表格里 `default base URL` / `custom base URL` / `trailing slash` 三个用例的入参与期望值均未参与断言，任何 BaseURL 都能通过。
   - 修复：重写为端到端真断言——表字段 `suffix`（`""` / `"/"` / `"//"`）拼到 `srv.URL` 后设为 BaseURL，mock server 捕获实际收到的绝对 URL（`http://` + r.Host + r.URL），与期望 `srv.URL + /binflow/api/repositories` 精确比对。
   - 补充：外部包测不到的纯拼接用例（零值默认 BaseURL、非路由自定义域名 `https://binflow.example.com`）新增内部测试文件 `client_internal_test.go`（`package client`）的 `TestAbsURLJoining` 覆盖。

2. **`RetryMax = 0` 语义坑 → 套件 101.9s**
   - `retryMax()` 把 0 解释为默认值 5，而测试 helper 与多处用例写 `RetryMax = 0` 意图是"不重试"，导致 5xx 错误用例每个烧满 5 次退避（1+2+4+8+16=31s），三个用例约 93s——这就是 conductor 实测 101.9s 的来源。
   - 修复：所有"无重试"意图处改为 `RetryMax = -1`（负值禁用重试的既有语义）；`client.go` 字段 godoc 改为无歧义表述（"A zero value selects DefaultRetryMax; a negative value disables retries"）；新增 `TestRetryMaxSemantics` 钉死三条语义（0→默认、负→0、正→透传）。
   - 效果：套件 101.900s → **8.894s**。

3. **golangci-lint 14 条告警清零**（项目门禁零告警，前 agent 未跑过 lint）
   - errcheck ×5：`resp.Body.Close` / `rc.Close` 按仓库惯例（`internal/replication/engine.go` 同款）改显式 `_ =`；两处裸 `json.NewDecoder(...).Decode` 改为检查错误并回 400。
   - errorlint ×1：`err == context.Canceled` 改 `errors.Is`（原写法对 `*url.Error` 包装恒为 false，属真实缺陷——幸而字符串兜底路径行为一致）。
   - revive ×7：`client.go` 局部变量 `max` 遮蔽内建函数改名 `retries`；6 个未使用 `r` 参数的 handler 改 `_`。
   - staticcheck ×1：`artifact.go` S1017 `HasSuffix` 包裹的 `TrimSuffix` 改无条件 `TrimSuffix`。

4. **一致性**：`TestRetryEventualSuccess` 的 `goodResponse` 裸 bool 改 `atomic.Bool`（同文件 `attempts` 已用原子，统一风格；原写法靠 net/http 内部同步链侥幸无竞争）。

5. **gofmt**：全包 7 文件缺末尾换行 + `repo.go` 结构体字段对齐不合规，`gofmt -w` 统一修复。
