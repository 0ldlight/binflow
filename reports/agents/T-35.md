### ② Service 扩 docker 用例（Service 接口新增 8 方法）

`Service` 接口新增（全部走 DockerStore，adapter 不摸 metadata——架构 §5.1 红线的落点）：

| 方法 | 行为 |
|---|---|
| `PutManifest` | 校验链（image/tag/digest/mediaType/size/refs）→ 权限对（write 门槛 + 覆盖异 digest node 需 delete）→ node 落在 `<image>/manifests/<hex>` 布局路径（mime=manifest mediaType）→ manifests 行 → tag 行（重指=upsert）→ refs 整体替换。同 digest 重推=幂等重发布（跳过 write 门槛、保留 provenance），返回 `PutManifestResult{Manifest, Node, TagRepointed}`（TagRepointed=tag 原 digest） |
| `ResolveManifest` / `ResolveTag` | 按 digest/tag 解析；读权限=r 于 image 文件夹路径 |
| `ListTags` | 字典序 + `n`/`last` 官方分页切片（last exclusive、n<=0 全量）；**未知 image 与「有 manifest 无 tag」区分**：前者 `ErrImageNotFound`（NAME_UNKNOWN），后者也按 ErrImageNotFound（对齐 PRD 定案 + 规格建议栏，渲染层归 T-40） |
| `ListImages` | `<repoKey>/<image>` 形态、字典序、keyset 游标（游标键=完整形态名）；跨 repo 游标拒绝 |
| `DeleteManifest` | 权限（d）→ 先 resolve（not-found 先行）→ **直接调 `DockerStore.DeleteManifest`**（级联 tags/refs 同一事务在存储层完成，T-34 遗留要求）→ node 删除 + prune 空父目录。含**残留 node 自愈**：级联已提交但 node 删除未跑（进程死亡窗口）时，重试的 404 分支会清掉 sha 匹配的残留 node |
| `DeleteRepoDocker` | 三表拆库（`DeleteImage` 逐 image + `DeleteRepoRefs`）；由 DeleteRepo 驱动，同时导出供 T-38+ 测试引用 |

新增哨兵：`ErrManifestNotFound`/`ErrTagNotFound`/`ErrInvalidDigest`/`ErrInvalidTag`/`ErrInvalidImage`/`ErrImageNotFound`；`ErrRepoTypeNotSupported` 措辞从 "not supported in M1" 改为 "not supported"（docker 已开，M1 字样失真；错误信息正文仍带 "supported from M3"）。digest 一律裸 hex（64 位小写十六进制，adapter 剥 `sha256:` 前缀——架构 §5.3 裁定 2）。

### ③ 删仓级联

`DeleteRepo`：docker repo 的 manifest 索引计入「非空」判定（nodes 已清而 manifests 仍在的仓不再被无 flag 删除放行）→ `DeleteRepoDocker`（manifests/tags 随 DeleteImage 三表同事务、refs 显式清——§11.12 无 FK 契约）→ repositories 行删除。docker 拆库对 generic repo 无行为影响（catalog 探测按 PackageType 短路）。

## 规格依据与口径说明

- digest 裸 hex + node 布局 `<image>/manifests/<hex>`：architecture §6 002_docker 注释块。
- 删 manifest 级联同事务：§11.12 一致性契约（存储层 DeleteManifest 内单事务，Service 编排 node/权限，不重复实现级联——T-34 遗留 #2）。
- 拆库必须清 docker_refs：§11.12（无 FK），DeleteRepo 内先拆后删仓行。
- 分页 `n`/`last`（exclusive 游标、字典序）：docker-registry.md §6（高置信度行：TreeSet 字典序 + last 排他 + n 上限）。
- ListTags 未知 image → NAME_UNKNOWN：§6「name 不存在 404」；「有 manifest 无 tag」的空 tags 形态（null vs []）渲染归 T-40，Service 层两者统一 ErrImageNotFound——与 PRD R4 定案一致，T-40 按需把「已存在但无 tag」改走空列表分支时只动 ListTags 一处（已留区分所需的 manifests 探测）。
- digest 64 位小写 hex 校验：架构 §5.3 裁定 2 的防御面（M2 仅 sha256）。
- tag 字符集 `[a-zA-Z0-9_][a-zA-Z0-9._-]{0,127}`：§6 DDL 注释（无 DB 级约束，服务层是唯一落点）。
- **【暂行口径，非规格硬约束】权限路径 = `<image>/`（尾斜杠文件夹形态）**：ADR-0010 第 5 条 scope subject `<repoKey>/<image>` 的镜像推导，与 M1 路径前缀授权模型对齐；未见明文规格，已用测试固化（授权 app/ 不授权 other/ 的作用域用例），review 若有异议改动面为 `dockerPermPath` 单点。
- **【低置信度标注】DeleteManifest 的残留 node 自愈**：级联提交后、node 删除前进程死亡的恢复路径为工程推断（规格未覆盖崩溃窗口行为）；实现保守——仅当 node 的 sha256 == digest 且 manifest 行已不存在时才清，其余一律不动，并有 foreign-node 不受影响的负向用例。
- DeleteRepo 对 docker 索引行的「非空」判定扩展：FR-7-AC5 的服务层推论（nodes 空 + manifests 在 = 仍有内容），规格无直接行，行为已固化在 `docker-rows-only repo no-flag delete` 用例。

## Review 修复（REQUEST_CHANGES → 已修复，2026-08-18）

Review 报告：reports/agents/T-35-review.md（3 blocker 全部按建议修法落地 + 3 顺手项）。

### B1（必修）：DeleteRepo 拆库顺序 docker_refs 泄漏窗口

- **修法**（review 建议案 1 的精确化）：refs 清扫移到 `Repos().Delete` **成功之后**。新顺序：`DeleteRepoDocker`（前半，逐 image `DeleteImage`——manifests/tags + 该 image 的 refs 同事务）→ `Repos().Delete` → `DeleteRepoRefs`（后半，收尾清扫：清掉「前半之后、仓行删除之前」窗口内并发 PutRefs 落下的无 FK 行）。
- `DeleteRepoDocker` 语义相应收窄为「前半」（manifests/tags 逐 image；返回移除的 manifest 行数），`DeleteRepoRefs` 不再在其中调用——两个函数的 godoc、api.go 接口文档同步改写，明说前后半的分工与 B1 理由。
- 失败一致性：`Repos().Delete` 失败时 refs 与仓行同存（可重试），不再是「失败即已掏空 refs」的半删除态。
- **测试**：
  - `TestDockerDeleteRepoCascades/delete failure leaves the repo row behind`（断言方向反转）：注错失败后仓行存活、失败后向存活仓 publish 仍可见（refs 没被从仓底下扫走）、重试补完（refs 随仓行之后清）。
  - `TestDockerDeleteRepoCascades/refs of a racing publish do not outlive the repo (B1)`（新增，review 探针的确定性复刻）：前半 → 手动 PutRefs（straggler）→ DeleteRepo → 断言 straggler 被收走（`RefsByBlob=false`）。

### B2（必修）：同 digest 幂等重推改写 manifest 行 + TagRepointed 三方矛盾

- **幂等零变更**：幂等分支（node sha == digest）跳过 `dk.PutManifest` 行写——manifest 不可变（同 digest=同 body），行写只会让零授权调用漂移 `created_by/media_type/size`。tag/refs 两个 upsert 照旧（重指合法、指针刷新合法）。结果报告**存储行**（`dk.GetManifest` 读回），不是调用方的再声明——/v2 面的服务真相不被未授权重推污染。
- **TagRepointed 定约**（按 coordinator 指令）：返回值=本次重指前的旧 digest，**仅当 tag 实际移动**（`prev.Digest != digest`）；新 tag 或同 digest 未动均返回空串。api.go 文档 / service 实现 / 测试断言三处对齐。
- **测试**：
  - `TestDockerPutManifest/same-digest repush is an idempotent republish`（重写）：零授权 alice 以 OCI mediaType/size=999 重推 → manifest 行 `created_by=admin、mediaType=schema2、size=100` 原样、node provenance 原样、结果报告存储行、`TagRepointed==""`、tag 行 updated_by=alice（刷新指针合法）。
  - `TestDockerPutManifest/tag overwrite repoints (FR-9-AC2 / Q4)`（既有，断言补强方向确认）：d1→d2 移动时 `TagRepointed==d1`（非空）。

### B3（必修）：哨兵错位（空 mediaType/负 size 与跨仓游标复用 ErrInvalidImage）

- 新增 `ErrInvalidManifest`（manifest 描述符参数非法：空 mediaType、负 size、nil ref → adapter 译 MANIFEST_INVALID 400）与 `ErrInvalidCursor`（分页游标非法：tags/list 坏 tag 形态游标、catalog 跨仓游标 → 400 分页族）。`ErrInvalidImage` 回归纯「镜像相对名非法」语义。
- ListTags 的 last 校验：`validateTag` 仍做字符集检查，但错误包装换 `ErrInvalidCursor`（信息里带 cursor 字样）；ListImages 跨仓游标同理。
- **测试**：`TestDockerPutManifest/validation matrix` 尾部两断言（空 mediaType/负 size → `ErrInvalidManifest`）、`TestDockerListTags/read gate` 坏游标断言、`TestDockerListImages/a cursor from another repo is refused`（→ `ErrInvalidCursor`）。
