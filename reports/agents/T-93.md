## 做了什么

### AC ① GE-01（W22/W22b）查询面

- **`internal/audit/api.go`**：
  - `Filter` 扩全参数：`Repo/Actor/Action/Since/Until/Limit/Cursor`（Since 闭、Until 开——透传 metadata 语义）；
  - 新增 `Page{Events, NextCursor}`（Events 恒非 nil 空切片起步；NextCursor 空串 = 末页）与 `Event.ID`（HTTP 面渲染 id 的载体）；
  - 新增 `NormalizeTimestamp`：RFC3339 解析 → **统一 UTC + 秒精度重排**（T-90 review 提示落点）——offset 归一（+02:00→Z）、亚秒 floor（审计行本身是 metadata.Now 的秒粒度，整秒域内文本序==时间序；floor 保证 `until` 不会因 '.5'<'Z' 的字典序陷阱漏行）。
- **`internal/audit/audit.go`**：
  - 消费侧 `store` 接口从 `Append+List` 收敛为 `Append+Query`（List 不再被本包消费，metadata 侧保留——T-90 遗留 3 的前半句兑现）；
  - `Logger.Query` 重写为分页形：**limit+1 探测行**判定 has-more（满页与末页可区分）、裁剪后以末行构造 nextCursor；`auditCursorSeparator("|")+cursorOf` 在消费侧拼 metadata 文档化的 `<time>|<id>` 契约，**格式漂移由 TestQueryCursorFollowPages 真库往返兜底**（漂移即分页断走查红）。
- **`internal/httpapi/audit.go`**（新文件）+ `router.go` 单 case + `server.go` `auditLog` 字段：
  - `GET /binflow/api/v1/audit?repo=&actor=&action=&since=&until=&limit=&cursor=` → 200 `{"events":[{id,time,actor,action,repo,path,detail}],"nextCursor"}`；
  - **detail 为对象**：存储的 detail 字符串经 `auditDetailObject` 以 `json.RawMessage` 原样嵌入（非对象/畸形/空 → `{}`）——Redact 在 append 时已做，这里只整形；
  - limit 缺省 100 / 上限 1000（超限、非数字、<1 → 400 E-01 信封）；since/until 非法 → 400（NormalizeTimestamp 文案直出）；**cursor 非法 → 400，errors.Is 精确锚定 `metadata.ErrInvalidCursor`**（T-90 review 提示：与 docker 分页的 `repo.ErrInvalidCursor` 同名不同面，勿混用）；
  - admin only：路由门 `routeAuth{required,admin}`（非 admin 403 / 匿名 401 + Basic challenge）；`s.auditLog == nil`（无 metadata 的单测栈）→ 503 兜底。
