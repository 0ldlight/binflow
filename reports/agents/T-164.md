# T-164 — 本地 DiskEngine → S3 S3Engine 在线迁移

## 交付内容

### 1. MigrationEngine（internal/storage/migration.go，新增）

包裹 disk + S3 双引擎、实现 `Engine` 接口的三模式状态机：

- **bypass**（未启用）：全部委托 disk。
- **dual-write**（`Enabled && !Completed`）：
  - `BeginSession` 同时在 disk 与 S3 建会话，返回 `migrationSession` 包装。
  - `migrationSession.Append` 用 `io.TeeReader + io.Pipe` 单次读取流式双写，
    校验两侧字节数一致；任一侧失败则双方中止（S3 multipart abort / disk 会话 abort）。
  - `Commit` 先 disk（得到权威 sha256）后 S3（同 ref）；S3 失败时回滚
    `disk.Delete` 该 blob —— **不允许出现"只有一侧可见"的半个结果**。
- **completed**（`Completed=true`）：全部委托 S3，disk 退役。
- 读路径：dual-write 下 S3 优先、`ErrBlobNotFound` 时回退 disk（迁移窗口内
  老 blob 仍可读）；删除双发；GC 双发。

### 2. 后台迁移拷贝（runMigration）

- `StartMigration` 幂等（已运行返回状态不报错）；列表 disk 全量 blob、
  差集计算 missing，bounded-concurrency worker 经 `copyBlob` 拷贝
  （S3 已存在则跳过，幂等可重启）。
- **本 session 关键修复**：`runMigration` 终态此前经局部 `status` 变量 +
  `storeSnapshot` 落盘，defer 路径会用陈旧副本覆盖 `statusGuard` 里的
  worker 进度（Migrated/Failed 归零）。重构为统一 `finish(err)` 闭包 +
  `updateSnapshotAtomically`，全函数不再触碰局部 status。
- 状态并发安全：`statusGuard`（mutex + 读/写均拷贝快照），修复了两处
  `-race` 数据竞争（直接写 struct 字段、`atomic.AddInt64` 与 copy-store 竞争）。

### 3. S3Engine（internal/storage/s3.go，新增）

- minio-go/v7，multipart upload 映射会话；对象键 `blobs/<xx>/<sha256>`，
  与 disk 布局一致（ADR-0019 / docs/reverse/storage-layout.md）。
- `Stat` 流式复校验（内容必须哈希回自身路径）；`Open` 404 包装
  `ErrBlobNotFound`；GC 用 ListObjectsV2 + grace。
- lint 修复伴随重构：新增 `api()` 辅助取高层 client —— `minio.Core` 用同名
  低层签名遮蔽了 GetObject/PutObject/CopyObject/ListObjects，显式选
  `core.Client` 是语义必需，集中到一个带注释的方法后 staticcheck QF1008 清零。

### 4. HTTP 面（internal/httpapi/migration.go 新增 + server.go/router.go 接线）

- `GET  /binflow/api/v1/storage/migration` → 状态 JSON（`StatusView`）。
- `POST /binflow/api/v1/storage/migration/start` → 幂等启动，202 + 当前状态。
- `MigrationStarter` 接口缝（httpapi 不 import storage）；未配置时 501。

### 5. 测试（migration_test.go / s3_test.go 新增）

14 个 migration 测试 + 18 个 S3 引擎测试；mockS3Server 为进程内 S3
（GET/HEAD/PUT/DELETE/Copy/Multipart/ListV2）。本 session：
- 修复 `runMigration` defer 覆盖 bug 后全部转绿；
- 高并发参数（4000+ worker 打 mock HTTP）造成 backlog 超时，回归为
  5–50 的真实并发值；927-blob 批量迁移保留作规模验证；
- 新增 `s3ObjectCount`（直读 mock 状态计数）替换两个从未被调用的
  GC-hack 辅助，在 TestMigrationManyBlobs / TestMigrationStartAndComplete
  里对 S3 端终态做硬断言（不只信 status 计数器）。

## 可靠性场景覆盖

- **并发写同 blob**：TestMigrationConcurrentWrites / TestMigrationConcurrentDualWriteWithBackground / TestS3ConcurrentSameBlobConverges（收敛到单一 blob）。
- **流式双写一致性**：TestMigrationDualWriteConsistency（多尺寸含 1MiB）、TestMigrationNewBlobsDuringMigration（迁移进行中经 dual-write 产生的新 blob 双侧可见）。
- **checksum 不匹配拒绝**：TestCommitChecksumMismatchRejected / TestS3CommitChecksumMismatchRejected（sha256/sha1/md5 矩阵）；S3 Stat 内容-哈希自校验。
- **中断/半写不可见**：disk 侧 temp+fsync+rename 三步曲（TestCrashWindowsSimulated 既有）；S3 侧 Abort 零残留（TestS3AbortZeroResidue）；dual-write Commit 的 S3 失败→disk 回滚。
- **GC 不回收在途引用**：TestGCGraceProtectsConcurrentUploads / TestGCDoesNotCollectInFlightReference（既有）+ TestMigrationGCBothStores（双引擎 GC 语义）。
- **迁移状态一致性**：statusGuard 快照拷贝语义 + runMigration finish 闭包（panic 路径亦不丢计数）。
