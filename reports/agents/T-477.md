# T-477 — X-Explode-Archive 链 spool 迁移共享 staging（T-474/T-476 家族终章）

状态：done（等收编；零 git 操作）
area：`internal/repo`（+ `cmd/binflow-server/main.go` 一行接线，+ `internal/migrate/artifacts.go` 裁定注释）

## 1. 依赖方向裁定（先查依赖图，任务的先决问题）

实查：`grep -rn 'binflow/internal/adapter' internal/repo/` → **零命中**；反向
`internal/adapter/{pypi,docker,…}` 大量 import `internal/repo`。**依赖是单向的：
adapter → repo**（架构 5.4，adapter 消费 repo.Service）。因此 `internal/repo`
**不能** import `internal/adapter`（成环）——T-474/476 的共享原语
`adapter.StagingDir/StageFile/ErrStagingUnavailable` 对 archive.go 不可达。

两条出路的取舍：

- **原语提为共同底包**（如 internal/staging，两边 import）：需重写
  `internal/adapter/spool.go` 及其五包调用面——**全部在本票 area 之外**（并行
  agent 的 adapter 面），且 T-476 刚封板；不做。
- **采用：repo 侧轻实现同语义孪生**（`internal/repo/staging.go`）：
  `stagingRoot`/`stagingLabel`/`service.stageUpload`，逐语义对齐 adapter 原语
  （按需建根 0o700、拒绝面点名尝试根的有界披露、wrapped cause 命名 resolved
  root）。差异一处（有意）：repo 的错误惯用法是 face-ready 的 `*StatusError`，
  不另设导出哨兵——httpapi `writeArchiveError` 对 StatusError 逐字渲染，507
  直接可映射；adapter 侧哨兵存在的理由（各 face 自行映射风格）在 repo 不成立。

归一为单一底包登记遗留（§6），需 conductor 开票给 adapter owner。

## 5. 面语义说明（reviewer 需知晓）

- 507 拒绝面是 **BinFlow 增补**（T-474 家族映射，spec 无此案：Artifactory 的
  temp dir 是它自己的配置面）；经 `writeArchiveError` 的 StatusError 逐字臂
  渲染，无 httpapi 改动。
- 有界披露（T-476 终裁同款）：客户端只拿尝试根（运维自己的配置值，唯一可行动
  事实）；os 错误细节与临时文件名进 slog（`repo: upload staging unavailable`）
  与 wrapped cause。
- `ConfigureStaging` 装配期单写、请求期只读（AttachReplicator 同款无锁契约，
  注释钉死「首请求前」）。
