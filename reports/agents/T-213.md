## 契约依据

- `docs/design/architecture.md` §3.1 [M7]：`Session.Offset() int64`——disk 后端 =
  `uploads/<id>/data` 文件长度；重哈希恢复（ResumeSession）后即重算后的文件长度，
  取代 adapter 侧内存镜像作为 416/Range 响应基准；实现必须并发安全（与
  Append/Commit 互斥读）。
- §3.1 ResumeSession 契约：「行缺失/已过期未清扫 → ErrSessionNotFound（fail-closed，
  行的唯一正确回收路径是 sweep）」。
- §5.3.1 契约 1（offset 权威性转移：事实源 = `Session.Offset()`）、契约 3（过期 =
  未知；「若实现复核发现引擎未查过期，属实现票必改项」——本票即修此缺口）、
  契约 5（S3 恒 hard 404，`TestS3ResumeSessionNotSupported` 钉死）。

## 变更清单（全部在 internal/storage）

### AC1 — `Session.Offset() int64`（实现 + godoc）

- `api.go`：`Session` 接口新增 `Offset() int64`，godoc 对齐 §3.1 [M7]/§5.3.1 契约 1
  （权威 offset 源、恢复后 = 重算文件长度、读与 Append/Commit 串行化）；接口级注释
  补「Offset 是唯一允许与 Append/Commit 并发调用的读方法」。
- `session.go`（disk `uploadSession`）：`Offset()` 持 `s.mu` 返回
  `state.Received`——活会话 = 已追加字节数（与文件长度相等，均在 s.mu 下更新）；
  恢复后 = ResumeSession 重算的文件长度。nil receiver 安全。
- `s3.go`（`s3Session`）：`Offset()` 持 `s.mu` 返回 `received`（已提交 parts +
  挂起 part buffer）。**仅为接口编译所需的最小新增，S3 引擎行为零改动**
  （ResumeSession 路径一行未动；见「遗留」说明）。
- `migration.go`（`migrationSession`）：`Offset()` 委托 disk 侧（disk 是 primary，
  Append 已强制两 backend 偏移一致）。

### AC2 — ResumeSession 过期 fail-closed

- `engine.go`：新增 `sessionRowExpired(row, now)`——边界与 sweep 的 `ListExpired`
  （`WHERE expires_at <= ?`）严格一致（`expires_at <= now` 即过期）；空/无法解析的
  `expires_at` 也判过期（expiry 是写路径不变量，BeginSession 恒写入；丢失效期的行
  不得永生）。
- `ResumeSession` 在 `Get` 成功后、**打开数据目录之前**检查过期：过期未清扫行 →
  wrap `ErrSessionNotFound`，且不 O_CREATE 任何文件（被拒绝的恢复不得在 sweep
  即将删除的目录下建文件）。
- 缺口根因（§5.3.1 契约 3 预判）：substore `Get` 不查 `expires_at`，恢复路径原先
  会复活 sweep 即将回收的行。修在 storage 层（解析 `row.ExpiresAt` 自查），未动
  `internal/metadata`（area 纪律；metadata 的 `Get` 语义「按 id 解析行」本身无错）。

### AC4 — godoc 契约措辞对齐 + N5 同族注释漂移清理

- `api.go` `ErrSessionNotFound` 哨兵 doc：补「已过期未清扫行」fail-closed 语义与
  「sweep 是行唯一合法回收路径」。
- `api.go` / `engine.go` 两处 `ResumeSession` godoc：补「Offset 返回重算文件长度」
  「过期=未知 fail-closed」「S3 恒 ErrSessionNotFound（§5.3.1 契约 5 hard-404）」。
- `s3.go` `ResumeSession` 注释：从一句「not resumable」扩写为引用 §5.3.1 契约 5 +
  `TestS3ResumeSessionNotSupported`（N5 同族：注释未跟上 M7 契约定稿）。
- **N5 同族漂移修复**：`engine.go` `Options.Sessions` 注释原称 nil 时「the startup
  sweep is a no-op」——与 `sweepSessions` 实际行为矛盾（nil store 时孤儿目录扫描
  仍运行，`sweepOrphanDirs(nil)`）。改为「skips its row pass (the orphan-dir scan
  still runs — crash residue stays reclaimable)」。

### 测试（新建 `resume_offset_test.go`）

- `TestSessionOffset` 三臂：
  1. 活会话 Offset == 追加字节数 == 磁盘 `uploads/<id>/data` 文件长度（逐段
     Stat 对照）；
  2. crash → 第二引擎 ResumeSession → Offset == 重算文件长度（非行内簿记、非 0），
     续 Append 增长、Commit 摘要正确；
  3. 并发臂（-race）：一 goroutine 连续 Append、另一 goroutine 轮询 Offset，断言
     单调不减且 ≤ 总量（与 Append/Commit 互斥读的并发安全契约）。
- `TestResumeSessionExpiredFailClosed` 表驱动（引擎时钟冻结，确定性边界）：
  - 未过期可恢复（Offset == 数据长度）；
  - 过期 fail-closed：严格过去 / **恰好 == now（`<=` 边界）** / 空 expires_at /
    无法解析 expires_at —— 四种均 `ErrSessionNotFound`，且断言**行未被删、数据
    文件字节原样**（fail-closed = 拒绝而非回收，回收只属于 sweep）；
  - 无行 → `ErrSessionNotFound`；
  - 有行无数据文件（目录在）→ 恢复成功、Offset==0（O_CREATE 归零语义维持），
    且再走 Append+Commit 全链路摘要正确。
- `TestS3SessionOffsetTracksAppends`：S3 腿 Offset 跟踪（新测试函数，未改既有
  S3 测试）。
- **红绿实证**：临时禁用过期检查（`if false && sessionRowExpired(...)`）→
  四个过期子例全部 FAIL（`ResumeSession err = <nil>, want ErrSessionNotFound`）；
  还原后全绿——测试确实钉死缺口，非恒真断言。

## 可靠性覆盖（本票故障场景）

- **并发**：Offset 与 Append 并发读写（-race 绿，s.mu 互斥）；全包 -race 绿。
- **过期/sweep 竞态**：ResumeSession 对已过期未清扫行 fail-closed，且拒绝路径
  不删行、不动数据文件（sweep 是唯一回收路径）；边界与 ListExpired `<=` 严格
  对齐，恢复与 sweep 对「哪些行可回收」永不分歧。
- **校验/恢复语义维持**：有行无数据文件 → O_CREATE 归零恢复 + 全链路 Append/
  Commit 摘要正确；重哈希恢复后 Offset = 重算文件长度（权威 offset 源）。
- **S3 契约**：ResumeSession 行为零改动，`TestS3ResumeSessionNotSupported` 绿。

## 遗留 / deviation（conductor 知悉）

1. **「S3 引擎零改动」的精确口径**：`s3.go` 有两处文本级改动——`s3Session.Offset()`
   （接口加方法的**编译必需**，无它全包不编译；行为零变化）与 `ResumeSession`
   注释扩写（AC4 godoc 对齐要求覆盖「ResumeSession godoc 与 §5.3.1 契约措辞一致」，
   契约 5 即 S3 腿）。S3 引擎的可执行行为（含 hard 404 路径）一行未动。
2. **空/畸形 expires_at 判过期**（fail-closed extra，超出票面四例的表行）：正常
   写路径恒写 RFC3339，此分支只对手工损坏行生效；判「过期」而非「忽略」是取
   fail-closed 姿态。若 conductor 认为应忽略，改动一行 + 两表行。
3. cmd/binflow-server / httpapi 消费方仅编译面受接口加方法影响（全仓 build+vet
   绿证明无破坏）；其行为回归归各自 area 与 T-216（adapter 接线票）。
