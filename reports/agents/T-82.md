## 一、做了什么

照 `internal/adapter/generic/handler.go`（T-66 留下的现成范式）给三个协议 adapter 补齐两条缝：

### 缝 1 — `*repo.StatusError` 直渲染分支（writeServiceError 顶部）

| adapter | 位置 | 修前行为 | 修后行为 |
|---|---|---|---|
| maven | handler.go `writeServiceError` | `ErrRepoTypeNotSupported` 臂对 method≠PUT/POST 回 **400**（virtual DELETE 实测 400，T-71 遗留①） | StatusError 先行：405 + Allow: GET + C5/not-propagated 文案逐字 |
| pypi | handler.go `writeServiceError` | 非 unfound 的 StatusError（SSRF 400 / hardFail 502 经 virtual 透传）落 default 臂 **500** | 引擎裁决逐字到 wire（400/502） |
| npm | errors.go `writeServiceError` | **完全缺失**（连 ErrRepoTypeNotSupported 臂都没有）→ virtual 写面/删面全部落 default **500** | 同上，405 + Allow: GET + C5 文案 |

三处均照 generic 的分支形态：`errors.As` → 展开 `se.Header`（Allow 等）→ `writeError(w, se.Code, se.Message)`。原有的 `ErrRepoTypeNotSupported` 臂（maven/pypi）保留为 non-StatusError 裸 wrap 的 fallback（remote 引擎未接线、List 拒绝等形态），注释已更新说明优先级。

**行为面变化说明**（审阅要点）：maven PUT-on-remote 的 body 文案从 adapter 自拟的 "Cannot deploy ... read-only pull-through caches." 换为 service 层 RE-05 的 "Remote repository '<key>' is a read-only proxy cache; ..."——405/Allow 不变，旧文案无任何测试断言（全仓 grep 证实）；与 generic 面行为对齐（generic 自 T-66 起就是 service 文案直渲染）。

### 缝 2 — `ExtraHeaders()` 结构化探测（GET 响应头组装处）

| adapter | 位置 | 备注 |
|---|---|---|
| maven | `serveFile`（artifact GET）+ `serveSidecar`（校验和 GET） | 新增 `applyReaderHints` helper（2 处共用）；sidecar 体虽为服务端计算，目标流的成员归属与 artifact GET 同问，RE-07 诊断头补齐 |
| npm | `servePackument` / `serveVersion` / `streamNode`（tarball） | `loadPackument` 签名增返 `http.Header`（读流时探针、关流前收集），12 个调用点机械更新（写面用 `_`）；`headers.go` 新增 `readerHints`/`applyHints` |
| pypi | `serveDownload`（packages/ 与裸内容路径） | 照 generic 内联 8 行（单点，不抽 helper） |

三处探针均为结构化 `interface{ ExtraHeaders() http.Header }` 断言（不 import remote/repo 引擎类型、不学习仓库 class，architecture 5.4），并在 conditional 304 / Range 206 之前写入——与 generic 一致，304 响应也带头。**修前：X-BinFlow-Resolved-From 与 X-BinFlow-Cache 在三协议路由上全部被丢弃（generic 面正常，T-71 遗留②）。**
