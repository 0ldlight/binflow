## 关键校准结论（供 conductor 回写 PRD §5.5 校准项 ⑤）

1. **E-17 响应字段需要修订**：真实创建响应 = `access_token / token_type("Bearer") / expires_in(永不过期时缺省) / scope / refresh_token(仅 refreshable)`，**不含 token_id**。建议 BinFlow 返回真实字段集 + `token_id` 作超集扩展；PRD C21a 的 JSON 请求体需兼容 form-urlencoded（真实端点只吃 form）。
2. **E-18 revoke**：form 参数 `token` XOR `token_id`（同传 400 / 都缺 400），`token_type_hint` 可选（`access_token|refresh_token`）；成功 200 纯文本 `Token revoked`；不存在/已吊销**仍 200** body `Token not found`（幂等）；吊销后 401。PRD 的 JSON 形态建议保留为兼容扩展。
3. **E-16 改密**：7.x 无 `PUT /api/security/password`；现行 `POST /api/security/users/authorization/changePassword`，**旧口令错误 400（非 401）**。建议 BinFlow 自有路径保留 + 补真实路径别名。
4. **E-19 建用户**：真实为 `PUT /api/security/users/{name}`（无集合级 POST），201 无 body；BinFlow 自有 `POST /api/security/users` 保留 + 补兼容路由。
5. 错误体三格式并存：制品 JSON errors / 用户管理纯文本 / token `{"error","error_description"}`。
