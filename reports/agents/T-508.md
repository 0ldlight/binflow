## 2. append 合并语义证明（合并键 = module id）

- **读-改-写全并发安全**：`mergeMu` 全局锁内 ListModules→merge→PutModules（陈旧基底的 last-writer-wins 会静默丢整段合并；CI 频度下全局锁零成本）。
- **合并律**（`mergeModules`）：incoming 模块 id 已存在 → artifacts/dependencies **追加**（seq 重排在既有尾部）；不存在 → 新模块落位。**零丢弃**。
- **测试证明链**：`TestAppendMergesByModuleIDWithoutOverwriting`（服务面：api 模块 1 artifact+1 dep → append 同 id 1+1 → 2/2，原行在前；sibling 模块原样；新 id 新模块）+ `TestBuildRESTAppendMergesByIDOnTheWire`（wire 面同断言）+ `TestCurlCompatBuildFamily/append_merges_by_module_id`（真实 curl）。
- **父 run 404 先判**（T-507 遗留 ③ 消化）：`Append` 在 body 解析**前** GetBuild；`metadata.ErrBuildNotFound` → httpapi 映射逐字 `Build-Info not found`——**不依赖翻译 PutModules 的泛化 FK 错误**（该遗留同步关闭）。
- started 省缺 = 定位最新 run 后并入**该 run**（`?started=` 经规范化后精确寻址）。

## 5. T-507 三遗留消化

1. **started 规范化（上传门）**：`build.NormalizeStarted`——接受 Java 正身形（`…SSS±HHMM`）/RFC3339（Z、带冒号 offset、任意小数位）/秒精度三族，统一渲染 **UTC `2006-01-02T15:04:05.000+0000`**（webhook §3.4 `build_started` 同形）。写面存规范形，读面 `?started=` 过同一门（异时区字面可寻址同一 run）→ 字典序=时间序，MAX(started) 保真（9 例 table-driven + wire 面 `%2B0800` 寻址臂）。payload 仍**逐字节**存原始文档（echo 的 started 以规范列值覆盖）。
2. **PutModules 孤儿段哨兵**：append 面 GetBuild 先判 404（§2）——不碰 FK 错误翻译。✅ 关闭。
3. **builds.put 指标**：§4 落地。✅ 关闭。

## 6. 关键裁定（BinFlow-native，留痕）

- **PUT 覆盖律**：header+modules+properties 整段替换（PUT=全量保存动词）；**promotion 历史不在替换内**（§2.4 append-only 不可变律高于参考的删-重建文件面行为）。
- **artifact 关联**：wire path 首段拆 (repoKey, path) → 活 nodes 行则建关联；节点缺/**sha256 与节点相左**（大小写不敏感比对）/path 无 repo 段/未接线 → record-only（行存、不冒领关联）——「假关联比无关联更糟」。
- **module properties / requestedBy**：payload-only（024 无 module_props 表——ADR-0045 决策 2 六表钉死）；append 腿无法承载（无 payload 落点）——**登记 M17 债**。
- **GET echo 合成**：payload 解析为底（未解释字段——buildAgent/vcs/issues/url——原样穿透）+ 规范真值覆盖（name/number/started/type/modules/properties/statuses[]）；append 后的合并立即可见。statuses[] 仅在存在时呈现（§9#7 中置信——不伪造空数组）。
- **列表族无分页参数**：官方 GET /build 与 /build/{name} 仅 projectKey/project（不承接）——规格面无分页可照，全量+可见集过滤即冻结面。
- body 上限 32MiB（防 DoS 地板；规格自带的 700MB manifest 上限是病态清单容忍度，不承接）。
