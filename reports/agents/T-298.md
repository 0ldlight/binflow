## 2. 选型论证（按票据要求记录）

1. **独立 binflow-deploy job（非 smoke 末尾 stage）**：
   - smoke 职责 = 快反馈（21s 热）；deploy 职责 = 变更环境，失败语义、超时、轮转策略都不同，混在一个 job 里红一票分不清是"代码坏"还是"部署坏"。
   - 门控用 Jenkins `upstream(threshold=SUCCESS)`：红/黄 smoke 不部署（本次 main 红期间实测拦截 3 次 smoke、1 次 deploy）。
   - 形态可分：默认 CI 形态（main HEAD，版本 `v1.0.0-ci.<sha>`）；release 形态走参数（从 docker-local 的 per-arch 镜像抽 goreleaser 已盖戳二进制，dogfood：发布产物由 BinFlow 自己托管分发）。
2. **docs 站 = 二进制嵌入（非 VM nginx 静态托管）**：
   - CD 模型下每次变更本来就重建二进制 + systemd 重启，"docs 更新不重启"的 nginx 收益在此模型下为零；嵌入则 code+console+docs **单产物原子部署、原子回滚**（回滚 #5 连 docs 一起回）。
   - 零新增 VM 组件（VM 无 nginx，装了就是第 4 个 systemd 单元 + 端口 + 健康检查 + 版本对账面）；版本戳一致（docs 与二进制同 revision，无漂移）。
   - 成本可控：docs 站 3.3MB（预算 15MB），+console 672K，最终二进制 19.96MB（旧 t247 单体 26.5MB，反而更小——`-s -w` 剥离）。
3. **宿主侧引擎 = nsenter helper 容器**：Jenkins agent 容器需控制宿主 systemd。chroot 方案连不上宿主 systemd bus（`Failed to connect to bus`）；`--privileged --pid=host --network host` + util-linux nsenter 进 PID1 命名空间后 systemctl/curl 全部命中宿主。信任边界：agent 本就挂着宿主 docker socket（等价宿主 root），helper 无新增权限，只是把既有能力用在明处。

## 8. 踩坑（后续复用）

1. **sandbox 拒绝 `hudson.model.Result$.SUCCESS`**（MissingPropertyException: hudson，import 行也拒）：declarative `upstream` 的 threshold 直接省略——ReverseBuildTrigger 默认即 SUCCESS。
2. **chroot 连不上宿主 systemd bus**：`--privileged -v /:/host chroot` 的 systemctl 报 `Failed to connect to bus: No data available`；`--pid=host` + `nsenter -t 1 -m -u -i -n` 才是正解。
3. **config.xml 更新后参数被清**（T-270 pitfall 7 三现）：push-jobs.sh 后 `buildWithParameters` 400；先跑一次 plain build 物化（红 main 上会失败但参数照样物化）。
4. **JVM 里读宿主文件路径不存在**（T-270 pitfall 8 复现）：script console 的 groovy 跑在容器内，看不到宿主 /srv 根——口令直接进 POST body（loopback）。
5. **goreleaser 时代 release 镜像不含真实 docs 站**：docs 断言必须 FORM 感知，否则 release 形态永远红（见遗留 L2）。
6. Jenkins REST POST 全程需 crumb+cookie；`-w '%{http_code}'` 判 201/400。
