## 做了什么

补齐 docker /v2 面对 `*repo.StatusError` 的 verbatim 渲染臂——T-95 遗留①定位的两处：

1. **`writeManifestPutError`**（manifest.go）：manifest PUT 的两步落仓（step-1 `svc.Put`、step-2 `svc.PutManifest`）返回 StatusError 时按**原状态码 + 原文案**渲染（此前落 default 臂 500 UNKNOWN）。臂放在 switch 最前，与四 adapter「verbatim first」先例一致；鉴权类拒绝从不以 StatusError 形态到达此面（plain sentinel，走既有 challenge 臂），前置安全。
2. **blob 注册失败支路**（uploads.go `writeBlobCreated`）：Commit 成功后 `PutLandedBlob` 注册被治理拒绝（quota 413 / pattern 409）时 verbatim 渲染（此前 500 UNKNOWN）。blob 物理已落盘、node 未写——verbatim 的 413/409 即「push 未落成」的诚实信号（W26c 契约）；解除拒绝后重推安全（Commit 去重 + 幂等重传豁免补齐行）。日志 WARN（policy 拒绝非故障，T-41 卫生），原 busy→denied→500 顺序保持，StatusError 臂插在 busy 之后（busy 不可能是 StatusError）。

### 信封 code 决策（注明裁决）

`writeVerbatimStatusError`（errors.go 新增）+ `specCodeOfVerbatim` 状态→code 映射：

- **413（quota）/409（pattern）→ `DENIED`**——官方码表中语义最贴（"the access controller denied access for the operation on a resource"＝策略拒绝）；adapter 内一致性：DENIED 本就是本 adapter 全部拒绝类的信封码。
- **TOOMANYREQUESTS 弃用**：规范把它绑 429 限流，配 413 是 status/code 错配。
- **不造自定义码**：无客户端消费 QUOTA_EXCEEDED 之类的自造码；逆向规格 §1 行 3 已示注册实现自由发散（Artifactory 的 SIZE_INVALID/NO_TAGS_FOUND），有官方码可用时不扩面。
- 其余状态沿用既有信封码：405→UNSUPPORTED（并携带 StatusError 自带 Allow 头）、401→UNAUTHORIZED、403→DENIED、未映射→UNKNOWN。
- verbatim 契约本身（status+message）不受映射影响：413 按原状态码出、message 逐字。

### 顺带（area 内，注释级）

- `tryMount` 的 PutFromBlob 失败注释补明：治理拒绝（413/409）**保持降级 202**（mount 是优化，spec 降级即正确路径），回退上传自身在 finalize 处出诚实 verbatim 拒绝——行为零改动，只把决策写明。
- **未动读面**（`writeBlobReadError`/`writeManifestReadError`）：quota 只在写面；pattern 的下载臂在 repo 层返回与 miss 逐字相同的 ErrNodeNotFound（service.go:263），docker 面既有 404 BLOB_UNKNOWN/MANIFEST_UNKNOWN 臂天然正确（新增测试 TestGovernanceRefusedReadsServe404 钉死）。remote docker 仓 FetchError 型 StatusError 的读面渲染是另一类缺口，登记遗留。
