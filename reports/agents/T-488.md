## 2. 与 T-489（ADR-0045/0046）对齐点清单——软缝十+八项逐答对拍

两 ADR 的软缝清单已在两规格 §0 逐项作答；**勘误回填项（ADR 骨架与官方字面不符，机制轴零翻动）**汇总：

| # | ADR | 骨架字面 | 规格 定案（官方双源） |
|---|---|---|---|
| E1 | 0045 软缝③ | 上传 `PUT /api/build/{name}/{number}` | **`PUT /api/build`**（name/number 在 body）；append = **POST**（非 PUT）`/api/build/append/{name}/{number}` |
| E2 | 0045 软缝⑨ | `DELETE /api/build/{name}?builds=&dateRange=&artifacts=` | 实际参数 = `?buildNumbers=<csv>&artifacts=0|1&deleteAll=0|1`（无 dateRange）+ POST `/build/delete` body 形态 |
| E3 | 0045 软缝⑥ | retention「days」 | 实为 **`minimumBuildDate`**（ISO8601 时间戳非天数）；async 缺省 true |
| E4 | 0045 点 11 | 「OSS 发行集合含 build CRUD 全族」 | 修正为「openapi.yaml 随 OSS 代码库发行 ≠ OSS 档可用」——官方描述三处 JCR/Pro + t226 旧活体 build 搜索族 400 Pro 门；**community 地板决策本身不翻案**（BinFlow 无许可门超集实现先例） |
| E5 | 0046 软缝② | 骨架示意 `PUT/GET /api/release_bundle/{name}/{version}` | 与两侧官方字面均不符——Artifactory 源侧 = `/api/release/*` 族；Distribution 侧 = `/api/v1/distribution/*`（T-513 按 release-bundle.md §1 对位） |
| E6 | 0046 软缝③ | 「409 vs 400」 | 定案 = **三态 202/200/409**（新/同签名续传/冲突）；409 体 = 通用 ErrorResponse `{"status":409,"message":"Bundle already exists"}` |
| E7 | 0046 点 4 | MinTier=pro 暂行 | 真身 = **Enterprise+**（官方明文）——不翻案、登记注记；Q2 出口②启用则升 enterprise（既定路径） |

**证实项**（ADR 暂行值获双源证实）：0045 软缝② build_repo 缺省 `artifactory-build-info`（DDL DEFAULT + webhook 示例 + 回落逻辑三证）；软缝④ append 合并键 = module id；软缝⑦ 最新 = 排序取首（无专用端点）；软缝⑤ promotion status = 自由字符串无闭集、现势 = 最新时间戳条目。0046 软缝⑤ created 单型 wired 倾向证实、软缝⑥ 显式清单倾向证实（官方三源并存，显式清单为合法子集）。

**软缝⑦补强**：查询/归档 body 的 `buildNumber` 支持 `LATEST` 哨兵值（官方 archive 端点 schema）——「最新」语义在 body 级有哨兵形态；GET 族仍无专用端点（排序取首结论维持）。
