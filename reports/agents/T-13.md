### AC2 校验头语义（§5.5 定案）

- `X-Checksum-Sha256/Sha1/Md5` 逐算法独立校验：`upload checksum mismatch 409` / `sha1 mismatch 409` / `md5 mismatch 409`；409 message 含 **received/actual** 双值（`Checksum error for '<repo>/<path>': received '<x>' but actual is '<y>'`，从 storage.Commit 的错误链解析重组）；curl C14 断言 body 同时含 received/actual 且拒绝后 GET 404（无残留 node）。
- **格式非法（宽度/非 hex）与不匹配分级**：非法 → 400（`upload malformed checksum 400`）；这是与 409 的有意区分——拼不出合法摘要的客户端根本没走到比对。
- `X-Checksum-Deploy: true`：缺专用头 → 400（逐字用规格文案 `Checksum deploy failed. no checksum header ...`）；格式非法或 blob 未命中 → **404**；命中 → **201 零传输**（curl C15a/C15b；`TestChecksumDeployZeroTransfer` 验证新路径可 200 下载且内容一致）。实现为 opener 打开既有 blob 重流入 Service.Put（权限/幂等重传/审计/事务边界全部复用，磁盘零拷贝、网络零 body）。
- `X-Explode-Archive` → 400（E-25）。
- 路径 `:properties`/`:statistics` 后缀 → **409** `Old metadata notation is not supported anymore`（PUT 与 DELETE 双侧）；普通文件名含冒号（`we:ird.bin`）不受误伤（专门用例）。

## 三、实现要点与取舍（review 关注项）

1. **decode 责任在本层入口**（T-12 review 移交）：`Layout` 从 `r.URL.EscapedPath()` 起步自行 `PathUnescape`，不依赖上游传的是 Path 还是 RawPath；解码失败（如 `%zz`）保持原文按字面处理（与 net/http 对非法转义的宽松行为一致），dot-segment 判定始终在解码后的形态上进行。
2. **不做 path.Clean 静默归一**：`a/./b`、`a/../b` 一律 400 而非重写成 `a/b`——重写会让客户端对与其请求 URL 不同的路径落 checksum，语义上不可接受；规格（repo-semantics §1）只见 `.` 处理，BinFlow 采取更严的拒绝姿态并在 layout.go 注释记录。
3. **sha1/md5 事实源**：storage.Open 只保证 Sha256+Size（T-9 回写项 D），三摘要全量事实在 metadata blobs 台账 → Handler 注入只读 `BlobLedger`（`metadata.Store.Blobs()` 结构化满足），GET/HEAD/FileInfo 的 sha1/md5 从台账取；台账缺行时优雅降级为 sha256-only（继续服务，一致性工具兜底），不 5xx。
4. **checksum-deploy 的实现路径**：Service.Put 的接口吃 io.Reader，空 body 提交的摘要只能是空串摘要——直接传 expect 无法落链。故注入 `BlobOpener`（= storage.Engine.Open 的函数类型）打开既有 blob 重流入 Put：零网络传输、零磁盘拷贝，权限检查/幂等重传/覆盖判定/审计/blob-first 事务边界全部复用 Service 既有机制。依赖 storage 只读侧（repo.Service 自身也依赖 storage 接口，同层 internal 包，不违反 §5.1「adapter 不摸 storage/metadata 内部」的精神——两者都只经接口）。**若 architect 认为 BlobOpener 应上收到 repo.Service（如 `PutFromBlob` 方法），属接口变更，走 architect 裁决。**
5. **sha1-only checksum-deploy**：BinFlow blob 以 sha256 寻址、台账 sha256 键，无 sha1 反查索引 → M1 返回 404（message 明示需 X-Checksum-Sha256）。规格（rest-api §1.3）只要求「两专用头都缺 400、格式非法或未命中 404」，sha1-only 属 BinFlow 自有语义限制，已在 handler 注释与本日志记录（主流客户端路径 X-Checksum-Sha256 完整可用）。
6. **folder GET on 内容路径**：目录 node 在内容路径上 404（`Failed to find the requested resource ...`）——目录浏览归 `/api/storage`（T-15），内容路径只服务文件；ErrIsFolder 信号在 handler 显式分支。
7. **错误信封**：本层自带 `writeError`（errors[] JSON），裸挂载也不漏 HTML；T-14 的中间件链与统一信封接入后双保险。`WWW-Authenticate: Basic realm="BinFlow Realm"` 在匿名写被拒时由本层补（T-14 的 authenticator 也会给，重复设置无害）。
8. **612 校验顺序**：`X-Explode-Archive` 与 `:properties/:statistics` 检查先于 checksum 头解析与 body 消费——拒绝请求不看 body（与 repo 层「先判权再耗 body」的修复同理）。

4. Range/条件请求（FR-4-AC14/AC15）归 T-20；本票已按规格发 `ETag`/`Last-Modified`/`Accept-Ranges: bytes` 头，T-20 只需加 206/304/416 分支。
5. `:properties`/`:statistics` 的 DELETE 旧写法同样 409（与 PUT 对称）；规格 §1.1 该行为标中置信度，按最保守的拒绝处理。
