## 一、裁决结论

**A 路径（开放）：`POST /api/security/token` 权限模型对齐 Artifactory——admin 全量；非 admin 已认证用户（本地/OIDC/LDAP 三臂同权）可为本人发 Token。FR-54-AC3 维持原文，不做勘误。**

四条护栏（防凭据扩散面失控）：

1. 非 admin 主体仅限本人：缺省 `username` = 调用者；指定他人 → 403 OAuth 形（沿用 `administrator privileges required` 文案）。
2. 非 admin 强制有限 TTL：`expires_in` > 0 且 ≤ 上限（默认 365d，K9 暂定 `auth.token_nonadmin_max_ttl`）；0/负值/超限 → 401 `invalid_request`（文案对齐 Artifactory）。
3. 验证期护栏：Token 验证须校验主体用户行存在且未禁用，否则 401（对冲「IdP 侧停用后 Token 存活至过期」）。
4. 审计：非 admin 铸 Token 记 `token.issue`（M5 G31a 既有 actor/fingerprint/TTL 面，internal/audit/api.go:89）。

不变的现状面：匿名拒绝；`GET /api/security/token`（列表）与 `revoke` 维持 admin-only（auth-model.md §3.3/§3.4）；admin 全量（可代任何主体、可永不过期）。

T-174 结论定格：**H26 维持「部分过」**——admin_group 腿 ✅ 不动；普通 OIDC 用户腿从「规格冲突悬置」转「实现票待修 FAIL 项」；D3 分级 P0(规格冲突) → P1(实现差距)。

## 二、依据链（四条，按决定性排序）

1. **Artifactory 对标（决定性）**：docs/reverse/auth-model.md §3.1（高置信度，反编译 + 官方文档双证）——真实权限模型 = 「admin 全量；**非 admin 已认证用户可为自己发 token**；匿名拒绝」，另有「非 admin 只能填自己 username」与 TTL 上限 `access.token.non.admin.max.expires.in` = 365d 双约束（含超限错误文案）。**B 路径的前提「Artifactory 同样限制（SSO 用户走短期 session）」与我方逆向规格事实相反**。走 B 须把 M1 E-17 该端点从「兼容（子集）」改标「有意不兼容」，直接违背 PRODUCT.md 架构对齐原则（迁移团队 CI 脚本平移断裂）。
2. **威胁模型（凭据扩散面）**：开放不构成提权——非 admin Token 主体 = 本人、权限 = 本人动态权限（identity token 语义，与 ADR-0010 第 4/5 条 docker token 同构）；能过 session 做的事才能过 Token 做，新增的只是「既有能力的持久化」。真实风险两处：① 持久化绕过 IdP 会话治理（IdP 停用后 Token 有效至过期）→ 护栏 3 + 护栏 2 对冲；② session 被盗 → 铸长期 Token 持久化立足点 → 审计（护栏 4）+ admin 可调低上限 + admin 可吊销。M7+ 可选加固（SSO session 铸 Token 需二次认证/double authentication）不入 M6。
3. **M1/M2 既有决策**：admin-only 并非 M1 安全红线，而是「`username` 参数未实现」的子集简化——M1 E-17 明文「M1 子集：username/expires_in/refreshable 参数可不实现（admin 无参创建即可）」：无 username 参数即无法区分「为自己/为他人」，admin-only 是当时唯一安全落点（T-174 所引「M1 D3 决策」的实质）。且 M2 起 `/v2/token` 已允许任意有效用户铸有限 TTL Token（FR-11 v1.1 双入口设计，T-43 QA 2.12 PASS：ci-bot 走 /v2/token 200）——「SSO 用户不应持有 Token」在本产品从来不是不变量；管理面维持 admin-only 不实质缩小凭据面，只砍掉自助服务与统一审计入口。ADR-0009（匿名读默认开 + 管理面恒认证）只约束「匿名 vs 认证」，不约束「非 admin vs admin」，与 A 路径无冲突。
4. **产品场景**：PRD §3 场景 B 明文「CI 用 LDAP 服务账号绑 Token」——服务账号通常非 admin；B 路径下每个 CI Token 都要 admin 代铸，违背 M6「企业就绪/SSO 免维护」目标（ROADMAP M6 定位）。

权限边界说明：FR-54-AC3 是已定 PRD 基线（P0 AC，随 PRD v1.0 入库）；A = 维持基线原文、纠正实现偏差，属 PM 规格裁决权限内；B = 修订已定 P0 AC，须用户明示。Q11 已留推翻出口。
