## 二、AC 逐条证据

### AC ① Engine/Session + 布局 + 落盘顺序 + singleflight + sentinel

磁盘布局实测（`TestPutLayoutAndDigests`）：`<data>/blobs/<sha256[0:2]>/<sha256>`、`sessions/<uuid>/{data,state.json}`，Commit 后会话目录归零。

落盘顺序（`session.go Commit`，ADR-0006 不可换序）：
```
校验期望摘要 → fsync(data) → singleflight(sha256){
    目标已存在 → 丢弃会话数据，返回既有引用（幂等去重）
    否则 rename(data → blobs/xx/<sha256>) → fsync(分片目录)
}
```
元数据事务不在本票范围（「blob 就位」即返回，T-12/T-10 负责）。

sentinel：`ErrBlobNotFound` / `ErrSessionNotFound` / `ErrChecksumMismatch`（另补 `ErrBlobCorrupt`、`ErrEngineClosed`），全部 wrap 后 `errors.Is` 可判（`TestCommitChecksumMismatchRejected`、`TestOpenReadSeekCloserAndMissing`）。

- `Open(path)` 返回 `io.ReadSeekCloser`：`TestOpenReadSeekCloserAndMissing` 断言 Seek(4)+Read 为 "4567"（T-20 Range 依赖）。
- 期望摘要大小写不敏感（`TestCommitAcceptsUppercaseExpectation`），非法长度/非 hex 同样按 `ErrChecksumMismatch` 拒绝。

### AC ② 启动清扫 + GC

清扫（`TestStartupSweepSessions` 表驱动）：TTL 1h 时 2h/25h 残渣删、10m 保留；默认 TTL=24h 时 23h 保留、25h 删。state.json 缺失/损坏走目录 mtime 回退（`TestSweepFallsBackToMtime`）。本进程活会话永不清扫（`TestSweepKeepsLiveSessions`）。

GC（`TestGCDryRunAndApply`）：mark=引用集合回调，sweep=未引用且 age>grace。dry-run 只出清单不删；apply 精确删除过期孤儿，引用中/宽限期内孤儿存活。`TestGCDoesNotCollectInFlightReference` 复现「blob 已落盘、元数据未写」竞态：宽限期内不被回收，超龄且持续无引用才回收。GC 忽略异构残渣（错分片目录/非摘要文件名，`TestGCIgnoresForeignEntries`）。

### AC ③ 流式约束 + 三摘要独立一致 + ReadSeekCloser

## 七、二轮修复记录（正确性 reviewer 深探转交，2026-08-17）

> 背景：正确性 reviewer 探针实证后 context 耗尽，结论由 conductor 转达。四项中 1 项必须修（singleflight panic 死锁）、2 项固化/注记、1 项记录为已知边界。

### 1（必须修）singleflight panic 死锁 — 已修

**缺陷**：`do()` 中 leader fn panic 时 `wg.Done()` 与 `delete(m, key)` 永不执行 → 等待者永久阻塞 + map key 泄漏，该 checksum 的后续所有上传死锁（reviewer 3 秒超时探针实证）。

**修法**（`singleflight.go`）：teardown 移入 `defer`（`defer func(){ mu.Lock; delete; mu.Unlock; wg.Done() }()`），顺序保证 map 条目先于 waiter 唤醒移除——否则 follow-up 可能加入垂死 call。panic 照常向上传播，但状态干净：等待者被释放（观察到零值 err，引擎侧语义=「重查 blob 路径」，与已完成航次同样安全）；godoc 已写明该契约。

**测试**（`round2_fixes_test.go`）：
- **`TestSingleflightPanicDoesNotWedgeFollowups`**：leader panic 传播出 `do()` → follow-up 调用 3s 内返回（不挂死）→ map 无 key 泄漏（后续调用执行自己的 fn）。
- **`TestSingleflightWaiterSurvivesLeaderPanic`**：已阻塞的 waiter 在 leader panic 后被释放。

### 2（固化）rename 失败路径 — 已固化为正式测试

reviewer 探针已证行为正确，本轮照其手法固化为 **`TestCommitRenameFailureIsClean`**：0500 只读 shard 目录注入 EACCES（root 环境自动 skip——root 不受 0500 约束）。断言五点：错误传播且含 rename/permission 语义；会话 finalized（再 Append 报 already finalized）；session 目录已清；blob 计数 0（无污染）；障碍移除后重试收敛为一个干净 blob 且 Stat 通过。

### 3（注记）GC 零宽限竞态 — godoc 已补设计注记

`gc.go` GC godoc 补：「mtime 年龄检查正是在途上传的保护层——blob 刚落盘即年轻，即便其元数据行未写（blob-first 顺序，架构 §3.3）；grace=0 仍只回收 mtime 已过（默认）宽限窗的 blob，不是『立即回收一切未引用』开关」。
- **`TestGCGraceProtectsConcurrentUploads`**：8 并发上传 vs hammering GC（grace=2s 覆盖上传突发）→ 8/8 blob 存活（与 reviewer 探针结论一致）。
- 补 **`TestGCAgedOrphanCollectedWithTinyGrace`** 钉另一半语义：显式过期（backdate 1min）的孤儿在 grace=1ns 下确实被回收——小 grace 不被静默升级为 24h。
- 注：reviewer 原探针用 grace=1ns + 年轻 blob 得「全部存活」，依赖的是 1ns 窗口内 mtime 不会落后于 now-grace 的时钟精度；固化为常驻测试时改用「覆盖突发的真实 grace」表达同一不变式（上传中的 blob 不丢），另加显式过期 case 表达 grace 语义，避免测试依赖时钟精度抖动。

### 4（已知边界）跨引擎清扫 — doc.go 已加使用约束

`doc.go` 补：「一个 data dir 同时只允许一个 Engine 实例」——启动清扫假设 sessions/ 属本进程，第二个 Engine 会把第一个的活会话当残渣（进程间活度不可见）删掉。M1 单进程部署（一个 binary 一个 data dir，ADR-0004）构造性满足；跨进程强制需 lockfile，M1 有意不做。reviewer 探针证实的行为与此记录一致。
