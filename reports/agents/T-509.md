## 3. docker promote 真实腿（本机 Docker Desktop，净窗）

**环境**：临时 binflow-server（127.0.0.1:18099，sqlite 临时目录 /tmp/t509-e2e/data，零复用用户实例）；docker 引擎障碍与解法——macOS Docker Desktop 的 dockerd 在 VM 内，`127.0.0.1:18099` 拒连（VM loopback ≠ host loopback）、`host.docker.internal` 通但 HTTPS-only。**解法**：一次性 `docker:27-dind` 内层 daemon（`--insecure-registry host.docker.internal:18099`，port 2376，用毕即删）——**零改用户 Docker Desktop 配置**（用户四个在跑容器 postgres/artifactory/bf-ga-control-plane/buildkit 全程未动，收尾复核原样）。真客户端链全程真 docker CLI（inner daemon 27.5.1）。

**流程**：`docker build`（FROM scratch + hello.txt）→ `docker push host.docker.internal:18099/dev-docker/myapp:1` → PUT /api/build（modules 两 artifact：docker manifest + generic bin，关联均解析）→ promote#1 `sourceRepo=dev-docker,targetRepo=rel-docker`（200，消息 `1 manifest(s), 2 blob(s), 1 tag(s)`）→ promote#2 `sourceRepo=dev-libs,targetRepo=rel-libs`（200）→ `docker pull rel-docker/myapp:1` 成功 → `docker rmi`（删本地缓存）→ **复拉成功**，RepoDigest 与源推送一致。

## 4. retention 形态（AC3）

- **窗口语义**：`ListBuildNumbers`（started 倒序）逐 run 判——豁免号优先；`minimumBuildDate`（ISO 时间戳，Errata ①「非天数」——经 NormalizeStarted 规范形后**字典序=时间序**比较）之前可删；`count>0` 时序位 ≥count 可删（count≤0=无 count 窗，Artifactory count=0 未配置惯例）。
- **设定≠同步删除的读法（留痕）**：官方「设定保留不立即删」+ async 缺省 true = 执行移出请求路径而非不执行。BinFlow M17 无后台 retention worker——端点=「验证（403/404/400 全同步）+ 执行（async 决定内联/脱线程）」。**名称级保留策略不持久化**（024 六表无 retention 表、payload 不可变——若翻案走 ADR-0045 勘误 + 新表）。
- **真实例证据**：3 run（8-01/9-01/9-05）+ floor 2026-09-01 → run#1 删、#2#3 留；再 seed 8-20 → async 缺省臂 → 复查 #4 已删。`deleteBuildArtifacts=true` 经载体 Delete 逐关联节点删（service 测试断言豁免 run 节点不受扰）。
- **audit（PRD「删除 audit」）**：每被删 run 一行 `build.delete`（detail: number/started/artifacts）+ 窗口一行 `build.retention`（detail: count/minimumBuildDate/deleted/kept）——真实例 `/api/v1/audit?action=build.retention|build.delete` 双双在案。

## 6. 关键裁定（BinFlow-native，留痕）

1. **audit +5 词落位（T-508 遗留归本票裁）**：落在 `internal/audit/api.go`（词表之家——`audit.Actions()` 闭集 + 5 常量；internal/build 经 audit facet 引用，import 方向合法）。**越界说明**：internal/audit 非本票 area，但 ADR-0045 决策 10 明文 mandate、纯增量（5 const + 5 行 picker）、且不落则本票写出的行不可被查询面过滤——裁为落位并在此留痕。emit 同址：Upload→build.upload、Append→build.append（upload.go 两处成功路径）、Promote→build.promote、retention→build.retention+逐 run build.delete。`Actions()` 无长度断言（预检），audit 包测试全绿。
2. **docker manifest 节点不经载体复制**（wire 测试抓到的真缺陷）：CopyOrMove 先落目标节点会使 PutManifest 走幂等重发臂（同 digest 已存在）而**跳过 index 行**——tag 指向无 manifest 行 = 404 pull。定案：manifest 节点+index+tag+refs 全由 PutManifest 承载（其双步契约本就如此）；**登记 divergence**：manifest 节点的源属性不随迁（body properties 臂仍落目标 manifest 节点；blob 属性照常随载体）。
3. **docker move 的源清理**：载体 OpMove 只搬节点行，docker index（manifests/tags/refs）需 `DeleteManifest` 的同事务级联——否则源留 ghost tag（测试断言源 tag 404）。
4. **dependencies=true**：受理 + warning「无可迁移」（inv-4 D1：依赖不解析节点）——登记 M17 divergence。
5. **target 不存在/非 local → 400**（ErrInvalidBuildInfo 家族）；对**无该仓授权**的调用者，w 门先答 403（no-oracle 正确姿——测试钉死：admin 过门后见 400，无位者恒 403）。
6. **failFast 悬空律**（决策 5 C 层）：record-only/节点已失 → failFast=true（缺省）4xx 拒（400/404 按成因）、false 跳过+warning。§3 多腿事实即其体现。
7. **retention 执行窗读法 + 策略不持久化**（§4）。
8. **promotion 历史 timestamp 定序**：promoted_at 秒精度 + 随机 id —— 同秒两行顺序不定；测试/调用方用 body `timestamp`（毫秒规范形）定序（§2.4 本就是官方定序机制）。
