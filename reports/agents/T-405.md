## 1. 路径契约（钉死，供 T-404 FE 对接）

```
PUT /binflow/api/v1/replications/{id}
```

| 项 | 定案 |
|---|---|
| `{id}` | **数值 row id**（GET 列表/创建响应投影的首字段 `id`）。不是 name——同族 DELETE 按 `{name}` 寻址，两种寻址并存的理由：name 经 store 的 UpdateContract 可改名（rename 是既有面），id 不可变；FE 手里的行两列都有，id 是安全键 |
| body | `{"enabled": true|false}`，**enabled 必填**（缺失/null → 400）。decode 复用 create 全形（`replicationConfigBody` 内嵌）：**其余字段解析但忽略**——FE 把整行 round-trip 回来不被拒（这是防 T-404 联调断裂的显式决策） |
| 成功 | `200` + **GET 投影原形**（`replicationConfigResponse` 11 字段：id/name/source_repo/target_url/target_repo/target_username/max_bandwidth_bytes_per_sec/max_items_per_push/enabled/created_at/updated_at；凭据字段永不回显）。写入后回读再投影（照 create 的 echo 姿态） |
| 权限门 | 路由 `routeAuth{required:true, manage:CapSystemWrite}` + handler 内 `p.Admin` 复检——与 POST/DELETE **同门同文**（403 文案逐字同） |
| 错误形态 | 照族惯例 errors[] envelope：匿名 401 / 非 admin 403（"requires an administrator account"）/ 未知 id 404（"replication config not found: \<id\>"，照 DELETE 措辞）/ 非数字或 <1 的 id 400（"id must be a positive integer"，照 uploads partNumber 惯例）/ 缺 enabled、坏 JSON 400 / store busy 503 / 未装配 Replication 501（"replication is not configured"，T-159 ruling 6）|
| 审计 | `replication.config.update`，actor=操作者，repo=source_repo，detail=`{"enabled":"…","name":"…"}`（字面量，沿 T-180 的 M6 词表注记——尚未入 internal/audit） |
| 副作用 | 翻转 bump `updated_at`（`metadata.Now()`）；**sealed 凭据与节流 cap 逐字节原样穿越**（read-modify-write 全行写回，测试断言 enc:v1 串不变且解密还原） |

## 2. PUT 覆盖面定案（AC2 留痕）

**仅 enabled，最小面。** 依据：

- T-402a 锚定（§3 差距表）：Artifactory 宽字段族（cronExp / pathPrefix×2 / syncDeletes / syncProperties / syncStatistics / enableEventReplication）为**中置信**（表单面板形态在 OSS 门后不可达，双源降级锚定）；BinFlow 模型一个都不载。全字段编辑 = R3 字段族 + R4 cron 语义决策，归 conductor 已规划的后续票（包 B）。
- 编号勘误：票面写「R6 字段族」，锚定表 R6 = Test 连通性、**R3 = 字段族**——按语义取 R3（两者同处「中置信 bundle 锚定」档，不影响定案方向）。
- 落法：decode 容忍全形但只应用 enabled（§1），使后续全字段票只需扩 handler 应用面，不破坏既有调用方。

## 3. 引擎语义对齐（AC1，勘误后口径：事件驱动 + 1min sweep）

**引擎零改动即满足口径**——enabled 本就是订阅行状态位，引擎两处现读：

| 腿 | 机制 | 生效时延 |
|---|---|---|
| 停·不入队 | `Enqueue` 每事件 `ListConfigs` 读位（engine.go 既有 `!c.Enabled → skip`） | 下一事件起即时 |
| 停·不执行 | `drain` 每趟（wake / 1min sweep）读位跳过 disabled 配置 | 下一趟起（≤1 sweep） |
| 在途 | `processTask` 的当前 attempt 不因翻位中断，跑完自身结论 | — |
| 恢复 | 新事件即时入队；**同一 backlog 由下一趟 sweep 排空**（无需 trigger） | ≤1 sweep |

观察行为注记（诚实留痕）：一个**失败中的**在途行会在本趟内烧完剩余退避重试（≤6 attempts）才停——勘误口径「读位决定入队/执行」按趟读取的自然结果；不在本票裁剪（裁剪=引擎改造，违背回归零变化）。测试固化的三腿见 §5。
