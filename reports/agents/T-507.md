## 1. 做了什么

ADR-0045（决策 2 + Errata ①②④㋓）+ build-info.md §3.2 的表族与 ACL 判定面全量落地：

### 1.1 表族 DDL（migration 024，双方言）

六表：`builds` / `build_modules` / `build_artifacts` / `build_dependencies` / `build_promotions` / `build_properties`。

- **唯一性四元**：`PRIMARY KEY (build_name, build_number, started, build_repo)` —— Errata ④㋓ 的「PK 扩含 started」定形，同名同号不同 started = 不同 run，`?started=` 消歧。
- **build_repo 缺省** `DEFAULT 'artifactory-build-info'`（Errata ② 三证）；逻辑键不要求 repositories 行、不自动建仓；Go 侧 `metadata.DefaultBuildRepo` 常量 + store 写/读空值归一化。
- **promotion status 无闭集**：自由字符串、无 CHECK（Errata ②）；表 append-only（store 无 update/delete 面）；六元组齐（含 comment）；现势 = `ORDER BY promoted_at DESC` 首行。
- **nodes 关联（真引用）**：`build_artifacts(repo_key, path) FOREIGN KEY nodes(repo_key, path) ON DELETE SET NULL` —— NULL = record-only（无 checksum 不建关联，§2.2）；节点删除后历史行保留、关联清空（append-only 历史不被节点删除摧毁）；module 段挂 nodes 路径即此列对。
- **payload 归档**：`builds.payload` 列（轴 2-A：build JSON 是 KB 级记录，不进 storage/nodes；备份随 metadata.db）。
- **Module ID 数据面**：`build_modules.module_id`（T-512 消费；append 合并键 + `<子build名>/<子build号>` 引用形态）。
- 索引：`builds(build_name)`、`builds(build_repo, build_name)`（ACL 可见集走查）、`build_artifacts(repo_key,path)`（制品反查）、artifacts/dependencies 的 sha1+sha256（checksum 关联与 dependency 搜索面——对位官方 artifacts sha1/md5 索引，BinFlow 校验和优先文化以 sha256 替 md5 索引，md5 存而不索引，已在 SQL 头注记）。
- **幂等**：`CREATE TABLE IF NOT EXISTS` + `CREATE INDEX IF NOT EXISTS`（post-011 惯例，t212 rewind 重放姿态）；语句双方言公共子集，postgres 侧逐字镜像 + README 版本史补 024 行。

### 1.2 metadata 缝（substores_builds.go + api.go + store.go）

- `metadata.BuildStore` 接口（dumb ledger，ScheduleStore 先例）：PutBuild（upsert 保 created）/ GetBuild（started='' → 最新 run）/ DeleteBuild（级联全段）/ ListBuildNames（按 (name,repo) 分组 + MAX(started)）/ ListBuildNumbers（started DESC，number DESC 决定性 tiebreak，TEXT 序）/ PutModules（事务性整段替换；父 run 缺失 FK 拒绝——append 404 语义的机制本体）/ ListModules（module_id 序 + seq 序嵌套）/ PutProperties（set 语义）/ ListProperties / AppendPromotion / ListPromotions。
- `ErrBuildNotFound` 哨兵；`Store.Builds()` 接口方法 + `sqliteStore.Builds()` 装配。

### 1.3 internal/build 新包（ACL 判定面）

- `service.go`：`Service` + `New(store, az)`；**allow 镜像与 repo/service.go:218 逐字同构**（p.Admin 短路 → nil az fail-closed → az.Can 委托）——同装配注入同一 `auth.Service` 实例（同源由构造保证）；`CanRead` 公开只读投影；读面 `GetBuild` / `ListBuildNames` / `ListBuildNumbers` 全部走 **r(buildRepo, buildName) 门 + path 位传 build_name**（target includes/excludes 按名模式生效）；列表 = **服务端可见集过滤**（逐 (buildRepo, buildName) 求值，非客户端过滤）。

## 5. 遗留 / 需上游确认

1. **started 排序保真**：混时区 started 字面量的字典序 ≠ 时间序；建议 T-508 上传编排规范化/校验 started 格式（或本票已留 started 为 wire 原文的取舍需在 T-508 复核）。
2. **同 key 真仓的通配桶边界**：若实例真建了 key = `artifactory-build-info` 的 local 仓，`bucketFor` 会解析出 class → ANY LOCAL 将覆盖该键（Artifactory 侧 buildinfo 仓是**短路拒绝**出 ANY 链）。ADR-0045 说「同 key 真仓存在亦无干扰」——数据面确实无干扰，但 ACL 面的 ANY 覆盖会出现。建议 ADR-0045 勘误或 T-491 侧在 repoClassAdapter 排除 buildinfo 键（本票不越界改 auth）。
3. `PutModules` 父 run 缺失时的 FK 错误为泛化约束错误（无专属哨兵）；T-508 append 面应先 GetBuild 判 404（`Build-Info not found` 逐字文案），不依赖翻译该错误。
4. DeleteBuild 要求精确 started（无 latest 解析）——T-509 批删/retention 先解析 run 坐标再删，store 面无隐式删除。
5. 全仓 `make lint` 的 4 处告警在并行会话的 httpapi/console 文件（server.go gofmt、system_logs.go G705、logtail_test.go ×3 staticcheck）——非本票，收编时请彼票自理。同因，末轮全量 make test 的 httpapi 20m timeout 属彼会话在途 WIP + 争用，本票零 httpapi 改动。
6. 全量 race 套件在本机与并行 sprint 会话互斥（两度 20m timeout 均为双套件并发所致）；若收编哨兵再遇 repo/httpapi 计时失败，建议独占窗口复跑（本票 solo 证据见 §3 表）。
