## 1. 做了什么

### 1.1 Dispatcher（internal/webhook/dispatcher.go，新）

复刻 replication Engine 的队列模式（ADR-0041 轴 3-A「复刻不共用」）：DB 行即队列、wake 信号 + poll 兜底、启动 sweep、ctx 取消即优雅排空。**wire 参数全部照 T-358 锚点翻转**（ADR「锚点回填位」条款：机制条款不翻，wire 参数翻）：

| 参数 | ADR 暂行 | 本票落地（锚点值） | 依据 |
|---|---|---|---|
| 尝试上限 | 10 | **5（首试计入）** | webhook.md 5.2 retryCount「The first try count as one」 |
| 重试间隔 | 2s×2 退避 cap 10min | **固定 10s，无退避曲线** | webhook.md 5.2 retryWaitMillis（官方无 backoff） |
| 重试条件 | — | **仅发送失败或 ≥500**；4xx 一步终态；3xx（不跟随=未送达形态）同判终态 | webhook.md 5.2 原文重试条件 |
| 单次 attempt 超时 | 10s | **30s（含建连/交换/读体）** | webhook.md 5.2 timeoutMillis |
| worker 并发 | 4 | 4（引擎内部常数，非官方 wire 参数，不翻） | ADR 决策 4 |
| 限流 | 无 | **token bucket：1000/s 均值 + 10000 突发**（pace attempt 起点，「到阈值后按 frequency 匀速」） | webhook.md 5.1 |
| 并发上限 | 无 | **maxConcurrentHandlers 50000：超限新事件在 Emit 缝拒绝**（计数+WARN，可见损失面） | webhook.md 5.1「超限的新事件被拒绝」 |
| 死信 | 持久死信面 | **无独立持久死信**：outbox 行 status=dead 可查可重放（ADR 机制条款保留）；排障环为可观察出口 | webhook.md 5.3 |

机制细节：
- **claim = 双谓词 CAS**：`UPDATE ... SET status='delivering', attempts=attempts+1 WHERE id=? AND status='pending' AND next_attempt_at<=now`。status 谓词防多 worker 共享行；**due 谓词防「重试间隔被压扁」**（§3 的 TOCTOU 修复，重点）。
- **attempt 计数在 claim 内原子递增**：kill -9 中断的 attempt 保持已计（重启 sweep 后最多多花一次尝试，at-least-once 语义内的诚实代价）。
- **启动 sweep**：delivering→pending（attempts 保留）+ 一行 INFO 水位（pending 数/sweep 数/参数）。
- **优雅停机**：in-flight attempt 在 ctx 边界中止，结局写走 detached ctx（writeTask 姿态），停机后零 delivering 行。
- **secret 投递时现读**（轮换即时作用于在途行，ADR 决策 3）；payload 用存储快照字节（HMAC 对存储字节）。
- **audit**：`webhook.dead_letter` 一词（actor/订阅/事件型/URL 脱敏，best-effort AuditSink 注入，replication 同构）。
- **Replay**：`Dispatcher.Replay(id)` dead→pending、attempts 清零、立即唤醒（ADR 决策 4 重放机制面；REST/控制台面归 conductor，见 §5-3）。

**修复的并发 bug（负载注入发现）**：初版 claim 的 CAS 只复核 `status='pending'`。窗口：worker B 扫描见行 due → worker A 认领并完成一次失败尝试、以 `next=now+10s` 写回 pending → B 的 CAS 只看 status 仍 pending 即认领——**重试间隔被压扁到扫描-CAS 间隙（实测 3.2~3.8ms）**。单机低负载下 24 次执行零失败、4 路负载+并行编译下 ~50% 复现；以 DIAG 日志（claim 的 now vs 行 next_due）钉死证据链。修复：CAS 增补 `AND next_attempt_at<=now`（双谓词原子）。修复后同负载 3×count=8 + 3×count=2 全绿。

### 6.4 startWebhookDelivery（startReplication 之后，同构）

```go
// startWebhookDelivery launches the delivery dispatcher's Run loop on a
// context derived from ctx and returns the drain function the shutdown
// path MUST call before closing the webhook database: it cancels the loop
// (in-flight attempts abort at their next context boundary and land their
// outcome rows on a detached context), then waits for every worker to
// park. Idempotent and safe on early serve failures.
func (s *stack) startWebhookDelivery(ctx context.Context, logger *slog.Logger) (drain func()) {
	if s.webhookDisp == nil {
		return func() {}
	}
	engCtx, cancel := context.WithCancel(ctx)
	done := make(chan struct{})
	go func() {
		defer close(done)
		if err := s.webhookDisp.Run(engCtx); err != nil {
			logger.Warn("webhook dispatcher stopped", "error", err.Error())
		}
	}()
	var once sync.Once
	return func() {
		once.Do(func() {
			cancel()
			<-done
			logger.Info("webhook dispatcher drained")
		})
	}
}
```
