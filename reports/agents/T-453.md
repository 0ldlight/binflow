## 2. AC2 — 能力位三旗 + 双布尔候裁臂

- **BE 承接核查（票内实证）**：`internal/httpapi/security.go` 的
  `userCreateBody`（PUT，L632-640）与 `userUpdateBody`（POST，L933-941）
  均无 profileUpdatable/disableUIAccess/internalPasswordDisabled 三域——
  decode 位静默吞咽；`userDetail` GET 回显 ProfileUpdatable **硬编码 true**
  （L736）、InternalPasswordDisabled/DisableUIAccess 恒零值。**行为联动零
  落点**（登录被拒臂/密码改道臂在 auth 面均无消费方）。
- **落法（T-439 预留位两档纪律）**：三旗 = 恒禁用 + 零提交 + hint 如实
  标注（两臂语义进 hint：Disable UI Access = 登录被拒臂——UI 登录被拒、
  API/Token 不受影响；Disable Internal Password = 密码改道臂——内部口令
  停用、认证走外部 IdP）；现值 = BE 回显出厂档（profile=true / 其余
  false——与 7.161 活体默认档同值）。
- **API 漂移钉（tripwire，t453 腿①）**：直连 PUT 携带三域 → **201**（吞咽
  不报错）而 GET 回显维持出厂档三断言——BE 承接票落地日本腿翻红即提示
  转正（届时控件解禁 + 进 body + 提交-回显-行为三链腿改写）。另：
  **payload 净度**断言（UI 真实创建的 PUT 体 = 七键闭集，三能力位零携带
  ——网络层对账）。
- **双布尔 vs 枚举候裁臂**：三值枚举下拉维持（ADR-0026 暂行）+
  `user-form-role-parity-note` 差异登记附注（7.161 = Administer Platform +
  Manage Resources 双布尔 + Platform Auditor / Manage Webhook；readonly_
  admin 无双布尔对位——不建不伪造）。组侧 Platform Administrator /
  Manage Resources / Manage Webhook / Auto Join / External ID = BinFlow 组
  模型无对位域（console-m8 §6.10 + RBAC 模型 §5），不建不做缺位登记。
