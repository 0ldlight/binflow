## 做了什么

1. **AC① 复制面板**：治理组新增「复制」页（`/binflow/ui/governance/replication`，导航项落
   治理组 admin-only 区），含两卡：
   - **复制目标**表：状态（运行态标签 + status-dot）/ 目标名 / URL（mono + 拷贝）/ 仓库
     （源 → 目标）/ pending / 进行中 / 失败（>0 标红）/ 累计成功 / 上次成功时间（`—` =
     从未成功）。运行态优先级：已停用 > 异常（N 失败）> 复制中 > 排队（N）> 正常。
   - **最近事件**表：时间（formatAuditTime mono）/ 状态 badge（**原样英文 enum 不翻译**，
     沿审计页 §4.10 口径——排障要比对 API）/ 制品路径（按 replication_id 映射源仓前缀，
     mono + 拷贝）/ sha256（截断 `7位…4位` 展示，拷贝完整值，§7.3）/ 尝试次数 / 最近错误。
2. **AC② 数据面**：`GET /binflow/api/v1/replication/status`，**每 10s 自动刷新**
   （`REPLICATION_POLL_MS = 10_000`，挂载即取 + setInterval；轮询 hook 沿 T-160
   MigrationPanel 形态）。四态收敛（console-ux §5.1/§3.6.3）：
   - loading：Skeleton（仅首帧；轮询不清空已到达数据）
   - 403：页面主数据面单张无权限卡（L2，复用缺省 `empty-state` 锚——治理组导航本就
     admin-only，兜底非 admin 直链场景）
   - **404 / 501：降级为一句提示**（404 = 端点未桥接——**当前真实二进制的实际行为**，已用
     真实服务端验证；501 = 实例未启用复制）；`targets: []` = 面正常但无目标 → EmptyState
   - 其它错误：无数据 → ErrorCard + 重试；有旧数据 → 保留表格 + 行内「上次刷新失败」
     （瞬断不清屏，同 T-160 语义）
3. **AC③ Playwright**：`web/e2e/replication.spec.ts` 7 用例（hermetic 全 mock，沿
   storage_migration 先例：dist/ 兜底 SPA + `/binflow/api/**` 全拦截）：
   ① 目标表 + 事件表渲染（计数/状态徽标/截断 sha256/拷贝锚/仓库映射前缀）；
   ② 10s 自动刷新（第二次轮询后状态 正常→异常（1 失败）前进，计数 ≥2）；
   ③ 空 payloads → 双空态、零表格；④ 501 与 404 分别降级（文案区分「未启用」vs「尚未桥接」）；
   ⑤ 非 admin 403 → 无权限空态；⑥ 轮询瞬断保留旧值 + 行内提示、零 ErrorCard。
4. 零新增 CSS（全部复用 `.table/.badge/.status-dot/.mono/.kv/.copy-btn/.field-hint` 等既有
   基元）；data-testid 沿 §10 规则 `repl-` 前缀（`repl-page/repl-targets/repl-target-<i>/
   repl-events/repl-event-<i>/repl-empty-{targets,events}/repl-unavailable/repl-stale`）。

## 契约假设清单（`GET /api/v1/replication/status`——桥接票以此对齐）

端点尚不存在（T-162 遗留 2）。形状按 `internal/replication/model.go` 真实 Go 类型推定，
序列化沿 `internal/storage.MigrationStatusView` 惯例（snake_case / int64 计数 / RFC3339
`*_at` 文本 / `''` 表空）：

```json
{
  "targets": [{
    "id": 1, "name": "dr-site",            // ReplicationConfig 公开字段（见下条剔除）
    "source_repo": "libs-release", "target_url": "https://…", "target_repo": "libs-release",
    "enabled": true,
    "pending": 2, "in_progress": 1,         // ConfigStatus 拍平（Store.Status(id)）
    "succeeded": 1204, "failed": 0, "skipped": 5,
    "last_success_at": "2026-08-22T07:59:01Z",  // '' = 从未成功
    "updated_at": "2026-08-20T10:00:00Z"
  }],
  "events": [{
    "id": 4567, "replication_id": 1,        // ReplicationTask 全量（ListTasks newest-first，
    "blob_sha256": "9f86d0…", "node_path": "org/app/1.0/app-1.0.bin",  // 跨配置合并取最近 N 条）
    "status": "failed",                      // 009 闭集 pending|in_progress|success|failed|skipped
    "attempts": 6, "last_error": "…",        // '' until a failure
    "created_at": "…", "completed_at": ""    // '' = 未终态
  }]
}
```

关键裁定（桥接票注意）：
1. **`target_username` / `target_password_enc` 不下发**（凭据不过状态面；AC 也不需要）。
2. `ConfigStatus.ReplicationID` 与配置 `id` 相等，**不重复透出**。
3. 计数字段名沿 Go：`succeeded`（非 "success"）、`in_progress`、`pending/failed/skipped`。
4. `last_success_at`/`completed_at` 空值用 `''`（沿 model.go 注释「'' when …」），非 null。
5. 事件表跨配置合并 newest-first（模型注释明言「history accumulates for the console event
   list (T-159)」）；建议服务端默认 limit 50、`?limit=` 可调——前端不传参，兼容任意 N。
6. 降级语义：**404**（端点未桥接/路由未挂）与 **501**（实例未启用复制）都给提示卡；403 admin 门；
   200 + `targets: []` = 已配置面正常但无目标（空态）。
