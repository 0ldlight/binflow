### internal/auth/ldap.go（新增，约 600 行）
- `LDAPConfig` 配置结构体（含 Enabled, URL, BaseDN, BindDN, BindPassword, UserFilter, UserIDAttr, GroupFilter, GroupNameAttr, AdminGroup, PoolSize, StartTLS, TLSConfig, ConnectTimeout, RequestTimeout）
- `LDAPConfig.defaults()` 方法填充默认值（UserFilter="(uid=%s)", UserIDAttr="uid", GroupNameAttr="cn", PoolSize=5, ConnectTimeout=10s, RequestTimeout=30s）
- `LDAPConn` 导出接口：抽象 Bind/Search/StartTLS/Close/SetTimeout 操作，供测试 mock
- `LDAPConnWrapper` 包装真实 `*ldap.Conn` 实现 LDAPConn
- `LDAPDialer` 导出函数类型：创建 LDAPConn 的工厂，测试可注入 mock
- `ldapPool` 通道式连接池（默认 5 连接，get/put/Close 操作）
- `LDAPUserResolver` 消费者侧接口：按 (provider, providerID) 查找用户
- `LDAPProvider` 实现 `IdentityProvider` 接口：
  - `ProviderName()` → ProviderLDAP
  - `Authenticate()` → 始终返回 ErrInvalidCredentials（LDAP 不支持 Bearer token，ADR-0020）
  - `Resolve()` → 委托给 LDAPUserResolver 查找已有用户
  - `Bind(ctx, username, password)` → 核心认证方法：
    1. service account bind（若 BindDN 配置）→ 搜索用户 DN
    2. 用户密码 bind 验证
    3. 搜索用户组（若 GroupFilter 配置）
    4. 检查 admin 组成员（若 AdminGroup 配置）
    5. 返回 Claims{Name, Groups, Admin, ProviderID}
  - `Close()` → 关闭连接池

## 设计决策

1. **Mock 选型**：未使用 go-ldap/v3 的 TCP mock server（该库不提供内置 mock），而是采用接口抽象（`LDAPConn` / `LDAPDialer`）实现 mock。这是 Go 标准模式（依赖注入），且测试覆盖了相同的 Bind/Search 逻辑路径。

2. **连接池**：使用 channel-based pool（`make(chan LDAPConn, maxSize)`），支持 get/put/Close 操作。池满时多余连接被关闭，池空时新连接被 dial 创建。

3. **安全**：配置中不包含密码字段（BindPassword 通过构造函数参数注入，由调用方从 env 读取）。支持 LDAPS（TLS）和 StartTLS。

4. **AdminGroup 判定**：先检查 group search 返回的 group names 是否包含 AdminGroup（支持精确匹配和大小写不敏感匹配），若 AdminGroup 是 DN 格式则执行 base-object search 获取 group name 进行二次比较。
