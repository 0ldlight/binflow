## 1. 实现面（HL-3：一个 /v2 面，两个包型）

Artifactory 的 HelmOCI 就是 docker v2 栈直接服务（`isDockerGroup = {Docker, OCI, HelmOCI}`）。BinFlow 落法同构——**协议面不复制，包型接线是增量**：

| 文件 | 变更 | 说明 |
|---|---|---|
| `internal/adapter/helmoci/`（新） | doc.go + handler.go | 包型注册壳：`Protocol()="helmoci"`、`RepoTypes()=[local]`、内容面委托 docker 面（与 docker 包型的内容面 404 姿态逐字节一致）。doc.go 承载三 media type 链 + 客户端语义文档 |
| `internal/adapter/docker/api.go` | `servesV2Plane()` 家族判定 | HL-3 家族事实落在 docker 面：`{docker, helmoci}` |

| `internal/adapter/docker/catalog.go` | catalog 过滤 widen | helmoci 仓的 image 进 `/v2/_catalog`（家族共享面 ⇒ 共享 catalog） |

| `internal/addons/slots.go` | `HelmOCI()` 槽 | package-type / **pro** / `helmoci`（M11 占位行转正；PRD 档位矩阵 locked→community, pro+ 解锁）。Helm() 注释同步修正（「rides the docker package type」→「separate package type and slot」） |

**为何三 media type 不需要新映射**：docker 面的 manifest 校验自 T-32 起就是 pass-through（no-whitelist，注释明言 "Helm OCI configs … depend on that"）——helm 的 `application/vnd.cncf.helm.config.v1+json` / `...chart.content.v1.tar+gzip` / `...chart.provenance.v1.prov` 按结构校验（config.digest + layers[].digest + 引用完整性）直接过，存储 Content-Type=客户端原值，manifest 往返字节一致（digest 语义的前提）。本票以测试+活体断言钉死这条链，而非加映射。

**门控三缝的机制**（无新分支，全部走既有 weave）：建仓面 = weave 2（validateRepoTypeDyn → 槽 known+locked → D3 400）；/v2 写面 = weave 1 的 `/v2` 臂（gateV2Write，POST/PATCH/PUT/DELETE）；读面 D1 不问。

**内容面**：`/binflow/<helmoci-repo>/...` → docker 面的 spec-body 404（与 docker 包型一致；浏览走 /api/storage 管理面，适配器无关）。**范围**：LOCAL only——remote（OCI 上游 pull-through）与 virtual（manifest 聚合）是后续票；虚仓 Helm/HelmOCI 不混仓校验（T-309 validateHelmFamilyMix）已在案，本票活体复证。

## 5. 三登记点的处置（T-313 D-2 / D-3 / D-5）

**D-5（oci:// 透传深化）——重评完成，维持 verbatim 透传**：helmoci 面已落地但仅 LOCAL——虚仓背后仍无 OCI 取数面（无 OCI pull-through、无 manifest 聚合），把上游 index 的 `oci://` 条目改写到 BinFlow 自身仍会指向取不到 chart 的 URL，劣于透传（透传至少指名可用上游）。规格默认「改写」的前提是 Artifactory 有 HelmOCI remote/virtual（JFrog 文档口径）；BinFlow 补齐该面之前 `helm.preserve.oci.urls` 开关无意义。行为有测试钉死（helm/urlrewrite_test.go「oci stays」+ virtual_test.go ocichart 条目）。**后续票触发器**：HelmOCI remote/virtual 立项时翻转本条 + 补改写目标形态（`oci://<对外host>/<repoKey>`）。

**D-2（chartsBaseUrl 分体基址，P2）——登记后置（conductor 余量条款授权）**：诚实实现需三处联动：① `parseRemoteConfig` 的共享 schema 加 per-protocol 槽（helm-only 字段进全包型共享配置，且 nuget/maven 等仓会得到一个 inert 字段——与 no-inert-fields 规则相抵，须 architect 定座）；② helm 侧 memberContext 读成员仓 config（现 ClassReader 契约只放行 Type，需新缝）；③ 取数侧（remote .tgz 回源基址=chartsBaseUrl+相对路径）需 internal/remote Engine 的 URL 覆盖——T-313 登记原文已明示「超出本票 area」。半落（只做改写识别不做取数覆盖）会产出一个回显但不生效的字段。建议随 D-3 同域并票给 architect 的 remote 域扩展票。

**D-3（`_external` 落盘缓存）——评估结论（供 architect 终裁，Q6）**：
- 现状：`_external/<proto>/<url>` 经 helm 适配器自建 guarded outbound client（同族 SSRF 链：per-hop 筛查/重定向复查/超时/私网豁免旗标）透传 + `X-Binflow-Upstream` 头，**不落盘**；`_transitive` 走 engine 落盘（已绿）。归因：`Engine.land()` 是唯一缓存写入口，其寻址=repoURL+相对路径，绝对 URL 取数无 engine 缝。
- 落地形态（若做）：Engine 增 FetchAbsolute（或 land 接受绝对 URL + 落盘路径即 `_external` 折叠路径——本身已是合法节点路径）+ TTL 定类（外部 chart 依赖文件按内容类，缺省 86400s 合理）+ 负缓存/stale 降级复用 + `_external` 代理侧改为消费 engine 结果。
- 收益：重复解析免重复 egress + 上游故障 stale 降级；成本/风险：动 internal/remote 核心（M3 SSRF 五参数面）回归面大，`_external` 触发面窄（上游 index 含外部 URL 条目才走）。
- **建议：滚 M13 单列**（与 D-2 同域并票）；M12 余量不开此回归面。非 DoD 缺口（Q6 暂行已明示「评估结论定 M12 内落地或滚 M13」）。

## 6. 客户端版本备注

- helm **v4.2.4**（本机）验证；OCI 语义与 3.8+ 一致（oci:// 引用/tag=version/--plain-http/prov 附加 layer）。helm 4 对 `--verify --keyring` 要求 keyring 为 openpgp 可解析形态（armored export 会报 `invalid data: tag byte…`，二进制 `gpg --export` + 验签需含公钥、签名侧需含私钥）——qa 复跑时照此备钥。

- oras/crane/skopeo 本机不可得；OCI 通用客户端等价面以 docker manifest inspect（#13）+ helm（ORAS 内核）覆盖。
