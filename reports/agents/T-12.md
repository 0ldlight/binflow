## 二、关键实现决策（对照 AC）

### AC1 Put 事务边界（正确性核心）

严格按架构 §3.3 + §3.2（T-25 a 案裁定）实现：

```
BeginSession → Append(reader) → Commit(expect)     ← 物理 blob 先就位
  ↓ (成功后)
blobs 行（ON CONFLICT DO NOTHING）                   ← blob-first 第二步
  ↓
nodes 行（upsert by (repo_key, path)）               ← 最后
```

- **反向被禁止且被 FK 兜底**：nodes.sha256 → blobs.sha256 外键使「先 node 后 blob」在数据库层不可能成功。
- **崩溃窗口**：Commit 后、元数据前崩溃 → 残留无引用 blob，GC 宽限期回收（ADR-0006 设计路径）；绝不产生指向不存在 blob 的 node。
- 两条**顺序敏感断言**固化该不变量（见测试节）。
- 存储层 sentinel（ErrChecksumMismatch/ErrSessionPoisoned/…）经 `%w` 原样透传，httpapi 可判。

### AC2 校验矩阵

- repo key：`[a-z][a-z0-9-]{1,62}`（PRD FR-3-AC4；T-22 回写后的 {1,62} 口径，总长上限 63）。
- 保留字：`api`、`v2` 精确匹配拒绝（ADR-0008）——`api-local` 合法（只是路由段前缀撞车才保留）。
- rclass：local 唯一可服务；remote/virtual → `ErrRepoTypeNotSupported`，message 含 "supported from M3"（400 形态归 httpapi 翻译，语义留在服务层）。
- packageType：generic 唯一（docker/maven/npm/pypi → 同上 M3 语义）；未知值 → `ErrInvalidRepoType`。
- UpdateRepo：description/config 可改，**type 与 packageType 不可变**（变更会静默改变全部 adapter 路由决策）。

### AC3 local 语义（repo-semantics.md 吸收）

| 规格（§3/§4，高置信度） | 实现 |
|---|---|
| 同路径同 checksum 幂等重传 → **免覆盖检查也免 deploy 权限检查**，保留 created/createdBy | `Put` 在权限门**之前**先做 `isIdempotentRedeploy` 判定；命中则跳过全部检查直接走 metadata 刷新路径。测试固化：**零权限用户** alice 重传同内容成功（spec 原文「无 deploy 权限也可完成」） |
| 同路径不同 checksum（或未带 checksum）= 覆盖，需对旧 node 有 DELETE 权限 | 覆盖检查先于 write 门；拒绝 message 含 `needs DELETE permission`（对齐规格文案形态） |
| 覆盖保留 created/createdBy、更新 modified 系 | putNode 的 overwrite 分支；测试用注入时钟断言 UpdatedAt 移动、CreatedAt/CreatedBy 不动 |
| Delete 只删 node 引用（blob 从不删，交 GC） | Delete/DeleteByPrefix 只动 nodes；测试断言 blob 文件在 node 删除后仍可 Stat |
| 路径不存在 → 404 幂等 | `ErrNodeNotFound`（服务层 sentinel；metadata 层的等价物不外漏） |
| 目录递归删 + prune 空父目录 | 尾斜杠路径 → DeleteByPrefix 子树删 + `pruneEmptyParents` 沿父链上溯；有存活子节点立即停；folder 行最后删（崩溃只可能多留不可能多删） |
| 删仓：非空不带参数 → 报错含 `deleteContent` 提示；带 true → 全删 | `ErrRepoNotEmpty` message 原文含 `deleteContent=true`（FR-3-AC5） |

**目录 node 表示**（M1 骨架自定，规格未约束存储形态）：nodes.sha256 列 NOT NULL + FK，目录行共享一个固定 marker sha256（64 个 '0'）+ 对应 blobs 行（ON CONFLICT DO NOTHING，全局一条）。目录的 Get 返回 `(nil, node, ErrIsFolder)`——adapter 以此渲染 FolderInfo。marker 从不可经 storage.Open 读到（无物理文件）。

### AC4 测试（全分支）

**基座选型**：按票据建议用**真引擎 + 临时目录**（storage.OpenEngine + metadata.Open on t.TempDir），集成度最高；仅错误注入与写序断言用装饰器包装真 Store（hookStore：journal 记录每次子库写操作的顺序 + 按操作名注入失败）。

覆盖清单（24 函数）：
- key 校验矩阵 16 例（非法字符/超长/保留字/边界长度）；类型矩阵 11 例（remote/virtual/docker/maven/npm/pypi → M3；未知值 → invalid）
- CRUD 生命周期（重复建/未知 key/不可变字段/列仓排序/删空仓）
- 管理面权限矩阵（匿名/非 admin × create/delete/get/list/update）
- Put/Get 往返、校验失败透传（storage.ErrChecksumMismatch）、路径校验 12 例
- **幂等重传免权限**（零权限用户成功）、**覆盖需 DELETE**（缺权限 403 + message 断言；授权后成功且 UpdatedAt 移动、CreatedAt 保留、旧 blob 行留存待 GC）
- 目录 node、非空 body 拒绝、marker 不可读、Get(folder) → ErrIsFolder
- 文件删/幂等删、目录递归删（含前缀兄弟 `d` vs `dx` 不误删）、prune 空父（全部剪除 vs 有存活子即停）
- 删仓两分支（拒绝时仓与 node 均存活；deleteContent=true 后全部消失；空仓直删）
- **事务边界三件套**：
  1. `TestPutMetadataFailureRollsBackNode`——注入 nodes.put 或 blobs.put 失败 → node 不存在；重传成功（一次性注入模拟瞬态故障）
  2. `TestPutBlobFirstOrder`——journal 断言 blobs.put 先于 nodes.put（T-25 a 案）
  3. `TestPutPhysicalBlobBeforeMetadata`——blobs.put 触发时物理 blob 文件必须已在磁盘（§3.3 反向禁止）
- 读权限矩阵、nil Authorizer fail-closed、审计尽力而为（失败不阻断）+ 事件序列
