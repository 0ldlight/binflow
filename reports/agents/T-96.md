## 做了什么

### 1. 互斥锁原语（storage.AcquireDataLock——T-94 未落地，本票先行实现并申报）

**申报（T-94 派单时避免重复）**：`internal/storage/datalock.go` + `datalock_unix.go` + `datalock_windows.go` 已实现 data 目录级跨进程互斥锁。T-94 只需在 REST gc 面（`internal/httpapi/system/gc.go`）消费 `storage.AcquireDataLock(dataDir, "gc")` 并在 409 body 里带上 `ErrDataLockHeld`/锁文件内容即可，**不要重写原语**。

- 形态（R9，供架构 review 把关）：`<data_dir>/.maintenance.lock`，0600，flock（unix）/ LockFileEx（windows，kernel32 直调——不把 x/sys 从 indirect 提为 direct，ADR-0005 依赖门不动）；`LOCK_EX|LOCK_NB`，争用返回 wrap `ErrDataLockHeld`；锁文件首行写持有者诊断记录 `pid=<n> op=<gc|export|...>`（进程死掉会留 stale 记录，错误文案明确说 "last holder"）。
- 同进程两个 fd 也互斥（flock 语义按 open file description）——serve 进程内 REST gc 与 CLI export 进程在同一 data 目录上真实争用。
- **gc CLI（cmd/binflow-server/main.go runGC）已接线持锁**（acquire → 整个 mark/sweep/ledger 清理 → release）：这是我的 area（cmd），使 W25b 双向互斥今天即可真机验证；REST 面归 T-94。
- import 不取锁：目标是空目录 + 停机，无争用对象（日志注明）。

### 2. export 子命令（GE-07，W28/W28b）

`binflow-server export -c <cfg> --output <dir> [--tar]`，流程（顺序硬规则，ADR-0015 决策 3）：

1. 取 data 目录锁（与 GC 双向互斥）；
2. **先 DB 快照**：`VACUUM INTO`（在线 backup API 面，serve 持续可写，WAL 兼容；实测产物为 plain rollback-journal 单文件、无 -wal/-shm 残留，已拒绝对已存在目标重写）；快照落 `<out>/metadata.db` 后 chmod 0600；
3. **purge 瞬态**：`DELETE FROM web_sessions`（架构 §11.19：web_sessions 不入备份；remote_cache 保留——其行描述随 blobs/ 走的缓存）；
4. **拷贝 blobs**：整树 `<data>/blobs/<2hex>/<sha256>` → `<out>/blobs/`，逐文件 `Chtimes` 保 mtime + 保权限位（ADR-0006 勘误②）；只拷合法形态（2-hex 分片 + 64-hex 且前缀匹配），外来文件不洗白（与 GC 扫描同过滤）；
5. **manifest.json**：`{formatVersion:1, createdAt, binflowVersion, blobCount, totalBytes, metadata:{file:"metadata.db", sha256}, graceNote, blobs:[{sha256,size,mtime}]}`（blobs 清单 = ADR-0015「sha256 清单」，按 sha 排序——import「前 100」抽验因此确定）；**引用集 = 快照自身的 nodes ∪ docker_refs**（不是磁盘现状、不是 blobs ledger——窗口内新增 blob 允许多拷但不被引用，import 后成 GC 候选）；导出时逐一 stat 输出文件，**引用缺失 = fail-fast**（源实例悬空引用，W28b「全存在」由导出侧自证）；
6. 产物目录 chmod 0700（NFR-S22，umask 无关）；metadata.db/manifest.json 0600；
7. `export.run` 审计写**源实例**（快照已封存，事件属源实例历史——恢复侧不含它，属正确语义）；actor=admin（对齐 T-94 对 gc.run 的 CLI 口径）；action 常量消费 T-93 已落的 `audit.ActionExportRun`（期间 T-93 落地，我删了本地重复常量改消费其面）；结构化 INFO 日志含吞吐（NFR-P19 记录不设门）。

防护：--output 非空拒绝（防混批）、output 与 data dir 互相嵌套拒绝（防自读自写）、失败清理半成品（blobs/metadata.db/manifest.json）。

### 3. import 子命令（GE-08，W30/W30b/W31/W32）

`binflow-server import -c <cfg> --input <dir> [--verify spot|full]`：

- **前置**：目标 data dir 必须空（唯一豁免 `.maintenance.lock`——锁残留不是状态；binflow.db/blobs/sessions 任一存在即拒，退出码非 0）；此检查先于读备份——目标永不被污染；
- **校验阶段（只读、先验证后写盘）**：manifest 结构校验（formatVersion ≤ 1、blobCount == len(blobs)、totalBytes == Σsize、metadata.file 必须裸文件名防穿越、sha256 形态、去重）；metadata.db 实测 sha256 == manifest 值；**schema 天花板**：快照 schema_migrations > 本 build 最新版 → fail-fast（迁移链只向前，ADR-0015 决策 4；旧快照在恢复后首开时自动升）；blob 完整性 = **size 全验 + sha256 抽验前 100**（sha 排序后的前 100，`--verify full` 全量重哈希）；
- **写阶段（db 先、blobs 后，ADR-0015 决策 4）**：copy metadata.db → sqlitePath(cfg)（默认 data_dir/binflow.db，显式 dsn 尊重之）+ CopyBlobsTree 保 mtime → data dir chmod 0700 → `metadata.Open` 打开恢复库（旧 schema 就地升迁）→ `import.run` 落审计（actor=admin，action 消费 T-93 的 `audit.ActionImportRun`）；**任何失败 clearDirContents 清回空（无半恢复）**，stderr 明示；
- `--verify` 非法值（非 spot/full）400 风格 CLI 报错。
