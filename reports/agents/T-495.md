## 1. 三载体形态表（本票定案）

### 1.1 Runner 注册闭集扩列勘误（留痕）

ADR-0044 决策 6 的载体表：maintenance 域 3 槽 → 6 槽。ADR-0046 K75 已开「第 4 域」（insights）先例——本票是同款增量注册纪律作用在**域内载体**层面：+3 个 dispatch 臂 + maintenanceSlots 清单扩列 + 闭集错误文案点名六槽，**021 domain CHECK 与台账 schema 零变化**（域仍是 maintenance，key 是域内自由键——021 注释原文「the maintenance job slot name」）。勘误行：代码注释（schedule_wiring.go Run doc + system_maintenance.go maintenanceSlots doc）+ 本节；DECISIONS.md 的 ADR-0044 勘误行归 architect（遗留 §7-1）。

### 1.2 与 7.161 §3.9 的对位与差异登记

- §3.9 区块 2「Enable Quota Control」两个实例级百分比字段（Storage Space Warning/Limit %）**不承载**：BinFlow 的阈值事实源是 per-repo quotaBytes（存储配额页）——T-462 FE 注记原文「quota 阈值走存储配额页」已注册该读法；本票给的是**检查的调度化**，不是第二阈值源。实例级百分比对若要承载需新持久席位（config 域/新表）——独立票。
- §3.9 区块 5 的 Compress/Prune 在 Artifactory 是**即时钮**；本票落的是 cron 载体（票面 AC 明定「三载体 cron 配置 CRUD」）。即时钮的 REST 面（若 FE 转正票需要）= 内核已备（三个 Run* 可直接挂 handler），一行路由的事。

## 2. TTL wire 面（AC2）

链路：`PUT /api/repositories/{key}`（remote 臂）body `metadataRetrievalCachePeriodSecs`（POINTER）→ `repoConfig.configJSON` 转发 → `parseRemoteConfig`（族规：缺席=存值保持/600 默认；显式 0=按缺席（600 产品默认）；**负值=点名 400**）→ canonical `remoteConfig.MetadataRetrievalCachePeriodSecs`（恒回显）→ create/update 两臂落 `remote_configs.metadata_ttl_seconds`。

- 消费端即browse.go:227 与 fetcher `ttlFor` 读的那一列——**internal/remote 零改动**（缝早已就位，缺的只是上游 wire 旋钮）。T-461 遗留「枚举快照 TTL 非 wire 可调——降级 e2e 用换 url 失效签名」解除：e2e 现在可以 PUT 缩窗代替换签名（e2e 归 FE/后续票）。
- 词族拼写：`metadataRetrievalCachePeriodSecs` 循官方字段命名族（retrievalCachePeriodSecs / metadataRetrievalTimeoutSecs 均为 repo-semantics §7.1 高置信行）；语义锚 = remote-browsing.md §1「远端内容按 Metadata Retrieval Cache Period 的值缓存」高置信引文。**该精确拼写不在 §7.1 表内（中置信——登记）**：官方文档单源（remote-browsing.md 成稿来源注记的 JFrog《Remote Repositories》文档族），无反编译参考。

### 4.1 httpapi 20m 超时归因 + 本票终绿证据（共租机器）

超时期间本机与 T-509 会话的深跑共存（iteration-1514 原文「T-509 深跑持续（21 进程）」；实测 load avg 29→**125**）。三次复跑取证：

1. `go test -race ./internal/httpapi`（40m 顶）→ 2294s 完成、**唯一失败** `TestUploadsOutOfOrderParts`（MPU 轮询限期测试，uploads 面，本票零接触）；
2. 该 MPU 测试单跑复验 → **4/4 PASS**（含 `-count=3`）；scratch worktree（`git worktree` @HEAD）逐组合回放（HEAD 裸 / +T-509 文件 / +T-509+本票文件 / +storage.go）**全部无法复现**——纯负载瞬态，非代码缺陷；
3. 终局：`go test -race -count=1 -timeout 40m ./internal/httpapi` → **`ok 1610.624s` EXIT=0，全包零失败**（含本票全部新测试）。

结论：httpapi 包测试健康；20m 门在本机今日被「套件增长（iteration-370 时 527s → 现 1610s）× 共租深跑负载」突破——本票新增测试合计 ~13s（占 20m 的 1%）。**TEST_TIMEOUT=20m 的重校准归 conductor**（遗留 §7-8）。

**quota 超限臂的实现细节**（测试钉死）：夹具先上传 18B 制品再 UpdateRepo 收紧 quotaBytes=10（上传门会拒「10B 仓里放 18B」的正序路径——收紧后的存量超标正是调度检查要暴露的形态）；断言 WARN 文案 `repository over its quota` + 仓名、detail `"repo":"gap-quota"` + `"overQuota":1`。

## 7. 遗留 / 上游确认

1. **DECISIONS.md ADR-0044 勘误行**（载体闭集 3→6）——architect 文件，本报告 §1.1 为留痕本体，待回填。
2. Artifactory §3.9 实例级 quota 百分比对无载体维持（阈值家 = per-repo quotaBytes）；承载需新持久席位——候 PM。
3. FE 转正（GCPage gc-cron-gap 注记 → 真三槽）归后续 FE 票（派单明定不碰 web/）；降级 e2e 的「换 url 失效签名」手法可换 TTL PUT。
4. prune 恒 dry-run 是本票定案；若运营要「定时真删」，那是 gc 槽既有能力（cron 配 apply 语义属后续裁定）。
5. compress 的 postgres 形态随 postgres store 落地（接口缝已备）；sqlite VACUUM 期间写者 busy→IsStoreBusy 503 族——运维按 Artifactory 同款「off-hours 压缩」预期（文档归 tech-writer 增量）。
6. 全仓 `make lint` 的两条余量在并行 T-509 会话 promote_test.go（gofmt/ineffassign）——归该票收口。
7. Compress/Prune 的即时钮 REST 面（7.161 §3.9 原生形态）未开——内核已备，挂路由即得，候 FE 转正票联裁定。
8. `TEST_TIMEOUT=20m`（Makefile）对 httpapi 包在本机已被套件增长 × 共租负载突破（终绿用时 1610.6s）——重校准（升 30m 或 CI 侧 split 已有、本地 per-package 门）归 conductor。
9. `TestUploadsOutOfOrderParts` 为负载敏感限期测试（load>40 时可瞬态失败，4/4 复验 PASS + worktree 回放无法复现）——登记为已知瞬态，非本票引入。
