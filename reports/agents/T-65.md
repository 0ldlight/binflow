## 一、实现内容

### 1. ssrfguard.go — NFR-S13 校验链（①②③⑦）

- **① scheme 断言**：`CheckURL` 对 http/https 之外的 scheme 一律拒绝（`scheme_not_http`）；建仓侧校验归 T-64，`NewClient` 构造时对 BaseURL 再断言一次（FR-15-AC3 的请求时镜像）。**建仓不拦私网 URL**（T-79 勘误五：IP 校验全部在请求时）——`TestNewClientSchemeAssertion` 显式断言 `http://10.0.0.1:9099` 构造成功。
- **② 全 IP 过清单**：`blockedRanges` 显式前缀表 = 0.0.0.0/8 与 ::（未指定）/ 10/8、172.16/12、192.168/16（RFC1918）/ fc00::/7（ULA）/ 127/8、::1（回环）/ 169.254/16、fe80::/10（链路本地，含 169.254.169.254 云 metadata）/ 224/4、ff00::/8（组播）/ 255.255.255.255（广播，置于 240/4 之前）/ 240/4（保留）。IPv4-mapped IPv6 先 `Unmap()` 折叠（`::ffff:127.0.0.1` 不得洗白）。**解析出的全部 IP 逐一过检，一个私网答案即整体拒绝**（round-robin 公私混排防绕过，`TestCheckURLMatrix/mixed resolution` 用例）。`allowPrivateUpstream` 豁免参数只放行 IP 清单，scheme 链永不豁免（有测试钉死）。
- **③ DNS rebinding 防护**：`Guard.Dialer(timeout)` 返回的拨号函数内部自行解析 → 全 IP 过检 → **pin 首个已验 IP 拨号**（不再走系统解析）；内层 `net.Dialer.Control` 回调对**实际连接地址**二次过检（backstop，正常永不触发，为未来重构保留）。check/dial/control 三阶段拒绝都以 `*RejectionError` 穿透 `url.Error`/`net.OpError` 包装（`errors.As` 可达）。
- **⑦ WARN 结构化日志**：每次拒绝恰好一条 `level=WARN msg="remote: outbound target rejected (ssrf-guard)"`，attrs = `repo`/`target`/`category`/`phase`/`ip`，零堆栈（测试断言无 goroutine/.go 帧）。**DNS 解析失败不算 SSRF 拒绝**（不 WARN、非 Rejection）——归 T-66 assumed-offline 路径，有测试钉死。
- 超时接线：返回的连接包 `idleTimeoutConn`——每次 Read/Write 前把 deadline 推后一个 socketTimeout，**读空闲超时**语义覆盖 mid-body 停滞（http.Transport 本身无 per-request idle-read deadline；`http.Client.Timeout` 会封顶整个流式体，FR-20-AC11 不可用，故不设）。

### 2. client.go — stdlib-only transport（②⑥④⑤）

- **零新依赖**：`go.mod`/`go.sum` 零改动（git diff 空），纯 net/nethttp/netip/slog。
- **④ 重定向手动跟随**：`http.Client.CheckRedirect = ErrUseLastResponse` 关自动跟随，`follow()` 循环逐跳：每跳（含初始）先 `CheckURL` 过全链再发包——**禁跳目标在第二个包发出之前被拒**（测试断言 hop 只被调用 1 次）；上限 **5 跳**（第 6 跳 `ErrTooManyRedirects`；5 跳边界成功用例并存）。301/302/303/307/308 全认；出站面只有 GET/HEAD，RFC 的 POST→GET 改写规则不适用（注释钉死）。
- **⑥ 超时**：`socketTimeoutSecs`（默认 **15s**，repo-semantics §7.1 socketTimeoutMillis=15000）统一驱动 Dialer.Timeout / TLSHandshakeTimeout / ResponseHeaderTimeout / idle-deadline。**h1.1 only**（ForceAttemptHTTP2=false：idle-deadline conn 包装不能 gate h2 多路复用流）。
- **⑤ 缓冲型 64MB**：`Fetch()`（metadata 类）按 `MaxBufferedBody`（默认 64MB）双路限流——Content-Length 预检快速失败 + `LimitReader(limit+1)` 实测截断，超限返回包装 `ErrBodyTooLarge` 的错误（T-66 映射 502）；`Stream()`（artifact 类）不限流，body 包原子计数器（`BytesRead()`，流式计数供 T-66 日志字段）。
- **重试**：幂等 GET/HEAD 连接级失败（ECONNREFUSED/ECONNRESET/EPIPE/EOF/ErrClosed）指数退避重试 **2 次**（200ms→400ms）。**超时不重试**（15s/次须尽快进 T-66 assumed-offline，别把延迟×3）；HTTP 状态码不重试（M41/M43/M44 上游计数负断言必须看到每次尝试）——两者都有测试钉死。**【规格待验证】**"幂等 GET 指数退避 2 次/超时"未明确超时是否触发重试，BinFlow 保守取"不重试"，推翻点是 `retriable()` 单行。
- **Basic 凭据**：`applyBasicAuth` 只构造透传（解密归 T-66/ADR-0012 决策 4）。**跨 host 重定向剥离 Authorization**（浏览器/Go stdlib 行为；规格未写，BinFlow 安全默认，双侧测试：同 host 保留/跨 host 剥离）。默认 UA `binflow-remote/1.0`（调用方可覆盖）。**方法白名单 GET/HEAD**（remote 不可写的出站侧物理保障，FR-20-AC9）。
- **DisableCompression=true**：不协商 gzip——制品字节逐位透传（架构 §4.5），避免透明解破坏上游 Content-Length/checksum 关系。
- 其它：`JoinURL`（base+path 拼接，双侧斜线折叠）；`FinalURL`（重定向后最终 URL，供 T-66 npm tarball/simple href 重写）；`CloseIdleConnections`（删仓/停机）；非 2xx 状态原样返回（状态语义归 T-66 状态机）。

### 3. 关键取舍与安全语义（供 reviewer）

| 决策 | 依据 |
|---|---|
| 每请求双解析（CheckURL 一次 + dial 一次） | check 相是 M42 取证与"零发包拒绝"的载体；连接复用（keep-alive）时不发生 dial，check 是唯一逐请求防线。DNS 开销每请求一次，M3 代理路径可接受 |
| 解析失败 ≠ 拒绝 | 上游可达性问题（assumed-offline），不是 SSRF 事件，不 WARN |
| 豁免仓跟随私网重定向 | 豁免语义即"可私网"；`TestClientRedirectPrivateFollowedUnderExemption` 钉死该语义（302→127.0.0.1:1 实际尝试连接、非链拒绝） |
| 前缀表只收 PRD v1.2 ②枚举集 | CGNAT 100.64/10、TEST-NET 等未列入（规格清单即契约）；要加是表内一行 + 测试一行的单点改动 |
| TLS 证书校验 | 走 stdlib 默认（URL hostname 作 ServerName——transport 从请求而非自定义 dial 取 TLS host，pinned IP 拨号不影响校验）；未加 TLSClientConfig 注入口（M3 无 clientTlsCertificate 需求，repo-semantics 列为不依赖项） |
