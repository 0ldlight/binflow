## 7. 缺陷登记

**D-T421-1 [P1] AQL criteria 对象成员次序敏感——操作符对象成员后不可再跟任何成员**
- 现象：`items.find({"repo":{"$match":"m8-perf-local*"},"type":"file"})` → **400** `Failed to parse query: ... syntax error near ,"type":"file"})`；`{"type":"file","repo":{"$match":...}}`（同样的成员、不同次序）→ **200**。
- 边界（bisect 定界）：`{"repo":{"$eq":…},"type":…}`、`{"path":{"$match":…},"type":…}`、`{"repo":{"$match":…},"path":{"$match":…}}`、`{"repo":{"$match":…},"$or":[…]}` 全部 400；标量/$or 在前、操作符对象居末 = 200；纯标量任意序 = 200。**判读：criteria 对象的解析循环把操作符对象成员当成了终结符。**
- 影响：官方 AQL JSON 成员无序语义被破坏；**PRD §5.5 L21 验收命令原样即中招**（其形为 `{"repo":{"$match":…},"type":"file","$or":[…]}`）。工作区影响：重排成员即绕过；失败形态=诚实 400（零伪空集、零数据面风险）。
- 归属建议：internal/search 语言前端（T-409 lexer/parser 域）——测试语料未覆盖混序成员组合（现有用例恰好都把操作符对象放末位）。
- 复现：净实例 + `curl -u admin:password -X POST http://127.0.0.1:8080/binflow/api/search/aql -H 'Content-Type: text/plain' -d 'items.find({"repo":{"$match":"m8-perf-local*"},"type":"file"}).limit(1)'` → 400；交换两成员 → 200。

**观察（非缺陷，登记）**：①root `?list` 400 "Cannot list files of root."（root 列表走 children 面）——help 文档口径可补；②带密码复制配置在无凭据主密钥实例上 400（诚实拒绝，文案指路 env）——部署文档归 T-426/T-429 面；③`/metrics` 在根路径（非 /binflow 前缀）——与 docs 口径核对归 T-430。
