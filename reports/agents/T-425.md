## 摘要（一屏版）

1. **parity 定性修正**：Artifactory 的远端浏览是**可选配置档**（`listRemoteFolderItems`，默认 **false**——repo-semantics.md §7.1 高置信）。BinFlow T-406 as-built（remote 浏览=仅缓存行）**就是 Artifactory 默认档的同形态**——所以本票不是「补齐缺口」而是「补可选档」。做成任何子集都不越 parity 边界，全做则部分包型属 L2 自有增强（Artifactory 官方设置面只覆盖 5 型，见 §1.2）。
2. **官方支持面（2026-09-02 实取 JFrog 文档）**：「List Remote Artifacts」设置仅出现在 **Debian / Generic / Maven / Opkg / RPM** 五个包型小节；专节《Browse Remote Repositories》明说**取决于上游是否支持浏览，Maven Central 支持而 Docker Hub 不支持**。PM 暂行倾向的「helm index / docker tags 先行」恰是 Artifactory **未**开放该设置的两型——子集排序存在两种互异逻辑（对齐 Artifactory 支持面 vs 协议廉价度），Q4 需择一（§3/§4）。
3. **13 型能力矩阵落定**：唯一 S 级 = **helm classic**（index.yaml 一文档=全树，BinFlow 缝最厚）；「一文档=全树」族另有 **deb/rpm**（索引大但解析器现成，M）；**docker/helmoci** tags 层可枚举但根树不可靠（公共 registry 禁/限流，M）；maven 双层（metadata 版本层可派生、目录层靠 HTML 抓取=脆弱）；npm/pypi/conan/goproxy/cargo **无根级枚举 API**（只可 per-已知包名）；generic 无协议标准（仅当上游恰服务目录索引）。
4. **建议出口 C（子集）**，但首批与 PM 暂行倾向**不同**：批1 = helm + deb + rpm（单索引文档全树、零 HTML 抓取、全部复用既有解析器与引擎缝，约 3 票）；批2（条件）= docker/helmoci tags 层 + maven metadata 版本层；明确不做 = HTML 目录抓取族（generic 全域、maven 目录层）与无 API 族（npm/pypi 根/goproxy/cargo/conan 根）。理由与成本/风险全量见 §3。
5. **t226 活体腿结构性降级**：OSS 7.84.10 的 REST 建仓面（local/remote 皆然）被许可门 400 拒（§1.4），无法用 REST 造探针 remote 仓；按 M14 R1 ③先例凭官方文档+规格双源推进，留痕在案。

## 1. Artifactory 行为基线（评估的 parity 锚）

### 1.1 配置档与默认值

- `listRemoteFolderItems`（UI 名「List Remote Folder Items」/「List Remote Artifacts」，官方文档两种拼写并用）：默认 **false**；「目录浏览时是否合并远端条目」。出处：docs/reverse/repo-semantics.md §7.1（置信度高）。
- 官方字段描述（2026-09-02 实取）："When set, lists the items of remote folders when browsing (simple and list browsing). This setting is required for dynamic resolution that depends on remote folder content information. **The remote content is cached according to the value of the Metadata Retrieval Cache Period.**" ——即远端列表本身走 metadata TTL 缓存族（BinFlow 对应 remote_configs 的 metadata TTL 600s 默认 + remote_cache 行，语义可直接映射）。
- virtual 联动：repo-semantics.md §8.5——virtual 目录 GET = 各成员（含 `listRemoteFolderItems=true` 的 remote）条目按 §8.1 顺序合并（置信度中）。若 BinFlow 开此档，FR-136 的 `listVirtual`（T-412）有一条「remote 成员仅缓存行」的既定口径要同步扩面——这是牵连面，Q4 材料已计入成本。

### 1.2 官方支持面（13 型中谁有这个开关）

JFrog 官方《Remote Repositories》页（https://docs.jfrog.com/artifactory/docs/remote-repositories ，2026-09-02 实取 markdown，71KB）「Additional Remote Repository Settings for Specific Package Types」节逐小节盘点（脚本全量比对，非抽样）：

| 官方小节 | 有无「List Remote Artifacts」 |
|---|---|
| **Debian / Generic / Maven(Gradle/Ivy/sbt) / Opkg / RPM** | **有** |
| Bower / Cargo / CocoaPods / Composer / Conan / Docker / Go / Helm(legacy) / Helm OCI / Hex / NuGet / P2 / PyPI / Swift / Terraform / VCS | 无 |

结论（置信度高，官方文档直读）：Artifactory 官方开放远端浏览的 = 「上游是纯 HTTP 文件树、服务目录索引」族（OS 包族 + generic + maven）。helm/docker/npm/pypi/nuget/go/cargo/conan 官方小节**均无**此设置。

### 1.3 官方行为声明（Browse Remote Repositories 专节）

原文要点（同上来源）："In some cases, the remote resource … supports remote browsing. In these cases, you can browse the contents of these repositories directly from the UI. For example, **Maven Central supports remote repository browsing, while Docker Hub does not**." 配图说明强调「图中包**未缓存**」——即浏览面直接呈现上游未缓存条目。

机制推断（置信度中——官方未写算法，仅给了正反例）：Maven Central 是 Apache 式目录索引服务器，Artifactory 的正例=**抓取/解析上游目录索引**；Docker Hub 反例=v2 API 只有 per-image tags/list、无可用 catalog，无法支撑根树。这个机制面直接预言了 §2 矩阵的分级。

### 1.4 t226 活体腿——结构性降级留痕

实例：t226-artifactory OSS 7.84.10（容器为他人所起在跑，本文未起任何栈）。探针实录（全部只读或失败探测，实例零残留——探针后仓库清单仍仅 example-repo-local）：

## 3. 三出口评估（Q4 材料·全量版）

### 出口 A：全做（13 型全开远端浏览）

- **成本**：一文档族 3 型 ≈ 3–4 票；per-实体族 7 型 ≈ 5–7 票（docker/helmoci 可共享一腿）；generic+maven 目录层 HTML 抓取器 ≈ 1–2 票 + 长期维护；FE 合成树面 1–2 票（T-412 display-only marker 模式复用）；per-型测试矩阵与上游压力回归 1–2 票。合计 **~11–16 票**，且 HTML 抓取族是持续性负债。
- **风险**：①HTML 抓取千人千面（上游改版即碎，Artifactory 同样存在此问题但我们无其多年积累的解析器族）；②上游压力面全开（pypi 根 simple 数 MB、nuget 全量游走数十页、Docker Hub 配额）；③「不可行」型（goproxy/cargo/conan 根树）要么造不出要么造假（用搜索/缓存行凑树=语义欺骗）。
- **用户价值**：全包型一致体验，但 8 型的价值增量实际很小（用户对这些型的使用以「知道包名拉包」为主——协议客户端本身不浏览）。

### 出口 B/C：子集（出口 C）——仅枚举形态天然适配的包型

两条子集排序逻辑（Q4 需择一，这是本票最重要的裁决输入）：

- **C1「Artifactory 对齐」序**：deb/rpm/generic/maven（+Opkg，BinFlow 无此型）——对齐官方设置面；但其中 generic 全域与 maven 目录层都押在 HTML 抓取上（可靠性低），**不建议作为首批**。
- **C2「协议廉价度×缝厚度」序**：helm（S，唯一一文档全树且缝最厚）+ deb/rpm（M，一文档全树+解析器现成）。

**本票建议：出口 C，取 C2 为批1，C1 的可靠子集为批2（条件）**：

- **批1（建议随 Q4 裁定进 M16）**：helm classic + deb + rpm。约 **3 票**（service 侧「远端枚举缝」一票——engine Fetch + index 派生 + display-only 合成行接 T-412 模式 + virtual 成员口径扩面一臂；per-协议 index 派生一票；FE 一票）。零 HTML 抓取、零新解析器、全部上游交互走既有 guarded egress + metadata TTL。
- **批2（条件票，批1 验证用户真实使用后再裁）**：docker/helmoci tags 层（M，共享一腿，定位为「drill-down 增强」而非根树——需向用户明示 catalog 根不可达）+ maven metadata 版本层（S–M，纯派生不做 HTML 抓取）。
- **明确不做**：generic 与 maven 的 HTML 目录抓取（脆弱负债）；npm/pypi 根/goproxy/cargo/conan 的根树（无 API——做了也是假树）。

- **成本**：批1 ~3 票 + 降级语义（assumed-offline 窗口内回退缓存行+空态文案「远端枚举不可用」）+ ACL 前置读门（FR-136.4 同款，T-412 allow() 先例）。
- **风险**：①上游索引文档大小（deb Packages.gz 数十 MB——需尺寸上限+缓存行落 metadata TTL，Artifactory 官方语义即「按 Metadata Retrieval Cache Period 缓存」，映射干净）；②virtual 聚合口径扩面（repo-semantics §8.5「含 listRemoteFolderItems=true 的 remote 成员」——T-412 的「remote 成员仅缓存行」注释要同步，牵连面可控）；③一致性（缓存行与远端派生行并存去重：缓存行优先、远端行 display-only 零落库——ADR-0013 姿态沿用，且 architecture.md §20 注记〔ADR-0016 边界〕预登记过「若开 remote 目录浏览，engine 落节点须与材料化助手合流」——T-406 读侧 putFolderRow 已部分兑现，余量入实现票评估）；④SSRF 无新面（枚举目标 URL 仍由 repo 配置决定，ssrfguard 既有）。
- **用户价值**：helm/deb/rpm 三型是「用户确实会翻目录」的型（挑 chart 版本、挑 suite/arch、挑 NEVRA），与树浏览 UX 天然匹配。

### 出口 D：维持缓存浏览（T-406 as-built）

- **成本**：0 票。
- **parity 定性**：= Artifactory **默认档**（listRemoteFolderItems=false）同形态——严格说不欠 parity，欠的是可选档。
- **用户价值缺口**：remote 仓浏览只见已缓存条目——「不知道上游有什么」的主诉残余存在（T-406 已消除红卡，剩的是发现面）。helm/deb/rpm 用户的价值损失最实（见 C）。
- **配套动作（若 D）**：用户文档明示「remote 浏览=缓存面（对齐 Artifactory 默认）」+ 远端发现走协议客户端/搜索面；`listRemoteFolderItems` 字段在 canonical config 中按名 400 或落库不生效（二选一，随 D 裁定登记 K66 收口）。
