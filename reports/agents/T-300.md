## 3. 过程中发现的三个样式层事实（含两个批一连带修复）

1. **emotion 注入序在 base.css 之后**（探测实证：临时 `.mono` span 生效、同 class 的 MUI input
   内字体被 MUI `font` shorthand 压制）——修正 T-299 日志「base.css 按特异性压过 MUI 默认」的表述：
   同级特异性 (0,1,0) 时 MUI 赢；**复合类（.badge.neutral 等 (0,2,0)）仍然 CSS 赢**。后续批次写
   className 续挂时必须用复合形态或显式 sx。
2. **`.field input` 后代选择器与 MUI OutlinedInput 叠双边框**（内层 input 的 border/bg 叠在
   fieldset 之内）——批一即存在（login/仓库表单的 TextField 同受影响），本票收窄为 `.field >
   input` 连带修复（探测：inner border 1px→0px；批一 login 页同受惠）。`.filter-bar input`
   同款，整块退役（过滤输入已全量 TextField 化）。
3. **裸 `.mono` 类在 MUI input 上失效**（(0,1,0) 对 (0,1,0)，emotion 后载赢）——新增
   `monoInputSx`（'& .MuiOutlinedInput-input' (0,2,0) 显式落 mono 栈）用于无 .field 包裹的
   过滤/矩阵添加位输入；`.field input.mono-input` 后代形态 (0,2,1) 天然赢，保留。
