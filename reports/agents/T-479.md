## 1. 设计

### 1.1 段结构（每腿 local → remote → virtual，段内顺序依赖）

- **`<leg>/remote`**：`uat-matrix-<proto>-remote`（rclass=remote）指真实公共上游，拉钉版小制品，断言
  回源+缓存冻结：`X-Binflow-Cache: MISS → HIT`（仓跨 run 保留，故 warm 形态 `HIT→HIT` / `REVALIDATED→HIT` 同样合法——`cached_twice` 白名单五态）。
- **`<leg>/virtual`**：`uat-matrix-<proto>-virtual` 成员 `[local, remote]`，断言 **local 成员命中**（`X-Binflow-Resolved-From: <local>`、字节一致）+ **远端制品经 virtual 解析**（`Resolved-From: <remote>`）——repo-semantics §8.5 / remote-virtual.md 两桶序口径。
- 报告行扩展：`record "<leg>/remote"`、`"<leg>/virtual"`（npm 额外 `npm/remote-npmjs` 边界 tripwire 行）+ 既有腿汇总行不变。段失败 → 腿 FAIL，但已记的 local PASS 行不掩蔽。
- CLI 不加段级过滤：virtual 段消费 local 段当 run 发布的制品（`npm-example@$VER`、`multi1:$VER`、`matrix/$VER`、`example.com/matrix@$GVER`、`matrix-chart-$VER`），段序即依赖序。

### 1.3 npm 特殊设计（产品边界如实处理）

docs/user/integrations/npm.md：npmjs 的 packument 不在 `<name>/packument.json` 布局路径——**npmjs 真上游不可代理（M4 backlog）**。方案两件套：

1. **布局兼容上游**（doc 认可形态「内网 Nexus/Artifactory 等」的等价构造）：实例上建 generic 仓 `uat-matrix-npm-upstream`，curl PUT 按 **npm 存储布局**落 tarball（`<pkg>/-/<pkg>-<ver>.tgz`）与 packument（`<pkg>/packument.json`，sha1/sha512 由 python3 hashlib 从 tarball 实算）。remote `uat-matrix-npm-remote` 的 url 指它（服务器经公网 IP 回源自身——hairpin 活体过，SSRF 公网 IP 放行）。完整客户端链（npm install）+ packument MISS→HIT 全绿。
   - 拓扑守卫：`host_is_public`（python3 ipaddress）——对 localhost/私网 BinFlow 干跑时自动 SKIP 该段（SSRF 防护按设计拒绝环回），CI 对公网 UAT 恒可用。
2. **npmjs 边界 tripwire**（`uat-matrix-npm-npmjs`）：tarball 路径**兼容**（`isarray/-/isarray-2.0.5.tgz` 经代理字节与上游 cmp 全等 + 缓存冻结）；packument 断言 **404**（文档化边界）。M4 交付 npmjs 代理时此行转红，强制更新本段。

### 1.4 幂等与稳定性

- **钉版**：全部拉固定版本/digest（非 latest）；docker 用 digest 寻址（`:linux` tag 上游可重建，digest 不可漂——若上游 GC 旧 manifest 会 FAIL 并提示重钉）。
- **warm cache 幂等**：矩阵仓跨 run 保留 → 钉版上游制品可能已缓存。`cached_twice` 允许 `MISS→HIT | HIT→HIT | HIT→REVALIDATED | REVALIDATED→HIT | REVALIDATED→REVALIDATED`；复跑 generic 腿实测 `HIT -> HIT` 仍 PASS。
- **网络抖动**：`retry_run 2`（3 次尝试、3s 退避）包裹引擎级探测与 conan install；守卫探测 2 次 8s 超时。
- virtual 写路由：一律不配 `defaultDeploymentRepo`（读聚合是被测面；generic 段顺带断言 C5 405 逐字文案）。

### 1.5 离线安全（strict-tools 语义沿用）

`guard_upstream <leg> <url>` 腿前探上游（runner 视角，任意 HTTP 码=可达）：

- 可达 → `NET_OK=1`，两段照跑。
- 不可达 → **`--strict-tools`（CI）：FAIL**（腿红，消息带探测码）；**本地干跑：SKIP**（`<leg>/remote`、`<leg>/virtual` 各记一行 SKIP，腿的 local 断言照常计分）。
- 单元验证（不可达地址 `https://10.255.255.1`）：lax 记 SKIP 返回 0 / strict FAIL 返回 1 / 可达置 NET_OK=1——三态实测过。
- 限制如实记：探的是 runner 出网；server 侧出网是另一跳（CI runner 与 UAT 均有公网出口，实际风险低）。
