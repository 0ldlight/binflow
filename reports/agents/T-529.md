**⑥实现摘要**：

- `CacheProjection` 八字段：Key = remoteKey+`CacheSuffix`；PackageType 镜像 repositories 行；其余六字段（RepoLayout/…/BlackedOut）自 canonical config JSON 逐键派生（拼写与 `repo.remoteConfig` tags 同步注释——import 会环，沿 `repoPolicy` 先例）。两个**固定值**（checksum 策略恒 client-checksums、快照行为恒 unique）按设计 §4 落注释不落字段（规格未给消费面，加字段=猜测补齐，违 clean-room 铁律）。
- 默认值规则（全部有锚）：priorityResolution/blackedOut/archiveBrowsingEnabled 缺省 false（产品默认）；repoLayoutRef 缺省 `maven-2-default`（`repo.defaultRepoLayoutRef` 同值 literal + 同步注释，artifactory.xsd 默认）；handleReleases/handleSnapshots 用 `*bool` 探针缺省 true（v1 remote echo seat 默认 + maven `ParseRepoConfig` 同规则；当前 remote canonical 结构不持久化这两键，行恒读 true——注释登记）；storeArtifactsLocally `*bool` 缺省 true = gate 缝。
- 非法输入语义：未知 key / 非 remote 类型行 → ok=false 无日志（正常解析面）；store 故障 → ok=false + WARN（接口无 error 席位，设计签名固定；degrade 姿势对齐 `virtualMemberOrder` 的漂移容忍——单仓故障不放大为解析面 outage；日志仅 repo key 与 store 错误文本，无凭据）；config blob 不可解码 → 产品默认值 + WARN。
- 读取面选择依据：blackedOut 的 authoritative 位置是 canonical JSON `blackedOut` 键（repo.Service create/update 均不写 remote_configs 行的 blocked_out 列——走读 service.go:2345/2733 证实），故投影单源取 JSON 键，与 repo 侧 `refuseBlackedOut`/`memberPriorityResolution` 同面。

**⑫风险**：

1. **handleReleases/handleSnapshots 当前恒读 true**：remote canonical 结构（`repo.remoteConfig`）不持久化这两键，v1/v2 wire 亦无 remote 写入席位（v1 echo 仅渲染默认）。投影读到的永远是目前的有效值 true——与 BinFlow 现状一致，但若后续票给 remote 配置面加这两键，投影面无需改动（读取面已就位）。已在代码注释登记。
2. **store 故障静默降级**：接口签名（设计定死）无 error 席位，store 故障 → ok=false + WARN，四桶序里该 remote 的 cache 步缺席（本体步仍在，D2 语义降级为两桶成员语义）。这是签名层面的固有权衡，非实现偷懒。
3. **repoLayoutRef 缺省值 literal 双源**：`defaultProjectionLayoutRef` 与 `repo.defaultRepoLayoutRef` 是两处 literal（import 环），已加同步注释（`repoPolicy` 先例）。漂移风险低（xsd 默认，不常动）。
4. 本票导出面尚未被消费（T-530 并行在做 internal/repo 侧）——集成正确性在 T-530 的测试面闭环，本票仅保证导出签名与设计 §4 逐字一致。
