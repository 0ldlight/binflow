## 1. 双计修正——缝的真身与勘误

### 1.1 前测（对 18194 净实例的 curl 探针，修正前二进制）

```
upload PUT docs/guide.md → 201
?stats 基线                    → downloadCount 0
item GET #1（无 query）        → downloadCount 1
item GET #2                    → downloadCount 2
内容面 GET                      → downloadCount 3
folder item GET ×2             → 不计数（Get 的 folder 分支先于埋点）
?properties GET（文件）        → +1（计数）
/api/search/checksum 直读      → 不计数（SearchResult 全字段集 FileInfo 同构）
```

结论：**item-info GET 经 storageNode → 内容面 Get 落点，as-built 即 +1 下载计数**（T-438 §3-2「探针面计数继承」登记的 BE 侧事实，本票 curl 复证）。BE 侧 de-probe 是已登记的「audit 面整理票」，本票 FE 不越界改 BE。

### 1.2 「useAsync 重复发射」诊断勘误（T-461 §6-3）

T-461 登记「useAsync 的 effect deps `[...deps, tick]` 数组恒新引用 → 随父渲染重复发射」。**该诊断不成立**：React 对 deps 逐元素 Object.is 比较，数组本身恒新引用不触发 effect 重跑；NodeDetail 的 deps 全是 primitives（kind/repoKey/path），跨渲染稳定。真身有两处（Playwright trace 钉死，18195 实例）：

1. **装载链的乐观赌装**（主凶，贡献 2 计）：`ArtifactsBrowser` 装载链取乐观全路径（`ancestorDirs(fullDir)` 含 URL 末段），末段是文件时 `listFolder` 对文件路径发 **FolderInfo GET + `?list&depth=1` 两枚请求，均经内容面 Get 落点各 +1 计数**（`?list` 臂在 400 前已计数——handleStorageList 先 storageNode 解析再拒文件）。trace 实证（修正前）：
   ```
   13.764 GET /api/storage/{repo}                    ← 根 listing（不计数）
   13.767 GET /api/storage/{repo}/docs               ← 目录 listing（不计数）
   13.792 GET /api/storage/{repo}/docs/guide.md      ← 赌装 FolderInfo（+1）
   13.982 GET /api/storage/{repo}/docs?list&depth=1  ← 目录 ?list（不计数）
   [缺]    GET /api/storage/{repo}/docs/guide.md?list&depth=1 ← 赌装 ?list（+1，本轮已修掉）
   14.079 GET /api/search/checksum?sha256=…&repos=…  ← NodeDetail 详情读（改道后零计数）
   ```
   ——T-461 实测「单次选中计 2~3」= 赌装 2 + NodeDetail item GET 1。另有一处次凶：分类未决期 `dir` 取乐观全路径，**展开 effect 把末段加进 `expanded` 集**，绕过装载门的 expanded 成员路径同样触赌装（本票 trace 第二轮定位）。
2. **NodeDetail 的 item 读本身**（贡献 1 计）：useAsync 每次选中发 item GET → 计数面。

### 1.4 后测（修正后，18195 实例 + 请求级探针）

- 浏览全链（深链 ×4 含根层文件 / 表行点击往返 / 重挂载）后：`?stats` 全程 0；**无 query 的 item GET 请求 = 0**（探针白名单 ?stats/?list/?properties/?permissions/docker_tags 读臂）。
- 3 次 no-store 内容 GET → `?stats` = 3，详情页计数 = **3（精确值）**——修正前该场景 ≥ 4（浏览污染）。
- 探针发现的副产物（登记不修）：内容面 GET 带 `Etag`/`Last-Modified` 无 `Cache-Control`——浏览器对同 URL 重复 fetch 走条件请求，**304 不落服务端 Get 落点 = 不计数**（诚实 HTTP 语义；spec 下载腿用 `cache:'no-store'` 对齐真实下载形态——t445 的 3-GET 腿此前靠 item GET 污染撑过 >=3 断言，本票去污染后该腿暴露此脆弱并同款加固）。

## 2. SystemLogsPage 数据源切换

### 2.1 主源（T-493 端点三臂全消费）

- **limit 尾随**：`GET /api/v1/system/logs?limit=N`（档位 100/200/500/1000 维持；行序最早→最新，环内遥测 held/capacity 投影进表头文案「（环形 {held} 行，取最近 {N}）」；`truncated` 时源说明行挂「环形已满，更早日志已被淘汰」徽标）。

- 7s 尾随倒计时 / Pause / Refresh now / 403（L2 卡 + 尾随自动停）/ error 错误卡 + 重试——两源同构；403 hint 按源分文案。

### 2.2 降级路径（T-459 as-built 形态延续）

## 6. 契约漂移 / 登记（供 conductor 逼 architect 回写）

1. **T-461 §6-3「useAsync deps 恒新引用 → 重复发射」诊断不成立**（React 逐元素比较；NodeDetail deps 全 primitives）——双计真身 = item face 计数继承（as-built 已登记）× 装载链乐观赌装（未被诊断过）。建议 architect 在 T-461 报告勘误行留痕。
2. **item-info / ?properties / ?permissions 面计数下载**（M1 as-built，T-438 登记「audit 面整理票候选」）：本票 FE 浏览路径已绕开（general 页签）；**属性/权限页签的浏览读仍各 +1**（`?properties`/`?permissions` 无非计数等价面——properties 仅 item face 体回显、搜索面不带）。de-probe 仍是 BE 票。
3. **内容面 GET 无 Cache-Control（带 Etag/Last-Modified）**：浏览器条件请求 304 不计数——「同会话同 URL 重复 fetch ≠ 重复下载」。对 UI 无影响；对以 fetch 断言计数的 spec 是脆弱点（本票两处 no-store 加固留范式）。
4. **root 层文件无元数据合并**（root ?list 400，既有登记）：本票以名搜索臂消化——详情字段族根层文件齐备，无缺位。
5. SystemLogsPage 源说明行等用户可见文案反转——**文档腿（whats-new/console.md）按票内指令未动，归 T-518**。
