## 3. 唯一未绿项的归因（TestBigTreeCopyNo5xx，非本票路径）

- 全量 repo 包（race 与非 race 各两次）**唯一**失败 = `TestBigTreeCopyNo5xx`
  （operations_test.go:776）：10k 节点 copy **dry-run 墙钟预算**（非 race 5s / race 45s）。
- 本票非测试代码的全部运行时增量 = 一个 map 字面量条目 + 注释 + 一条错误文案——
  copy/move 计划走查不经过建仓矩阵，常数级改动无任何可能影响该路径性能。
- 负载敏感性实证：同一测试 load avg ~38-148 时 11.16s（>5s，FAIL）→ load ~13 时
  **3.39s PASS**；race 下 load 高企时 1m7s/2m35s（>45s，FAIL）。本机当日 load 峰值
  148-205（QA 全树 race + 用户应用：iTerm/WindowServer/UURemote 常驻）。
- 同机同族的既有失败（先于本票）：QA T-421 首轮全树 `internal/metadata 1528s`、
  `internal/repo 1519.962s` 双双 25m 超时 FAIL——即 T-421/T-423 在查的 busy/perf 家族。
- 结论：环境性负载 flake，非回归；留 T-421/T-423 处置（其票据范围正覆盖此族）。
