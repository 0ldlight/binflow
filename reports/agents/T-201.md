## 做了什么

### 1. D-3 [P0] — REST 触发的迁移不再随请求消亡

`internal/httpapi/migration.go` `handleMigrationStart`：`StartMigration(r.Context())` → `StartMigration(context.WithoutCancel(r.Context()))`。

- 根因（T-173 D-3）：net/http 在 handler 返回即取消 r.Context()，后台迁移在盘存阶段死于 `list disk blobs: storage: gc: context canceled`（H12/H14 不可达）。
- 手法沿用既有判例：GC 的 sweepCtx（T-94 N1，system_gc.go:158）与 replication enqueue（T-162，repo/service.go notifyReplicator）同为 WithoutCancel —— 保值、只摘取消。生命周期未丢：MigrationEngine.StartMigration 自派生可取消 ctx，Close() 仍会在优雅停机时叫停迁移（引擎自身契约，未改）。

### 2. D-1 — stats/metrics/GC-sizing 按引擎列举

三处消费面 + 一条只读 seam + cmd 装配：

- **seam**：`internal/storage/s3_inventory.go`（新文件，避开 T-202 的 s3.go）——`BlobStat{Size, LastModified}` + `(*S3Engine).BlobStats(ctx)`：一次 ListObjectsV2 走 `blobs/` 前缀，extractSha256FromKey 过滤异形键（与 GC sweep 同过滤）。纯只读。
- **stats**：`internal/httpapi/system.go` —— `countBytes` 移为 Server 方法，physical 半边按 `Deps.BlobInventory`（消费侧接口，S3Engine 直接满足）分支：有 seam 走引擎列举求和；否则原 dirSize 盘走（M1 行为不变）。
- **/metrics**：`refreshStorageBytes` 优先走 seam（物理对象字节），gauge help 文案同步；无 seam 的 s3 标签栈保留 usage 行求和旧回退。
- **GC sizing**：`handleSystemGC` 候选字节走 `sumCandidateBytesFromInventory`（一次列举按候选过滤求和；候选不在列举中报 `ErrBlobNotListed`，语义对齐盘路径 sumBlobFileSizes 的"中途消失"读法）——S3 下不再打 `gc candidate sizing incomplete` WARN。
- **装配**：`cmd/binflow-server/main.go` newAssembledServer —— `backend=s3` 且引擎为 S3Engine（纯 S3 / migration.completed）时注入 `deps.BlobInventory`；**dual-write（MigrationEngine）不注入**：迁移期间盘上仍全量持有 blob，盘走继续正确（也避免给 MigrationEngine 加方法碰 T-164/T-202 交界）。

### 3. D-2 — export/import 引擎感知（对称修复）

`cmd/binflow-server/backup.go`：

- 选择器 `engineBackedBlobStore(cfg)`：`backend=s3` 且非 dual-write（迁移完成或未配置）→ 引擎面；disk 与 dual-write 保持原盘树拷贝（dual-write 盘侧全量，恢复到盘后由迁移的幂等重扫补齐 S3）。
- **export**：`exportBlobsFromEngine` —— 逐个 live-set sha 走 `engine.Open` 流出（快照先行、mtime 保序的 ADR-0015 硬序不变）；对象 LastModified（经 BlobStats seam，cmd 侧自有消费接口）落为 artifact 文件 mtime，W28/W32 的"GC 宽限钟不归零"在 S3 面保真；引擎取不到 blob = 源实例 dangling reference，拒绝出包（W28b 原语义）。与盘拷贝的差异：引擎面只装 live set（桶内孤儿对象不是备份的事），已注释说明。
- **import**：`importBlobsIntoEngine` —— artifact 的 blob 经引擎会话协议（BeginSession/Append/Commit，与迁移引擎 copyBlob 同一驱动）上传，manifest sha 为期望摘要（引擎 commit 校验门在线上把关）；逐 blob 幂等（桶已有则跳过，且**绝不**回滚删除既有对象）；写阶段失败以 WithoutCancel ctx 回滚删除**本次新建**的对象——no-half-restore 契约延伸到桶。
- usage 文案与文件头注释同步（main.go Notes + backup.go 包注释）。
