# T-150: storage.Backend interface + Engine signature change (Open -> io.ReadCloser)

**Agent**: dev-go-storage
**Date**: 2026-08-22
**Status**: done

## Summary

Defined the `storage.Backend` interface (package-internal per ADR-0019) and changed `Engine.Open` return type from `(io.ReadSeekCloser, BlobRef, error)` to `(io.ReadCloser, BlobRef, error)`.

## What was done

### 1. New file: `internal/storage/backend.go`
- Defined `Backend` interface with five methods:
  - `Put(ctx, sha256, reader, size) (BlobRef, error)`
  - `Get(ctx, sha256) (io.ReadCloser, BlobRef, error)`
  - `Delete(ctx, sha256) error`
  - `Exists(ctx, sha256) (bool, error)`
  - `List(ctx) ([]string, error)`
- Package-internal: not exported outside `internal/storage`
- Pure blob CRUD — no sessions, no GC, no locks

### 2. Changed `internal/storage/api.go` — Engine.Open return type
- `Open(ctx, sha256) (io.ReadSeekCloser, BlobRef, error)` changed to `(io.ReadCloser, BlobRef, error)`
- Added doc comment explaining ADR-0019: the DiskEngine returns `*os.File` (which implements `io.ReadSeekCloser`); callers that need Seek type-assert

### 3. Changed `internal/storage/engine.go` — implementation
- `engine.Open` return type changed to match the interface
- Comment updated to document the ADR-0019 contract

### 4. Consumer fixes (type assertions where io.ReadSeekCloser is needed)

| File | Line | Change |
|---|---|---|
| `internal/repo/service.go` | 278 | `service.Get`: type-assert `rc` to `io.ReadSeekCloser` before returning |
| `internal/repo/virtual.go` | 229 | `probeLocalMember`: type-assert `rc` to `io.ReadSeekCloser` before returning |
| `internal/remote/fetcher.go` | 595 | `land`: type-assert `bodyRC` before passing to `hinted()` |
| `internal/remote/fetcher.go` | 740 | `serveCopy`: type-assert `body` before passing to `hinted()` |
| `internal/repo/landed_blob_test.go` | 374 | `failReadEngine.Open`: change return to `io.ReadCloser`, type-assert inside |
| `internal/storage/engine_test.go` | 260 | `TestOpenReadSeekCloserAndMissing`: type-assert before `Seek` call |

### 5. Unchanged call sites (no Seek needed)
- `repo/service.go` lines 510, 623: `PutFromBlob` and `PutLandedBlob` only call `Close()` and use `BlobRef.Size` — no type assertion needed
- All test files that only call `io.ReadAll`/`Close` on the reader

## Open issues

None. The `Backend` interface is defined but not yet implemented by any type — the DiskEngine directly implements `Engine` (not `Backend`). The `Backend` interface is ready for T-151 (S3Engine) to implement.

## Notes

- The `remote/hintedReader` and `remote/cachestate.go` `hinted()` function still accept `io.ReadSeekCloser` — this is a remote-layer concern, not storage-layer. The type assertions happen at the call sites in `fetcher.go` where `storage.Engine.Open` is called.
- The `repo.Service` interface still returns `io.ReadSeekCloser` from `Get` and `ReadVirtualMember` — this is a repo-layer contract, independent of the storage Engine interface change. The `service` methods type-assert the `io.ReadCloser` from `Engine.Open` to `io.ReadSeekCloser` before returning.
