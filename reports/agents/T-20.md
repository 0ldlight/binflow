## 一、实现

新文件 `internal/adapter/generic/conditional.go`（区间解析 + 条件评估，纯函数无 I/O）；`handler.go` 的 `handleGet` 在写完公共头后按序求值：**条件请求 → Range → 全量 200**。GET 与 HEAD 走同一分支（HEAD 命中 206/304/416 时与 GET 同头、无 body）。

### Range（FR-4-AC14）

| 客户端形态 | 行为 |
|---|---|
| `bytes=0-99` / `bytes=42-42` | 206 + `Content-Range: bytes 0-99/<total>` + 精确切片（Seek + io.CopyN） |
| `bytes=10-` 开区间 | 206，end 收敛到 total-1 |
| `bytes=-10` 后缀 | 206，start = total-N；N > total → 收敛为全量（仍 206） |
| `bytes=90-999999999` | end 钳制到 total-1 → 206 |
| start >= total（`bytes=100-`、`bytes=999999999-`、`bytes=100-99`） | **416 + `Content-Range: bytes */<total>`**，无 body |
| 非法数字（`abc`、`+10`、`-abc`、`--5`、`1-2x`）、start > end（`50-10`）、`-0` | **416 + `bytes */<total>`** |
| 多区间（`0-49,60-69`）、非 bytes 单位（`items=`）、`bytes=`（空集） | 忽略 → 200 全量（不产生 5xx） |

实现要点：
- 416 一律带 `Content-Range: bytes */<total>`（语法非法集无 first-pos 可报，RFC 9110 的 unsatisfied-range 形态是唯一合法 Content-Range；Artifactory 形态保持）。与 Go stdlib `http.ServeContent` 的差异（它对 `abc`/`50-10` 回裸 416 无 Content-Range）是刻意对齐 Artifactory 规格的结果。
- `bytes=-0`（零长后缀）按 RFC 9110 定义 unsatisfiable → 416（stdlib 产生 0 字节 206，属其已知怪癖）。
- 空实体（total=0）：所有区间形态 416。
- 超过 int64 的数值（`9999999999999999999999-`）解析失败 → 416（不存在可回 200 的字节区间）。
- OWS 容忍：`bytes =0-5` 合法；token 内空白（`bytes=10- 20`）→ 416。

### 条件请求（FR-4-AC15）

- **If-None-Match**：弱比较。BinFlow 的 ETag 是裸 sha1，客户端三种拼写（裸 / `"quoted"` / `W/"weak"`）剥离前缀与引号后比较 → 304 无 body；`*` 资源存在即 304；逗号列表逐项匹配；不匹配 → 200 正常。ETag 未知（ledger 未命中 sha1）时不产生 304。
- **If-Modified-Since**：早于 Last-Modified → 200；晚于或相等 → 304（秒级截断比较，与 Last-Modified 粒度一致）；日期不可解析 → 200；Last-Modified 缺失 → 200。
- **优先级**：两者同在时 If-None-Match 独占（命中与否都不再看 IMS，RFC 9110 §13.2.2 求值顺序）。
- **与 Range 复合**：条件请求先求值——命中 304（Range 不再处理）；未命中且区间合法 → 206。

### 304 携带的头

BinFlow 在 304 上只回条件相关的头（ETag、校验和头、Cache-Control 等），不带 Content-Length/Content-Type —— Content-Length 与 Last-Modified 在求值前写入 map，WriteHeader(304) 后不会出现在线上。

```
$ curl -I -H 'If-None-Match: 40d72e0c…'         → 304
```

### 客户端版本注记（curl 8.7.1 / LibreSSL，macOS 15）

`curl -z` 的日期解析器对 ISO-8601（`2020-01-01T00:00:00Z`）**静默不发头**（行为等价无条件请求），仅 RFC 1123 形态到达线上。测试与日志一律用 IMF-fixdate，并在测试注释中写明：若未来 curl 升级改变解析行为，测试会显式失败而非空转通过。

## 四、决策记录（未定案形态的处置，供 conductor 知悉）

1. **语法非法 Range → 416（而非忽略）**：PRD AC 只列了 `bytes=abc`、start>end、start>=total 三类为 416，未定案"其他非法拼写"。按 RFC 9110（服务器可对无效 ranges-specifier 回 416）+ Artifactory 形态统一处理，且杜绝把垃圾输入放大成全量下载。
2. **多区间/非 bytes 单位 → 忽略**：PRD 明文"不做 → 200 全量"。
3. **`bytes=`（空集）→ 忽略**：RFC 9110 允许 server 忽略无效 ranges-specifier；忽略保住客户端下载。
4. **空实体所有区间 → 416**：0 长表示层无合法字节位。
5. **304 不回 Content-Length/Last-Modified**：条件相关的头（ETag 等）保留。
