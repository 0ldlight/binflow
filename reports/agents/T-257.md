## 做了什么（按票面六项）

### 1. N+1 退役（E2 内嵌为主 + E5 按需为辅——选型论证）

- **UsersPage**：行模型 = E2 加宽列表项本体（email/adminRole/enabled/groups
  全内嵌），`fetchUserRows` 的 listUsers + 逐用户 getUser 并发扇出
  （seed-m9 20 用户 = 21 请求）删除——**单请求**。
- **GroupsPage**：`scanMembership` 改 `snapshotFromUsers(listUsers())`
  单请求双索引（user→groups / group→members）；成员数列 + hover 花名册 +
  穿梭候选全集 + 成员落盘的当前组集全由 E2 投影推导。页级三请求
  （listGroups + listUsers + listPermissionTargets），与用户数无关。
- **选型论证**（architecture §14.1 E5 逐字指定，非自行裁量）：**列表成员
  计数 = E2 客户端过滤**（一次请求全量推导——不开编辑器也全量新鲜；
  groups 列表端点 K19 明令不加宽，membersCount 双物化面必漂移）；
  **编辑器选区 = E5 `?includeUsers=true` 按需单组读**（打开瞬间取，比页面级
  E2 快照新鲜；且给两视图交叉断言以真实意义——若两侧同源派生则断言空转）。
  编辑器打开 = 恰 1 次 E5 请求，用户列表不重拉（e2e 钉死）。
- 成员落盘写臂不变（逐用户 POST groups 全量替换——组侧写端点无票承载），
  补幂等护栏：E5 视图与 E2 快照竞窗外已入组的用户跳过追加（防重复组名）。

### 2. Status 列回显驱动（E2/E3 消费）

- 列表新增 **Status 列**（可排序，`users-sort-status`）：`StatusLabel`
  （widgets.tsx）渲染 启用/禁用 徽章，真值 = E2 `enabled`（恒渲染）。
- **UserDetailPage knownEnabled hack 退役**：编辑初值 `editFromDetail(d)`
  直取 E3 `d.enabled`；「本页写过的值即已知值 + 默认启用假设」状态机、
  保存后 `setKnownEnabled` 补写、以及「服务端暂无 enabled 回显（契约漂移
  已登记）」hint 文案全部删除，替换为回显事实注记。账户信息卡新增
  Status 行（同徽章形态）。T-237 期登记的契约漂移①②随本票销账。

### 3. 删除用户面（E4 消费）

- **`useUserDelete` hook**（widgets.tsx，列表行与编辑页共用；RepoDeleteConfirm
  同款 holder 闭包缝）：ConfirmDialog 基座 + **输入用户名强确认**
  （confirmDisabled: typed !== name）+ **不可恢复文案**（级联清单：组员/
  授权/token/会话同事务删除、审计保留、重复删除 404 非幂等明示）。
  - 强度说明：console-m8 §4.6 用户行的「双按钮」基线由 M9 升格为强确认
    （票面指定 + review 裁定「文案体现不可恢复」）——见契约漂移①。
- **入口两处**：UsersPage 行内 删除 按钮（admin 列，`user-delete-<name>`）+
  UserDetailPage 账户信息卡危险区（`user-danger-zone` / `user-delete`，
  success 后回列表）。**自删/内置 admin 两态 UI 预禁用 + title 述因**
  （服务端 400 终裁兜底）；last-admin 400 与 404（已被他人删）不预判——
  服务端原文如实 toast，404 时刷新列表（对象已不存在，不伪造成成功）。
- readonly_admin：无删除入口（L4），服务端 403 兜底（e2e 重放腿）。

### 4. 组穿梭单源（两视图）

UserDetailPage 组穿梭：已选 = E3 用户详情 `groups[]`，候选全集 = listGroups；
GroupsPage 成员穿梭：已选 = E5 `userNames`，候选全集 = E2 用户列表。两页
穿梭的成员事实同源（user_groups 行），e2e 交叉断言：E2 计数 === E5 花名册
=== seed 计划（m9-g01 = [u1,u11]）。

### 5. governance.ts 词表

### 6. e2e/m9/users-groups.spec.ts 填肉（占位 skip 退役，6 腿）

- **N01 users**（含 axe）：恰 1 次 `GET /security/users`、**逐用户
  `GET /security/users/{name}` = 0**、数据面 GET ≤3（实际 1）；加宽回显
  渲染断言（email/组 chip/角色/Status）+ Status 列排序。
- **N01 groups**：3 数据 GET（groups/users/permissions）、fanout=0；成员数
  列 = 2 + title 花名册；开编辑器恰 1 次 `?includeUsers=true` 且用户/组
  列表不重拉；selected 列 = u1/u11；**交叉断言 E2 计数 === E5 花名册 === 2**。
- **N02 Status 真值**：带外 POST enabled:false → 列表徽章 禁用（无 fanout）、
  编辑器 checkbox 未勾（E3）+ facts 徽章；旧漂移 hint 文案反断言消失；
  测试内收敛回启用（**不在 afterAll**——per-worker afterAll 在
  fullyParallel 下会与本腿 disable 竞争反翻转，实测踩过）。
- **N03 删除全链**：强确认三段（错名禁用/对名解禁/取消存活）→ 成功 toast
  （服务端文本）+ 行离场（免 reload）→ GET 404 `User not found` 逐字 →
  E5 级联视图（专属组 userNames 归空）→ 重复删 404 逐字（确定性非幂等）→
  自删/内置行禁用 + 服务端 400 文本逐字（内置腿 + 第二 admin 自删腿，
  last-admin 场景留服务端测试——e2e 需清空全部 admin，过于侵入）。
- **N03 编辑页危险区**：同强确认 → 回列表 URL + 行离场；admin 编辑 admin
  时危险区按钮禁用（含 axe）。
- **N03 readonly**：无删除入口（列表反断言 + 详情危险区反断言）+ 写重放 403。
- 计数器口径：排除 `/v1/session`（每次文档加载的探活）与 `/system/version`
  （useVersion 模块缓存、每 boot 一次的壳牌版本行）——两者是 app chrome
  非页面数据，N01 预算按页面所骑请求计。
