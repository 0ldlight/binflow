## 1. 做了什么

### 1.1 GC 内核 callable 化（AC1——调度与手动同载体）

`internal/httpapi/system_gc.go`：POST /system/gc 的处理器内核整体提取为导出方法
**`Server.RunGC(ctx, GCRunRequest{Actor, Apply, GraceHours, RemoteAddr}) (*GCRunResult, error)`**——
grace 解析（缺省=storage.gc_grace_hours）、数据目录维护锁（ErrDataLockHeld 语义保持）、
dry-先行的两遍 sweep、候选计径（S3 引擎感知）、blobs 台账拆除、gc.run 审计行、完成日志，
全部一处内核两个入口。REST handler 只剩鉴权/解码/错误映射（errGCGraceRange→400、
ErrDataLockHeld→409、其余→500）。调度侧以 Actor="scheduler"、Apply=true、GraceHours=nil
（grace 兜底不缩短——ADR 决策 8①）走同一内核；RemoteAddr 字段保住 REST 面 gc.run 行的
remote_addr 合并（载体行为 diff=0）。

### 1.2 维护面 GET/PUT /api/v1/system/maintenance（AC1）

`internal/httpapi/system_maintenance.go`（路由 @CapSystemRead/@CapSystemWrite）。三 cron 槽
（gc | cleanup-unused-cache | cleanup-virtual——ADR 决策 2 DDL 注释的闭集）：
- GET：三槽投影（cronExp/enabled/nextRun/lastRun/lastStatus/lastError），无行=未调度缺省态
  （零预置——维护面首配前全空，ADR 决策 2「不预置」）。
- PUT：逐槽 arm（`{"gc": {"cronExp": "0 0 /4 * * ?", "enabled": true}}`）；空 cronExp=删行
  （无行=不调度单态）；enabled=false=停用形（cron 保留、next=''——DDL 单态）；**全 arm 先验后写**
  （双 arm 一坏不半落）。手动面 POST /system/gc、POST/GET /system/cleanup 零变化
  （「Run Now」就是它们——并存维持有专测）。
- **Cleanup 两族接线**：两 cleanup 槽 fire 时同走 `repo.CleanupEngine.RunOnce`
  （Trigger=cron/Apply=true/Actor=system-cleanup）——ADR 决策 8① 闭集原文「Cleanup 两族全量
  pass（RunOnce）」的直读：BinFlow 无 virtual-only 载体（virtual 聚合不缓存），两族=一个三腿
  全量 pass，**C 层差异留痕不伪造**。
- Quota 百分比 / Compress / Prune：无 BinFlow 后端载体，BE 面缺位不伪造（FE 姿态归 T-462）。

### 1.3 备份定时 CRUD REST（AC1）

`internal/httpapi/system_backups.go` + metadata 侧 022 台账：
- **migration 022_backups**（sqlite SQL + postgres README 版本史行——T-446 的 021 lockstep 同款）：
  `backups(key PK, enabled, export_dir, created_*, updated_*)`——payload 半；cron 半在 021
  （domain='backup'，key 同）。**零预置**（Artifactory 出厂 backup-daily/weekly 是有意差异，
  ADR 已登记）。Artifactory 描述符字段无载体者（仓子集——BinFlow 导出=全实例快照；incremental/
  retention 轮转/zip/邮件告警）**缺位不伪造**。
- `metadata.BackupStore` 四方法（Put upsert 保 created_*/Get/Delete→ErrBackupNotFound/List），
  Store 接口 +`Backups()` 装配行。
- REST 五面：`GET /api/v1/system/backups`（列表）+ `PUT /api/v1/system/backups`（官方单 PUT 形，
  body 带 backupKey）+ `GET/PUT/DELETE /api/v1/system/backups/{key}`（路径键优先）。wire 字段
  =ADR 软缝⑦三名逐字（backupKey/cronExp/nextBackupTime）+exportPath（服务器路径；绝对路径、
  禁 `..`——防穿越）。**nextBackupTime 可写位**：过去时间 400（CheckNextRunAt——决策 9②），
  未给=表达式推算。DELETE 双行联动删（payload+schedule；台账删除失败仅 WARN，runner 兜底
  tombstone）。ADR-0015 勘误二边界不破：/api/export/** 维持 404、import 维持 CLI-only。

### 1.5 复制配置 cron 字段（AC2——M15 Q5 推翻兑现面）

`internal/httpapi/replication.go` 扩 `cron_exp`（wire snake_case 从族形；规格语义对位
replication.md §2.1 cronExp）：
- create 带 cron → 先验后写（坏表达式不落 config 行）→ 配置+台账行同请求落；回显
  `cron_exp`+`next_schedule_sync`。不带 cron → 无行（纯事件轨）。
- PUT /{id} 扩为 enabled **或** cron_exp（至少其一；空编辑 400 文案更新——t405 表随刻意变更）；
  显式 `""`=清（删行单态）；**enabled 翻转镜像台账行**（停用=park：enabled=0/next=''；启用=自 now
  重臂——一个开关同时停事件轨与调度轨，零新权限通道姿态）。
- DELETE 配置 → 台账行联动删；响应投影（list/GET/create/update）全部带 cron 回显。
- 400 族：`Invalid cronExp <expr> for <key>: <引擎点名原因>`（锚 §3 文案族——BinFlow 面 cron
  **可选**，故锚的 `cronExp is required` 臂永不触发——**有意差异登记**）。
- `internal/replication/schedule.go` 新增 **`ScheduleRunner`**（域 Runner：`Run(ctx, key)` 结构性
  满足 scheduler.Runner，**不 import scheduler**——依赖方向=引擎消费域载体）：config 消失→
  tombstone 行+nil；disabled→park 行+nil；**封锁（§9.2-B-4）→ skip 非失败**（WARN+nil，台账保持
  cron 下周期再 fire）；否则 TriggerFullSync 同载体（种子行+wake——零第二执行器零新队列）。

## 3. L48 双实例腿（AC2 断言口径——ADR 决策 8④ 内容层）

`TestScheduledFullSyncTwoInstanceZeroDuplicateDelivery`（internal/replication，T-420 夹具复用）：
真实双实例（B 带内容 PUT 计数中间件——只计携带 X-Checksum-Sha256 的字节传输）+ 真实
scheduler（25ms tick，replication 域注册真 ScheduleRunner）+ REST 面落每秒 cron 的配置：

1. **按点触发全量同步**：3 制品先落 A → 配置带 cron 建 → 调度 fire → B 逐路径 sha256 与源一致
   （内容 PUT 计数恰 =3——每制品传输一次）。
2. **调度窗内同制品增量事件不双推**（内容层零重复）：窗内上第 4 制品 → 事件轨 1 次传输（计数 4）；
   等下一次调度 fire 全量重种 4 路径 → 目标 HEAD 命中幂等 → **计数仍 4 + B 物理 blob 集仍 4**
   （目标 blob 集不增、零重复字节传输——任务层行允许并存，收敛交给幂等，scheduler 包注释口径）。
3. **Replicate Now 与调度并存幂等**：调度在途时 POST /{id}/run → 200（scheduled=4 重种）→
   收敛后计数仍 4、blob 集仍 4。
4. 台账/审计：schedule 行 last_run/ok 落地；`replication.schedule.run` 审计行 actor="scheduler"。
