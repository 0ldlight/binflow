## 1. 做了什么（ADR-0044 K68 七条逐点兑现）

### 1.1 动作闭集 r/w/d/m → r/w/d/m/a（K68.1）

- `internal/auth/api.go`：+`ActionAnnotate = "a"`（注释 = 属性写权限、path-plane、
  不开内容字节面、m ↛ a、docker scope 词表不收）。
- `internal/auth/authorizer.go`：rowAllows +`case ActionAnnotate: row.CanAnnotate`
  ——**path-plane 求值**（走 targetCovers，include/exclude 生效；对照 m 的 repo-scope）。
  readonly_admin 文档口径 w/d/m → w/d/m/a（代码不变——短路 `action == ActionRead` 结构性
  恒拒 a）。admin 旁路结构性放行 a。匿名面结构性恒拒 a。
- `internal/auth/authenticator.go` + `deps.go`：PermissionRow +`CanAnnotate`，两处
  adapter 拷贝。
- `internal/auth/groups.go`：PrincipalBits +`Annotate`；ItemPrincipals merge 并入。

### 1.2 properties 写门翻转（K68.1 单点）

- `internal/httpapi/properties.go`：`allowPropsWrite` 判 `ActionWrite` →
  **`ActionAnnotate`**（§25.6 点名的单点翻转，PUT/DELETE 两动词同门）。403 文案
  "requires write access" → "requires annotate access"。GET properties 维持 item-info
  r 门不变。文件头/路由注释（router.go）同步。

### 1.3 wire 词翻新（K68.2）

- `internal/httpapi/permissions.go`：
  - PUT（POST create-or-replace）收词：`read / deploy-cache / annotate / delete /
    manage` + **`write` 别名收一轮**（= deploy-cache，**不附带 annotate**——拆分语义）。
    未知词 400 文案列新五词 + 别名说明。
  - GET 回显**正名单单形**：read, deploy-cache, annotate, delete, manage（此序）。
  - DB 列 can_write 不改名、内部码 w 不变（本票零 schema 更名）。
- `internal/httpapi/storage.go`：`?permissions` 视图字母集 **+a**（r/w/d/m/a 序，
  m 后追加保持 M7 锚序）。**差异留痕**：参考实现字母表 annotate=`n`（docs/reverse/
  rest-api.md §3 勘误行，高置信）；BinFlow 按 ADR-0044 K68.2 用内部码 `a`（「内部
  compact 码与 wire 词分层」——ADR 定案优先，差异已写进 principalLetters godoc）。

### 1.4 迁移 023 + dry-run 报告 + 零提权（K68.3/4/5）

- `internal/metadata/migrations/{sqlite,postgres}/023_annotate_action.sql`：
  `ALTER TABLE permission_principals ADD COLUMN can_annotate INTEGER NOT NULL DEFAULT 0`
  + `UPDATE ... SET can_annotate = 1 WHERE can_write = 1`（零提权等价回填）。方言公共
  子集逐字同步（011/020 先例）+ postgres README 版本史补行。
  - **实现细节**：文件头 rollback 说明首词原写 "Rollback"，撞上
    TestMigrationsHaveNoTransactionStatements 的全文关键词扫描（ROLLBACK 是保留 token
    ——迁移器独占事务边界），改为 "Reverse migration" 表述（guard 测试随后全绿）。
- store 读写四点（PutTarget insert / GetTarget / PrincipalsFor / Principals）+ 列。
- **dry-run 报告**（`internal/metadata/annotate_report.go`，CurrentVersion 同款 raw-DB
  公共函数、JSON 可渲染）：
  - `AnnotateMappingDryRun` = principals 全行映射表 {行 → deploy-cache（can_write 原值
    不动）+ annotate（回填 = write）}——只读 can_write，**pre-023 库可跑**（真 dry-run）；
    报告 MappingRatePercent。
  - `AnnotateBackfillVerify` = post-apply 双向断言（WriteWithoutAnnotate /
    AnnotateWithoutWrite 双计数 + 逐行 Disagreements）；pre-023 库上跑 = 诚实的
    no-such-column 错误（不静默通过）。
- **迁移可回滚**（K68.4）：rollback = `DROP COLUMN can_annotate` + ledger 行（can_write
  全程不动）+ wire 词翻回（代码面）。测试固化往返。

### 1.5 既有断言反转⑤（write 动词 → T-444 归属）

## 4. 差异与上游裁定项（conductor 请过目）

1. **?permissions 字母 `a` vs 参考实现 `n`**：docs/reverse/rest-api.md §3 勘误行（高置信）
   记 Artifactory 字母表 r/w/**n**/d/m（annotate=n）；ADR-0044 K68.2 定 BinFlow 内部码
   `a` 且视图字母集 +a。按 ADR 实现（效力序：ADR-0044 为 T-444 前置定案），差异写进
   principalLetters godoc。若 conductor 要对位 `n`，翻转面 = principalLetters 一处 +
   一行测试（零语义影响——字母是呈现码）。**建议在 docs/reverse/rest-api.md 的
   「BinFlow 子集 r/w/d」行加勘误**（reverse-engineer 域，非本票 area）。
2. **FE 兼容期实测口径**（AC2「旧 write 消费面映射呈现」的落法）：GET 回显正名单形
   （K68.2 明文「兼容臂只在收不在发」）后——
   - **保存路径安全**：PermissionEditorPage 水化 `f.users[name]=[...actions]` 原样持有
     GET 回显数组（含 "deploy-cache"），保存时按原数组回发 → PUT 收词接受 → **存量
     授权零丢失**（手数验证 PermissionEditorPage.tsx:459/653 + api.ts PERM_ACTIONS）。
   - **展示面漂移**：勾选渲染 `actions.includes('write')`（widgets.tsx:121）在 T-455
     前对 legacy 授权显示未勾——纯显示、无数据风险。
   - **e2e 破坏面（FE 域，T-455 波收）**：web/e2e/security.spec.ts:175、
     web/e2e/m8/permissions.spec.ts:170/437、web/e2e/m9/permissions-mholder.spec.ts:200
     四处 GET echo 断言 `'write'` 将红（rbac.spec.ts:225 是 PUT body——别名收，不破；
     t104:123 的 'write' 是 FE 文案非 wire，不破）。**请 conductor 排给 T-455 或 FE
     值守票**。
3. **dry-run 报告无 CLI 挂点**：报告函数是 metadata 公共 API（raw-DB 形，CurrentVersion
   先例）+ 测试证据链；操作员 CLI 面（如 `bf db annotate-dry-run`）不在票面 area
  （cmd/），需要时 5 行挂点另立小票。
4. **internal/migrate（bf-migrate）零改动**：其迁移面不含 permission targets（grep 证
   实），write→deploy-cache 拆分与其无交集。
