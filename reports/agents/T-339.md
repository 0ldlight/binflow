## 2. 管线设计（规格锚点：repo-operations.md §1）

- **端点形状**：`POST /binflow/api/{copy,move}/{srcRepo}[/{srcPath}]?to=/{targetRepo}[/{targetPath}]`（§0 表 #1/#2；to 必填、dry/failFast 0/1、suppressLayouts 默认 1）。**无 202/异步任务形态**（§7 终裁）。响应 200 + `{"messages":[{"level","message"}]}`，Content-Type `application/vnd.org.jfrog.artifactory.storage.CopyOrMoveResult+json`；status=最后一条 error 携带码，error 无码→409 兜底，无 error→200（§1.5）；errors 在前 warnings 在后；level 取 logback 枚举拼写（V-3 中置信，按代码证据取大写）。
- **parse**：路径归一、§1.1 逐字 400（Source/Target repository key is empty）、源空路径 WARN+仓根语义。处理器内先查源 key 再查 to（§1.1 顺序）。
- **precheck（§1.2）**：目标 remote/virtual → 400 逐字消息（cache 形态 BinFlow 无此 rclass，登记不可达）；源/目标 repo 不存在 → 400 `Could not calculate repo path from src=…, target=…: repository <key> not found`；同 RepoPath → 400 `Skipping <verb> <path>: Destination and source are the same`；目标首段 `.jfrog` → 404 `Internal metadata request blocked`。`SystemIdentity` 字段留作 trash 内部豁免 seam（§1.2 `_system_`，T-345 消费；REST 面永不置位）。
- **validate（§1.3 逐项链，顺序即优先级）**：#1 源读（403 逐字）→ #3 目标 include/exclude（403 逐字，Artifactory copy/move 族自身用 403，与 BinFlow 上传面 409 分立，登记）→ #4 move 源删（403 逐字）→ #5 目标已存在且无删权限 → **401**（逐字 override 消息）→ #6 目录落文件下（400 逐字）→ #7 目标缺写（403 逐字）。#2 snapshot/release 策略 BinFlow 仓配置无此字段（登记 N/A）；#8 Release Bundles 不适用。BinFlow 扩展：配额（W26 对齐，逐项 413 消息不失败整请求）。ACL 判定按 (repo,path,action) 记忆化——万节点树不再 N×3 次权限查询。
- **transfer（§1.4）**：零拷贝（blobs 台账引用复用，测试断言台账行数不变）；元数据随行（created/createdBy/modified——BinFlow 无 modified_by 列，登记；stats 不存在故天然不随行）；properties 全量复制（覆盖=删旧再拷，旧属性不残留，测试钉死）；unix 目标调整（进目录/改名/尾斜杠三臂+根目标边界）；move=逐文件拷→删+目录自底向上剪除+父链清扫；目标空目录回收（copy/move 共用，测试曾抓到只在 move 分支跑的缺陷已修）。
- **assemble**：汇总 INFO（`copying X to Y completed successfully, N artifacts and M folders were copied`；dry 前缀 `Dry run for `；move 用 moving/moved）；审计一条 op 级（artifact.copy/artifact.move，props.* 先例）；**copy-only** 异步触发 CopyMoveObserver（候选目录=落地文件父目录去重排序集；move/dry 不触发，测试钉死；notifyReplicator 姿态：脱离请求 ctx+recover 盾）。
- **仓型语义（源侧）**：local 直读；remote=本地缓存行树 + 文件 miss 经 FR-20 引擎落地拷贝（fetchRemoteIntoCache）；virtual=两桶序成员路由（文件取首个持有成员〔local 持有或 remote 缓存行〕；目录取首个持有 folder 行成员）。move-from-virtual 拒绝（400，与 RE-08「删除不穿虚拟」一致措辞）。

## 5. 差异登记（规格 vs 实现）

1. **dry-run 含 error 时的 HTTP 状态**（§1.4/§1.5 两读）：取 §1.5 组合读法——dry 与真实跑同一聚合规则（最后 error 码/409/200），请求级 fatal（参数、类拒绝、.jfrog）两模式都按真实码。另一读法（dry 恒 200）待 live 复核，已建议并入规格 V 清单。
2. **V-2 源不存在**：取文档口径 400（`Could not find item at <repo>/<path>`），代码 warning 分支不采。
3. **community 门控码**：Artifactory 400 text/plain → BinFlow D4 403+头（Q4 终裁明确照 addon 门先例，非照 Artifactory 原码）。
4. **`Skipping <verb>` / 汇总消息中的动词**：规格写 `copy/move` 字面，实现按实际动词渲染（规格措辞系其自身摘要约定，判定为模板意涵）。
5. **suppressLayouts=0（跨布局翻译）**：中置信、LayoutsCoreAddon 域，BinFlow 不实现，所有取值行为等同 1（处理器解析该参数，登记分歧）。`atomic` 参数（仅代码证据）解析登记、无行为——BinFlow 逐项管线天然即 atomic=false 部分成功姿态。
6. **flat 端点**：不实现（Artifactory 默认部署即 404，§1.6；路由落 E-26 404，测试钉死）。PRD 105「flat 模式」若指布局扁平化应与 Artifactory flat 解耦命名——维持 T-335 的 PM 回写建议。
7. **cache 仓目标拒绝臂**：BinFlow 无独立 cache rclass（remote 缓存落 remote 自身命名空间，ADR-0012），该 400 消息不可达，保留登记。
8. **virtual 源目录拷贝**：取首个持有成员的子树（不做跨成员并集聚合）——规格对 virtual 源无据（无据处登记）；virtual 源文件路由仅查 local 持有+remote 缓存行，不穿 FR-20 上游（要上游现落请从 remote 仓直拷）。
9. **BinFlow 扩展**（规格 §1.3 链外）：配额逐项 413（W26 对齐）；modified_by 列不存在（created/createdBy/modified 随行，modified_by 登记缺位）；审计为 op 级一条（artifact.copy/move，props.* 先例，入 audit.Actions() 词表待审计属主一行）。
10. **消息中路径拼写**：`<repo>/<path>`（仓相对、目录带尾斜杠）；规格未锚定渲染式样，登记。
