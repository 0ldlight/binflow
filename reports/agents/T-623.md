## 语义结论证据（票面要求①）

代码迹（高置信，模块缓存源直读）：

- `ldap.DialURL`（go-ldap v3.4.14 conn.go:263-285）：parseLDAPURL → `dc.dial(u)` → 只用 `u.Scheme` 与 `u.Host`；`NewConn(c, u.Scheme == "ldaps")` 不携带任何认证态。
- `u.User` 在 go-ldap v3.4.14 全部非测试源零引用（`grep '\.User\b' *.go | grep -v _test` = 0 hit）。
- BinFlow 侧认证全显式：服务 bind（ldap.go:710，BindDN+BindPassword）、direct 臂（:615，pattern DN+用户密码）、search 臂（:640，搜得 DN+用户密码）。
- 生产配置路径双重保险：configmanager `ldapConfigFromSection` 投影 `u.Scheme + "://" + u.Host`，userinfo 进不了运行时 cfg.URL。

结论：LDAP cfg.URL 的 userinfo 是死重（非认证源，对照 remote repo URL 的活认证源语义）→ 渲染面 redact 零行为变更，剥离/拒绝选项无必要（无现网行为可破坏）。
