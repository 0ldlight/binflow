### AC① 迁移 API 契约回写（docs/design/architecture.md）

事实源（先读代码后写字）：

- `internal/storage/migration.go` — `MigrationStatusView` json tag：
  `running / done / total / migrated / skipped / failed / error(omitempty) /
  started_at(omitempty, RFC3339) / finished_at(omitempty, RFC3339)`；
  `runMigration` 中 `Total = len(missing)`（在本地盘而不在 S3 的 blob 数）、
  `Skipped = len(diskList) - len(missing)`（盘点时 S3 已有）；从未启动时
  `loadSnapshot` 返回零值 → 全 0 基线快照。
- `internal/httpapi/migration.go` — GET status：`Migration == nil` →
  **501** `migration is not configured`（错误信封格式）；POST start：幂等
  （已运行返回状态）→ **202 + 状态体**；`StartMigration` 出错 → **409**。
- `internal/httpapi/router.go:337-341` — 两端点均 `routeAuth{required,
  admin:true}`。
- `cmd/binflow-server/main.go:307-316, 539-582` — `deps.Migration` 仅在
  dual-write 装配（`backend=s3 && migration.enabled && !migration.completed`）
  时接线；其余一切启动形态（disk 后端 / 纯 S3 / completed）两端点 501。
  这就是「未配置 → 501 非 404」的装配层根因（404 是 E-26 兼容层兜底，
  会把「端点存在但本实例未启用」误报成「产品没这个端点」）。
- `internal/config/{api,load,validate}.go` — 键 `storage.migration.
  {enabled,completed,concurrency}`；concurrency 零值经 `defaults()` 填 5，
  `enabled=true` 时显式 ≤0 → `Validate()` 报错；`enabled=true` 且
  `backend≠s3` → cmd 装配层拒绝启动。
