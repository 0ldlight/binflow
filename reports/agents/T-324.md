**结论**：本票范围 = remote 缓存 unused-cleanup（策略源是 M10 已持久化的 per-repo 字段），**不是** M12+ 的治理面策略引擎。与既有 GC（T-94/T-173 谱系：清「无引用 blob」）的边界：GC 是存储层无引用回收；unused-cleanup 是**策略性删除 remote 缓存的 node 引用**（删引用后 blob 走既有 GC 回收）——即「cron 包装既有 GC + 策略面 + 审计事件 + REST 触发/查询端点」基线（与派单口径一致，无歧义需裁决）。

### 引擎语义（clean-room 设计）

一次 run = 三条腿，单把数据目录维护锁（与 gc/export/import 同族互斥）：

1. **session 腿**：存储引擎新能力 `SessionSweeper.SweepExpiredSessions`（open-time 扫掠的按需重跑）——零孤儿保证的「会话」半边；长运行 serve 不再等重启才回收过期上传会话。
2. **policy 腿**：对每个 `unused_cleanup_period_hours > 0` 的 remote 仓，cutoff = now − period；FILE node 同时满足「窗口内无下载事件」且「updated_at ≤ cutoff（窗口内未再落地）」→ 删 node 行 + remote_cache 校验行（node_props 随 FK 级联）。**「在用」oracle = 审计 trails**：本仓下载事件 ∪ 所有以本仓为成员的 **virtual 仓**的下载事件（virtual GET 记在 virtual key 下，成员制品经聚合服务不得误删——「排除表」的诚实实现）。
3. **gc 腿**：`storage.GCSweep`（ADR-0031 双门：hold set + 单点 Live）apply 一遍全库，回收 policy 孤立出的 blob（及任何其他孤儿），并同 REST/CLI gc 一样拆 blobs-ledger 行。grace 窗内的 blob 保守保留并计入 `gracePending`（下次 run 回收——测试钉死该姿势）。

**零孤儿保证**（票据验收核心）：完成 run 后无残留——
- **索引**：被清路径 node 行 + remote_cache 行同失；docker 索引行不可能孤儿（remote docker 仓不存在，M3 类矩阵 FR-15-AC7）。
- **blob**：policy 孤立的 blob 由 gc 腿删文件 + 删 ledger 行；仍被引用（跨仓 dedup）保留是正确行为非残留；grace 窗内保留是有意的保守（下次回收）。
- **会话**：过期 session 行 + temp 文件由 session 腿清。

policy 单路径删除顺序 = node 行先、校验行后：中途 crash 留下「无 node 的校验行」是**惰性**残留（fetch 路径先查 node 才看校验行；下次 fetch 的 PutCache upsert 自愈）。

## 4. 差异登记（无逆向规格处的自裁）

1. **「未用」oracle = 审计 trails**（BinFlow 自有）：Artifactory 有独立下载统计子strate；BinFlow 无（T-317 统计字段同为 no-op，登记在案）。副作用裁定：**audit.enabled=false 时 policy 腿拒绝运行**（报告写明原因，session/gc 腿照跑）——没有下载痕迹就没有诚实的「未用」，宁可不删。差异级别：行为等价物，语义对齐「未被下载的清理」。
2. **窗口内重新落地（updated_at > cutoff）= 保活**：remote refetch 本身是使用信号（pull-through 服务了请求）。Artifactory 未公开此细分；保守方向（多保留）。
3. **cron 节奏 = 固定每小时 tick**（产品默认，可注入），非 Artifactory Quartz `0 0 /4 * * ?`（storage-layout 待验证 3 建议不复制该表达式）。per-repo period 是策略阈值，tick 只是观察频率。
4. **删除粒度 = node 行 + remote_cache 行**；Artifactory 的 Zapping/负缓存联动语义（milestone-3 C6：本地操作、不回传上游）已对齐——本引擎纯本地，绝不同步上游删除。
5. **metrics 族名** `binflow_cleanup_{objects,bytes}`（gauge、无 `_total`）：PRD 只说「计数器（清理对象数/字节数）」；按 ADR-0022 命名规则 + registry 的 `_total` 保留规则落 gauge 型 scrape-快照（replTasks 先例），语义为进程启动以来累计。
6. **REST 面自有管理端点** `/api/v1/system/cleanup`（POST/GET）：Artifactory 的 cleanup 是后台任务 + UI 面无公开 REST 触发端点；BinFlow 按 gc 家族（GE-03）同形自裁（dispatch 基线明示「REST 触发/查询端点」）。
7. **GET 状态面直接交付**（gc 面的 GET 是登记过的 P2 债 ADR-0015 erratum ②）：cleanup 引擎自带原子 last-run 快照，GET 便宜——不还 gc 的债，也不复制债。
