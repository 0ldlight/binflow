## 事实源（先读代码后写 UI）

- `internal/httpapi/migration.go`：POST `/binflow/api/v1/storage/migration/start`
  —— `Migration == nil` → **501** `migration is not configured`（errors[] 信封）；
  `StartMigration` 出错 → **409** + err.Error()；成功（含幂等重复调用）→
  **202 + StatusView 状态体**。GET status 同一 501 语义。
- `internal/storage/migration.go`：`Total = len(missing)`（盘点时在本地盘而不在
  S3 的 blob 数 = 待迁移基数）、`Skipped = len(diskList) - len(missing)`（盘点时
  S3 已有，**不在 total 基数内**）、`Migrated/Failed` 为待迁移集的两种终态计数；
  从未启动 → 全 0 基线快照。中断重启后重新盘点、只补缺（SkipIfExists）。
- `docs/design/architecture.md` §7.1 T-176 回写版两行契约与上述一致，无漂移。
- 先例：`GCPage.tsx`（doApply 的 useConfirm + 输入 YES 二次确认 + 409 互斥红
  面板 + toast）、`ConfirmDialog.tsx`（confirmDisabled 前置缝、Esc=取消、焦点
  圈）、`ReplicationPage.tsx`（治理组页面纪律）。

## 交付内容

### AC① 启动按钮（MigrationPanel.tsx）

- 「启动迁移」按钮（`btn danger`，testid `migration-start`）渲染条件 =
  面板有数据态（`ok` / error-with-stale）且 `!running`：
  - **仅 admin 可见**：403 → 整面板本就隐藏（§3.6.3 L3，T-160 既有），按钮
    随面板不可达；治理组导航本身 admin-only，端点 200 即 admin 证明。
  - **未配置降级态隐藏**：501 → unconfigured 分支只渲染一句提示，无按钮
    （e2e ③ 补了显式断言）。
  - running 态不渲染（幂等重复启动无意义，状态行已呈现「迁移中」）；已完成
    态保留（重跑只补新缺，语义安全）。
- POST 成功：202 状态体经 `merge()` **即刻并入**本地 phase（不等下一轮 5s
  轮询；hook 新增 merge 出口），toast 成功提示。

### AC② 危险确认对话框

- 复用 `useConfirm`（T-99 基座，零新组件）：`danger: true` 红变体 +
  `confirmDisabled: 输入 YES`（沿 GC apply 的 §3.5 前置缝同款），testid
  `migration-confirm-text`。
- 影响说明按实际迁移语义措辞（四条）：
  1. 触发语义：先盘点（本地盘有、S3 还没有的构成待迁移集）再逐个流式拷贝，
     S3 已有的跳过不重拷（幂等可重跑）；
  2. **双写期间写入放大**：双写装配下每个上传同时落本地盘与 S3（约两份
     写入流量 + S3 请求费用）；
  3. **中断可恢复**：可安全中断/重启后端——重启后重新盘点、只补缺失，
     已拷贝的不重拷；
  4. **完成前不要关闭后端**或改 storage.migration 配置；完成后由运维置
     completed 切 S3 单写；启动请求 202 立即返回、后台执行。
- 409 → 行内红面板（复用 `.gc-error` 样式，testid `migration-start-error`）：
  标题「迁移启动被拒（HTTP 409）」+ 人话解释 + 服务端 message mono 原样
  （§4.10 排障口径）；其它非 2xx 同面板泛化标题。

### AC③ Playwright 三用例（e2e/storage_migration.spec.ts，hermetic mock 沿 T-160）

- ⑥ 确认流程：GET 随 POST 翻转（闭包共享状态）；断言对话框四条影响说明
  在场、未输 YES 时确认钮禁用、输 YES 后 POST 恰 1 次、202 体即刻并入
  （状态转「迁移中」、total=300、running 态按钮退场、成功 toast）。
- ⑦ 取消流程：已输 YES 后点取消——不发 POST（计数 0）、面板保持未开始、
  按钮仍在、无 toast。
- ⑧ 409 冲突态：mock 409 `migration is not enabled` → 行内红面板含「409」
  与服务端 message、按钮保留可重试、无成功 toast。

### AC④ 进度 pct 基数口径修正（T-176 遗留③）

- 修正前：`pct = (migrated + skipped) / total`，而 total 只含待迁移集
  （missing）——skipped 分母不在基数内，skipped>0 时提前触顶（Math.min
  封顶不越界但读数失真）。
- 修正后：`pct = (migrated + failed) / total`——分子分母同基（待迁移集的
  每个 blob 终态非迁移即失败），完成时自然到 100%，永不提前触顶；skipped
  单独一行呈现不计入进度。同步修正「blob 总数」标签 → 「待迁移 blob
  （盘点时）」与面板底部 hint 文案。
- e2e ①② 断言 re-baseline（T-176 日志已预告）：30.0%→**25.0%**、
  55.0%→**50.0%**、97.5%→**92.5%**；⑤ 的 40.0% 不受影响（skipped=0）。
