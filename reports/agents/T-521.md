## ⑭ en-completeness CI 提案（未实施，交付 conductor/devops 裁量）

**问题**：en 缺页静默回退 zh，无构建错误；双语验收门（en 全覆盖）当前无机器保障。

**最小可行方案（ratchet 棘轮模型，优于百分比阈值——单调不回退、无悬崖）**：

1. 脚本 `ci/check-en-coverage.sh`（约 20 行 bash，无新依赖）：

```bash
#!/usr/bin/env bash
# Fails when English page coverage regresses (ratchet, never below baseline).
set -euo pipefail
cd "$(dirname "$0")/.."
zh_list() { (cd fern/pages && find . -name '*.mdx' | sort); }
en_list() { (cd fern/translations/en/pages 2>/dev/null && find . -name '*.mdx' | sort) || true; }
zh=$(zh_list); en=$(en_list)
total=$(grep -c . <<<"$zh" || true)
covered=$(comm -12 <(echo "$zh") <(echo "$en") | grep -c . || true)
baseline=$(cat ci/en-coverage.baseline 2>/dev/null || echo 0)
echo "en coverage: ${covered}/${total} pages"
if [ "$covered" -lt "$baseline" ]; then
  echo "REGRESSION: covered ${covered} < baseline ${baseline}; missing pages:"
  comm -23 <(echo "$zh") <(echo "$en"); exit 1
fi
```

2. 基线文件 `ci/en-coverage.baseline`：初值 `10`（本票落点）。新增 zh 页须同票加 en 页或显式 bump 基线（diff 里可见、评审可拦），删除 en 页则直接红。
3. 接线位置：并入现有 CI 质量闸门链的文档腿（`.github/workflows/ci.yml` / `.circleci/config.yml` 归 devops-engineer 所有——tech-writer 提案，devops 实施接线）。脚本与基线文件本身可由 tech-writer 票落 `ci/`（需 devops 放行 area）。
4. 附带检查（可选，第二期）：`comm -13` 方向同时抓 en 孤儿页（en 有 zh 无——路径镜像破坏时告警）；以及 en docs.yml 导航项与 zh 页集合的标题对齐 lint。
5. 终态：covered == total 时可升级为「缺页即红」的硬门，对齐双语验收门；ratchet 期间不阻塞单语新增。
