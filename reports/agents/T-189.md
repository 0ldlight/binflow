## 一、做了什么

T-165 写 internal/client 时按自述契约编码，T-166 实锤两处对真服务端会挂（假后端按 client 契约应答 → 测试假绿）。本票把解码/编码面全部对齐 internal/httpapi 实际行为，并把测试假后端改成**拷准真服务端行为**，另起真 httpapi 栈做四链交叉验证。

### 1. AC ①：CreateRepo 适配 200 纯文本（repo.go）

真服务端 `handleRepoPut`（repositories.go:374）create 回 `200 text/plain` `Successfully created repository '<key>'\n`，update 拼写（PUT 命中已存在 key / POST，repositories.go:356/412）回 `Repository <key> update successfully.\n`。改造：

- `CreateRepo`/`UpdateRepo` 收敛到新私有 `mutateRepo`：JSON body 照发，响应用 `doRaw` 拿原始字节，**非 JSON 体 = 成功常态**（真服务端永不回 JSON）；返回值改为**请求回显**（纯文本体不含仓字段，文档注明）。
- JSON 兼容臂（AC 允许）：body 首个非空白字节为 `{`/`[`（`looksLikeJSON`，client.go 新增）才尝试 JSON 解码，且解在回显之上——`TestRepoMutationJSONCompatibility` 钉住该臂，默认行为是真服务端形态。
- `DeleteRepo` 本就不解码（out=nil），只需注释补口径。

### 2. AC ②：CreateToken 对齐 access_token/int64 token_id（token.go）

真服务端 `tokenCreateResponse`（security.go:133-138）回 `{"access_token","token_type":"Bearer","expires_in"(0=永不过期时**省略**),"scope","token_id":<int64>}`。改造：

- `TokenCreateResponse` 重写 + 自定义 `UnmarshalJSON`：真形态优先（access_token → `Token`；int64 token_id → 十进制文本 `TokenID`，与 revoke 端点 token_id 形态一致）；**旧拼写 `{"token":…, string token_id}` 作为 decode-only 兼容臂保留**（cmd/bf 的假后端仍是旧形态且不在本票 area，先保其编译与测试绿；刷新后可退役，见遗留①）。
- 删掉真服务端从不回的 `Description`/`IssuedAt` 字段；`Username` 保留但注明真服务端不回显（对真栈恒空）。

### 4. AC ③：测试改造（client_test.go 重写假后端）

四个 CRUD 测试的假后端全部按 internal/httpapi 实际行为重写（措辞、Content-Type、状态码逐一拷贝）：repo 变更回纯文本（含 nosniff 头）、错误回 errors[] 信封、真 404 文案；token 假后端按 `parseTokenCreateRequest` 语义收 JSON/form 两臂、回 int64 token_id、revoke 只认 form + 400 用 OAuth 错误体；user 假后端 201 空体、userDetail 形态、纯文本错误、oldPassword 校验；artifact 假后端嵌套 checksums、list int64 size、上传 201+Location、删除 204。另加 `TestRealResponseSnapshots`：8 个真形态快照用例（token 创建/永不过期、repo list `type`、repo config `rclass`、userDetail、fileInfo 嵌套 checksums、list int64 size）直接对字面 golden body 解码断言。

### 5. AC ④：真栈交叉验证（realstack_test.go 新增）

`TestClientAgainstRealServerStack` 起 cmd 测试先例的轻量真 Deps 栈（sqlite metadata + 真存储引擎 + 真 auth.Service + 真 repo.Service + 真 generic adapter + 真 httpapi，仅 listener 是 httptest），internal/client 四链全过：

- **bootstrap**：Basic 臂（自定义 RoundTripper，cmd/bf 同款组合）走真 wire 给 admin 发 token → access_token/token_id/expires_in/token_type/scope 全部解出。
- **repo 链**：create（纯文本 200）→ GetRepo（repoConfig 解码）→ UpdateRepo（POST 纯文本臂）→ ListRepos（`type`→rclass）。
- **artifact 链**：upload → download 字节一致 → GetArtifactInfo（size string + 嵌套 sha256 与本地 sha256 逐字一致 + mimeType）→ ListArtifacts（int64 size）。
- **user 链**：CreateUser（201 空体）→ GetUser（userDetail）→ ListUsers（admin+ci-user）→ ci-user Basic 改密成功 / 错旧密码 400 真文案。
- **token 链**：admin 替 ci-user 发 token；非 admin 持 token ListRepos 403；**T-190 模型**非 admin CreateTokenForm 为本人发 60s token 成功；admin 按 token_id revoke、按 token 值 revoke 各一次；被吊销 token 再请求 → 401 StatusError。
- 收尾 DeleteArtifact（204）→ DeleteRepo → GetRepo 404。
