## 1. 做了什么

### 1.1 internal/scheduler 新包（纯新包，三文件 + doc 注释）

- **cron.go** — Quartz 六域子集解析器（纯函数零 IO 零 DB）。收：6/7 域（5 域 Unix 形态拒）、
  `*`/`?`/`,`/`-`/`/`（含裸 `/N`——出厂 GC 模板 `0 0 /4 * * ?` 直证，C-d）、月名 JAN–DEC/
  周名 SUN–SAT 大小写不敏感（1=SUN）、`L`（dom 月末）与 `nL`（dow 该月最后周几）、
  年域 1970–2099（见 §3 软缝对齐）。拒：`W`/`#`/`LW`/`L-<offset>`、混合名-数区间、
  dow 数字 0、闭集外任意字符、双具体日域、双 `?`——**每个拒绝 message 点名形态**。
  长度门 = `MaxExprLen` 256（引擎内部常量，零新配置键）。day-of-month/day-of-week
  互斥：恰其一为 `?`（双具体值/双 `?` 均拒）。
- **next.go** — `Next(expr, after)` / `(*Parsed).Next(after)` 纯函数计算器：UTC、秒分辨率、
  **严格晚于 after**（同秒触发不计入，锚 §4.1）、确定性（同输入同输出——TestNextRunDeterministic
  固化）。逐域级联推进（年→月→日→时→分→秒），最稀疏形态（2 月 29 日，跨 2 年+）有界步数收敛。
  年域视界 2099 外 → `ErrUnreachable`。PUT 期校验 `ValidateExpr(expr, now)`（Parse+Next 必须出值）
  与过去时间拒配 `CheckNextRunAt(at, now)`（`ErrPastNextRun`，备份面 nextBackupTime 可写位的
  引擎侧守卫——T-450 REST 面直接消费）。
- **scheduler.go** — `Run(ctx)` 独立 1min ticker（`DefaultTickInterval` 内部常量，测试可注入）
  + 启动坍缩扫（boot 扫过期行每行补一枪，next 自 now 重算）+ `Kick(ctx, domain, key)` 手动
  触发等价缝（与到点同一 dispatch 路径——队列入 loop，绝不旁路并发）。域注册面
  `Register(domain, Runner)`——域闭集 = 代码常量（maintenance|backup|replication），未知域/
  重复注册/nil runner → 装配期 error。`Runner` 接口 = ADR 决策 6 原文（同一载体幂等收敛，
  scheduler 永不建第二执行器）。audit facet = `AuditSink`（replication 引擎同形，best-effort）
  + metrics facet = 共享 `metrics.Registry` 上两族
  `binflow_scheduler_fires_total{domain}` / `binflow_scheduler_failures_total{domain}`
  （webhook dispatcher 同款：引擎自注册，nil = 不计量）。

### 1.2 防护三面（AC2，ADR 决策 9）

1. **解析期**：闭集校验（`ErrInvalidExpr`，message 点名形态——零注入：纯字符串→结构体，
   无 eval 无拼接）+ `ValidateExpr` 不可达拒配 + `CheckNextRunAt` 过去时间拒配。
2. **运行期——每域并发 1**：dispatch 单循环串行（域内串行的最强形——结构性保证，
   TestSchedulerPerDomainConcurrencyIsOne 以 max-in-flight 探针固化）。
3. **运行期——错过窗坍缩**：due 谓词 `next_run <= now`，每 fire 后 next 自 now 重算——
   多窗过期只补一枪（TestSchedulerMissedWindowsCollapseToOneFire：3 窗过期 + 数 tick 后
   fires == 1）。
4. **运行期——时钟回拨**：`now < last_run` 的行跳过 + WARN + 自 now 重排（不重复触发，
   TestSchedulerClockRollbackSkipsAndRearms）。
5. 附带两个诚实性守卫（测试固化）：运行中配置变更不被写回碾压（runOne 跑完**重读行**，
   next 从**新**表达式重算——TestSchedulerMidRunConfigEditSurvivesWriteBack）；
   shutdown 中止（ctx canceled）不落 run state、行保持 due 由下次启动坍缩补一枪
   （TestSchedulerShutdownAbortLeavesRowUntouched）；无 runner 的域 WARN+重排不 fire
   （增量注册姿势，TestSchedulerUnregisteredDomainRearmsWithoutFiring）。

## 2. 与事件驱动并存（AC2 票内声明——断言反转⑦边界）

声明固化在 `internal/scheduler/scheduler.go` 包注释（结构性保证 = import 边）：

- 调度**只触发全量类任务闭集**：scheduler 只 call 注册的 Runner，不 import repo 内容写路径、
  不 import webhook Bus——增量推送仍是事件驱动引擎唯一领地。
- 复制全量 = T-450 注册 `TriggerFullSync` 同载体（种子行+wake，零第二执行器零新队列）。
- **零重复投递 = 内容层口径**：任务层允许同窗并存（全量种子行 + 事件增量行——
  TriggerFullSync「重复触发不合并」既有豁免），内容层零重复（目标侧 sha256 幂等命中，
  blob 已在即不传字节）。调度窗内增量事件不抑制不互斥——双轨各走，收敛交给幂等。
