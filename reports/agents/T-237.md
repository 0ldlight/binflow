## 1. 交付内容

### 1.1 用户列表（/admin/security/users）

- 列集对齐 console-m8 §6.9：**Name │ Email │ Groups │ Role**。Groups 列 = 「计数 badge | 组名 chips」（Artifactory `1 | readers` 形态）+ title 悬浮明细；Role 列三值 badge（admin=role-warning / readonly_admin=neutral / user=neutral——§6.9[1]「Role 列承载三值 badge」，比旧版 plain `—` 更贴规格）。Realm/Last Login/Admin 布尔列不建（§6.9[1]）。**Status 列不建——契约漂移①**（无 enabled 回显，无数据不伪造）。
- **列头排序**（§3.3 C1 / §4.7）：Name/Email/Groups/Role 四列，点击循环 asc → desc → none，`aria-sort` 三态同步，热区 = 整格 th（内部 button 承载键盘，click 冒泡不双发）。默认 Name asc。
- 底部计数行 `用户总数： N`（§6.9）。
- 取数：列表（简形态）+ 逐用户详情**链式并发**（email/角色/组员在详情端点——T-101 事实），行级失败降级 `—` 不伪造。
- 「New User」Quick 入口衔接：T-235 的用户菜单「新建用户」落本页，`＋ 新建用户` 为页头主按钮（路由表冻结无 /new 路由，列表页 + 主按钮是诚实等价——范围注记）。

### 1.2 新建用户（页内分区表单）

- 分区形态（C8）：**用户设置**（用户名* blur 校验 / Email* / 角色三值下拉）/ **选项**（□ 启用）/ **口令**（初始口令*）/ **相关组**（双列穿梭）。
- 必填未满足主按钮**禁用**（reverse §4.6 Save 置灰形态）；必填空文案「请填写此字段」语义；服务端 400 原文行内（`user-form-error`）。
- 底部 `取消 / 重置 / 创建用户`。
- 创建体：角色走**一致对** `admin: role==='admin'` + `adminRole: role`（服务端 resolveCreateRole 的对一致性校验要求，非「混发」；编辑臂仍只走 adminRole）；`enabled` 显式携带（T-208 seam）。

### 1.3 用户编辑器（/admin/security/users/:name）

- 分区：**用户设置**（用户名锁定 mono+拷贝 / Email / 角色下拉——M7 §7.1，wire 三值即选项值，变更落 `user.role.change` 审计）/ **选项**（□ 启用）/ **口令 + 确认口令**（编辑态留空 = 不改；不一致挡提交）/ **相关组穿梭** / 底部 `取消 / 重置 / 保存`。
- **enabled 翻转姿势（T-224 非缺陷②收口验证）**：表单全量提交形态——保存体**总是携带 enabled**（POST 部分更新臂指针语义：携带即写入），天然满足 PUT replace 语义注记。读侧无回显（漂移①）→ `knownEnabled` 本地回显：本页写过的值即已知值，未写过按「建号即启用」假设；带外变更不可见（hint 明示）。e2e 实证往返：禁用 → 登录 401 行内错误；重新启用 → 同口令可登录（§5）。
- **双列穿梭（C5）**：Available N / Selected N + 空侧「未选择项」；条目 = checkbox（勾选移右 / 取消移回），键盘 Tab+Space 天然可达，**沿用 T-101 冻结锚 `user-form-group-<name>`**（视图内唯一，跨列迁移不改锚）。
- **用户权限矩阵**（§6.9[5]）：只读汇总表 = Permission Name（mono 链接进权限编辑器）│ 应用途径（直接 / 经组 badge）│ read/write/delete/manage 四列；manage 列头 tooltip「manage = 仓库配置派生权（不隐含读写删）」（§7.2）；来源 = `listPermissionTargets` 前端折叠（`grantsOfUser`，直接行 + 经组行并集）；无授权 = 空态文案。Builds/Release Bundles Tab 不建。
- 账户信息卡（`user-facts` / `user-facts-role` 锚原样）保留 realm/角色/最近登录/API URI；删除用户说明改为指向禁用（无 DELETE 端点，漂移②）。

### 1.4 组管理（/admin/security/groups）

- 列表：**组名（+描述副行）│ 权限数（+ manage 徽章）│ 成员数**（§6.10 列集 + 描述副行信息密度）；列头排序（name/perms/members）；底部计数行；行内 编辑/删除（admin）。
- **adminPrivileges 徽章**：BinFlow 组模型无该布尔（rbac-model §5 有意不跟进）；徽章呈现「组在至少一个 target 上持有 **manage**」——manage（ADR-0026 仓库配置派生权）是最小诚实同构，title 说明差异，数据源 = permission targets（零新端点）。
- 编辑器同形态分区：**组设置**（组名 create 态校验/edit 态锁定 / 描述）/ **成员穿梭**（Available=全部用户 / Selected=成员；创建态即可选，PUT 建组后落盘）/ **组权限矩阵**（编辑态，四动作列）/ `取消 / 重置 / 保存|创建组`。
- 成员写路径：逐用户部分更新臂（`POST /security/users/{u}` groups 全量替换该用户组集）；部分失败 = 行内名单 + 「组本体已保存」说明（不静默）。
- **删除守卫文案对齐 §4.6**：标题 + 「确定要移除该组吗？此操作不可撤销。」 + （N>0 时）「将解除 N 个成员的关联」 + 409 预告；409 冲突面板（`group-delete-reason`）与 target 名解析链接原样（链接直达新路由）。
- 成员数据：无按组查询端点（漂移③）→ `listUsers` + 逐用户 `getUser` 汇总（N+1，T-99 先例；行级失败降级）。

## 3. 契约漂移登记（conductor → architect 回写）

1. **GET /api/security/users[/{name}] 无 `enabled` 回显**（T-208 只落写侧 *bool）。后果：§6.9 Status 列不可实现；编辑器启用位「默认启用 + 本页写过即已知」，带外禁用不可见。建议 userDetail 增补 echo。
2. **无 DELETE /api/security/users/{name}**：§6.9 Actions→删除用户与 §4.6 用户删除文案不建（既有登记：SE 域仅 GET/PUT/POST；契约冻结）。
3. **组无按组成员查询端点**（GET group 仅 {name,uri,description}；Artifactory `?includeUsers=true` 无对应）：成员数/穿梭 = 用户侧 N+1 汇总。
4. **组无 adminPrivileges 字段**：有意不跟进（rbac-model §5）；UI 以 manage 持有徽章同构。
