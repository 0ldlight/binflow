## 做了什么

1. **internal/config/binstore.go（新，解析器与并存裁决）**：
   - **发现（决策 1）**：`binstore.yaml` = 与已解析生效的主配置文件同目录（`loadBinstoreNextTo`）；
     无主配置 boot（defaults+env 腿）经 `ApplyBinstoreForDefaultBoot` 走 `./binstore.yaml → $BINFLOW_HOME/binstore.yaml`
     （镜像主配置解析序）。文件缺席 = 零行为变化。
   - **schema（决策 2）**：`version`（缺席=1，出现必须为 1）/`chain`（有序 provider 链）/`migration`（链级 mode）。
     type 闭集 filestore|s3；保留名 cache-fs/azure/gs 拒启文案点名「保留 slot 未实现」；
     链形校验：各至多一次、合法序 [filestore]/[s3]/[filestore,s3]；migration 块仅双员链合法且必填
     （filestore+s3 无迁移意图 = cache-fs 语义，本 build 不存在该形态）；mode 闭集 bypass|dual-write|completed；
     s3 参数族与内嵌 storage.s3 键名逐字平移。未知键/重复键/类型错一律拒启，错误含**绝对路径+行号+键名**
     （yaml.Node 手工遍历取 Line；语法错由 yaml 库自带行号）。
   - **凭据纪律（决策 4）**：全文件递归 secret 扫描（任意深度、含 provider 子树），`secret_access_key`/secret 形键
     → 拒启 + 行号 + env 逃生口（`BINFLOW_STORAGE_S3_SECRET_ACCESS_KEY`）；secret env **恒**注入生效链的 S3 provider。
     文件权限宽于 0600 → WARN（非拒启；Windows 跳过）。
   - **三分支（决策 5）**：以链键（backend/s3/migration）为判定对象，`chainView` 归一化后**语义比较**（非文本比较）：
     ①无文件+链键显式（YAML 或 env）→ 照常起 + 每启 WARN；②文件在+内嵌链键缺席→静默、文件生效；
     ③等价→文件生效+WARN；**分歧→拒启**，错误指明两处来源文件与分歧键。
     归一化口径：`migration.enabled && !completed` 无条件归一为 dual-write（决策 3 映射）——内嵌 disk+enabled
     的组合若与 binstore dual-write 等价则 WARN+文件生效，否则分歧拒启；`completed` 与纯 backend=s3 互为等价
     （决策 3「终态等价形态」）；bypass 归一为仅 filestore 装配（与纯 disk 等价，S3 参数为前置声明不参与比较）。
   - **env 覆盖（决策 6）**：binstore 生效时链相关 env 键（backend/s3.*/migration.*，不含 secret）忽略+WARN
     （`buildOpts.skipChainEnv` 贯穿 applyEnv）；secret env 恒生效。
2. **internal/config/{api,load}.go**：`Config.StartupWarnings []string`（loader 不打日志，cmd 统一经真实 logger 输出）
   + `StorageConfig.Chain StorageChain`（providers/mode/source——决策 7 的链形态自描述标签）。
   `Load` 重构为 decode → binstore 三分支裁决 → build（跳过链 env）→ overlay → **再 Validate**
   （binstore 声明的 [s3] 缺参数与内嵌拼写同形拒启）。`secretEnvHint` 从 secretYAMLErr 抽出共用。
3. **cmd 存储 wire**：`openStorageEngine` 零改动（装配消费归一化后的 cfg.Storage——「装配入口改读 binstore」
   经 config 层归一实现，REST/备份恢复/gc 全部同源零变化）；runServe 增加
   `storage chain resolved` INFO（provider 序+mode+来源，凭据结构性缺席）+ StartupWarnings WARN 输出；
   gc/backup export/import 三子命令输出 warning；无主配置 boot 腿接 `ApplyBinstoreForDefaultBoot`。

## 差异登记（报不自裁）

   但 binstore 加载失败发生在 config.Load——先于 metadata/audit 平面构建（openStack 内），启动拒绝路径上无处落审计行。
   fail-fast 错误文本（路径+行）即失败腿信号。若需审计事件须在 openStack 之后补记成功腿/换载体，属新裁决面。
2. **`version` 键可选**（缺席=1）：决策 7 拒启清单未列「缺 version」，按未列不拒处理。
3. **显式默认值的内嵌链键参与分歧判定**：`backend: disk`（显式拼写默认值）+ binstore [s3] → 分歧拒启
   （非静默吞并）——依据决策 5 理由「独立文件优先只吞并等价遗留、不吞并分歧」；「全默认」静默（分支②）
   仅指完全未声明链键。分支②/③的边界以此口径落测试。
4. **embedded `disk + migration.enabled` 的意图归一**：归一为 dual-write（决策 3 对 migration.enabled 无条件映射）；
   与 binstore dual-write 等价则 WARN+文件生效（该内嵌组合单独存在时今天会被 openStorageEngine 拒启——
   binstore 等价形态反而修复了 boot），不等价则分歧拒启。

   `ensureDataDir` 三行 → 按仓库 T-26 先例行级 `//nolint:gosec` 带理由（.golangci.yml 未动）；
   binstore ReadFile 的 G304 同理（路径级排除只覆盖 load.go）。
