### 架构决策

- **T-130 K2 最终裁决**：distroless 基础镜像为 `gcr.io/distroless/static-debian13:nonroot`（debian13，非 debian12），alpine 基础镜像为 `alpine:3.24`
- **自包含构建**：console (SPA) 和 docs (Docusaurus) 在容器内从源码构建，不依赖 builder 本地 checkout 状态（T-106 先例）
- **Docusaurus 路径修复**：`docs-site/docusaurus.config.js` 引用 `path: '../docs/user'`，Docker 构建时需要 `COPY docs/ /docs/` 使 Docusaurus 能解析内容树
- **distroless 无 shell**：HEALTHCHECK 使用自建 Go 二进制 `healthcheck-probe` 替代 wget；数据目录通过 `datadir` 中间 stage 预创建并设置 nonroot 权限
- **healthcheck-probe 构建**：Go 1.26 模块模式要求 go.mod，通过 heredoc 内联创建 `module healthcheck-probe` + `go 1.26`
- **多架构**：通过 `docker buildx build --platform linux/amd64,linux/arm64` 构建，需 QEMU 模拟。本地环境（darwin/arm64）用 docker driver 构建 amd64 单平台；CI 可用 container driver 构建多平台

## 遗留问题

- **多架构 arm64 本地验证**：当前环境为 darwin/arm64，docker driver 不支持多平台同时构建。需 QEMU + container driver 或 CI 验证 arm64。Dockerfile 已正确声明多平台构建指令。
- **真发布推送**：不在本票范围内（Q1/DoD 7 由 conductor + 用户确认后执行）。`build-release.sh` 仅做本地 tag，不推送。
- **imagetools inspect**：使用 docker driver 的 `--load` 模式时，镜像仅在本地，imagetools inspect 会尝试访问 Docker Hub 而超时。这是预期行为，CI 中使用 container driver 时 inspect 可正常工作。
