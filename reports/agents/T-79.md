## 三处落点（DECISIONS.md，均为追加勘误注，决策本体未删改）

### 1. ADR-0012 勘误一（remote 故障降级语义，PRD 为准）

决策 2「无副本 → 502 spec 信封」**作废**，追加勘误括号注：
- 上游 5xx/超时/连接失败 → 仓标记 **assumed-offline**（静默 `assumedOfflinePeriodSecs` 默认 300s，期内零上游流量——同时修正本 ADR「不自动熔断」表述，静默期即轻量熔断）；
- 有缓存（**含过期**）→ 服务缓存 + **`X-Binflow-Upstream-Error`** 头（取代原 `Warning: 111` 方案）；
- 无缓存 → **404**（E-01，message 含 offline/assumed offline 状态）；仅 `hardFail: true`（默认 false）→ 502；
- 补 PRD 负缓存定案：上游 404 → 写负缓存 + 有过期副本仍回发（"expired but serving"）。

### 2. ADR-0013 联动记录段（virtual 语义，触发本 ADR 自带的 PM 联动条款）

- **① 解析顺序升级两桶序**（PRD C3/FR-21-AC7）：Artifactory 四桶 → BinFlow 两桶简化（优先桶 = `priorityResolution:true` 成员按声明序在前，其余成员桶内声明序在后）；「跨类排序 local<remote 固定」作废，`position` 语义修订为「桶内声明序」；**stale 命中即成员结果**（remote 命中 stale 含过期副本即返回、不跳下一成员），仅真正 404（负缓存/无副本/offline 无缓存）继续桶序。决策骨架（成员序、首命中即返、只读默认）不变。
- **② 写路由边界升级**（PRD FR-21-AC4，P1）：`defaultDeploymentRepo`（别名 `defaultDeploymentRepoRef`/`deploymentRepository`）配置后 virtual 可写（路由到该 local 成员，权限/覆盖/checksum 链按目标仓语义，virtual GET 立即可见）；未配 → 405 + 定案文案；指向非 local 成员 → 400 建仓校验；npm publish/PyPI upload 同走路由。
