## 做了什么

1. **E9 seam（`auth.ManageCoverage`，internal/auth/rbac.go）**：签名按 §14.1.9 逐字 `(map[string]struct{}, bool)`——布尔 = **全域哨兵**（admin 的 m 由角色 bypass 覆盖一切现存与未来仓，无可枚举集，map 为 nil + bool true；非全域恒返回可用（非 nil）集合）。求值 = EffectiveRole 同族并集：遍历全部 target，凡 target 携带 `can_manage` 行且该行覆盖 principal（自身 user 行大小写不敏感 / `Principal.Groups` 组行，SE-07 并集）→ 并入该 target 全部 repos（includes/excludes 永不参与，ADR-0026 decision 3）。readonly_admin = 空集非全域（该角色 Can(m) 恒 false，与 CanManageRepo 写臂拒绝同构）；nil principal = 空 deny。**失败姿态镜像 Can**：rows/targets 查询失败、repos 列 JSON 损坏（跳过该 target）、permission source 缺 rows facet（老 fake）——一律 log + 空集 deny（坏权限表永不放宽访问）。O(targets+rows) 两次 store 读，缓存留缝不实现（§14.1.9 预算）。
2. **metadata 单趟缝（选型论证）**：`PermissionStore` 接口 additive 新增 `Principals(ctx)`——全部 target 的全部 principal 行**单查询**返回（与 PrincipalsFor 同 JOIN/同排序，孤儿行防御性排除）。论证：覆盖集求值手里没有 repo 键，既有两缝只有「逐 distinct repo 调 PrincipalsFor」（查询数随仓数 N+1）或「逐 target 调 GetTarget」（随 target 数 N+1）——两者正是任务点名的 N+1 闸禁面，故落第三缝；auth 在内存判定主体覆盖（沿「store 出行、auth 判定」的既有分工，PrincipalsFor 文档明言 patterns 在内存求值）。零迁移、零新配置键。
3. **auth 侧接线**：`permissionStoreAdapter` 增 `Principals`（行类型换算）；auth 包内消费侧可选 facet `coverageRowsSource`（类型断言发现，与 session/permission-view/ManagementAuthorizer 同模式）——`permissionSource` 接口本体零加宽，`failclosed_test.go` 的 `failingPerms` 等既有 fake 零改动照常编译（T-253 接口加宽教训的反向应用）。
4. **E6 端点（internal/httpapi/permissions.go + router.go）**：
   - **路由分裂即全部路由面改动**：GET `v1/permissions` 在 dispatch 处按「携非空（trim 后）filter 值」分裂——非空 → `routeAuth{required:true}` + `handlePermissionListManage`（门在 handler 判，族 4 写臂同款模式，ADR-0030 E6 行「filter 分支 handler 判」）；无/空 filter → **原路由原 handler 逐字冻结**（`required+CapSecurityRead`）。`?filter=`（空 ask）按 T-253 可选参数惯例 = 无 ask，走冻结路由（所有调用者行为与无 filter 完全一致）。
   - **filter 分支三臂**：CapSecurityRead（admin/readonly_admin）→ 全量，与无 filter 响应**逐字节相等**（同一 writeJSONBody + 共享行构造 `permissionBodyOf`，测试 cmp 钉死）；普通用户且覆盖集非空 → 仅 `repos ⊆ 覆盖集` 的 target 子集（**条目字段与全量列表一致**——name/repos/patterns/principals 全渲染，§14.1.6 原文，编辑器注水面所需）；覆盖集为空 → 403 与无 filter 路由门**同形同字节**（同一 `writeError(403, "administrator privileges required")`，零新增可区分面）。部分覆盖 target 隐藏（t-part 腿钉死）；空 repos 的手工行按「非空认证」拒绝渲染（写臂同构，vacuous-subset 读法会展示不可编辑 target）。**未知 filter 值 → 400 errors[] 信封**（`filter must be "manage" (unknown filter value: "bogus")`，沿 T-253 ?include 消息形态与 trim 容忍、大小写敏感拒绝）。信息隔离（NFR-S49）：覆盖集外 target 的名称/仓/pattern/principal 不出现在响应任何位置（负向 grep 钉死）。
   - **渲染单趟**：`writePermissionTargets` = ListTargets + Principals 两次查询 + 内存按 target 分桶（JSON map 键序由 encoding/json 排序保证，与冻结路径 GetTarget 行序无耦合）；**冻结无 filter 路径保留其历史 GetTarget-per-target 查询形态**（行为冻结的最小改动读法，其 N+1 属既有行为非本票回归面，N+1 闸测试将其作为对照腿记录 `[1 0 0 N]`）。
5. **族 4 写臂收敛（§14.1.9「共用单决策点」落地）**：`canManageAllRepos` 从「逐 repo `CanManageRepo(write=true)`」改为一次 `manageCoverageOf`（消费侧 facet `manageCoverageAuthorizer` + fail-closed 解析器，镜像 `managementAllowed` 姿态）+ 子集判定。行为等价性：user 侧覆盖集 ≡ {r : Can(r,"m")}（`TestT254ManageCoverageMatchesCan` 逐格钉死）；admin 走哨兵（原逐 repo true）；readonly_admin 空集 deny（原写臂 false）；store 错误 deny→同 403。副作用收益：写臂覆盖判定从 2N 次查询（每 repo PrincipalsFor+ListTargets）降为 2 次常数。
6. **测试**（全部新增，表驱动 + 字节级 + N+1 闸 + 真实栈）：
   - `internal/auth/t254_manage_coverage_test.go`：角色/并集形态 11 例表（nil/admin×2 拼法/readonly/direct m/大小写/组 m/组 m+direct 并/组 read 不授予/他人 user 行/组名 user 行 type-keyed）；**Can≡coverage 等价格**；fail-closed 四态（rows 错/targets 错/坏 JSON 仅跳过自身/facet 缺失）+ 活体对照。
   - `internal/metadata/t254_principals_store_test.go`：空表/排序/旗标 + **Principals 与 GetTarget 逐 target 行集一致**（两渲染面不漂移的 store 级锚）。
   - `internal/httpapi/t254_manage_filter_test.go`：角色矩阵（admin/readonly 全量字节等 + direct/组/部分重叠 m-holder 子集 + 空 403 双分支字节等 + anonymous 双分支 401+Basic 挑战）；**无 filter 字节级快照**（golden 字面量，先以探针测试在改动前抓取现网字节、改后 diff 逐字节一致再固化——见下「自测」第 7 条）；seed-m9 u9 腿 fixture 级复刻（t-in 在列字段完整、t-out/t-grp/t-part/t-u8r 与越界仓键/主体名 13 项负向 grep 零泄露）；参数边（空值=无 ask 双角色/空白 trim/`MANAGE`·`read`·重复参数 400/400 先于数据面且不泄露 target 名）；**N+1 闸**（计数装饰器：m-holder filter GET 恒 `[ListTargets=2, Principals=2, PrincipalsFor=0, GetTarget=0]`，5→10 target 计数不变 = K 无关性；admin 臂 `[1,1,0,0]`；冻结无 filter 臂 `[1,0,0,10]` 对照）；**写臂单次求值**（3 repos 覆盖 POST = 201 且 PrincipalsFor=0/Principals=1；越界 POST 403 文案逐字含 manage coverage 且先于未知仓校验）。
7. **m-holder 可达性腿（T-259 服务端前提）**：真实栈 u9 **session cookie**（POST /api/v1/session → binflow_session）GET `?filter=manage` = **200** 且 body = [t-in]——cookie 臂与 Basic 臂判定等价（Principal.ViaSession 不参与授权面），控制台直链的服务端前提已具备，记录给 T-259 消费。

## 口径差处理（conductor 派单 vs 权威契约）

- **派单行文「name+轻量形态 / admin 带 filter = 全量 name 轻量（无 principals）」与权威契约冲突**：派单明示「权威契约 = ADR-0030 + architecture §14.1 E9/E6」，而 §14.1.6 原文「条目字段与全量列表一致」+「CapSecurityRead → 全量（与无 filter 响应等价）」、PRD FR-79.2 同文且「wire 细节与 ADR 冲突时以 ADR 为准」、AC4「字段完整」——**按权威契约实现全字段形态**（编辑器注水面 = E6 + 主体名手动录入，§14.1.6；v2 的 name+uri 是「非 admin 可见性」参照而非字段集契约）。真实栈以 cmp 钉死 admin 两形态字节等。若 conductor 复核仍要轻量形态，属契约变更（需先改 §14.1.6/PRD），非本票实现偏移。
- **派单签名 `([]string, error)` vs §14.1.9 `(map[string]struct{}, bool)`**：派单自身括注「admin 返回哨兵全量形态或 nil+bool，按 §14.1」即指向后者——按 §14.1.9 落地；error 位被「失败=空集 deny（Can 姿态）」吸收，E6 空集 403 与坏 store 403 同形（fail-closed，不泄露、不翻转）。
- N+1 闸读法：覆盖集求值与 filter 分支列表渲染**常数趟**（4 次查询，K 无关）；冻结无 filter 路径保留其既有 GetTarget-per-target 查询形态（字节冻结优先；其收敛非本票 AC，候选登记见下）。
