## 二、K1 终裁（ADR-0011 增补①~⑤，勘误式追加）

**决策方向：交付形态（embed 主交付 + 独立 tar 可选）与工作流细则不变；四项构建细节定案 + 一项暂行修正。**

1. **搜索索引 = 外挂本地全文 `@easyops-cn/docusaurus-search-local` + nodejieba（zh 分词）**。候选对比：内建索引（只搜元数据——G18 不可达，否决）/ 外挂本地全文（选中）/ Algolia 类外网服务（违反 NFR-S29 零外网断言，结构性排除）。索引 build 期生成静态文件随 embed 走、浏览器本地检索。nodejieba 是原生 addon，**仅存在 docs-site node 构建链**——不进 Go 二进制、不进运行时镜像（ADR-0005 构建链/运行时隔离）。
2. **self-host 资产落盘 = build 产物原样进 internal/docs/dist，零后处理**：Docusaurus 默认全量打包，baseUrl `/binflow/docs/` 原生前缀化——console 的 relink-assets 手法不需要（T-126 预判定案）。红线：零外链组件；G18 route-abort 是常设验证面。
3. **版本化 = v1.x 目录（Q4）+ `lastVersion` 单版本期默认路径无版本段**；`defaultLocale: zh` 唯一。v2 出现时再裁决默认版本切换。
4. **fallback 触发线四步定案**：(a) docs-size 归因 → (b) 内容减重优先（内容票路径，不算 fallback）→ (c) 减重后仍 >15MB：dist 置占位、二进制重建、docs-static tar 升格唯一渠道，**触发与解除均须用户确认**（Q1 联动）→ (d) 总量超 40MB 而 docs ≤15MB 不触发本 fallback（归因另案）。
5. **docs-static tar = 同一 build 产物原样**（tar 根即站点根、无嵌套；不二次构建）；Release 附 sha256；自托管说明归 T-141。

## 三、K2 终裁（ADR-0017 新增——不并入 ADR-0004：供应链细节有独立生命周期，0004 是用户定基线只细化不混写）

1. **ghcr.io 命名空间 = `ghcr.io/lzwzzy/binflow`**（与 module path github.com/lzwzzy/binflow 同源）；**单镜像名 + 变体 tag**（vs 双镜像名：少两处仓库/权限/文档维护面）。
2. **tag 家族**：`v1.0.0`（→distroless，PB-03 暂行转正）/ `v1.0.0-alpine` / `v1.0.0-distroless` / `latest`（→最新版 distroless）。**GA 不发 dev/edge 滚动 tag**——滚动自动推送与 Q1「逐项用户确认 + 凭证用户注入不入 CI」结构性冲突。
3. **基镜像锚定**：`gcr.io/distroless/static-debian13:nonroot` + `alpine:3.24`（禁 latest），锚定粒度 = 发行系 tag（每次发布重拉吸收 CVE patch），**发布清单记录当次解析 digest**（可复现性记录项，NFR-S27）；digest 钉死被否（手工发布模型下只有摩擦与遗忘风险）。
4. **SBOM = GA 携带 syft 最小面**（每变体一份 SPDX JSON 作 GitHub Release 附件；不接 ghcr attestation、不进推送管道——Q1 流程不变；syft 按ADR-0005 准入记录、不入 go.mod）。**签名 = M6+（结构性理由）**：keyless cosign 依赖 GitHub Actions OIDC 身份，与 Q1「推送非 CI 驱动」直接冲突；自持密钥引入长期私钥保管义务，违背 M5 零密钥姿态（gitleaks 零命中）；无公钥策略与验证指引的签名不构成安全承诺。M6+ 发布链 CI 化时 keyless + SLSA provenance + helm provenance 一并评估（新 ADR）。
5. **Chart 仓库 = GitHub Pages 经典 helm repo**（`https://lzwzzy.github.io/binflow/charts/`，index.yaml + tgz；Q1 首选转正）。vs OCI：消费零凭据零版本门槛（helm 3.0+；OCI 要 ≥3.8 且 helm search 不覆盖）、渠道家族同质（公共 Web 静态面）、发布面吻合手工确认模型、离线包已含 tgz。OCI chart 不排除 M6+ 增补，GA 不双轨。

**主线逻辑**：供应链各面让「CVE 新鲜度 + 材质可审计」先行，「逐字节复现 + 签名信任链」记录化或后置——后者在手工发布模型下要么不可用要么是义务；渠道全部收敛「公共 Web 静态面 + 手工可确认推送」，与 Q1 零张力。**R7 安全底线不变：本 ADR 只定「推什么、推到哪」，不改「谁推、凭何确认」。**

## 四、§7.1 两行补遗（architecture.md，§6.4 #6 收口）

事实源 = 本仓实现（非逆向），两处均「实现早于文档」的表漏列：
