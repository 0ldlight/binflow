## 一、缺陷回顾（依据）

T-167 遗留①：client 的建仓请求体三字段拼写与真服务端解码面不匹配——
`members`/`includes`/`excludes` vs internal/httpapi `repoConfig` 识别的
`repositories`/`includesPattern`/`excludesPattern`。本票先读
`internal/httpapi/repositories.go` 的请求结构体逐字段核实（AC ① "以实现为准"）：

| client 旧 tag | httpapi repoConfig tag | 丢失路径 |
|---|---|---|
| `members` | `repositories`（[]string，virtual 臂） | configJSON virtual 臂收不到成员 → config 为空 → repo.Service `parseVirtualConfig` 拒绝空成员表 → **400（响亮失败，非静默）** |
| `includes` | `includesPattern`（local 臂） | local config 透传不含该键 → **静默丢弃** |
| `excludes` | `excludesPattern`（local 臂） | 同上 |

修正 T-167 报告的一处措辞：virtual 丢成员在当前服务端是 **400 拒绝**（T-64 起成员表必填），不是"静默建出空 virtual"；patterns 丢确实是静默的。realstack 负面用例（下文）钉住了这个 400。

## 二、变更

### internal/client/repo.go（本票核心，AC ①）

- `RepoCreateRequest` 三字段 **json tag 对齐真服务端**：`Members → "repositories"`、`Includes → "includesPattern"`、`Excludes → "excludesPattern"`。**Go 字段名不动**（Members/Includes/Excludes）——internal/migrate 与 cmd/bf 的调用面零改动，只有 tag 过线（T-167 预言的"tag 对齐即全量生效"成立）。
- `RepoInfo`（读回面，服务 AC ③）：tag 同步改为真拼写；新增 **`configuration` 回显折叠**——真 GET 体（`repoConfigOf`）把存储的 canonical config 嵌在 `configuration` 键下（virtual 是 `{"repositories":[...]}`，local 是透传的 patterns map），顶层从不携带这三字段。`UnmarshalJSON` 将其折叠进平铺字段（顶层拼写优先），与 T-189 给 `ArtifactInfo` 折叠嵌套 checksums 是同一动作。没有这一步，"GET 回读一致"在真栈上不可能成立。
- `mutateRepo` 回显逻辑无改动（字段名未变）。

### internal/client/doc.go

新增 Request-shape policy（T-191）段：编码面与解码面同一规则——请求体携带 httpapi 实际解码的拼写。

### internal/client/client_test.go（AC ②）

- repo 假后端重写为按 **真 httpapi 请求 tag** 解码（新 `realRepoPutBody`：`repositories`/`includesPattern`/`excludesPattern`）；PUT/POST 合并为一个 handler（沿用 handleRepoPut/Post 的回退语义：class/packageType 缺省取存量行）。
- GET single 按 `repoConfigOf` 形态把 canonical config 嵌进 `configuration` 回显。
- 新增两个子用例断言**线上字节**（map 级）：virtual 建仓体带 `repositories` 且**无** `members` 键；local 建仓体带 `includesPattern`/`excludesPattern` 且无 `includes`/`excludes` 键；并各接一段 GetRepo 折叠回读断言。
- `TestRealResponseSnapshots` 新增 3 个 golden：virtual GET 体（嵌套成员）、local GET 体（嵌套 patterns）、**建仓请求体的字节级 pin**（`{"key":...,"rclass":"virtual","packageType":"generic","repositories":[...]}` 逐字节相等）。

### internal/client/realstack_test.go（AC ③）

- bootstrap 收敛为 `bootstrapAdminToken` helper（原内联块平移，断言原样保留）。
- 新增 `TestRepoConfigEncodeRoundTripRealStack`：真 httpapi 栈（sqlite metadata + 真存储 + 真 auth/repo.Service + 真 httpapi）上——
  1. 建 local 成员仓（带 `**/*.jar;**/*.war` / `internal/**` patterns）+ 第二 local 成员；
  2. 经 client 建 virtual（Members 两成员）；
  3. `GetRepo(virtual)`：成员**含顺序**逐值回读一致（走 canonical virtualConfig 存储 + configuration 回显 + 折叠解码全链）；
  4. `GetRepo(local)`：patterns 逐值回读一致（透传 config 全链）；
  5. **负面证据**：裸 HTTP 用旧拼写 `{"...","members":[...]}` 打真服务端 → **400**（服务端从不读 `members`，成员表空被 repo.Service 拒绝）；
  6. 清理：先删 virtual 再删成员。

### 邻接测试断言刷新（越界说明，见"四"）
