## 做了什么

`bf license` 离线子命令族三动词（ADR-0032 决策 1 的签发链，全程无网络、无 profile、无 config 依赖）:

1. **`bf license keygen`**：生成 ed25519 权威钥对。私钥 PKCS#8 PEM（kid 走 PEM header，一文件自洽），`O_EXCL` 创建 mode 0600，**拒绝覆盖已存在私钥**（防权威钥被静默清掉）；公钥以 raw hex 打印（verifykey.go 的拼写）+ 可选 `--pub-out` 落文件；`--as-go-const` 打印首发换常量所需的两行 Go 常量（`EmbeddedVerifyKeyID` + `embeddedVerifyKeyHex`）。默认路径 `./binflow-license-private.pem`（.gitignore 显式留名）。
2. **`bf license issue`**：读私钥（`--key` > env `BINFLOW_LICENSE_KEY` > 默认路径，ADR-0032「--key/env 注入、不入库」）→ 构造 payload v1（typ/alg/kid/ver/licenseId〔RFC4122v4, stdlib 手写〕/licensee/tier/issuedAt/notBefore/expiresAt/addons/limits 预留）→ ed25519 签 payload 原文字节 → `<b64url(payload)>.<b64url(sig)>`。校验：tier 走 `license.ParseTier` 闭集；pro/enterprise 必须带 `--days`（付费档无 expiresAt = malformed grant，§15.1.1）；community 缺省 days = 永久（expiresAt 字段省略 = null）；addons CSV 去空/去重/字符集校验，缺省 = 档位全解锁（字段省略）；kid = `--kid` > PEM header（缺省 bf-lic-2026）。**签名后立即用 `license.VerifyDocument` 自检**（钟拨到 notBefore+1s 使未来生效日也能自检）——格式漂移死在工具处，不出门。stdout 模式只打印文档一行（管道友好）；`-o/--out` 落文件 0600 + 打印摘要。私钥文件权限过宽（group/other 可读）→ stderr WARN 不阻断。
3. **`bf license inspect`**：`<file|->`（stdin 支持）→ 本地解码回显字段（含 perpetual/addons/limits）+ 两条验签裁定：主裁定（`--key` 公钥 hex 文件，缺省 = 内嵌公钥即「stock 二进制是否接受」）+ stock-binary 裁定（有 `--key` 时也照报）。主裁定失败 → 字段照打 + 非零退出（AC1 篡改腿可脚本化）。给私钥文件会被点名拒绝（inspect 不碰私钥）。验签错误文本直接采用 internal/license 的 redacted 错误（本就无 payload 内容）。
4. **首发三步流程文档**：落在 `bf license --help`（三步：keygen → 换 verifykey.go 常量重编译 → issue）与 keygen `--as-go-const` 输出注释里。没动根 README——area 纪律（README 归属未授权），--help 已满足票据「README 或 --help」二选一。
5. **测试**（`cmd/bf/license_test.go`，全表驱动）：
   - 三命令 help 面 + 未知动词 + 零 config 可用性；
   - keygen：0600/PEM/kid header/pub-out 与打印一致/`--as-go-const` 与公钥一致/覆盖拒绝（且文件未被触碰）/bad kid 4 变体/默认路径（t.Chdir）；
   - issue：校验失败 10 变体（缺 licensee/坏 tier/pro 与 ent 缺 days/负 days/坏 not-before/坏 addon id/坏 kid/缺私钥文件/非 PEM/公钥文件误用）+ 字段逐项断言（含 addons " ha, go ,,ha " → [ha,go]、--not-before 逐字、+365 日历天）+ kid 优先级（--kid > PEM header）+ env key + 永久 community + -o/--out + 0600 + 宽权限 WARN；
   - inspect：`--key` 往返 OK + stock REJECTED（首发前真话）、stdin、**篡改签名段首字符**（尾字符在 RawURLEncoding 下只动被丢弃的 padding 位——不改解码字节，测试注释固化了这个坑）与篡改 payload 段 → 非零退出且字段照显、外键拒绝、缺省 = 内嵌裁定 FAILED、PEM 私钥拒绝、4 种畸形文档、缺文件/参数数；
   - **端到端**（`TestLicenseEndToEndServerInstall`）：keygen → issue pro → 文档放 `license-dir/`（BINFLOW_M10_LICENSE_DIR 挂载点形态）→ inspect 绿 → **真实 httpapi 栈**（sqlite metadata + 真 auth/repo/storage + license.Manager 以 keygen 公钥为 VerifyKeys = 首发换钥后的世界，T-279 构造注入缝）→ 装 go 仓 D3 400（body 点名 tier 'community' < 'pro'）→ POST 装 license 201 → GET tier=pro/licensee=Acme → **go 仓创建 200** → 篡改文档安装 400 且 pro 原状（D7）→ DELETE 后 go 仓回到 D3 拒绝。

## 规格依据

- ADR-0032 决策 1：文档 v1 = `<b64url(payloadJSON)>.<b64url(ed25519Sig)>`、签发链 `bf license keygen/issue` 离线、私钥 --key/env 注入永不入库、验签公钥编译期内嵌（首发换常量 = T-279 遗留③，本票 `--as-go-const` 供其粘贴）。
- architecture §15.1.1（payload 字段/闭集/expiresAt null 仅 community/addons 缺省=档位全解锁/limits 预留原样回显）、§15.1.2（校验链单函数——inspect/自检直接复用 `license.VerifyDocument`）、§15.1.3 D3/D7（e2e 断言的 400 点名与「安装失败现状态不变」）。
- PRD FR-84（84.3 离线签发工具、AC1 签发自检/篡改失败、AC2 安装闭环）。**PRD↔票据拼写分歧**：PRD 写 `bf license generate --expires`，conductor 票据与 ADR 裁定口径为 `issue` + `--days`——按票据实现（`--not-before` 补 RFC3339 起效日）；已留 `--not-before` 而非 `--expires`，如需 PRD 原拼写属一词别名，可在终审时加。
- 门控消费面（`repo.AttachPackageTypeGate`/`addons.Registry`/`license.Manager`）全部走既有导出缝，e2e 内的 gate 适配器是 cmd/binflow-server 私有 `packageTypeGate` 的测试侧镜像（那边不导出，本票不越界去改）。
