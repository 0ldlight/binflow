## 6. 发现与缺陷（本轮新登记）

- **D-A（P1，产品裁定项）**：dual-write S3 停机窗姿态——GET 存量 500（fallback 仅 ErrBlobNotFound）、PUT 500 且 disk 零落盘（BeginSession S3 臂失败连带 abort disk 臂）。与 M6 PRD §FR-50「S3 写失败不阻塞请求+重试队列」文面冲突；实现自 M11 前即此（非 M11 回归，binstore.yaml 等价透出）。**处置建议二选一**：M12 补 fail-open（本地优先写+异步 S3 重试队列）或 PRD 勘误收口「fail-closed on session begin」。证据：/tmp/t327/i18292 复现序列（D-A 全 transcript 在本报告 §2 L09 行）。
- **D-B（P1，REST 传输层缺口）**：deb/rpm 仓策略键（`byHash`/`debianDefaultArchitectures`/`historyCycles`/`origin`/`label`；`calculateYumMetadata`/`yumRootDepth`/`enableFileListsIndexing`/`yumGroupFileNames`）**经 repositories REST PUT 不可达**——repoConfig 传输结构体（httpapi/repositories.go configJSON local 臂）只透传通用族，策略键被 scenario-D 容忍静默丢弃（实测 PUT 200 后 GET 无该键、by-hash 永不生成、auto-async 409 分支不可触发）。适配器读 config blob（deb/reindex.go RepoConfig）但唯一写径是测试 harness 直种。文档（debian.md §3「常用仓配置 JSON」/rpm.md §3「{"calculateYumMetadata": true}」）承诺的配置面 REST 上不成立。**归因：产品缺口（T-310/T-311 各自差异表未登记此面）**——建议开小票补 repoConfig 透传（或专用子对象），随票补 409/by-hash 分支真测。
