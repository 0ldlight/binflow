## 4. 过程发现与处置

1. **`hasText` 子串负断言假红**：列集腿 `th.filter({ hasText: '类型' })` 首跑即红——「包类型」表头含「类型」子串。改整格正则 `/^类型$/`（spec 注释留痕）。
2. **t404 旧「remote Tab 无列」断言的空洞性 + 翻转**：该腿 `toHaveCount(0)` 在空 remote Tab 上**空过**（无行 → 无表 → 表头恒 0）——B-3.9 落地后语义反转，且原断言从未真正锚定「列缺席」。本票翻转为：先备 remote 行再断言列**在场** + push-only title + 0 cell（非空断言）。**parity 册 v1.5 B-3.9 行「列 + Run 动作已随 T-404 落」系对账勘误**——T-404 实作仅 local Tab；v1.7 已改写留痕。
3. **退役锚的 spec 反断言会制造永续 broken**：`repos-columns-item-type` 的 count-0 反断言使 anchor-audit A2 红（`form-reset` 当年靠 `form-*` 生成器族掩蔽侥幸逃生，type 无族可掩）。处置 = 文案级负断言（菜单项文本 `/^类型$/` count 0），退役锚不再进 spec 选择器。
4. **建仓态 Test 的诚实处理**：T-442 端点按已存 key 寻址（仓不存在 404）——建仓态给 hint 行不给死按钮（Artifactory 建仓态有 Test 钮但 BinFlow 端点语义不支持，不伪造）。票内登记。
5. **dirty-gating 与外部变更腿的交互**：`repositories.spec.ts` 的「编辑态成员被外部删除 → 400 行内回显」腿原样点击 Save 会先被 dirty 门拦（表单无变更）——补一处描述变更使 Save 可达，腿语义（服务端 400 文案行内）不变。
6. **AppShell/跨页 emitter 零触碰（area 纪律）**：quick 菜单与 7 处 `/new` 链接全部经路由表兼容映射工作（m8/shell + t383 两腿钉死）；如需把 emitter 直链新路由（省一跳 redirect），建议另立小票（AppShell 属公共组件）。
