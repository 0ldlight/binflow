## 做了什么

### AC① ME-04~07 触发时机 + 两个生成器 + 删除联动（`calc.go`，新文件）

**calculator 结构**：Handler 持有（`New` 第 4 参 `NodeReader` 注入）；一个**进程级执行锁**串行化所有重算执行（sync 腿与 async 腿共锁）+ WaitGroup（测试排水）。并发不变量：每次重算**在锁内**list 存储事实，故「最后一次重算的写」必然包含其触发前落盘的全部节点——这就是 FR-17-AC5「等效合并不丢版本」的实现论证（stale 覆盖 fresh 在锁序下不可达）。计算器失败一律 slog ERROR/WARN，绝不上浮内容面（无 5xx）。

**触发时机四类**（`afterArtifactDeploy` / `afterMetadataDeploy` / `afterDelete`，挂 put.go/handler.go 成功路径，以**落盘 node.RepoKey**（T-71 路由 virtual 的真实目标仓）为地址：
- unique snapshot 文件（任何 ext）/ **non-unique pom** → 父 version 目录**同步**重算（阻塞 deploy 响应；`l.Timestamped || (pom && l.Snapshot)`）；
- 其余 artifact（release jar/pom、non-unique 非 pom）→ 父 version 目录异步；
- pom → 加算祖父 module 目录（非递归）异步；
- delete → 源侧受影响目录树异步（artifact：version 目录 + module 目录；metadata：其自身目录；仅 local 仓——handler 先经 ClassReader 判类，remote 的 DELETE 是缓存失效、virtual 到不了这）；sidecar 删除无触发（内容事实未变）。
- 客户端 PUT `maven-metadata.xml` → 201 走通用上传链后**同步**重算受影响目录（裁决见下）。

**版本组目录生成器**（`recalcModule`）：versions = 含 `*.pom`（直系、非旁车——`x.pom.sha1` 不算）的子版本目录集去重，VersionComparator 排序；latest = 排序最后（SNAPSHOT 也算）；release = 最后非 SNAPSHOT（全 SNAPSHOT 时**省略**该元素）；lastUpdated = 计算时刻 `yyyyMMddHHmmss` UTC（锁内取 now，单调性由执行序保证）。

**SNAPSHOT 版本目录生成器**（`recalcVersionDir`）：groupId/artifactId **取自目录拼写**（maven-2-default 下目录即坐标，layout 上传时已对文件名校验；坐标与路径不符的 pom 是客户端错误，不洗入 metadata——裁决注释在代码）；`<version>` = 目录拼写；buildNumber/timestamp 取**最新 unique snapshot pom**（buildNumber 数值比较、timestamp 决胜）；无 unique pom → 固定 buildNumber 1 无 timestamp（spec 原文）；spec 沉默处的裁决：有 unique 文件但无 pom 时取全部 unique 文件最大 N（保住编号单调，不回落到 1）；snapshotVersions 每 (extension × classifier) 取最新一条（recency = node.CreatedAt，buildNumber/timestamp 决胜），entry `<value>` = 文件版本拼写、`<updated>` = 时间戳去点号（non-unique 条目取计算时刻）。

**删除规则**：无 pom 事实 → 删 metadata 及 `.sha1/.md5/.sha256` 旁车节点（sha512 伴随按 PRD 注记留 P2）；**RTFACT-6242 例外**：非 SNAPSHOT 目录中现存 snapshot 型内容（`<snapshot>` 块或任何 snapshotVersion 条目）不删；探针读失败也**不删**（fail-safe 向）。

**checksum 一致性（AC②/M14）**：`.sha1/.md5` 旁车 GET 本就由 serveSidecar 从 ledger 现算（T-67 面），因此**恒等于**当前 metadata 节点内容——重算改写后旁车与响应头自动一致，无陈旧窗口。

### 关键行为修正（防 mvn 破坏，正确性红线）

**metadata 旁车 PUT 不再 409**（`putSidecar`）：Target 为 metadata 文档时跳过 client-checksums 比对、落实测值。理由：FR-17 v1.1 服务端权威重算会在任意 deploy 改写 metadata 字节，mvn 随后 PUT 的旁车值（对**它自己**的 XML 算的）与服务端实测**必然**不一致——不豁免则同步重算后 mvn deploy 100% 死于 409（真服务器日志实证五次 deploy 的 metadata+旁车 PUT 全 201）。>1024B 守卫与目标必须存在两条不变。

### 三处 spec 沉默的裁决（已在代码注释 + 本节声明，供 reviewer 复核）

1. **release 版本目录不生成 version 级 metadata**：规格只定义版本组目录与 SNAPSHOT 版本目录的内容规则（release 版本发现走 module 级，Maven Central 同惯例）；release 目录的重算 = 清理通道（无 pom → 按组规则删，受 RTFACT 守卫保护）。
2. **客户端 PUT metadata 的重算取同步**：v1.1「权威内容以服务端计算为准」+ M15 型断言（PUT 后即读）要求 201 返回时内容已权威；异步会让「等效合并」对调用方可观察地抖动。plugin 群变体 `metadata-maven-metadata.xml` 无生成器，PUT 原样存储不触发。
3. **groupId/artifactId 目录派生**（见上）。另：删除触发的重算经触发 principal 的 delete/write 授权——include 精确排除 metadata 路径的极端 ACL 下联动会降级为 WARN（不 5xx），注释已述。
