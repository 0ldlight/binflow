## 三、真实客户端链（`BINFLOW_DEB_E2E_APT=1`，debian:bookworm 容器 + dpkg-deb 真包）

`TestClientE2ERemoteVirtualAptContainer`（41.69s PASS）：

1. 容器内 dpkg-deb 构造两枚真 .deb（binflow-e2e 1.0-1 / binflow-virt 2.0-1，control.tar.xz）；
2. curl debPUT 分别入 deb-apt（origin local，byHash=ALL）与 deb-apt2（第二 local 成员），双 201；
3. **remote 腿**：`deb [trusted=yes] $BASE/binflow/deb-mirror stable main`（deb-mirror 上游=deb-apt）→ `apt-get update`（Release/Packages/by-hash 全部经引擎回源；apt 自身按 by-hash 地址校验 SHA256 通过）→ `apt-get install binflow-e2e` → `Status: install ok installed` / `Version: 1.0-1` → 运行输出 **`binflow t314 remote`**；
4. **virtual 腿**（新容器）：`deb [trusted=yes] $BASE/binflow/deb-virt stable main`（成员=[deb-mirror(remote), deb-apt2(local)]）→ `apt-get update`（虚仓重算 Release + 合并 Packages，apt 按 SHA256 节校验**聚合自己的字节**通过）→ `apt-get install binflow-virt binflow-e2e` 双包装机（binflow-virt 走 local 成员首命中、binflow-e2e 走 remote 成员回源下载）→ 双 `Status: install ok installed` → 运行输出 **`binflow t314 virtual` + `binflow t314 remote`**。

回归：T-310 本地腿 `TestClientE2EAptContainer` 复跑 PASS（39.40s，`binflow t310`）。

## 四、差异登记

|---|---|---|---|
| R1 | **S9 remote 路径归一化不实现** | BinFlow 钉 archive-root URL 姿态：上游 URL 自带嵌套前缀（如 `http://deb.debian.org/debian`），请求路径原样拼接——与 generic/conan remote 同模。Artifactory 的"请求路径内定位 /dists/ 截后缀"服务于 flat-URL 上游，BinFlow 配置模型下无此形态 | debian.md §8 remote 行（中置信）；规格待验证清单 §12-2 |
| R2 | **remote DELETE = RE-06 缓存驱逐（204），非 §8 的粗粒度"DELETE 拒绝"** | 服务层既有裁决优先（BinFlow 全域 RE-06；且即 §4.3 evictItemInCache 的内容面等价物——单文件元数据缓存强制刷新）；未缓存路径回共享 404 | debian.md §8（中） vs repo 层 RE-06（已裁） |
| R3 | **S10 stanza 去重键定为 Package+Version+Architecture+下载地址（Filename/Directory），首见成员胜** | 键含下载地址使存活行与首命中下载自洽：同地址不同字节→保首成员行（其校验和=实际服务字节）；同包不同 pool 路径→两行并存（各自地址各自成员，均自洽）。规格明标此细节未逐行核对（待验证清单 §12-1），本键为 T-314 裁定并已测试固化 | debian.md §8 virtual 行 + §12-1 |
| R4 | **virtual 不出签名族（InRelease/Release.gpg 404）且无 by-hash** | 成员签名不覆盖聚合重渲体；虚仓不留哈希史；apt 官方回退（trusted=yes→Release；by-hash→正名）。Release 亦不写 Acquire-By-Hash 行 | §4.2 unsigned（DB-1 延伸）+ §5 官方回退 |
