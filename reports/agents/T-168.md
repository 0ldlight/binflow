## 两处红的根因（同一个根因）

复现栈（`go test -race -count=1 ./cmd/binflow-server/`）：

```
panic: adapter: Register: duplicate protocol "npm" [recovered, repanicked]
  internal/adapter/registry.go:53  ← adapter.Register 的 duplicate 契约 panic
  internal/adapter/npm/api.go:114  ← npm.Register
  cmd/binflow-server/main.go:300   ← newAssembledServer
  cmd/binflow-server/main_test.go:1048 ← TestServeGracefulShutdownLog
```

- `newAssembledServer` 每次调用都把 npm/pypi handler 注册进**进程级全局 adapter 注册表**（npm/api.go:112 注释明载 "cmd assembly calls it exactly once; a duplicate panics"——生产语义正确，不该改）。
- 包内已有此约束的规避先例：metrics_wiring_test.go 头注 "The full newAssembledServer cannot run twice in one process"；auth/replication/s3 各 wiring 测试全部用轻量 Deps 形态绕开。
- 前 agent 的 `TestServeGracefulShutdownLog` 是**第二个**全量装配调用方：文件序在前的 `TestServeAssembledStackPing` 先注册，轮到本测试时 `npm.Register` 触发 duplicate panic，测试进程崩溃，main_test.go 之后的所有测试文件（metrics/replication/s3）全部没跑。
- 附带发现：该测试的日志断言是**同义反复**——测试自己 `logger.Info("shutting down gracefully")` 再断言缓冲区包含它，生产行为删了它也照样绿。

## AC② — nginx SSL 模板收尾（deploy/nginx/）

模板在盘但有三处真实缺陷，已修：

1. `listen 443 ssl http2;` 是 nginx ≥1.25.1 的弃用语法 → 改 `listen 443 ssl;` + `http2 on;`（与 deploy/compose 钉的 nginx:1.27-alpine 同代）。
2. `proxy_set_header Connection "upgrade"` 对**所有**请求硬发升级头 → 改标准 `map $http_upgrade $connection_upgrade`（conf.d 文件被 include 在 http{} 内，map 放文件顶合法），有升级请求才透传。
3. `ssl_stapling on` 无 `resolver` 不生效 → 补 `resolver`（示例 systemd-resolved，注释给 1.1.1.1/8.8.8.8 备选）+ `resolver_timeout` + issuer chain 说明。

README.md 微调同步（nginx ≥1.25.1 版本要求）。
