### cron 三域（文档示例的原样来源）

```bash
# 维护三槽：GET 首配全空 → PUT arm gc（先验后写）→ 坏表达式 400（文案逐字入文档）：
#   5 域: "Invalid cronExp 0 0 5 * * for gc: scheduler: invalid cron expression:
#          got 5 fields, want 6 or 7 (a 5-field Unix cron is not a Quartz expression)"
#   W:   "... day-of-month field \"15W\": element \"15W\": nW (nearest weekday) is not supported"
#   L(dom) "0 0 3 L * ?" → 200 收录；空 cronExp → 200 清除；enabled=false → cron 保留 nextRun=""
# 备份：PUT nightly（MON-FRI 2:00）→ 200 回显 nextScheduleBackup=2026-09-07T02:00:00Z；
#   相对路径 400 "exportPath must be an absolute server path (starting with '/')"；
#   过去时刻 400 "... is not in the future; pick a time after now or omit the field"；
#   显式 nextBackupTime 2026-09-08T03:30:00Z → nextScheduleBackup 原值回显；DELETE 204
# 投影：GET /system/schedules 全域 + ?domain=backup 单域；?domain=bogus → 400
#   "domain must be one of maintenance, backup, replication (or omitted for every domain)"；匿名 401
# 复制：POST 带 cron → PUT cron_exp arm（next_schedule_sync 回显）→ enabled=false park
#   （cron 保留 next=""）→ enabled=true 重臂 → cron_exp:"" 清除 → "not a cron" 400 点名 →
#   空 body 400 "enabled or cron_exp is required; no other field is editable on this face"
# 审计：maintenance.schedule.set / backup.schedule.set（set/cleared/deleted 三 action 形）
#   / replication.schedule.set——detail 含 key/cronExp/next_run/enabled（逐行核对）
```
