## 1. 实施清单（四条主线 + 安全增项）

### 1.1 表格族：摘 .table 续挂 → MUI Table small 原生

页面（13 处 Table）：Repositories / Users / Groups / Permissions（+ widgets.PermSummaryTable、
PermissionEditor 双矩阵表）/ Audit / Quotas / Replication（目标 + 事件两表）/ License addons /
StorageSummary / Search / ArtifactsBrowser 树表（`table tree-table` → 只留 `tree-table`，
content-visibility 性能规则不动）。

- `<Table className="table">` → `<Table>`（MuiTable 默认 small 主题档：行高 ≈33px、
  cell 6px padding、表头字重、divider 行线全交 MUI）；RepositoriesPage 的
  `fontSize: var(--bf-fs-body)` 覆写一并摘除（14px 主档已由主题承载）。
- 行 hover：`.table tbody tr:hover` 压制规则随续挂摘除而失效 → **TableRow 补 `hover` 属性**
  （MUI 原生 hover，action.hover 承载面；.table CSS 悬停规则对摘类后的表格不再命中）。
- `td.wrap` 续挂 → TableCell `sx={{ whiteSpace: 'normal', wordBreak: 'break-word'/'break-all' }}`
  （描述列 break-word——中文场景 break-all 会截断 CJK 内英文单词，行为更保守；路径/digest
  列 break-all 沿旧语义）。base.css 的 `.table` 族规则**保留**（Dashboard 批 D 清扫对象仍在
  职消费，删了会裸奔）——本批页面侧零引用。

### 1.2 徽章：badge → Chip 全原生（badgeChipSx 续挂摘净）

- 全部 `sx={badgeChipSx}` 摘除（inert 空对象引用清零——pages/ 域内 41 处消费面全部落地；
  LoginPage 残留引用归批 B/D，muiAtoms 导出保留）。
- 色彩映射（§3.2）：`neutral → Chip 默认 filled（action.selected 底 + text.primary）`；
  `success/warning/danger → variant="outlined" + color success/warning/error`；
  `tier-pro → outlined info`、`tier-enterprise → outlined warning`（LicenseAddonsPage 的
  TIER_COLOR + RepositoryFormPage 网格/单选 label 内档位徽章）。**类名组合原样续挂**
  （`badge warning` 等——§3.8 toHaveClass/hasText 钩子零变化）。
- **filled 语义色不可用**（差异登记 D-1）：MUI v7 的 contrastText 按「与深色文字 ≥3:1 优先深字」
  派生——亮色 warning #946200/白 或 深字 实测 3.7:1、暗色 success #3fbf6f/白 2.4:1，全部不过
  axe 4.5 门（spec §5.6-3「filled 语义色底」的假设在 tokens 色板下不成立）；outlined 的
  语义色文字对 paper 双主题实测 5.1~7.4:1。语义徽章一律 outlined。
- **base.css `.badge` 族 = 迁移期 shim**：选择器改 `.badge:not(.MuiChip-root)`（差异登记 D-2）
  ——DeployDialog（components/，批 B/D 域）仍有 4 处原生 span.badge 消费者，整块删除会让
  其裸奔、越界改 components/ 则破并行纪律；:not() 把 Chip 根从旧配方排除（皮肤即刻交还
  Chip），span 消费者视觉零变化，批 D 末位 span 退役后整块删除。
- mono 徽章（组名/manage/pattern/kind）：Chip 换装后 (0,1,0) 的 `.mono` 类压不过 emotion 的
  font 继承（monoInputSx 同款机理）→ 使用点 `sx={{ fontFamily: 'var(--bf-mono)' }}`
  （--bf-mono 是布局 token，断言腿 3 合法）。security.css 的
  `.perm-pattern-summary .badge` mono 规则随之退役；tree.css 的
  `.tree-table td .badge.warning` tint 块退役、间距块选择器改 `.MuiChip-root`。
- status-pill（widgets.StatusLabel）→ Chip outlined success/error，类名续挂（ADR-0029 决策 3
  的「行级 .badge 唯一性」语义沿袭）；security.css 配方规则删。

## 2. 实施中修复的回归（有根因链与复现证据）

1. **Tabs 方向键「不选择」**（keyboard.spec:170 首轮红）：MUI Tabs 默认方向键**只移动焦点**
   （Tab.handleFocus 仅在 `selectionFollowsFocus && !selected` 时才触发 onChange——Tab.js:243
   实证），与旧 onTablistKeys 的「方向键 = 选择 + 焦点」不等价。修复：三处 Tabs 补
   `selectionFollowsFocus`（repo 详情 / repos 列表 / authcfg），复跑绿。**建议回写 spec
   §3.5 的「Tabs 换装」条目：凡替代 onTablistKeys 的 Tabs 必带 selectionFollowsFocus。**
2. **首轮全量 13 红的分解**：keyboard:170 = 本批上述回归（已修）；5 个共居负载假阳性
   （CFG1 / repositories-admin:98 / governance-monitoring:32 / m9 u9 / gc:202——串行复跑
   全绿；同机并行 agent 正跑自己的 e2e（8125 实例 + 其 playwright worker），首轮负载
   24）；其余 7 个归批 B（下条）。
3. **批 B 域红 7 个**（非本批面，两轮全量稳定复现，证据链）：
   - smoke:90 ×3 / auth-shell:89 / keyboard:204——`confirm-cancel` 存在但 `toBeFocused`
     失败：ConfirmDialog 的 Dialog 化初始焦点未接线（components/ConfirmDialog.tsx 为
     批 B M 状态文件）；
   - setmeup-deploy:101（首轮）——smu 网格元素 `toHaveCount` 失败：SetMeUpDialog 批 B
     在途（其文件 tsc 报错同步佐证 WIP；终轮已绿——批 B 边改边好）；
   - repositories:58/104——`.copy-btn` locator 失配：批 B 已把 CopyButton 换 IconButton
     并摘 `.copy-btn` 类（CopyButton.tsx 文件头自述「T-344 批 B」），e2e 存量 `.copy-btn`
     定位器未同步——**该 spec 契约归批 B 收口（保留类名或改 spec）**。

## 5. 差异登记（与规范文字不一致处 / 交接要点）

- **D-1 Chip filled 语义色不可达**：spec §5.6-3 与 §5.3 假设「Chip filled 对比度由 MUI
  contrastText 承载」——实测 MUI v7 getContrastText 以「与 rgba(0,0,0,.87) 对比 ≥3 优先深字」
  派生：亮色 warning/success/error main 上深字 3.7~3.8:1、暗色 semantic main 上白字
  2.2~3.2:1，全部 <4.5 不过 axe 门（permissions.spec T-266 腿对 users-table 做 include 扫描，
  必炸）。**落地：语义徽章 outlined（文字 = color.main 对 paper 双主题 5.1~7.4:1），中性
  filled default。建议 conductor 逼 ux-designer 把 §5.6-3 的「filled 语义色底」改判为
  「outlined 语义色 / filled 中性」并回写 spec。**
- **D-2 base.css `.badge` 族落地为 `:not(.MuiChip-root)` shim 而非整块删除**：规范 §3.2
  判「保名去规」，但 DeployDialog（components/，批 B 正在改）有 4 处原生 span.badge——删除
  = 裸奔回归，改文件 = 破并行零交集纪律。shim 达成规范的真实意图（MUI 皮肤生效），批 D
  末位 span 消费者退役后整块删除（建议登记到 D 波清单）。
- **D-3 MigrationPanel 水位条保留手作 DOM**：storage_migration.spec:122 断言
  `[data-testid="migration-bar-fill"]` 的行内 `width: 25%`——LinearProgress 的 determinate
  实现无此 DOM 契约（transform 动画）。换装需先改 spec 断言形态（值断言
  aria-valuenow 等价覆盖）。已换装面：QuotasPage/RepoDetailPage（无 fill 锚）。
- **D-4 `td.wrap` 的 break 语义分叉**：旧 `.table td.wrap` 是 break-all；本批对「描述类」
  列落 break-word（CJK 内英文单词不被拦腰截断），路径/digest/sha 列保持 break-all。
  视觉差异极小，走查可辨。
- **D-5 `.table` 族基线保留**：Dashboard 仍有 `<table className="table">`（批 B 页面域，
  T-344C 派单为 components/ 独占未覆盖）——base.css 规则保留至批 D 清扫。同理 `.btn`
  （Login/Profile/Dashboard/components 消费）与 `.field` label 结构（TextField label 浮标化
  未在本票范围——dispatch 限定「denseInputSx 残留退役」）。
- **D-6 单票 SPA 增量不可剥离**：共享工作树含 T-344C 在途 components/ 改动（构建即合并
  产物）；331,562B 为双批合并值。累计口径（NFR-P51）判定通过；单票 +3.25% 帽待两票分别
  落库后可按各自 diff 重算。
- **D-7 键盘链路等价性**：repo-tabs 方向键从 onTablistKeys 换为 MUI Tabs 内建（选择随
  焦点）；keyboard.spec §4 断言（aria-selected + toBeFocused）由 MUI 行为覆盖。repos/
  authcfg tab 条无键盘 spec 消费（grep 实证），方向键换 MUI 无断言面变化。
- **D-8 spec §6 波 C 的 Paper 化项（danger-zone/repo-form-section/authcfg-group）与
  radio/check RadioGroup 化未做**：dispatch 将本票范围收窄为「表格/徽章/表单（dense 输入）/
  Tabs」四主线；上述项不在四主线内且 FormControlLabel+Radio/Checkbox 已是 MUI 组件（T-299
  批一换装过）。建议归 D 波或后续小票。
