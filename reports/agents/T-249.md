# T-249 — npm packument 追加语义修复

- 票据: T-249 [P1] npm packument 追加语义修复（T-247 产品发现 P-1）
- 角色: dev-registry-adapter；area: `internal/adapter/npm`（+ 测试）
- 日期: 2026-08-24

## 1. 缺陷回顾（T-247 §6.8）

npm 包**第二个版本**发布时，packument 节点（`<pkg>/packument.json`）已存在且字节必然变化（新增版本），`repo.Service.Put` → `authorizeContentPut` 命中「覆写需 DELETE」臂 → 纯 write 的 CI 账号必 403（`E403 PUT …/npm-local/<pkg>`）。T-247 以 permission target 加 delete 缓解；本票修产品语义。

## 2. 语义判定表（本票定义的实现语义）

| packument 转换（old → new） | 权限臂 | 依据 |
|---|---|---|
| **追加新版本**：old 的每个版本在 new 中幸存且 manifest 逐字节不变（新增版本任意；dist-tags / time / readme 等**文档级簿记**任意变化） | **write**（`PutOptions.SkipOverwriteCheck=true`） | [NPM-API] 公开规范：publish = packument PUT，追加新版本是标准发布路径；版本不可变性在 **tarball 层**已由 spec §2.3 step 4 无条件 403 保证（与本表第四行一致） |
| dist-tag 增/删/移动（版本 manifest 不动） | **write** | 同一判定器自然覆盖；spec §2.1 该路由错误列为「403 无 write/annotate」，无 delete 要求 |
| **改动既有版本数据**：dist 摘要变 / manifest 字段覆写（含 `deprecated` 标记）/ 版本删除 / `versions` 集合缩减 | **维持 DELETE 臂**（无 delete → 403） | 本票裁定：已发布版本数据的重写保持 repo-semantics §3 覆写对；deprecate/单版本 unpublish 的 npm 10 形态（`-rev` PUT 全文档替换 / 无附件 deprecate PUT）在此臂下 |
| 重新发布既有版本（tarball 已存在） | **无条件 403**「Cannot modify pre-existing version」（有 delete 也 403） | spec §2.3 step 4 既有行为，未改动 |
| 全新包（无既有 packument 节点） | write（无既有节点，覆写臂本就不触发） | — |

判定实现：`packumentAppendOnly(oldDoc, newDoc)` = **版本集 diff**（old 每个版本在 new 中必须存在）+ **既有版本 manifest 深比较**（`jsonValueEqual`：map 键集相等 / 数组长度相等 / `json.Number` 按**字面拼写**比较——「1.0」≠「1.00」，即逐字节规则；dist-tags/time/根级字段不参与判定）。

## 3. 规格依据（clean-room）

1. **公开规范优先**（ADR-0001：有公开规范的协议以官方文档为准）：npm registry HTTP API——package publish 就是 packument PUT，发布新版本是标准路径，npmjs.org 上持 publish 权限即可连发任意多版本；版本不可变由「Cannot modify pre-existing version」403 保证（BinFlow 已实现，见 publish.go step 4）。
2. **docs/reverse/maven-npm-pypi.md §2.2/§2.3**：Artifactory 的包级元数据 `.npm/{name}/package.json` 是**服务端维护的聚合文档**（tarball 才是 content）；版本保护规则（step 4）落在 tarball 层。Artifactory 的 npm 发布仓不存在「第二版本需 delete」的行为记录——其 packument 对应物是服务端簿记，不走制品覆写权限对。
3. **docs/reverse/repo-semantics.md §3**：覆写/DELETE 臂是**制品 content 层**规则（DbStoringRepoMixin 的 isFileOverwrite）；旁车 checksum 与 maven-metadata.xml「永不触发覆盖检查」是既有的 freely-rewritable 家族先例（BinFlow T-68 已落 `PutOptions.SkipOverwriteCheck` SPI）。BinFlow 的 `packument.json` 节点是把 Artifactory 服务端聚合文档落成存储节点的**实现选择**，其 PUT 命中 content 覆写臂是实现产物而非协议要求——本修复把「追加版本」这一标准发布路径从该臂中豁免，豁免粒度按上表收紧（真覆写仍走 DELETE 臂），不是全家免检。
4. 无 Artifactory 直接逆向证据表明 npm packument 追加需 delete；依 1/2/3 以公开规范为准（票面授权）。

## 5. 测试矩阵（append_semantics_test.go）

- `TestPackumentAppendOnlyClassifier`：fresh / 相同 / 追加 / 簿记变化→true；版本删除 / dist 摘要变 / 字段覆写 / 数字拼写漂移 / versions 清空→false。
- `TestPublishAppendRidesWriteGrant`（**T-247 回归腿**）：ci-rw（r/w 无 d）连发 1.0.0、1.0.1 → **双 201**，packument 双版本、latest=1.0.1。修复前第二发必 403。
- `TestRewriteExistingVersionNeedsDelete`：
  - deprecate 字段覆写：无 delete **403** / 有 delete **201**；
  - -rev PUT 改 1.0.0 dist.shasum：无 delete **403** / 有 delete **200**；
  - **混合**（新增 1.0.2 + 改 1.0.0）→ 无 delete **403**（判定器按旧版本改动静默，不因「也含追加」放行）/ 有 delete 200；
  - -rev PUT 删 1.0.1：无 delete **403** / 有 delete 200；
  - 重发篡改 tarball 的 1.0.0：admin / 无 delete / 有 delete **全部 403**（step 4 无条件，含断言「Cannot modify pre-existing version '1.0.0'」措辞）；
  - -rev PUT 追加 1.0.2：无 delete **200**（判定器另一 HTTP 面）。
- `TestDistTagMoveRidesWriteGrant`：无 delete 的 add 201 / rm 200。

**M3 既有序列零回归**：`go test -race ./internal/adapter/npm/...` 全绿（61.8s / 复跑 44.5s）。既有覆写保护测试（step4 重复发布 403、M26 packument 重放 403）**未改断言**——它们钉的是 tarball 层 step-4 臂，新语义下该臂逐字不变；packument 旧 403 行为无任何测试钉过（正是缺陷漏网原因），故无需更新既有断言、不属静默改动。消费方包 `internal/httpapi`（69.4s）、`internal/replication`（6.4s）全绿（replication 的 npm push 不经本包 save 面，另见遗留 2）。

## 6. 真实客户端验证（npm 10.9.8 / node 22.23.2，macOS 本机）

栈：本仓源码构建 `binflow-server`（含修复）→ `127.0.0.1:18081`，sqlite 本地 filestore；`npm-local` 仓 + 用户 `ci-rw`（非 admin）+ permission target `t249-ci`（`["read","write"]`，**无 delete**）+ Access Token（`POST /api/security/token`，`_authToken` 形态 .npmrc，`npm whoami`=ci-rw）。

| # | 操作（全部以 ci-rw write-only 凭据） | 结果 |
|---|---|---|
| 1 | `npm publish` 1.0.0 | `+ t249-real-hello@1.0.0` ✓ |
| 2 | `npm publish` 1.0.1（**T-247 P-1 场景**） | `+ t249-real-hello@1.0.1` ✓（修复前 E403，见下） |

## 8. 遗留 / 建议

1. **deprecate 的产品语义**：本票裁定下 `npm deprecate` 需 write+delete（改既有版本 manifest = 字段覆写）。npmjs.org 只需 publish 权。若后续要放开，需产品定夺（可考虑「仅 `deprecated` 字段增删视为簿记」的再放宽），建议开票而非本票夹带。
2. `internal/replication/push_npm.go`（area 外）对目标 packument 的合并写若以非 admin principal 运行，可能踩同一覆写臂——其注释自称「merge 不整覆写」，未在本票验证范围，留待 replication 票自查。
3. T-247 文档若仍写「npm CI principal 需 write+delete」，应更新为「write 即可（T-249 后）」——文档区非本 area，留给 tech-writer/conductor。
