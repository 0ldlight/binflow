## 1. 口径单一权威化（任务 ①）

### 1.1 分桶定义（落 §10.6，audit 为可执行实现）

- **家族 = 选择器前缀归一**：模板/动态段（`${…}`、`<…>`）在首个动态段截断归一
  `前缀-*`；静态名自成一族。
- **掩蔽语义**（明文化）：动态族前缀覆盖同前缀一切具体名——族内任一具体引用即消费
  全族。实例：`group-delete-reason` 的引用使 `group-delete-*` 族存活；
  `user-delete-confirm-name` 掩护 `user-delete-<name>`；`form-member-order` 活化
  `form-member-*`；`tree-repo-filter` 活化 `tree-repo-*`。
- **registered** = 册有 ∧ src 有；**planned** = §10.4 白名单（册有 src 无 = 设计态）；
  **retired** = §10.6 退役总表（册有 src 无）；**unregistered** = src 有册无（硬违规）；
  **dead** = src 有 ∧ spec 零消费（处置队列，**清单不落册——audit 实时输出即视图**）；
  **broken** = spec 引用 ∧ src 家族无（硬门 = 0）。
- **src 口径** = 第一方渲染 DOM 锚落点：web/src 全量四形态 + **两个盲区修复**
  （`'data-testid'` 对象键条件展开——widgets 的 user-status 徽章自此可见；
  web/scripts/mock-idp.mjs——IdP 模拟页 `idp-login-page` 真身）+ **组件逻辑自消费**
  （src 内 querySelector 选择器引用的锚不计死锚：模板选择器按字面前缀——
  `smu-tab-` / `tree-repo-` / `tree-node-` 三处）。
- **spec 口径** = web/e2e 全量 .ts（README 等 .md 不计——v1.7 把 README 示例
  repos-row-docker-local / error-retry 误当覆盖，正是旧手抄清单漂移根源之一）。

### 1.2 audit ↔ 册自动对账：选型论证（任务 ①）

**采「audit 解析册」（--ledger 模式），否决「册由 audit 生成」**：

1. 册是规范性文档——「先入册再落码」要求意图先于实现，权威在册侧人写批次叙事；
   工具只能消费规范、不能产生规范。
2. 反向生成会把规范性来源变成工具输出；§10.2/§10.3 的批次叙事（裁定、替换形态、
   冻结语义）无法由工具生成，混排必然漂移。
3. 解析面收敛为两张表首列的反引号锚名（§10.4 白名单 + §10.6 退役总表）——
   **格式即契约**，破格即断言失败（fail loud），漂移无法静默累积。

`--ledger` 断言（违例 exit 1，入 qa 硬门）：A1 unregistered=0；A2 broken=0；
A3 retired 桶 ⊆ 退役总表 ∪ §10.4 白名单（禁止静默退役）；A4 退役表 ∩ src 家族 = ∅
（家族精确名判）。「registered 与册行数一致」由 A1+A3+A4 联合保证（src 无散锚、
册侧 doc-only 族全部落在表/白名单内）。
