## 一、三处分歧终裁

### ① readonly_admin 内容面语义（Q2 核心）——**ADR-0026 原案胜出：全域只读、w/d/m 硬拒、角色短路 target**

- **终裁**：readonly_admin 的内容面 = **全域只读**（`Can(p, repo, path, "r")` 恒 true，w/d/m 恒 false）；permission target **不参与** readonly_admin 的任何求值（内容面与仓库域均短路）。「不可与 target 组合」= 组合**无效**而非**非法**——不引入 principals 写入/入组的校验报错，组合静默无效果。**否决** PRD FR-64「数据面与普通 user 同权——走 permission targets 判定，角色不加持数据面权限」的措辞。
- **理由**（三条，均已写入 ADR-0026 理由段）：
  1. **角色名是安全不变量，不是缺省便利**。PRD 语义下「组员身份携带 w 授权 + 只读角色」= 一个能删制品的「只读管理员」——恰是 rbac-model.md 实证的 Artifactory 最近似物（project 域 Viewer 预定义角色：成员单角色制、无叠加，#1/#2 高置信：实例级无角色层、无 read-only admin）所排除的形态。审计/合规场景（PRD 场景 A）要的是「**不可能**改」，不是「默认没改」。
  2. **闭集可枚举验证**。3 角色 × 动作全表可被 QA 矩阵穷举（m7-rbac-matrix.sh 正是此形态）；组合语义使矩阵无界。
  3. **表达力零损失**。「读若干仓 + 写若干仓」本就由 `user` + target 表达；可组合的 readonly_admin 只制造第二条带优先级歧义的写路径。
- **架构风险 #2 复核**（硬编码只读若被要求可组合则推翻重裁）：rbac-model 实证不支持组合形态，风险不触发；若用户未来显式要求组合，届时新 ADR 推翻本条（已在 ADR-0026 留此口径）。
- **连带定案（Q2 子项，readonly_admin 管理面读界的两处精化）**：
  - **GC dry-run 不开放**：`POST /api/v1/system/gc` 全路由 = `system:write`，readonly_admin 403（含 apply=false）。否决 PRD Q2 暂行「dry-run 开放」——readonly 角色不 POST 写路由的守门不变量优先（审计日志里出现 readonly_admin POST 系统写路由本身就是坏形状）；且与 PRD 自身 FR-64-AC3「GC 触发 → 403」内部矛盾，本裁决一并消解。如未来要开放，M8+ 拆 GET 只读路由。
  - **读面清单勘误**：PRD 12 端点清单三处修正——`GET /api/v1/stats` 实为 `GET /api/v1/storage/stats`；`GET /api/security/token`（列表）**端点不存在**（M1 E-17 有意不存在，T-211 实测 404 佐证），从清单删除；补 `GET /api/v1/replications`（配置列表，属系统观测读）。`GET /api/v1/storage/migration` 在未装配双写的裸实例**过门后 501**（§7.1 既有契约，T-211 实测佐证）——readonly_admin 矩阵断言按「过门 501」判而非 200。

### ② 干净停机 Close 语义（Q3）——**PRD 方向胜出：Close 保留未过期会话**（ADR-0028 Accepted，推翻 architecture §5.3.1 契约 7 原「维持现状」裁决）

- **终裁**：`Engine.Close` = 停止接受变更 + 排空在途 Append/Commit + **不删除任何未过期会话行与数据文件、不做过期清理**；sweep + TTL 是会话行唯一回收路径；Close 打一条**保留清单** INFO（计数 + id，截断）替代原「清册 INFO」。三径 kill -9 / SIGTERM / compose restart 对称可续传，「跨重启续传」不再限定异常中断。S3 后端不受影响（无 DB 会话、ResumeSession 恒 404 维持）。
- **理由**（ADR-0028 全文，候选 A 维持现状 / B 保留 / C config 开关，选 B）：
  1. **对称性倒挂不可辩护**：T-209 后 kill -9 可续传而 SIGTERM 不可——干净路径劣于崩溃路径，等于激励运维用 kill -9 达成续传。
  2. **主价值场景落在干净停机**：PRD 场景 C（升级重启续传 2GB 层）与 M7 量化门槛（kill -9 与 SIGTERM **双**腿可续传）本就以此为立项动因；选 A 则 FR-67-V16 与门槛无法达成。
  3. **结构约束已消失**：会话 DB 化后行回收由「启动 sweep + TTL」独立承担，Close 清册降级为冗余双保险；「瞬态不进备份面」不变量约束的是备份产物内容，与 Close 行为无关（export 本就不含该表）。
  4. 孤儿风险有界（24h TTL）且 FR-70/V32 防孤儿回归钉死；C 的开关是为无消费者的分歧面加旋钮，否决。
- **牵连回写**（已全部落地）：
  - **ADR-0006 决策 2**：追加勘误④（append-only 注记，指向 ADR-0028；布局/落盘/sweep 本体不变）。
  - **architecture**：§3.1 Close godoc、§4.3 状态机注、§5.3.1 节首（「无 ADR 需求」改「Close 语义有 ADR」）+ 契约 7 重写、§9 停机链（「超时丢弃 session」改「超时保留」）、§11 条 11/33。
  - **T-209 qa O-1 措辞回写建议**（qa 报告为历史记录不回改，供引用方对齐）：O-1 的「干净停机清会话（非回归）」判定在 **M6 语境仍正确**（当时 Close 清会话确为既定语义、非缺陷）；**M7 起为目标行为变更**（ADR-0028）。PRD §5.6 反转表该行已与本裁一致；tech-writer 续传文档措辞以 ADR-0028 为准（不再写「异常中断后」限定）。

### ③ step-up 契约（Q5）——**ADR-0027 修订转 Accepted：PRD 作用域 + 折中交互形态**（五处统一）

| 维度 | PRD FR-68 | ADR-0027 Proposed | **T-214 终版** |
|---|---|---|---|
| 作用域 | 全部非 admin session 臂 | 仅 SSO 臂（provider∈{oidc,ldap}） | **全部非 admin web session 臂**（含本地用户；采用 PRD） |
| 本地/LDAP 交互 | body `step_up_password` | body `password`（LDAP 重 bind；本地不触发） | **`step_up_password`**（本地 argon2 校验 / LDAP bind 重验，`users.provider` 选腿；`password` 弃用——RFC 6749 保留字段名，防语义冲突） |
| OIDC 交互 | `prompt=login` → 单次 mint grant（≤5min） | body `id_token` + auth_time ≤15min 新鲜窗口 | **mint grant**（采用 PRD 方向；init 携 `purpose=step_up` 强制 `prompt=login` → callback 不建新 session、换发 grant → 铸造请求 body `step_up_grant`） |
| 错误码 | 401 `step_up_required` | 401 `reauthentication required` | **401 `step_up_required`（缺失）/ `step_up_invalid`（失验/过期/复用）**，OAuth 形错误体 |
| config 键 | `auth.token_step_up`（默认 false） | `auth.token_stepup_fresh_seconds`（N=15min） | **`auth.token_step_up`（bool，默认 false）+ `auth.token_step_up_grant_ttl_seconds`（默认 300s，域 [60,3600]）**；fresh_seconds 作废（新鲜窗口概念被 grant TTL 取代） |

- **作用域扩围理由**：威胁载体是 **session 臂本身**（cookie 即 bearer 证明、与身份源无关）；本地用户部署是 BinFlow 主体形态，只护 SSO 臂护了少数；LDAP 腿 bind 重验机制被本地腿免费复用；默认 off 零现状行为变化。Q11 留痕原口径（「SSO session」）记录为扩围依据的超越而非违背。
- **OIDC 腿弃 id_token 新鲜窗口的理由**（ADR-0027 候选 A'）：console 须在登录后留存 id_token——浏览器凭据留存扩大攻击面，新鲜窗口内 XSS 同时拿到 cookie + id_token 即可**无声**铸 Token，加固被自己的载体击穿；且「登录后 N 分钟免交互铸造」与「铸造即需重认证」语义自相矛盾。grant 单次性使 cookie 窃贼与 XSS 均无法无声通过；`prompt=login` 是 OIDC Core 标准语义。代价 = callback 加 purpose 分支 + 进程内 grant 台账（sha256 存储、绑定 user+session、单次消费即删；重启丢失 = 用户重走 re-auth，可接受，零 schema）。
- **端点**：`POST /api/security/token`（唯一在产签发端点）。§7.1 主表 `POST /api/v1/tokens` 行系 M1 规划残留（router 无此路由，T-214 勘误删除）；M8+ 若落自有签发端点，ADR-0027 同缝适用防旁路。
- **豁免**：admin session、Basic、Bearer（token）、`/v2/token`、匿名（401 挑战照旧）。Q11 四护栏零变更。
- **审计统一**：`token.issue` detail 增 `step_up: true` + `step_up_method ∈ {password, oidc_reauth}`（仅 step-up 路径出现；ADR 原 `second_factor` 维度弃用）。
- **wire 字段与枚举统一（跨 ①③ 的全局裁定）**：
  - 用户面 wire 字段名 = **`adminRole`**（camelCase；对齐 Artifactory security wire 字段命名，rbac-model §1.2 `adminPrivileges` 同族；与既有 `admin` 布尔配对、避免与泛化「role」概念撞名）；**DB 列名保持 `role`**，handler 一处映射（quotaBytes→quota_bytes 先例）。ADR-0026 原「wire `role`」措辞废止。
  - 枚举拼写 = **`user | readonly_admin | admin`**（snake；否决 PRD kebab `read-only-admin`：Artifactory wire 枚举值无 kebab 形态〔access API v2 snake〕、BinFlow wire 枚举惯例 snake〔rclass / grant_type〕、wire=DB=代码常量同拼消灭一层映射）。
  - token 面（whoami/session 回显）同名同拼；token 签发/验证响应不携带角色字段（即时生效由 Verify 重查 users 行实现，见下）。

## 二、ADR-0026 转 Accepted 与 §7.1 清点表终版

- **ADR-0026**：Proposed → **Accepted**（M7 立项确认 = BOARD 2026-08-23 录板）。转正修订五处（状态行「转正修订」清单 + 决策 1/2/3/6 与理由/后果段内联修订）：①① 的终裁与短路语义；② wire `adminRole`/snake 枚举；③ 路由清点终版；④ **readonly_group 映射**；⑤ **即时生效缝**：TokenRegistry.Verify 重查 users 行 role（与 enabled 同缝，T-208 护栏③先例）——V04「同 Token 升降角色即时生效」的实现前提。
- **§7.1 清点表终版**（8 路由族，T-215 逐路由 diff 施工图）：依 **router.go 实际注册点**枚举（30 个 admin:true 注册 + usage + ?permissions），相对基线三处修正：`GET /api/v1/replications` 补入系统观测读；`GET /api/v1/permissions` 归安全读 + token 列表端点不存在勘误；usage/{repo} 移入仓库域（判定 = CanManageRepo(read) ∨ Can(r)，W26b 既有 r 放行零回归）。三处新精化：**建仓臂**（PUT 而 repo 不存在）与 **DELETE 删仓**维持 CapRepoWrite admin-only 不下放（router 中建/换仓同路由，handler 分臂判门——PRD FR-65 边界）；m-holder 编辑 permission target 的门 = CapSecurityWrite ∨ target.repos ⊆ m 覆盖集（handler 校验，越界 403）；m-holder 不获全局列表（过滤列表 M8+，§11.30 维持）。§7.1 主表两处幻影行（`/api/v1/tokens`、`/api/v1/repositories` 全族、`/{key}/_list`）strikethrough 勘误。
- **OIDC/LDAP readonly 组映射（显式裁决：加映射键）**：`oidc.<provider>.readonly_group`（组名，group claim 值）与 `ldap.readonly_group`（组 DN）——与既有 admin_group 同节同形；idp_sync 权威式求值：admin_group 命中 → admin **>** readonly_group 命中 → readonly_admin **>** 其余 → user；两键缺省 = 行为与今日一致。依据：idp_sync 的 is_admin 刷新是权威式（每次登录重写，idp_sync.go refreshProviderAdmin 代码事实）——无映射键则 readonly_admin 对联邦用户结构性不可维护（每次登录被重写回 user）。
- **逆向证据收口**：§12 待确认 #14 已标注「已回答」（rbac-model.md 2026-08-23）：实例级无角色层/无 read-only admin（高置信）、组级 adminPrivileges 存在但 BinFlow 有意不跟进（M4 FR-27-AC9 维持）、manage 为 ACE 动作而仓库级 admin 正式对应物在 project 域——BinFlow 无 projects，target 的 m 是最小诚实同构（rbac-model §5 建议 2 背书），与 ADR-0026 零冲突。
