## 1. 做了什么

### AC1 — internal/metrics 包（Registry + Format）

- `internal/metrics/metrics.go`（单文件 ~430 行，BOARD AC 点名 metrics.go；ADR-0022 的
  registry.go+format.go+prometheus.go 三文件拆分以 BOARD AC 为准收敛为单文件）：
  - `Registry`：`sync.Map`（name → *family），family 内第二层 `sync.Map`（canonical label key → *series）。
    series cell 全部 lock-free：`atomicFloat`（CAS 循环，prometheus/client_golang 同款技术）+ `atomic.Uint64`。
  - 最小 API：`NewCounter/NewGauge/NewHistogram(name, help[, buckets])`（注册时声明 name/help/type；
    同 spec 重注册幂等、异 spec 报错、非法名/桶报错）+ `Counter.Inc/Add`、`Gauge.Set/Add`、
    `Histogram.Observe`（labels 为交替 key/value 变参）。
  - `Format()`：Prometheus text format 0.0.4——`# HELP`（`\`、换行转义）、`# TYPE`、
    label 值转义（`\`、`"`、换行）、family 按名排序 / series 按 label set 排序（字节稳定输出）、
    histogram 渲染 `_bucket{le=...}`（存储 per-bucket 增量、渲染时前缀和成累积 + 隐式 `+Inf` 收于
    count）+ `_sum` + `_count`。空注册表渲染空串；零 series family 仍输出 HELP/TYPE（FR-61-AC1
    要求流量前名字在场）。
- 四类指标（family 定义在 httpapi/metrics.go，命名沿 ADR-0022 `binflow_<subsystem>_<metric>_<unit>`）：
  - HTTP：`binflow_http_requests_total{method,path,status}`（counter）、
    `binflow_http_request_duration_seconds{method,path}`（histogram，PRD 默认桶 .005~10）、
    `binflow_http_requests_in_flight`（gauge）。
  - 存储：`binflow_storage_blobs_total{engine}`、`binflow_storage_blob_bytes_total{engine}`
    （engine=disk|s3 标签）。
  - 认证：`binflow_auth_logins_total{source=local|oidc|ldap}`（预播 0 保证在场；console 登录成功
    按 principalSource 计数，失败不计）。
  - 复制：`binflow_replication_tasks{status=pending|in_progress|success|failed|skipped}`（gauge，
    快照从 Store 拉）——**仅 Deps.Replication 非 nil 时注册**（FR-61-AC4 不暴露零值）。

### AC2 — 端点挂载 + require_auth

- 挂载点确认：读 router/server 现状，`/healthz`/`/readyz` 走 `route()` 根级 switch + baseChain
  （ADR-0008 前缀例外族，ADR-0010 同类豁免）。`/metrics` 同法挂根级 case（增量追加，未动既有分支）。
- `metricsHandler`：默认匿名（baseChain only，与探针同 posture——scrape 不付 auth 往返成本）；
  `metrics.require_auth=true` 时追加 authenticate + principal 门（匿名/被拒凭据 → 401 + Basic challenge，
  任意有效凭据 → 200，PRD「需认证」非 admin 门）。
- Content-Type `text/plain; version=0.0.4; charset=utf-8`；GET/HEAD only（其余 405 + Allow）。
  Deps.Metrics 未接线（历史测试栈）→ 503 诚实降级，不空 exposition 不 panic。
- **scrape 时快照**（dispatch 指定的最小埋点面）：blob 数 = `Metadata.Blobs().Count()`；
  字节数 = disk 走 `dirSize(blobs/)`（与 /api/v1/storage/stats 同 walk）/ s3 走 `repo_usage` 逻辑字节
  之和；复制 = ListConfigs × Status 求和。快照失败 Debug 日志 + 保持旧值，端点永不因 store 打嗝失败。
- **HTTP 中间件**：插在 baseChain 的 accessLog 与 recover 之间（读 accessLog 装的 statusRecorder；
  recover 在内层使 panic 恢复后计数仍落地；defer 计数使 ErrAbortHandler 再 panic 路径也不泄漏
  in-flight）。path 标签归一化 `normalizeMetricsPath`：探针/`/metrics` 原样、`/v2` 整面折叠、
  console/assets/docs 折叠、内容面 `/binflow/:repo/:path`、API 族按已知变参尾折叠（storage/
  repositories/security users·groups/v1 replications/v1 usage/npm/pypi），未知深族 2 段字面 + `:rest`
  兜底——基数封顶（FR-61-AC2）。
- cmd 接线：`newAssembledServer` 构造 `metrics.NewRegistry()` 注入 Deps.Metrics（每进程一个）。

## 6. 遗留 / 需上游确认

1. **复制延迟直方图 `binflow_replication_latency_seconds` 与 PRD H55 的 events_total 命名未实现**：
   需在 internal/replication Engine 埋点（非本票 area，dispatch 明示「超范围埋点留遗清单」）。
   本票交付 dispatch 口径的 `binflow_replication_tasks{status}`；PM/QA 需对 H55 断言名做校准
   （建议 H55 改 tasks 或另票补 events/latency）。
2. **H53 promtool check metrics 未跑**（本机无 promtool）：格式正确性由 metrics_test.go 逐字节
   golden + 真二进制 curl 背书；QA T-175 H53 需用带 promtool 的环境补验。
3. **s3 引擎标签的字节语义**：disk=物理字节、s3=repo_usage 逻辑字节之和（无廉价 S3 物理字节面；
   ADR-0022 的 s3_objects_total/s3_used_bytes 替代指标留 M6+）。s3 腿仅编译验证，无 S3 栈单测
   （T-178/T-173 域复验时顺带）。
4. **未实现的 PRD/ADR 点名指标**（超最小埋点面）：`binflow_auth_sessions_active`（metadata 无
   session 计数 seam）、`metrics.sample_rate`（直方图采样，现为全量、strict schema 拒未知键）、
   Go runtime 指标（goroutines/memstats）。需要时另票。
5. **`/metrics/json`**（architecture.md §7.1 已列 [M6]）：未实现，票面 AC 未含。
6. 登录计数仅覆盖 console session 登录（POST /api/v1/session）按 source；Basic/token 的每请求
   认证不计为登录（避免把 QPS 计成登录数）——若需按 PRD {method,status} 全臂口径另票。
7. T-168 遗留红仍在 main_test.go（graceful-shutdown 测试 + adapter 双注册 panic），本票以
   `-skip` 规避，未触碰禁区文件。
