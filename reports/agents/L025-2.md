## 二、nightly 调度 bug（race_full 从未执行）

### Changes

根因（文档 + #91 证据定案）：CircleCI 现行调度语义——「schedule 触发的是整条 pipeline，默认其
**每个** workflow 都跑」；而携带 legacy `triggers: schedule:` 块的 workflow 在项目级 schedule 触发
的 pipeline 里**不跑**（其触发条件永不匹配）。故 #91 的 schedule 事件跑了无 triggers 的 `uat`
workflow（build→deploy_uat→十腿——误部署），而带 legacy 块的 `nightly` 从未执行（race_full 零执行，
T-473 → L024-2 登记实证）。origin/main（f91b9e52）已含 nightly 块——排除「main 无 workflow」假说。

修复（CircleCI 官方迁移指南的 sanctioned 形态，`pipeline.trigger_source` 双向门）：
- `uat` workflow：`when: pipeline.trigger_source != "scheduled_pipeline"`——schedule 触发不再误部署
- `nightly` workflow：撤 legacy `triggers: schedule:` 块，`when: pipeline.trigger_source ==
  "scheduled_pipeline"`——任何 schedule 触发落到 race_full + 十腿矩阵（对常驻 UAT，无 deploy）
- 不钉 `pipeline.schedule.name`：本 org 的 schedule 名不可查询（API v2 对 standalone chunk org 回
  500/Project-not-found，L024-2 与本票双重验证），且本项目只有一张 schedule，无歧义面
- nightly jobs 不挂 branch filter：schedule trigger 自钉单分支，filter 反而会复刻「永不执行」形态
- 风险登记：若改后 nightly 仍不触发，需在 CircleCI UI（Project Settings → Triggers）建/重建
  03:17 UTC daily、branch main 的 schedule trigger——用户动作，API 不可达（见 Next）
