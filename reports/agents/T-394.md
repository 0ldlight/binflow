## 1. 做了什么

### 1.1 主项：npm legacy login（K60-1 解锁，T-374 L1 闭环）

**唯一修复面 = httpapi 写认证门对 couch 用户文档族豁免**（docs/reverse/npm.md §2.3-1）：

- `internal/httpapi/router.go`：
  - 新增 `isCouchUserDocument(rel)` 谓词：匹配 ESCAPED 仓相对尾路径 `-/user/org.couchdb.user:<name>`（K60-1）与 `.../-rev/<rev>`（K60-6 retry 拼写，适配器 as-built 同臂服务）；结构钉死（`-`/`user` 两段字面量、id 段以 `org.couchdb.user:` 起且段内无 `/`、至多一对非空 `-rev/<rev>`、容忍单个尾斜杠——镜像适配器 parseRoute 宽松度），任何包名/dist-tag/tarball 地址都不可能落进族内。
  - 新增 `Server.npmCouchLoginExempt(r)`：PUT + 谓词命中 + **repo 行 PackageType==npm** 才豁免。仓行在门前解析（仅命中路径族才查一次；未知 key/查询失败/非 npm 类型一律保持原门）。**类型钉死是承重墙**：否则 generic 仓会把这个路径族当普通节点匿名写入（谓词若只看路径=安全洞；strict 测试第 8/9 行就是这两条）。
  - `dispatchContent` 接线：`required && s.npmCouchLoginExempt(r)` → `action, required = "", false`。连带语义（全部 K60 §2.3-4 定案）：不要求凭据（body 臂可达）、不做仓路径写 ACL（login 是认证面，DE 同构「login 路由不做仓路径权限检查」）、跳过 addon 授权门（零制品落盘）。publish/dist-tags/unpublish/读面（whoami/ping）一概不动。
- `internal/adapter/npm/session.go`：**纯注释**零行为——原「栈注记」声称全装配下匿名 login PUT 必在门口 401，T-394 后该族被豁免，注释改为如实描述（ BOARD 票面 area 含 internal/adapter/npm；dispatch 指令未列，故只改过时注释不碰代码）。
- 测试（table-driven）：
  - `internal/httpapi/t394_npm_login_gate_test.go`（外部包，走全栈）：豁免正例（api mount + 裸内容面双入口 → 201 + token → token 过 whoami → 幂等再铸 201 非 409）；凭据臂（错口令/空 body → 401+Basic challenge；Basic 头臂仍 201）；**strict 不外溢 11 行**（publish/scoped publish/dist-tags/非 couch id/空名/杂尾段/DELETE/同族打 generic 仓（两拼法）/未知仓/`/-/v1/login` 维持 401）；读面不动（whoami 匿名 401+challenge、ping 200）。
  - `internal/httpapi/t394_npm_login_gate_internal_test.go`（内部包）：谓词单测 21 行（含 `%2F` 转义名单段、`-rev` 变体、尾斜杠）。

### 1.2 子项 2：helm PVC keep（注解面）

- `charts/binflow/templates/pvc.yaml`：注解块改为 `merge (dict "helm.sh/resource-policy" "keep") .Values.persistence.annotations`——keep 恒在，用户注解合并进来，键冲突时 keep 单键胜出（无重复键风险）。`helm template` 三态验证：默认有 keep；`--set persistence.annotations.foo=bar` 合并且 `helm.sh/resource-policy=remove` 冲突时仍单键 keep；`existingClaim`/`enabled=false` 时模板不产出。
- `charts/binflow/values.yaml`：`persistence.annotations` 注释补合并优先级与手动清 PVC 指引。
- `charts/binflow/templates/NOTES.txt`：Notes 段追加「PVC 带 keep——`helm uninstall` 有意保留数据卷，删数据须手动 `kubectl delete pvc`」（T-376 裁决建议的原样落地；仅 chart 自建 PVC 时渲染）。**卸载幸存的 UAT 实证归 T-399 验证腿**；Chart 版本 bump 亦归 T-399。

## 4. 遗留 / 需上游确认

1. **K60 §2.2「body 缺 name/password → 400 `User or Password fields are missing.`」未对齐**：as-built 适配器空凭据答 401+Basic challenge（T-393 就绪度判定 body 臂「已备」即含此姿态；npm 对两码都归 E401/ENEEDAUTH 不敏感，且真实 login 恒带账密，近不可达）。票面修复面唯一门豁免，故未动适配器；如要逐字对齐 DE 文案，另开小票（一行 + 一测试）。
2. **whoami 对「已认证但无该仓读权限」账号 403**（npm 渲染成 E403 且文案误导）：as-built 读面 ACL 语义（`action="r"` 走 `Authorizer.Can`），非本票改动面；K60-2 规格无此行。npm 语义上 whoami 是会话端点、按理可不应受仓 ACL 管——建议 conductor 裁：维持（记入规格 as-built 注）或开小票把 `/-/whoami`、`/-/ping` 移出租路径 ACL。低危（能 login 的用户通常至少有读）。
3. **T-393 待验证清单 #1 已闭环**（本票 AC1 首跑绿）；#2（npm ≥11/node ≥24 loginCouch 漂移）仍开放，随文档站客户端升级窗抽测。
4. PVC keep 的 `helm uninstall` UAT 实证与 Chart 版本 bump 归 T-399（票面既定）；release-engineer 会审本注解面（文件地图协作点）。
