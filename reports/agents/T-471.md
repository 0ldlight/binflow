## 背景与漂移证据

GH Actions `ci` 的 e2e job 在 main 上 flake：同树（c4da02e，run 33855887617 等）两轮失败集不同——
`t443-list-entry-dirty` / `repositories.spec:58` / `t451-pager-unification` / m9×2 轮换出现，
全部 "element(s) not found"，334 passed 大面绿；本地四门同 spec 全绿在案。

判读：**慢机尾延迟，不是回归**——失败集轮换（同树不同轮失败不同测试）+ 大面绿 + 失败全部死在
locator 等待（远未触及 180s 单测预算）。吸收面应放在 CI-only，本地面严格度不变。

## 配置变更（web/playwright.config.ts）

### 1. `retries: process.env.CI ? 2 : 0`（核心）

- 漂移对应：失败集轮换 = 非确定性尾延迟；retries=2 让真坏 selector 仍红（连续三败），只吸收尾部。
- 本地保持 0（Playwright 默认值，显式写出）：本地协议是「serial rerun green = pass」（web/README.md），
  本地红必须响亮。flaky 结果在 CI 的 github reporter 上有 flaky 标注，不静默。
- env 面不变：`process.env.CI` 是既判别（reporter 行已用），GH Actions 内建 `CI=true`，
  **ci.yml 无需传 env，未动**。

### 2. `expect.timeout`: CI 10s / 本地 5s（默认值显式化）

- 漂移对应：所有 straggler 死在 expect 的 locator 等待（5s 默认档）——冷启动共享 runner
  （server + 2 chromium workers 挤 4 vCPU）上最紧的闸。CI 翻倍到 10s。
- 不再调高：真回归应以 3×10s/腿 的成本浮出，不是藏在宽裕轮询后面。
- **actionTimeout 不设**：Playwright 默认 0 = actions 直接吃 180s 单测预算，本就不是绑定约束；
  `timeout: 180_000` 维持（漂移形态不是 test-timeout）。

### 3. `workers`: 评估后维持现状（只改注释）

- CI 侧 `ci.yml` e2e step CLI 传 `--workers=2`（flag 优先于配置文件的 4）——等于 4 vCPU
  ubuntu-latest 上 Playwright 自家 cpu/2 启发式，且该机还要跑被测服务，不算超售。
- 降到 1 被否：套件墙钟约翻倍，顶 45m job 预算；而失败形态（同并行度下 334 绿 + 单例 5s
  straggler）是尾延迟不是持续互饿。吸收手段 = retries + expect 档。
- 升档仍按 ci.yml 原注释：连续三轮 main 绿后方可。本地 4 不变。
