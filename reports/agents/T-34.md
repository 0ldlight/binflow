## 做了什么

### ① 002_docker 迁移（sqlite 实装 + postgres 占位同 M1 策略）

- 新增 `internal/metadata/migrations/sqlite/002_docker.sql`：`docker_manifests` / `docker_tags` / `docker_refs` 三表 + 三条索引（`idx_docker_manifests_image`、`idx_docker_tags_image`、`idx_docker_refs_blob`），列集/复合主键/FK 声明/索引逐项对照架构 §6 定稿块；DDL 语句为原文翻译（列定义顺序与类型一致），注释为英文重述（含 tag 字符集注释、digest 逻辑外键注释、GC mark 扩容注记、docker node 布局约定）。
- 文件体内无任何事务语句（BEGIN/COMMIT/ROLLBACK/START TRANSACTION）——迁移器自包事务（T-10 M9 红线），并有表驱动单测 `TestMigrationsHaveNoTransactionStatements` 对**全部**内嵌迁移文件生效（003+ 自动继承该守卫）。
- `migrations/postgres/README.md`：补版本对照清单（001/002 各建什么），维持「postgres 文件必须与 sqlite 一一对应」的 M1 策略；不新建占位 .sql（M1 先例：目录只有 README）。
- 迁移幂等 + 老库升级路径单测：
  - `TestDockerMigrationIdempotent`：同库二次 Open，版本恒 2、无重放。
  - `TestDockerUpgradeFromM1Database`：构造「只有 001 + 真实 M1 数据（repo/blob/node/admin 改密）」的库（应用 002 后回滚 ledger 并 drop 三表来仿真 M1 库），再以当前构建 Open → 仅补 002、M1 数据原样、admin 口令不被种子覆盖、新表立即可写。

### ② DockerStore 子接口

- `api.go` 新增导出值类型 `DockerManifest` / `DockerTag` / `DockerRef`、哨兵 `ErrManifestNotFound` / `ErrTagNotFound`、接口 `DockerStore`；`Store` 增 `Docker() DockerStore`（全部仅导出面，无内部结构泄漏）。
- 新增 `substores_docker.go` 实现（沿用 M1 wrapExec 错误标注范式）：
  - manifests/tags 单行 CRUD（upsert 语义：manifest 刷新元数据列、tag 重指 digest）；
  - `PutRefs`：单 manifest 引用集**整体替换**（DELETE+INSERT 同事务，空集即清空）；
  - `ListTagsByImage` / `ListManifestsByImage`：repo+image 作用域、tag/digest 字典序；
  - `ListImages(repoKey, after, limit)`：catalog 事实源（docker_manifests DISTINCT image），字典序 + **exclusive keyset 游标**（`image > ?`），limit<=0 为全量；
  - `DeleteManifest`：manifest 行 + 级联清指向它的 tags + 它发出的 refs，**单事务**（架构 §11.12「manifest 删除同事务清 refs/tags」约定的存储层落点）；缺行返回 `ErrManifestNotFound`；
  - `DeleteImage`：三表同事务整体清除，幂等，返回移除的 manifest 行数（缺 image 不是错误，404 决策归调用方）；
  - `DeleteRepoRefs`：docker_refs 无 DB 级 FK 的专用拆库钩子（对齐 repositories 级联缺口）；
  - `RefsByBlob`：repo 作用域 blob 引用预检（idx_docker_refs_blob 的用途，对齐 idx_nodes_blob）。
- `store.go`：`sqliteStore` 增 `Docker()` 访问器；`var _ DockerStore = (*dockerStore)(nil)` 编译期断言。

### ③ 建表零行为变化 + 一致性契约

- `doc.go`：新增「docker_refs consistency contract (architecture 11.12)」专节——无 FK 的理由（复合主键部分列不可声明跨表 FK）、四条契约（DeleteManifest 同事务级联 / DeleteImage 三表同事务 / 拆库必须调 DeleteRepoRefs 否则 refs 变成永久 GC live 垃圾 / GC mark = nodes ∪ docker_refs 与孤儿 tag 归属服务层）；并补 layout 图（substores_docker.go）与 docker node 布局约定。
- M1 测试零回归：仅两处**口径演进**改动（见下），无断言弱化；全仓 `go test ./...` 11 包全绿。

## 规格依据与口径说明

- DDL 唯一依据：docs/design/architecture.md §6「002_docker.sql」定稿块（572-611 行）——列定义/主键/索引/FK 声明逐项一致；§11.12（一致性契约）、§4.4 注记（GC mark = nodes ∪ docker_refs）写进 doc.go 与 002 注释。
- **「三表 + 两索引」的 AC 措辞与架构定稿有出入**：架构 §6 定稿实际含**三条**索引（两条 `(repo_key, image)` + `idx_docker_refs_blob`）。以「严格按架构 §6 定稿 DDL」为准，落了三条；请 reviewer 对照时以架构定稿块为准（AC 摘要疑为笔误，`idx_docker_refs_blob` 在架构内有明确用途注记：删 blob 前查引用）。
- 「按 repo+image 前缀查询」实现口径：repo+image 作为 /v2 name 前缀的**作用域**（ListTagsByImage/ListManifestsByImage 精确匹配 image，字典序返回）+ catalog 侧 ListImages 全名字典序 keyset 分页——对应 §5.3 映射表 `tags/list` 与 `_catalog`（T-40 的 n/last 语义）与 T-35 AC② 的 ListTags/ListImages。未加「image 子树前缀模糊列举」端点（registry API 无此端点，catalog 按全名分页）；若 T-35/T-40 需要可加方法，不破坏既有签名。
- digest 存**裸 hex**（不带 `sha256:` 前缀），与 blobs 主键同源（架构 §6「blob 主键同源」注记 + §5.3 裁定 2）；adapter 负责剥前缀。
- 低置信度项：无（本票全部行为均有架构定稿 DDL 或 M1 既有模式背书）。
