# T-154: OIDC Provider 实现（go-oidc/v3）

## 工作内容

实现 OpenID Connect 身份提供者，使用 `github.com/coreos/go-oidc/v3` 进行 ID Token 验证，
覆盖 OIDC Bearer 认证臂、PKCE 登录流、可配置 claims 映射。

## 修改文件

### `internal/auth/oidc.go` (NEW - 347 行)
- `OIDCConfig` 结构体：IssuerURL / ClientID / ClientSecret / RedirectURL / Scopes / UserClaim / GroupClaim / AdminGroup
- `OIDCUserResolver` 接口（导出，供外部测试）
- `OIDCProvider` 结构体：实现 `IdentityProvider` 接口
- `NewOIDCProvider()`：OIDC 发现、验证器构造、oauth2.Config 初始化
- `Authenticate()`：ID Token 校验 → claims 提取 → UserClaim/GroupClaim/AdminGroup 映射
- `Resolve()`：委托给 OIDCUserResolver 查找本地用户
- `GeneratePKCEPair()`：PKCE S256 verifier + challenge 生成
- `extractClaim()`：嵌套 claims 提取（dot-separated path）
- `extractGroups()`：groups/roles 提取（JSON array / single string）
- `unmarshalClaims()`：结构化 + raw map 双重解析（导出供测试）

### `internal/auth/deps.go` (MODIFIED)
- `userStoreAdapter` 新增 `GetByProvider()`：通过 List() 迭代匹配 (provider, providerID)
- `adaptUser()`：添加 ProviderLocal 默认值

### `internal/auth/oidc_test.go` (NEW - 813 行)
- `mockOIDCServer`：基于 httptest + jose 的完整 mock OIDC（discovery / JWKS / token 端点）
- 测试覆盖：
  - `TestOIDCProvider_NewProvider`：正常发现 + 缺少参数错误 + 默认值
  - `TestOIDCProvider_Authenticate_Success`：有效 token 提取 name/groups/providerID
  - `TestOIDCProvider_Authenticate_AdminGroup`：admin_group 映射
  - `TestOIDCProvider_Authenticate_CustomClaims`：自定义 user_claim/group_claim
  - `TestOIDCProvider_Authenticate_FallbackToSub`：缺失 user_claim 回退到 sub
  - `TestOIDCProvider_Authenticate_ErrorCases`：过期 / 错误 issuer / 错误 audience / 垃圾 token
  - `TestOIDCProvider_Authenticate_GroupClaimVariants`：数组 / 单个字符串 / 空数组
  - `TestOIDCProvider_Resolve`：已存在 / 不存在 / nil resolver
  - `TestPKCE`：生成 / S256 验证 / 唯一性
  - `TestOIDCConfig_Defaults`：空配置默认值 / 自定义覆盖
  - `TestOIDCProvider_OAuth2`：oauth2.Config 字段验证

## 规格依据

- ADR-0020：OIDC 身份提供者架构
- 高置信度实现：ID Token 验证（JWKS + issuer + audience + expiry）对齐 go-oidc/v3 官方 API
- 中置信度处理：UserClaim/GroupClaim 映射行为通过 httptest mock OIDC 固化

## 遗留问题

1. `metadata.User` 目前缺少 Provider/ProviderID 字段，`adaptUser()` 固定返回 ProviderLocal。
   migration 008 DDL 已有但 Go struct 未更新——需要 T-154 后续的 metadata 层更新。
2. `userStoreAdapter.GetByProvider()` 使用 O(n) List() 遍历——可在 metadata 层增加索引后优化。
3. pre-existing `internal/httpapi/system.go` 的 minio API 不兼容（与本 ticket 无关）。
