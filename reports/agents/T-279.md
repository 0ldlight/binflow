## 做了什么

1. **文档 v1 + 验签链**（`internal/license/document.go`）
   - `<base64url(payloadJSON)>.<base64url(ed25519Sig)>`，签名对象 = payload 解码后的原文字节（无再规范化）；外围空白 TrimSpace（curl -d @file 尾随换行容忍，测试钉死）。
   - 链序 = §15.1.2：split → base64url decode → JSON unmarshal → typ/alg/kid/ver 静态校验 → 字段形状（tier 闭集/licenseId 非空/RFC3339/社区档才允许 perpetual）→ ed25519.Verify → 时间窗（notBefore/expiresAt 双侧 1h leeway）。
   - 六个 sentinel（ErrBadDocument/ErrBadHeader/ErrUnknownKey/ErrBadSignature/ErrExpired/ErrNotYetValid）+ `IsVerificationError` 分类助手；错误文本不含 payload/licensee/签名（NFR-S52）。未知 JSON 字段容忍（ver 守版本契约）。
   - 表驱动 24+ 用例（`document_test.go`）：篡改 payload 一字节 / 篡改签名一字节 / 错 kid / 空 kid / 错 typ / 错 alg / ver=2 / tier 越集 / 过期超 leeway / notBefore 未来超 leeway / leeway 边界内两例（30min 内仍过） / pro 无 expiresAt / 三段 / 非 base64url / payload 非 JSON / 签名长度错 / 时间戳坏 / **异 issuer 同 kid 密钥签发 → ErrBadSignature**（=「测试密钥文档在内嵌公钥下拒」的机制）。
2. **档位闭集 + Manager**（`internal/license/manager.go`）
   - `Tier`（community<pro<enterprise 全序，代码常量）；`State` 为 atomic.Pointer 快照，读零锁；`State()` 对快照做时钟求值（过期/未生效 → 降 community，NFR-S53「不维持不可验证高档位」；Expired 标记区分「从未装」与「装了已过期」）。
   - `Install`（验签全过才 PutLicense 原子替换 + 快照刷新，D7 失败不动现状态）/`Uninstall`（幂等降地板）/`Load`（启动重跑同一验签链；坏行 WARN + license.invalid + community，不拒启动）/`Run`（每日 ticker，间隔可注入；降级迁移只 audit 一次）/`State`/`AddonEnabled`（§15.2.3 单求值点：disabledSet → tier 全序 → 白名单；地板不受白名单约束）/`PackageTypeAvailable`（织入点 2 的同值拼写，minTier 由调用方 registry 解析——防环取原语参数）。
   - `Options.VerifyKeys` 注入缝（生产 `EmbeddedVerifyKeys()`，测试自生成钥对——不碰生产常量、无 build tag）；`Options.Now` 时钟注入（过期测试零 sleep）；`Options.DisabledCSV` = addons.disabled（解析 + 五核心 id WARN 但生效）。
   - 并发：`-race` 下 4 writer × 800 次 Install/Uninstall × 4 reader 持续断言快照自洽（Licensed⇒licenseId 非空 + tier ∈ 付费闭集；未装 ⇒ 无 licenseId）零撕裂。
3. **migration 012**（双方言幂等）
   - `sqlite/012_license.sql` + `postgres/012_license.sql`（语句在共同子集内逐字同步；`CREATE TABLE IF NOT EXISTS licenses(id INTEGER PRIMARY KEY CHECK(id=1), …, expires_at TEXT NULL=perpetual)`；postgres README 版本史追加 012 条目）。
   - metadata：`LicenseRecord` + `LicenseStore`（GetLicense 空= nil,nil；PutLicense 单事务 DELETE+INSERT 原子替换；DeleteLicense 幂等）+ `Store.Licenses()`（嵌入 wrapper 的测试 fake 不受接口加方法影响）。
4. **REST 三端点**（`internal/httpapi/license.go` + router.go + server.go Deps.License）
   - `GET /binflow/api/system/license` = CapSystemRead，回显 §15.1.4 字段全集（licensed/tier/licenseId/licensee/issuedAt/notBefore/expiresAt/perpetual/daysToExpiry/addons/limits），**不回显 doc 原文**；addons = 文档显式白名单（null=档位全解锁；有效视图归 T-282 /api/v1/addons）。
   - `POST` = CapSystemWrite，body=纯文本文档（64KiB 上限），验签全过 → 201 + 状态体即时生效；失败 400（`LICENSE_EXPIRED — document is expired / not valid yet`、其余一律 `LICENSE_INVALID — verification failed`，不泄内部细节）；持久化失败走 5xx 家族（busy→503）且**不**记 license.invalid。
   - `DELETE` = CapSystemWrite，200 纯文本 `License removed successfully.`，幂等（未装实例同样 200；仅真实移除时审计）。
   - 路由守卫计数 25→28（t215_guard_test 常量按其自身规程更新并注明 T-279 三行来历）。
   - readonly_admin GET 200 / POST+DELETE 403；普通用户 GET 403；匿名 401（真实栈 + 真实二进制双证）。
   - 审计：license.install/delete/invalid（actor/tier/licensee/licenseId/expiresAt——licensee 仅入审计不入 slog，NFR-S52 的 ADR 例外）。
5. **降级与无撕裂**：见 2/3；DB 行外部篡改后重启 = cmd 侧两次 openStack 实测（readyz 200 + WARN + community + system-actor license.invalid + 行保留作证据）。
6. **装配**（cmd/binflow-server/main.go）：openStack 构造 Manager（内嵌公钥 + md.Licenses() + BestEffort audit）并同步 Load；runServe `go stack.licenseMgr.Run(ctx)`（信号 ctx 同 HTTP drain）；newAssembledServer `deps.License = stack.licenseMgr`。DisabledCSV 暂传空串——config 键 `addons.disabled` 归 T-283 接线（见遗留）。

## 规格依据与裁定

- ADR-0032 决策 1/2/4、architecture §15.1.1~§15.1.5、§15.5（migration 012）、NFR-S52/S53、FR-84-AC1~AC7。
- **PRD↔ADR 分歧按 T-293 登记口径取 ADR**：路径 `/api/system/license`（非 PRD 的 /api/v1 前缀）；POST 201（非 PRD 200）；D6 到期即降无 grace（PRD Q6 的 30 天宽限不采纳）；GET 无 `source` 字段（licensed 承载同一事实）。
- 自有裁定（均已在代码注释+测试固化）：① leeway 双侧 1h（§15.1.2 字面），过期判定 = expiresAt+1h；② `addons: []`（空数组）≡ 缺省（档位全解锁）——空白名单是无意义授权；③ State() 读时对快照做时钟求值（ticker 仍负责审计/日志迁移与 DB 重验）——比「快照原样直到 tick」更紧的 fail-safe，且保证 GET 展示与门控判定同源不分叉；④ 内嵌验签钥 = T-279 bootstrap 随机生成、**仅公钥入库，私钥即刻销毁**（写密钥是 stop-and-ask 红线）——后果：当前 stock 二进制验证不了任何文档、恒 community 地板（= 不变量 1 的 fail-safe 姿态）；首发签发时 release 侧用 T-281 keygen 生成权威钥对并替换该单一常量。
