## 1. Schema 定座留痕（T-342 §5 D-2①「须 architect 定座」→ 票内定案）

**chartsBaseUrl per-protocol 槽**（ADR-0041/0042 均未涵盖，引用既有先例定案）：

1. **存位**：remote 仓 canonical config JSON（`repositories.config`），**不加 remote_configs 列** —— enableTokenAuthentication/contentSynchronisation 先例（T-317 注释明言「no remote_configs columns: booleans default … zero migration surface」）。engine（repoPolicy）与 helm memberContext 从同一 JSON 读。
2. **per-protocol 边界**：仅 `packageType=helm` 的 remote 接受；其它包型携带 → 建仓/改仓 **400 点名字段**（`chartsBaseUrl %q is not accepted (the divergent charts fetch base is a helm remote-repository behavior)`）。定案依据 = **validateLocalKeypairRef 先例**（keypair_config.go：非 debian/rpm local 仓携带 keypairRef「refused by name——the inert-field trap」；静默接受产 inert 字段、静默丢弃让管理员误信生效，两害取明拒）。取舍登记：Artifactory 迁移脚本在非 helm remote 上携带此字段会得 400 而非被忽略——与 keypairRef 同款取舍，明拒优于暗弃。
3. **值域**：绝对 http(s) URL（scheme/host 校验、尾斜杠裁剪）；显式 `""` = 清除；REST 运输层 `setStr` 语义下空串不可作清除载体（与 username/url 同款，票内不另开缝）。

## 2. 设计摘要

### 2.1 引擎缝（internal/remote/fetcher.go）

- **URL 覆盖缝**：`contactUpstream` 的出站解析收敛到 `outboundFor(row, cfg, pol, repoKey, upPath, kind, target)`——`target != ""`（FetchAbsolute）走无凭据外部客户端 + `Request{URL}`；否则 chartsBaseUrl 生效时 content 类换基址（同 origin → 仓凭据客户端 + 绝对 URL 覆盖；**异 host → 无凭据客户端**（BaseURL=charts base）——redirect 链的 Authorization 剥离规则前移到取数源头，仓凭据绝不发往第三方 host）；否则原 path-joined。`chartsBaseFor`：helm + 非空 chartsBaseUrl + **content 类**才换基址（index.yaml 等 metadata 类恒走仓 URL——基址是「chart 存放地」非「索引挂载地」）；package-type 门为手改行的纵深防御（非 helm 一律不换）。
- **FetchAbsolute**：`Fetch`/`FetchAbsolute` 共享 `fetchFlow`（target 穿参），全套 RE-04 状态机复用（负缓存/TTL 分类/单飞/双查/stale 降级），落盘即 land() 原链（blob-first、checksum 寻址、TTL 行、GC hold）。差异两点（均为刻意）：① 无凭据 egress（`externalClientFor`：独立客户端池 `extClients`，key=`repoKey\x00baseURL`，签名=豁免旗标+超时；Forget 清理）；② **第三方故障不写 assumed-offline 窗口、不受其静默**（attempt 的 offline 窗口检查与 mapTransportFault/mapUpstreamStatus 的 markOffline 均按 external 跳过；无副本 404 文案点名 external target 而非谎称 upstream offline）。hardFail 的 502 口径不变。
- T-363 登记的「singleflight/assumed-offline 收编」评估：FetchAbsolute 天然走同一 singleflight 键空间（repoKey+path）——即 T-363 D-1 尾巴中「T-367 引擎缝可评估收编」的自然兑现。

### 2.2 服务缝（internal/repo/remoteexternal.go + api.go）

- `RemoteExternalPlane` 能力缝（RemoteV2Plane 先例——type-assert Service，不扩 Service 主体、不破测试 fake）：`FetchExternal`（直连面：读门 + 类门）与 `FetchVirtualExternal`（成员面：成员在序 + remote 型守卫，ReadVirtualMember 口径，不重跑成员权限）。core 共享：FetchError→StatusError（unfound 包 ErrNodeNotFound 供适配层换文案）、MISS 臂 GC hold 释放 + artifact/cached webhook、审计一行（成员面记 virtual key + resolvedFrom detail，getVirtual 口径）。
- RemoteFetcher 接口加 `FetchAbsolute`（引擎满足，编译钉）。
- ClassReader 契约注释补一句 T-367 widening note：helm virtual 的 memberContext 经此缝读成员 canonical config 的公开字段 chartsBaseUrl（非保护字段；canonical 形态永不含口令）。

### 2.3 配置槽（internal/repo/config.go）

- remoteConfig/remoteConfigInput 加 `chartsBaseUrl`；`parseRemoteConfig(config, packageType)` 签名加包型（Create/Update 两调用点透传）。canonical 回显 omitempty。
- **REST 运输层**（internal/httpapi/repositories.go，area 外最小增量）：repoConfig 加 `ChartsBaseURL string`，configJSON remote 臂 `setStr`；GET 侧经既有 `configuration` verbatim 回显（无需改动）。

### 2.4 消费点（internal/adapter/helm）

- `serveRemoteExternal`/`serveVirtualExternal`：优先经 RemoteExternalPlane（落盘 + HIT + `X-Binflow-Upstream` + virtual 面加 `X-BinFlow-Resolved-From`）；seam 缺席（裸测试 double）回退 T-313 直通面（旧行为保留为降级路径）。unfound 族维持本面 404 文案，其余 StatusError verbatim。
- `memberContext`：识别基址 = 配置的 chartsBaseUrl（读成员仓 config JSON），缺省回退 cfg.URL（S10 回退链）。
- `_transitive` 不动（T-313 起即 path-joined 引擎取数、天然落盘）；本票为其补 live 双跳链验证（上游本身是 BinFlow virtual）。

### 2.5 Rider：virtual 成员类型收紧（conductor 裁定，T-365 登记转来）

- `validateV2MemberTypes(virtualPackageType, memberRows)`：**v2 家族（docker/helmoci）virtual 的成员须同包型**——helmoci virtual 配 docker 成员 → 400；docker virtual 配 helmoci 成员同拒（矩阵解封 T-380 后生效，当前该臂先撞 M3 矩阵 400，测试断言矩阵文案并注明）。文案照混仓家族模式：`virtual repository cannot mix the helmoci and docker package types (a helmoci virtual aggregates helmoci repositories only); member %q is a %s repository`。挂接在 validateHelmFamilyMix 之后（helm×helmoci 混仓规则不动，双向维持）。**范围**：照裁定原文限 v2 家族；非 v2（如 helm virtual 配 docker 成员）不在收紧范围（测试断言放行，票内登记归 conductor 后续裁）。

## 6. 登记与遗留

1. **area 外增量**：internal/httpapi 一字段运输透传（§2.3）——AC1 REST 腿的最小必要；校验/规范化全部在 repo.Service（该 struct 的架构注释自述如此）。供 conductor 复审归档。
2. **成员同型的全包型推广**：rider 限 v2 家族（裁定原文）；helm virtual 配 docker 成员当前放行（成员 miss 于聚合，无害但语义松）——是否照「virtual 成员须同包型」推广到全部包型归 conductor 后续裁（一次推广可能碰既有测试的面）。
3. `_external` 面的 HEAD：GET-only 405 维持（helm.md §2 未列 HEAD）；live #9 的 GET 探头绕开。
4. `_transitive` 的上游 404 负缓存：path-joined 键路径照写（引擎原生），无新增。
5. FetchAbsolute 与 v2 面（RemoteV2Plane）不交叉：OCI 取数不走 _external（协议无此面）；如未来 OCI 依赖图需要外部取数，缝已就位。
6. 无阻塞项。
