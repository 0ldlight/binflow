## 1. AC② D-3 — repositories.spec.ts 删仓 reason 口径对齐 ADR-0016

**改前复现**（自起实例 127.0.0.1:18093，`make console && make build` 真二进制内嵌本次
console 产物）：

```
$ BASE=http://127.0.0.1:18093 npx playwright test e2e/repositories.spec.ts
  ✘ repositories.spec.ts:52 local generic full lifecycle ...
    - unexpected value "HTTP 400：repository is not empty: \"t99a-mt3wdb9jm…\"
      holds 2 node(s); retry with deleteContent=true to remove them"
    > 145 | toContainText('holds 1 node(s)')   ← 断言期待 1，服务端实际 2

**口径依据**：`internal/repo/service.go:2085` 删仓守卫用 `ListByPrefix(ctx, repoKey, "")`

**改动**（`web/e2e/repositories.spec.ts:144-147`）：断言 `holds 1 node(s)` → `holds 2
node(s)`，注释写明 ADR-0016 口径（1 文件 + 1 材料化祖先目录）。

**改后**：repositories.spec.ts 4/4 绿（lifecycle 5.6s，含删仓双段流 + 内容 404 断言）。

## 2. AC③ D-4 — governance.spec.ts GC 用例放行 migration 501 未配置语义

**服务端语义实证**（未配置迁移的默认实例）：

```
$ curl -u admin:password http://127.0.0.1:18093/binflow/api/v1/storage/migration

```

契约面（architecture.md §端点表 :1022-1025）明文：**「未处于双写装配 → 501
『migration is not configured』，非 404」**——规格漂移、契约正确，**无契约漂移项**。
UI 侧行为正确：`MigrationPanel.tsx`（只挂在 GCPage）对 501 降级为
`migration-unconfigured` 一句提示（T-160 AC①），非错误态。

**改动**（`web/e2e/governance.spec.ts`，三处）：

1. 词表常量 `MIGRATION_501`（:72-78）：`/^501 \S+\/binflow\/api\/v1\/storage\/migration$/`
   放行项，注释说明 T-164 语义 + 仅 GC 用例可达（MigrationPanel 只挂 GCPage，grep 实证）。
2. GC 用例正向断言（:215-217）：`migration-unconfigured` 提示可见——把「放行」落成可验证
   的预期态（501 是既定语义且 UI 已消化，不是服务端故障）。
3. GC 用例收尾零 5xx 账面（:269-271）：`errors.filter(!MIGRATION_501.test)` 后断言空——
   其余 5xx 仍零容忍，放行面最小化。

**改后**：governance.spec.ts 4/4 绿（单独跑 49.3s；全量并行轮亦绿，见 §4）。

### 附带必要改动：audit 用例超时余量（D-2 同族的 e2e 面）

governance.spec.ts 为 serial 模式——audit 用例（:79）挂掉会短路后面全部用例，D-4 的
验证路径根本走不到。改前两连复现：

```

20.8s / 35.2s / **50.0s**——最后一轮在旧预算下必挂）。处置：`test.setTimeout(60_000)`
加倍余量（governance.spec.ts:81-84，断言本体零改动）。**不改 playwright.config.ts**
（超出本票 area）；全局超时是否上调归 conductor/conductor+qa 另议。
