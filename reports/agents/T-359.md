## 1. 决策要点（八轴全 A）

| 轴 | 决策 |
|---|---|
| 事件总线形态 | 单一进程内总线 `internal/webhook.Bus`——域缝一行 `Emit(ctx, Event)`；门控/订阅匹配/fan-out/入箱收敛单点；与 audit.Recorder **平行不合并**（契约/可靠性档位/脱敏方向三差异） |
| 订阅模型 | push-only（HTTP POST outbound，2xx=成功；3xx/4xx/5xx/超时=可重试）；at-least-once + 接收端幂等义务文档化；**test 端点同步直发**（不入 outbox、不重试，响应带 attempt 结果）；pull 面与 inv-4 I4 registration 不平移（留痕 M14+） |
| 投递器 | 新建 `internal/webhook.Dispatcher`，**复刻** replication Engine 队列模式（DB 任务行 + 退避切片 + signal/drain + 启动 sweep），不共用实例（域语义不渗透）。参数：尝试上限 10、退避 2s×2 递增 cap 10min、attempt 超时 10s、worker 4、超限→dead（可查可重放）；启动 sweep delivering→pending；优雅停机接线 |
| 入箱时序 | 同步小事务 fan-out（域提交后、响应前，单 DB 事务批插逐订阅行）；入箱失败 = WARN + `enqueue_failures_total` 指标，不阻塞主路径 |

| 签名与 secret | HMAC-SHA256 over 存储字节 + per-subscription secret；头名/编码随 T-358（K49）；secret 存 enc:v1 AES-256-GCM（复用 `BINFLOW_REMOTE_CREDENTIALS_KEY` 主密钥族）；POSTURE 三句 + 回显哨兵 write-only PUT |

| 第 19 槽 | ID="webhook"、**Kind=KindFeature**（不新增第三值——"feature-int" 是注记非 Kind）、MinTier=pro（Q4 暂行，T-358 取证后翻转 = slots.go 一行）；三缝：REST 403+头 / Emit 首行不入箱（gate func 注入，不 import license）/ 熔断期投递暂停不丢 |

## 2. 备选对比留痕（淘汰理由）

- **各域自挂（总线轴 B）**：匹配/门控/入箱在 N 个域包重复，订阅模型演进 = N 处改；「事件织入面降级不入箱」无法单点收敛。
- **通用事件日志底座（轴 C，event-sourcing lite）**：audit（best-effort、内部 schema、入库 redact）与 webhook（at-least-once、外部 envelope、出站签名）可靠性档位与脱敏方向相反——合并 = 为想象买单。
- **pull 模型 / I4 registration 全平移**：单体单消费者（无 Worker/Xray 对端），为不存在的消费者建面。
- **泛化共用 replication.Engine**：replication 任务 = blob 引用 + 凭据 + 平面协议；webhook 任务 = 内嵌信封 + 签名头——共用引擎使两域任务语义互相渗透。
- **域事务内真 outbox**：repo.Service.Put 无贯穿 tx 结构（audit 同为提交后旁路），为强一致重写主路径违背「旁路增量」选题前提；进程内缓冲在 kill -9 窗口丢事件（L06 红线）。
- **secret 明文列 / mTLS**：前者违 ADR-0012「永不存明文」纪律；后者不适配内网 CI 简单端点形态。
- **SSRF 默认放行（replication 同款）**：三先例（replication/auth 测试连接）的私网目标是静态配置面；webhook URL 是 REST CRUD 动态面 + 任意外发端点——SSRF 升梯向量，默认拒 + 显式开关。
- **仅 wired 子集注册**：闭集缩水使「可订阅但无触发」退化为静默不存在，文档与订阅校验面失真。
- **新增 Kind "feature-int"**：Kind 的路由语义（package-type ID 即路由键）下 integration 特征零路由差异；动闭集断言与 /api/v1/addons 呈现为零收益。

## 3. 风险

1. **wire 字面量未锚**（K47/K49/K48 + 单型/多型订阅形态）：ADR 已留「锚点回填位」+ 效力序（用户裁决 > webhook.md > ADR > PRD 暂行）；UNIQUE(event_type,url) 若被多型形态证伪 → 子表 additive 迁移，机制不变。T-362/364 开工前置 = T-358 交付（依赖序已在 PRD §1.3）。
2. **退避/上限参数为 ADR 自有值**（官方重试语义未取证）：若 T-358 锚定官方可观测重试行为，wire 可观测面照锚点翻转、内部机制条款不变（锚点回填位已声明）。
3. **入箱 best-effort 的丢失窗口**（域提交成功 → 入箱前 kill -9）：以 `enqueue_failures_total` 指标显式可见化；L06 零丢承诺范围 = 已入箱事件（ADR 已把边界写死，防 QA 断言扩大化）。
4. **熔断期投递暂停的积压增长**：行不尝试故不死信——长期熔断 + 高事件量下 queue_depth 无界；缓解 = 水位指标可见（启动行 + gauge），处置归运维（清熔断或删订阅）。
5. **area 纪律**：域缝插入行（repo/adapter 各一行 Emit）与并行票可能重叠——ADR「后果」已标注归事件织入大票窗口独占（PRD §1.3 既定），conductor 派发时执行。
