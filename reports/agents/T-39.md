## 实现

### ① PUT（DE-08，`manifest.go` `putManifest`）

校验链（每一步失败都在任何状态变更**之前**回答，顺序即注释 ①~⑦）：

1. **reference 形状**：`sha256:` 前缀 → digest 文法（`parseDigestParam`，失败 400 `DIGEST_INVALID`）；否则按 tag 字符集 `[a-zA-Z0-9_][a-zA-Z0-9._-]{0,127}` 边缘镜像校验（失败 400 `MANIFEST_INVALID`）。
2. **有界读体**：`http.MaxBytesReader` 上限 4MB（§6.5 定案③；chunked body 同样被计数，不信任 Content-Length）；超限 400 `MANIFEST_INVALID`。
3. **结构性解析**（`parseManifest`，按 Content-Type 选 schema 族——docker-registry.md §3#5）：
   - schema1 / schema1+prettyjws → 400 `MANIFEST_INVALID`（暂行口径，M2 不支持）；
   - Content-Type 缺失 → 400（透传存储没有值可存）；
   - 四种已知类型走专形：index/list 要求 `schemaVersion`+`manifests[]` 且逐 child 有 digest；image 要求 `schemaVersion`+`config.digest`+layers 逐条 digest（`layers:[]`/缺省 = 合法 scratch）；
   - **未知 Content-Type 不拒收**（PRD 透传裁定，R3 中间立场）：按 body 自身形状判读——有 `manifests[]` → index 语义；有 `config`/`layers` → image 语义；两者皆无 → 400。Helm OCI config 等 FR-12 承载路径由此外）。
   - 解析用指针探测区分「字段缺」与「字段 null」；`schemaVersion:0` 与缺字段用原 body 复查区分。
4. **digest 判定**：digest = body 逐字节 sha256；by-digest PUT 与计算值不符 → 400 `DIGEST_INVALID`（FR-9-AC4）。
5. **引用完整性**（架构 §5.3 链②③）：config/layer digest 逐条查本 repo 的 `<image>/blobs/<hex>` node 在场；index 子 manifest 按其 descriptor mediaType（四种 manifest/index 族）改查 `<image>/manifests/<hex>`——**lazy**：只查在场性，从不递归解析子 manifest 内部。空层 `sha256:a3ed95ca...` 豁免（T-38 常量直用，客户端根本不上传它）。缺失 → 400 `MANIFEST_BLOB_UNKNOWN`（官方码，§10 建议栏 1；D13b）。probe 的非 miss 失败（权限/store 故障）如实上抛渲染，不误报 BLOB_UNKNOWN。
6. **落盘两步**（T-35 服务契约「adapter 先走普通 blob 路径」的忠实落地）：
   - `svc.Put` 把 body 走 blob 面：`<image>/blobs/<hex>` node（manifest 即 blob——spec 的 `/v2/<name>/blobs/<digest>` 同样供应 manifest，且该 node 是后续 index push 引用完整性的探测锚点）；
   - `svc.PutManifest` 写 `<image>/manifests/<hex>` node（mime = manifest Content-Type，FR-7-AC4）+ manifests 行 + tag 指针（Q4：同 tag 再推 = 重指）+ refs 台账。
   - **两条 node 路径分离是关键**：PutManifest 的幂等探测键在 MANIFEST 路径——先写 manifest 路径再调 PutManifest 会撞上幂等分支导致 manifests 行永不落（本票实现期实测踩中并修正：症状 = PUT 201 但 by-digest GET 404）。blob 路径先行不触发该分支。
7. **201** + `Location`（相对路径 `/v2/<name>/manifests/sha256:<hex>`）+ `Docker-Content-Digest`；body 含 subject → 附 `OCI-Subject` 头（§3#10 照抄；referrers 端点本身维持 DE-15 的 404）。subject digest 形状非法时静默降级为无头（§3#8「解析失败仅日志」姿态）。

### ② GET/HEAD（DE-09）

- by-digest（`sha256:` 前缀直查 manifests 行）/ by-tag（`ResolveTag` 取当前指针再取行）；**serving truth 是 manifests 行**——Content-Type 与 size 取自行，不取调用方。
- body 与 push 原文**逐位一致**：读取路径流式拷贝 `<image>/manifests/<hex>` node 的原始字节，从不重序列化（重序列化会移动 digest）。
- `Docker-Content-Digest` + 存储 Content-Type + Content-Length；HEAD 只有头。
- **Accept 协商**（`acceptAllows`，§4 校准）：Accept 集含存储类型 / `*/*` / `type/*` → 200；集合不含且非通配 → **404 `MANIFEST_UNKNOWN`**（不转换——schema2→1 降级明确不做）。Accept 缺失视为全收（curl/老工具依赖）；全畸形 token 视为无约束而非全拒。
- tag 覆盖后 by-tag 服务新 manifest、旧 digest 仍可取（FR-9-AC2）。

### ③ DELETE（DE-10）

- **仅 by-digest**：`svc.DeleteManifest`（node + manifests 行，store 同事务级联 tags/refs——FR-9-AC6）→ **202**；随后 by-digest / by-tag 均 404 `MANIFEST_UNKNOWN`；被引用 layer 不受影响（GC 归属）。
- **by-tag → 405 `UNSUPPORTED`** + `Allow` 头（v1.1 定案，R2；官方 spec 禁止 by-tag），tag 本身不受影响仍可 GET。404（未推过的 digest）/ 403 DENIED / 401 挑战按哨兵映射。

### ④ 分派与错误码（最小增量）

- `handler.go`：repo 门 + `authorizeRoute`（T-37）之后按 tail 前缀 `manifests/` 分派（与 blobs 同构的一行增量；token/scope/权限门零改动）。
- `errors.go` 新增三码：`MANIFEST_UNKNOWN` / `MANIFEST_INVALID` / `MANIFEST_BLOB_UNKNOWN`（信封复用 T-33 的 `writeSpecError`，api-version 头全响应携带）。
- 三张错误映射表（put/read/delete）覆盖 T-35 全部哨兵：`ErrForbidden`→403 DENIED、`ErrUnauthorized`→scoped 挑战、`ErrInvalidManifest/Tag/Image`→400 MANIFEST_INVALID、`ErrInvalidDigest`→400 DIGEST_INVALID、`ErrEngineClosed`→503 UNAVAILABLE、其余→500 UNKNOWN + ERROR 日志。

## 关键裁定记录

1. **未知 Content-Type 的 body-shape 判读**（R3 中间立场的落地细节）：PRD 只说「透传不白名单」，没说怎么验。裁定：未知类型不直接 201，而是按 body 自身形状（manifests[] / config+layers）套用同一条结构性校验——既保透传（Helm config 的 `"config":{"mediaType":"application/vnd.cncf.helm.config.v1+json",...}` 实测 201 + 取回同 CT 逐位一致），又不给「任意 JSON 假manifest」开口子。两者皆无 → 400。
2. **manifest 落盘 = blob node + manifest node 双行**：T-35 契约「body 先走 blob 路径」按字面落地为 `<image>/blobs/<hex>` node（不是内部 session 直灌）。收益：manifest 可经 `/v2/<name>/blobs/<digest>` 取（spec 允许）、ledger 带真 sha1/md5、index 引用完整性探测有锚点；代价：一个 image 的 node 树多一行（FR-8-AC7 去重语义不变——同 digest 只有一份物理 blob）。
3. **`schemaVersion:0` 合法**：`hasSchemaVersion` 用原 body 指针探测区分「值 0」与「字段缺」，只有字段缺才 400。

## 遗留 / 交接

1. **T-40（catalog/tags）**：路由分派点已留（tail 非 blobs*/manifests* 落基座 404），`ListTags`/`ListImages` 的 service 面已就位；`ErrInvalidCursor` 哨兵在 T-40 的 `n`/`last` 渲染处消费。

3. **同 digest 重推换 Content-Type 的边角**：body 不可变（digest 同 = 字节同），但同一 digest 用不同 CT 重推会刷新 blob/manifest node 的 mime 列，manifests 行的 media_type 因幂等分支**不动**——GET 的 serving CT 取自 manifests 行（稳定），item info 的 mimeType 取自 node（可能被刷新）。两源在病态重推下可分歧；M2 无影响（客户端不会同 digest 换 CT），记录备查（review 范围外确认「真但无 M2 触发路径」）。
4. **`schemaVersion` 语义深度校验未做**（如 schema2 应为 2）：结构性存在性校验已够 M2 兼容面（distribution 参考实现同样只验结构不验值域）；若 T-43/T-44 conformance 暴露客户端依赖再加。
5. **buildx/crane/oras 本机不可用**：D08b 已走 curl 手构造降级（票据允许）；T-44 需在可控环境补 buildx 真多架构 + crane 验证（R11 预告路径）。
6. **docker login/pull 本体**：环境项（daemon insecure-registries），与 T-37/T-38 留档同因同解，归 T-44/T-45。
7. **DELETE 后 manifest body 仍可经 `/v2/<name>/blobs/<digest>` 取回**（review non-blocking #5，实测 200）：blob node 不随 DeleteManifest 删除、回收归 GC——与 DE-14（无单 blob 删除）一致，设计内。QA/文档（T-43/T-46）勿误报为泄漏。
