## 一、做了什么

### 0. 跨 area 补缝（先行说明，需复核）

派单语假定「T-71 done——你的聚合在协议层消费其成员序」，但 T-71 的成员序（`virtualMemberOrder`）是 `internal/repo` 的**未导出**函数，且聚合必需的另两件事——**免重授权的逐成员元数据读取**（local 成员 node+blob / remote 成员走 T-66 引擎链）与**免授权的成员 node 事实列举**（pypi simple 的收集输入）——在 repo.Service 上不存在；适配器持有的缝（ClassReader/BlobLedger/NodeReader/storage.Engine 的各种组合）凑不齐，而经 `svc.Get(memberKey,...)` 逐成员读会在成员上重跑读门（持有 virtual 读权限但无成员读权限的用户会被 403，违背 T-71「成员是解析内部量」的姿势）。

处置：按架构 §5.4 的 adapter SPI 面惯例，在 `repo.Service` SPI 段**新增三个方法**（`internal/repo/api.go` + `virtual.go`，共 ~150 行含文档，零既有行为变化）：

- `VirtualMemberOrder(ctx, virtualKey) ([]VirtualMember, error)`——两桶序导出（Key/Type/Priority 三字段，Priority 供 maven foundByPriority 短路消费）；
- `ReadVirtualMember(ctx, virtualKey, member, path)`——单成员元数据文档读取，**成员资格守卫**（必须是该 virtual 当前成员，防任意仓免授权读）；local → node+blob，remote → FR-20 全链（含 stale 语义）；unfound → `ErrNodeNotFound`，分类故障 → `*StatusError` 原样；
- `ListVirtualMember(ctx, virtualKey, member, prefix)`——local 成员 node 事实列举（remote 成员诚实拒绝：其聚合态是上游文档不是 node 集）。

连带机械改动：`internal/adapter/docker/{blob_test,review_fixes_test}.go` 的两个 Service fake/包装补上三方法签名（纯接口符合性，blob 面永不调用）。**这两处超出派单 area（adapter/{maven,npm,pypi}），请 conductor/architect 复核收编或改派小票重做**——不改则本票无法落地，改动面已压到最小且全程按既有 SPI 惯例。

### 1. Maven（AC①，FR-21-AC6 / ME-05 virtual 面）

`internal/adapter/maven/virtual_metadata.go`（新）：virtual 仓的 `maven-metadata.xml` GET 拦截（`handleGet` 顶部按 class 分派）——按桶序逐成员取同名文档**内存合并**：

- versions 去重按 Maven 版本序重排（VersionComparator）；latest=排序末位（SNAPSHOT 计入）、release=末位非 SNAPSHOT；
- snapshot 块取 buildNumber 更大者（timestamp 决胜）；snapshotVersions 按 (extension×classifier) 以同规则合并并**保留输出**（规避 MNG-5180——Maven 客户端自身 merge 丢弃该段）；
- **foundByPriority 短路**：优先桶成员已产出即不再碰非优先成员；
- **每次现算不缓存**；成员 unfound 贡献空；**分类成员故障（SSRF 400/hardFail 502）整体透传**（「任一成员被 block 整体透传」）；成员文档坏 XML → WARN 跳过（单成员腐坏不炸全索引）；
- 旁车（`.sha1/.md5/.sha256` of metadata）= **合并体**的服务端计算值；主响应 ETag/X-Checksum-* = 合并字节实测三摘要，If-None-Match 304；lastUpdated 取成员最大值（非 now()，保输出按状态稳定）；合并响应不带 Resolved-From（虚拟层推导，非任一成员副本）；
- plugin 群变体（`metadata-maven-metadata.xml`）维持 first-hit 透传（规格只定义标准文档的合并）。

### 2. npm（AC②前半）

`internal/adapter/npm/virtual_packument.go`（新）+ `loadPackument` virtual 分支：

- 首个持文档成员为**基底**（identity/通用字段/description 取先到者）；后续版本 **putIfAbsent**；`dist-tags`/`time` 按 key 并集（先到先得）；**latest 重算**（latestVersion 语义 = 合并集最大 semver，与 unpublish repoint 同惯例）；**每次现算**（TTL 600 语义按规格 §4.3 建议不实现）；
- ETag 落到**渲染后合并体**的 sha1（返回合成 node，Sha256 置空以绕开 ledger 单成员值），Last-Modified 取基底时间戳；Resolved-From = 基底成员（连同其 X-BinFlow-Cache 提示，T-82 断言保持绿）；
- 成员故障策略（PRD 对 npm 无明示，**裁定从 pypi 收集姿势**）：分类故障跳过不阻塞其它；全空时回放记住的故障而非裸 404；
- **写面不见合并**：publish/dist-tag/unpublish 走 `loadPackumentForWrite`——路由 virtual 读**部署目标成员自己的**文档（防把其它成员版本抄进目标仓；未配路由的 virtual 读 first-hit，写照旧 C5 405）；dist-tags GET 是读面看并集。

### 3. PyPI（AC②后半 + T-70 遗留的 remote simple 面）

`internal/adapter/pypi/virtual_simple.go`（新）+ `serveProjectPage` class 分派：

- **逐成员收集条目合并**：local 成员 = node 事实重建（`ListVirtualMember`）；remote 成员 = 经 FR-20 链拉上游项目页**解析**（HTML PEP 503 / JSON PEP 691 嗅探，sha256 取 fragment/hashes）；去重键 (filename, sha256) 先到先得（href 指向解析序会命中的成员路径）；按 filename 排序、ETag 稳定；
- **格式回退**：请求 JSON 而任一贡献成员只出 HTML → 整页回退 HTML（local 事实两态原生，remote 以上游实际为准）；
- **任一成员失败不阻塞其它**：分类故障跳过 + 全空回放故障；
- remote 成员「包不存在」**保留负缓存行**（PRD 定案复用 FR-20 参数——与 T-71 探索性 artifact miss 的清除姿势相反，已对 ADR-0013 的措辞边界在代码注释与本日志固化：聚合成员读=成员自身的真读）；
- remote 成员条目的 BinFlow 路径**保留上游 `packages/` 前缀**（成员缓存镜像上游布局；href 形如 `../../packages/packages/<...>`，下载走 first-hit 回该成员拉取）；
- **裸 remote 仓**同法服务项目页（单成员退化形；经被寻址仓自身的正常 GET 门）——T-70 留下的 M46/M47 过渡 400 就此收口；simple 根索引（P2 面）对 virtual/remote 维持过渡行为。

## 五、规格依据与裁定记录

- 高置信度直译：maven 四合并规则 + foundByPriority + 不缓存（repo-semantics §8.3/maven-npm-pypi §1.6）；npm 基底/putIfAbsent/并集/latest 重算（§2.6，TTL 600 语义按规格 §4.3 建议裁掉）；pypi 逐成员收集/格式回退/失败不阻塞（§3.6）。
- **自定裁定**（均有测试固化）：① npm 成员故障策略从 pypi（PRD 对 npm 无该条款）；② npm 写面读部署目标自身文档（防合并泄漏进成员——规格未提写面与聚合的关系）；③ maven 坏 XML 成员 WARN 跳过（规格只定 block 透传）；④ 合并体 lastUpdated 取成员最大值（取 now() 会令每次输出变化）；⑤ pypi remote 成员条目路径保留上游 packages/ 前缀；⑥ 元数据成员读**保留**负缓存行（PRD pypi 定案；与 ADR-0013「探索性 miss 不落盘」的边界 = 该 ADR 管 artifact 扫描，本面是成员真读——建议 architect 回写时收口这句）；⑦ 合并 maven 响应无 Resolved-From / npm 合并响应 Resolved-From=基底成员；⑧ 裸 remote pypi 仓项目页就位（T-70 过渡语义收口，M46/M47 面）。
- 已知边界：真 pypi.org 上游的 files.pythonhosted.org href 不经本仓解析（引擎只连配置上游，R7 mock-first 姿势）；npm 真npmjs 上游的 packument 不在 `<name>/packument.json` 路径（BinFlow/Artifactory 型上游可用）；二者的真实公网上游代理归 M4 评估。
