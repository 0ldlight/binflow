## 2. FR-113.2 BE — byHash 值域枚举校验归 repo.Service（T-327R 遗留② / K45 票内定案）

**改动**：

### 3b. userDnPattern 消费缺位（T-305 遗留，按 auth-integration.md v2 定行为=直写生效）

规格（§1.5 规则 5，高置信）：`userDnPattern` 非空 → 直接 DN 绑定（`{0}` 替换用户名）；`search` 非空 → manager/匿名先搜后绑；**两者同配仍可认证，失败时打互斥 warn**（文案逐字锚定）。

**实现**（internal/auth）：
- `ldap.go`：`LDAPConfig.UserDNPattern` 字段；`Bind` 重构为 `bindUser` 两臂梯子——**直写臂**（{0} 替换 + **RFC 4514 DN 值转义**（escapeDNValue：`" + , ; < > \` 全位转义 + 首尾 `空格/#`——DN 语法版的 ldap.EscapeFilter，防 `alice,dc=evil` 拼 RDN 重定向子树）→ 直接 bind，无 manager bind 无搜索；协议类失败=provider_error 即拒；invalid-credentials **回退搜索臂**（「两者同配仍可认证」）→ **搜索臂**（原 resolveUserDN 流程原样：manager/匿名 bind + UserFilter 搜索 + 用户 DN bind）。双臂皆败且 pattern 已设 → `warnLDAPModesExclusive`（规格逐字文案 + user 上下文）。UserDNPattern 为空时行为与改前**逐字节同路**（既有全量测试实证）。
- `configmanager.go`：`ldapConfigFromSection` 补 `UserDNPattern: sec.UserDNPattern` 投影（T-305 缺位正是此行）；section 校验（{0} 必含）T-305 已备，零改动。
- 测试 `internal/auth/t346_userdnpattern_test.go`（5 腿）：直绑成功（binds 恰一条=替换后 DN、零用户搜索）；DN 转义（拼接用户名落escaped值、失败关闭）；回退腿（binds 序=[patternDN, managerDN, searchedDN]，认证成功）；双臂皆败分类（user_not_found / bad_credentials）；**ConfigManager 腿**（section PUT 带 userDnPattern → 下一次认证即走直绑）。mock 增 binds/searches 记录（ldap_test.go）。
