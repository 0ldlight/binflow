## 一、实现内容

按 T-188 裁决（A 路径开放）把 `POST /api/security/token` 从 admin-only 改为「已认证即可，护栏在 handler 内」：

1. **路由门（router.go）**：`routeAuth{required: true, admin: true, oauth: true}` → `routeAuth{required: true, oauth: true}`（仅 create；`revoke` 与既有 admin-only 面不动，无 GET 列表路由维持不存在）。匿名 → 401（oauth 形）由路由门承担。
2. **主体判定（security.go handleTokenCreate）**：缺省 `username` = 调用者；非 admin 指定他人 → **403** OAuth 形，沿用 `administrator privileges required` 文案（K9；原实现是死代码分支的 401，已纠正）。admin 可代任何主体。
3. **非 admin 有限 TTL（护栏 2 / K9）**：对**有效 TTL**（显式 expires_in 或缺省继承 TokenDefaultTTL）要求 `0 < ttl ≤ auth.token_nonadmin_max_ttl`；0（永不过期）/ 超限 / 缺省默认值超限 → **401 invalid_request**，文案对齐 Artifactory：`The user: '<u>' can only create user token with expires in larger than 0 and smaller than <max> seconds (requested: <n>)`。admin 不受限（可永不过期、可超上限）。负数 expires_in 维持全员 **400**（auth-model.md §3.1 参数表，高置信度）。
4. **验证期护栏 3（已有行为，测试固化）**：`TokenVerifier.Verify` 每次验证重查主体用户行（不存在/禁用 → 401）——本轮以直连 sqlite 改 `enabled`/删行的腿固化。
5. **审计（护栏 4）**：`token.issue` Detail 从 `{fingerprint,ttl_seconds}` 扩为 `{fingerprint,ttl_seconds,subject,source}`——subject 区分「admin 代铸」（actor≠subject），source = 铸造者认证臂（local/oidc/ldap，取 `Principal.Source`）。
6. **Source 一致性修复（internal/auth/token.go）**：`TokenVerifier.Verify` 原硬编码 `Source: ProviderLocal`，与 session 臂「Source = 用户行 owning provider」政策（T-157 leftover 3）矛盾——OIDC/LDAP 用户铸的 Token 在 whoami/审计里报 local。改为 `Source: u.Provider`（Authorizer 不读该字段，纯信息面，无权限影响）。
7. **K9 配置键（internal/config）**：新键 `auth.token_nonadmin_max_ttl`（**秒**，对齐 Artifactory `access.token.non.admin.max.expires.in` 的单位语义），默认 **365d**（`DefaultTokenNonAdminMaxTTL = 31536000s`）。沿 T-179 模式：raw struct 指针字段 + build 装配 + Validate 正值校验（0/负值拒启动——0 上限会使非 admin 全部 401，宁拒启）+ env 双拼写（K9 单下划线 `BINFLOW_AUTH_TOKEN_NONADMIN_MAX_TTL` 显式别名 + 通用 `BINFLOW_AUTH__TOKEN_NONADMIN_MAX_TTL`）。

## 五、规格依据与裁量说明

- **高置信度直接实现**：auth-model.md §3.1——「admin 全量；非 admin 已认证可为自己发；匿名拒绝」「非 admin 指定他人」「TTL 上限 365d + 超限 401 invalid_request 文案」「负数 → 400」。
- **与票据摘要的一处出入（已按 PRD 执行，请 conductor 复核）**：派单 AC6 摘要写「TTL 超限 **400**」，但 Q11 草案 AC（milestone-6.md §7 Q11 实现票草案 AC 第 4 条：`expires_in 超上限 → 401`）+ FR-54-AC3（`expires_in=0 → 401 invalid_request`）+ auth-model.md §3.1（超限 → 401）三处一致为 **401**。票据明示「七条 AC 草案读 §7 Q11」，故按 401 实现；负数维持 400（规格参数表，适用全员）。
- **TTL 判定取 effective TTL**（缺省继承默认 TTL 后再判上限）：规格明文「缺省取系统默认」+ 上限护栏语义推定；防运维单抬 `token_default_ttl_hours` 绕开护栏。测试固化（cap=2h 时缺省腿 401, requested: 2592000）。
- **Source 修复**：规格依据 = session 臂既有政策注释（session.go T-157 leftover 3）+ H36（whoami source 正确性）。Authorizer 不读 Source，无权限面影响。
- **禁用用户行的 REST 面缺失**：`/api/security/users` 无 enabled 开关（wire body 不含该字段，metadata 亦无 seam），H26 草案 AC5 的「admin 禁用用户」操作当前只能直连 DB——测试以直连 sqlite 模拟。若需要正式 API 面（PATCH enabled），建议另开票（M6 治理面）。
