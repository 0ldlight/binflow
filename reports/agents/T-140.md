# T-140 [P2] FR-47 storage uri 基址族修正（DM-01）

## 改动概要

修复 storage REST API 中 `uri` 字段存在重复/缺失 `/binflow/api/storage/` 前缀的问题，统一所有 storage 响应中的 URI 格式。

## 问题分析

`storageURI` 函数是 URI 构造的唯一入口，但调用者传入的 `relPath` 参数不一致：

| 调用位置 | 传入路径 | 旧 result | 问题 |
|---|---|---|---|
| `fileInfoOf` (item info / search) | `node.Path` (e.g. `acme/x.bin`) | `http://host/repo/acme/x.bin` | 缺少 `binflow/api/storage/` |
| `writeFolderInfoBody` (folder info) | `strings.TrimPrefix(displayPath, "/")` | `http://host/repo/acme/` | 缺少 `binflow/api/storage/` |
| `handleStoragePermissions` (?permissions) | `"api/storage/"+path` | `http://host/repo/api/storage/acme/w.bin` | `api/storage/` 在 repo key 之后 |
| `handleStorageList` (?list) | `"api/storage/"+node.Path` | `http://host/repo/api/storage/acme/` | `api/storage/` 在 repo key 之后 |

正确格式应为：`{scheme}://{host}/binflow/api/storage/{repo}/{path}`

## 修复方案

**单 seam 修正**：在 `storageURI` 函数内部嵌入 `/binflow/api/storage/` 前缀，消除调用者的不一致。

### 变更文件

1. **`internal/httpapi/storage.go`**
   - `storageURI` 函数：`base + "/" + repoKey + "/" + relPath` → `base + "/binflow/api/storage/" + repoKey + "/" + relPath`
   - `handleStoragePermissions`：去掉 `"api/storage/" + path` 中的 `"api/storage/+"` 前缀
   - `handleStorageList`：去掉 `"api/storage/"+node.Path` 中的 `"api/storage/+"` 前缀

2. **`internal/httpapi/t92_search_test.go`**
   - 搜索测试 URI 断言：`h.srv.URL+"/generic-local/acme/artifact.bin"` → `h.srv.URL+"/binflow/api/storage/generic-local/acme/artifact.bin"`

### 一致性验证

- `uri` 和 `downloadUri` 共享同一 `storageURI` 调用，格式一致
- `?list` 的顶层 `uri` 与 `files[].uri`：顶层用 `storageURI` 构造完整 URL，files 内 uri 保持相对路径（rest-api.md section 3）
- `?permissions` 的 `uri` 与 item info uri 共用相同 `storageURI` 构造规则
- FE tree/search 无需改动（FE 不消费顶层 uri）
