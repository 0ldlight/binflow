## 0. area 映射核对（票面 vs 实际落点）

票面 area 写的是 `internal/storage（nodes 扩列 + 埋点）+ internal/httpapi`。实际：

- `internal/storage` 是 blob 物理后端（fs/S3），**nodes 表不在那里**——nodes DDL/CRUD 在
  `internal/metadata`，下载埋点着陆点在 `internal/repo`。按票面括号语义（「nodes 扩列 +
  埋点」+「FileInfo/?stats 投影」）落到了 metadata/repo/httpapi 三包，`internal/storage`
  **零改动**（busy 预算 RetryOnBusy 只是消费）。并行票 T-437 只动 docs——零冲突。
- 请 conductor 复核此映射是否需要留痕到 M16-SPLIT。

### 1.2 三分计数口径埋点（AC1）

**单源声明（AC3 票内声明）**：nodes 四列 = 下载面唯一计数通道（批次③字段族与 FR-148
usage 域唯一数据源）——零第二计数通道、零派生聚合、零 audit 侧独立计数。声明固化在
`internal/repo/downloadstats.go` 包注释 + `metadata.NodeStats` godoc。

- `metadata.NodeStore` 新增两方法（接口面，fake 均为嵌入实现——零破坏）：
  - `CountDownload(ctx, repo, path, by, at, remoteServed)`：**单条自增 UPDATE**
    （`download_count = download_count + 1` SQL 原子）+ 刷 last_downloaded_*；
    folder 行经 `sha256 <> FolderMarkerSHA` 在 SQL 边排除（folder 恒零的结构性保证）；
    缺行静默 no-op（计数跟 audit 同为 best-effort 姿态）。
  - `Stats(ctx, repo, path)`：四列投影读（`NodeStats` 新类型——**Node 结构体零变化**，
    217 个调用方零扰动）。
- `internal/repo/downloadstats.go`：`markDownload`（单缝 = audit 行 + 计数 UPDATE 同址
  同序同 best-effort；计数失败 WARN 不挡下载——technical debt #4 同款）+ busy 预算包裹
  （T-423 `storage.RetryOnBusy`）+ origin 维度 + statsSync 资格标记。
- **着陆点接线 12 处**（凡 audit ActionDownload 之处即计数——同源同址）：
  - 臂①直连：service.go Get(local)、ResolveManifest、ResolveTag；archive.go（folder
    根 → UPDATE 结构性 no-op）。
  - 臂②经 virtual：virtual.go getVirtual / ReadVirtualMember / readRemoteMemberDoc；
    dockervirtual.go auditVirtualResolve ×4 调用点——**计数落成员行**，audit 行仍指

  - 臂③ remote 服务：service.go getRemote、dockerremote.go ProbeRemoteCache(HIT/STALE)

### 1.3 remote_download_count 语义裁定（票内核对，两源张力留痕）

- **裁定**：该列 = 「该 remote 仓作为服务点的下载次数」——**计数行落在 remote 仓即 +1**，
  含直连 remote GET（臂③）与 virtual 解析到 remote 成员（该 remote 缓存服务了这次下载）。
  依据：architecture §6 DDL 注释 + ADR K69.2 括号语义（「该 remote 仓作为服务点」）+ 派单
  防错条（「只记 remote 缓存命中服务的下载，非 smart remote 回拉」）。测试
  `TestT438VirtualArmCountsMemberRow` 固化（local 成员 1/0、remote 成员 1/1）。
- **张力登记（需 T-440 裁）**：docs/reverse/aql.md §14.1 line 330 警告「勿把 remote 缓存
  命中灌进 remote_downloads（那是 Artifactory smart-remote 回拉语义，BinFlow 无源恒
  null/0）」——该条针对 **AQL wire 面**的字段族；ADR K69.7 又说四列承载 AQL
  remote_downloads。两文冲突，软缝清单 ⑧ 已在册。**本票只建列+?stats 投影（按 K69.4 明文
  五字段含 remoteDownloadCount）；AQL/usage 域怎么映射该列是 T-440 的决定面**——若 T-440
  按 aql.md 走「AQL remote_* 恒 null」，该列仍可作为 ?stats/Batch③ 自有指标存在，不冲突。

### 1.4 ?stats 面（AC1 后半；FileInfo 零变化）

- 路由：`/api/storage/{repo}/{path}?stats` GET 挂 **item-info 同款内容面读门**
  （routeAuth{}，匿名随开关）——K69.5 明文「非档位调用者 ?stats 投影省略字段」= 路由不
  403、字段级门。
- `statsInfoBody` 五字段：`uri/downloadCount/lastDownloaded/lastDownloadedBy/
  remoteDownloadCount`（K69.4 正名投影）；`remoteLastDownloaded`/`remoteLastDownloadedBy`
  无源**不投影不伪造**（§11.49）。
- **lastDownloadedBy 可见性门**：`managementAllowed(Authz, CanManage(CapSystemRead))`
  （admin ∨ readonly_admin——与 GET /api/v1/audit 同档）；非档位 omitempty 省略；计数面
  无门。
- **探针不自计数**：?stats 经 `statsNode`（`ReposSvc.List` 同 path-scoped 读门、零
  audit 零计数）解析节点，**不走 svc.Get**——统计读不是三分口径任何一臂（ADR「HEAD/
  探测不计」），自反馈（读统计改统计）是荒谬形。folder 行经 List 精确臂解析 → 结构性
  零值 200；repo 根无行 → 404（不伪造零）。
- virtual 地址：List 聚合返回成员行 → Stats 读成员行计数（臂②口径，virtual 无行）。
- compat_test 的 E-26 名单摘除 stats（?propertiesXml/?lastModified 维持 404）。

### 1.5 statisticsEnabled / sourceOrigin 行为化（AC2）

- **计数无条件**（本地统计是本地事实，不同步键门控）。
- `enabled && statisticsEnabled` → remote 服务臂 audit download 行 detail 附
  `"statsSync":true` 资格标记（`statsSyncDetail`，每 remote 下载一次 policy 行读——与
  remoteContentTTL 同型）；通知本体缺位维持 §11.48 登记。
- **sourceOrigin 落库**：全部 12 着陆点 audit detail 增 `origin` 维度
  （`direct | virtual:<vkey> | remote`）——三分口径审计轨迹，nodes 零新列（K69.6③）。

## 3. 与派单/ADR 的差异留痕（ conductor 请过目）

1. **「FileInfo 投影扩字段」正位**：派单摘要写「基础 FileInfo 加 downloadCount/
   lastDownloaded 等非敏感字段」——但 DECISIONS.md:1135 与 architecture §25.5 均明文
   「**基础 FileInfo 零变化**，AC1 的『FileInfo 投影』按锚正位为 ?stats 面」。按派单自身
   的「以 ADR 定案为准」指令，**实现了 ?stats 面、FileInfo 零变化**。若 conductor 实意
   是混合形（FileInfo 也带非敏感字段），是 5 行的正向追加，请示下。
2. **probe 面（/api/storage item-info / properties / permissions GET）as-built 会写
   audit download 行**（storageNode→svc.Get，M1 起）→ 计数跟随（同源同址的必然）。**后
   果：浏览 item-info/属性/权限视图会 +1 计数并刷 last_downloaded_by**（控制台浏览会污染
   下载统计的观感）。?stats 本身已豁免（statsNode 不走 svc.Get）。**这不是本票引入的
   audit 行为**（改它会动 cleanup walkDownloads 保活集语义——超票面），登记为上游裁定项：
   若要「浏览不计下载」，应开一张 audit 面小票把 storageNode 换成门控非审计读（一行换
   缝），计数自动跟随，零拆对。
3. **docker tag 寻址 manifest GET as-built 写两条 audit download 行**（ResolveTag +
   ResolveManifest）→ 同一 manifest 行每次 tag GET 计 2；digest 寻址计 1。同为 as-built
   audit 形态的继承，同上属 audit 面整理票候选。
4. **remoteexternal virtual 面**（FetchVirtualExternal）origin=virtual:<vkey>、计数落
   remote 成员行且 remote 列 +1（成员缓存服务了下载——与 §1.3 裁定一致）。
