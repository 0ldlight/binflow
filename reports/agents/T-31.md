## 关键发现（对 BinFlow M2 最有用的）

- **单体/chunked 判定**不是看方法而是「PUT 时 `_uploads/<uuid>` 文件是否已存在 + 老 docker UA 正则兜底」。
- **GET 上传状态标准端点缺失**（官方 spec 有），Artifactory 用 `.patch` 后缀变体；DELETE 取消上传也未见实现——靠 24h 清理兜底。
- manifest 校验失败回 MANIFEST_INVALID 而非官方 BLOB_UNKNOWN；tags 空回 404 NO_TAGS_FOUND 而非 200——两条明确偏离，文档「校准建议」节建议 BinFlow 按官方走。
- 空 blob digest `sha256:a3ed95ca...`（32B gzip 空 tar）硬编码合成响应。
- 存储：manifest=`<image>/<tag>/manifest.json|list.manifest.json`，blob=`<alg>__<hex>`，会话=`<image>/_uploads/<uuid>.patch`，索引=`.jfrog/` 下 catalog/tags/referrers 三类缓存文件（懒构建）。
- 401 挑战 scope 由路径正则推导（manifests→repository:<image>:pull[,push]、catalog→registry:catalog:*）。

## 与官方文档的冲突（已写入规格 §10）

1. 错误码表新增 SIZE_INVALID / NO_TAGS_FOUND / "NOT FOUND"（含空格）/ INTERNAL_ERROR。
2. 分页 n 缺省：官方 100，Artifactory 全量。
3. tags 空响应：官方 200 空数组，Artifactory 404。
4. DELETE manifest by tag：官方禁止，Artifactory 支持。
5. PUT 收尾 400 文案结尾缺引号（原文 bug，注明不复刻）。
