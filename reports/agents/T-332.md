## 1. ADR-0039 要点（DECISIONS.md，新号顺延 0038）

| 端点 | 翻转后形状 | 响应 |
|---|---|---|
| create | `POST ?repoKey=&repoPath=&partSizeMB=`（QueryParam 非 JSON 体） | 200 `{"token"}` |
| config | `GET /config`（能力探测 + jfrog-cli UA 版本门 2.62.2） | 200 `{"supported": bool}`（filestore 回 false，**探测端点不回 501**） |
| urlPart | `POST ?partNumber=N`（Bearer token） | 200 `{"url"}`（URL 查询串自带 `?token=`） |
| status | `POST`（Bearer） | 200 `{status, error, progress, checksumToken}`，词表 **PARTS/PROCESSING/FINISHED/NON_RETRYABLE_ERROR** |
| complete | `POST ?sha1=`（**sha1 非 sha256**） | **202 受理**，任务异步 |
| abort | `POST`（Bearer） | 204 |
| part（urlPart 目标） | `PUT /part/{id}/{n}?token=`（**200** S3 PutObject 形；免 Authorization） | 200 会话回显 |

关键映射：① token = 自解析能力 `<32B随机hex>.<sid>`，sha256(随机段)+48h 过期持久化进 T-323R caller blob（v2），重启后同 token 续用（T-323R 保留）；② complete 异步：后台 goroutine 跑引擎同步 `Commit(BlobRef{Sha1})`，FINISHED 前经 `metadata.Blobs().Put`（既有导出缝）落 ledger 行，**节点由客户端凭 5 分钟 checksum-deploy token 零传输落**（治理门随客户端 PUT 走）；③ create 范围放开（无包型校验；virtual 回落 defaultDeploymentRepo；unknown/remote/无 w → **403** Artifactory 原文）；④ 旧形状退役（无兼容垫片；v1 blob 行 fail-closed）。引擎缝（Begin/Append/Commit、caller-blob 持久化、懒重建、sweep）**零改动**。

## 2. 实现要点（internal/httpapi）

- **认证车道**：create/config 走常规路由门；urlPart/status/complete/abort/part 走**能力车道**——dispatch 级豁免谓词 `isMPUCapabilityRoute`（isLoginEntryPoint 同型先例）+ handler 自裁：MPU 形状 token → 能力路径（失配 404）；非 MPU 凭据 → 照中间件原判 401/403（presented-but-rejected 姿态不弱化）。
- **能力解析**：`parseMPUToken`（64hex.sid）→ 注册表/懒重建（T-323R funnel 原样）→ `subtle.ConstantTimeCompare(sha256(rand), blob 绑定)` + TTL 校验。
- **乱序分片**：顺序快路直流 `Session.Append`（内存与片大小无关）；跳序片进有界暂存（**64 片/128MiB**，越界 409），缺口闭合后按序 flush；短片段关流后仍有在途暂存片 → 会话判失败（登记残余）。
- **finish 任务**：detached context（客户端断连不杀组装）；成功铸 checksum-deploy token（auth.Service `Issue` facet，5 分钟真 API token）；失败态载 error。
- create 的 caller blob 升 v2（+tokenSha256/tokenExpiry）；v1 行（旧 wire 在途会话）fail-closed。

## 3. 真客户端验证（jfrog-cli 2.122.0，brew 安装，MinIO 真栈）

220MiB 随机语料 `jf rt upload` 全链 **GREEN**，下载字节一致：

```
09:48:33 [Info] [Multipart upload jf/mpu7.bin] Upload completed successfully!
{"status":"success","totals":{"success":1,"failure":0}}   (9.3s)
cmp big-mpu7.bin dl7.bin → BYTE-IDENTICAL
端点轨迹：config 200 ×1 / create 200 ×1 / urlPart 200 ×11 / part 200 ×11(乱序) /
complete 202 ×1 / status 200 ×2(PROCESSING→FINISHED) / 部署 PUT 404(探测)→201 / GET 200
```

真客户端修形三处（已回写 ADR）：
1. **part PUT 不带任何 Authorization**（把 urlPart 答案当 S3 presigned 用）→ 能力随 URL `?token=` 传递（访问日志只记 path，能力不落日志）。
2. **part PUT 只认 200**（202 被当失败重试直至 abort）→ 翻为 200。
3. **分片并发乱序到达**（--split-count 默认 5 工作池）→ 有界重排暂存。

另证：客户端 MPU 触发前置门 = `/api/system/version` ≥ **7.82.2**（客户端自查日志原文），版本报 "dev" 时客户端静默走整体式 PUT——与 config 探测叠加存在（验证用 scratch 构建 ldflags 覆盖版本号，不改产品面）。状态词表与解析表取自 **jfrog-client-go 公开源码**（completionStatus 枚举 + parseMultipartUploadStatus：QUEUED/PROCESSING 续轮询、FINISHED/ABORTED 终态、NON_RETRYABLE_ERROR 致命、其余 unexpected→abort），推翻了我初版自拟的 Uploading/Finishing/Failed 词表（初版真机一跑即被客户端 abort 证伪——真客户端验证的价值所在）。

## 5. 覆盖的故障场景（可靠性）

- **并发**：乱序分片并发 PUT（重排暂存+flush 串行化）；同 id 并发懒重建单飞（funnel，seam 计数断言恰 1）；-race 双跑。
- **中断**：kill -9 后重启——同一 token 经持久化绑定复活会话、续传剩余分片、complete、checksum-deploy、字节对账（探针腿 4 + 单测 TestUploadsRestartResumeUnderToken）；complete→FINISHED 窗口 kill -9 的行为已登记（status 回 PARTS，补救=重发 complete）。
- **校验失败**：畸形 sha1 400；错值 sha1 → 202 受理后任务 NON_RETRYABLE_ERROR（error 载文），无节点落地、S3 MPU 回收（mc 断言）。
- **GC/生命周期**：complete 只落 ledger 行+物理 blob，节点由客户端落——客户端不落 = 无引用 blob 归 ADR-0031 两阶段回收；abort/清扫回收 S3 侧（mc 清零审计）；idle sweep 语义不变（uploads_internal_test 原样绿）。
- **凭据攻击面**：伪造 secret → 404；跨会话 token → 404；常规 API token 冒用 → 403；垃圾 Bearer → 401（中间件原判）。

## 6. 差异登记（ADR-0039 后果节全文）

残余五项：① checksum-deploy token 为全用户 API token（5 分钟）非窄域（internal/auth 扩展缝后续票候选；真客户端 deploy 同时带原凭据+X-Checksum-Deploy-Token 头，服务端忽略未知头不受影响）；② filestore config 200/false（探测本义）vs Artifactory 其余端点 404（既有 501 裁定保留）；③ complete 窗口 kill -9 任务态丢失；④ UA 版本门 2.62.2 不可配置；⑤ 短片段后在途暂存片判失败（S3 manifest 完整性 vs 流式 EOF 残余语义差，真客户端不触发）。另：ledger 行直写经 `metadata.Blobs()` 而非新增 repo.Service 方法（area 纪律；architect 若偏好收口留后续票）。
