### 3.1 t247-mvn-publish

```groovy
pipeline {
  agent any
  options { timestamps() }
  environment {
    BINFLOW = 'http://172.16.58.129:8080'
  }
  stages {
    stage('BinFlow health gate') {
      steps {
        sh 'curl -sf $BINFLOW/readyz && curl -sf $BINFLOW/binflow/api/system/ping && echo binflow-ready'
      }
    }
    stage('Scaffold demo library') {
      steps {
        sh '''#!/bin/bash
set -e
rm -rf hello-lib
mkdir -p hello-lib/src/main/java/com/binflow/ci
cat > hello-lib/pom.xml <<POM
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>
  <groupId>com.binflow.ci</groupId>
  <artifactId>hello-lib</artifactId>
  <version>1.0.$BUILD_NUMBER</version>
  <packaging>jar</packaging>
  <properties>
    <maven.compiler.release>21</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>
</project>
POM
cat > hello-lib/src/main/java/com/binflow/ci/Hello.java <<JAVA
package com.binflow.ci;

public class Hello {
    public static String greet() {
        return "hello-lib built by Jenkins build #${BUILD_NUMBER}, resolved from BinFlow";
    }
}
JAVA
echo scaffold-done
'''
      }
    }
    stage('Build + deploy to BinFlow maven-local') {
      steps {
        withCredentials([usernamePassword(credentialsId: 'binflow-ci-bot', usernameVariable: 'BF_USER', passwordVariable: 'BF_PASS')]) {
          sh '''#!/bin/bash
set -e
cat > settings.xml <<XML
<?xml version="1.0" encoding="UTF-8"?>
<settings xmlns="http://maven.apache.org/SETTINGS/1.2.0">
  <mirrors>
    <mirror>
      <id>binflow</id>
      <mirrorOf>*</mirrorOf>
      <url>http://172.16.58.129:8080/binflow/maven-virtual</url>
    </mirror>
  </mirrors>
  <servers>
    <server>
      <id>binflow</id>
      <username>${BF_USER}</username>
      <password>${BF_PASS}</password>
    </server>
  </servers>
</settings>
XML
# every plugin + dependency resolves through BinFlow maven-virtual (mirrorOf *)
cd hello-lib
mvn -B -s ../settings.xml -DskipTests \
  -DaltDeploymentRepository=binflow::default::http://172.16.58.129:8080/binflow/maven-virtual \
  deploy
# verify the artifact is visible server-side right away
VER=1.0.$BUILD_NUMBER
curl -sf -o /dev/null -w "hello-lib-$VER.jar HEAD on maven-local: %{http_code}\n" \
  http://172.16.58.129:8080/binflow/maven-local/com/binflow/ci/hello-lib/$VER/hello-lib-$VER.jar
curl -sf -o /dev/null -w "hello-lib-$VER.jar HEAD via maven-virtual: %{http_code}\n" \
  http://172.16.58.129:8080/binflow/maven-virtual/com/binflow/ci/hello-lib/$VER/hello-lib-$VER.jar
'''
        }
      }
    }
  }
  post {
    always { cleanWs() }
  }
}
```

## 4. 验收证据（build log 关键行 + BinFlow 侧 curl）

### 4.1 生产侧

- mvn #1：`binflow-ready` → `Uploaded to binflow: …/maven-virtual/com/binflow/ci/hello-lib/1.0.1/hello-lib-1.0.1.{pom,jar}` + `maven-metadata.xml` → `BUILD SUCCESS` → `hello-lib-1.0.1.jar HEAD on maven-local: 200` / `via maven-virtual: 200`。**插件与依赖共 279 个构件全部经 BinFlow（mirrorOf * → maven-virtual → remote-central）下载**，零 Central 直连。
- npm #1：`npm whoami`=admin 链路 token 生效 → `+ binflow-ci-hello@1.0.1`（`.npmrc` 用 `_authToken=` 形态）→ `npm view binflow-ci-hello version`=1.0.1。
- docker #1：`Successfully built 36470c8f433c` → `Login Succeeded`（ci-bot）→ `1.1: digest: sha256:36470c8f433c…` + `latest: digest: sha256:36470c8f433c…`。

### 4.2 消费侧（t247-consume-all #3 / #4）

```
BinFlow metadata says hello-lib release = 1.0.1      ← 版本从 BinFlow maven-metadata.xml 取
Downloaded from binflow: …/hello-lib-1.0.1.jar       ← fresh ~/.m2（workspace 内全新 local repo）
BUILD SUCCESS
consumer got: hello-lib built by Jenkins build #1, resolved from BinFlow
added 1 package in 155ms
binflow-npm-roundtrip-ok from build #1
Digest: sha256:36470c8f433c…                        ← 与生产侧 push digest 逐位一致
binflow-docker-roundtrip-ok from image build #1
HTTP/1.1 200 OK
X-Binflow-Resolved-From: maven-remote-central         ← Central 代理腿证据（junit 4.13.2 经 BinFlow）
```

#4 追新：`metadata says 1.0.2` → `consumer got … build #2`；npm 取到 build #3（1.0.3）；docker 取到 build #2 镜像——**链式版本递增全靠 BinFlow metadata/tag 自描述，job 间无静态版本耦合**。

### 4.3 BinFlow 侧 curl

- maven metadata：`{"latest":"1.0.1","release":"1.0.1","versions":["1.0.1"]}`（#2 后为 1.0.2）。
- npm packument：dist-tags `{"latest":"1.0.1"}`、versions 1.0.1（后 1.0.3）。
- docker：`/v2/_catalog` → `["docker-local/t247/hello-img"]`（neg-img 负面腿残留已按 digest DELETE 202 清掉）；`tags/list` → `["1.1","1.2","latest"]`。
- 取件头：`X-Binflow-Resolved-From: maven-local` + `X-Checksum-Sha256: cd5979d4…`（jar 经 virtual 命中 local 成员）。

### 4.4 负面腿（t247-negative #1，如实记录）

- 错误口令 mvn deploy：`Failed to deploy artifacts … status: 401 Unauthorized`，mvn exit 1；BinFlow 侧复核 `neg-lib` 元数据 **404（未落任何制品）**——401 不是"半写"。
- 未登录 docker push：`error from registry: unauthorized`，exit 1；`docker login`（credential store 取 ci-bot）后重推 → `1: digest: sha256:d36e21aa…` + `RETRY OK`。失败→修复→重试全链在一条 job 内完成。

## 6. 踩坑记录（后续 agent 复用）

1. **Docker Hub 直连不通**：`jenkins/jenkins:lts` 走 T-230 配好的 mirrors（daocloud/1ms）2m31s 拉成。但 **容器内 `apt-get` 挂死在 deb.debian.org**（构建层卡 14 分钟，单 http method 挂起）——把 Debian 源 sed 到 TUNA 后 30s 内装完。VM 上任何容器内 apt 都建议先换源。
2. **Debian 13 拆包**：`docker.io` 装完**没有 CLI**（trixie 把 CLI 拆成独立 `docker-cli` 包），挂宿主 socket 的 agent 容器要装 `docker-cli` 不是 `docker.io`。
3. **8080 冲突**：BinFlow systemd 保 8080（T-230 默认口），Jenkins 映射 9090。
4. **insecure-registries 取舍**：Jenkins 容器内 docker CLI 访问 registry 不能用 `localhost:8080`（那是容器自身网络），必须宿主 IP `172.16.58.129:8080`——而宿主 IP 不在 docker 的 localhost 特例里，需在 daemon.json 显式 `insecure-registries`（已加，mirrors 保留）。测试环境选 insecure + 记录；生产应上 TLS（或反代 443）。
5. **Jenkins REST 403**：新版 crumb 与 session 绑定，`-H "Jenkins-Crumb: …"` 必须配 `-b` cookie jar 一起发（两次踩中）。
6. **Groovy 单引号串转义**：`sh '''…'''` 内的 shell `\|` 是非法 groovy 转义（编译期报 `unexpected char: '\'`）→ 用 `grep -E "a|b"`；`node -e "…\"…\"…"` 引号嵌套会被剥层 → 改写临时 .js 文件执行。
7. **ssh heredoc + sudo 管道互斥**：`ssh host 'echo q | sudo -S bash -s' <<EOF` 里 sudo 与 bash 争抢同一 stdin，脚本静默不执行——先 `cat > /tmp/x.sh` 落盘再 `echo q | sudo -S bash /tmp/x.sh`。
8. **[产品发现 P-1] npm 包第二个版本发布 403**：npm publish 的 packument PUT 会**覆写已有 packument 节点**，命中 `authorizeContentPut` 的"覆写需 DELETE 权限"臂（maven 的 maven-metadata.xml 在自由覆写族里，npm packument 不在）→ 无 delete 权限的 CI 号第二个版本必 403（`E403 - PUT …/npm-local/binflow-ci-hello`）。**缓解**：permission target 给 ci-bot 加 `delete` 后 #3 即绿。建议 dev 侧评估把 packument 覆写纳入 freely-rewritable 家族（语义上它是元数据增长不是删除性覆写），或文档化"npm 发布仓的 CI principal 需要 write+delete"。
9. **docker manifest 裸 curl 要带对 Accept**：客户端 docker CLI 透明处理；`curl` 不带 `Accept: application/vnd.oci.image.manifest.v1+json` 会 404（BinFlow 严格匹配 manifest mediaType）——影响按 digest 删除之类的运维脚本。
10. mvn #1 188s（279 个构件经 remote 首拉，2C VM）→ #2 9.7s（容器 ~/.m2 持久）；消费腿用 workspace 内 fresh local repo 保证"只从 BinFlow"证据成立，每跑全量拉但 mvn 只有十来个构件，7s 级。

## 7. CI 场景结论（可入 PRD 场景库的形态）

**场景：Jenkins 流水线以 BinFlow 为唯一制品源（pull-through + 发布 + 消费）**，四条 job 全绿实证：

1. **maven**：`settings.xml` 单文件（mirror `*` → `maven-virtual` + `<server>` 凭据）同时解决解析与发布（`altDeploymentRepository` 指回 virtual，defaultDeploymentRepo 落 local）——插件、依赖、发布物 100% 过 BinFlow，CI agent 无需任何外部仓库出网（除 BinFlow 回源）。
2. **npm**：`.npmrc` registry + `_authToken`（BinFlow Access Token，可吊销、独立于登录口令），publish/whoami/view 全链 token 化。
3. **docker**：registry 走宿主 IP + insecure-registries（或 TLS），`docker login --password-stdin` 吃 credential store 凭据；多 tag 同 digest push。
4. **消费**：mvn 版本号从 BinFlow `maven-metadata.xml` 的 `<release>` 动态取、npm 用 dist-tags latest、docker 用 :latest tag——生产/消费 job 零静态耦合，链式追新自动成立（#4 实证）。Central 依赖经 `maven-remote-central` 代理（`X-Binflow-Resolved-From` 头佐证），air-gap 只需把 remote 换内网上游。
5. **失败语义**：错误凭据 401（无半写）、未认证 push unauthorized、修复后重试即通——CI 重试策略可安全依赖。

前置成本：一台 2C/4G+ 的 VM 可同时跑 Jenkins（≤1.6G）+ BinFlow（<200M）+ 构建负载；镜像拉取依赖 mirrors（Hub 直连不可达环境）。
