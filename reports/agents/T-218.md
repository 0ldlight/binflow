## 一、做了什么

### 1. 用户编辑页角色下拉（FR-66-AC1 / V12）

- `web/src/pages/security/UserDetailPage.tsx`：admin 复选框升级为**角色三值下拉**
  （`user-form-role`；选项 value = wire snake 严格值 `user|readonly_admin|admin`，
  显示名友好中文 + wire 值并书）。保存走既有 POST `/api/security/users/{name}` 部分更新
  通道，仅角色变化时携带 `adminRole`，**永不与 `admin` 布尔混发**（同时发且不一致 →
  服务端 400，UI 结构性规避）。GET 回显：下拉值/账户信息卡 `user-facts-role` 均来自
  `adminRole` 字段归一（闭集外回退 admin 布尔镜像，与服务端 roleFromStored 同 fail-safe）。
- `web/src/pages/security/api.ts`：`UserDetail.adminRole`、`UserUpdateBody.adminRole`
  契约面补齐；注释写明冲突 400 语义。

### 2. 权限页 principals manage 复选（FR-66-AC3 / V14）

- `PermAction` 扩四值 `read|write|delete|manage`（wire 全词形，T-217 实况）；
  `PERM_ACTIONS = [r,w,d,m]`——矩阵表头加 manage 列、diff/快照（targetdiff.ts
  ACTION_ORDER）同步扩 m、空主体行 colSpan 4→5、admin-note 文案 r/w/d → r/w/d/m。
- 回显按服务端 wire 序（read→write→delete→manage append 序）自然对齐；V14 断言
  `['read','manage']` 逐字。

### 3. readonly_admin 只读态（FR-66-AC2 / V13）

- **判定位**：`web/src/lib/api.ts` 新增 `AdminRole` 闭集类型 + `normalizeAdminRole` /
  `canAdminWrite` / `isReadOnlyAdmin`（Whoami 补 `adminRole?` 字段——session.go 两处
  回显已带）。UI 只做呈现，服务端 403 是唯一守门（V13 直接重放写请求验证）。
- **导航**：AppShell 安全/治理组对 readonly_admin 可见（adminOnly 门放宽为
  `admin || readOnlyAdmin`）；会话盒「只读」徽章（`session-readonly-badge`）。
- **页面呈现**（readonly_admin 进入时）：
  - 仓库/用户/组/权限列表页：数据可见（读面 CapRepoRead/CapSecurityRead 全过），
    写入口隐藏或禁用 + 「只读管理员视角」注记（`*-readonly-note`）；
  - 权限编辑器：深链可达、矩阵（含 manage 位）只读呈现（全部控件禁用、保存/删除/
    危险区不渲染）；/new 创建臂给只读空态；
  - 用户详情：角色下拉/Email/组员/口令输入全部禁用 + 保存禁用 + 注记；
  - 配额页：行内「编辑上限」禁用（repoManage write）；GC 危险区（dry-run+apply）与
    迁移启动维持 admin 门（Q2：dry-run 也 403）；仓库表单页非 admin 空态对 readonly
    给出专用文案；仪表盘横幅区分 readonly（读面全可见）与普通用户（面板收敛）。
- 用户列表「admin」列升级为「角色」列（admin / readonly_admin 徽章，来自详情端点回显）。

### 4. governance.ts 词表（T-215 移交项）

- `AUDIT_ACTIONS` 补 `user.role.change`（位置对齐 internal/audit Actions() 序：
  group.member 之后、permission.create 之前）——审计页动作选择器不再缺项；
  V13 断言 `option[value="user.role.change"]` 存在。

### 5. Playwright 三腿（`web/e2e/rbac.spec.ts` 新增，零新增运行时依赖）

- **V12**：admin UI 把 alice 设为 readonly_admin → toast → `GET /api/security/users/{u}`
  回显 `adminRole=readonly_admin` + `admin=false`；reload 后下拉回显；审计对账
  `action=user.role.change` 且 detail 含目标用户（FR-64-AC6 控制台侧闭环）。
- **V13**：readonly_admin 独立上下文登录走查——导航安全/治理组可见 + 只读徽章；
  仓库/用户（列表+详情）/组/权限（列表+编辑器深链）/审计五页可见且只读注记在位、
  写入口无 UI 路径（count 0 / disabled）；**服务端兜底**：同会话直接重放四类写请求
  （建仓 PUT / 保存用户 POST / 删组 DELETE / 写权限 POST 全词 manage）全部 **403**
  且 message 含 `administrator privileges`（errors[] 信封与纯文本两形态统一提取）；
  读面同时存活（GET /v1/permissions 200——只读态不是 403 姿态）。
- **V14**：编辑器勾选 manage → diff 确认框逐条（`授予用户 carol manage`）→ 保存 →
  `GET /api/v1/permissions` 回显 `users[carol] = ['read','manage']`（r/w/d/m 序）→
  reload 后复选仍勾（wire 往返）。

## 四、契约漂移

无（本票全部按契约文档实现）。两处**登记非漂移**的实况说明：

1. wire 动作集是**全词形**（`read/write/delete/manage`）而非架构文档个别处的字母缩写
   （r/w/d/m）——文档两种拼法混用但语义一致，前端取 wire 全词（T-217 实况）。
2. `user.role.change` 的审计 detail 形如 `{user, old, new}`（recordRoleChange）——
   审计页 detail 通用呈现，无需专用渲染。
