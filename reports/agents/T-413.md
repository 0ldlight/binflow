### 关键实现决策（规格依据）

1. **两段织入的「单源」边界**（ADR pt 4 / 轴 3-C 否决理由）：path include/exclude 的**匹配语义**只在
   auth 的 matcher（targetCovers/matchesAny）——SearchScope 只读 target 的 JSON 列做**存在性分类**
   （patterns 有无），行级裁决全部经 CanRead=allow()。模式永不翻译成 SQL。
2. **PathScoped=false 的判定充分性**：仅当某覆盖 target 的 includes/excludes 均空（targetCovers 空模式=
   覆盖仓内任意路径）才免行复核；includes 匹配空串的模式（`*`/`**`）不构成 open（excludes 可能仍在），
   分类一律走 pattern 在场即 scoped——过度分类安全（多查一次 CanRead），欠分类才是泄漏。
3. **超时码位 408**（Errata ⑤ 定案）：`ErrQueryTimeout` 哨兵 + cause **渲染不包装**（`%v` 而非 `%w`——
   包装会让 context.DeadlineExceeded 仍可 errors.Is 命中，408 族泄漏回 ctx 族；errorlint 抑制注释留痕）。
4. **6000 字符门**（Errata ⑥）：T-409 as-built 已在 Parse 入口（`ErrQueryTooLong`）——引擎入口=Parse，
   检查点满足，不重复设门。
5. **readonly_admin 全域 open**：照 auth.Can 的角色短路序（该角色 r 恒真）——与 CanRead 同源的推论；
   脱敏臂则按「非 full admin 即脱敏」（p.Admin）——readonly_admin 见 `unknown`（暴露面从严，Errata ⑧
   「非 admin」的从严读法，PM 可翻）。
6. **翻页/截断口径**（ADR pt 4 定案）：offset 为 SQL 侧 offset，逐页过行复核；Truncated=cap+1 探测见
   原始行序仍有余量（诚实上界，非「可见行余量」）。测试固化：2505 行三页不交并集=全量。
7. **流式装饰的真身**（ADR pt 5）：LIMIT 下推 + 物化上界 cap+1=1001 行——结构性零 OOM；httpapi 逐行
   encode 归 T-415（可选）。Engine 额外暴露 `Result.Elapsed` 供 T-415 记 metrics/慢查 WARN（本包保持
   零 IO，不自行打日志）。

## 规格依据（docs/reverse/aql.md）

- §5 K63 校准表：上限 1000+截断标记+分页可达全量（C 层）；429 码位与 body `too many requests`（A 层，
  ErrResourceBusy 消息逐字）；**408 超时码位（A 层，非 503/504）**；并发 4/不排队/Retry-After 头（C 层）；
  流式批大小形态对齐、参数自有。
- §5 上限通告文案 `AQL query reached the search hard limit, results are trimmed.`（A 层逐字——
  `TruncationNotice` 常量，T-415 渲 range.notification）。
- §6 权限语义：行级过滤在结果流侧、canRead 复核（BinFlow 等价实现=SQL 谓词织入+行复核，ADR-0043 钉死）；
  非 admin 脱敏 created_by→`unknown`（Errata ⑧ 归本票/T-415 投影装饰——本票在引擎侧单点落地）。
- §7 virtual 不作查询实体（scope 排除 virtual 仓）；Errata ⑦「展开后的成员仓仍过 SearchScope 织入」——
  织入在规划（virtual 展开）之后 AND 合取，构造序保证。
- ADR-0043 pt 1（文件布局：engine.go/gate.go 归 T-413；repo.Service +2 方法 api.go+search.go）、pt 4（两段
  织入+翻页口径）、pt 5（执行序+常量族+零配置键）、pt 6（错误面）、Errata ⑤⑥⑧。
