# T-157 — OIDC/LDAP HTTP 端点挂载（httpapi + route）

- 状态: done（待 review）
- 日期: 2026-08-22
- role: dev-go-core / area: `internal/httpapi`

## 做了什么

1. **OD-01** `GET /binflow/api/v1/oidc/login`：生成 256-bit 随机 `state` + PKCE（S256，
   复用 `auth.GeneratePKCEPair`），事务（state + code_verifier）写入短时 HttpOnly cookie
   `binflow_oidc_tx`（Path=/binflow/api/v1/oidc，SameSite=Lax，10 min），302 到 IdP 授权
   端点（`AuthCodeURL` + `code_challenge`/`code_challenge_method=S256`）。
2. **OD-02** `GET /binflow/api/v1/oidc/callback`：IdP error 参数 → 400；state 与事务
   cookie 常量时间比对（mismatch → 400 + warn 日志）；code 换 token（带
   `code_verifier`）失败 → 502；ID Token 经 **共享 Authenticator 的 OIDC Bearer 臂**
   验证并映射/自动建用户（`oidcPrincipal`：仅注入 `Authorization: Bearer <id_token>`
   的合成请求走 `Deps.Auth.Authenticate`，不复制 auth 层映射逻辑）；签发
   `binflow_session`（与密码登录同构、同 TTL/cookie 契约）+ 302 `/binflow/ui/`；任何
   退出路径都清除一次性事务 cookie。
3. **路由/中间件**：dispatchAPI 新增两条路由（空 routeAuth，浏览器匿名入口）；
   `Deps.OIDC OIDCLoginFlow`（消费侧 seam，`*auth.OIDCProvider` 天然满足）为 nil 时
   两条路由回答 E-26 404（FR-54-AC6/H29 不暴露端点）。T-91 B1 的「登录入口豁免」从
   POST /api/v1/session 扩展到两条 OIDC 路由（`isLoginEntryPoint`）：陈旧/被投掷的
   binflow_session cookie 不得把用户锁死在 SSO 登录之外。
4. **AC②（先本地后 LDAP）HTTP 面确认**：`handleSessionCreate` 既有调用
   `AuthenticateCredentials`（T-156 已含 LDAP 回退），WithLDAP 克隆不破坏该 facet——
   本票用真实 `auth.Service + 真实 auth.LDAPProvider + mock 目录`端到端验证（见测试）。
   httpapi 侧无需改动 handler。

## 遗留 / 需上游确认

1. **cmd + config 接线缺口（阻塞真实 Keycloak/OpenLDAP 验收 T-174）**：`internal/config`
   尚无 `auth.oidc`/`auth.ldap` 配置段，`cmd/binflow-server` 未构造 provider。期望接线：
   `oidc.enabled=true` 时 `auth.NewOIDCProvider(...)` 同一实例既传
   `svc.WithOIDC(prov, creator)` 又设 `httpapi.Deps{OIDC: prov}`；LDAP 同理
   `svc.WithLDAP(auth.NewLDAPProvider(cfg, auth.NewLDAPResolver(md.Users()), nil))`。
2. **internal/auth 缺导出的 userCreator 构造器**：`WithOIDC(prov, creator)` 的 creator
   参数在包外无法获得（`userCreatorAdapter` 未导出且 `NewFromStore` 设的 creator 会被
   WithOIDC 覆盖）。需 auth 层补 `auth.NewUserCreator(md.Users())` 之类的导出函数
   （或 WithOIDC 保留既有 creator），否则 cmd 只能关掉 OIDC 自动建用户。
3. **H36 的 whoami `source` 字段**：PRD 要求 whoami 返回 source，但 session 臂
   （internal/auth/session.go `authenticateSession`）把 `Source` 硬编码为 `local`，且
   whoami body 目前无 source 字段。属 auth 层（T-156 域）+ httpapi 小改，建议另开小票。
4. **同名用户冲突（PRD Q5 未定案）**：本地已存在同名用户而 LDAP 目录同名 bind 成功时，
   现行走「resolve by (provider,provider_id) 未命中 → 自动建行 → 用户名唯一冲突」路径，
   会得到 500（login failed）。本票未在测试中固化该行为（置信度低/待定案），需 Q5 定案后
   由 auth 层处理。
5. 存量 lint：`internal/httpapi/storage.go:144` revive empty-block（此前 ticket 遗留，
  非本票引入，未越权改动）。
