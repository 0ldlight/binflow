## 1. 做了什么

### 1.1 D8 翻转（AC1 主体）

`internal/adapter/conan/v1.go` 的 `serveV1RecipeDelete`（v1 `DELETE conans/<ref>`）：

- **旧（T-308 as-built）**：`resolveRRev` 解析 latest 修订 → 只删 `<root>/<rrev>/` 子树 → `removeRecipeRevisionEntry` 从 index.json 摘一行。多修订坐标删一次后旧修订存活。
- **新（本票）**：与 v2 面 `serveRecipeDelete` 同型——`subtreeExists` 判坐标根 `<user>/<name>/<version>/<channel>/` 存在 → `svc.Delete` 整树（index.json + 全部修订 + 全部包修订）→ 200；不存在 → 404（v1 族既有 miss 文案 `Path not found`）。写权限门原样走 `svc.Delete`（canWrite 不过 → 403，规格行代码补充）。删后索引手术不再需要（index.json 随树同灭）。
- 语义对齐：conan.md §3.2 D8 行双证——Artifactory `LocalConanHandler.removeRecipe` 对 `getRecipePath(...)`（无修订段）直接 repoService.delete；conan 1.66 参考实现 `remove_conanfile` 删整个 revisions 根（controller docstring "remove all revisions, packages and package revisions"）。
- 附带修正（登记）：miss 判定从「索引层 latest 可解析」改为「存储层坐标根有树」——索引损坏/为空但树在的坐标从「404 卡死不可删」变为「可整树清除」，与 Artifactory 路径基删除一致。404 文案选择：规格行只钉状态码不钉文案，取 v1 族既有 `Path not found`（§3.2 files 通道同款），不引入 v2 面的 `Couldn't find path`。
