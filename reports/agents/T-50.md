## ADR-0011 要点（DECISIONS.md 追加，未推翻任何旧决策）

**生成器**：Docusaurus（vs Hugo/Jekyll：无 React 生态、版本化要自建；vs 纯 Markdown 目录：无导航/搜索/版本切换，非产品级）。理由：与 M4 控制台同栈 React（技能/构建链/i18n 复用）、Artifactory 官方文档站同类形态（迁移心智连续）、版本化文档 + 中英 i18n 是产品级内建能力。

**接点 a 交付形态**：**go:embed 进 binflow-server、挂 `/binflow/docs/**`（统一前缀内）为主**；独立静态站点托管为用户可选自办（同一份产物），BinFlow 不承诺双轨。理由：15 分钟跑通 + air-gapped/离线场景文档随二进制走是差异化（独立站在受限网络恰不可达）；「单二进制含文档」与「含控制台」同一哲学。体积预算：docs 产物典型 5~15MB，40MB 上限内可控，M5 check-size 实测把关，超限 fallback 独立 tar（不预先复杂化）。

**接点 b 源文件工作流**：docs/user/ 保持 Markdown 源（tech-writer 按文件地图继续写入，frontmatter 只用 Docusaurus 兼容子集 title/description/sidebar_position）；`docs-site/` 目录聚合构建（docusaurus.config.js/sidebars/i18n 配置归 architect/release-engineer）；CI/Makefile 负责 build + 复制进 embed 目录；writer 的 DoD 不含构建站点。

**M4/M5 票面影响**（ADR 后果条目）：T-46 等 docs/user 既有产出即 Docusaurus 首批页面（frontmatter 兼容子集需回查）；M5 文档矩阵票前必须先有 **Docusaurus 脚手架票**（node 依赖/build 链/embed 复制//binflow/docs 路由/check-size 实测——类比 T-7 工程脚手架先行）；Makefile 增 `docs` 目标；M5 部署矩阵加「docs 站点产物」一项。
