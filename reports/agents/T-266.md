## 2. 债项 ②：repos-deploy / repo-deploy 入口 readonly 预收敛（T-242 遗留）

T-244 遗留原文：*"`repos-deploy-<key>` / `repo-deploy` 入口对 readonly_admin
未禁用（PUT 403 行内呈现兜底）——与 tree-deploy 的预收敛禁用不完全一致"*。
修法沿 tree-deploy（T-244 ⑤）/ T-237 / T-240 的 readonly 注记模式：

- `RepositoriesPage.tsx` 行内 `repos-deploy-<key>`：`disabled={readOnly}` +
  `title={readOnly ? '只读管理员不可写（服务端 403 兜底）' : 原文案}`（tree-deploy
  同款 tooltip 文案）。
- `RepoDetailPage.tsx` 头部 `repo-deploy`：同款双属性。
- 两页 readonly 注记文字补 deploy 语义（list：`创建/删除仓库与浏览器部署（Deploy）
  等写操作已禁用——服务端一律 403 兜底`；detail：`仓库配置只读、浏览器部署
  （Deploy）已禁用…`）。e2e 对两注记只断言可见性（grep 全量证明），改文案零断言风险。
- m-holder（普通 user 持 manage）不受影响：`readOnly = isReadOnlyAdmin(session)`
  仅对 readonly_admin 为真——m-holder 详情页 deploy 仍可用（写面由服务端按路径
  ACL 终裁，W12d 语义不变）。Set Me Up 入口不动（readonly 可用 + step-up 铸币，
  setmeup-deploy spec readonly 腿的既有口径）。
- **双保险形态保留**：DeployDialog 的 403 行内兜底（E-11 错误语义面）原样未动
  ——预收敛只是呈现层收敛；服务端 403 仍是终裁（spec 新断言钉死，见下）。
