# T-153 — auth.IdentityProvider interface + OIDC Bearer arm extension

## Area

`internal/auth`

## Acceptance Criteria

- AC1: Define `IdentityProvider` interface in `internal/auth/identity.go`. `Authenticator.Authenticate` adds a new OIDC Bearer arm that validates ID Token signature (JWKS) -> extracts claims -> maps to `*Principal` (Source=oidc).
- AC2: OIDC users auto-create `users` rows on first auth (`source=oidc`, `password_hash` empty, `is_admin` mapped per `admin_group`). Empty `password_hash` users cannot log in via Basic arm.
- AC3: Table-driven unit tests: `identity_test.go` + `authenticator_test.go` with new OIDC Bearer arm tests.

## Work Done

### Files created

- **`internal/auth/identity.go`** — `IdentityProvider` interface with `ProviderName()`, `Authenticate()`, `Resolve()` methods. Types: `Provider` (string constants `ProviderLocal`/`ProviderOIDC`/`ProviderLDAP`), `Claims` (Name, Groups, Admin, ProviderID), `ProviderUser` (Username, IsAdmin, Enabled), sentinel `ErrProviderUserNotFound`.

- **`internal/auth/identity_test.go`** — 5 tests: `TestIdentityProviderInterface` (mock implements the interface), `TestClaimsCarriesRequiredFields`, `TestProviderConstants`, `TestErrProviderUserNotFound`, `TestProviderUserStruct`.

### Files modified

- **`internal/auth/api.go`** — Added `Source Provider` field to `Principal` struct (line 35): identifies which identity provider authenticated the request ("local"/"oidc"/"ldap").

- **`internal/auth/authenticator.go`** — Key changes:
  - Added `oidcProvider IdentityProvider` and `userCreator userCreator` fields to `Service` struct (lines 39-43).
  - Added `Provider Provider` and `ProviderID string` to `user` struct (lines 66-67).
  - Added `userCreator` interface (lines 124-126) — write seam for auto-creating users.
  - Added `NewUserParams` exported struct (lines 131-138): Username, PasswordHash, IsAdmin, Enabled, Provider, ProviderID.
  - Added `WithOIDC(prov IdentityProvider, creator userCreator) *Service` method (lines 161-166): returns a copy of Service with OIDC arm wired.
  - Updated `authenticate()` dispatch (lines 204-217): between the API token Bearer arm and the Cookie arm, inserted the OIDC Bearer arm — when `oidcProvider != nil` and the token is not a known API token, try `authenticateOIDC()`.
  - Added `authenticateOIDC()` method (lines 290-348): validates token via provider -> resolves user -> auto-creates if needed -> returns Principal with Source=ProviderOIDC and Groups from claims.
  - Updated `authenticateBasic()` (line 250): users with empty password_hash (OIDC/LDAP) get explicit rejection with message "user %q has no local password".

- **`internal/auth/token.go`** — Line 62: `TokenVerifier.Verify` now sets `Source: ProviderLocal` on returned Principal (was missing; caused test failure `TestAuthenticateOIDCWithAPIToken`).

- **`internal/auth/session.go`** — Line 107: `authenticateSession` now sets `Source: ProviderLocal` on returned Principal (was missing).

- **`internal/auth/groups.go`** — `fillGroups` (lines 66-79): changed from overwriting `p.Groups` to union with existing groups (e.g., OIDC claims groups) with deduplication. Previously `fillGroups` clobbered the OIDC claims groups set by `authenticateOIDC`.

- **`internal/auth/deps.go`** — Added `userCreatorAdapter` struct (lines 136-155) implementing `userCreator` interface. Updated `userStoreAdapter.Get()` (lines 37-38) to set `Provider: ProviderLocal` (with comment that metadata.User struct doesn't have these fields yet — T-154).

- **`internal/auth/auth_test.go`** — Added 7 OIDC arm tests: `TestAuthenticateOIDCValidToken`, `TestAuthenticateOIDCInvalidToken`, `TestAuthenticateOIDCWithAPIToken`, `TestAuthenticateOIDCAutoCreate`, `TestAuthenticateOIDCNoAutoCreate`, `TestAuthenticateOIDCDisabledUser`, `TestAuthenticateOIDCUnwired`. Fixed test mocks to use exported `auth.NewUserParams` instead of anonymous structs.

## Specification Basis

- ADR-0020 (OIDC/LDAP authentication extension): interface design, auto-create, empty password_hash constraint.
- `docs/reverse/auth-model.md` section 3.6 (Bearer arm dispatch order).
- Migration 008 DDL (provider TEXT, provider_id TEXT columns on users table).

## Low-Confidence Items

- OIDC/LDAP session login (the session arm Source is hard-coded to ProviderLocal for now — T-154 will update when adding OIDC login endpoints).
- The `provider` and `provider_id` columns on `metadata.User` Go struct are not yet defined (migration 008 DDL exists but the struct update is deferred to T-154). The adapters in `deps.go` default to `Provider: ProviderLocal` with a TODO comment.

## Legacy Issues

None. All OIDC arm behavior is tested and passing.
