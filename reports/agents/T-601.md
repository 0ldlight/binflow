## 二、A 模型（权威，live 双轮钉死，drift 0）

**工件本体 GET/HEAD（local+virtual × generic+maven，六腿同形，HEAD≡GET 同键同值）**：

| 头 | A 形 |
|---|---|
| `Content-Disposition` | **恒发**（非仅非 ASCII 名）：ASCII 名=`attachment; filename="<basename>"; filename*=UTF-8''<basename>` 双参数；非 ASCII 名=**仅** `attachment; filename*=UTF-8''<pct-encoded>`（无 ASCII fallback 参数） |
| `X-Artifactory-Filename` | URL-encoded basename（非 ASCII 名=pct-encoded） |
| `X-Artifactory-Id` | 实例级 opaque id（双轮稳定，如 `c261ac14…:-8000`） |
| `X-Artifactory-Node-Id` | `art1`（节点标识） |
| `X-Artifactory-Origin-Remote-Path` | **字面量 `local`**（local/virtual 解析面的本地工件；远程缓存面真值未探） |
| `X-Jfrog-Version` | `Artifactory/7.161.26 86126900`（产品自标识） |
| `X-Checksum-Md5/Sha1/Sha256` | 全三键（计算值） |
| `ETag` / `Last-Modified` / `Accept-Ranges` / `Content-Type` / `Content-Length` | 无引号 sha1 / RFC-1123 / `bytes` / 后缀映射（.pom→`application/x-maven-pom+xml`、.jar→`application/java-archive`、.txt→`text/plain`、.bin→`application/octet-stream`）/ 实长 |

**状态变体头集模型**：
- **206**：= 200 全集 + `Content-Range: bytes 0-9/62`（前缀/后缀 Range 均 206）
- **416**：**裸集** = `Content-Range: bytes */<total>` + `Content-Length` + infra 三头（`X-Artifactory-Id/Node-Id`+`X-Jfrog-Version`）——CT/ETag/校验三键/CD/Filename/Accept-Ranges/Last-Modified **全撤**
- **304**：近全集 = 保留 CD/Filename/ETag/Last-Modified/校验三键/infra，撤 `Content-Type`/`Content-Length`/`X-Artifactory-Origin-Remote-Path`
- 条件族：If-None-Match 裸值与引号值均 304；If-Modified-Since 未来时刻 304

**virtual 解析面**：成员头全继承（与 local 腿逐字节同头集，含 Origin-Remote-Path: local）。

## 三、B 模型（pristine @4a7c0f74 双实例双轮，drift 0）

- 六面腿与 A 的**共有键全部同值**：X-Checksum 三键、ETag（无引号 sha1）、Last-Modified、Accept-Ranges、Content-Type（含 .pom `application/x-maven-pom+xml` 四点全一致）、Content-Length、206/Content-Range、304 撤 CT/CL、INM 引号容忍、HEAD≡GET
- **缺**：`Content-Disposition`、`X-Artifactory-Filename`、`X-Artifactory-Id`、`X-Artifactory-Node-Id`、`X-Artifactory-Origin-Remote-Path`、`X-Jfrog-Version` 全族——**六面×GET/HEAD×200/206/304 全状态零出现**
- **自加**：`X-BinFlow-Resolved-From`（**仅 virtual 面**：gv/mvv GET/HEAD/Range 均带，值=成员仓 key）；`X-Request-Id`（全响应请求级 UUID，normalize 类）
- **416 反向异态**：保持 200 全集（CT/ETag/校验三键/Accept-Ranges/Last-Modified 全留）vs A 裸集

**边界控制腿**（BIN-80 面，仅标记）：mv-get-sidecar-ctrl——A=200 裸（无 CD/无校验头/CT=`application/x-checksum`）；B=200 自加 `Etag`+`X-Checksum-Sha256`+`Accept-Ranges`＝已登记 BUG 面（maven/sidecar-get-x-checksum-sha256-echo）原样复现，归 BIN-80 修复票。

## 六、与 BIN-80/T-598（xsha-echo）边界声明

1. **本票面**＝工件**本体** GET/HEAD（下载面）响应头集；**BIN-80 面**＝**sidecar**（{src}.{algo}）GET/HEAD 的校验头回显（A 动词条件模型：GET 零校验头零 Etag / HEAD Etag+triple）。两票不得互相吸收对方腿面。
2. 边界控制腿 `mv-get-sidecar-ctrl` 在本票 raw 中**仅作分界标记**：其 B 自加 Etag/X-Checksum-Sha256/Accept-Ranges 面=已裁 BUG 原样复现，归 BIN-80 修复票，本票不重裁、不吸收。
3. **物理相邻警示**：generic 下载 handler 内 checksum-value 服务分支（pristine `generic/handler.go:483-484` 一带）与工件下载分支同文件；BIN-80 修复（sidecar 撤自加头）若触及该分支，不得顺手动工件本体面（F1/F2/F5 归 R14 票 A）；反之票 A 不得碰 sidecar 分支。**两票 area 按「路由分支」划界而非按文件**，互 review 时点名此注记。
4. 交叉不冲突面：工件 GET 的校验三键双端一致（本票六腿+L041 m1-get-jar-ctrl 双证）——BIN-80 修复 sidecar 分支不影响该结论；BIN-80 的 HEAD triple 缺键面亦不因本票 F1/F2 落地而变化。
