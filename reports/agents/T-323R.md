## 1. 方案选择（设计留痕）

缺口：`mpuRegistry` 进程态，协议坐标（repoKey/path/mime/部件账）无持久家 → 重启后 `/api/v1/uploads` 必 404。
T-323 给了两条路，**选型一（MultipartUploads 扩带 caller context 的 begin/resume 对）**，理由：

- **自持表被排除**：httpapi 是叶子，无自有 schema；走 metadata 需新表 + migration（越 area 且两张表无法共享 upload_sessions 的 TTL/sweep 生命周期）；走 data_dir 平面文件则失去事务性与既有清扫。
- **State 列所有权不破****：`s3SessionState` 是引擎自有 JSON，`Caller` 字段以不透明 blob 嵌入（引擎逐字存取、永不解释）——引擎仍拥有该列，REST 面仍零 metadata 触达（§5.3.1 contract 6 精神不变）。
- 新能力接口 `storage.MultipartUploadContexts`（Begin/Resume 对 + `MaxMultipartCallerState`=8KiB 上界）按能力发现惯例挂在 `deps.Uploads` 上断言——生产纯 S3 栈 `deps.Uploads` 即 S3Engine 本体（main.go:522 直通），无需给 httpapi 引入 Engine 依赖。

关键裁决（防跨面串扰）：**ResumeSessionContext 只收养带 caller blob 的行**——docker 臂走 plain `Engine.ResumeSession` 不写 blob；REST 探测 docker 会话 id（或反向）在引擎侧于任何 S3 调用/注册表 attach **之前** fail-closed 为 `ErrSessionNotFound`，行不动、活句柄不打扰。测试钉死（§4 TestS3ResumeContextFailClosedAndBounds）。

部件账不持久化：`parts = ceil(offset/partSize)`、`awaiting-complete ⟺ offset%partSize≠0`，从引擎权威 `Session.Offset()` 对持久 partSize 推导（REST 面契约保证非末部件恰为 partSize）——行与字节不可能打架，pending partBuf 字节随进程死（T-323 语义）。

## 2. 实现清单

`internal/storage/api.go`：`MultipartUploadContexts` 接口 + `MaxMultipartCallerState`（8KiB）+ 契约注释。
`internal/storage/s3.go` / `s3_resume.go`：
- `s3SessionState.Caller`（omitempty，v1 兼容：旧行解出空串=不可经此通道收养）；`s3Session.caller`；`sessionStateLocked` 快照携带（部件 flush 的 SetState 不丢坐标）。
- `beginSession(ctx, partSize, caller)`；`BeginMultipartSessionContext`（空/超界 caller 在任何服务端资源打开前拒绝）；`resumeSession(ctx, id, requireCaller)`；`ResumeSessionContext`。
- **附带（T-323 §5-3 同票裁决，一行级顺手修）**：`sweepOrphanSessionObjects`——complete 成功后 CopyObject 前 crash 窗口留下的**已完成** `sessions/<uuid>/data` 对象（in-progress 清单看不见，T-323 §6 登记残件），按对象 LastModified 超 TTL 清扫，挂入 `sweepSessions`（随引擎 Open + T-324 维护钟跑，fresh/rebuilt 两臂的窗口都盖住）。安全性：in-progress 会话在其 key 上**无对象**（部件是 MPU 态）；任何 complete 都以新 LastModified 覆写该 key，超龄对象按构造不可恢复（行过期先于对象超龄，同一时钟）。

`internal/httpapi/uploads.go`：
- 包注释改写（重启可见性契约）；`mpuCallerState`（v1：repoKey/path/mime/partSizeBytes/createdBy/createdAt）。
- `mpuRegistry.resuming` + `mpuResumeAttempt`：per-id single-flight funnel（docker T-216 同款：flyer 在 r.mu 外跑 ResumeSessionContext——S3 I/O 不许挡无关查找；waiters 共享结局、不随各自 ctx 短路）。

## 5. 遗留

- **config 重分片（swap）后的会话不跨重启**：swap 换新引擎会话（新 uuid 行）而 REST id 保持旧值（能力 URL 稳定），重启按 REST id 只能命中已 abort 的旧行 → 404。swap 时零字节在途，客户端 re-create 无损；修它需引擎侧同 id 重开（begin-with-id）语义，收益不抵侵入，登记即可。
- 裸 status 列表只展示**本进程已知**会话；重启会话在被任一动词首次寻址后才入列（docker T-216 同款 lazy 姿态，包注释已声明）。
- 多实例共享 bucket 的 sessions/ 对象清扫安全性：对象级超龄判定与单实例论证同构（任何 complete 覆写 key 时间戳），但未做多实例演练，维持 T-323 §6 的登记口径。
- MinIO scratch 容器已销毁；kill -9 引擎测试 env 门控默认 skip（CI 不依赖容器）。
