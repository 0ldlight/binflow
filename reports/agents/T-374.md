### 2.3 附带发现（如实回写 + 遗留）

**交互式 `npm login --auth-type=legacy` 在真实链路不可用**（npm.md 原文按 PRD 口径声称可用；T-77 O-4 已自认「交互式流程未在本轮直跑」——本票补课实证）：

- 机制：npm 把账密放登录 PUT 的 **body**（couchDB 惯例，不带认证头）；而 httpapi 内容面对写动词先过认证（`contentAction(PUT)` → required，middleware.go 匿名 PUT → 401 `authentication required` + `WWW-Authenticate: Basic`），**请求到不了** npm 适配器的 body 凭据臂（session.go:96-125——该臂在适配器单测直调下工作正常，`TestLoginIssuesToken` 绿；全程 0ms 佐证比对从未执行）。
- 实测：expect 伪TTY 交互 login → E401「Incorrect or missing password」（npm 对外层 401 的渲染）；curl 带 Basic 头同端点 → **201 铸 token 正常**（header 臂好使）。
- 处置：npm.md login 行改为如实描述（含 T-77 O-4 留痕引用 + 修复归服务端票）；日常路径改推 `_auth` / `_authToken` 两行。**遗留 L1 见 §4**。
