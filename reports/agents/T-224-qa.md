## 1. 环境与起法（复现用）

```
# Keycloak 26.2.5（dev 模式，kcadm 配 realm/client/组/用户 + groups mapper→claim id_token）
docker run -d --name t224-keycloak -p 8181:8080 \
  -e KC_BOOTSTRAP_ADMIN_USERNAME=kcadmin -e KC_BOOTSTRAP_ADMIN_PASSWORD=… \
  quay.io/keycloak/keycloak:26.2.5 start-dev
# client: confidential+secret(env 注入 BINFLOW_AUTH_OIDC_CLIENT_SECRET)、standard flow、
#         PKCE S256 (attributes.'pkce.code.challenge.method')、redirectUris 8180/8183 callback
# OpenLDAP（osixia；bootstrap 挂载目录会被其 startup rm 清空——改为起后 ldapadd 注入 + ldapi EXTERNAL 改 ACL）
docker exec -i t224-openldap ldapadd -x -H ldap://localhost:389 -D cn=admin,… -w … < 60-structure.ldif
docker exec t224-openldap ldapmodify -Q -Y EXTERNAL -H ldapi:/// -f acl.mod   # by users read（T-174 姿态）
# BinFlow 三实例（本报告 §0 端口/键名）；docker 流: docker:27-dind --insecure-registry=host.docker.internal:8180
```

OIDC 表单腿用 curl cookie jar 三步（init→authorize 表单→POST 凭据→callback）。**坑**：login init 的请求域必须与 `redirect_url` 同 host（127.0.0.1 vs localhost cookie 域分离会致 tx cookie 丢失 → callback 400）。

## 4. 缺陷

**无（P0~P2 均无）。**

非缺陷登记（转 conductor 知会，不阻塞本票）：
1. **NFR-S41 措辞 vs ADR-0027**：NFR-S41 写「TTL ≤5min」，而 ADR-0027 决策 4/PRD K12 定案域为 **[60,3600]**（实测 3600 可启动可服务）。契约以 ADR 为准（T-214 终裁），建议 PM 把 NFR-S41 措辞修为「默认 300s、域 [60,3600]」。
2. **PUT /api/security/users/{name} 部分更新门槛**：仅翻 `enabled` 也必须带 email+password（replace 臂语义，Artifactory 兼容文案「Please provide a valid user email.」）。T-208 seam 行为正常（全量体 201），文档/控制台需按此姿势调用（归 T-218/T-225 面）。
3. **回跳腿残留**：第二身份回跳会在 `users` 留下 ssouser2 自动建行（Bearer 臂解析副产物，H25 既有行为；grant 仍被拒）。设计使然，登记备查。
4. **grant 签发无独立审计事件**（review 已判 non-blocking 维持）：签发/未消费焚毁仅 INFO 日志，无 `step_up.grant` 类审计词——review §5 建议的评估小票维持待办。

## 5. 企业部署默认值建议（任务项 8）

- **默认 off 不改变现状**：实例 B（零 step-up 配置）Q11 四护栏全部原样（自铸 200/他人 403/TTL 帽 401/禁用即 401）、审计零新字段——升级即开箱无感，平移脚本零影响（实测）。
- **CI/Basic 臂零影响**：开启态下 `curl -u`（CI 姿势）与 `/v2/token`（docker login 底座）均不触发二次认证；docker push/pull 往返逐位一致（实测 digest 稳定）。企业开 `auth.token_step_up` 不需要动任何 CI 凭据。
- **建议开启人群**：所有有人机交互（web console）访问的企业部署——威胁模型是 session cookie 被盗后铸 365d Token（ADR-0027 背景）；纯 headless/CI-only 部署收益趋零、可不开。
- **开启成本**：本地/LDAP 用户铸造时多一步口令重验；OIDC 用户多一次 `prompt=login` 重认证（console T-218 落地后为引导流）；TTL 默认 300s 合适，勿调向 3600 上限（窗口越大，被盗 grant 的可用期越长）。
- **运维注意**：grant 台账进程内存——重启即清（用户重走一次重认证，可接受，ADR 决策 4）；多实例部署时各实例独立台账，grant 必须回到签发它的实例消费（当前单实例部署事实，与 ADR 假设一致）。
