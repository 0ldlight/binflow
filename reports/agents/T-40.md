## AC 对照

1. **AC1 形态**：`_catalog` → 200 `{"repositories":["<repoKey>/<image>",...]}` 全局字典序（源 = `svc.ListImages` 聚合 = docker_manifests distinct；跨 repo 聚合后**必须全局重排**——`team-x/app` 按字节序排在 `team/app` 之前（'-' 0x2D < '/' 0x2F），按 repoKey 分段拼接会错序，测试 `TestCatalogListsImagesLexicographic` 含嵌套名 `team1/acme/team/app`）；`tags/list` → `{"name","tags"}` 字典序；空仓 `"tags":null`（`TestTagsListNullOnTaglessImage`，指针解码断言等价 `jq '.tags == null'`）；name 不存在 → 404 `NAME_UNKNOWN`（未知镜像/未知仓/非 docker 仓三态）。

## 设计裁定（本票内，可复审）

1. **聚合在 adapter**：`svc.ListImages` 是单 repo 签名（T-35 契约），跨仓 catalog 由 adapter 聚合（repo 枚举走自有 `RepoLookup.List` 缝——生产包装 `metadata.RepoStore.List`，构造器签名不变，零装配点改动）。每可见 repo 一次全量（n=0）再全局切片：正确性要求（页可跨 repo），代价是单节点规模可控；M3+ 若需下沉，应给 Service 加全局 ListImages（架构面，非本票）。
2. **catalog 游标不预检**：官方语义是「> last 过滤」，last 无效形（越界/不存在）返回空尾而非 400——与 distribution 一致；`ErrInvalidCursor` 的 repoKey 前缀校验只在 per-repo 透传时才有意义，聚合路径不触发（tags/list 仍透传并映射 400）。
3. **cursor 错误码复用 `PAGINATION_NUMBER_INVALID`**：官方错误码表无 cursor 专用码（distribution 仅注册 NUMBER_INVALID），repo.ErrInvalidCursor 注记「官方 family 所在」按此落。
4. **空 catalog 渲染 `[]`**：null 约定仅 tags（PRD R4）；repositories 空 JSON 数组更稳（Artifactory 同）。
5. **catalog GET-only**（+405+Allow: GET）：spec 仅定义 GET；与 ping 的 GET+HEAD 不同属端点语义差异，非不一致。
