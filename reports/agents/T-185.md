### D4：IdP 组落库 + is_admin 每次认证刷新

- 新增 `internal/auth/idp_sync.go`：
  - 消费侧写缝 `GroupSyncSource`（`SetUserGroups` + `ListGroupNames`）与 `AdminFlagWriter`（`SetAdmin`），`WithGroupSync` / `WithAdminFlagWriter` 构子（clone 语义）。
  - `syncProviderGroups`：claims 组集 → 与 `user_groups` 现值比较 → 有差异时按本地组存在性过滤（未物化的 IdP 组名跳过，Debug 日志）→ `SetUserGroups` 原子替换（Info 日志）。稳态零写（集合相等即返回）。
  - `refreshProviderAdmin`：claims.Admin 与 DB 行不一致时写回（`UpdateProfile` 保 email），请求 Principal 一律用 claims 值（ADR-0020：provider 权威）；写失败记 Error 不阻断。
- `authenticator.go`：`authenticateOIDC` / `authenticateLDAP` 的 resolve 路径与 auto-create 路径都接入 sync + refresh。
- `deps.go`：`groupStoreAdapter` / `userStoreAdapter` 实现新缝；`NewFromStore` 装配（WithOIDC/WithLDAP clone 会带过去，cmd 装配无需改）。

**语义决策**（PRD 置信度「中」，已在测试固化，见 §5 遗留）：

| 决策 | 依据 |
|---|---|
| 替换（replace）而非并集 | PRD FR-54/OD-05「每次登录刷新组成员；被移除的组在刷新后权限即时失效」（FR-54-AC5/H28 的验收形态就是移除→重登→403） |
| 未物化的 IdP 组跳过、不自动建组 | T-174 H28 实测姿势（QA 先本地建组 developers 再授权）；自动建组会扩授权面且 reverse 规格未覆盖（auth-integration.md 待验证清单 #3） |
| claims.Groups == nil 不动成员、非 nil 空集清空 | groups_claim「可选」（PRD）；nil=无组信息（防未配组面的配置每登录清掉管理员手授的本地组），`"groups": []`=显式零组 |
| is_admin 对 provider 行每次认证以 claims 为准（含降权） | ADR-0020 管理员映射条款明文「后续每次认证时根据 Provider 最新 claims 刷新」；O-4/D4 指控的正是「首登定死」 |

### D4 session 半边（AC2）

组授权对 session 用户生效的机制 = 登录时落库 + `authenticateSession` 重建 Principal 后 `fillGroups` 读 `user_groups`（既有 M2/M4 链路，无需改 session 臂本身）。另补 `AuthenticateCredentials` 成功路径的 `fillGroups`（登录响应的 whoami 直接带组；本地用户登录也报 DB 组）。

### D1/D2（httpapi）

- `security.go`：`userListItem`/`userDetail` 增 `source` 字段；`realm` 由恒 "internal" 改为按 provider（local→internal，oidc/ldap→同名；依据 docs/reverse/auth-model.md §1.1「realm: internal/ldap/… 按用户返回」高置信）。`providerSource` 归一化未知值防走私（与 adaptUser 同规则）。
- `session.go`：`sessionWhoami` 增 `groups`（恒渲染 `[]` 非 null），login 响应与 GET /api/v1/session 两处填充。
