## 一、做了什么

在 T-148 骨架（help/--version/BINFLOW_SERVER_URL）之上，用 **flag 包**（非 cobra）实现两级分发（noun → verb）与四个子命令，全部 HTTP 调用链直接消费 T-165 的 `internal/client`（零重复造轮子）：

1. **`bf repo create <key> --type --package-type --description`** → `client.CreateRepo`（PUT `/binflow/api/repositories/{key}`）；成功输出 `Repository '<key>' created.`；rclass/packageType 客户端 fail-fast 校验。
2. **`bf artifact upload <file> --repo --path [--content-type]`** → `client.UploadArtifact`（PUT `/binflow/{repo}/{path}`）；本地预计算 sha256（先 hash 后 Seek(0)，与 client 重试语义解耦），输出 `sha256: <hex>` + `uri: <base>/binflow/<repo>/<path>`（H58 要求的两要素）。
3. **`bf user create <username> --password|--password-env --email [--admin]`** → `client.CreateUser`（PUT `/binflow/api/security/users/{name}`）；成功输出 `User '<username>' created.`；--email/--password 客户端前置校验（对齐服务端 400 语义）。
4. **`bf token create [--username --expires-in --scope --description]`** → `client.CreateToken`（POST `/binflow/api/security/token`）；**token 原值打印为 stdout 第一行**（H60 的 `| grep` 脚本形态可直接消费），后随 `token_id/username/scope/expires_in` 元数据行。

### 配置管理（AC ②）

`~/.bf/config.yaml`（`BF_CONFIG` 可改路径），YAML 用 `go.yaml.in/yaml/v3`（与 internal/config 同一 import 路径）：

```yaml
default_profile: default
profiles:
  default:
    base_url: http://localhost:8080
    username: admin            # 非密钥，可落盘
    password_env: BINFLOW_PASSWORD   # 密钥只存 env 变量名（引用），不落明文盘
    token_env: BINFLOW_TOKEN
    skip_tls_verify: false
```

- **密钥不落盘**：profile 只承载 `password_env`/`token_env`（环境变量名），运行时解析；不提供任何明文密钥 YAML 字段。
- 覆盖序（高→低）：base URL `--server` > `BF_BASE_URL` > `BINFLOW_SERVER_URL`（T-148 别名保留）> `profile.base_url` > 内置默认；凭据 `BF_TOKEN` > `token_env` 解析；basic `BF_USERNAME`+`BF_PASSWORD` > `profile.username`+`password_env` 解析。
- `--profile <name>` 切换；未知 profile 报错并列出可用名；`default_profile` 指定隐式选择；**零配置可用**（无文件 → 空 profile → 默认 localhost:8080）。
- Basic 认证通过 CLI 层自定义 `http.RoundTripper`（`basicAuthTransport`，仅在请求无 Authorization 头时注入）与 `client.NewWithClient` 组合实现——internal/client 只注入 Bearer，本组合不改 client 包即补齐 basic 臂，且 Bearer 优先级自然保持。
- `skip_tls_verify` 走 `Transport.Clone()` + InsecureSkipVerify（显式 `//nolint:gosec` 带理由，opt-in 语义）。
- 配置解码复刻 T-8 B1 裁定：**多文档 YAML 拒绝**（第二个 Decode 必须 io.EOF）；文件缺失/空文件 → 空配置非错误。

### flag 细节

- 全局旗标（--profile/--server/--help/--version）须在命令词之前（stdlib flag 在首个非旗标参数处停止解析，usage 已注明）。
- `parseArgs` 助手支持**位置参数与旗标交错**：`bf repo create test-repo --type local` 与 `bf repo create --type local test-repo` 等价（消费一个位置参数后重解析剩余）——PRD 示例均为位置参数在前，必须支持。
- 子命令 `-h/--help` 由 flag 内建 ErrHelp 触发、经 `ignoreHelp` 映射为 exit 0（帮助输出 stdout；修掉 T-42 登记过的「子命令 --help exit 1」老问题在本二进制的形态）。
- 退出约定：失败 → stderr 错误 + 非零退出码；服务端 `errors[].message` 经 client StatusError 透传到错误文案（有测试钉住）。

## 五、遗留（供 conductor 裁量）

1. **【跨包缺陷，阻塞 QA T-175 H57/H60】internal/client 解码面与真实服务端两处不匹配**（本票 area=cmd/bf/，未越界修复；测试假后端按 client 契约给 JSON）：
   - `client.CreateRepo` 把 2xx 响应体按 JSON 解码，而真实服务端 `handleRepoPut`（internal/httpapi/repositories.go:374）回 **200 纯文本** `Successfully created repository 'x'\n` → 对真服务器建仓成功会被 CLI 报成 `client: decode response` 错误。
   - `client.CreateToken` 期望 `{"token":…,"token_id":<string>}`，而真实服务端 `tokenCreateResponse`（internal/httpapi/security.go:133-138）回 **`access_token` + `token_id` 为 int64** → 解码报错（number into string）。
   - 修复建议（internal/client 小改）：repo/user 族 2xx 非 JSON 体按成功容忍（或按 Content-Type 分流）；TokenCreateResponse 改 `access_token` + int64 token_id（或双字段兼容）。修好前 QA 请勿按 H57/H60 判 CLI 死刑。
   - `CreateUser`（真服务端 201 空体，client 跳过空体）与 `UploadArtifact`（out=nil 不解码）两链对真服务端可用。
2. `bf config set <key> <value>`（PRD CL-02 提及）未实现——票面 AC 仅要求读取/引用；如需写入面建议另派小票（含原子写与权限 0600）。
