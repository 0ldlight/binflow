### 设计要点（对照 T-321 模式）

- **产物形态**（rpm.md §4.2-4.3）：`repodata/repomd.xml.asc`（全文 detached ASCII armor）+ `repodata/repomd.xml.key`（关联 keypair 的 armored 公钥，dnf `gpgkey=` 的直接消费对象）。两者**固定名**——与 deb 的 InRelease/Release.gpg 同为固定名族，轮换=同路径覆写，代数保留（`pruneGenerationsLocked` 只碰摘要前缀文件，固定名天然白名单）。
- **X-GPG-PASSPHRASE 不收**（D-8）：管理面与内容面都不读该头；口令封在 keypair 行，seam 签名时解封。
- **virtual 聚合不签**：确认 T-315 报告 D-3 口径（404 + 成员签名必验不过），照旧。规格差异登记见下。
- **错误分类**：两哨兵→跳签清旧（4.3 的「防旧签名验新 repomd」）；执行错→recompute 500 上浮。

## 真实 dnf gpg 链（BINFLOW_RPM_E2E_GPG=1，rockylinux:9 容器，PASS 99s）

`TestClientE2EDnfGpgContainer`：真 rpmbuild 制包→curl PUT→sync reindex（签名）→容器内：

1. **阴性对照**：`repo_gpgcheck=1` + `gpgkey=file:///etc/pki/rpm-gpg/binflow.asc` 但**未导入** → `dnf makecache -y` 拒绝：`Failed to retrieve GPG key … Couldn't open file …binflow.asc`，标记 `MAKECACHE REFUSED AS EXPECTED`。
2. **正向**：`curl <host>/repodata/repomd.xml.key` 落盘 + `rpm --import` → `dnf makecache -y` `Metadata cache created.` → `dnf repoquery -y`（`binflow-e2e-gpg-0:1.0-1.el9.noarch`）→ `dnf install -y` → `rpm -q` → `cat hello.txt` = `binflow t322 gpg` → `Complete!`。
3. 回归：`BINFLOW_RPM_E2E_DNF=1` 的原（无签名）容器链复跑通过。

### 容器腿首跑发现并修掉一个真问题（测试侧）

首跑阳性腿报 `repomd.xml GPG signature verification error: Bad GPG signature`。容器内二分定位：**gpg 本体对线上三件套验签 GOOD**（字节对齐无误，sha256 存档），rpm 4.16.1.3 在**密钥确认后**也验过（`makecache -y` 直接 `Metadata cache created.`）——根因是 dnf 的 gpgkey 导入确认在无 tty 管道下读到 EOF→按拒绝处理，librepo 把「无钥可用」误报成 Bad GPG signature；且测试原把 makecache 管道接 grep/head，**pipeline 末命令退出码掩盖了真失败**。修正：所有验元数据的 dnf 调用带 `-y`、makecache 改重定向后 grep（退出码保真）、阴性/阳性腿显式标记输出。产品侧无改动（签名本身与 rpm/dnf 完全互通）。
