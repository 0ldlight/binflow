## 1. 结论摘要

§11.31 债在**引擎层付清**：S3 multipart 会话的 upload ID 落 `upload_sessions` 表，
`S3Engine.ResumeSession` 经 ListParts 重建（部件清单 + 持久字节偏移），kill -9 后重启可续传至完成并通过完整性对账。
**探针断言翻转在 REST 面被登记为共享文件交集**（mpuRegistry 是进程态 + 协议坐标无持久家；需动 `cmd/binflow-server/main.go` 接线与 `internal/httpapi/uploads.go` —— 两者均在 T-319 在途域），本票按纪律不改，交付精确补丁文本（§5）。

关键设计事实（live MinIO 实证，见 §3.1）：**in-progress MPU 的部件不可读回**
（GetObject partNumber → NoSuchKey；raw GET partNumber → 400）。因此磁盘臂的「重哈希部分数据」恢复在 S3 侧无对应物，
重建会话的 Commit 走**完成-后读回校验门**：CompleteMultipartUpload → 流式读回装配好的临时对象 → 三摘要对账 → 才发布。
慢于内存链，但校验的是将发布的真实字节。

## 2. 实现清单

`internal/storage/s3.go`：
- `S3EngineOptions.Sessions`（`metadata.UploadSessionStore`）+ `Logger`；engine 增 `rows/log/ttl` 字段。
- `beginSession`：NewMultipartUpload 成功后 Create 行（state JSON 携 upload_id/upload_key/part_size/created_at/received）；
  行写失败 → abort 新 MPU 并 fail（磁盘臂 dir→row→file 序的 S3 镜像：crash 在两者之间 → 孤儿 MPU 交 TTL sweep）。
- `flushPartLocked`：每个部件落 S3 后 best-effort `SetState`（received==已落部件和的精确时刻；WithoutCancel，磁盘臂 N3 同款）；
  失败 → 毒化（fail-closed，与磁盘臂 persistStateLocked 对齐）。
- `Commit`：`preResumed > 0`（重建会话）分流至 `commitRebuiltLocked`；否则原内存链校验路径不变。
- **complete-race 分支补 B5**：complete 报错但目标 blob 已在（并发赢家）时，原代码 `finishLocked` 不 abort → MPU 泄漏到 TTL；
  现补 best-effort `AbortMultipartUpload`（fresh 与 rebuilt 两臂同修，回归测试 + 变异验证见 §4）。
- `Close`：**有 rows 时改为 ADR-0028 保留语义**（detach 不 abort；MPU+行存活，重启即续传；一行 INFO 报告保留清单——SIGTERM/compose restart 与 kill -9 等价）；
  无 rows 保持历史 abort（无可续传物则急切回收更优）。
- `finishLocked`：终态动词删行（done+forget 不够，行不得长命于上传）。
- sweep 扩为 `sweepSessions`：过期行 → 连带 abort 其 MPU + 删行；既有孤儿 MPU 年龄扫描 → 现在连带删其行（key 内嵌 session id）。
- `sessionIDFromUploadKey`：`<prefix>/sessions/<uuid>/data` → uuid 抽取。

`internal/storage/s3_resume.go`（新）：
- `s3SessionState`（v1 JSON，metadata 层不解释）+ marshal/unmarshal。
- `ResumeSession` 全契约：无 store/缺行/过期未扫/无 upload_id → `ErrSessionNotFound`（fail-closed，行不被拒答消耗）；
  ListParts 分页重建 parts + offset=Σsize；**pending partBuf 字节随进程死**（offset=最后落盘边界，行内 received 只是遥测、永不信任）；
  NoSuchUpload → 同 key 新开 MPU、offset 归零（磁盘臂「行在数据文件失」的镜像）；同 id 活会话 last-writer-wins、锁外 detach（锁序同磁盘臂）。
- `commitRebuiltLocked`：tail 部件入私有 sessions/ key → complete → **读回门**（io.Copy 过三摘要、尺寸对账、normalizeHex 同表校验；
  mismatch → RemoveObject 临时对象 + ErrChecksumMismatch，零发布）→ 持有 hold → dedup → CopyObject 发布。
- 内存上限：读门为流式（三个固定 hash 态），与制品大小无关。

`internal/storage/api.go`：`Engine.ResumeSession` 与 `MultipartUploads` 契约注释翻转（S3 自 T-323 起可续传；store-less 保持硬 404）。

## 3. 真实 MinIO kill -9 链（验收主证据）

### 3.1 前置实证：in-progress 部件不可读

`docker run minio/minio:latest`（127.0.0.1:29000，bucket t323）+ 一次性 Go 探针：

```
ListParts: 2 parts, objectParts: part 1 size=5242880 ... part 2 size=5242880
partGET read err: The specified key does not exist.
rawGET partNumber=2: status=400
```

→ 读回门只能发生在 complete 之后（装配对象是全文唯一可读形态）。

### 3.2 kill -9 全链（`TestS3ResumeKill9AgainstLiveMinIO`，真进程真 SIGKILL）

子进程（测试二进制 re-exec）：sqlite rows 库 + S3Engine，BeginSession 后流 5MiB 部件，打印 SESSION id + READY 后阻塞；
父进程 `Process.Kill()`（SIGKILL，无 Close 无清理）→ 进程内 digests/partBuf 全灭，sqlite 行 + MinIO MPU 幸存 →
新引擎同 bucket 同库 ResumeSession → ListParts 重建 → offset==5MiB 断言 → 续传 6MiB → Commit → Stat 重哈希 + Open 逐字节对账 →
行消耗 + 零在途 MPU 残留。**本测试首轮曾红**：子进程自造随机 payload ≠ 父进程 whole → 读回门抓住内容不一致（409 语义）——
恰是该校验门拒错的活体证明；修正为共享 payload 文件后绿。

```
    s3_resume_test.go:823: child streaming into session 079b6c2f-...; delivering SIGKILL
--- PASS: TestS3ResumeKill9AgainstLiveMinIO (0.74s)
ok   github.com/lzwzzy/binflow/internal/storage 1.175s
```

mc 终态审计：bucket 内恰 1 个 sha 寻址 blob（11MiB），`mc ls --incomplete` 为空，sessions/ 零残留。

## 5. 差异登记（共享文件交集——按纪律不改，附精确补丁）

2. **`internal/httpapi/uploads.go`（httpapi 包，T-319 在途域）——REST 面重启可见性（T-209 N6/O-2 同类债）**。
   `mpuRegistry` 为进程态且协议坐标（repoKey/path/mime/部件账）无持久家 → 重启必 404。方案（docker 臂 T-216 同款）：
   `resolveMPUSession` 缺行时经 per-id single-flight 走 `Engine.ResumeSession`；协议坐标需随行持久
   （upload_sessions.State 为引擎所有，建议 MultipartUploads 扩一个带 caller context 的 begin/resume 对，或本面自持表）——
   **建议独立小票**（T-323 交集登记）。同文件 47~56 行包注释（"S3 restart-resume stays the registered §11.31 M8+ debt"）随之过期。
3. **`internal/adapter/docker/resume_test.go`（非本票域）**：`hardNoResumeEngine` 注释称 mirrors S3Engine contract——
   S3 现已可续传，该 fake 仍是合法的「永不续传后端」夹具（适配器 404 行为测试仍成立），但镜像表述过期；顺手票可改注释。
   注意：**接线落地后 docker 面 S3 重启续传自动获得**（其 resolve 已走 ResumeSession），无需适配器改动。
4. **探针 leg 4 翻转条件**：1+2 落地后，`m10-mpu-probe.sh` leg 4 由 404 断言翻为
