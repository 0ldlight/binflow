## 2. 实施中修复的回归（根因链）

1. **对话框回调 ref 抢焦**（permissions.spec:349 首轮稳定红，两轮复现）：ResourceDialog 的 `focusCancel` 回调 ref 每次渲染都是**新函数**——React 对变化的 ref 走 detach(null)→attach(node) 重挂，对话框内每敲一个字符（state 更新重渲染）就 queueMicrotask 把焦点抢回取消钮。事件捕获探针实证：`keydown@INPUT` 一帧后 `keyup@BUTTON:perm-res-cancel`，后续键入全部落进按钮、Enter 合成 click 取消 → 对话框关闭。**修法：`useCallback` 稳定引用**（只在真实 mount 时触发一次）。**同一潜伏缺陷在批 B 的 ConfirmDialog 里存在**（fill 型 spec 不可见——一次性 input 事件后才抢焦；type 型键盘流必炸）——同修。建议回写 spec §4.2/T-344C 交接 D6 条目：回调 ref 首焦必须 useCallback。
2. **axe × Dialog Fade 竞态**（T-344C D7 预警面）：permissions.spec:102（perm-res-dialog）与 repositories-admin.spec:50（pkg-grid）两处 axe include 扫描落在 225ms 入场动画中途——补 `toHaveCSS('opacity','1')` 收敛等待（断言语义不变，批 B 先例同款）。
3. **无钥匙实例重启失败**：首轮实例的 SAML secret 已被旧随机主密钥密封，新随机钥匙解不开（`stored secret cannot be unsealed`）——净数据目录重启解决；也说明这类实例的 key 必须跨重启固定（运维口径，非本票面）。

## 5. 差异登记（规范文字 vs 实际落地）

- **D-1 `.card` 族落地为 `:not(.MuiPaper-root)` shim 而非换装即删**：spec §3.2 波 B 行的 `.card` 换装范围 = 批 B 六页；实际 pages 域尚有 31 处 div 消费者（批 C 未覆盖 .card——四主线无此项）。shim 达成规范真实意图（换装面即刻 MUI 皮肤），末位 div 换装后整块删除（建议登记下批）。与批 C D-2 的 `.badge` shim 同族。
- **D-2 `.field` 族仅六页内浮标化**：`.field > input`/`.confirm-input`/`.modal .server-reason`/`.field-error`/`.field-hint` 等规则保留——ArtifactsBrowser/widgets/LicenseAddons/RepoDeleteConfirm/GCPage/MigrationPanel 等域外消费者在役（T-344C D10/T-344D D-5 谱系）。spec §3.2 的 C 波「TextField label 浮标化」在 pages 全域的收口需要单独票（预计随下批 .card 同收）。
- **D-3 smu-tabs 保留**（§1-④ 留痕）。
- **D-4 回调 ref 首焦必须 useCallback**：spec §4.2 与 T-344C 交接 D6 的「回调 ref + 微任务」形态不完备——每次渲染重挂 ref 会逐字符抢焦（§2-1）。已修 ConfirmDialog + ResourceDialog 两处；**后续给任何 MUI Dialog 加「打开即聚焦 X」照抄时必须带 useCallback**。建议 conductor 逼 ux-designer 回写 spec 该条目。
- **D-5 AppShell.tsx:361 的快捷键护栏仍引用 `.modal-backdrop` 选择器**（`[role="dialog"], .modal-backdrop`）：类已无渲染位，前半选择器覆盖全部 MUI Dialog，行为正确——纯死引用，未动（壳域归批 A 面，零收益不越界）。
- **D-6 无证书漂移**：本票纯前端 + e2e，未触 API 契约。
