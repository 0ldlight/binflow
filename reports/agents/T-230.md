## 1. SSH 可用性固化（免密腿）— ✅

- 复用本机既有 `~/.ssh/id_ed25519`（`SHA256:IkFTc1LqKRRcjnBLqEtXLraNtmxhtTauUf7GxXCM0KU`），pubkey 以幂等方式 append 进 VM `~/.ssh/authorized_keys`（0700/0600 权限，当前 1 行）。
- 验证：`ssh -o BatchMode=yes -o PasswordAuthentication=no lzw@172.16.58.129` → `KEY_AUTH_OK`，后续全部操作走密钥，零密码。
- **坑位记录（后续 agent 必读）**：本机 macOS 的 `expect` 5.45 + ssh 密码形态在密码正确时仍静默挂死（pty 送入 password 后 sshd 无回包，120s 超时无任何输出；非密码错误——错误会秒回 Permission denied）。改走 `SSH_ASKPASS` + `SSH_ASKPASS_REQUIRE=force`（无 pty）一次成功。**密码腿只用于装公钥这一步，现已不需要；后续 QA/review agent 直接 `ssh lzw@172.16.58.129` 即可。** VM sudo 需密码（`sudo -S` 读 stdin 形态可用）。

## 3. docker 就绪（T-226 前置）— ✅

- 安装：`apt-get install docker.io`（Ubuntu 24.04 官方包）→ **Docker 29.1.3**，`systemctl enabled + active`，overlayfs（containerd snapshotter v1）/ cgroup v2 systemd driver。
- 免 sudo：`usermod -aG docker lzw`，实测 `docker info` 以 lzw 直跑成功。
- **Docker Hub 直连不可达**（`registry-1.docker.io` i/o timeout；apt 走 Ubuntu 源正常）。探测 4 个国内 mirror 均 API 存活，已写入 `/etc/docker/daemon.json`：`registry-mirrors: ["https://docker.m.daocloud.io", "https://docker.1ms.run"]`（docker 为本次全新安装，无用户既有配置被覆盖）。此后 `docker pull minio/minio` 直接成功。

## 5. 结论（供 T-226 / 后续票消费）

1. **systemd 部署腿真机复验通过**：contrib/systemd unit（含全部硬化项）在 Ubuntu 24.04 / systemd 255 上安装即起、协议腿（docker push/pull + npm publish/install）全绿、SIGTERM 优雅停机实证——M5 矩阵方式 6 的裸机腿有了真机证据（此前 T-138/T-169 仅脚本干跑 + 文档复跑）。
2. **docker 就绪**：29.1.3 + mirrors + minio 镜像在位，T-226 的 MinIO 容器腿可直接 `docker run` 起 MinIO（建议挂载卷 + 端口规划时避开 8080——binflow systemd 腿默认口）。

4. **网络口径**：VM 出网依赖 Ubuntu 源/国内 mirror；Docker Hub 直连不通。后续票凡需拉新镜像（postgres/nginx/artifactory），走 mirror 或本机 `docker save | ssh docker load`（deploy/offline 同思路）。macOS↔VM 8080 双向可达，跨机客户端腿可用。
