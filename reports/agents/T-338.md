## 1. AC 逐条证据

### AC-A1 停机窗 PUT（site-1）
- **引擎级**：`TestFailOpenWindowPUTLandsDiskAndEnqueues`——mock down 下 3 PUT 全成功；`blobs/<2hex>/<sha>` 布局落盘实证（os.Stat）；queue_depth=3；同内容重复 PUT depth 不增（幂等入队）；条目 JSON `{version:1,sha256,enqueued_at}` 逐字段断言；temp 零残留。
- **服务端级**（真 MinIO docker stop）：2MiB PUT **=201**（T-327 L09 实测 500）；磁盘 `data/blobs/f7/f796…` 落盘；`data/replay-queue/f796….json` 在案。首窗 PUT ~5s（minio-go 重试链），窗内后续走快路。
- 首错 WARN 日志（服务端实测）：`storage: s3 arm failed; opening fail-open window … first_error="…dial tcp 127.0.0.1:29000: connect: connection refused"`——错误链含 S3 侧完整因果。

### AC-A2 停机窗 GET 三类件（site-2）
- **引擎级**：`TestFailOpenWindowGETThreeClasses`——三类件（窗口前 disk-only 存量 / 窗口前双写件 / 窗口内新件）GET+Stat 全 200 等价；`read_fallback_total` 在 S3-miss 回退时增长（窗口前存量件断言 >0）；不存在件诚实 `ErrBlobNotFound`。`TestFailOpenWindowOpensOnRead`——停机后首个 GET 触发开窗（读也是开窗触发器）且回退 200。
- **服务端级**：窗内 GET 新件 **=200** sha 字节级一致；GET 窗口前制品 **=200**（T-327 实测 500）。

### AC-A3 中途死亡降级（site-3 反删盘废止）
- **引擎级**：`TestFailOpenMidSessionDegradation`（Append 臂死亡：双段 Append 跨停机 → PUT 成功 + disk blob **存在**〔旧码此处反删〕+ 入队）+ `TestFailOpenCommitArmFailureKeepsDisk`（Commit 臂死亡同断言）+ `TestFailOpenDiskFailureIsHonest`（disk 地板诚实失败——仅剩一后端无降级余地）。
- **服务端级**：窗内全部 PUT（12/12）即此路径的批量形态。

### AC-B 队列持久化 + 重启幸存
- **引擎级**：`TestFailOpenQueueSurvivesRestart`——S3 仍停机时 Close（worker 窗中取消）→ 同 data dir 重建栈 → 水位 depth=2 → 恢复排空全到 S3。`TestFailOpenQueueLoadSalvage`——stale temp 载入时清扫；损坏 JSON 按文件名打捞（派生状态立场）；异文件不动。
- **服务端级**：窗口内置债 → kill 服务 → MinIO 起服 → 重启 → **启动水位行实见** `INFO storage: migration dual-write replay queue watermark depth=1 drain=scheduled` → 1s 内 `drained=1 rounds=0` → mc stat 对象在 → queue=0。

### AC-C 排空对账
- **引擎级**：`TestFailOpenRecoveryDrainAndReconcile`——恢复即排空（depth→0、窗关）；**对账兜底实证**：队列从未见过的 pre-migration 孤儿 blob 被 diskList×s3Set diff 抓到并补拷；事件序 window{open,带错误链}→window{close}→drained{drained≥2,reconcile_missing=0}；恢复后稳态 PUT 恢复同步双写（H13 真值不动）。
- **live 真栈**：`TestFailOpenLiveMinIOOutageWindow` 全链 PASS——`drained=5 source_gone=0 permanent_failed=0 rounds=1`（4 队列债 + 1 对账抓的存量）；**mc 侧逐对象零缺**：MinIO 对象数==disk blob 数（超集不变量），逐 sha 比对全中。
- **服务端级**：MinIO 重启后 **1 秒**关窗+排空（19:51:30 start → 19:51:31.816 drained）→ mc stat 2MiB 对象落桶 → 恢复后 GET sha 一致。

### AC-D 治理交互
- `TestFailOpenGovernanceInterplay`：窗内 Delete **诚实失败**（非 nil）；窗内 GC 双臂合并错误返回 **诚实失败** 且 disk sweep 仍回收无引用 blob（fail-open 只覆盖数据面的直接断言）；恢复排空遇 source-gone → **条目 drop + `skipped_source_gone` 计数 + 不卡死收敛**（drained 事件 source_gone=1）；无引用件不被补拷到 S3。
- ADR-0031 压力回归：`TestMigrationConcurrentWrites`（20 goroutine×5）+ gc_hold 族原样绿（全包 -race ×2）；降级会话 GC hold 自然只落 disk 臂（T-333 §6 预判成立）。

### AC-E 模式边界
- `TestFailOpenBypassUntouched`：bypass 在停机下 PUT 照常（disk-only 本就如此）、零入队、**不创建 replay-queue 目录**、stats 全零——零新代码路径。
- `TestFailOpenCompletedUntouchedAndGate`：completed 停机下 GET 诚实失败（无回退地板——disk 可能已被运维删）；**拒启 gate**：`CheckCompletedReplayQueue` 空队列 nil / 非空返回 `ErrCompletedWithReplayQueue` 且文案点名两条出路（切回 dual-write 排空 / 人工确认弃队列删目录）。
- H12~H15 服务端复跑（fresh 实例 + 真 MinIO，H 序列形状）：窗内 12 PUT 12/12=201；migration/start=202；**迁移中上传=201**（H13）；status `done=true skipped=12 failed=0`（H12——排空先收敛、扫描幂等跳过）；13/13 GET=200；H14 断点=AC-B 腿；H15=s3only 链 roundtrip + completed 单测。s3 链冒失启动（桶不存在）→ 指名拒启（既有 fail-fast 姿势顺带实证）。

### AC-F 可观测
- 六指标数据面 `ReplayStats()`（引擎自有计数，scrape 读——T-324 cleanup.Stats 先例）：`queue_depth`（gauge 源）/`drained_total`/`failed{outcome=retry|permanent|source_gone}`/`read_fallback_total`/`window_open`（0/1）——各语义在上述测试中逐枚断言（幂等不增深、permanent 不重复记账、source_gone 一次、回退计数含 NotFound 路径、窗开关翻转）。
- 两审计事件 facet：`SetReplayEvents`→`ReplayEvent{window open/close, drained{drained,source_gone,permanent,reconcile_missing,rounds}}`——internal/storage **不 import audit**（分层纪律）；装配层发射为后续 3 行 wiring（见 §3 差异）。
- 日志三线实测在案：首错 WARN（含 S3 错误链）/permanent WARN（16 轮阈值，条目保留）/启动水位 INFO（>0 附 drain=scheduled）。

### AC-G 回归
- **binstore.yaml 三链 roundtrip**（真实二进制 + 真 MinIO，L08 口径）：`[filestore]` PUT 201/GET 200 sha 一致 + `data/blobs/23/231b…` 落盘；`[s3]` roundtrip 绿 + 本地 blobs 目录不存在（bucket-only 姿态）+ mc stat 对象在；`[filestore,s3]+dual-write` PUT 201 + 双侧同 sha（磁盘文件 + mc stat 1.0MiB 对象）+ 启动行 `storage chain resolved providers=filestore,s3 mode=dual-write`。
- **migration status 端点形状逐字节不变**：GET `/api/v1/storage/migration` = `{"running","done","total","migrated","skipped","failed"}` 六键，队列状态未渗入（93.6 冻结）；引擎级 `TestFailOpenStatusViewShapeUnchanged` 跨 fail-open 事件前后 key set 不变。
- 既有测试全绿（全包含 migration/gc_hold/s3_resume/streaming 等全量）。
