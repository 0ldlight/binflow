### 环境注记（复现者提示，非产品面）

- **dind PMTU 黑洞（新登记 L 级注记，T-377 D2 的邻域形态）**：本机 dind↔host 大包下行（host→容器方向 ~3.6MB 级响应体）会停摆——dind 内 wget 直连 A（M2 起 就绪的 local 面，与本票零关）同症，host 侧 curl 同一 URL 7ms 全量返回 → **纯环境网络症**。解法：dind 启动后立刻 `iptables -t mangle -A OUTPUT/-A INPUT -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --set-mss 1300`，且**必须先重启 dind**（既有长连接保留旧 MSS）。症状表现：服务端 goroutine 卡在 response write（SIGQUIT 栈：serveBlobBody→io.Copy→conn write）。
- A2（认证腿上游）base_url 留空（realm 随请求 Host 派生 → host 侧 B2 可解析）；dind 直接面向的实例（A/B/B2）须 `host.docker.internal:<port>`（T-367/T-373 手法）；宿主 daemon 无法达 macOS loopback（Docker Desktop VM 语义）——推 A2 的种子改走 curl+Basic。

## 6. 登记与遗留

- **断言翻转 7 处**（§2）：remote docker 400→200 族；docker virtual 维持拒绝（文案换锚 substring "are not supported"）。docs/user/admin/remote-virtual.md L195「docker remote 建仓 400」一行已过期——归 **T-397**（文档 A 增量票，dep 本票）顺笔。
- **remote family 指标口径的如实说明**：产品无 Prometheus remote 族（RE-11 的 /api/v1/remote/stats 是 P2 占位，Engine.Stats 为内部数据面且无端点）；/v2 remote 缝的观测面 = X-BinFlow-Cache/-Upstream-Error 头 + audit download 行 + remote_cache TTL 行——**docker remote 全部自动生效**（live #5/#11）。engine 内存 hits/misses 计数器不喂 adapter 驱动的 /v2 拉取（T-363 既有姿态，非本票回归）——若 P2 stats 端点立项，两计数源需归并（候选池建议条目）。
- **无 WriteTimeout**（httpapi 仅 ReadHeaderTimeout 10s）：stalled client 会让 handler 无限期阻塞在写（本票 dind PMTU 事故的栈象）——全产品既有姿态、非本票面，登记候选（低优先：加 WriteTimeout 是横切变更，需 architect 裁）。
