## 1. 缺陷机理（修复前）

`sweepDist` 的 by-hash 保留按 `by-hash/<ALGO>` 目录（算法目录 = 一个索引族目录下的桶）混装**同代各压缩拼写**——一次重算把 plain + `.gz` + 可选集（如 xz）共 N 个不同摘要写进同一个算法目录。原实现按桶内**条目数**裁 newest `historyCycles` 条：

- `historyCycles < 每代拼写数`（如 cycles=1 + 3 拼写）时，当代条目按 `UpdatedAt` 排序挤不进窗口——**当代的 by-hash 拷贝被裁掉**，而 Release（Acquire-By-Hash: yes）仍广告着这些摘要，apt 按 by-hash 地址取索引即 404。违反 debian.md §5「当前版必须可取」（官方地板，高置信）。
- 节点时间戳是 RFC3339 **秒级**字符串（repo.Service `now()`），同代条目全并列，排序保序任意——被裁的是哪个拼写纯凭字典序运气。此前默认 cycles=3 恰好 ≥ 强制拼写数 2（plain+gz），默认值掩护了缺陷；T-327R 打开 REST 键后 cycles=1/2 即触发。

## 2. 实现（internal/adapter/deb/reindex.go）

语义对齐 debian.md §5 + rpm 侧 `pruneGenerationsLocked` 既有姿态（「当代保护 + 窗口界总量」）：

1. **当代显式保护（按摘要地址，不看时间戳）**：新 `byHashAddresses(f, policy)` 把「索引文件 × 策略 → by-hash 地址」抽成唯一拼写；`writeByHashCopies` 改用它写，`sweepDist` 用它构造**当代地址集** `currentGen`——当代条目永不进裁剪计划，cycles 再低也不裁。
2. **按代分组裁剪（新纯函数 `byHashPrunePlan`）**：桶内先剔除当代；余下（历史）条目按 `UpdatedAt` **分组为代**（一次运行的全部拼写共享同一秒级时间戳；秒内两次运行合并为一组——多留历史，安全方向；绝不会少留），保留 newest `historyCycles-1` 组，更旧的整组裁。**窗口界总量**：cycles 计当代在内的总代数（cycles=1 = 只留当代；rpm 同款「当代占一个槽」语义）。
3. **策略翻转的边带行为**：`byHash=NONE` 时 `currentGen` 为空（写侧本就不写）——从 ALL 翻到 NONE 后的遗留 by-hash 树按历史代自然老化出清（此前是「桶内永远留 newest 3 条」的僵尸态）。规格未钉此边角，新行为更贴合 §5「NONE = 无 by-hash 目录」；已登记于 §5 说明。
4. 排序加 path 字典序 tiebreak（秒级并列下的确定性，rpm 同款注释口径）。

`historyCycles=0` 边界：规格未定义（§5 开放问题清单列有「默认值与裁剪行为」），维持既有 `normalized()` 折叠 `<=0 → 默认 3`——「0=全不保」会同时违反官方「历史 ≥2 代」地板；本票用测试钉住该裁定（见 §3），未擅自引入新语义。

## 3. 测试（internal/adapter/deb/t327g_retention_test.go，新）

| 用例 | 覆盖 |

| `TestByHashPrunePlan`（纯函数，8 例 table-driven） | cycles 低于拼写地板时当代全保；窗口按代计数非按条目；cycles=1 整组裁尽全部历史；同秒两代合并为一组（安全方向，合并组第 4 条不被条目计数误裁）；当代占槽；空当代集（策略关闭）按代老化；非正 cycles（直调）全裁；时间戳最旧但摘要未变的当代条目仍受保护 |
| `TestByHashCyclesOneKeepsCurrentSpellings`（引擎腿） | **缺陷精确复现形**：ALL 策略 + xz 可选拼写（每代 3 拼写）+ cycles=1，两代 debPUT 后——当代全部拼写（plain/.gz/.xz）的 SHA256 地址 200 且字节一致 + 当代 MD5Sum 族 200；v1 全部拼写 SHA256/MD5Sum 地址 404（waitGone 轮询 sweep 落地） |
