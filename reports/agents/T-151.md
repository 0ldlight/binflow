# T-151: S3Engine Implementation (minio-go S3 Backend + Engine Implementation)

## Status: done

## Summary

Implemented `S3Engine` in `internal/storage/s3.go` -- a full `Engine` interface implementation backed by `minio-go/v7` for S3-compatible object storage. The implementation maps Engine sessions to S3 multipart uploads and stores blobs under the `<prefix>/blobs/<sha256[0:2]>/<sha256>` key layout.

## Implementation Details

### s3.go

- **S3Engine**: Implements `Engine` interface. Holds `*minio.Core`, bucket name, bucket prefix, session registry, and optional clock override.
- **Factory functions**: `OpenS3Engine(core, bucket, opts)` and `OpenS3EngineWithClient(client, bucket, opts)`.
- **Session mapping**: `BeginSession` -> `NewMultipartUpload`, `Append` -> `PutObjectPart`, `Commit` -> `CompleteMultipartUpload` + CopyObject + RemoveObject, `Abort` -> `AbortMultipartUpload`.
- **Commit flow**: Verify expected digests -> check blob existence (dedup) -> CompleteMultipartUpload -> CopyObject to target key with `blob-created-at` metadata -> delete source.
- **Concurrent dedup**: `CompleteMultipartUpload` failure re-checks blob existence; if another goroutine completed the same upload, the session returns successfully (winners converge). When blob already exists on `StatObject` check, the multipart upload is aborted to clean up.
- **Open**: Returns `io.ReadCloser` from S3 GetObject (per ADR-0019 contract).
- **Stat**: Streams blob once, verifies sha256 matches key path, returns all three digests.
- **GC**: Mark-sweep over S3 ListObjects; respects grace period and `apply` flag.
- **s3Backend**: Internal `Backend` implementation for direct blob CRUD (Put/Get/Delete/Exists/List).
- **extractSha256FromKey**: Parses sha256 from S3 key paths; validates digest and shard prefix.

### s3_test.go

- **Mock S3 HTTP server** using `httptest.NewServer` that handles all S3 operations: ListObjectsV2, GetObject, PutObject, StatObject, DeleteObject, CreateMultipartUpload, PutObjectPart, CompleteMultipartUpload, AbortMultipartUpload, CopyObject, bucket location.
- Uses `credentials.NewStaticV2` to avoid AWS chunked transfer encoding (V4 would add chunk-signature markers to PUT body).
- Handles S3 query parameters with empty values (`?uploads=`, `?location=`) via `url.Values.Has()` instead of `url.Values.Get()`.

## Issues Fixed (Post-Implementation)

1. **TestExtractSha256FromKey shard mismatch**: Test case `blobs/dd/` + 64 d's expected empty string (shard mismatch) but sha256 starts with "dd" matching the shard. Fixed by using `blobs/ee/` (different shard).

2. **Concurrent Commit race**: `CompleteMultipartUpload` fails when another goroutine already completed the same multipart upload. Fixed by re-checking blob existence after `CompleteMultipartUpload` failure -- if the blob exists, the session returns successfully (another goroutine won the race). Also added `AbortMultipartUpload` cleanup when blob already exists on the initial `StatObject` check.
