## Specification adherence

- **Migration 008**: SQL files `008_oidc_ldap.sql` (both sqlite and postgres) implement the DDL defined in PRD M6. Tests verify idempotent re-application and column existence with correct defaults (`provider='local'`, `provider_id=''`).
- **LDAP login fallback**: `POST /api/v1/session` (via `AuthenticateCredentials`) tries local password (argon2id) first, then LDAP bind if `ldapProvider != nil`, then returns `ErrInvalidCredentials`. Spec alignment: `docs/reverse/auth-model.md` section 3.6 (high confidence).
- **OIDC/LDAP user detection**: `adaptUser` checks `Provider` field; users with `ProviderOIDC` or `ProviderLDAP` and empty `PasswordHash` are rejected at the Basic arm with a clear error message (cannot use password auth). This aligns with ADR-0020 decisions 2-4.
- **Auto-create**: `NewFromStore` now wires `userCreatorAdapter` so both OIDC and LDAP auto-create paths work. Callers can still override via `WithOIDC(prov, creator)`.

## Legacy issues

- LDAP resolver (`GetByProvider`) iterates all users O(n). A future optimization (T-157) should add a provider+provider_id index.
- `golangci-lint` has numerous pre-existing issues in `internal/auth/` (revive, unused-parameter, gofmt in files not touched by this ticket). These existed before T-156 and are not introduced by these changes.
