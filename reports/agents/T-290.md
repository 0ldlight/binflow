## 2. 四项自有裁定（供 review/终裁复核）

1. **P1 三字段以 PRD FR-90 终版为准**：派单文本把 `enableTokenAuthentication` 列为 P1 三字段之一，但 PRD 90.2/Q7/LC-12 终裁其为 M11（严格 schema、不做 inert 字段）且派单亦令「第三字段按 PRD FR-90 终版（读 PRD 确认）」——按 PRD 落：`socketTimeoutMs` / `metadataRetrievalTimeoutSecs` / `missRetrievalCachePeriodSecs`。`contentSynchronisation` 归 M11 确认登记（本票未做任何 inert 落库）。
2. **`missRetrievalCachePeriodSecs` 双拼写**：PRD/LC-12 拼写与 Artifactory 实拼（`missedRetrievalCachePeriodSecs`，repo-semantics §7.1 高置信）差一个 "ed"。clean-room 规则（公开规范优先）：canonical 保留 Artifactory 拼写，PRD 拼写作输入别名（冲突 400，同 virtualConfigInput 别名分歧先例）。
3. **「未知字段 400 维持」的 as-built 落法**：M3 实况是未知字段**丢弃容忍**（scenario D 迁移脚本契约，`TestM02bRemoteConfigValidation` 钉死），并无「未知字段 400」可「维持」。逐字实现全局 400 会破 scenario D（AC5 回归红线）。落法：**仅对两个 M11 字段按名 400**（错误体点名字段 + M11 指引）——AC4 字面（`contentSynchronisation` → 400）达成，scenario D 容忍不变，且正是 90.1「诚实不做 inert 面」同款精神（对照 filestore 501 先例）。**PRD↔as-built 分歧登记给 T-293**。
4. **014 列消费优先级**：行列（>0）> canonical JSON 字段 >  legacy `socketTimeoutSecs` > 产品默认——单一解析点 `effectiveSocketTimeoutMs` / `effectiveMetadataWait`（fetcher.go），pre-014 行为零回填零变化。
