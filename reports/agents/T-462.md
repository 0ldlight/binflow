## 6. 票内裁决（置信度标注）

| # | 裁决 | 依据 |
|---|---|---|
| 1 | 维护面形态 = 三槽行表（行级保存/清除），非 7.161 整页表单+底部 Reset/Save | PUT 逐槽臂先验后写（T-450）——行级即最小臂面；§3.9 区块序对位（GC→危险区、cleanup→立即清理、Quota/Compress/Prune→缺位注记）（高） |
| 2 | gc 槽「手动执行」= 滚向危险区入口，不另设直发 | ADR-0044 决策 7①「Run Now 各自既有面并存」——GC 的手动面就是 dry-run-first 危险区（高） |
| 3 | cleanup Run Now = POST {apply:true} + 常规 danger confirm（无输入档） | 与调度 fire 同载体同参数（T-450 报告 §1.2）；引擎自带 grace/策略门——YES 输入档留给无门裸删的 GC apply（中高，票内定案） |
| 4 | cron 合法性零 FE 预检（服务端唯一权威，400 点名文案行内原样） | BinFlow 子集（W/# 拒收等）FE 无解析器——不复制一套会漂的校验（高；§10.5 批块留痕） |
| 5 | nextBackupTime 编辑态不回填 next-run | wire 语义 = 可写「首跑时刻」，未给才推算——回填会造成「保存=冻结当前 next」的误改（中高，票内定案） |
| 6 | 备份 cronExp 空 = 合法保存（payload 行保留不调度） | backend 单态法（system_backups.go）合法态；hint 明示（高——wire 实证） |
| 7 | 治理复制页调度列 join 配置面而非改 status 面 | status 面（T-159/T-180 冻结）不携 cron；配置面回显现成——零后端改动（高） |
| 8 | cron_exp 恒随体提交（空串 = 纯事件轨），不做空省略 | flip-off 过 round trip 纪律（enabled 同款）；服务端 nil/"" 等价——恒提交更诚实（中高） |
| 9 | audit picker 补九词（54→63） | internal/audit Actions() 镜像纪律（T-353 同款）——T-450 落词后 FE 镜像欠账随本票清（高） |
