### 启动烟测（渲染产物 → 真实 binflow-server）
构建：`go build -o /tmp/t295/binflow-server ./cmd/binflow-server`。配置 = helm template 渲染的 configmap 原文，仅 `data_dir` 改指临时目录（本机无 /var/lib 写权），listen 走 env 覆盖。

**变体 A（默认渲染，键全量形态）**：
- 起服 `binflow listening` + `/healthz` 200 + `/readyz` 200 — 渲染文件整体通过严格 schema fail-fast
- license 三端点 community 地板姿态：
  - `GET /binflow/api/system/license` → 200 `{"licensed":false,"tier":"community","perpetual":true,...}`（无 license = 地板）
  - `POST .../license`（垃圾文档）→ 400 `LICENSE_INVALID — verification failed`（地板不动，D7）
  - `DELETE .../license` → 200 幂等 floor-keeper
- `GET /binflow/api/v1/addons`：5 core + properties enabled（community 解锁面）；go/nuget/cargo=pro 锁、ha/xray=enterprise 锁，reason 均为 tier 锁（与 disabled 的 reason 可区分）

**变体 B（全形态渲染，oidc+ldap 开）**：起服到 `wiring auth.oidc` 才失败（假 issuer 的 OIDC discovery 网络错误）。**config.Load 已完整接受全形态文件**（含 readonly_group、step-up、addons——失败点在配置装载之后的 assembly 阶段），严格 schema 面验证达成；网络依赖段不阻断结论。

**变体 C（M10 键全开 + 无网络依赖段）**：`addons.disabled: "nuget, not-a-slot , , docker"`：
- 起服成功，`/healthz` 200，无 panic/fatal —— **ADR-0032 §K24 容错**：空格 trimmed、空 CSV 项丢弃、未知槽位 `not-a-slot` 静默容忍（惰性集合项，视图中不可见）
- 核心包类型 `docker` 命中 → 启动日志 WARN 一条：`license: addons.disabled includes a core package type (effective immediately)","addon":"docker"`（降级旋钮：WARN 且照样执行）
- enforcement 视图与执行同源：`docker`、`nuget` → `enabled=false, reason="disabled by configuration"`；`nuget` 的 reason 从 tier 锁翻转为 disabled（求值顺序：config 断路器先于 tier）；`not-a-slot` 不出现
- license GET 地板不变（licensed=false/community/perpetual=true）
- 制品 roundtrip：`PUT /binflow/api/repositories/t295-repo`（generic local）200 → `PUT /binflow/t295-repo/t295-smoke.txt` 201 → `GET` 200 → sha256 一致（`64a3648c…b5d4`）→ 干净停机（`binflow stopped`）
