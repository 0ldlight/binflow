## 1. 做了什么

### 1.1 remote 仓型（remote.go，新）

- **读路径全走既有 pull-through 引擎**：`svc.Get` 在 remote 仓自动分发 FR-20 链（负缓存、TTL 双类、守卫回源、stale-while-error）——conan 侧零引擎代码。
- **UpstreamPath 翻译面**（provider.go，goproxy T-285 姿态）：存储语法 `<user>/<name>/<ver>/<ch>/…` 与 v2 wire 语法 `v2/conans/<name>/<ver>/<user>/<ch>/…` 段序不同、端点词汇不同，provider 的可选 facet 在出站一跳完成翻译；缓存键/落点/singleflight 全保持存储拼写。
- **索引文档 = revisions 端点同构体**：`index.json`（recipe 与 package 两平面）回源映射到对应 `revisions` 端点，拉回的即索引文档（S2 同构的天然利用），latest/revisions 按 T-308 本地臂同一形状渲染。
- **两个 marker 文档**（无存储形态的 wire 文档）：files 清单（`…/<rRev>/.files.json` ↔ `…/revisions/<rRev>/files`）与 packageId 元数据（`…/<rRev>/.search.json` ↔ `…/revisions/<rRev>/search`）缓存上游响应体后**逐字服务**——引擎 TTL/负缓存/stale 原样生效；隐式 latest 变体先经代理索引解析 rRev 再取 marker。
- **文件体**：`export/<path>` ↔ `…/files/<path>`、`package/<pid>/<pRev>/<path>` ↔ `…/packages/<pid>/revisions/<pRev>/files/<path>`，内容类 TTL（不可变）。
- **写拒绝**：PUT 落到共享臂后由服务答 RE-05 只读 405（Allow: GET）；DELETE 族在 handler 内同文案拒绝（本地臂的 subtree 探针用 svc.List，remote 类不服务 List，须先拒）；checksum-deploy 同经 PutFromBlob 的服务侧拒绝。
- **search 不代理**（T-287 约束：引擎上游跳是 path 拼接，带 query 的端点不可达）→ 404 诚实文案 `msgRemoteSearch`，差异登记。
- **握手三端点类无关**：{v1,v2}/ping、{v1,v2}/users/{authenticate,check_credentials} 在 remote/virtual 上服务（能力头带 only_v2）——见差异 D1。

### 1.2 virtual 仓型（virtual.go，新）

- **文件体零新代码**：`svc.Get(virtual, path)` 已是双桶 first-found 成员解析（local 成员节点 + remote 成员经 FR-20 链，`X-BinFlow-Resolved-From` 随 reader）。
- **revisions/latest 合并**（S11）：逐成员 `ReadVirtualMember` 读各自 `index.json`（remote 成员同样经引擎+翻译），按修订字符串去重（首见成员行保留）、`sortRevisions` 排序（time 降序、同 time 修订降序）；latest = 归并后首项。
- **files 清单并集**：local 成员出节点事实（`ListVirtualMember`），remote 成员出 marker 文档；空并集 → 404 `Path not found`。
- **packageId 行并集**：local 成员从事实推导（latest pRev 的 conaninfo.txt 解析，全走成员缝），remote 成员取 marker 文档；pid 键首见成员胜。
- **search 并集（仅 local 成员）**：remote 成员目录不可枚举（成员缝拒绝，T-287/nuget 姿态）——差异 D8。
- **成员失败策略**（npm/pypi 聚合规则）：unfound 贡献空；分类失败（SSRF 400 等）跳过并记住首个；全部落空且有记住失败 → 浮出该失败（绝不伪装成纯 404）。
- **写平面**：PUT 走共享臂由服务路由（defaultDeploymentRepo → local 成员；未配置 → C5 405）；**登记尾的索引读改成员定向**（revision.go `readRecipeIndexForWrite`/`readPkgIndexForWrite`：`virtualWriteTarget` 探测路由目标，经 `ReadVirtualMember` 读目标成员**自己的**索引——npm loadPackumentForWrite 防拷贝规则，否则追加在归并视图上会把其他成员的修订链复制进目标成员，测试断言防污染）。DELETE 在 handler 内答不传播 405（措辞随有无写路由二态，repo 包既有文案的复述）。

### 1.3 既有文件点状修改

- `handler.go`：`RepoTypes` → {local, remote, virtual}；类门重构（握手类无关 / v1 数据面 S6 400 逐字 / v2 分流 serveRemote·serveVirtual）；`isV1Family` → `isV1DataFamily`（握手三 kind 移出拒绝集）。
- `layout.go`：marker 字面量与三个路径构造器。
- `provider.go`：`Classify` 两个 marker 计入 metadata 类；`UpstreamPath` facet（未知形状恒等直通）。
- `revision.go`：写平面成员定向索引读 + `virtualWriteTarget`/`memberRecipeIndex`/`memberPkgIndex`。
- `doc.go`：三仓型行为文档更新（含 marker 布局行）。
