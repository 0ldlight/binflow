## 3. 实测暴露的部署面缺陷与修复（全部 in-area 修复 + 复测）

| # | 缺陷 | 实测暴露 | 修复 |
|---|---|---|---|
| C1 | **Chart Deployment 无 strategy**（K8s 缺省 RollingUpdate）——SQLite/serve.lock 单写者，升级瞬间新旧 pod 并存共享 RWO PVC，新 pod CrashLoop `serve.lock is held by another process`，`--wait` 挂死在 Pending termination，旧 pod 持续供旧配置。原生清单 deploy/k8s 本有 `type: Recreate`，Chart 漏抄 | L5 helm upgrade：configmap 已更新 999/5 而回显仍 5000/14，双 pod 并存实见 | templates/deployment.yaml 补 `strategy: Recreate` + 注释；复测 upgrade → 单新 pod 6s Ready → 回显 999/5 ✓ |
| C2 | **Chart 缺 `checksum/config` 注解**——ConfigMap 内容变化不改 pod template，仅改配置的 `helm upgrade` 不触发滚动，静默维持旧值（M13 旋钮族恰是 restart-effective 文档语义，upgrade 即重启的预期被破坏） | C1 修复前先加注解验证 hash 变化但回显仍旧值 → 顺藤定位 C1 | pod template 补 `checksum/config: sha256(configmap.yaml 渲染)`；复测 pod-template-hash 变化 + 回显翻转 ✓ |
| C3 | **install-offline.sh 四处**：① 探针硬编码 `:8080` 不随 `BINFLOW_BIND_PORT`（自定义端口必超时误报失败）；② helm 模式找 `charts/binflow-${VER}.tgz` 而 `helm package` 命名=Chart 版本（`binflow-1.3.0.tgz`）——helm 模式对任何正经打包必 404；③ helm 模式装 Chart 缺省镜像 `ghcr.io/lzwzzy/binflow`——air-gap 定义上不可达；④ cleanup() 空数组 `"${CREATED_IMAGES[@]}"` 在 bash 3.2（macOS 系统默认）+ `set -u` 下 unbound 崩 | L5 首跑三连红（①现场复现；②③dry-run/真跑复现；④失败路径回滚时复现） | ①探针随 .env 端口；②`binflow-*.tgz` 自动发现（零或多拒绝）；③`--set image.repository=binflow --set image.tag=${VER}-distroless` 钉捆绑镜像（install/upgrade/dry-run 三处）；④长度守卫。复测：自定义端口 GREEN、helm 模式真装真升全绿、dry-run 两模式 exit 0 |
