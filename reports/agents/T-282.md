## 做了什么

1. **`internal/addons` 包**（新增，4 文件）
   - `addons.go`：`Kind` 二分（`package-type` | `feature`）+ `Addon{ID, Kind, MinTier, PackageType, DisplayName, Description}` 描述符 + `Registry`（`New(items ...Addon)` / `All` / `ByID` / `ForPackageType` / `PackageTypeAddons` / `FeatureAddons` / `Len`；构造后只读，返回副本）。装配期 panic 家族：空 ID、空 DisplayName、未知 Kind、package-type 缺 PackageType、**PackageType ≠ ID**（ADR「包型 addon 时 ID ≡ package_type」）、feature 带 PackageType、MinTier 越档位闭集、重复 ID——adapter.Register 同款「启动期暴露」姿态。
   - `view.go`：消费侧接口 `Gate{AddonEnabled}` 与 `Evaluator{Gate + State}`（`*license.Manager` 直接满足）；`Statuses`/`StatusOf` 输出 `Status{Addon, Enable, Reason}`；`PackageTypeAvailable(ctx, gate, packageType)` = 织入点 2 的单一拼写（registry 解析 id/tier + Manager 判定，nil gate = community 地板诚实值）——T-283 repo 校验链直接消费。**reason 推导严格镜像 Manager 的求值序**（disabled → tier → 白名单）：disabled 探针 = `AddonEnabled(ctx, id, TierCommunity)`（Manager 先查 disabled 集且与 tier 无关，故地板探针 false ⇔ 且仅 ⇔ config 熔断）——零改 `internal/license` 实现「disabled by configuration」归因。reason 串按 §15.2.5 例：`license tier community < pro` / `disabled by configuration` / `not named in the license addon allowlist`。
   - `slots.go`：11 槽位构造器。**档位归属 = 代码常量非数据**（PRD 86.2）：五核心（generic/docker/maven/npm/pypi）+ properties = community 地板（properties 有意不兼容 Artifactory pro 档——M10 交付物非 upsell）；go/nuget/cargo = pro 占位（描述注明 adapter 落地里程碑）；ha/xray-integration = enterprise 占位，描述携带「slot reserved — the feature body lands M11+」注记（PRD 86.2/AC3 的回显要求）。
   - 依赖方向按 ADR：`addons → license`（Tier 类型 + 消费侧接口）；license 不 import addons。
2. **cmd 装配清单**（`cmd/binflow-server/main.go`）：`addonManifest()` = literal slice（§15.2.1 选型 B：no-init、显式装配、可 grep 可 diff、编译期完备）——新槽位 = slots.go 一个构造器 + 此处一行，门控/回显/建仓合法集零分支改动（FR-86-AC2）。`newAssembledServer` 注入 `deps.Addons`。
3. **GET /api/v1/addons**（`internal/httpapi/addons.go` + router.go + server.go）
