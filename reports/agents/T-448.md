## 1. 架构决策（票内核定留痕）

1. **RemoteFetcher 扩列 BrowseRemote（非新 capability 接口）**——T-442 §6-1 留给我的二选一。理由：service 恰好持有一个引擎句柄（`repo.New` 内组装），browse 与 pull 是同一引擎的两面；第二个字段会造出 remoteEng≠nil 而 browseEng=nil 的生产不可达态。接口无外部 fake（全树 grep：仅 service 字段一处引用），扩列零波及。
2. **引擎不读开关维持**（T-442 §6-2 的「repoPolicy 镜像」预判**不采纳**）：browse.go 注释明言引擎永不读 `listRemoteFolderItems`，off 姿态 = 无人调用（构造性 diff=0）；repo 侧 `listRemoteFolderItems()` 容错探针（memberPriorityResolution 同款：探针失败 = 手改行 → 默认 false）。若在 repoPolicy 镜像该字段，引擎就会长出「读开关的第二个消费者」——与 T-442 的设计注释直接冲突。
3. **配置面类型门 = chartsBaseUrl 姿势**：`true` 于 batch-1 之外（generic/docker/npm/…）**按名拒绝**（no-inert-fields 规则——接受了管理员会以为 generic 树也并远端行）；absent / 显式 false 全型放行（false 即产品默认）。类型集合问 `remote.BrowseSupported`（单一源，repo 不自拼写 helm/debian/rpm 镜像）。官方开档 5 型中的 generic/maven 属 BinFlow「明确不做 HTML 抓取族」（remote-browsing.md §6）——迁移脚本带 `listRemoteFolderItems:true` 的 generic remote 会拿到点名 400，差异如实登记（见 §5-1）。
4. **降级注记的 wire 通道 = 可选 SPI 段 `RemoteBrowsePlane`**（RemoteV2Plane 先例，消费方 type-assert）：`ListWithRemote` 返回 `RemoteBrowseListing{Nodes, RemoteDegraded}`；**`Service.List` = 同一条 listRows 通道丢弃 note**——不引入第二解析通道（FR-136.2 同族纪律）。httpapi 渲染腿（FolderInfo/?list 加 note 字段）**不在本票 area**（M16-SPLIT T-448 area = internal/repo）——缝已备好，一行接线归 conductor 派发（见 §5-2）；T-461 Playwright 的降级呈现腿依赖该接线。
5. **远端行的行形**：folder 行 = `path + "/"` + `metadata.FolderMarkerSHA`（与存储 folder marker 同形，childInfos/isFolderPath 零改渲染）；file 行 = 空 sha256/size/mtime——**空 sha256 即 display-only 的构造性标记**（一切落盘 file node 必带 blob digest）。零落库（§4-3），缓存行优先（去重键 = 去尾斜杠路径）。
6. **文件夹面（树展开）的父母枚举证法**：`Get(dir/)` 未命中缓存时以**父目录枚举中的 IsFolder 条目**为存在性证明（空目录也可解），非「子非空」证法；degraded/denied 不认领（落穿引擎，让引擎自己的错误态说话）。ADR-0013 姿势：浏览读零写（测试钉死 node 行数前后相等）。virtual 文件夹面（getVirtualFolder 尾部）同款兜底，行 RepoKey=virtual key（既有 synthesized marker 同形）。
7. **listVirtual 成员单位折叠**：每成员「缓存行先、本成员派生行后」在成员自己的 §8.1 位次入并集；派生行被**任一成员**的缓存行压制（§4-3 缓存优先跨成员读法），raw path 首成员胜（§8.1 序，与 T-412 完全一致）。virtualMember 增挂 pkg/cfg（virtualMemberOrder 已加载的行——省二次 Get，解析走客自身不读）。
8. **§5 权限面裁法**：远端派生行过成员 allow()（越权仓零泄漏 AC 探针位）；成员**缓存行**维持 T-412（virtual 自身门覆盖）——与内容面「已知路径解析不重门」并存的行为差异是规格自裁（remote-browsing.md §5 明文：枚举整棵上游树 ≠ 解析已知路径），browse.go 头注留痕。
9. **§5 patterns 过滤条**：repo-semantics §7.1 的 include/exclude patterns 在 BinFlow canonical remote config **不存在该旋钮**（T-95 裁定 remote/virtual 读面暂不门控，spec-pending）——过滤条 Vacuous，登记：远端读面 governance 落地时派生行过滤随同一门走（§5-3）。

## 3. 设计要点（review 快读）

- off = 构造性 diff 0：未开档仓 `remoteBrowseRows` 首判即返 nil（零引擎调用、零上游接触、note 空）——既有全部 T-406/T-412 断言即 off 回归面。
- 一次枚举 = 一窗一 fetch：引擎快照（metadata TTL，默认 600s）在进程内；listRows 的「条目 + folder 自行」两次 BrowseRemote 读同一快照，零额外上游接触（测试钉 hits）。
- 降级永不塌树：BrowseResult.Degraded / 引擎外错误 / ErrBrowseDenied 三态——前两者出 note（后者是门答，零行零 note），行一律照常。
- 计数单源：本票**零新计数位**——点击派生行 = 内容面 GET，T-438 的 arm 3（remote-serving，双列 + audit 同址）天然覆盖；测试以 stats 1/1 + audit 行钉死联动。
