## C2 `generic/checksum-get-virtual-ondemand` — 建议：对齐实现（ALIGN），限定 generic 域 virtual 面

### ① 终裁建议与理由

**建议 = 对齐实现**：generic 链 virtual 面 GET `{src}.{algo}`——
- `.sha256` 未设 client 值且源可解析 → **200 主摘要回显**（blob sha256，按需"计算"实为查表：ADR-0006 sha256 寻址，源 blob 主摘要即答案，L040 N3 成本下探结论）；
- `.sha1/.md5` 未设 → **404 `Checksum not found for <src>`**（裸路径、无 repo 前缀——写手已存在：internal/adapter/generic/handler.go:465，T-583 落地件）；
- 源不可解析（成员全 miss）→ **404 `Could not find resource; Path: '<virt>:<src>'`**（指源；该前缀写手 internal/ 零命中，**需新建**——本票唯一新文案件）。

理由：
1. **用户可见影响（命中对齐锚点）**：generic 虚拟仓是脚本/镜像自动化取 `.sha256` 校验和的常规消费面（curl 管道、校验脚本直连 `<virt>/<path>.sha256`）；A 服务计算值、B 恒 404 Failed-to-find（指终缀路径）——真实客户端拿到 404 vs 校验和，行为分歧直接。
2. **实现成本低、缝已预留**：internal/adapter/generic/handler.go:479 `serveVirtualClientChecksum`（T-583/BIN-65 落地）现只服务 stored-value 半面，miss 双臂落穿普通链——其注释原文已明示「the on-demand face is the C2 family's own ruling」。扩展点单一：源 miss 分支渲染 `Could not find resource; Path:`、值空分支按 algo 分流（sha256→`digestsOf(node).sha256` 回显 / sha1、md5→复用 465 行写手）。无存储改动、无新计算链。
3. **风险=作用域互斥，票面必须钉死**：
   - **maven virtual 面是反向模型**：A 对 maven virtual `…jar.sha1` GET = 404 `Checksum not found`（不计算），B 现=200 计算值（L040 Arm1a GET 行）——该面属 `maven/checksum-put-unrouted-virtual-plane`（N1，BUG，R12 修复票已排队）范围，**不得被本票的"virtual 按需计算"共享层实现波及**。实现必须留在 generic 链 handler 内，不下沉 repo 层。
   - **本地面不生成**：A 本地 generic GET 未设恒 404 不计算（L037 Arm5 附注），本票零触碰（9a/9b 回归腿守住）。
   - N6 注记（B local GET 拦截臂遮蔽 virtual 落地实体 `.sha1` 文件）为 C1/C5 修复设计考量，不入本票。
4. **matrix 覆盖**：GET sidecar 面现为差分臂域（L037 Arm5/L039 Arm1/L040 N3），matrix 无专行；PUT 族对照行 D01-R09（PUT /{repoKey}/{path}，P0，layer A）。修复票验收=差分双轮；是否随票挂 matrix 腿归 compatibility-engineer。
5. **clean-room 纪律**：A 模型经 L039 Arm1 + L040 N3 双批双轮钉死，且 N3 已把 L039 登记「任意未设算法」修订收窄为「仅 sha256」——本建议严格采修订后模型；sha512、终缀大小写于 virtual GET 面未探，**不入本票**（C3 修复落地时大小写族自会带腿）。

### ② R13 工程票输入草案

- **票面要点**：generic virtual sidecar GET 三态对齐——sha256 未设=200 主摘要回显（查表）；sha1/md5 未设=404 `Checksum not found for <src>`；源 miss=404 `Could not find resource; Path: '<virt>:<src>'`（新写手）。实现限定 internal/adapter/generic（禁下沉 repo 共享层——maven virtual 反向模型保护）。stored-value 半面（T-583）与本地面零回归。
- **area**：dev-registry-adapter（internal/adapter/generic）。
- **验收腿集草案**（差分双轮 + 真实客户端）：

  2. virtual `.sha1`/`.md5` 源在场未设 → 404 `Checksum not found for <src>` ×2；

  5. 负向控制：maven virtual sidecar GET 面零改动（N1 族领地，本票禁入）；
  6. 真实客户端锚：curl 脚本经 virtual 仓取 `.sha256` 并 `sha256sum -c` 校验通过（generic 域验证载体）。

## C5 `maven/metadata-checksum-dedicated-route` — 建议：三分面裁定（PUT 对齐 + GET 对齐 + 可见性 facet 拆立后置）

### 面一 C5-PUT（专用路由）：建议 = 对齐实现，方案 = **文件名键控专用路由**（明确否决「拦截豁免」）

**A 模型（已钉死，L039 Arm5+addendum + L040 N4 双轮×2）**：路径末段恰为 `maven-metadata.xml.{sha1,md5,sha256}` 的 PUT → **200 空体、无 CT、无 Location**；无源存在性检查（源缺=no-op 零副作用）、无值校验（值错亦 200）、client 值零持久化（FileInfo oc 不记）；层级无关（根/group/version 同形）；**跨 packageType**（generic 仓同样命中）；非 `.xml` 的 `maven-metadata.*` 不入。

**方案裁定：文件名键控专用路由，否决拦截豁免**。理由：
1. 专用路由的三性质（层级无关/源无关/零持久化）是**路由级**性质——拦截臂语义=存在性检查+值校验+注册（L037 全模型），「豁免」需逐项跳过且拦截臂根本不在非 local 面运行、也看不到 metadata 存储（L039 Arm5 B 现状根因）；显式前置路由直接表达 A 模型，且零存储写=**无数据风险**（不建文件/节点/目录，addendum 四腿实证零副作用）。
2. **次序模型（票面钉死，全部有实证）**：remote 拒绝先于终缀解释（L039 Arm7「部署拒绝压过一切终缀解释」）→ 部署路由门（未路由 virtual 405，sidecar 不豁免，L040 N1）→ **文件名键控 metadata 路由（本面，仅 local 目标与已路由 virtual 达此层）** → sidecar 拦截臂 → 普通部署/metadata 通道。
3. **用户可见影响（真实 mvn 客户端面）**：mvn deploy 每次部署 metadata 伴随 PUT `maven-metadata.xml.{sha1,md5}`；B maven 域全 404（源在场也 404 误报源缺）=mvn 传输日志噪音/失败面；generic 域三端三形（B1 普通部署/B2 拦截注册）与 A 的 200 空体三方分歧。
4. **成本**：双链（maven put.go 拦截臂前、generic handler.go 拦截臂前）各一条前置路由规则，返回 200 空体——纯路由、零存储调用。**未探面不猜**：已路由 virtual 面 metadata-checksum PUT、generic 仓根级、`.sha512`、终缀大小写变体均未探 → 票内探腿先行定形（探得 A 形后再实现对应臂，探不得就不实现该臂）。

### 面二 C5-GET（按需计算）：建议 = 对齐实现

**A 模型**：GET `maven-metadata.xml.{sha1,md5,sha256}` 恒按需计算 200（任意算法、任意层级——含从未 PUT 的 `.sha256`）；跨 packageType 于 generic 仓同样成立（L040 c5 行：generic 仓 GET `.sha1`=200 计算值）。因 PUT 零持久化，GET 恒服务计算值（client 宣称值永不落盘，无 overlay 交互——干净）。

理由与成本：
1. **机制存量可复用**：maven 链已有「对派生 metadata 文档计算 sidecar 摘要」全套机械——`strippedSnapshotMetadata`（metadata 字节读取）+ `writeDerivedSidecar`（计算+条件请求渲染，maven/handler.go 现存）；generic 链 `digestsOf(node)` 文件节点摘要现成。扩展=把 `maven-metadata.xml` 目标的 sidecar GET 从「节点摘要查表 404」改道「metadata 源字节计算」，双链各一处。
2. **注意钉界**：本面是文件名域例外——generic 本地未设 404 规（P8/C2 族）对 `maven-metadata.xml.*` 文件名**不适用**（L040 generic 行实证），票面显式写明例外仅限该文件名族，防实现泛化到任意文件。
3. **用户可见影响**：mvn resolve 场景不取 metadata 校验和（低频），但仓库校验工具/一致性巡检（real: `mvn` 生态外的 repository validator、镜像校验脚本）会取；PUT 面对齐后 GET 面单独留 404 会构成「PUT 200 而 GET 404」的自相矛盾面，客户端可感知。
4. 与已 VERIFIED 的 `maven/derived-sidecar-validator-family` 契约零冲突（该契约覆盖工件 sidecar 的 LM/IMS 面；metadata 目标的条件请求面未探——不实现不猜，LM/IMS 行为留探腿后定）。

### 面三 C5-visibility（metadata 可见性 facet）：建议 = **拆立新条目，UNKNOWN 补证后置裁定**（不随本两面对齐打包）

- facet 内容：PUT `maven-metadata.xml` 201 后 FileInfo 源 **A=200 / B=404 node not found**（B 的 metadata 存于 metadata 存储，文件节点查询不可见——L039 Arm5 双 facet 之一）+ 拦截臂对 metadata 存储不可见（PUT 面已由专用路由绕开，此臂仅余历史意义）。
- 拆立理由：①**不阻塞前两面**——专用路由零持久化无需可见性，GET 走 metadata 读取器不走 FileInfo；②**牵动面广**（L039 原注）：REST /api/storage FileInfo 契约、UI 制品树（metadata 是否显示为文件节点）、下载计数等 metadata-plane 邻面全被牵动，是一个「BinFlow 要不要让 metadata 以文件节点形态可见」的产品级取舍（A 可见；BinFlow 现架构 metadata 独立存储是有意设计），对齐成本与 UI parity 影响需独立评估，可能终点是 INTENTIONAL（内部存储形态差异）而非对齐；③证据未齐——A 对各层级 metadata 的 FileInfo 形态、FolderInfo 列表是否含 metadata 未系统取样。
- 处置：本裁定随 C5 主体翻态时，同步立案新条目（草稿见下），review_gate=下轮探针补 A FileInfo/FolderInfo 各层级形态 + UI 影响评估后独立裁定。

## C7 `generic/remote-deploy-refusal-form` — 建议：四分面裁定（a 对齐 / b 收注 / c 对齐+探腿 / d 对齐+证据门控）

### 面 a：generic 仓 remote PUT 拒绝形 — 建议 = 对齐实现（404 Could-not-find-local-repo，复用 T-553 引擎文案）

**A 形（双轮×2）**：404 `Could not find a local repository named <key> to deploy to.`（终缀与否同形，拒绝先于一切终缀解释与回源）。**B 形**：405 `Remote repository '<key>' is a read-only proxy cache; …` + `Allow: GET`（repo/service.go:304 `refuseNonLocalWrite`，FR-20-AC9/RE-05 锚）。

理由：
1. **权威栈完整且同向**：docs/reverse/rest-api.md §1.2 step 2（「local/remote-cache 不存在 → 404 Could-not-find…」，**高置信，官方文档亦记载**）+ L039 Arm7 + L040 N2 活体双轮×2。效力序上规格级实证 > PRD——**PRD milestone-3 RE-05 行（`PUT/POST /binflow/<remote>/<path>` → 405+Allow:GET，P0 兼容）与活体 A 矛盾**，该行权威域应收窄至非存储面协议（docs/reverse/helm.md RE-05=chartmuseum API 面 405+Allow:GET 为 A 真形；conan 面 as-built 同族）——不是推翻 RE-05，是**域注记**。PRD 归 product-manager，移交 conductor（见 Next）。
2. **B 内部双拒绝形并存自身即缺陷**：maven 链已答 A 形逐字（T-553 引擎 `deployNoLocalRepoMessage`，httpapi/router.go:2422；L040 1c 双轮逐字），generic 链仍 405——同一行为两种拒绝形。对齐=把 generic 链上传拒绝改走同引擎文案（T-553 模式已双轮验证）；service 层 `refuseNonLocalWrite` 保留为非 HTTP 调用方的安全网（其注释自述 safety net 定位），不再是客户端面。
3. **用户可见影响**：误配客户端（npm/curl 等推到 remote）拿到的 status+body 分歧（405 read-only vs 404 no-local-deploy-target），status 族变化改变客户端重试/报错分支。
4. **成本/风险**：成本低（文案与渲染路径现成）。风险=B 侧 405 断言翻新（httpapi/deploy_refusal_family_test.go:107 t553-grem 腿）；**docker/cargo 的 405 不动**（docker/remote.go:720、cargo/remote.go:53——其面的 A 形证据未动，属 C7 域外，可另立候选票补证，本票禁顺手翻）；CT 微面（maven 面 A=`application/json;charset=ISO-8859-1` 已注记、generic 面 CT 未探）→ 票内探腿钉，不猜。

### 面 b：maven 仓 remote PUT — 已逐字一致，**无动作**

T-553 引擎文案 + L040 Arm1c 双轮逐字（唯 CT charset 微差在案）。建议：C7 条目改写时**收注该面已对齐**（resolved 的组成部分），防止后续票误触。

### 面 c：DELETE remote-miss 文案 — 建议 = 对齐实现（remote 面先行 + local 对照探腿门控扩族）

**A 形（双轮）**：404 `Artifact deletion error: Item <repo>/<path> does not exist`。**B 形**：404 `Could not locate artifact. Path: '<repo>/<path>'.`（generic writeServiceError ErrNodeNotFound 非 GET 臂，handler.go:851——借 maven miss 族文案）。
- 用户可见：REST/UI 删除不存在制品于 remote 仓的报错文案（curl/UI toast 直出）。
- 成本低（同 status 改文案）。**诚实边界**：A 对 **local** 仓 DELETE-miss 文案未探（本批 c7 腿仅 remote）——若 A local 面同族（`Artifact deletion error` 形），对齐应族级统一；若不同，则域限 remote 面。**票内先跑 local 对照探腿，证据门控是否扩族**——不猜。

### 面 d：sidecar-GET through remote — 建议 = 对齐实现（maven 面：撤 a-priori 拒绝、回源代理）；generic/rpm 面=探腿证据门控

**A 形（maven 面，双轮）**：remote 面 GET `{artifact}.sha1` **会回源取**——404 文案包对 `.sha1` 的上游拉取错误（错误外显族，非固定拒绝文案）。**B 形**：三锚 a-priori 拒绝 404 `Checksums are not downloadable.`——maven 前置拒绝（adapter/maven/handler.go:230-236，注释锚 maven-npm-pypi.md §1.5/FR-20 step 2）+ **remote 引擎共享臂**（remote/cachestate.go:68，测试断言「sidecars never proxied」零上游命中）+ rpm 拷贝（rpm/handler.go:53）。
- **实证压过规格**：docs/reverse/maven-npm-pypi.md §1.5 行 101「GET checksum（remote repo）**绝不回源**：直接 404 固定文案」与 L040 双轮回源实证（错误包上游拉取过程）**直接矛盾**——活体差分为权威，规格行需勘误（reverse-engineer 域，上报）。B 的固定拒绝文案是规格错误假设的实现产物（非 A 来源文案），对齐依据充分。
- **用户可见影响**：mvn 经 remote 仓取工件校验和（checksum policy 非 ignore 时）——A 供真实校验值，B 恒 404 → mvn 降级 warn-fallback（校验策略失效面），真实客户端可感知。
- **诚实边界（票面如实标注）**：A 上游**可达**时的 200 成功形态未直证（A 实验网不可达 fixture 上游，L040 头注「以错误外显形态判别」）——对齐目标定义=「sidecar 终缀经 remote 读面走**与普通文件 GET 相同的**回源/缓存机械」（错误外显族已证同机械），A 侧 200 成功形态留开放观察腿（网络受限，如实 NOT_RUN）。
- **作用域与门控**：引擎臂是共享的——直接删除即全域翻转；maven 面 evidence in hand，**generic/rpm 面 A 形未探**（L040 NOT_RUN 清单明示 generic 面腿未设）→ 票内探腿先行，探得 A 亦回源则全翻，探得 A 拒绝则域限 maven（引擎臂加域限或 maven 面前置放行）。rpm 面同批探。
- **安全**：撤拒绝后走普通 remote 读链=私网上游守卫（NFR-S13）天然覆盖，守卫域零变化；验收含守卫负测腿（未豁免仓 sidecar GET 仍守卫拒）。

### ② R13 工程票输入草案（C7 两票——area 不同必须拆）

**票一 C7-PUT/DELETE（area：dev-go-core〔internal/httpapi 引擎拒绝〕+ dev-registry-adapter〔generic writeServiceError 文案〕协作，主 area=dev-go-core）**
