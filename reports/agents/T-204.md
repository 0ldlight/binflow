# T-204 认证尾巴清偿（auth tail cleanup）

## 票据
- 标题：认证尾巴清偿（P2）
- 摘要：清偿 T-192 遗留的两项尾巴：(1) docker / npm 两个适配器直接调用纯 `auth.VerifyPassword`，绕过 argon2 并发闸门；(2) `auth.hash_concurrency` YAML 键尚未接线。
- area：`internal/auth` / `internal/adapter` / `internal/config`（`cmd/binflow-server` 接线一处，见遗留）

## AC 与完成情况

### AC① 把两个适配器直达入口路由过闸门
完成。做法：把 T-192 的 gated 入口 `Service.verifyPassword` 导出为 `Service.VerifyPassword(ctx, password, encoded)`；在消费侧定义 `adapter.PasswordVerifier` 接口（接口在消费侧定义）；两个适配器的组装点通过 capability probe 从既有入参恢复该能力。

- `internal/adapter/docker/token.go`：`authenticateForm` 去掉 `auth` 直调，改用 `h.verifier.VerifyPassword(ctx, ...)`；`New` 中对 `authz` 做 `authz.(adapter.PasswordVerifier)` probe。
- `internal/adapter/npm/session.go`：`serveLogin` 的表单凭据分支改用 `h.verifier.VerifyPassword(ctx, ...)`；`WithAuth` 中对 `tokens` 做 probe。
- 纯函数 `VerifyPassword`（包级）保留为默认 `hashVerify` seam，二者不同名、不冲突。

storm 模拟测试（小参数注入证明闸门生效）：
- `internal/adapter/docker/token_gate_test.go`：`TestFormCredentialStormThroughGate` 用 6 个 16 MiB 派生、gate=1，实测 ~7x 串行。
- `internal/adapter/npm/session_gate_test.go`：`TestCouchLoginStormThroughGate` 实测 ~5.8x 串行。

### AC② 接线 `auth.hash_concurrency`
完成。沿 T-179/T-186 的 raw-struct + env-override 模式：
- `internal/config/api.go`：`AuthConfig.HashConcurrency int`（0 = 派生默认）。
- `internal/config/load.go`：raw `HashConcurrency *int`（区分缺省与显式 0）、build 分支、`setEnvValue` 的 `envIntPos` 分支、defaults()。
- `internal/config/config.go`：`splitEnvKey` 增加 `auth.hash_concurrency` 定位。
- `internal/config/validate.go`：负数拒绝（0 = 派生默认，正向语义）。
- `cmd/binflow-server/main.go`：`authSvc` 构造后若 `>0` 调 `WithHashConcurrency(...)`。

未设置时默认 = GOMAXPROCS 限幅（`maxHashConcurrency`），行为不变。

### AC③ 测试：解码/默认/env 覆盖 + 闸门上限断言
完成：
- `internal/config/hash_concurrency_test.go`：缺省=0、YAML=4、YAML 显式 0、env、env 覆盖、大值 64 不限幅、负数/非数值/未知键拒绝。
- `internal/auth/t204_gate_test.go`：`Service.VerifyPassword` 闸门有界（limit 1/2/4 × workers）、取消的调用者被放弃、预取消快速失败。
- 适配器两个 storm 测试（AC①）同时覆盖 wiring + 串行化断言。
