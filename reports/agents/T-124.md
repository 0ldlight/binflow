# T-124 工作日志 — folder 节点零占位 sha 破坏 export 修复（D-106-1）

状态: done（自测全绿 + 真机往返通过；待主会话 qa）

## 1. 缺陷与根因（复述确认）

- 显式目录节点（C16 mkdir = PUT 尾斜杠空 body，`repo.Service.Put` folder 分支）在 `nodes` 行存 64 零占位 sha256，并在 blobs 台账落一行共享 marker 行（size 0、**无物理文件**）。
- `internal/metadata/snapshot.go` `SnapshotChecksums` 的 `SELECT DISTINCT sha256 FROM nodes WHERE sha256 != ''` 滤不掉占位 → `cmd/binflow-server/backup.go` Step 3 把它当被引用 blob 强求存在于拷贝树 → fail-closed 拒绝整库导出。
- 写入处实证（占位是**稳定契约**，非巧合）：`internal/repo/service.go` `emptyFolderSHA` 常量；`ensureFolderLedger` 写共享台账行；读平面按**值**分支（`service.go` Get → ErrIsFolder、`virtual.go` probeLocalMember）。全库唯一 folder 行写入点（remote fetcher 只写真实内容摘要）。

## 2. 选法论证：按值排除（Option A），不按 path LIKE（Option B）

选 **`AND sha256 != <占位值>`**，理由：

1. **值即契约**：整个读平面按值分支（Get/虚拟成员探测），占位值是 folder 语义的载体；路径形状只是写入侧的拼写（generic 适配器 `isFolderNode` 按尾斜杠、search 的 nodeQuery 按 `path NOT LIKE '%/'`——两种键法并存，说明路径形状不是唯一真理）。
2. **不可碰撞**：SHA-256 输出不可能为 64 个零（`sha256("")` = e3b0c442…，测试已固化），checksum-deploy 声明该值也会因 filestore 无物理对象被拒（PutFromBlob 双维校验）→ 按值排除永不误伤真实 blob。
3. **docker_refs 半边无路径**：值语义规则对 UNION 两边概念统一。

常量按票据建议导出：`metadata.FolderMarkerSHA`（store.go，紧邻 `NeverExpires`），SQL 与消费方共用；`repo.service` 的 `emptyFolderSHA` 改为 `= metadata.FolderMarkerSHA` 的编译期别名（单一拼写，防漂移）。

## 4. import 侧同查结论（无需改）

- `verifyBackupBlobs`（size/spot/full 三档）只遍历 `manifest.Blobs`；修复后 manifest 永不含占位 → 恢复链不会绊倒。
- **存量包无兼容问题**：缺陷形态的 export 在 `WriteManifest` 之前就拒绝退出且 `cleanupBackupDir` 清场——世上不存在携带占位的 manifest 工件。
- 恢复库由 `metadata.db` 整文件拷贝 → folder 行 + marker 台账行原样随行（真机已验证，见 §6）；恢复后首次 `metadata.Open` 的迁移链不触碰占位。

## 5. GC mark 集同查结论（已顺手同修）

- 害处评估：占位进入 mark 集不会误保活任何对象（无物理文件可匹配），确认"无害但语义脏"。
- 仍选择同修（cmd + httpapi 两处）：`storage.GC` 只按 mark 集对**盘上文件**做 sweep，跳过占位零决策变化；但"mark ⊆ 物理 blob sha"由此成立，杜绝未来消费者踩 T-124 同类坑；两处代码自带同形同跳同步契约，单修一处反而违约。
- ledger marker 行不受影响：`FilterUnreferenced` 对 nodes 反连接，folder 行仍引用它（FK 安全），未被 GC 删除路径触及（删除集只含盘上文件）。
