## 做了什么

按 architecture §15.3（权威契约）+ PRD FR-89 + inv-3 §3.1（矩阵参数传输入口）落地属性系统后端四件：

1. **SplitMatrixParams 单点**（§15.3.1，M1 预留缝兑现）
   - `adapter.SplitMatrixParams(decoded) (clean, matrix)`：取 decoded 全路径（含 repoKey 段）**首个 `;`**，其后缀每段含 `=`（`;k=v;k2=v2` 形）才剥离；否则整体保持 M1 字面路径（兼容回退，§11.39）。
   - `adapter.ParseMatrixProps(matrix)`：键 `[A-Za-z][A-Za-z0-9_.-]{0,63}`、值无控制字节 ≤1024B、≤64 对；非法键 → wrap `ErrBadRequestPath` → 400（Artifactory 非法键姿态，rest-api.md §1.3 高置信）。
   - `adapter.ResolveContent(r)` = Layout 全形态（key, rel, props, err）；`Layout` 变为其丢弃 props 的薄壳——所有经共享 Layout 链的面（generic/maven 全动词）自动获得剥离；**非法键在 GET/HEAD/DELETE 同样 400**（单点对称，双动词语义一致）。
   - `adapter.WithDeployProps/DeployPropsFrom`：与 WithPrincipal 同构的 request-context 注入缝（§15.3.1 伪代码位点）。
   - 存量兼容的形态学裁定（表驱动固化于 `internal/adapter/matrix_test.go`）：`a;b.bin`/`file;name.jar`/`x;y;z.txt`/`dir;d/…`/maven 布局 `;` 名 → 字面；**成对后接裸尾（`;k=v;extra`）/尾随 `;`/`;;` → 整体字面**（「整体匹配」严格读法）；`a;b=1.bin`（值含 `.bin` 的成对形）→ 剥离（这是特性本身，seed-m10 头注已声明为 documented behavior change）。
2. **migration 013 node_props**（§15.3.2 选型 A）
   - sqlite + postgres 双方言同体：`(repo_key, path, name, value)` 主键（多值=多行）、`FOREIGN KEY (repo_key) REFERENCES repositories ON DELETE CASCADE` + 复合 FK `(repo_key, path) → nodes(repo_key, path) ON DELETE CASCADE`、`idx_node_props_name(name, value)`（M11+ 搜索预留）。
   - 纚合：NodeStore.Delete/DeleteByPrefix/仓库删除**同语句级联清 node_props**（FK 构造性兑现 §15.3.2「同事务清」）；孤儿注解（node 不存在）被 FK 拒绝（测试固化）。
   - 子仓 `metadata.NodePropStore`：`List`（键→有序值集）/`Merge`（§11.40 合并律：同名键值集替换、异名键保留，单事务）/`Delete`（选键；nil=全删，幂等）。
3. **?properties 三动词**（§15.3.3 + inv-1 §F / rest-api.md §3）
   - 路由：`/api/storage/…` 既有 storage 分支追加参数臂（`?list`/`?permissions` 同族第三员）；**无参数分支字节不变**。router.go 与 T-285 的 v2/content 段不冲突（他 patch goproxy 挂载，我 patch storage/ 分支——文件级共存，各自日志注明）。
   - GET：`{"properties":{…}}`（§15.3.3 表体）；过滤=逗号多键+尾 `*` 通配（前缀匹配）；空参=全量；无命中=200 `{}`（**BinFlow 有意分歧**：Artifactory 404 "No properties could be found."——§15.3.3 表裁定，非 §11.40 但同族「自有语义待校准」）；`atomic=true` 任一字面键缺失→404（FR-89.2）。门=item-info 同门（内容面读、匿名随 anonymous_access）。
   - PUT：合并写（merge=同名键值集替换）、204；node 须存在（404）；folder 可挂属性；`recursive=1` = folder 行 + 前缀全节点。门=route `required` + handler 内 `Authz.Can(w)`（**同内容面 Authorizer**；不要求 `d`——§15.3.3 与覆盖写解耦）。
   - DELETE：选键/`*` 通配/`properties=*` 全删，幂等 204；空参=400 "Unspecified properties to delete."（rest-api.md §3 高置信）。recursive 同 PUT。
   - **逗号文法**（一处钉死）：raw query 值上按**未编码逗号**切段，含 `=` 段开新键、无 `=` 段续前键值集——`qa=passed,owner=team-a`（PRD L19 原样）与 `k=v1,v2`（§15.3.3 多值例）同一文法；`%2C` 解码后为值内容（encode 语义可钉死给 tech-writer）。
   - 详情体 additive：FileInfo/FolderInfo 附 `properties`（omitempty，无属性节点字节不变——M9 冻结断言零改动）；填充点在 writeFileInfo/writeFolderInfoBody，**不进 fileInfoOf**（search 面共享者保持精简字段集）。
   - 审计：`props.write`/`props.delete`（repo/path/键清单摘要 + recursive 标记入 detail）。
   - E-09 反转：`?properties` 离开 unimplemented 清单（storage.go + compat_test，T-97 R5 flip 同款注释）；`propertiesXml`/`stats`/`lastModified` 仍 E-26。
4. **PutOptions.Properties**（§15.2 接口归属——Options 扩展，New 零动）
   - `repo.PutOptions` 增 `Properties map[string][]string`；`PutWithOptions` 前置 `propSetGuard`（非法集 400、零副作用）→ `putNode` 共尾 `applyDeployProps`（§15.3.1「全族同链」：Put/PutWithOptions/PutFromBlob/PutLandedBlob 共尾，后两者现传 nil——见遗留 3）。
   - generic/maven 的 PUT 链改经 `ResolveContent` + context 缝 → `PutWithOptions`（generic 流式/文件夹臂、maven artifact/metadata/sidecar 臂全接）；`repo.ErrInvalidProperties` → 400 映射进两处 writeServiceError（防御背刺）。
   - 属性形状规则的**规范落点调整**：validator 本要放 repo，但 `repo→remote→adapter` import 环禁止 `adapter→repo` → 移到 `metadata`（013 表的行形状法，双方可达），repo 以 facade 别名（`repo.ErrInvalidProperties`/`repo.ValidatePropSet`）。理由注释在 `internal/repo/props.go` 头。
5. **e2e/m10 properties spec 填肉**：L18（矩阵部署+读回+详情回显+后缀再寻址）/L19（PUT merge/多值/通配/atomic/递归/选删/全删幂等）/L20（非法键双臂 400+不落地、空删 400、未知 404）/L22（seed-m10 五 fixture 逐字节 + verifyM10 复跑 + E-09 翻转 200）。L21（UI Tab）归 FE 票。断言 `{"properties":{…}}` 包裹形态（§15.3.3 为权威；README §2.3 内联示例是解包裹形态——见遗留 5）。
6. properties addon（community 地板）：本票无门控腿；确认——测试栈 `deps.Addons==nil` 走 `minTier<=community` 恒通、m10 矩阵 T01~T06 基线零偏移（无 license 实例属性面仍通）。

## 规格依据与置信度处理

- 高置信直实现：矩阵参数剥离语义+非法键 400（rest-api.md §1.3 / inv-3 §3.1 高）；`?properties` 端点族与错误码（rest-api.md §3 高：空删 400 "Unspecified properties to delete."、PUT 204）；`:properties` 旧写法维持既有 409（generic/maven 既有臂，未动）。
- §15.3 自有裁定照办：GET 空命中 200 `{}`（vs Artifactory 404）；PUT merge=同名键值集替换；recursive=folder 行+前缀全集；值集存储多行。
- **中置信固化于测试**（翻转点已隔离在 handler 单点，§11.40 同族）：逗号文法（对-续段式）；empty value 拒绝（矩阵+REST 双臂同词 "Properties value cannot be empty."）；`properties=*` 全删；recursive 显式 opt-in（非 rest-api.md §3 的「folder 默认递归」中置信读法——§15.3.3 表为权威）。
- **低置信（规格待验证，已按严格/确定性读法实现并日志标注）**：①矩阵参数 empty value 是否 400（无双证）；②尾随 `;`/混合形（`;k=v;extra`）整体回退字面（「整体匹配」的严格读法）；③GET 命中空集 200 vs 参照面 404。均待 M10-F/M11 rest-api 规格票 curl 对照后翻转（§12-16 校准点）。
