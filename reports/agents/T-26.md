## 二、gosec 豁免复核裁决（.golangci.yml）

### 触发面取证（grep 全仓）

| 规则 | 产品面触发点 | 测试面触发点 |
|---|---|---|
| G401 弱哈希 | internal/storage/digest.go（sha1/md5 为 Artifactory 兼容附属摘要，ADR-0003 sha256-only 寻址） | streaming/engine/round2 等 *_test.go 构造 md5/sha1 期望值 |
| G115 整型收窄 | internal/metadata/password.go:91（argon2 参数传递，上方有 spec floor 边界检查） | streaming_test.go 测试算术 |
| G204 子进程 | **零触发**（产品代码无 exec.Command） | streaming_test.go 调宿主 shasum/md5（t.TempDir 内自建文件） |
| G304 变量路径 | config/load.go:62（`-c` 操作员给的配置路径——读它就是功能本身）+ storage/engine.go 七处（路径 = 引擎自有根 + 生成 UUID 或 64-hex 校验名，见 blobPath 守卫） | 多处 t.TempDir 路径 |
| G301/G306 目录/文件权限 | **零触发**（产品统一 0o700/0o750/0o600，原生通过） | 崩溃残态夹具（0o755/0o644 模拟半写残渣） |

### 逐条裁决

1. **G301/G306 → 完全移除豁免**。产品面本来就过（不豁免也 0 告警），只有测试夹具触发——归入测试整体豁免。此规则从全局豁免清单里删掉后，产品面新增宽松权限会被正常捕获，净收益最大。
2. **G204 → 收窄到 `*_test.go`**。产品面零触发，保留全局豁免等于永久熄灭「未来有人引入子进程」的告警面。收窄后产品面任何 exec.Command 都会报。
3. **G401 → 收窄到 digest.go + 测试**。兼容摘要只应存在于 digest.go（集中封装处）；其他包再 import md5/sha1 会被告警，强制走 sha256 或说明理由。
4. **G115 → 收窄到 password.go 单文件单规则**（argon2 参数行，界检在上方）。
5. **G304 → 收窄到 config/load.go 与 storage/engine.go 两文件**，配置内逐文件写明理由（操作员路径 = 功能；引擎路径 = 根 + UUID/validated hex，无请求可控分量）。其他任何包新增变量路径文件操作都会报。
6. **测试文件整体豁免 gosec**（`_test\.go` 路径规则）：G204/G401/G301/G306/G304/G115 在测试里全是夹具构造与交叉校验固有模式，不进二进制；逐规则写豁免纯属仪式。产品面保持全覆盖。

### 连带问题与处置

- 收窄后测试里的旧 `//nolint:gosec` 注释变「unused」，nolintlint 报 8 处。v2.12.2 的 `allow-unused-in-tests: true` 在同文件命中排除规则时不生效（隔离模块探针实测），故取 `allow-unused: true` + `require-explanation: true`（既有注释都在讲理由，保留其意图说明价值；新指令必须带解释），并注明升级工具链后应收紧回 allow-unused: false。
- require-explanation 顺手揪出 repo_test.go 两处裸 `//nolint:errcheck`，补上理由注释（超出本票授权范围的最小必要修改，两行注释、不改逻辑，向 conductor 报备）。
- 探针验证：隔离模块用**项目同款配置**放入新增违规文件（md5 import + exec.Command + os.ReadFile 变量路径），G501/G401/G204/G304 四条全部命中——证明豁免只覆盖白名单路径，产品安全面恢复监督。
