## 一、做了什么

### 1. Authenticator（AC ①，架构 §3.4；auth-model.md §3.6 高置信度）

`internal/auth/authenticator.go` — `Service.Authenticate(ctx, r) (*Principal, error)`，nil,nil=匿名。

入口与优先级（`Authorization` 头优先于 `X-JFrog-Art-Api`）：

| 入口 | 行为 |
|---|---|
| `Authorization: Basic user:pass` | 先按口令校验（argon2id）；失败且 pass 可验证为 token 时走 token 分支，此时 Basic 用户名须与 token 主体 **忽略大小写一致**，否则 401（"Token principal mismatch"，auth-model.md §3.6 `verifyMatchingPrincipal`） |
| `Authorization: Bearer <token>` | token 验证（为 M2 docker 预留，M1 已可用） |
| `X-JFrog-Art-Api: <token>`（含旧名 `X-Api-Key`） | token 验证 |
| 无任何凭据 | (nil, nil) 匿名 |
| 有凭据但被拒 | 明确错误类型：一切失败 `errors.Is(err, ErrInvalidCredentials)`；无凭据 `ErrNoCredentials` 语义由 nil,nil 承担，401/匿名 的分层决定权留给调用方（T-14） |

其他：用户 disabled 一律拒绝（Basic 直拒、token 在 owner 检查时拒）；Basic 头损坏（base64 非法/无冒号）= 无效凭据而非匿名。

### 2. TokenRegistry（AC ②，NFR-S2；PRD E-17 v1.3 + auth-model.md §3）

`internal/auth/token.go`：

- `Issue(ctx, user, ttl) (*IssuedToken, error)`：32B crypto/rand → hex（64 字符）；**DB 只存 sha256(plaintext)**，明文仅签发返回一次；ttl<=0 = 永不过期（存 `metadata.NeverExpires` 哨兵）。返回结构体含 `access_token / token_type="Bearer" / expires_in（秒，0=永不过期）/ scope="api:*" / token_id（超集扩展）/ username` —— HTTP 形态归 T-15，本层只出结构体。
- `Verify(ctx, plaintext)`：查摘要 → 过期检查 → 吊销检查（吊销=删行，无行即含吊销/未知）→ owner enabled 检查；`last_used_at` 尽力盖章（失败不阻断）。
- `Revoke(ctx, plaintext)` / `RevokeByID(ctx, tokenID)`：按值吊销先查再删（未找到返回 wrap `metadata.ErrTokenNotFound`，HTTP 层映射幂等 "Token not found" 200，auth-model.md §3.4-5）；按 id 直接删。
- `PasswordChanger.ChangePassword`：旧口令校验（错→`ErrInvalidCredentials`→HTTP 400 非 401，auth-model.md §2.2）→ 新口令空/与旧同 的类型化错误 → argon2id 重哈希写回（走 UserStore.UpdatePassword）。

### 3. Authorizer.Can（AC ③，架构 §3.4；PRD E-24；auth-model.md §4 高置信度）

`internal/auth/authorizer.go` + `internal/auth/pathmatch.go`：

- **admin 全通过**（不经 permission target）。
- 命名 permission target 判定链：`PrincipalsFor(repoKey)` 取该 repo 的全部 principal 行 → 过滤（用户名忽略大小写、`principal_type=="user"`——M1 无组，group 行不误用）→ 该行须授目标 action → 所属 target 的 `repos` 含该 repo → **include/exclude Ant 风格匹配**（`**` 跨段、`*` 段内、空 includes=全含、目录裸前缀具 matchStart 语义覆盖未上传子路径、token 去空白）→ 任一满足即授权。
- exclude 语义（与规格逐字对齐）：「excludes 优先于 includes」**作用于单个 target 内部的 pattern 评估**；多个 target 之间是并集——一个 target 排除的路径仍可被另一个无排除的 target 授权（Artifactory 权限合并行为，auth-model.md §4「admin 不经判定、targets 合并」）。两个方向都有测试固化。
- 无命中=拒绝；**store 错误 fail-closed 并 slog 记录**（打错的权限表绝不能放行）。
- 匿名（p==nil）：仅 `config.Security.AnonymousAccess==true` **且** `action==read` 且内容路径（repo+path 形态——Can 本身即内容路径决策点；管理面 `/binflow/api/**` 的「恒需认证」由 T-14 在路由层把守，本包 godoc 已注明契约边界，ADR-0009）。

### 4. audit.Logger（AC ④，架构 §3.5）

`internal/audit/audit.go` + `api.go`：

- `Append(ctx, Event) error`：补服务器侧字段（Time 空则打点、Actor 空则 `anonymous`、Detail 空则 `{}`）→ **Redact 脱敏**（credential 形态键值→`[REDACTED]`）→ `RemoteAddr` 并入 Detail JSON 的 `remote_addr` 键（audit_events 表无该列，结构保持与 metadata.AuditStore 对齐，字段不丢）→ 落库。
- `Record`（Logger 具体方法 + `BestEffort(l) Recorder` 接口包装）：**尽力而为**——错误 slog 记录（含 action/actor/repo/path/error，不含 Detail 载荷与任何凭据）并吞掉，绝不阻断主流程。
- `Query(ctx, Filter)`：newest-first、repo/actor 过滤、limit 默认 100。
- `audit.enabled=false` 时 Append 是 no-op（文档化姿态，非错误）。
- Action 词汇表常量（deploy/delete/download/login.*/repo.*/token.*/password.change）。

### 5. argon2id 归置（票据指定决策点）

**选择：实现保留在 `internal/metadata/password.go`，`internal/auth/password.go` 做薄 re-export（auth 拥有的 API 面）。**

理由（三选一中的影响最小评估）：
- 上移到 auth：auth 的 store 适配器（deps.go）import metadata → metadata 的 admin 种子（Open 内 seedAdmin）需调 HashPassword → **import cycle**。
- 注入 hook（metadata 暴露 RegisterHasher）：能解环，但引入进程级可变全局 + 启动顺序耦合 + 双注册 panic 面，复杂度明显高于收益。
- 保留原处 + auth re-export：零行为变化、零新机制、metadata 既有测试不动、调用方看到 auth.HashPassword/VerifyPassword 的 auth 拥有 API。**架构 §3.4「密码校验归 auth」在 API 面上成立，实现位置记为对架构的字面偏离**——已在两文件 godoc 互相注明，请 architect 知悉（后续若 metadata 种子改为外部注入可顺势上移）。

- **修法（采 reviewer 建议路径 1）**：约定 **path 以 `/` 结尾 = folder**（与 `repo.isFolderNode`/`internal/repo/validate.go:126` 的尾斜杠约定一致）；`segsMatch(pSegs, tSegs, isFolder)` 仅对 folder 形态启用「pattern 耗尽但路径有余段」的前缀规则，文件路径严格全段匹配。上游 `PathMatcher.matches` 的 `useStartMatch` 正是 `repoPath.isFolder()` 门控——语义对齐。
- **行为变化（须知 T-13/T-14/T-15）**：`includes:["ci-out"]` 现在授权 **folder** `ci-out/`（列表）及其下 folder，但**不再**授权文件 `ci-out/a.bin`——要覆盖前缀下的文件请用 `ci-out/**`（Artifactory 惯例写法，PRD C22b 用的就是 `ci-out/**`，主流程不受影响）。
- **新约定一句话（请 conductor 转 architect 回写架构 §3.4 Authorizer 注释）**：「Can 的 path 以尾斜杠标识 folder；Ant matchStart 前缀规则仅对 folder 路径生效，文件路径必须与 pattern 全段匹配（对齐 Artifactory PathMatcher 的 isFolder 门控）；调用方路由 folder 请求时须保留尾斜杠。」
