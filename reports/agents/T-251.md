# T-251 — E2/E3/E4 users 域端点：列表 additive 加宽 + enabled 回显 + DELETE 全链

- 状态: done（自测全绿；契约闸门 0 deviations 维持）
- 角色: dev-go-core ｜ 批次: M9 B2 ｜ 2026-08-24

## 做了什么

1. **E2 列表加宽**（additive）：`GET /api/security/users` 列表项在既有
   `{name,uri,realm,source}` 之上增 `email`/`adminRole`（snake 三值闭集）/
   `enabled`（恒渲染）/`groups`（成员集，空 = `[]` 恒非 null）。数据源 =
   users List + `GroupStore.MembershipsByUser`（user_groups JOIN groups 的
   一次聚合查询，ORDER BY username, g.name——全列表恒两次查询，与用户数
   无关，即 FR-78 要杀的 N+1 的服务端半边）。
2. **E3 enabled 回显**：`GET /api/security/users/{name}` 的 userDetail 增
   `enabled: bool` 恒渲染（DB 行事实，读侧闭环 T-208 的 `*bool` 写侧）。
   既有字段的条件语义（groups 恒渲染 []、lastLoggedIn omitempty）不动——
   gap-endpoints §1.2 的「空组省略」是中置信序列化形态，且改为 omitempty
   会破坏既有消费者，非 additive。
3. **E4 DELETE 全链**：`DELETE /api/security/users/{name}`（新路由，
   `CapSecurityWrite`、无覆盖集臂）。用例在 `auth.Service.DeleteUser`
   （护栏判定 + 级联编排），级联在 `UserStore.DeleteCascade` 单事务：
   先剥 permission_principals 的 user-typed ACE 行（该表无 FK，显式删），
   再删 users 行，FK 级联 user_groups/tokens/web_sessions（Verify 缝逐请求
   重查 owner → 行删即 401，ADR-0025 护栏③同缝）；audit_events 保留。
   - 护栏全 400 纯文本，检查序按 §14.1 E4 列举序：**存在性（404
     `User not found`，同族于 GET 单用户与组面）→ 内置 admin（含保留名
     anonymous——正常实例无此行，天然 404，护栏仅兜手建行）
     → 最后一个 admin → 自删**。last-admin 先于 self 的理由（代码内注
     释钉死）：wire 门是 security:write，last-admin 目标只能是调用者自身
     （存在第二个 admin 即非 last），self 先查会让 last-admin 400 在 HTTP
     面不可达且丢失更有信息量的文案。
   - 文案逐字：成功 `The user: '<name>' has been removed successfully.`
     （auth-model §1）；`Cannot delete the built-in admin user.` /
     `Cannot delete the current authenticated user.` /
     `Cannot delete user '<name>'. There must be at least one user
     configured with admin privileges.`（rbac-model §1.2.2 组面同族镜像）。
   - 审计 `user.delete`（新 action 常量，仅成功删除记录；detail
     `{"user":...}`，actor/remote_addr 走 Event 既有字段）。
   - 重复删除 = 404（BinFlow 自有 pre-probe；Artifactory 吞 Access 404 视
     为成功的幂等语义是并发窗口产物，§14.1 钉了 probe 形态——代码注释已
     注记）。
4. **守护断言更新**（两处，均为契约演进要求）：
   - `t97_groups_test.go` W40「列表瘦形态」断言 → E2 加宽形态（仍禁
     admin 布尔与 password 形字段；jane 空组断言 `[]` 非 null）。ADR-0030
     E2 对 W40 姿态的取代。
   - `t215_guard_test.go` manage 门计数 24 → 25（E4 新路由的
     CapSecurityWrite 门；注释内注记）。
5. **facet 接线**：httpapi 侧 `userDeleter` facet 经类型断言发现（与
   sessions/permView/stepUp 同 posture）；fake Authenticator 栈 DELETE →
   503 而非 panic。auth 侧 `userDeleteSource` seam 仅 NewFromStore 接线，
   bare `New` 的 DeleteUser 先查 seam-nil fail-closed（不碰任何协作者）。

## 规格依据

- ADR-0030（Accepted）E2/E3/E4 表 + K18/K19；architecture §14.1 E2/E3/E4/通则。
- gap-endpoints §1.1（列表闭集 + 无参）、§1.2（`enabled` 不存在——BinFlow 自有扩展由 §14.1 E3 定形）、§2.1/2.2（成功文案逐字、级联序：ACE 剥离先行）、§2.3（守卫矩阵——自删/last-admin/内置为低置信，§14.1 以 BinFlow 增强定形为 400 + 指定文案，我按其指定实现并在代码注释标注镜像来源）。
