## 1. 票内核定留痕（M16-SPLIT AC1 要求的「票内定案」）

1. **存储腿落 internal/metadata（越出票面 area 一格，最小必要）**：单查询 GROUP BY 只能在存储层表达——audit 包仅持 `Append/Query` 消费侧接口，翻页聚合违反 AC1。沿 **T-251 `MembershipsByUser` 先例**（同一端点、同一 N+1 语境、同为 store 聚合方法）加 `AuditStore.LastActionTimes(ctx, action)`：action 参数化（登录派生是第一个消费者，不是唯一合法值），SQL 守 SQLite/Postgres 公共子集（ADR-0007；postgres 仍为 M1 占位禁用，无第二栈要改）。全树 fake 排查：唯一 fake `failingAudits` **嵌入** `metadata.AuditStore` 接口（`audit_test.go:126`）——扩接口零编译波及，全树一次编译过。
2. **派生时延口径 = 查询时派生（不物化）**：每次列表调用一条 GROUP BY（idx_audit_action(action,time) 服务过滤）。无 schema 变更、无写路径耦合、append-only 日志是唯一事实源——派生永不与存储的 trail 相左。时延断言钉死：真实登录（POST /api/v1/session）后的**下一次**列表调用即见值（`TestUserListLastLoginProjection/a_real_console_login...`，二次登录 1.1s 后值前进）。
3. **派生面挂具体类型、不进 `audit.Logger` 接口**：`LastLogins` 是 `*logger` 的方法；httpapi 以 facet 断言发现（`lastLoginSource`——session/permView/stepUp/userDelete 发现先例，server.go 装配处）。裸 Logger fake 零改动；metadata-less 单元栈 facet 为 nil → 字段不渲染，端点行为 = pre-M16 逐字节。
4. **wire 形态**：字段名 `lastLoggedIn`（`userDetail` 既留的保留位拼写 + Artifactory access API 同名；M16-SPLIT 行文的 "lastLogin" 以 conductor 派单与本仓既有拼写为准）；值 = 存储的 audit Time 原样透传（`metadata.Now()` 即 RFC3339 UTC——列表族时间形态）；无登录史 → **键不存在**（`omitempty`，非 null 非 ""：T-252 键集断言先例，FE「Never」列渲染归 T-468）。
5. **ACL（NFR-S76 自身/管理员可见性门）**：投影搭乘列表既有的 `CapSecurityRead` 管理门——无新端点、无新暴露面；403（非管理员）/401（匿名）既有门逐字不动（`TestUserListLastLoginVisibilityGates` 断言）。管理员自身行也在列表内（登录后自见）。
6. **失败语义 = fail-closed**：派生查询失败 → 500 `"derive last logins: …"`（与 memberships 臂一致）。半派生列（一行查询失败全员显示「从未登录」）会误导该列存在目的（安全审查）——宁可整列表 500（`TestUserListLastLoginFailsClosed`）。
7. **「无端点列不伪造」解除依据留痕**：M16 前无任何端点承载登录时间 → FE 列不伪造（K 条纪律）。本票后数据源已备：`GET /api/security/users` 行级 `lastLoggedIn`；T-468（L1 列选器推广条件票，dep 本票）消费此字段渲染 Last Login 列。
8. **audit disabled 姿态**：`config.Audit.Enabled=false` 时 Append 文档化 no-op → 无 trail → 派生空 → 字段全员不渲染（「未记录」的诚实读法，非错误；`TestLastLoginsDisabledAuditSeesNoLogins`）。

## 3. 设计要点（review 快读）

- 查询成本：每次列表第 3 条查询（List + MembershipsByUser + LastActionTimes），与用户数无关；索引 `(action,time)` 等值过滤，GROUP BY 结果 ≤ 有过该 action 的 actor 数。
- 已删用户的 stale actor 留在 map 中不被查键——投影按列出的用户名 lookup，零泄漏、零清理需求。
- `userDetail`（单用户 GET）的同名保留位**本票不填**：AC 语境是列表投影；单用户面如有需求走既有 `Query(Actor+Action, Limit=1)` 定向查询即可（登记 §4）。

## 4. 登记不做 / 遗留

- **lastLoggedIn 排序臂**：按 conductor 派单「留票内登记不做」——默认序（username ASC）不变；如需 `?orderBy=lastLoggedIn` 走后续票（届时存储层已有 map，排序在 handler 内存即可）。
- **单用户 GET `/api/security/users/{name}` 的 lastLoggedIn**：保留位仍在（`omitempty` 恒缺）。FE 详情页如需，一行 facet 复用（§3）。
- **T-468（FE 列消费）**：本票为其解锁；消费字段 `lastLoggedIn`（无史=键不存在→渲染 Never 的口径归 FE 票）。
- metadata 存储腿越出一格 area（§1-1 已留痕理由）；conductor 复核如不认可该缝，替代方案只有「audit 包翻页聚合」——违反 AC1 单查询，不建议。
