## 变更文件

### `internal/config/api.go` (修改)
- 在 `StorageConfig` 中新增 `Backend` 字段（default "disk"）
- 新增 `S3Config` 结构体，包含 bucket, region, endpoint, access_key_id, secret_access_key, use_path_style, upload_part_size, upload_concurrency, bucket_prefix
- 新增 `StorageBackendDisk` 和 `StorageBackendS3` 常量

### `internal/config/config.go` (修改)
- 新增 `DefaultStorageBackend`, `DefaultS3UploadPartSize` (5 MiB), `DefaultS3UploadConcurrency` (4) 常量
- 新增 `S3SecretEnvVar` 常量 ("BINFLOW_STORAGE_S3_SECRET_ACCESS_KEY")
- 在 `splitEnvKey` 中注册所有 S3 相关环境变量映射（storage.backend, storage.s3.* 等）

### `internal/config/load.go` (修改)
- 在 `raw` struct 中新增 `Storage.Backend` 和 `Storage.S3` 子结构体
- 在 `build()` 中连线 S3 字段从 YAML 到 Config
- 在 `defaults()` 中添加 S3 默认值
- 在 `setEnvValue()` 中处理 S3 环境变量（envSecret, envBool, envString, envIntPos）
- 在 `rejectSecrets()` 中递归扫描 `storage.s3.secret_access_key` 防止 YAML 泄露

### `internal/config/validate.go` (修改)
- 新增 `storage.backend` 枚举校验（disk | s3）
- 新增 S3 后端必填字段校验（bucket, region, endpoint, access_key_id, secret_access_key）
- 新增 S3 upload_part_size 和 upload_concurrency 正数校验
- S3 后端跳过 data_dir 创建

### `internal/config/config_test.go` (新增测试)
- `TestLoadS3Defaults` - 验证 S3 默认值
- `TestLoadS3FullYAML` - 验证完整 S3 YAML 配置解析
- `TestLoadS3EnvOverrides` - 验证环境变量覆盖 YAML
- `TestLoadS3SecretAccessKeyEnvOnly` - 验证 secret_access_key 必须通过环境变量设置
- `TestLoadS3SecretAccessKeyCaseInsensitive` - 验证环境变量大小写不敏感
- `TestLoadS3SecretAccessKeyRejectedInYAML` - 验证 YAML 中 secret_access_key 被拒绝
- `TestValidateS3BackendMissingFields` - 验证 S3 必填字段校验（9 子用例）
- `TestValidateS3BackendValid` - 验证完整 S3 配置通过校验
- `TestValidateBackendUnknown` - 验证未知 backend 值被拒绝
- `TestValidateS3SkipsDataDirCreation` - 验证 S3 后端跳过 data_dir 创建

### `internal/httpapi/system.go` (修改)
- 新增 `context` 和 `time` import
- 新增 `minio-go/v7` 和 `credentials` import
- 重构 `probeStorage()` 为分发函数，根据 backend 类型调用 `probeDiskStorage()` 或 `probeS3Storage()`
- 新增 `probeDiskStorage()` - 保留原有磁盘写探测逻辑
- 新增 `probeS3Storage()` - 使用 minio-go/v7 执行 BucketExists -> PutObject(sentinel) -> RemoveObject 三步骤探测

### `internal/httpapi/system_test.go` (新增测试)
- `TestHealthEndpointStorageDiskOK` - 验证磁盘后端 health endpoint 返回 storage status "ok"

## 遗留问题
1. **httpapi 测试无法运行**：`go test ./internal/httpapi/...` 被 `internal/storage/s3.go` 的编译错误阻塞（T-151 并行工单，minio-go Client 方法签名不匹配）。httpapi 包自身代码编译和 `go vet` 均通过。待 T-151 修复后，`TestHealthEndpointStorageDiskOK` 和现有 `TestSystemEndpoints` 可一并验证。
2. **S3 健康探测集成测试**：`probeS3Storage()` 需要真实的 S3/minio 端点才能集成测试。当前只针对磁盘后端做了单元测试。待 CI 环境配置 minio 容器后可补充 S3 路径的集成测试。
3. **probeS3Storage 中 Secure 参数**：当前硬编码为 `true`（HTTPS）。未来可考虑根据 endpoint URL scheme 自动判断，或新增 `use_ssl` 配置项。
