## 1. AC1 逐项探测结论

### 1.1 入口拓扑（R1）— 活体实测，高置信

- 管理域侧栏（230px）五组：Projects / Environments / Repositories(Repositories+Layouts) / User Management(Authentication Providers) / General(Proxies+Monitoring) / **SERVICES(Artifactory)**——**无全局复制管理入口**；MC「Replication」页在导航词表内但 `HIDDEN_WHEN_SERVICE_NOT_INSTALLED(MC)`（bundle 证，OSS 无 MC 不可达）。
- 复制配置入口 = **仓库编辑页左轨步骤条**：`/ui/admin/repositories/local/example-repo-local/edit`，`jf-steps` 横排三步（1600 视口实测）：Basic `is-active` x=302 / Advanced x=721 / **Replications `is-disabled` x=1141**——各步等宽 **387px**、y=146、高 40px、`data-cy="panel-<Title>"`。Replications 是**表单节非路由**（子路由变体 /replication、/replications、/edit/replications 全 404）。

### 1.2 license 门形态（R2）— 活体实测，高置信

- 步禁用语义：class `jf-steps__item is-disabled`（文本 40% 透明 + `cursor:default` + 指示条灰 #f1f3f8）；**无 aria-disabled**；hover **无门文案 tooltip** 渲染；点击 **no-op**（URL 不变）。无障碍注记：禁用步对 AT 不可感知（aria 缺失）——BinFlow 实现时用 `aria-disabled` 更优（自有增强，不倒退）。
- REST 门：`GET /api/replications`、`/api/replications/{key}`、`/api/replication/configs` → 一律 **400** `"This REST API is available only in Artifactory Pro (see: jfrog.com/artifactory/features)…"`。
- 反差两枚：UI-API `GET /ui/api/v1/ui/global/replications/config` → **200** `{blockPullReplications:false,blockPushReplications:false}`（不受门）；本地仓表单模型 `GET /ui/api/v1/ui/admin/repositories/local/example-repo-local` → 200 携 `"replications":[]`（字段未被 license 剥除）。

### 1.3 表单字段集（R3）— **锚定降级 ①**：OSS 门后不可活体核验；bundle + 公开 REST 双源，中置信

- bundle Vuex 模型默认值（原文）：remote(pull) 仓 `{enabled:!1, cronExp:"", enableEventReplication:!1, pathPrefix:"", syncDeletes:!1, syncProperties:!1, syncStatistics:!1, type:"remote"}`；local(push) 仓 `replications:[]`（数组=multipush 多目标）。
- 票面七项对位：URL/仓对 ✚ 凭据（username/password，REST 文档面）、cron 表达式 ✚（cronExp，见 1.4）、启停 ✚（enabled）、**enabled 事件** ✚（enableEventReplication——cron 外的即时事件复制开关）、**enabled 无仓剔除** ✚（syncDeletes——删除同步）+ pathPrefix/syncProperties/syncStatistics 三枚补充。
- 表单面板本体（字段排布/分节/Test 按钮位）在 OSS 永不渲染（懒加载 chunk 因步禁用永不触发）——**形态层留白，未编造**。

### 1.4 cron 形态（R4）— 中高置信（bundle 实证；活体直连未复现成功）

- 服务端校验：`GET {api}/crontime?cron=<exp>&isReplication=<bool>`（validateCron/validateCronString 两入口，isReplication 区分复制语义）；帮助文案直链 **quartz-scheduler.org CronTrigger 2.3.0 教程**（= Quartz cron 格式）；校验失败 i18n `"The cron expression is invalid"` / `"Please enter a valid cron expression"`。
- **降级 ②**：crontime 端点活体直连 404（/api/system/crontime）与 401（UI-API 形态）——未复现 UI 调用上下文，**未验成功不升高置信**。

### 1.5 Replicate Now 动作形态（R5）— 列表列高置信（活体+bundle）；面板内按钮中置信

- 活体：本地仓列表列序 Repository Key/Type/Project/Environment/**Replications**/Shared With；Replications 表头 x=1224 w=140@1600；OSS 每行 cell = 纯文本 **「0」**。
- bundle 渲染器（chunk `Lifecycle~ReleaseBundlesListV2~repositories.js`）：启用态 cell = `a.icon-run.replication-column-button`（`id="repositories-local-replicate"`，24px，hover #43a047，disabled opacity .3）；el-tooltip 三态：全局封锁→"Push Replication Is Blocked"｜已启用→**"Run Replication"**｜未配置→"No Replication Configured"；点击 emit `execute-replications` → `POST {api}/admin/repositories/executereplicationnow?replicationUrl=<url>`（body=repoModel，响应 info→toast）。multipush 全量 `executeall`；remote 触发 `exeucteremotereplication`（官方路径原文拼写如此，照录）。

### 1.6 Test 动作（R6）— bundle，中置信

- `POST {api}/admin/repositories/testlocalreplication?replicationUrl=<url>`（body 携 replications:[cfg]）；remote 对位 `/admin/repositories/testremotereplication`。表单侧按钮形态 OSS 不可达（同降级 ①）。

### 1.7 列表/状态呈现（R7）— 中高置信

- 词表："Last Replication Status" 列标签；dashboard widget `{LABEL:"Replications", DESCRIPTION:"Monitor the status of active replications occurring across your multiple deployments and review historical replication runs."}`（MC 数据支撑，OSS 不渲染；活体 OSS 实际呈现仅列表「0」）。

### 1.8 全局封锁开关（R8）— 中高置信（UI-API 活体 200 + bundle）

- `blockPushReplications`/`blockPullReplications` 为 **General Settings 表单字段族成员**（与 fileUploadMaxSize/folderDownload*/globalOfflineMode 同页）；tooltip："When set, push/pull replication will not be triggered regardless of configuration."；GET/PUT `global/replications/config`。

### 1.9 面板容器形态（R9/R10）— 活体高置信

- 复制配置 = **整页路由表单内嵌步骤节**（无 modal/drawer、无独立路由）；push 模型 = 源仓→目标 URL+目标仓对（multipush 数组）；pull = remote 仓属性单元素。
