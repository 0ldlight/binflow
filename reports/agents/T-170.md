## 上游发现（阻塞 S3 端到端，均不在本票 area）

烟测实证两处缺口，S3 blob 端到端（制品落 MinIO）当前不可达：

1. **`internal/httpapi/system.go` probeS3Storage（约 :155）`Secure: true` 写死**：minio-go 对带 `http://` scheme 的端点直接报 `Endpoint url scheme "http" conflicts with the secure option`——任何 MinIO/http 端点下 `/readyz` 永远 503、容器永远 unhealthy（compose 健康门即卡在此）。修复应按 endpoint scheme 推断 Secure。属 dev-go-core 区。
2. **`cmd/binflow-server` 启动装配未按 `storage.backend` 选引擎**：`storage.OpenEngine(cfg.Storage.DataDir, ...)` 只走磁盘路径（实测 backend=s3 时 blob 落 `/var/lib/binflow/blobs/` 而 MinIO 桶为空）。internal/storage 的 S3 引擎与迁移代码在盘但未接线。属 dev-go-core 区。

另：本地缓存的 `binflow:v1.0.0-alpine` 镜像是 S3 config 接线前的旧构建，带 S3 env 启动会 unknown-env fail-fast——已在 compose 头部注明首跑加 `--build`。

小观察：rejectSecrets 拒绝 `storage.s3.secret_access_key` 时错误文案提示的逃生口是 `BINFLOW_ADMIN_PASSWORD`（secretYAMLErr 单一文案），指向略误导，建议顺手改为按路径给对应 env 名。
