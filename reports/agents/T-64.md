## 做了什么

### ① FR-15-AC1~AC4/AC7 — 三型模型与配置校验（internal/repo）

- **类型矩阵放开**（validate.go）：local/remote/virtual × {generic,docker,maven,npm,pypi}，唯二拒绝 = remote+docker / virtual+docker → `ErrRepoTypeNotSupported`，message 改为 **"not supported in M3 (docker is local-only; PRD Q4)"**（FR-15-AC7 定案口径）。新增常量 `PackageMaven/PackageNpm/PackagePypi`（api.go）。
- **config.go（新文件）**：按 rclass 的 typed 配置模型。
  - remote：`url`（必填，**建仓只校验 scheme ∈ {http,https} + host**，尾斜杠裁剪；私网/环回 URL 建仓成功——NFR-S13/ADR-0012 勘误⑤）/`username`/`password`（**输入接受、永不持久**——canonical JSON 无此字段，remote_configs 行恒空串，防明文窗口，T-66 落地加密链）/`retrievalCachePeriodSecs` 7200/`missedRetrievalCachePeriodSecs` 1800/`socketTimeoutSecs` 15/`assumedOfflinePeriodSecs` 300/`hardFail` false/`allowPrivateUpstream` false/`priorityResolution` false（显式 0 = 缺省；负值 400；未知字段**丢弃不拒**——PRD 场景 D 迁移脚本兼容）。
  - virtual：`repositories`（必填非空）/`defaultDeploymentRepo` + 别名 `defaultDeploymentRepoRef`/`deploymentRepository` **并收**（一致取值、冲突 400）。
  - local：维持 M1 passthrough（`{"x":1}` 原样），仅对跨界字段 `priorityResolution` 做 bool 类型校验（T-71 两桶序的成员标记，local/remote 均可携带）。
- **CreateRepo 分型落地**（service.go）：全部校验先于首写（拒绝零残留）；`repositories` 行落地后写 **remote_configs 行**（url/username/Password=""/**ContentTTL=7200 产品默认**（DDL 86400 仅 schema 兜底——003 迁移注释钦定 T-64 落值）/MetadataTTL=600/allowPrivateUpstream）或 **virtual_members**（SetMembers，position=声明序）。审计 detail：remote 建仓恒带 `"allowPrivateUpstream":<bool>`（NFR-S14 ⑤）。
- **validateVirtualMembers**（service.go）：成员存在 / 禁嵌套 virtual（PRD §2.2 有意不兼容）/ 禁重复 / 禁自引用（update 路径可达）/ defaultDeploymentRepo 必须为**成员中的 local 仓**（指向非 local 或非成员 → 400）。
- **UpdateRepo 分型**：提供 config = 全量替换（Artifactory PUT 语义）——remote 走 UpdateConfig（**行丢失（建仓 crash 窗口）回落 CreateConfig 自愈**）、virtual 走 SetMembers 原子换表；无 config 仅改 description 时**不碰**配置行/成员表。allowPrivateUpstream 翻转审计 `"allowPrivateUpstream":{"from":false,"to":true}`。
- **GET 掩码**（NFR-S14）：canonical 形态构造性不含 password；GetRepo/ListReposFiltered 对 remote 行再过 `maskRemoteConfig`（读取边界防御——直接注入 DB 的 password 也不回显，测试覆盖）。
- **ListReposFiltered**（新接口方法，M04/FR-15-AC5）：type/packageType 精确匹配，"" = 不过滤，**非法值 → 空数组不报错**（rest-api.md §2 定案）；ListRepos = 无过滤特例。**httpapi 查询参数接线是遗留项（见下）**。
- **DeleteRepo**（FR-15-AC6）：remote 仓删除时显式 `DeleteCacheByRepo`（缓存为派生态：两条路径都清、不阻塞删除、计数入审计 `"removedCacheRows":N`）；remote_configs/virtual_members 依赖 FK 级联（T-62 契约）。

### ③ PutLandedBlob 用例 + docker finalize 切换（§11.13 收口）

- **api.go**：Service 接口新增 `PutLandedBlob(ctx, p, repoKey, path, ref, mime)`（PutFromBlob 的"创建台账行"变体，契约注释写明与 PutFromBlob 的差异——不要求台账行预存在、ref 应携带会话三摘要、O(1) Open 存在性/尺寸探针、绝不重读字节）。权限对/覆盖/幂等重传语义与 Put 完全一致。
- **service.go**：实现 + 抽取 `authorizeContentPut`（Put/PutFromBlob/PutLandedBlob 三处共用的权限对——防安全相关门序漂移）；audit detail 带 `"landedBlob":true`。物理 blob 缺失 → 普通 error（**不映射 ErrNodeNotFound**，内部不一致不是客户端可寻址 404）。
- **adapter/docker/uploads.go**：`registerBlobNode` 从「store.Open 回读流喂 svc.Put（O(size) 重读+二次摘要）」切换为直接 `svc.PutLandedBlob(...)`；注释块重写（§11.13 债务收口说明 + B4 失败语义保留）。
- **性能收口钉板**：`TestPutLandedBlobNeverReadsTheBytes`——failReadEngine 使已提交 blob 不可读但 Open 的 ref（size）保真：PutLandedBlob 成功；对照：旧回读 workaround（同引擎 Open 后喂 Put）在同一引擎上必然失败。**对比测试即债务可视化**。
