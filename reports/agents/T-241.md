### 1.2 编辑器分区（§6.11 线框逐区块）

- **[1] 目标信息**：名称（编辑态锁定，`perm-form-name`）+ 适用仓库 chips（✕ 即摘，冻结锚
  `perm-repo-remove-<key>`）+「添加仓库…（新建态）/ 编辑仓库…（编辑态）」按钮——冻结锚
  `perm-repo-add` 自本票起承载**两步资源对话框的入口**（语义不变：加仓库走它；reverse §3.8
  新建态为 Add Repositories）。
- **两步资源对话框**（§3.3 C6 / §4.5，对齐 reverse §3.8 Edit Repositories）：
  - ① 选择仓库：双列穿梭（复用 T-237 TransferBox，条目锚 `perm-repo-pick-<key>`）；
    **Any Local / Any Remote 通配桶不建**——BinFlow 契约 repos[] 必须逐个指名现存仓库
    （permissions.go 对 unknown repository 400，无 `**` 约定；§4.5「仅当契约支持时渲染，
    否则列实体仓」的后者分支），对话框内 admin-note 明示。
  - ② 设置模式（可选）：include/exclude 逐行 chip 编辑——**T-101 冻结锚原样迁入**
    （`perm-pattern-{chip,input,add,remove}-{include|exclude}[-<i>]`）。
  - 步进件：步骤号 + 步骤标题（`perm-res-step`）；取消/下一步/上一步/确定
    （`perm-res-{cancel,next,back,ok}`）；焦点圈进 + Tab 循环 + Esc = 取消不回填
    （ConfirmDialog 同款陷阱）；确定 一次性回填 repos+patterns（draft 语义，取消零副作用）。
- **[2] 路径模式**：只读摘要行（`perm-patterns-summary`，include/exclude chips + 计数 +
  「在对话框第 2 步修改」指引）+ **模式测试器**（灵魂件原样保留：逐条命中明细 + exclude
  优先最终判定；`perm-pattern-{test,result,verdict}`；pathmatch.ts 现役引擎本地求值——
  与 internal/auth 同源，fixtures/parity 双闸不动，零端点零后端耦合）。
- **[3] 用户区块 / [4] 组区块（展开矩阵形态）**：各表各锚（用户表 = 冻结锚 `perm-matrix`；
  组表 = 新锚 `perm-matrix-groups`——rbac V14 的「`perm-matrix` th manage 恰 1」断言不被
  双表破坏）；动作四列 read/write/delete/manage（**M7 语义保留**：manage 第 4 列、矩阵头
  tooltip「不隐含读写删」、wire 全词形、回显 r/w/d/m 序，T-217 后端定案）；区块各配
  添加位（`perm-add-user` / `perm-add-group` 冻结锚）与行摘除
  （`perm-matrix-remove-{user|group}-<name>`）。
- **保存链**：diff 确认（`perm-diff`，+ 授予 / − 撤销逐条）→ POST create-or-replace →
  toast → 回列表；必填门（名称/≥1 仓库/有变更）主按钮禁用；危险区删除
  （`perm-danger-zone` / `perm-delete-button`）与 readonly 全禁用态原样。

### 1.3 覆盖集语义呈现（任务项 4，T-217 B1 / §7.2/§7.10）

- **UI 不自行判定覆盖集**（§7.10 铁律）——三条呈现面全部服务端事实驱动：
  1. 保存/删除的 403 服务端原文行内/toast 如实呈现（`form-error` 既有形态保留）；
  2. 普通 user（潜在 m-holder）直链列表/编辑器 → L2 无权限卡 + **边界说明**：控制台编辑器
     需要 security:read（列表与主体枚举是管理面读端点）；manage 持有者仍可经 API 在
     manage 覆盖集内维护 target（覆盖集外 403）；
  3. 编辑器组区块 admin-note 载明 B1 语义：manage 持有者经 API 编辑 target 时，服务端要求
     其引用的全部仓库（**含替换前的存量**，union(body, 存量) ⊆ 覆盖集）落在覆盖集内。
- **e2e 实证**（§4 腿 3）：m-holder 覆盖集内 POST 201 / body 侧出界 403（'manage coverage'
  原文）/ **B1 替换臂**（body 集内但同名存量在集外 → 403 + 存量清单字节不变）/ 删除同门
  （集内 204 / 集外 403）/ 读面 403 + 双页 L2 边界文案。任务面写「覆盖集内 200」——wire
  事实是 POST 建/替换均 201（handlePermissionCreate 恒 StatusCreated），断言按 201。

### 1.4 对话框 color-contrast 修复（复工首件，conductor 指定）
