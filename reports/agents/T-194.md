## 做了什么（对照 AC）

### AC① ldap 块补 `skip_tls_verify` / `group_base_dn`

`charts/binflow/templates/configmap.yaml` auth.ldap 块（+9 行）：

- `group_base_dn`：可选字符串，空 = 服务端回落 `base_dn`（PRD FR-55）。**非空才渲染**
  （`{{- if .Values.config.ldap.groupBaseDn }}`），写法逐字对齐 `bind_dn`/`group_filter`
  等现有可选字符串键模式；插入位置对齐 load.go 字段序（group_filter 与 group_name_attr 之间）。
- `skip_tls_verify`：可选布尔，默认 false。**无条件显式渲染**（对齐 `start_tls`/`pool_size`
  现有模式），理由：T-183 教训——键静默缺席会被读成静默默认；该键是安全姿态键（评估专用、
  启动打 WARN），显式渲染 `skip_tls_verify: false` 让证书校验姿态在渲染出的 ConfigMap 里
  直接可审计。模板内注释说明 T-186/T-194 来历与 WARN 语义。

### AC② oidc 块逐键核对（internal/config/api.go + load.go）

`load.go` raw schema `auth.oidc` 共 8 个 YAML 键：`enabled`/`issuer_url`/`client_id`/
`redirect_url`/`scopes`/`user_claim`/`group_claim`/`admin_group` —— chart **已全部渲染**
（T-183 修 `enabled` 后再无缺口）；`OIDCConfig.ClientSecret` 是 env-only 设计键
（BINFLOW_AUTH_OIDC_CLIENT_SECRET），按 ADR-0009 永不入 YAML，chart 侧走
`config.oidc.existingSecret`，正确。**OIDC 无需补键**。
ldap 侧补齐后 13/13 全渲染（`bind_password` env-only 同理不入）。

### values.yaml / values.schema.json 同步

- `charts/binflow/values.yaml` ldap 块补 `groupBaseDn: ""`、`skipTlsVerify: false`
  （各带 `# --` 注释，写法沿现有键；注释说明缺省语义与"仅评估"约束）。
- `charts/binflow/values.schema.json` ldap properties 补两键类型声明
  （string / boolean），schema 与 values 锁步（lint 会按 schema 校验）。
