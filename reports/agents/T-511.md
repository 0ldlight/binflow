## 1. 做了什么

### 1.1 三入口查询绿（AC1）

**字段注册表（internal/search/fields.go）**：

- 新 Domain 常量：`DomainBuild`/`DomainModule`/`DomainDependency`（实体域，入口拼写为复数 builds/modules/dependencies）。
- **入口内注册表** `buildFieldRegistry`（entry→wire name→Field）：wire 名与 item 域刻意撞名（"name" 在 builds.find 里解析为 builds.name），解析按入口域路由（parser.`lookup`）。
- 字段集**逐字冻结 §15.1**：
  - builds：url/name/number/started/repo/created/created_by/modified/modified_by 九默认输出 + ◆id（internal, unsupported）；
  - modules：name（默认）+ ◆id；
  - dependencies：name/scope/type（默认）+ sha1/md5（include-only）+ ◆id。
- 默认/star 输出集按 §15.1 表序冻结（`buildDefaultOutput`/`buildStarOutput`）。
- **builds.url 裁定**：BinFlow builds 表无 url 列（CI URL 在 payload 归档文档）→ 注册为 output-only（include 可用、criteria/sort 拒绝「output-only」），渲染时从 payload JSON 提取——virtual_repos 先例，不造数据。
- builds.modified_by 与 item 域不同：**有源**（builds.updated_by 列），完整 criteria/include/sort 支持。

**parser（internal/search/parser.go）**：

- 入口分发：items + 三 build 入口放行；其余走 unsupportedDomains（支持清单文案更新为四入口）。
- 域名点段预读：`build.promotions.find` 等两段入口域名在拒绝文案里具名（build.find 的 "find" 非段）。
- build 入口内：@key 属性臂拒绝（property 子域入口 M17 维持关闭，§15.3）、未知字段/内 id 诚实拒绝、include 覆盖默认集、sort 必须 result field（isResultField 按入口默认集泛化）。
- $msp 在 build 入口自然拒绝（property-scoped 校验）。

**规划与求值（internal/search/buildplan.go，新）**：

- `BuildSearcher` 消费侧缝（Runs/Modules/CanReadBuild）——T-507 边界：build 不 import search；装配在 httpapi。
- `BuildRow` 统一行模型（run 坐标 + 入口自有成员 + 自然序 tiebreak）。
- `PlanBuildQuery`：AST → 闭包谓词树 + 投影 echo（OutputField 复用）+ sort/window。
- 谓词语义与 item planner 镜像：字符串六序比较（字节序 = SQLite BINARY collation）、$match/$nmatch 走 match.go **单内核新 Go 侧执行器** `MatchesPattern`（'*'任意串'?'单字节、整值匹配——SQL LIKE 语义的 Go 半边，防三译者）；日期走 `resolveDateLiteral`（部分精度区间边界同 dateArm）+ `$last/$before`（periodBoundary 单位表与 periodArm 逐字同源）；**不可解析日期行值 = 一切比较 false**（SQL NULL 行规则，julianday 对位）。
- `ParseBuildInstant` 导出（时间布局单点：RFC3339 / Java-canonical 毫秒 / 无毫秒三布局）——renderer 与排序共用。

**引擎（internal/search/engine.go）**：

- `EngineOptions.Builds BuildSearcher`；nil → `ErrBuildSearchUnavailable`（诚实 503 类，items 不受影响）。
- Run 分发：build 入口 → `runBounded`（runAST 重构出的共享段：**同一 K63 门**（4 并发→429）、同一 QRL、同一 10s deadline、同一 1000 行 cap——零豁免）。
- `executeBuild`：plan → searcher 全量枚举 → 谓词过滤 → **行级 ACL 织入**（CanReadBuild 按 (buildRepo, buildName)，**每 run 一次 memoize**——百依赖 build 只求值一次）→ created_by/modified_by 非 admin 脱敏（unknown）→ 排序（稳定，自然序 tiebreak）→ offset/limit 窗口 + cap 截断。
- Result 增 `EntryDomain` + `BuildRows`（items 行不混型；Plan 只填投影/窗口 echo）。

### 1.2 两老搜索端点（AC1）

**internal/httpapi/search_build.go（新）** + router 两路由 + server.go 装配：

- **BuildSearcher 适配器**（httpapi = 装配层）：枚举走 BuildStore 已发布面（ListBuildNames → 去重名 → ListBuildNumbers(name,"") 跨 build repo → 逐 run GetBuild/ListModules；url 从 payload 提取）；CanReadBuild = build.Service.CanRead（同一 allow() 镜像）。server.go 在引擎装配处注入（s.builds 在场即织入）。
- **POST /api/search/buildArtifacts**（§15.4 逐字文案，含「your」拼写照抄）：
  - 三 400：缺名 / 号状态双缺 / 双给（`Cannot search without …` 三条 verbatim）。
  - 门：先 r(DefaultBuildRepo, name)（403 无存在性 oracle）→ 解析 run（number 臂：具体号=最新 run；**LATEST 哨兵**=全名最新 run；status 臂=最新现势 promotion 状态匹配的 run）→ ListModules 取**已关联制品**（RepoKey≠""）→ repos[] 过滤 → **制品仓 ACL**（repo.CanRead——地址即数据，不泄漏不可读 URI）→ mappings[] 首配重写（Go regexp，$1 组 token）→ `{"results":[{"downloadUri":…}]}`（downloadURI=直连内容地址）；空 → 404 `Could not find any build artifacts for build '<name>'[ number '<n>'| status '<s>']`（number 臂回显请求号含 LATEST）。
  - body 上限 1MB；ResultCap + 截断头。
- **GET /api/search/dependency**：sha1/sha256 至少一（40/64 hex 校验，非法 400）；buildRepo 缺省 DefaultBuildRepo（preferred-build-info 解析）；project 参数接受且忽略（单项目姿态）；枚举 build repo 内 runs → 依赖 checksum 命中 → 按 (name, number) 去重（最新 run 优先）→ uri = `<base>/binflow/api/build/<name>/<number>`（build API 形态，段级 PathEscape）；**空集 = 200 results:[]**（家族主导臂裁定，见 §4 低置信登记）；ResultCap。
