效力序与纪律基线：以活体差分为模型权威（A=Artifactory **7.161.26** Enterprise+ @192.168.120.38:8082，L041 双轮 + 本票 T-600 双轮共四轮实证）；本票补证两腿四态全 PASS、双轮 drift=0；未探面不猜（clean-room），各修复面均显式列出「未探面=票内探腿」。

## 1. `rest/repo-config-put-ct-strictness` — 建议：BUG，对齐实现（三臂分解；影响面 rationale 修订）

### ① A 模型终形（L041 Arm 4 + T-600 p2-* 补证）

| 臂 | A 形（双轮×2） | B 形（双轮×2） |
|---|---|---|
| PUT 无 CT | 415 errors `Unsupported Media Type`（L041 r4 + p2-put-noct-missing-ctrl 复锚） | 200 建仓 |
| PUT `application/json;charset=UTF-8` | **400 errors `Unsupported repository type 'local' or media type 'application/json;charset=UTF-8'`（T-600 新钉：第三形态；rclass 取自 body，CT 串逐字内插）** | 200 建仓 |
| POST 无 CT / text-plain / xml / vnd.api+json | 415 `Unsupported Media Type`（L041 r4-*） | 200 |
| POST charset → **已存在** key | 404 `No repository <k> was found.`（**无引号**变体，L041 + p2-post-charset-existing-ctrl 复锚） | 200 更新成功 |
| POST charset → **缺失** key | **404 `No repository '<k>' was found.`（带引号——T-600 新钉：no-quote 变体系「存在仓+charset」专属，缺失 key 恒带引号）** | 404 `Repository does not exist: repo "<k>": repository not found` |
| 精确 `application/json` 控制腿 | 200（双端同，建/改同形） | 200 |

**模型定性升级**：该面不是孤立的 CT 严格度，而是 A 已记载的 **Content-Type 协商族**（rest-api.md:151 GET 面以 CT（非 Accept）做类型协商 → 406；:175 批改面 vendor CT 过滤 → 404）在**写面的同族臂**——charset 参数把请求送进 vendor 协商路径（存在仓→查不到→404 no-quote；缺失仓→通用路径→404 带引号），PUT 面 charset→模型协商失败→400 type/media refusal（**B 已有同族写手逐字**：handleRepoPut distribution 臂 `Unsupported repository type 'distribution' or media type 'application/json'`，repositories.go:733）。

### ② 裁定：BUG，全臂对齐。影响面 rationale 修订

原 rationale「真实客户端恒带 CT，影响面低」**只对 415 臂成立，对 charset 臂方向性错误**：Spring RestTemplate / 部分 OkHttp 封装 / Jenkins Artifactory 插件等 Java 系客户端**默认发送 `application/json;charset=UTF-8`**——该种群对 A 的 POST update 恒 404、PUT create 恒 400（操作**失败**），对 B 却 200 成功。这不是「错误文案分歧」而是**成败本身分歧 + 状态分歧**（B 会建出 A 拒建的仓、改出 A 拒改的配置）——超集方向但组织先例一致裁对齐（nuget/xsha 自加头、GET 自加头同向先例）。B 零 CT 检查同时是信任边界输入校验缺席。

### ③ 修复面分解（全部 internal/httpapi/repositories.go 单文件，handler 层）

1. **415 门**（PUT+POST）：CT 缺席或 media type ≠ application/json → 415 errors `Unsupported Media Type`。注意 charset 参数**不是** 415（A 模型）。
2. **PUT charset 臂**：CT=application/json 带参数 → 复用 :733 distribution 写手模式，插值 body rclass + CT 全串 → 400。
3. **POST charset 臂**：存在 key → 404 无引号 `No repository <k> was found.`；缺失 key → 404 带引号（与条目二 POST 臂共享写手）。
4. **未探面=票内探腿**：PUT+text-plain/xml/vnd.api+json（A 形未探，探得才实现）；PUT charset+body rclass=remote 的插值复核腿；GET 面同族 406 协商（rest-api.md:151 已规格化、B 现状未核）**不入本票**（独立面，防票面膨胀）。

**测试翻新**：B 侧依赖「无 CT 也成功」的既有测试（repo config 写面族测试须补 CT 头或改断言）；console 前端回归腿（web/src/lib 若裸 fetch 带 CT 则零影响，修复票带一条 console smoke 断言）。

### ① A 模型（L041 Arm 3 + T-600 复锚）
