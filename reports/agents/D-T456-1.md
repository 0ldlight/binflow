- 角色: dev-go-core · area: `internal/httpapi`（wire 面）

## Root cause

`internal/httpapi/repositories.go` 的传输结构 `repoConfig` **从未携带** `listRemoteFolderItems` 字段
（T-448 落地了 service 层 `remoteConfigInput.ListRemoteFolderItems *bool` 与 canonical
`remoteConfig.ListRemoteFolderItems bool`，但 wire 面漏了）：

1. **PUT 静默吞**：PUT/POST `/binflow/api/repositories/{key}` 请求体经
   `json.Decoder.Decode(&repoConfig)` 解码——`listRemoteFolderItems` 是未知字段，被静默丢弃；
   `configJSON("remote")` 渲染的 config map 不含该键 → `parseRemoteConfig` 读到
   `in.ListRemoteFolderItems == nil` → canonical 恒 false → 字段不落库。
2. **类型门 400 不可达**：同一原因——字段不参与 typed decode，mistyped 值
   （`"yes"` / `1` / `[]`）同样被静默吞，永远到不了「400 + 字段名」的诊断路径。

GET 侧无需改动：canonical `remoteConfig.ListRemoteFolderItems` 无 `omitempty`（恒在场，
hardFail 同姿势），经 `repoConfigOf` 的 `configuration` map 原样透出——字段一旦落库即回显。

## 设计要点

- **值域门不下沉 wire**：`true` 仅 batch-1（helm/debian/rpm）的 by-name 400 保持在
  `parseRemoteConfig`（chartsBaseUrl 姿势——单一门，无 wire 侧镜像漂移）；测试只验证它
  穿过 REST 面可见。
- **测试 fixture**：helm/debian/rpm 是 addon slot（静态枚举只有 generic/docker/maven/npm/pypi）。
  测试用 `repo.AttachPackageTypeGate(h.svc, fakeGate)` 解锁三类型（repo 层 t448Env 同姿势）；
  handler 侧 `deps.Addons == nil` 时 `checkAddonPackageType` 直接放行，无需挂 addons.Registry。
- **对 T-461（FE）的契约输出**：flip 开关须发全量 remote config（full-replace PUT 模型，
  flag-only 更新会被 `url is required` 400 拒——既有语义，非本票引入）；读面走
  `GET configuration.listRemoteFolderItems`（布尔恒在场）。
