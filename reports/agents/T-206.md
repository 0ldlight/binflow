# T-206 — 修复 T-203 D-6 启动 sweep 在未建 bucket 冷启动态硬失败

- **优先级**: P1（阻断全仓统一复跑；会导致全新 S3 部署首启失败）
- **角色**: conductor（主会话直接修复）
- **状态**: done
- **area**: `internal/storage`（s3.go / s3_test.go）

## 现象

全仓统一复跑 `go test -race -count=1 ./...` 暴露 `cmd/binflow-server` 6 个测试失败：

```
s3_stack_test.go:455: openStack(backend=s3): opening s3 engine: sweep orphan uploads in binflow:
    storage: s3: open: sweep orphan uploads: storage: s3: list multipart uploads:
    The specified bucket does not exist.
```

涉及 `TestOpenStackS3BackendUploadsToBucket` / `TestOpenStackMigrationDualWrite` /
`TestOpenStackMigrationCompletedS3Only` / `TestExportS3StreamsBlobsFromEngine` /
`TestExportS3DanglingReference` / `TestExportImportS3Roundtrip`。

## 根因

T-203 D-6 落地了「启动时回收孤儿 multipart upload」`sweepOrphanUploads`，并在
`OpenS3Engine` 内无条件执行 `listIncompleteUploads → ListMultipartUploads`。当目标
bucket 尚未创建（全新部署首启 / 测试冷启动）时，S3 兼容存储返回 `NoSuchBucket`，
链路未区分「bucket 不存在」与「真正的列举错误」，导致 `OpenS3Engine` 整体失败。

T-203 的定向测试都预置了 bucket，因此漏掉了冷启动路径。

## 修复

`internal/storage/s3.go` `listIncompleteUploads`：`ListMultipartUploads` 返回
`NoSuchBucket`（或空 code + 404）时按「空清单」处理（无可回收孤儿），不再向上抛错：

```go
if err != nil {
    // A missing bucket is a benign cold-start state: there is nothing to
    // sweep. S3-compatible stores report it as NoSuchBucket (some also an
    // empty code with a 404 status), so treat both as an empty listing.
    if resp := minio.ToErrorResponse(err); resp.Code == "NoSuchBucket" ||
        (resp.Code == "" && resp.StatusCode == 404) {
        return nil, nil
    }
    return nil, fmt.Errorf("storage: s3: list multipart uploads: %w", err)
}
```

## 回归测试

新增 `TestS3StartupSweepToleratesMissingBucket`：mock flag
`listMultipartNoSuchBucket` 令 `handleListMultipartUploads` 返回 NoSuchBucket，
断言 `OpenS3EngineWithClient` 仍成功返回 engine（修复前会失败）。
