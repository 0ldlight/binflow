## 做了什么

### 1. 三缝织入（architecture §15.1.5 伪代码 + ADR-0032 D1~D7）

**缝 1 数据面写（`internal/httpapi/license_gate.go` + `router.go`）**
- `gateAddonWrite`：插在 `dispatchContent` inner 的 repo 行查询之后、adapter 分发之前，
  仅 `required`（= `contentAction` 的写标志，复用零新判定）为真时求值；slot =
  `Addons.ForPackageType(row.PackageType)`，求值 = `s.addonsEval.AddonEnabled`（与
  /api/v1/addons 可见面同一求值源——可见性与执行不可能分叉）。
- 读动词不过门（D1）；**内部写豁免实战验证**：挂载的 fake go adapter 的 GET 臂在
  miss 时经 `svc.Put` 落盘（pull-through 缩微），在门 DENIED 状态下照常成功
  （`TestT283ContentGateD1D2`）；repo.Service 全部内容路径零 license 调用
  （`TestT283ServiceWritesBypassGate`）——architect 风险 1 的两面都钉死。
- `/v2` 根级例外臂（`gateV2Write`）：docker slot 的写动词（POST/PATCH/PUT/DELETE，
  覆盖 upload 三步族）在 /v2 dispatch 处过门——旁路即无门的反面教材位；
  `/v2/token` 是认证面不过门；读全过。
- D2 拒绝形：403 errors[] 信封 `license required: addon 'go' needs tier 'pro'
  (current: none)` + 头 `X-Binflow-License-Required: go`；allowlist 收窄形有自己的
  措辞（不谎报「差档位」）；disabled 熔断形点名旋钮与恢复路径且**不**带该头
  （装 license 救不了 config 熔断，头名不得说谎）。

**缝 2 建仓/改仓/删仓（`internal/repo` D3）**
- 消费侧接口 `repo.PackageTypeGate{Verdict(ctx, pt) → {Known, Unlocked, Refusal}}` +
  `repo.AttachPackageTypeGate`（AttachReplicator 先例，`New` 签名零变动）；cmd 用
  `packageTypeGate{reg, ev}` 适配（addons.Registry.StatusOf + license.Manager——两个
  协作者只在装配点相遇，repo 不 import license/addons）。
- **静态枚举扩 dynamic（T-282 遗留②）**：`validateRepoTypeDyn`——gate 已接且
  registry-known 的包型合法（go/nuget/cargo 可建仓，三 class 全开）；静态五型保留
  M3 class 裁定（docker 仍 local-only）；unknown 仍走静态枚举 400；gate=nil 逐字节
  M9。Create/Update/Delete 三面 + virtual 成员面（FR-85.1④：locked 成员拒绝建/改
  virtual）都过门；删仓同拒（票面裁定，PRD 85.3「仓配置零删除」的字面）。
- 新哨兵 `ErrPackageTypeNotAvailable` → httpapi 400（ADR D3 形，PRD↔ADR 的 403/400
  分歧维持 ADR 侧，等 T-293/K25 终裁）。

**缝 3 feature addon（`Server.RequireAddon`）**
- 导出的 handler 首行门（§15.1.5 草图原样）：`RequireAddon(w, r, id, minTier) bool`，
  拒绝形与缝 1 同一 `denyAddon` 单点（D4=D2 形）。M10 仅 seam：properties 缝归
  T-286，ha/xray 本体 M11+；`TestT283RequireAddonSeam` 表驱动（floor 拒 / enterprise
  通 / pro 不通 enterprise 槽）。

### 2. addons.disabled 键接线（`internal/config` + cmd）
- `addons.disabled`（CSV 标量，env `BINFLOW_ADDONS__DISABLED`）→ `cfg.Addons.Disabled`
  → `license.Options.DisabledCSV`（T-279 已消费）；严格 schema（未知子键/列表形拒绝）。
- disabled 形态 BOOTFAIL 基线翻活：矩阵六格 BOOTFAIL→实姿态（npm=400 / generic=200 /
  gated=400）。

### 3. 审计/指标
- 审计 `license.addon.denied`（词表常量在 repo/api.go——缝 2 与 httpapi 缝 1 共用一
  个拼写）：缝 1 行 {addon, tier, need} + Repo/Path/Actor；缝 2 行 {addon, refusal}。
  注：PRD 85.4 写的是 `addon.gate.deny`、票面写 `license.addon.denied`——按票面落，
  分歧登记。词表进 audit.Actions() picker 仍是 audit owner 的一句话（T-279 遗留同款）。
- 指标三件（`internal/httpapi/metrics.go`）：`binflow_license_tier`（gauge，闭集序数
  0/1/2，scrape 时刷新）、`binflow_addon_gate_requests_total{addon,decision}`（counter，
  allow/deny，缝 1+缝 3 计数；缝 2 是 400 校验拒绝归审计不归此计数——HELP 注明）、
  `binflow_addons_enabled{addon}`（gauge 0/1，与 /api/v1/addons 同源求值）。
  registry 未挂则 family 不暴露（replTasks 先例）。

### 4. 无撕裂（NFR ≤1s）
- Manager atomic 快照消费：`TestT283NoTearingUnderFlips`——12 goroutine 持续写
  gated 仓 + license 装/卸 ×10：228 个应答全部 ∈ {200,403}（无 5xx/无中间态），
  装/卸 REST 返回后下一请求即翻转（计时 <1s 断言）。
