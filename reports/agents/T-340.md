## 1. 根因（先复现后动刀）

D-F 报告口径「`_/_` 坐标删树成功但回 404」。逐形态复现结论：**单 pid 批量两形态本就 200**（v2 落盘与 v1 通道落盘均验证）；真正机制是**批量语义**——`servePackagesDeleteIDs` 循环内任一 pid 在 latest rRev 下无树（conan 2 多二进制/旧修订残留的自然形态）时，`svc.Delete` 回 `ErrNodeNotFound`，整体渲染 404「Path not found」，而先到的 pid 树已删＝「删树成功但回 404」。修复前复现（单测，工作树改动前运行）：

```
POST /v1/conans/hello/1.0/_/_/packages/delete  {"package_ids":[<live>,<stale>]}
→ (404, "Path not found")；随后 GET …/revisions/<rev>/packages/<live>/revisions → 404 Couldn't find revisions（树已删）
```

规格核对（docs/reverse/conan.md §3.2）：recipe DELETE 行错误列为「200 / 404」，而 `packages/delete` 行**只有 200、无 404 臂**。参考实现取证（conan 1.66 OSS 客户端 wheel 内置 server，conans/server/rest/controller/v1/delete.py + service/common/common.py）：`remove_packages` 对每个 pid 走存储删除，**缺失路径静默无操作、恒回 200 空 body**；且参考实现跨全部 rRev 删（BinFlow v1 面按既定 latest 解析模型不动，本票只修结果码）。

## 2. 修复

`internal/adapter/conan/v1.go` `servePackagesDeleteIDs`：per-pid 的 `ErrNodeNotFound` → `continue`（幂等批量）；保留 ①未知 ref（resolveRRev 失败）404「Path not found」②非法 pid 400 ③其余错误透传。成功恒 200 空 body（规格 wire 形态）。
