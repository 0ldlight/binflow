## 2. 票面条款④执行实录——BOARD 降级语义在 v7 失效与替代方案

`npm install` 后 `npx eslint .`：**37 errors**（set-state-in-effect 25 / refs 8 / immutability 2 / purity 1 / preserve-manual-memoization 1，横跨 21 文件）> 30 预算 → 按票面降级。**但实测 v7.1.1 只有两个 flat tier 且都全量启用 compiler 派生规则**：

```
configs.flat 键 = ['recommended-latest', 'recommended']
recommended(16 rules) 与 recommended-latest(17) 的差集 = 仅 react-hooks/void-use-memo
set-state-in-effect 在 recommended 里同为 "error"
```

即「降级 `configs.flat.recommended`」在 v6 语义下是回到经典两规则，在 v7 是**同一套 compiler 规则原样**（BOARD 该条款写于 v6 语义，v7 已失效）。逐条审视 12 处非 set-state-in-effect 违规：全部是**有意为之的 escape-hatch 模式**——AuthContext 的 render 期 latest-value ref 镜像（行内注释记载它修的 401 并发重复 toast 竞态，review B1）、MUI `anchorEl={ref.current}`、非受控 `holder` 逃逸、回调内 `window.innerWidth` 读取。在「行为零变化预期」的纯工具链票里重写这些 = 正是 >30 条款要防的 churn。

**替代执行**（保持票面意图：lint 绿 + compiler 规则上线 + 欠账可见）：
- 主 tier 用 `recommended-latest`（票面首选目标）；
- 命中存量代码的 5 条降 `warn`（CI 的 `npm run lint` = 裸 `eslint .`，warning 不败门）——每条 warning 都是可见的清理欠账（ratchet）；
- **10 条零违规的 compiler 规则**（set-state-in-render / use-memo / void-use-memo / static-components / error-boundaries / incompatible-library / globals / unsupported-syntax / config / gating）+ 经典两规则（rules-of-hooks / exhaustive-deps）全部 `error` 当日生效——较 v5 实为净增强。

结果：`npx eslint .` → **0 errors / 37 warnings / exit 0**。
（ratchet 欠账的清偿应另立行为敏感清理票：镜像/锚点模式的时序语义改动不属于工具链票。）
