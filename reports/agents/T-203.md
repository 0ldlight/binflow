# 工作日志 T-203 — S3 blob-created-at 元数据保真 + 孤儿 MPU 启动回收

- role: dev-go-storage
- 日期: 2026-08-22
- 票据: T-203 [P2]（BOARD 只读引用；来源 T-173 QA 报告 D-5/D-6）
- 分区: `internal/storage`（S3 引擎）

## 目标

修复 T-173 两条 P2 缺陷：

1. **D-5**：Commit 的 `CopyObject` 缺 `ReplaceMetadata:true`，导致 S3 服务端 COPY 默认不替换元数据，`blob-created-at` 自定义元数据被静默丢弃；GC grace 用 `LastModified`，从不读该元数据。要求：上传携带 `blob-created-at`（RFC3339），GC grace 基于它（无则 fallback `LastModified`），与 disk 后端口径对齐。
2. **D-6**：启动时回收孤儿 multipart upload（中断/崩溃会话遗留的 incomplete MPU），列举 in-progress MPU 并 abort 超出 grace 时长的孤儿（disk 有 startup session sweep 对应物，S3 缺失）。

## 变更清单

- `internal/storage/s3.go`
  - 新增常量 `blobCreatedAtMetaKey = "blob-created-at"`、`uploadKeySegment = "sessions"`。
  - `S3EngineOptions` 增加 `SessionTTL time.Duration` + `sessionTTL()` 方法（fallback `DefaultSessionTTL`）。
  - `uploadKeyPrefix()`：推导 `<prefix>/sessions/` 路径片段（无 prefix 时为 `sessions/`）。
  - `blobCreatedAtFromMeta(meta map[string]string) (time.Time, bool)`：大小写不敏感（`strings.EqualFold`）查找 `blob-created-at`（Go `http.Header` canonicalize 后变 `Blob-Created-At`），RFC3339 解析，失败返回 `false`。
  - `Commit` 的 `CopyObject` 补 `ReplaceMetadata: true`；`putEmptyBlob`/`Commit` 用 `blobCreatedAtMetaKey` + `timeNow()` 写创建时间。
  - GC grace：对未引用对象发一次 `StatObject`（HEAD）读 `blob-created-at`，命中则以其为 grace 时钟，否则 fallback `obj.LastModified`（`ListObjects` 在 v7 API 不带 UserMetadata，故逐未引用对象 HEAD）。
  - `listIncompleteUploads()`：`ListMultipartUploads` 分页（`maxUploads=1000`、`IsTruncated`/`NextKeyMarker`/`NextUploadIDMarker`），前缀过滤到 `uploadKeyPrefix()`。
  - `sweepOrphanUploads(ctx, ttl)`：对 `Initiated` 早于 cutoff 的孤儿 `AbortMultipartUpload`，多孤儿收集 firstErr（不中断整体清扫）。
  - `OpenS3Engine` / `OpenS3EngineWithClient`：启动时跑 `sweepOrphanUploads`，签名改为 `(Engine, error)`（对齐 disk `OpenEngine`），sweep 失败则拒绝启动。

- `internal/storage/s3_test.go`
  - mock 增加 `mockUpload.initiated`；`handleStatObject` 回显 `x-amz-meta-*` 与存储的 `LastModified`；新增 `handleListMultipartUploads` 路由与处理器（XML 输出、prefix + keyMarker 过滤、按 key 排序）。
  - 新增 helper：`addOrphanUpload`、`uploadCount`、`objectMetadata`、`setObjectMetadata`。
  - 更新 `newS3Engine` / `TestResolveS3PartSize` 捕获 `(Engine, error)` 返回。
  - 修复既有 `TestS3GCGracePeriod`：`putS3` 现在写 `blob-created-at` 元数据，须清空元数据才测 LastModified fallback（避免与新语义冲突）。
  - 新增测试：`TestS3CommitPreservesBlobCreatedAtMetadata`、`TestS3GCGraceUsesBlobCreatedAt`、`TestS3GCGraceFallsBackToLastModified`、`TestS3StartupSweepsOrphanUploads`、`TestS3StartupSweepIsIdempotent`、`TestBlobCreatedAtFromMeta`。

- `cmd/binflow-server/main.go`
  - 仅签名接线 ripple：`OpenS3EngineWithClient` 现返回 `(Engine, error)`，按 name 语义 wrap 错误（非 cmd 新功能）。

## 可靠性覆盖

- 并发：新增测试与全量 `-race` 173.5s 覆盖（含既有「并发写同 blob」测试，GC 逐对象 StatObject 路径在并发下无竞态）。
- 中断：D-6 孤儿回收 —— 构造孤儿 MPU（模拟崩溃遗留）→ 引擎启动 → 断言孤儿被 abort；`Initiated` 在 grace 内的保留。
- 校验失败：`TestBlobCreatedAtFromMeta` 覆盖 malformed 值返回 `false`（fallback 生效）；`blobCreatedAtFromMeta` 大小写不敏感对 `Blob-Created-At`（http.Header canonicalize）与 `blob-created-at` 均命中。
- GC 不误删：D-5 grace 时钟对迁移 blob 从原创建时刻起算（保留更长）；fallback LastModified 覆盖 mc 导入/旧部署无元数据的对象；`TestS3StartupSweepIsIdempotent` 确保重复启动不重复 abort（幂等）。
