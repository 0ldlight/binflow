# T-158 — 控制台 SSO 登录 UI（OIDC + LDAP 登录页面）

- 状态: done（待 review）
- 日期: 2026-08-22
- role: dev-frontend / area: `web/src/pages / web/src/components`（+ 对应 e2e spec）

## 做了什么

1. **AC① SSO 按钮（`web/src/pages/LoginPage.tsx`）**：登录卡在密码表单下方渲染
   「使用 SSO 登录」次级按钮（`data-testid="login-sso"`，「或」分隔线隔开），
   点击后**顶层导航** `GET /binflow/api/v1/oidc/login`（后端 302 → IdP，
   state+PKCE 事务全在后端 cookie/重定向里，前端不经手任何令牌）。
2. **「仅 oidc.enabled=true 时显示」的探测方式（当前无公开探测端点，务实选型）**：
   挂载时 `fetch(OIDC_LOGIN_URL, { redirect: 'manual' })` 读「是否发生 302」——
   - `opaqueredirect`（type/status=0）→ 已启用，渲染按钮（浏览器不离开页面、
     **绝不触达 IdP**，只读取重定向事实）；
   - `404` → 未启用（T-157 契约：disabled 实例该端点 E-26 404，FR-54-AC6/H29），
     按钮永不渲染；
   - 5xx/网络错误 → 无法断言，按未呈现收敛（密码表单仍可用，其自身错误如实呈现）。
   副作用说明：对启用实例的探测会让后端铸造一对 state+PKCE 落一次性事务 cookie
   （10 分钟过期；真实点击时被新事务覆盖，无害）。
   未走 `lib/api` 的 rawRequest：数据层面向 JSON 面（非 2xx 一律抛 ApiError、
   fetch 默认跟随重定向），此处需要导航语义的原始响应（area 纪律也要求不动
   `web/src/lib`）。
3. **点击时复核一次（跳转失败错误提示态）**：登录页可能停留多时，实例或已重启/
   改配置。复核仍是 302 才 `window.location.assign`；404 → 行内错误
   「SSO 登录未启用…」+ 按钮收敛隐藏；5xx/网络 → 行内错误
   「SSO 登录暂不可用（服务异常）…」+ 按钮保留可重试（`data-testid="sso-error"`，
   role=alert）。避免把用户丢到裸 404/5xx JSON 页。
4. **AC② LDAP 透明**：目录用户与本地用户共用同一表单（后端先本地后 LDAP 回退，
   T-156/T-157），前端零分支、零提示差异——`POST /api/v1/session` 面与 401 文案
   均未改动，仅由测试固化该行为。
5. **样式（`web/src/styles/base.css`，仅登录页小节内追加）**：登录卡按钮通栏、
   `.login-divider` 分隔线、`.login-sso-error` 间距；全部走既有 token，暗/亮两态
   自动适配（无硬编码颜色）。
6. **e2e `web/e2e/login.spec.ts`（新增，hermetic mock 模式，同 T-160
   storage_migration.spec.ts 写法）**，5 例全绿：
   - ① oidc 404 → SSO 按钮整体隐藏、密码表单完好（用 `expect.poll` 命中计数防
     「初始渲染本来就没有」的假通过）；
   - ② oidc 302 → 按钮可见；点击发起**顶层 document GET** `/binflow/api/v1/oidc/login`
     并离开 SPA（断言 documentNavs=1、探测+复核≥3 次命中、URL 已离开 /ui/）。
     注：Chromium 不跟随 Playwright fulfill 合成的导航 302，文档请求直接以 mock
     IdP 落地页应答；真实「302 → IdP」跳转契约由 T-157 的
     TestOIDCLoginRedirectContract（Go）固化；
   - ③ 探测时启用、点击时被关（404）→ 行内「SSO 登录未启用」+ 按钮收敛；
   - ③b 点击复核遇 503 → 行内「SSO 登录暂不可用」+ 按钮保留可重试；
   - ④ LDAP 透明登录：守卫重定向 /login?return → 错误目录口令 401 行内红字 →
     同一表单正确目录凭据 200 → 落地壳（session-user=jdoe、非 admin 收敛视图，
     管理卡 403 即隐藏）。

## 四态对照（SSO 面）

- 默认（oidc off）：按钮不渲染，表单即全部；
- 可见（oidc on）：按钮 + 分隔线，探测为 fetch 不导航；
- 加载：提交 spinner（既有）；SSO 点击复核期间按钮禁用 +「正在跳转…」；
- 错误：SSO 行内 alert（未启用 / 暂不可用两档）；LDAP/本地统一 401 行内红字。

## 契约漂移

- 无实质漂移。`GET /binflow/api/v1/oidc/login` 的 302/disabled-404 行为与
  T-157 报告及 `internal/httpapi/oidc.go` 一致。
- 非漂移但**需后端小端点（建议开票，本票未自行实现后端）**：探测目前依赖
  「对 login 路由 GET 看 404 与否」。更稳的形态是公开
  `GET /api/v1/auth/methods`（返回 `{ password: true, oidc: bool, ldap: bool }`，
  匿名可读、不泄露内部状态），前端可精确渲染并顺带给 LDAP 用户展示「或目录
  账号」提示；端点落地后探测应迁入 `lib/api.ts`（需动 web/src/lib，越本票
  area，未动）。
