## 实现

### ① upload 三式（DE-02/04/05，`uploads.go`）

- **POST initiating** → 202 + `Location: /v2/<name>/blobs/uploads/<uuid>`（**相对路径**，R6）+ `Docker-Upload-UUID`（纯 UUID，无 `.patch` 后缀）+ `Range: 0-0` + `Content-Length: 0` + api-version 头。官方形，不采纳 Artifactory 的省略 Range。
- **POST `?digest=` 单请求**（规格照抄 7）→ 201 + `Location` blob URL；digest 失配 → 400 `DIGEST_INVALID`（官方码；Artifactory 的 `BLOB_UPLOAD_INVALID` 文案不采纳）+ 会话 Abort 零残留。
- **PATCH**：无 `Content-Range` = 全量流式（官方 Stream upload）；给了则**起点必须 == 服务端 received**，失配 416 + `Range: 0-<received-1>` 空 body（§2.2#3 高置信度行）。`Range` 头随每块返回累计值。
- **PUT `?digest=` 终结**：body 可空（流已推完）或带末段（`Content-Length != 0` 时先 Append 再 Commit）；`Commit(expect)` 失配 → 400 `DIGEST_INVALID`，会话已被 storage 消费（Commit 失败即 finalize 的 storage 契约）+ 注册表移除。
- **GET `<upload-url>`** → 204 + `Range` + `Docker-Upload-UUID`（官方端点，规格建议栏 5——Artifactory 的非标 `.patch` GET 不做）；**DELETE** → 204 取消。
- **会话注册表**（`sessionRegistry`）：进程内 UUID→Session+received 映射，重启后旧会话 404 `BLOB_UPLOAD_UNKNOWN`（架构裁定 1：跨进程续传 M3+；磁盘残渣由 storage 既有 TTL sweep 收）。
- **毒化对接**（ErrSessionPoisoned）：Append 失败 → 注册表标记 `poisoned` 但保留条目（客户端能观察到失败而非静默归零）；毒化会话的后续 PATCH → 416 + 权威 offset（重启线索）；毒化 finalize → 400 `BLOB_UPLOAD_INVALID` + 消费（绝不 Commit）。

### ② mount + 读路径（DE-03/06/07/14，`blob.go`）

- **mount**：`?mount=&from=` → 源 repo read（NFR-S12，经 `Authorizer.Can`）且源 layout 有该 blob（`repo.Service.Get` 探测）→ 201 走 `PutFromBlob` 零拷贝（sha1/md5 取 ledger 行，不信任客户端声明）；任一不满足 → **降级 202 普通会话**（spec 的 fall-back，永不报错）。目的地权限形拒绝（403 族）仍如实渲染。
- **GET blob**：200 流式 + `Docker-Content-Digest` + X-Checksum 全套 + ETag(=sha1) + `Accept-Ranges: bytes`；Range 206/416 复用 M1 条件请求基建语义（单 range 切片 / 越界 416 `bytes */<total>` / 多 range 与非 bytes 单位忽略走 200）；404 `BLOB_UNKNOWN` spec 体（detail 带 digest）。
- **HEAD blob**：200 + Content-Length + Docker-Content-Digest + X-Checksum-Sha256/Sha1/Md5（规格照抄 6）。
- **DELETE blob** → 405 `UNSUPPORTED` + `Allow: GET, HEAD`（DE-14 有意不兼容：物理回收唯一入口是 GC）。
- **node 路径** `<image>/blobs/<hex>`（架构 §6 布局约定）。
- **空层特例**（规格照抄 4）：digest `sha256:a3ed95ca...` 的 GET/HEAD **直接合成 32B 固定响应**，不查库（docker push 空层高频路径——客户端根本不上传该 blob）；sha1/md5 由常量 bytes init 时计算（非手抄），测试逐位校验常量自洽。manifest 校验豁免归 T-39（引用链查询时同样短路）。

### ③ 关键设计裁定：blob 的 metadata 挂账走 `repo.Service.Put`（非 PutFromBlob）

上传 finalize 后的 ledger+node 挂账不能走 `PutFromBlob`：它要求 ledger 行**已存在**（孤儿 blob 拒绝），而 ledger 行只由 `Put` 的 `putNode` 路径创建——全新 docker push 没有先前的 generic deploy 可依托。裁定：adapter 在 `Commit` 后将刚落盘的 blob 经 `store.Open` 回读成流，喂给 `svc.Put(path, body, expect)`——与 generic 上传**同一条落账路径**（blobs 台账行 + node 行、既定顺序、幂等重传规则全继承），`Put` 内部的 session Commit 对已存在 blob 是 singleflight 幂等命中（同 FS 零拷贝、无第二份物理副本）。挂账失败（Commit 已成功）→ 按架构语义记 ERROR 日志、blob 成 GC 候选，201 仍然成立（blob 已持久）。此裁定不越 area（未改 repo 包，复用既有 SPI）。

### ④ 装配（最小增量）

- `docker.Handler.WithStorage(store storage.Engine, ledger BlobLedger)` setter：T-37 的 `New` 签名不动（旧装配点零改动编译通过），生产装配两处（`cmd/binflow-server/main.go`、`httpapi/harness_test.go`）各加一行 `.WithStorage(st, md.Blobs())`。
- storage seam 为接口注入（架构 §5.3 会话对接裁定的落点：adapter 持协议状态 received+UUID 配对，storage 不感知协议头）；`BlobLedger` 与 generic.BlobLedger 同构（consumer-side interface）。
- `handler.go`：repo 门 + `authorizeRoute` 之后按 tail 分派 `blobs/uploads*` 与 `blobs/*`，manifests/tags/catalog 仍落 T-39/T-40 的基座 404——**不动 token/scope/既有 handler 逻辑**（仅删掉 T-33 留的空 sessionRegistry 桩，实现移至 uploads.go）。

## 规格依据

- 202 头形/Range 0-0/相对 Location/纯 UUID：docker-registry.md §2.1 + §10 建议栏 6/7（官方形，不采纳 Artifactory 的省略 Range 与 `<uuid>.patch`）。
- Content-Range 错位 416 空 body：§2.2#3 高置信度。
- digest 失配 400 DIGEST_INVALID：§2.3 + T-32 裁定（Artifactory 的 BLOB_UPLOAD_INVALID 文案不复刻）。
- POST 单请求 201：§10 照抄栏 7。
- GET 上传状态 204 + Range：官方端点，§10 建议栏 5（`.patch` 变体不做）。
- mount 降级 202：spec fall-back 语义（架构 §5.3 裁定 3）。
- 空层 32B 合成：§2.3 + §10 照抄栏 4；常量 bytes 取自逆向规格确认的固定 artifact（hex 直写 + 测试逐位断言）。
- blob DELETE 405：DE-14/D13d（ADR-0006 安全底线）。
- Range/条件请求：M1 generic/conditional.go 的语义契约在 docker 面复述（generic 实现是包私有；跨包导出会耦合两 adapter 的 HTTP 面，故同规则本包实现，契约注释指明同源）。

## 遗留 / 交接

1. **T-39（manifest 链）**：blob 读路径与 node 布局已就位——manifest body 走本票的上传端点落 blob 后，`PutManifest` 直接可用；空层豁免在 manifest 引用链查询处短路（`emptyLayerDigestHex` 常量已导出于包内）；`blobNodePath(image, hex)` 是共享布局函数。
2. **T-40（catalog/tags）**：路由分派点已留（tail 非 blobs* 落基座 404），接上即走。
3. **`TestSingleflightExecutesOnce` flake（转 dev-go-core）**：M1 concurrency_test.go 的 announce/收流机制在 12 包全量 -race 并发跑的重负载下 605s 超时一次；当前树分组 -race 与单用例 -race 均 ok。非本票文件，建议复核其 `started` 通道的握手时序。
4. **PRD 勘误建议（转 conductor/PM）**：PRD §8 的 D06/D13 示例 URL 用 `/v2/docker-local/blobs/uploads/`（**单段 name**），按 ADR-0010 第 3 条（name = repoKey/image）这是 404 形。T-43 复跑时应写 `/v2/docker-local/<image>/blobs/uploads/`（本票 curl 与测试均已用全名形）。
5. **`Docker-Upload-UUID` 响应头大小写**：Go 的 http.Header 规范化为 `Docker-Upload-Uuid`；HTTP 头域大小写不敏感，docker/oras/crane 均按规范化名匹配（distribution 参考实现同样经 Go 栈发出 `Docker-Upload-Uuid`），非兼容性风险，记录备查。
6. **挂账失败的 201**（裁定 ③ 的边界）：Commit 成功但 `svc.Put` 失败时响应仍 201（blob 已持久，GC grace 兜底）。若 review 认为该窗口应 5xx，改动点在 `writeBlobCreated` 单处。
7. **docker 客户端级验证**（D05/D08）：环境项（daemon insecure-registries）归 T-44/T-45 compose 路径（T-37 已留档）。
