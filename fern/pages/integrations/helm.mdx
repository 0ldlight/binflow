# Helm Chart 仓库接入（经典 chart 仓 + HelmOCI）

BinFlow 的 helm 仓 = 标准 chart repository：上传 `.tgz` 自动解析 Chart.yaml 并**重算 `index.yaml`**，客户端 `helm repo add` 后即获得搜索/安装能力；**local / remote（代理）/ virtual（聚合）三类仓型齐备**。

> helm / helmoci 包型均为 **pro 档**能力——建仓/上传需 pro 及以上 license；未解锁时既有 chart 仍可 `helm pull`/`install`。
>
> 命名辨析：本文前半是 **helm 经典 chart 仓**（`index.yaml` + `.tgz`）；「HelmOCI」节是 **OCI 形态 chart 仓**（`helm push` 到 `oci://` 地址，包型 `helmoci`——走 /v2 栈但与 docker 是两个包型）。用 Helm Chart **部署 BinFlow 本身**见 [Helm Chart 安装](/install/helm)。

- 仓 URL：`$BASE/binflow/<repoKey>`（index.yaml 在仓根）；index 条目 `urls` 恒为相对路径。

## local 仓：打包、上传、安装

```bash
export BASE=http://localhost:8080 ADMIN_PW=<管理员口令>
curl -su admin:$ADMIN_PW -X PUT $BASE/binflow/api/repositories/helm-local \
  -H 'Content-Type: application/json' \
  -d '{"rclass":"local","packageType":"helm"}' -o /dev/null -w '%{http_code}\n'   # 200

helm create mychart && helm package mychart    # mychart-0.1.0.tgz

curl -su admin:$ADMIN_PW -T mychart-0.1.0.tgz $BASE/binflow/helm-local/mychart-0.1.0.tgz \
  -o /dev/null -w '%{http_code}\n'             # 201（index 随即重算）

helm repo add binflow $BASE/binflow/helm-local
helm repo update
helm search repo binflow/mychart
helm pull binflow/mychart --version 0.1.0
helm install my-rel binflow/mychart --wait     # STATUS: deployed
```

- 上传即解析：`.tgz` → tar 归档根的 Chart.yaml；**无 Chart.yaml 或坏 tar 跳过索引但不拒 PUT**（按普通文件落库）。
- 同 name+version 重传 = 覆盖（index 条目 remove+add）；版本排序按 SemVer 降序。
- `.prov` 签名文件是普通文件：`curl -T mychart-0.1.0.tgz.prov …` 落库即可（不进 index）。

### provenance 验签（--verify）

helm 的验证器要求 `.prov` 是 **clearsign 文档**且正文两段式（Chart.yaml 元数据 + `files:` sha256 块）。注意 detached 签名（`gpg --armor --detach-sign`）会被 helm 拒绝（`signature block not found`）；两段之间必须有一行字面 `...`：

```bash
{ cat mychart/Chart.yaml; echo; printf '...\nfiles:\n  %s: sha256:%s\n' \
    mychart-0.1.0.tgz "$(shasum -a 256 mychart-0.1.0.tgz | cut -d' ' -f1)"; } > prov-payload.txt
gpg --clearsign prov-payload.txt                # 产出 prov-payload.txt.asc
curl -su admin:$ADMIN_PW -T prov-payload.txt.asc \
  $BASE/binflow/helm-local/mychart-0.1.0.tgz.prov -o /dev/null -w '%{http_code}\n'  # 201

helm pull binflow/mychart --verify --keyring <你的公钥 keyring>
# Signed by: <uid> / Chart Hash Verified: sha256:<hex>
```

### reindex 与只读别名

```bash
curl -su admin:$ADMIN_PW -X POST $BASE/binflow/api/helm/helm-local/reindex                # 异步全仓
curl -su admin:$ADMIN_PW -X POST $BASE/binflow/api/helm/helm-local/reindex/mychart-0.1.0.tgz  # 同步单包
```

`/binflow/api/helm/<repoKey>/…` 是内容面的**只读别名**（GET/HEAD 200；写 405）——适合管理面可达、内容面被网闸的拓扑。

## remote 仓（代理上游 chart 仓）

```bash
curl -su admin:$ADMIN_PW -X PUT $BASE/binflow/api/repositories/helm-remote \
  -H 'Content-Type: application/json' \
  -d '{"rclass":"remote","packageType":"helm","url":"https://charts.example.com/stable"}' \
  -o /dev/null -w '%{http_code}\n'    # 200

helm repo add bf-remote $BASE/binflow/helm-remote
helm repo update && helm pull bf-remote/upchart --version 0.1.0
```

`index.yaml` 与 `.tgz` 均 pull-through；DELETE = 缓存驱逐（204/404）；PUT → 405。

### chartsBaseUrl：分体回源基址

上游「索引」与「chart 实体」不在同一地址时（index 在仓库站、tgz 在 CDN），给 remote 仓配 `chartsBaseUrl`——**metadata（index.yaml）恒走仓 URL，content（tgz/`.prov`/`_external` 折叠路径）改走分体基址**；未配置回退仓 URL：

```bash
curl -su admin:$ADMIN_PW -X PUT $BASE/binflow/api/repositories/helm-xbase \
  -H 'Content-Type: application/json' \
  -d '{"rclass":"remote","packageType":"helm",
       "url":"https://charts.example.com/stable",
       "chartsBaseUrl":"https://cdn.example.com/charts"}' \
  -o /dev/null -w '%{http_code}\n'    # 200
```

仅 helm 包型 remote 接受该字段（其它包型携带 → 400 点名字段）；值必须为绝对 http(s) URL；**凭据边界**：分体基址与仓 URL 同 host 复用仓凭据，异 host 无凭据出站。

## virtual 仓（聚合 + URL 改写）

```bash
curl -su admin:$ADMIN_PW -X PUT $BASE/binflow/api/repositories/helm-virt \
  -H 'Content-Type: application/json' \
  -d '{"rclass":"virtual","packageType":"helm",
       "repositories":["helm-local","helm-remote"],
       "defaultDeploymentRepo":"helm-local"}' -o /dev/null -w '%{http_code}\n'  # 200

helm repo add bf-virt $BASE/binflow/helm-virt
helm repo update && helm install t bf-virt/extchart --wait
```

- **合并**：逐成员读 index.yaml，按 `(name, version)` **first-wins**；chart 内版本 SemVer 降序重排。
- **URL 改写**：指向成员仓基址（或其 chartsBaseUrl）的 URL → 成员相对路径；指向**外部 host** 的 URL → 折叠为 `_external/<scheme>/<host>/<path>`（经虚仓受控 egress 取数，响应头 `X-Binflow-Upstream` 标上游；折叠路径取数落盘缓存，二次拉取 `X-Binflow-Cache: HIT`）；`oci://` 条目保留原样。
- **写**：PUT 路由到 `defaultDeploymentRepo` 的 local 成员（未配置 → 405）。
- **helm 与 helmoci 不混仓**：虚仓自身与全体成员的包型家族不得同时含 `helm` 与 `helmoci`（建/改仓 400）。
- 布局约束（可选，建仓 JSON 两开关默认关）：`forceMetadataNameVersion` / `forceNonDuplicateChart`——开启后坏包或同名同版本重复在字节落库前 403 拒绝。

## HelmOCI 仓型（OCI 形态，local + remote + virtual）

`helmoci` 包型走 **/v2 OCI Distribution 栈**（与 docker /v2 面同协议同端口，但是独立包型）：

```bash
export REG=<host>          # 例 127.0.0.1:8080（明文 HTTP 时客户端加 --plain-http）
helm registry login $REG -u admin -p <口令> --plain-http
helm push mychart-0.1.0.tgz oci://$REG/helmoci-local --plain-http
# Pushed: …/helmoci-local/mychart:0.1.0（digest 与 tgz 本地 shasum 对账）
helm pull oci://$REG/helmoci-local/mychart --version 0.1.0 --plain-http
helm install rel oci://$REG/helmoci-virt/mychart --version 0.1.0    # 经 virtual 聚合
```

### remote 仓（代理上游 OCI registry）

`url` 指向上游 registry 的 **distribution API 根（含 `/v2`）**——Docker Hub 形态 `https://registry-1.docker.io/v2`；上游是另一台 BinFlow 时 `http://<host>:<port>/v2/<上游仓key>`。

- manifest/blob 按需回源、以实测 sha256 寻址落盘（digest 强校验，不符永不落盘）；**二次拉取零回源**（`X-Binflow-Cache: HIT`）。
- **上游认证链**：上游 401 + Bearer challenge → 仓凭据自动完成 token 交换（公用 registry 无需凭据）。
- **降级**：上游 5xx/断连 → 有过期副本答 `STALE` + `X-Binflow-Upstream-Error` 续服务；无副本 404（`MANIFEST_UNKNOWN` 族，零裸 5xx）。
- 写动词全量 405；**tags/list 与 _catalog 只见已缓存的 tag**（`--version` 显式拉取不受影响）。

### virtual 仓（成员聚合）

- **成员序 first-seen**：manifest/blob 按成员序逐成员解析；响应带 `X-BinFlow-Resolved-From: <成员key>`。
- **tags/list / _catalog 并集**：tag 按成员序 first-wins 去重 + 排序；remote 成员只贡献已缓存 tag。
- **成员同型校验**：helmoci virtual 的成员必须 helmoci 型——配 docker 成员 → 400（`virtual repository cannot mix the helmoci and docker package types`）。
- 写面一律 405（/v2 面的 push-through 路由未实现——未配 `defaultDeploymentRepo` 与已配的 405 文案不同，后者点名目标）。

## 边界与有意不做

| 项 | 行为 |
|---|---|
| PUT `index.yaml` / `.index/**` | **403**（服务端生成的索引不可手写） |
| 聚合 index 缓存 | 按请求现算（成员变更下一请求即见） |
| namespace 模式（useNamespaces） | 未实现 |
| helmoci /v2 push-through | 未实现——virtual 写面一律 405 |
| 上游 tags/list 代理（helmoci remote） | 不做——tags/list 只见已缓存 tag |

## 常见报错对照

| 症状 | 原因 | 处置 |
|---|---|---|
| 建仓 400 `package type 'helm' is not available ...` | community 档 | 装 pro/enterprise license |
| 上传 403 + `X-Binflow-License-Required: helm` | license 写门；下载/索引读不受影响 | 重装 license |
| `helm pull --verify` 报 `signature block not found` | `.prov` 不是 clearsign 两段式 | 按「provenance 验签」配方重产 |
| 上传 `.tgz` 后 `helm search` 看不到 | 包无 Chart.yaml/坏 tar（跳过索引不拒传） | 修包重传 |
| PUT index.yaml 403 | 索引是服务端生成物 | 用上传/删除/reindex 维护 |
| 虚仓建仓 400 混仓 | 成员家族混仓（helm×helmoci / helmoci×docker） | 拆成两个虚仓 / 成员全部同型 |
| remote 建仓 400 `chartsBaseUrl … is not accepted` | 非 helm 包型的 remote 携带该字段 | 去掉该字段 |
| `helm pull oci://…` 404 `MANIFEST_UNKNOWN` | remote 未缓存且上游 404/不可达；或 tag 未缓存 | 显式 `--version` 触发回源；看 `X-Binflow-Upstream-Error` |
| 虚仓上 PUT 405 | 未配 `defaultDeploymentRepo` | 建仓时指定 local 成员 |
